# LabelDesk ปิดช่องว่าง Roboflow ด้วย solution pack ไทย

**ข้อสรุปหลัก:** หลัง Tasks 1–26 LabelDesk ครอบคลุม ML loop (auto-label, train, evaluate, stream), analytics, QA/workforce, SDK/webhook, drift และ PDPA/RBAC ไว้แล้ว ช่องว่างที่เหลือกับ Roboflow และคู่แข่งไม่ใช่ "ฟีเจอร์พื้นฐาน" แต่เป็น 4 กลุ่ม คือ (1) **การค้นและ curate ข้อมูลด้วยภาษาธรรมชาติ/embedding และการหา suspect label** ซึ่งปรากฏในแพลตฟอร์มอย่างน้อย 3 ราย (Encord, SuperAnnotate, FiftyOne/Roboflow) (2) **การประกอบ pipeline แบบ no-code (Workflows)** ที่ Roboflow มี block catalogue ขนาดใหญ่ ทั้ง OCR, tracking, tiling แบบ SAHI, PTZ และ notification (3) **ชั้น deploy ฝั่ง edge** ได้แก่ export หลาย runtime, fleet manager, batch inference และ MCP/agent API (4) **ความต้องการเฉพาะภาคอุตสาหกรรม** ได้แก่ anomaly detection แบบ good-only, OCR ภาษาไทย, attribute/grouping สำหรับ claims, DICOM เราเสนอ backlog ใหม่ **Tasks 27–50 (24 รายการ)** โดยมี 8 รายการเป็น Must ข้อเสนอเชิงกลยุทธ์คือไม่แข่งแบบ horizontal กับ Roboflow แต่ขายเป็น "สร้างโมเดลตรวจสอบโดยไม่ต้องมีทีม ML + ข้อมูลอยู่ในไทย + ปิดงานผ่าน SI" ผ่าน solution pack 4 ชุด (Factory QC & PPE, Thai Document & Plate, Claims Inspection, Agri Grading) หมายเหตุความเชื่อมั่น: ผลค้นส่วนใหญ่เป็นหน้า vendor และ search summary ตัวเลขตลาดแต่ละสำนักขัดกันเอง และข้อสรุปเรื่อง "ภาคไหนต้องการอะไร" ส่วนใหญ่เป็นการอนุมานของเราเอง ไม่ใช่ข้อกำหนดที่ยืนยันแล้ว

## Roboflow และคู่แข่งยังนำอยู่ 4 จุดที่ Tasks 1–26 ไม่ครอบคลุม

เมื่อเทียบ inventory ของ Roboflow กับ backlog ปัจจุบัน สิ่งที่ LabelDesk ปิดแล้วมีมาก: Auto Label ด้วย SAM 3 และ VLM verify (Task 4), Smart Select/ Box prompt (Task 17), review mode และ labeling analytics (Task 23), confusion matrix drill-down และ model compare (Task 20b), audit log และ SSO/RBAC (Task 26), REST/SDK/scoped key (Task 24) ([Roboflow pricing](https://roboflow.com/pricing); [Roboflow docs](https://docs.roboflow.com/annotate/ai-labeling)) ส่วนที่ยังขาดมี 4 กลุ่มชัดเจน

กลุ่มแรกคือ **curate ข้อมูลด้วย semantic search** Roboflow มี semantic search ในหน้า dataset และ Similarity Search ใน annotator ([Roboflow export docs](https://docs.roboflow.com/datasets/exporting-data)) Encord ให้ค้นภาพ/เฟรมด้วยภาษาธรรมชาติ บันทึกผลเป็น Collections มี embedding plot, duplicate/outlier และ label-error detection ([Encord docs](https://docs.encord.com/solutions-documentation/applied-ai/annotation-and-curation)) SuperAnnotate ทำ vector similarity + NL search เช่นกัน ([SuperAnnotate](https://www.superannotate.com/blog-category/product)) Task 20a ของเรามี UMAP embedding map และ Task 9 มี missing-box แต่ **ยังไม่มีช่องค้นด้วยข้อความ และยังไม่มีคิว "suspect label" ที่เรียงตามความไม่ตรงกันระหว่างโมเดลกับ label** (Task 9 เจอเฉพาะกล่องที่ขาด ไม่ใช่คลาสผิดหรือกล่องเลื่อน) ซึ่งเป็นงานที่ cleanlab ObjectLab ทำได้ด้วย `find_label_issues` ([Cleanlab tutorial](https://docs.cleanlab.ai/master/tutorials/object_detection.html)) และ FiftyOne มี `compute_mistakenness()` ที่ให้คะแนนความน่าสงสัย ([FiftyOne tutorial](https://docs.voxel51.com/tutorials/detection_mistakes.html)) Voxel51 อ้างว่าลูกค้ารายหนึ่งลดภาพที่ส่ง review ด้วยมือได้ 77% (ตัวเลข vendor) ([InfoWorld](https://www.infoworld.com/article/4085132/improving-annotation-quality-with-machine-learning.html))

กลุ่มที่สองคือ **Workflows แบบประกอบได้** Roboflow มี block หลายร้อยตัว ทั้ง OCR (EasyOCR, PP-OCR), barcode/QR, ByteTrack/BoT-SORT, Line Counter, Time in Zone, PTZ tracking ผ่าน ONVIF, image slicer แบบ SAHI, perspective correction, ตัวกรอง confidence, และ sink ไปยัง S3/webhook/Email/Slack/SMS ([Roboflow blocks](https://docs.roboflow.com/workflows/blocks)) ส่วน Task 10 ของเรามี rule engine เฉพาะ count/zone/line/dwell/vlm ซึ่งเป็นรูปแบบตายตัว ลูกค้าโรงงานที่ต้อง "ตรวจ → crop → OCR → เทียบรหัส → ส่งสัญญาณ" ยังประกอบเองไม่ได้ Roboflow ยังมี Batch Processing สำหรับภาพ/วิดีโอแบบ async และ Cloud Streaming ([Roboflow deployment](https://docs.roboflow.com/deployment/overview)) ซึ่ง backlog เรายังไม่มี batch inference job

กลุ่มที่สามคือ **edge และ agent surface** Ultralytics Platform รองรับ export 17–22 รูปแบบ (แหล่งข้อมูลไม่ตรงกันเรื่องจำนวน), inference endpoint แบบ scale-to-zero และ remote training ที่ stream metric จากเครื่องลูกค้า ([Ultralytics docs](https://docs.ultralytics.com/platform/)) YOLO26 เป็นโมเดล NMS-free ออกแบบสำหรับ edge พร้อม export ไป NPU อย่าง DeepX ([LearnOpenCV](https://learnopencv.com/yolov26-real-time-deployment/); [Ultralytics DeepX](https://docs.ultralytics.com/es/integrations/deepx)) Task 14 ของเราทำแค่ TensorRT Roboflow มี Deployment Manager สำหรับ fleet edge (Enterprise) ([Roboflow enterprise](https://docs.roboflow.com/deployment/self-hosted/enterprise.md)) และมี **MCP server** ที่ให้ Claude Code/Cursor สร้างโปรเจกต์ auto-label train และ deploy ได้ ([Roboflow MCP](https://blog.roboflow.com/mcp-server/)) ส่วน Task 24 ครอบคลุมแค่ SDK/CLI/webhook

กลุ่มที่สี่คือ **modality และ metadata เฉพาะทาง** Roboflow มี annotation attributes, annotation groups, video segment/action recognition, anomaly detection block และ Visual Search Classifier ([Roboflow annotate](https://docs.roboflow.com/annotate/annotation-tools); [Roboflow blocks](https://docs.roboflow.com/workflows/blocks)) V7 และ Encord รองรับ DICOM/point cloud ([V7](https://www.v7darwin.com/); [Encord](https://docs.encord.com/solutions-documentation/applied-ai/annotation-and-curation)) Task 22 ของเรามี OBB/keypoint/video แล้ว แต่ไม่มี attribute, grouping, DICOM หรือ anomaly

สัญญาณจากฝั่ง emerging ยืนยันทิศทางเดียวกัน: SAM 3 prompt ด้วยข้อความ (ผู้เขียนอ้าง accuracy 2 เท่าของระบบก่อนหน้า) ([arXiv 2511.16719](https://arxiv.org/pdf/2511.16719)) ถูกใช้ใน Roboflow Auto Label แล้ว แต่ prompt ทั่วไปไม่ได้ตั้งชื่อคลาสให้ ผู้ใช้ยังต้องกำหนดเอง ([Roboflow blog](https://blog.roboflow.com/best-image-annotation-tools/)) ดังนั้น prompt → pre-label → review → train เป็น table stakes แล้ว จุดแข่งจริงคือการตั้งชื่อคลาสและ QA อัตโนมัติ ซึ่ง Task 4 ของเรา (VLM verify, prompt parser) ได้เปรียบอยู่แล้ว ส่วน FiftyOne Agentic Labeling ยังเป็น Beta และ Enterprise-only ([Voxel51 docs](https://docs.voxel51.com/enterprise/agentic_labeling.html)) และ synthetic data ยังให้ผลผสมในงานวิจัย ([arXiv 2511.23450](https://arxiv.org/pdf/2511.23450); [TNO](https://publications.tno.nl/publication/34645222/07v7xkq9/snel-2025-data.pdf)) จึงควรเป็น Defer

## Differentiation: ห้าสมมติฐานและฟีเจอร์ที่พิสูจน์

โน้ตวางตำแหน่งให้ 5 สมมติฐาน ความแข็งแรงของหลักฐานต่างกันมาก เราจึงเรียงตามน้ำหนักและระบุฟีเจอร์ที่ "ต้องส่งมอบจริง" เพื่อให้ข้อความการตลาดไม่ลอย

**สมมติฐาน 1: "ไม่ต้องมีทีม ML" จากภาพดิบถึงกล้องจริง (หลักฐานแข็งสุด).** องค์กรไทยที่ใช้ AI ระดับองค์กรมีไม่ถึง 20% จากตัวอย่างราว 600 แห่งในปี 2024 ([Asia News Network](https://asianews.network/?p=292796)) และ 56% ระบุว่าขาดบุคลากรดิจิทัล ([Nation Thailand](https://www.nationthailand.com/business/40068656)) โดย SME พร้อมเพียง 17% (แหล่งเดียวกัน) ตัวเลขสองชุดนิยาม "การใช้ AI" ต่างกัน จึงอ่านเป็นทิศทางเท่านั้น ฟีเจอร์พิสูจน์: Task 4 (SAM 3.1 + VLM verify), Task 9 + Task 28 (แนะนำและแก้ข้อมูลอัตโนมัติ), Task 29 (anomaly ใช้เฉพาะภาพปกติ), Task 31 (workflow แบบลาก), Task 12 (เดโมครบวงจรในเครื่องเดียว) และต้องวัด "เวลาจากภาพชุดแรกถึง stream แรก" เป็น KPI ที่โชว์ได้

**สมมติฐาน 2: Sovereign by design (หลักฐานปานกลาง).** ข้อมูลชีวมิติเป็น sensitive ตาม PDPA และการส่งข้ามประเทศต้องปฏิบัติตามกฎ ([Tilleke](https://www.tilleke.com/insights/thailands-regulations-for-cross-border-personal-data-transfer-come-into-force/24/)) Roboflow ให้ data sovereignty แค่ US/EU และต้องเป็น Enterprise ([Roboflow pricing](https://roboflow.com/pricing)) แต่ยังไม่พบเอกสารที่บังคับ on-prem สำหรับธนาคารหรือโรงงานตรง ๆ และข้อกำหนด BoT AI Risk Management (ก.ย. 2025) ยังไม่ได้ตรวจเนื้อหาเรื่อง data residency ([Tilleke](https://www.tilleke.com/insights/thailand-insurance-industry-ai-and-privacy-regulatory-updates/25/)) ฟีเจอร์พิสูจน์: Task 26 (retention, face blur, ไม่ทำ face recognition เป็น default, audit การดู footage, residency), Task 35 (edge agent ทำงาน offline), Task 43 (blur ทะเบียน) และ DPA template ภาษาไทย ข้อควรระวัง: อย่าอ้าง "PDPA compliant" ในหน้า landing (Task 18 ใช้ข้อความ "Data stays in Thailand") จนกว่าจะผ่านการตรวจทางกฎหมาย เพราะ guideline เฉพาะ CCTV ยังเป็นร่างที่ไม่ผูกพัน ([HLC](https://hlc.com/en/publications/thailand-pdpc-consults-on-sectorspecific-pdpa-guidelines))

**สมมติฐาน 3: ขายผ่าน SI และผู้จัดจำหน่ายแบบ per-camera (หลักฐานปานกลาง).** Tapway (มาเลเซีย) ขาย Vision AI ในไทยผ่าน Advantech, Appomax และ S I Media โดยตั้งเป้า 500 camera license ใน 12 เดือน ([CRN Asia](https://www.crnasia.com/news/2025/distributor/vision-ai-software-developer-tapway-partners-three-thai-firm)) Ailytics (สิงคโปร์) ระดมทุน Series A 7.4 ล้านดอลลาร์ และมีกว่า 400 deployment ([Thailand Business News](https://www.thailand-business-news.com/?p=336534)) นั่นแปลว่าคู่แข่งภูมิภาคเริ่มแล้ว แต่ทั้งสองขายแอปสำเร็จรูป ไม่ใช่เครื่องมือสร้างโมเดลเอง ฟีเจอร์พิสูจน์: Task 24 (scoped key, SDK, webhook), Task 25 (usage metering → ราคาต่อกล้อง), Task 26 (RBAC สองระดับ ให้ SI จัดการหลายลูกค้า), Task 37 (MCP/agent API), Task 50 (เอกสารเสนอราคา THB) ยังไม่มีหลักฐานว่า SI ไทยรายใดพร้อมร่วมงาน ต้องเริ่มคุยกับ partner 2–3 รายเพื่อยืนยัน

**สมมติฐาน 4: Vertical pack แทนการเทียบ Roboflow ทุกฟีเจอร์ (หลักฐานอ่อนถึงปานกลาง).** Roboflow ขยับ 2026 เร็วมาก (Auto Label with Workflows, Active Learning, multi-model per version, MCP) ([Roboflow changelog](https://docs.roboflow.com/reference/changelog/changelog/july-2026.md)) การไล่ตามทุกข้อเป็นเกมที่แพ้ ส่วน Ailytics/Tapway เลือก vertical CCTV ฟีเจอร์พิสูจน์: Task 32/33/39/40 ที่ทำเป็นชุดเฉพาะภาค และเทมเพลตพร้อมใช้ (Task 48) แต่ไม่มีข้อมูล vertical-vs-horizontal ที่เทียบผลตอบแทนได้จริง ต้องยืนยันด้วยการขายนำร่อง 2 vertical

**สมมติฐาน 5: จัดซื้อสไตล์ไทย (หลักฐานอ่อนสุด).** depa เปิด grant AI/ดิจิทัลสำหรับธุรกิจ 15,600 ราย ปิดรับ 16 ม.ค. 2026 ([Thailand.go.th](https://www.thailand.go.th/issue-focus-detail/depa-targets-15600-businesses-with-ai-and-digital-grants-to-boost-competitiveness-in-southern-thailand)) และ voucher ดิจิทัลสำหรับ SME ([depa](https://www.depa.or.th/en/digitalservice/digital-transformation-fund/goals-and-areas)) แต่ยังไม่ได้ยืนยันเงื่อนไขปี 2026 และ LabelDesk ต้องเป็นผู้ให้บริการที่ผ่านการขึ้นทะเบียนก่อน ควรเป็น "ตัวช่วยปิดดีล" ไม่ใช่หัวใจของ value proposition ฟีเจอร์พิสูจน์: Task 50, UI ภาษาไทย (IBM Plex Sans + Anuphan ใน Task 11), support เวลาไทย

## Conclusion

ผลที่พลิกภาพเดิมคือ **ช่องว่างของ LabelDesk ไม่อยู่ที่ฟีเจอร์ labeling แล้ว แต่อยู่ที่ "ชั้นบน" และ "ชั้นข้าง"**: ชั้นบนคือการค้น curate และแก้ข้อมูลอัตโนมัติ (27, 28) ที่ทำให้คนที่ไม่ใช่ ML engineer ได้ผลดี ส่วนชั้นข้างคือการเชื่อมกับโลกจริงของโรงงานและทีม SI (PLC, กล้องอุตสาหกรรม, LINE, edge agent) ซึ่ง Roboflow ซึ่งเน้นตลาดโลกและ cloud/Enterprise ไม่ได้ทำให้ตลาดไทย และ Tapway/Ailytics ขายเป็นแอปสำเร็จรูป ช่องว่างตรงกลางจึงเปิดอยู่: เครื่องมือสร้างโมเดลเองที่ติดตั้งในไทยและส่งมอบผ่าน SI

สิ่งที่ยังไม่รู้และควรทดสอบก่อนลงทุนเต็มที่ มี 4 ข้อ: (1) anomaly good-only ใช้ได้จริงกับภาพ PCB/IC ของลูกค้าไทยหรือไม่ (2) SI ไทยพร้อมขายแบบ per-camera/per-line ของเราจริงหรือไม่ (3) ข้อกำหนด on-prem/residency ของธนาคารและโรงงานเป็นข้อบังคับหรือแค่ความชอบ (4) Roboflow จะลดราคาหรือเปิด region เอเชียหรือไม่ เนื่องจากมีรายงานว่าปรับราคาช่วง ก.ค.–ต.ค. 2026 ([usagepricing](https://www.usagepricing.com/blueprint/activity/roboflow-2026-10-04-core-price-cut-free-credits), แหล่งรอง ยังไม่ยืนยัน) ข้อ 1–2 ตอบได้ด้วยโปรเจกต์นำร่อง 4–6 สัปดาห์กับ design partner หนึ่งโรงงานและหนึ่ง SI

**ข้อจำกัดของรายงานนี้:** ใช้หน้า vendor และ search summary เป็นหลัก ส่วนใหญ่ไม่ได้เปิดอ่านเต็มหน้า (Labelbox, LandingLens, Supervisely, Edge Impulse, V7 Go เป็น lead ที่ยังต้องตรวจ); ชื่อโมเดลใน Auto Label list ของ Roboflow ยังไม่ยืนยัน; ไม่พบกรณีศึกษา bin-picking, pallet counting, เอกสาร OIC ฉบับจริง และข้อมูล MEA; ประเด็น LINE Notify ในข้อ 33 มาจากความรู้ทั่วไป ไม่ใช่โน้ตวิจัย; รายละเอียดการ implement ของ Task 7 (augmentation/preprocessing recipe) และ Task 22 ผู้เขียนไม่ได้เปิดอ่านเทียบกับ Roboflow ทีละ option จึงไม่ได้เสนอ parity task สำหรับจุดนั้น
