# YOLO26 PPE Model Guide

## Which files should I use?

Use only models under:

```text
models/production/
```

Do not use `models/archive/` unless you are reproducing an old experiment.

## Production model paths (v3 dataset, 4 classes)

Classes: `person`, `helmet`, `closed footwear`, `harness`

| Model | Task | Recommended weight | mAP50 | mAP50-95 |
|---|---|---|---:|---:|
| `small_detection` | Bounding-box detection | `production/small_detection/stage_2_final_fine_tuning/weights/best.pt` | 0.670 | 0.479 |
| `medium_detection` | Bounding-box detection | `production/medium_detection/stage_2_final_fine_tuning/weights/best.pt` | 0.693 | 0.507 |
| `small_segmentation` | Instance segmentation | `production/small_segmentation/stage_2_final_fine_tuning/weights/best.pt` | 0.566 | 0.389 |
| `medium_segmentation` | Instance segmentation | `production/medium_segmentation/stage_2_final_fine_tuning/weights/best.pt` | 0.599 | 0.431 |

Segmentation rows show box metrics; mask mAP50 is 0.509 (small) and 0.512 (medium).

Metrics source: `../artifacts/evaluation/yolo/production_v4_recipe/all_metrics.json`.

ONNX exports: `../artifacts/onnx_models/production/<model>.onnx`.

## Model selection

- Choose `small_detection` for a balanced detector (19.4 MB, 22 ms).
- Choose `medium_detection` for the best detection accuracy (mAP50 0.693).
- Choose `small_segmentation` for the fastest instance segmentation (8.6 ms).
- Choose `medium_segmentation` for the best segmentation quality.

`small` corresponds to YOLO26s. `medium` corresponds to YOLO26m.

## Why does each production model contain two stages?

```text
model_name/
├── stage_1_initial_training/
└── stage_2_final_fine_tuning/
```

### `stage_1_initial_training`

Initial 150-epoch training from upstream pretrained weights. The backbone starts partially frozen and uses the full augmentation recipe. (`medium_segmentation` early-stopped at epoch 117; best epoch 96.)

### `stage_2_final_fine_tuning`

A separate 50-epoch fine-tuning job initialized from stage 1 `best.pt`. All layers are unfrozen, the learning rate is lower, and augmentation is reduced.

The current evaluation and ONNX export use:

```text
stage_2_final_fine_tuning/weights/best.pt
```

## Why are old versions retained?

| Archive | Purpose | Production status |
|---|---|---|
| `version_1_initial_baseline` | Initial setup and hyperparameter tuning trials | Do not use |
| `version_2_improved_baseline` | Improved dataset preparation and longer training | Do not use |
| `version_2_5class` | Former production models trained on the v2 five-class dataset (person, helmet, boots, shoes, harness) | Do not use — different class schema |
| `version_3_adamw_experiment` | Incomplete AdamW optimizer comparison | Do not use |

They remain only for reproducibility and historical comparison.

## Framework-standard files

These names are generated by Ultralytics and intentionally remain unchanged:

- `weights/best.pt`: checkpoint with the best validation score
- `weights/last.pt`: checkpoint from the final epoch
- `args.yaml`: training arguments
- `results.csv`: metric history by epoch

## Loading a production model

```python
from ultralytics import YOLO

model = YOLO(
    "models/production/medium_detection/"
    "stage_2_final_fine_tuning/weights/best.pt"
)
```

For segmentation:

```python
model = YOLO(
    "models/production/medium_segmentation/"
    "stage_2_final_fine_tuning/weights/best.pt"
)
```
