## User story
As the champion running a 30-day pilot, I want five steps that tick themselves when the work is actually done, so that "we are nearly there" is a number instead of a feeling.

## UX flow (LabelDesk words)
1. **Home, first visit** (`/:ws`) — a `Card` at the top offers three intents: "Find defects", "Count people", "Read plates". Choosing one asks for a project name and creates a project with the matching class list and a suggested model family. [empty: the card appears once and stays out of the way after dismissal] [loading: the card renders with the buttons disabled and a one-line skeleton]
2. **`Start here` checklist** — five steps: upload 20 images, label 5, approve 3, train a model, deploy it. Each row shows the real count beside it ("12 of 20 images") and a link to the screen where the step happens; a step ticks only when the count reaches its target. [empty: before the first project, the checklist reads "Create a project to start the checklist." with `Choose an intent`]
3. **`Hide this checklist`** — the card collapses to one line above the project grid, "Show the start-here checklist", which restores it.
4. **A sample set** — when the deployment has no starter pack, the intent dialog says "A sample image set is not available in this deployment — upload 20 of your own and the checklist starts counting." rather than creating placeholder images.
5. **Flag off** — Home renders exactly as today.

## Backend changes
- Models/schema: `workspaces` gains `onboarding JSON` in `app/schema/identity.py` (`WORKSPACES`) holding `{intent, dismissed, started_at}`; existing rows read `null`, no backfill.
- Routers: `app/routers/onboarding.py` (new) — `GET /api/ws/{ws}/onboarding` returns `{intent, dismissed, steps: [{id, label, done, count, target, href}]}`; `POST …/onboarding/intent` (201: creates the project with its classes; 422 on an unknown intent); `POST …/onboarding/dismiss` and `DELETE …/onboarding/dismiss`.
- Services/jobs: `app/services/onboarding.py` (new) — `INTENTS = {"defects": {...}, "people": {...}, "plates": {...}}` (label, project type, class names, suggested family), `steps(db, ws) -> list[dict]` computed from `Image`, `ImageClass`/`n_annotations`, `TrainedModel` and `DeploymentAlias` counts, `state(db, ws)`, `start(db, c, intent, name) -> Project`, `dismiss(db, ws, value)`.
- Permissions + workspace isolation: `workspace.update` to start an intent or dismiss; `GET` needs `workspace.read`; the project is created in the calling workspace only, and counts never cross workspaces.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Tests to write first
pytest — `apps/backend/tests/test_onboarding.py`:
- `test_steps_are_derived_from_real_counts` — a fresh project → all five steps `done: false` with `count: 0`; after 20 images and 5 labelled images → the first two are `done: true` and the third is not.
- `test_a_step_never_ticks_from_a_flag_alone` — set `onboarding.intent` by hand → no step becomes done.
- `test_starting_an_intent_creates_classes` — `POST …/onboarding/intent {"intent": "plates", "name": "Gate"}` → 201, the project exists with the four plate classes and type `object-detection`.
- `test_an_unknown_intent_is_422` — `intent="astrology"` → 422 naming the three.
- `test_dismiss_and_restore_round_trip` — dismiss → `dismissed: true`; restore → `false`; a labeler's dismiss → 403.
- `test_another_workspace_counts_nothing` — workspace B holds 20 images → workspace A's checklist still reads 0.
- `test_flag_off_hides_all_four_routes` — with the flag off → every route 404 and Home behaves as today.

node — `apps/frontend/tests/onboarding-checklist.test.mjs`:
- `test_next_step_is_the_first_unfinished_row` — `nextStep([{done:true},{done:false,id:'label'}])` returns `label`.
- `test_progress_names_both_numbers` — `progressLine([{done:true},{done:false}])` is "1 of 5 steps done".
- `test_all_done_collapses_the_card` — `progressLine` on five done steps returns the finished sentence and `nextStep` returns `null`.

## Acceptance criteria
- [ ] The three intents create a project with the matching classes and never create placeholder images.
- [ ] Every checklist step is computed from stored counts and cannot be ticked by hand.
- [ ] Hiding the checklist survives a reload and the one-line restore puts it back.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no card, no Help line, routes 404, and Home is unchanged.

## Notes for the implementer
`sam3_auto_label/` is untracked (BEYOND §5), so there is no starter pack to copy into a new project and the dialog says so instead of inventing a sample set. Derive the steps in the API, not the browser: the same counts feed T-778's adoption view, and two derivations is how a checklist and a report start disagreeing.
