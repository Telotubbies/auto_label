## User story
As a workspace member, I want to know which library versions trained a model, so that I can rebuild the same environment instead of guessing why an export behaves differently.

## UX flow (LabelDesk words)
1. **Model detail → Built with** — a short list (framework and version, torch or onnxruntime and version, Python version, CUDA when present) and a "Download environment" link. [empty: an imported model with no recorded environment reads "Environment not recorded"] [loading: skeleton lines] [error: "Environment could not be read" plus retry]
2. **Download environment** — a `requirements.txt` with pinned versions, generated from the record, not from the current interpreter.
3. **Artefact zip** — the same file sits inside it, so the container files from T-938 install from it.

## Backend changes
- Models/schema: `apps/backend/app/schema/training.py` — one `ADD COLUMN` block, `trained_models.environment JSON DEFAULT '{}'`; `environment: Mapped[dict] = mapped_column(JSON, default=dict)` in `apps/backend/app/models/training.py`. Backfill `{}` for existing rows.
- Routers: `GET {P}/models/{mid}` gains `environment`; `GET {P}/models/{mid}/requirements` returns `text/plain` named `<model>-requirements.txt`. Both `project_ctx`, `project.read`.
- Services/jobs: `apps/backend/app/services/model_env.py` (new) — `capture(family: str) -> dict` returning `{"python", "packages": {name: version}, "cuda": str|None}` from `importlib.metadata.version` over a per-family table (`ultralytics → ["ultralytics", "torch", "torchvision"]`, `tensorrt → ["tensorrt", "onnx"]`, `hf → ["transformers", "torch"]`, `onnx → ["onnxruntime"]`, `vlm → []`), `to_requirements(env: dict) -> str`. Called by the training job when it sets `weights` so the record is written in the same transaction as the artefact.
- Permissions + workspace isolation: `project_ctx`; foreign model id is 404 through `_model`.
- Secrets/safefetch: none — no package names come from the request.
- OpenAPI: yes — `python tools/export_openapi.py`, `npm run gen:api-types`.

## Tests to write first
pytest — `apps/backend/tests/test_model_env.py`:
- `test_capture_records_the_python_version` — `capture("ultralytics")["python"]` equals `platform.python_version()`.
- `test_a_missing_package_is_recorded_as_absent_not_fatal` — with `torch` uninstalled the dict omits it and no exception escapes.
- `test_requirements_are_pinned` — every line of `to_requirements` contains `==` and no line is empty.
- `test_a_model_becoming_ready_carries_its_environment` — the training completion path stores a non-empty `environment`.
- `test_requirements_route_is_scoped` — the sibling workspace gets 404, and the response is `text/plain`.
- `test_a_model_without_an_environment_says_so` — `environment: {}` renders the empty sentence, and the route returns 404 rather than an empty file.

## Acceptance criteria
- [ ] A model trained after this card lists its framework, runtime and Python versions.
- [ ] "Download environment" returns a pinned `requirements.txt` that matches the record.
- [ ] An imported model with no record says "Environment not recorded" and offers no download.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged — no flag here: the fields are additive and the block renders nothing on its own.

## Notes for the implementer
Overlap: none. This is per-model capture; `apps/backend/requirements.txt` stays the deployment's own list and must not be edited by this card.
Do not scan imports and do not infer versions from the worker's pip freeze: six families means six fixed tables, and a wrong pin is worse than an absent one.
