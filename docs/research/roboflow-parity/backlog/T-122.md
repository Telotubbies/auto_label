## User story
As a labeler on a fixed camera, I want to duplicate a shape and to copy the previous image's whole label set in place, so that six identical boxes take six nudges instead of six drags.

## UX flow (LabelDesk words)
1. **Editor → Objects tab** — with one shape selected, `Ctrl/Cmd+D` and a new **Duplicate** button in the Stack order block both clone it, offset by 2% of width and height, clamped so the clone stays inside the image. The clone becomes the selection, the stack shows it front-most, and one undo removes it. [empty: no selection → the button is absent, `Ctrl/Cmd+D` does nothing] [error: the clone would land entirely outside the image → clamp to the nearest edge instead of refusing]
2. **Editor → Objects tab → "Repeat previous"** — sits under the Duplicate button, disabled with a tooltip "Open the previous image first" when `idx <= 0`, and when the previous image has no annotations. Clicking it fetches that image's labels, drops any whose class no longer exists in the project, and appends them at identical coordinates. [loading: "Copying 6 labels…" on the button] [error: fetch or class check fails → toast, nothing appended]
3. **Repeat onto an image that already has labels** — a confirm names both counts: "Add 6 labels from IMG_0031 to this image's 2?" with Cancel / Add.
4. **Result** — one undo step, one save, a toast "6 labels copied from IMG_0031". Copied shapes keep `source: "human"`; the log records `Repeat previous`.
5. **Undo scope** — undo/redo stay per image session (they already reset on image change, `Editor.tsx:360`): `Ctrl/Cmd+Z` after `→` never rewrites the previous image.

## Backend changes
- Models/schema: none — copies are ordinary annotations written through `PUT /api/images/{id}/annotations`.
- Routers: none. The previous image is read with the existing `GET /api/images/{image_id}` (`images.py:446`), which already enforces workspace and project scope.
- Services/jobs: none.
- Permissions + workspace isolation: the read and the write both go through `image_ctx`, so a previous-image id from another workspace is 404 and a labeler outside the assignment is 403.
- Secrets/safefetch: none.
- OpenAPI: no — no route or schema change.

## Frontend changes

## Acceptance criteria
- [ ] `Ctrl/Cmd+D` and the Duplicate button clone the selected shape with a 2% offset, select the clone and leave one undo step.
- [ ] Duplicate is impossible with no selection and while an annotation is locked (the lock message appears instead).
- [ ] Repeat previous appends the previous image's labels at identical coordinates, drops labels of deleted classes, and reports how many were copied.
- [ ] Repeating onto an image that already has labels asks first with both counts, and Cancel changes nothing.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: the features are tools inside the existing editor.
- [ ] Keyboard-only path: `b` → draw → `Ctrl+D` → `Ctrl+Z` → Tab to Repeat previous → Enter.

## Notes for the implementer
The offset is `dx = 0.02, dy = 0.02` in normalised units for every shape kind, applied to `x/y`, polygon points, `cx/cy` and keypoint triples alike; a clamped clone is better than a refused one. Repeat-previous is all-or-nothing: never append a partial set after a fetch or class-check failure.
