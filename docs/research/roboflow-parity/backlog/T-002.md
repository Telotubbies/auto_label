## User story
As the reviewer of any area-2 PR, I want the ingest, grid, split, version-freeze and deletion
guarantees pinned so that a query/import/metadata card cannot quietly break the duplicate pre-check,
the 2,000-file cap, the bulk bar or the cached health report.

## UX flow (LabelDesk words)
1. **Upload** — files are hashed in the browser, `POST /uploads/check` marks the already-present ones,
   the drop zone shows `N duplicates skipped`, and the run ends in one summary
   (`Uploaded N · duplicates skipped N · failed N`). [empty: no files chosen, Create stays disabled]
   [loading: per-batch progress] [error: per-file rows grouped by reason]
2. **Refusal** — over 2,000 files in one request or over the byte budget answers 413 before any row is
   written; over the plan's image count answers 402.
3. **Dataset** — the grid's selection bar appears with the count; Move split / Tag / Set status /
   Delete act on the selection; Delete asks `Delete N images?`.
4. **Annotate board** — an ingest becomes one card in Unassigned; moving it to Dataset approves its
   images.
5. **Health** — the report shows counts, class balance, dimensions, heat map and recommendations; a
   cached report carries `health_stale` and the job behind it; `POST …/health` queues one scan and a
   second call while queued does not queue another.
6. **Versions** — a version freezes the split each image had at generation; later project changes do
   not reach it.
