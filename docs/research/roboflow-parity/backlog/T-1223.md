## User story
As the merge captain, I want one wave-Q1 findings file that is deduped, severity-ranked and already split
into dispatchable fix cards, so that the next merge batch starts with a queue instead of a debate.

## UX flow (LabelDesk words)
1. **Collect** — the four reports (areas 1–3) and the five journey results are read; any finding without
   evidence is rejected back to its author.
2. **Dedupe** — same root cause becomes one finding; the merged finding lists every screen it touches.
3. **Severity** — S1–S4 per the program, assigned by R13 and reviewed by R19 for anything accessibility.
4. **Fix cards** — one ready-to-dispatch card stub per S1/S2 in the same file, `_BRIEF.md` shape, ≤ 3 h,
   exclusive files, with the failing spec named as its regression test.
5. **Owner list** — questions only the owner can answer (Thai review, a pricing claim, a real-hardware
   claim) are separated from fixes.
6. **Release note** — `docs/qa/releases/q1.md` states what shipped, the metric table, the open S1/S2 and
   the accepted S3s.

## Acceptance criteria
- [ ] Every finding from Q1 is either in the file or explicitly rejected with the missing evidence.
- [ ] Duplicates are merged by root cause, not by screen; each merged finding lists its screens.
- [ ] Every finding has the full format: id, severity, persona, route, build, steps, expected, actual,
      rule, measure, evidence, proposed card.
- [ ] Every S1/S2 has a dispatchable card stub, ≤ 3 h, with exclusive files and a named failing test.
- [ ] The metric table covers J1–J5 (steps, time, errors) and the three SUS-8 persona scores.
- [ ] The release note states the open S1/S2 count; it does not call the wave shipped while an S1 is open.
- [ ] Empty, loading and error states: their findings are included, not only the happy-path ones.
- [ ] Owner questions are separated and none is answered by an agent.
- [ ] Workspace isolation: a cross-workspace finding is S1 and is escalated to R7, never filed as S2.
