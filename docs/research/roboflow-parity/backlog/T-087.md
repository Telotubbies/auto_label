## User story
As an annotator, I want to see an image's dimensions, split, batch and dates beside the canvas and to
download, cover or remove it from one menu, so that "why is this in test?" is answered where the boxes are.

## UX flow (LabelDesk words)
1. **Editor · right inspector · Attributes** — rows: dimensions (`1920 × 1080`), file size, uploaded,
   last modified, split (`test`), batch (`2026-11-17 · shift`), assignee, annotations count.
   [empty: an image with no batch reads "Ungrouped"] [loading: 7 skeleton rows while the image resolves]
   [error: metadata failed to load → the rows show "—" with a retry link]
2. **Editor · header menu (⋯)** — **Download image**, **Find similar** (T-088), **Use as cover**,
   **Remove from project**. Download saves the original file with the stored name. [error: a missing file →
   "This image's file is missing" and the row offers Remove]
3. **Editor · header menu · Use as cover** — the project card on Home shows this image; the menu item reads
   "Cover image" and is disabled with a check when it already is.
4. **Editor · header menu · Remove from project** — confirm "Remove `IMG_0421.jpg` from this project? The
   file and its labels are removed."; on success the next image opens.

## Backend changes
- Models/schema: `Project.cover_image_id VARCHAR(32) NULL` in `models/project.py` (AttributeError-safe
  name) + one `PROJECTS` entry `"cover_image_id": "VARCHAR(32)"` in `schema/dataset.py`.
- Routers:
  - `apps/backend/app/routers/images.py` — `GET /api/images/{image_id}/download` returns the stored file
    with `Content-Disposition: attachment; filename="<safe name>"`; `404` when the file is gone.
  - `apps/backend/app/routers/projects.py` — `ProjectPatch` accepts `coverImageId` (validated to be an
    image of this project, else 404); `project_out` returns `coverImageId` and `coverThumb`.
  - `image_out` gains `size` (bytes) and `batchName` (joined once per list page; the editor's single-image
    read joins the batch row).
- Services/jobs: none.
- Permissions + workspace isolation: download and cover are under the existing `image_ctx`/`project_ctx`;
  cover needs `c.perm("project.review")`; a foreign image id never resolves.
- Secrets/safefetch: none.
- OpenAPI: yes — one route + fields.

## Acceptance criteria
- [ ] The attributes block shows dimensions, size, dates, split, batch, assignee and count with a loading
      and a missing-file state.
- [ ] Download returns the original bytes with the stored filename; a missing file is a readable 404.
- [ ] Cover is per project, validated, and shown on the project card; removing it is not offered here.
- [ ] Remove from project keeps today's behaviour (confirm, then next image) and is not a new delete path.
- [ ] Empty, loading and error states above render.
- [ ] Flag off: n/a — the block and menu are additive; without them the editor is exactly as today.
- [ ] Workspace A cannot see or change workspace B's data (a foreign image or project id is refused).

## Notes for the implementer
Reuse `download()` from `lib/api/client.ts` — it already streams with the bearer header and reads the
filename from `Content-Disposition`. Preprocessed/augmented variants exist only inside a generated version
(`version_dir`), so this menu downloads the original bytes; the export path (T-089) is where a version's
variants leave the system. Prev/next image and the "view source image" toggle stay with the editor shell
card (`3-F3.1`) — do not add a second header navigator here. Do not add "use as cover" to the grid; the
editor menu is the only entry point.
