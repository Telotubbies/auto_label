## User story
As an admin, I want one key row to carry every risk state — protected, disabled, default, due for rotation,
scoped — so that I can audit credentials without opening each one.

## UX flow (LabelDesk words)
1. `GET /api/ws/{ws}/keys` returns one row per key:
   `{id, name, prefix, scopes, publishable, created, last_used, created_by, protected, disabled_at,
   is_default, in_use, rotation_due, metadata, owners: [{id, name}]}`.
2. `in_use` is computed (no default key set and this row is the fallback) and is `false` for a disabled key.
3. `[empty]` `{keys: []}` — the screen owns the explanatory block.
4. `[error]` a key created before this card has NULL for every new column and renders as `protected: false`,
   `disabled_at: null`, `rotation_due: null`, `metadata: {}`, `owners: []` — no backfill script.

## Backend changes
- Models/schema: `ApiKey` gains `protected: bool = False`, `disabled_at: float | None`, `is_default: bool = False`,
  `rotation_due: float | None`, `metadata: dict | None`, `owner_ids: list | None`, `folder_id: str | None`
  (the last is used by T-395). Append to `API_KEYS` in `app/schema/identity.py`:
  `{"protected": "BOOLEAN DEFAULT FALSE", "disabled_at": "FLOAT", "is_default": "BOOLEAN DEFAULT FALSE",
  "rotation_due": "FLOAT", "metadata": "JSON", "owner_ids": "JSON", "folder_id": "VARCHAR(32)"}`.
- Routers: `GET /api/ws/{ws}/keys` (`routers/workspaces.py`) is rewritten to build the payload from
  `services/keys.row(db, key)`; status 200; `403` without `workspace.keys`; `404` for a foreign workspace slug.
- Services/jobs: `app/services/keys.py` (new) — `row(db, key) -> dict`, `scopes_of` re-exported from `apikeys`,
  `in_use_row(db, ws) -> ApiKey | None` (a default key, else the oldest enabled full-access key),
  `is_disabled(key) -> bool`, `masked(key) -> str` (`prefix + "…"`, never the secret).
- Permissions + workspace isolation: `workspace.keys`; every select filters `ApiKey.workspace_id == c.ws.id`.
- Secrets/safefetch: the stored `hash` is never returned; only `prefix` and a mask leave the API.
- OpenAPI: yes.

## Frontend changes

## Tests to write first
pytest — `apps/backend/tests/test_key_payload.py`:
- `test_row_carries_every_state` — a protected, default key with metadata returns all fields.
- `test_in_use_falls_back_to_the_oldest_enabled_key` — two full keys, none default → the older one is `in_use`.
- `test_disabled_key_is_never_in_use` — only key disabled → no row carries `in_use`.
- `test_prefix_only_no_secret` — the payload contains no `key` or `hash` field.
- `test_old_rows_read_as_null_and_false` — insert a row with NULL new columns → stable payload.
- `test_foreign_workspace_keys_are_not_listed` — two workspaces → each sees only its own.
- `test_flag_off_returns_the_six_field_payload` — flag off.

## Acceptance criteria
- [ ] Every state the key table needs arrives in one list call, with no per-row request.
- [ ] A stored secret is never in the payload; only the prefix and a mask leave the API.
- [ ] Empty, loading and error states above all render (empty list, pre-existing rows, 403).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the previous payload shape and the previous table behaviour.
- [ ] Existing-database test: `schema.apply` adds all seven columns idempotently to a database that already has keys.

## Notes for the implementer
`in_use` is derived on read, never stored, so a revoked default cannot leave a stale badge. The mask is
`prefix + "…"` — the reveal in T-389 is a UI-only affordance over a key the admin already typed.
