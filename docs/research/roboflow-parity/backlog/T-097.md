## User story
As a reviewer, I want to see exactly which images were skipped as duplicates, and a re-uploaded image to
come back with its old labels, so that "uploaded 936, saved 120" is answerable and deleting is not scary.

## UX flow (LabelDesk words)
1. **Upload result sheet** — "Added 37 · duplicates 3 · failed 0" expands to the three skipped names with
   their batch, and a "Download list" link writes a CSV. [empty: zero duplicates → the expander is absent]
2. **Upload result sheet** — an image whose row exists but was removed comes back as "Restored 2 images with
   their labels" rather than as a new or skipped image. [error: a restore whose file is gone → the row is
   re-ingested and reported as "added", never as restored without bytes]
3. **Dataset · Images** — a restored image keeps its previous batch, split, tags, metadata and review
   status; the grid shows it exactly where it was. [loading: the count resolves with the upload response]
4. **Dataset · Images** — after a remove, the trash-less rule is stated once in the confirm:
   "Re-uploading the same file restores its labels."

## Acceptance criteria
- [ ] Every skipped duplicate is named with its batch, not only counted.
- [ ] Re-uploading a removed image restores the row with labels, tags, metadata, split, batch and review
      state, and does not create a second row.
- [ ] A restore whose bytes are gone re-stores the file and meters it once.
- [ ] Dedupe stays per project and per workspace as today; another project's copy is untouched.
- [ ] Empty/loading/error states above render (no expander at zero, restore line on success).
- [ ] Flag off ⇒ today's aggregate counts only, and a removed image returns blank.
- [ ] Workspace A cannot see or change workspace B's data (404 for a foreign project id).

## Notes for the implementer
The two hash sets are different on purpose: the live set answers "skip", the all-rows set answers "revive".
Do not merge them, or a removed image would silently stay removed. Revival must not resurrect an image whose
project moved the file intentionally — the row is the source of truth.
