## User story
As a labeler, I want one zoom level and one set of view settings to survive image changes, so that inspecting forty small defects does not mean re-zooming forty times.

## UX flow (LabelDesk words)
1. **Editor** (`/:ws/:project/images/:imageId`, today `routes/project/index.tsx:15`; wave E moves it to `/:ws/p/:project/annotate/:imageId`) — the wheel scales the canvas, `+` / `-` step through 1.2×, `0` fits the viewport, `1` jumps to 100%. [empty: the image list is empty → previous/next are disabled and the stepper reads the fitted scale] [loading: image bitmap still decoding → keep the previous scale, no jump] [error: image fails to load → see T-163's decode state]
2. **Floating glass bar, bottom centre** — the existing stepper (`Editor.tsx:1250-1258`) gains one padlock toggle, `aria-label="Lock zoom"`, pressed state persisted. While locked the tooltip reads "Zoom locked — new images open at this scale".
3. **Header / right thumbnail strip** — `←` / `→` or the arrows move to the next image; with the lock on, the new image opens at the locked scale, with it off it opens fitted.
4. **Canvas** — `Esc` clears a half-drawn box, polygon or smart-polygon point set first; a second `Esc` saves if dirty and leaves to `/:ws/:project/annotate`. [error: save fails → stay on the image and show the save-failed bar from T-121]
5. **Session memory** — brightness/contrast (T-138), the zoom lock, the active assist id (T-139) and the class-filter text persist for the tab session. Tool mode, selection, multi-selection and the open panel do not.

## Acceptance criteria
- [ ] Locking zoom shows a pressed padlock, and the next image opens at the locked percentage; unlocking returns to fit.
- [ ] `+`, `-`, `0`, `1` zoom the editor while the canvas or the page has focus and do nothing while a text field is focused.
- [ ] `Esc` cancels drawing first, then leaves to the board, and unsaved edits are saved before the navigation.
- [ ] Brightness/contrast and the locked zoom survive `→` navigation and a full page reload of the same tab session; tool mode and selection do not.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — unchanged here: this card adds no endpoint.
- [ ] No flag: the change is editor-local state inside an already-shipped screen, so there is no flag-off surface to hide.
- [ ] Keyboard-only path works: `1` → `+` → `→` → draw → `→` → `Esc`.

## Notes for the implementer
Fit keeps today's `0.92` padding (`Editor.tsx:274`); the lock stores the *resulting* scale, not a percentage string, so a later window resize rebuilds fit from the same number. `Esc` order is draw-state → selection → leave, and it never leaves while a save is in flight.
