## User story
As a reviewer, I want the timeline of the image in front of me with each changed field spelled out, so that I can put a label set back the way it was without asking an engineer to read a database.

## UX flow (LabelDesk words)
1. **Editor → right rail → `History`** (`/:ws/p/:project/annotate`) — a tab beside the shipped panels, opened by the tab or by `i`. Newest first, grouped by day with the day as a small heading. [loading: five skeleton rows] [empty: "No changes since upload." / "ไม่มีการเปลี่ยนแปลงตั้งแต่การอัปโหลด"] [error: "Could not load this image's history." + **Try again**]
2. **A row** — actor, time, and one line per delta: `"box 3: person → worker"`, `"status: review → approved"`, `"box 5 added"`, `"tags: +night-shift"`. A row with no delta (a version export) reads its action in words.
3. **`Restore this label set`** — on an older revision, visible to reviewers only; a confirm reads `"Restore the label set from 14:20? This adds a new entry; nothing is erased."` and the rail reloads with the restore as the newest row. [error: 409 from the server prints its class sentence inline]
4. **Version header → `History`** (`/:ws/p/:project/versions`) — the same panel in a `Modal`, headed `"Built from 1,204 images · exported 3 times · last served 2 hours ago"` with a linkable line per event. [empty: "This version has no recorded events yet."]
5. **Model header → `History`** — the same `Modal` for a model's create, train, export and alias events.
6. **Keyboard** — `i` toggles the rail's History tab; `Esc` closes the modal without changing anything.

## Acceptance criteria
- [ ] The editor rail opens a History tab listing this image's revisions newest first, grouped by day, with actor and time.
- [ ] Every delta reads as a sentence naming the object, the field and both values; an entry with no delta names its action.
- [ ] A reviewer restores an older label set and the rail shows the restore as a new newest entry, with the labels equal to the restored revision.
- [ ] Empty, loading and error states above all render: "No changes since upload.", five skeleton rows, the load error with **Try again**, and the 409 class sentence inline.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — a 404 renders the neutral unavailable line.
- [ ] Flag off ⇒ no tab, no `i`, no version or model History button, and the editor rail is exactly today's.

## Notes for the implementer
The restore path already exists server-side (a normal save), so the UI must not touch annotations directly: post the revision id and refetch. Print the delta, never a raw JSON blob — the shipped Details expander on the audit page already shows JSON, and a second raw view is what makes this panel unreadable on a factory tablet. If `i` is already bound in `shortcuts.ts`, drop the binding rather than remapping someone's habit.
