## User story
As a returning user with a bookmark, I want `/w/ppe/annotate` and the new `/w/p/ppe/annotate` both to open the same screen, so that the URL prefix can change without breaking a link someone saved or a test that asserts it.

## UX flow (LabelDesk words)
1. **Any project URL** — `/:ws/p/:project` opens the project overview; `/:ws/p/:project/upload|annotate|dataset|train|models|deploy|settings` open the stage screens; `/:ws/p/:project/annotate/:imageId` opens the editor and keeps `status`, `batch` and `review` in the query.
2. **An old URL** — `/:ws/:project/browse` lands on `/:ws/p/:project/dataset`; `/:ws/:project/images/:id?status=done&batch=b1` lands on `/:ws/p/:project/annotate/:id?status=done&batch=b1`; `/:ws/:project/versions` lands on `dataset?tab=versions`, `/:ws/:project/model-insights` on `train?tab=models`, `/:ws/:project/streams` on `deploy?tab=streams`. The redirect is `replace`, so Back does not bounce. [error: a project slug that does not exist still renders "Project not found" on the new path, not a redirect loop]
3. **A workspace page whose name looks like a project** — `/w/models`, `/w/settings/members` and `/w/p/…` never resolve as a project; the reserved-segment list gains `p` and the test pins it.
4. **The project named `p`** — its upload page is `/w/p/p/upload` and it resolves: the segment after `p/` is the project, the segment before it is the prefix.

## Acceptance criteria
- [ ] `/w/p/ppe` renders the project overview; `/w/p/ppe/annotate` renders the board; `/w/p/ppe/annotate/<id>?status=done` opens the editor on that slice.
- [ ] Every legacy URL lands on its new screen with a `replace` navigation and no visible flash of a 404.
- [ ] A bookmark with a query string keeps it through the redirect (image, batch, review and status params).
- [ ] A workspace page is never read as a project: the reserved-segment test and the shell's `useMatch` agree.
- [ ] Empty, loading and error states above all render: the redirect renders nothing (no spinner), and an unknown project renders the existing "Project not found".
- [ ] Workspace A cannot see workspace B's data: the redirect only re-shapes the path; `PermGate` and the 404 from `/project` are unchanged.
- [ ] No flag: the change is additive and reversible in one commit; the legacy branch is what makes it safe.

## Notes for the implementer
Do not duplicate the child route list — build it once as `PROJECT_CHILDREN` and mount it under `p/:project`, or the two trees drift the first time a page is added. `p` is reserved in the shell set but not in the backend slug list: a project created before this card with the slug `p` still resolves at `/w/p/p`, which the round-trip test pins.
