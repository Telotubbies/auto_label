## User story
As the customer's privacy officer, I want a case for each request with its own clock, so that a PDPA request is answered from a record instead of a spreadsheet and a personal inbox.

## UX flow (LabelDesk words)
No screen in this card (T-752 owns the workbench):
1. **Opening a case** — `POST /api/ws/{ws}/compliance/requests {kind: "access" | "erasure" | "objection", subject_label, identifiers: ["Somchai Jaidee", "EMP-4471", "img_9f2a"]}` answers `{id, due, days_left: 30, status: "open"}`. The identifiers are free text: a name, a staff id, an email, one reference frame — whatever the controller was given.
2. **The list** — `GET /compliance/requests` returns newest first with `days_left`, and a negative `days_left` reads `"4 days overdue"` in the workbench. [empty: "No requests yet — nothing is due." / "ยังไม่มีคำขอ — ไม่มีกำหนดที่ต้องดำเนินการ"]
3. **A refusal** — a case may be set to `refused` with a note, and the note is printed on the case, because a refusal without a stated reason is the request the regulator reads first.
4. **A case may not be reopened** — `PATCH` with `status: "open"` on a closed case is 409 `"A closed request cannot be reopened — open a new one."`
5. **Every step is audited** — `dsar.create` and `dsar.status` rows name the case id and the new status; the case itself never stores the subject's data beyond the identifiers the officer typed.

## Backend changes
- Models/schema: `DsarRequest` appended to `app/models/compliance.py` — `id (PK)`, `workspace_id (FK CASCADE, index)`, `kind VARCHAR(16)`, `subject_label VARCHAR(200)`, `identifiers JSON`, `received FLOAT`, `due FLOAT`, `status VARCHAR(16) default "open"`, `note TEXT default ""`, `created_by (null)`, `closed FLOAT null`. No `ADD COLUMN`.
- Routers: `app/routers/compliance.py` (new), prefix `/api/ws/{ws}`, `dependencies=[Depends(require_flag("task_dsar"))]` — `GET /compliance/requests`, `POST /compliance/requests`, `GET /compliance/requests/{id}`, `PATCH /compliance/requests/{id}` (`status`, `note`); 422 for an unknown kind, 404 for a foreign id, 409 for an illegal transition.
- Services/jobs: `app/services/dsar.py` (new) — `CLOCK_DAYS = 30`, `STATUSES = ("open", "found", "exported", "erased", "refused", "closed")`, `create(db, ws, actor, kind, subject_label, identifiers) -> DsarRequest` (trims, caps 10 identifiers of 200 chars each, dedupes), `days_left(request, now) -> int`, `advance(db, ws, request, status, note) -> DsarRequest` (forward-only through `ORDER`, refuses `open` from a closed state), `out(db, request) -> dict`.
- Permissions + workspace isolation: `c.perm("workspace.update")` (owner/admin) on every route — no new permission line in `rbac.py`; every query filters `workspace_id == c.ws.id`, so a foreign case id is 404.
- Secrets/safefetch: none — the identifiers are the controller's own input and are stored plainly, which is why the card caps them and never asks for a national id number.
- OpenAPI: yes — four routes and the case shape.

## Tests to write first
pytest — `apps/backend/tests/test_dsar_case.py`:
- `test_a_case_starts_open_with_thirty_days` — `POST` answers `status: "open"`, `days_left == 30`, and `due == received + 30 days` (within a second).
- `test_identifiers_are_trimmed_deduped_and_capped` — ten repeated and spaced identifiers become two; eleven distinct is 422; a 201-character identifier is 422.
- `test_an_unknown_kind_is_422` — `kind: "delete-account"` is refused and no row is written.
- `test_a_closed_case_cannot_be_reopened` — `PATCH` to `refused` then to `open` is 409 whose detail contains `cannot be reopened`.
- `test_days_left_goes_negative_and_is_reported` — a case with `due` in the past answers a negative `days_left` and is not deleted.
- `test_every_step_is_audited` — one create and one status change leave `dsar.create` and `dsar.status` rows naming the case id.
- `test_a_foreign_case_is_404` — a case id from another workspace is 404 on read and on patch.
- `test_flag_off_leaves_no_surface` — with the flag off all four routes are 404 and no row can be created.

## Acceptance criteria
- [ ] A case records kind, subject label, identifiers, received and due, and answers a `days_left` count that goes negative past the due date.
- [ ] Status moves forward only; a closed case cannot be reopened and a refusal carries a note.
- [ ] Every create and status change writes an audit row naming the case.
- [ ] Empty, loading and error states above all render: an empty list, a 422 naming the offending identifier, and a 404 for a foreign case.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no compliance routes, no stored case, and the workspace behaves exactly as today.
