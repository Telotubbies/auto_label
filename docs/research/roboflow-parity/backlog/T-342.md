## User story
As a Python developer, I want either to call the server from my own process or to load an exported model inside it with the same result shape, so that moving from a notebook to a service is a constructor change.

## UX flow (LabelDesk words)
1. **Server call** — `LabelDesk().workflow(project, workflow_id, image="photo.jpg")` posts to T-316's invoke route and returns the envelope's `outputs`; `wait=True` polls until a slow run finishes, `raise_on_error` is the default so a 422 raises `LabelDeskError(422, "image is required")`.
2. **In-process** — `from labeldesk import load_model; m = load_model("models/ppe/best.onnx"); m.infer("photo.jpg")` returns the same `{"predictions": [...], "image": {...}, "time": ...}` the server returns, because it calls the same detector code the self-hosted image runs (`apps/inference/detect.py:build_detector`).
3. **`[error]` a missing backend** — loading a `.pt` without `ultralytics` raises `LabelDeskError(0, "the ultralytics backend is not installed; pip install labeldesk[gpu]")` instead of an `ImportError` traceback.
4. **`[empty]` an empty model directory** — `load_model("models/")` with no supported file raises `LabelDeskError(0, "no model files found in models/")`, the same sentence the container logs.
5. **Same model, two paths** — one docstring example per path in `packages/sdk/README.md`, each five lines, so the comparison is visible.

## Notes for the implementer
Import the detector from `apps/inference/detect.py` rather than reimplementing the mapping — that is the one place where the "same shape" promise is kept. Do not add a second server: `load_model` runs in the caller's process and never binds a port.
