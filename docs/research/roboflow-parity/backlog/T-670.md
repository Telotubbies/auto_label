## User story
As a quality engineer at a plant with three lines, I want to create a site, lines under it and stations under a line, so that "Line 2 / Press / Infeed" is found by the name on the plant drawing and one station row answers which model is on that cell.

## UX flow (LabelDesk words)
1. **Sites** (`/:ws/sites`, rendered by T-671) — the user creates `โรงงานบางปู`, then `ไลน์ 1`, then `สถานี Press · Infeed` under it. [empty: `ยังไม่มีไซต์ — เริ่มจากเพิ่มไซต์แรกของโรงงาน`] [loading: `กำลังโหลดโครงสร้างโรงงาน`] [error: `โหลดโครงสร้างไม่สำเร็จ — ลองอีกครั้ง`]
2. **A station is created with a project** — the form asks for the project it inspects, the model ref, the threshold and the reject action. A model ref outside that project's registry is refused in the form, not saved and broken later. [error: `โมเดลนี้ไม่พร้อมใช้งาน — เลือกโมเดลที่เทรนเสร็จแล้ว`]
3. **A camera is attached to a station** — the station's camera list is the set of streams whose `station_id` points at it; attaching a stream from another workspace fails as if it never existed.
4. **A station delete** — cameras are detached first and the streams themselves stay; the confirm text names the count. [error: `ลบสถานีไม่สำเร็จ — ยังมีกล้องผูกอยู่`]

## Backend changes
- Models/schema: `app/models/plant.py` (new) — `PlantSite(id, workspace_id, name, created)` `UniqueConstraint(workspace_id, name)`; `PlantLine(id, site_id, workspace_id, name, created)` `UniqueConstraint(site_id, name)`; `PlantStation(id, line_id, workspace_id, project_id, name, model_ref, threshold, reject_action, reasons, shift, created, updated)` `UniqueConstraint(line_id, name)`, `project_id` **not null**, `reject_action` `log|signal|stop` default `log`, `reasons` JSON list default the five plant defaults, `shift` JSON default `{}`. Register the module in `models/__init__.py` (import + name re-export + `DOMAIN_MODULES`); `Base.metadata.create_all` in `bootstrap.py` creates the tables. `Stream.station_id` nullable `VARCHAR(32)` is an `ADD COLUMN` entry in `app/schema/streams.py` `STREAMS`.
- Routers: `app/routers/plant.py` (new), prefix `/api/ws/{ws}/plant`, `Depends(ws_ctx)`, router-level `Depends(require_flag("task_plant_hierarchy"))`; `GET /sites` (site + line + station counts), `POST /sites` (201), `DELETE /sites/{id}`, `POST /sites/{id}/lines` (201), `GET /lines?site=`, `POST /lines/{id}/stations` (201), `GET /stations?line=`, `GET /stations/{id}` (station + cameras + today's counts), `PATCH /stations/{id}` (`model_ref`, `threshold` 0–1, `reject_action`, `reasons` max 12 × 64 chars, `shift`), `POST /stations/{id}/cameras` `{stream_id}` (200), `DELETE /stations/{id}/cameras/{stream_id}`. 409 duplicate name, 400 unknown model ref or bad body, 404 unknown id.
- Services/jobs: `app/services/plant.py` (new) — `station_counts(db, station, day_start) -> {"cameras", "events_today", "rejects_today"}`, `attach_stream(db, station, stream)`, `detach_stream(db, stream)`; validation of `model_ref` reuses `adapters.resolve(ref, db, workspace_id=c.ws.id)` and the `("ultralytics", "tensorrt")` family allowlist. No job.
- Permissions + workspace isolation: reading a site/line/station needs `project.read` on the station's project; every mutation calls `apply_project_role(c, station_project)` then `c.need("admin")`; every query filters `workspace_id == c.ws.id`, and an id from another workspace is a 404 — never 403.
- Secrets/safefetch: none — no URL is fetched and no credential is stored on a station.
- OpenAPI: yes — new router and schemas; regenerate `openapi.json` and `api-types.gen.ts` last on the branch.

## Acceptance criteria
- [ ] A site, its lines and a line's stations are created, listed and deleted through `/api/ws/{ws}/plant`, and each station names the project it inspects.
- [ ] A station stores a model ref, a threshold, a reject action and its reason codes; an unknown model ref is refused with 400 before anything is written.
- [ ] A camera is attached and detached, and `GET /stations/{id}` returns its cameras and today's event and reject counts.
- [ ] Empty, loading and error states above all render — this card returns `[]` for an empty plant and the two screens in T-671 own the three states.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the whole `/plant` prefix is 404 and stream create/update behaves exactly as today.

## Notes for the implementer
`PlantStation.project_id` is **not null**: a station inspects one project's data, reuses that project's model registry for validation, and a plant with three lines has three projects — the site and line levels stay workspace-scoped so a later roll-up can still cross lines. `reasons` defaults to `["scratch", "dent", "contamination", "wrong part", "other"]` in that order, and `threshold` defaults to `0.5`. Do not add `site_id`/`line_id` columns to `Stream`: the station is the only attachment point, so a camera cannot belong to two lines.
