## User story
As a project owner, I want named metric thresholds that produce a pass/fail verdict per model, so that a
release decision is a rule everyone can read instead of a judgement on two decimals.

## UX flow (LabelDesk words)
1. **Project settings → Models → Release rules** — `/:ws/p/:project/settings` gains a section: rules in a
   table with metric, comparator, value, "applies to" (a class or all), and the last model it blocked.
   [empty: "No release rules" plus *Add a rule* and three suggested rules for the task — detection:
   "*mAP50 ≥ 0.80*, *recall ≥ 0.85*, *median latency ≤ 250 ms*"] [error: "Rules could not be saved: <reason>"
   with the previous table unchanged]
2. **Add a rule** — metric select (limited to the metrics the task actually produces), comparator
   `≥ / ≤`, a number, and an optional class. [error: a metric the task does not produce is absent from the
   select, and a hand-posted one is a 400 that names the four that exist]
3. **A model is judged** — on save, every evaluated model in the project is re-judged; the Models list gains
   a *Gate* column: green *Pass*, red *Below gate*, grey *No evaluation*.
4. **Read the verdict** — the model's Evaluation panel puts the rule rows above the KPI strip, each with its
   value and the gap: "recall(helmet) 0.71 — 0.19 below 0.90". [empty: a rule whose class was removed reads
   "class no longer exists" and the verdict is *Cannot judge*, never a pass]
5. **Delete a rule** — the column stays but the verdict becomes *No rules*.

## Backend changes
- Models/schema: new table in `apps/backend/app/models/evaluation.py` — `ReleaseRule(id, workspace_id,
  project_id, metric, comparator, value, class_name NULL, created, created_by)`, unique
  `(project_id, metric, class_name)`. Same module as T-946, appended by this card.
- Routers: new `apps/backend/app/routers/release_rules.py` (new), `P = "/api/ws/{ws}/projects/{project}"`:
  `GET {P}/release-rules` → `{rules: [...], metrics: [{key, label, comparator}]}`; `POST {P}/release-rules`
  body `{metric, comparator, value, class_name?}` → 201; `DELETE {P}/release-rules/{id}` → 204. 400 for an
  unknown metric for the project's task, a comparator other than `gte`/`lte`, a value outside `0..1` for a
  ratio metric, or a class not in the project's classes; 404 for a foreign id.
- Services/jobs: `apps/backend/app/services/release_rules.py` (new) —
  `verdict(db, project, model) -> {"status": "pass"|"fail"|"no_evaluation"|"no_rules"|"cannot_judge",
  "rules": [{metric, comparator, value, actual, delta, class_name, status}]}`; `metrics_for(task)` maps the
  task to the metric keys `services.evaluate` actually stores (`AP50`, `AP`, `f1_best.precision`,
  `f1_best.recall`, `latency_ms`, and per-class `per_class[].AP`). Counting is read-only; no job.
- Permissions + workspace isolation: read `project.review`, write `c.need("admin")`; a rule or model from
  another project is a 404.
- Secrets/safefetch: none. Dependency: none added (no `mlflow-skinny`), so no
  `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] A stored rule yields pass/fail per model with the actual value and the signed gap.
- [ ] A rule naming a missing class yields `cannot_judge`, never a pass.
- [ ] A metric the project's task does not produce is refused at write time with the valid set named.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
