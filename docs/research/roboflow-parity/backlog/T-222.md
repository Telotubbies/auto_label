## User story
As an ML engineer, I want the version page to state the recipe the model actually used and let me lift that recipe onto newer data, so that retraining after new labels is one click instead of twenty guesses.

## UX flow (LabelDesk words)
1. **Version detail → Recipe** — three ordered blocks: *Preprocessing* (one line per step, in run order), *Augmentation* (ops with their numbers, or "None"), *Output* ("3× · train only"). Above them: "Frozen at generation — this recipe cannot change for this version." [empty: "No preprocessing and no augmentation — the source pixels, unchanged."] [loading: a three-line skeleton] [error: "This version's settings could not be read." with the reason]
2. **Lock explanation** — a lock icon with the sentence: "Changing augmentation at train time would be a silent lie: the pixels were already written." and a link to *Reuse this recipe* for the opposite action.
3. **Reuse this recipe** — opens the wizard prefilled from this version's settings (normalised), with a banner: "Prefilled from v3. Nothing is generated until you press Create." [loading: the wizard opens with the counts already cached] [error: a settings object that normalises to conflicts opens on the offending step with T-193's messages]
4. **Data is not copied** — the banner states it: "The recipe travels; the images do not."
5. **Legacy recipe** — a `contrast: true` / flat augmentation version renders as its canonical equivalent, with a small "read as: contrast stretch, 2 augmentations" note.

## Backend changes
- Models/schema: none — reuse reads `Version.settings` and never writes a version.
- Routers: none.
- Services/jobs: none — the wizard sends the normalised settings to `POST /versions` as a new version (a new row, a new number; the old one is untouched).
- Permissions + workspace isolation: reuse is a create, so it needs `reviewer`; the version payload it reads is already scoped (foreign version id 404).
- Secrets/safefetch: none.
- OpenAPI: no.
