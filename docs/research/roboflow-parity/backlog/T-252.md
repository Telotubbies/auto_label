## User story
As an ML engineer, I want one number line — minutes, credits and the GPU it will run on — before I commit, so that a 12-hour run is a decision and not a surprise invoice.

## UX flow (LabelDesk words)
1. **Train → sticky summary** — every change to dataset, preset, family or epochs re-asks the quote and the summary updates: "~18 min · 3 credits · RTX 4090". [empty: no dataset yet ⇒ "Pick a dataset to see the estimate" and Start stays disabled] [loading: the three numbers get a shimmer in their final slots, the old values do not jump to zero] [error: "The estimate is unavailable for this setup" plus the reason code; Start stays enabled only if a previous quote exists]
2. **The floor is printed** — under the cap field: "Shortest run that can still produce a model: 6 min · 1 credit."
3. **A quote that cannot be guessed** — a family with no throughput table prints time only ("~18 min · credits quoted at the standard rate") and never a fabricated VRAM figure.

## Backend changes
- Models/schema: none.
- Routers: `POST {P}/train/quote` body `{version_id | image_count, task?, family, variant, epochs, imgsz, batch}` → `{minutes, credits, credits_exact: bool, gpu, vram_mb, minimum_minutes, minimum_credits, basis: {train_images, epochs, imgsz, images_per_minute}}`; **400** naming valid choices for a bad `(task, family, variant)` via `train_catalog.resolve_variant`; **400** `"pick a generated version"` for a version that is not `ready` or belongs to another project (same message as `POST /train`).
- Services/jobs: new `apps/backend/app/services/train_quote.py`:
  - `CREDIT_GPU_SECONDS = 1800` (1 credit = 30 min of GPU) — one constant, cited by T-253/T-263.
  - `quote(train_images, epochs, imgsz, variant, family) -> dict`: seconds = `images × epochs × (imgsz/640)² / 600 × 60` (the formula already behind `Train.tsx:34` and `_gpu_estimate`), credits = `ceil(seconds / 1800 × 2) / 2` (half-credit steps), `minimum_credits = ceil(MIN_TRAIN_GPU_S / 1800)`.
  - `THROUGHPUT = {"rf-detr": 420, "ultralytics": 600, "hf": 300}` images/minute; an unknown family returns `credits_exact: False` and uses 600 with a `basis.assumed` note.
  - `VRAM` from `train_catalog` size rows; `gpu` label comes from `LD_TRAIN_DEVICE` when set, else `"RTX 4090"` (the label already used by the design).
- Permissions + workspace isolation: `c.perm("project.read")` — the quote is a read; a foreign project slug is 404, a foreign `version_id` is 400 with the same "pick a generated version" text so ids do not leak.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate both files.

## Tests to write first
pytest — `apps/backend/tests/test_train_quote.py`:
- `test_quote_scales_with_epochs_and_resolution` — doubling epochs doubles the minutes; doubling `imgsz` quadruples them (600→640 is not used, use 320 vs 640).
- `test_credits_round_up_in_half_steps` — 10 min → 0.5 credit, 18 min → 1.0, 200 min → 7.0; never `0.0` for a runnable setup.
- `test_minimum_is_the_smallest_runnable_run` — `minimum_credits == ceil(MIN_TRAIN_GPU_S / 1800)` and is independent of the dataset size.
- `test_unknown_family_marks_the_estimate_unexact` — `family="hf"` sets `credits_exact is False` and keeps every number an int/float.
- `test_foreign_version_is_a_400_with_the_train_message` — a version of another project → 400 "pick a generated version".
- `test_unknown_variant_names_the_valid_choices` — 400 containing "choose one of".
- `test_quote_matches_the_charged_reservation` — the seconds the quote reports for a dataset × epochs equal `handlers.training._gpu_estimate`-style reservation used by `POST /train` within 1 %.

## Acceptance criteria
- [ ] One route returns minutes, credits, GPU, VRAM, the minimum and the basis it used.
- [ ] The credit figure follows one constant (1 credit = 30 min) that the cap and the stop rules reuse.
- [ ] A bad variant or a non-ready version is a 400 naming the fix — never a 500 and never a quote for a run that cannot start.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no route consumer; `GET /train/options` and `POST /train` behave exactly as today.

## Notes for the implementer
`POST /train` must keep reserving with the same function the quote uses (`metering.check(..., "gpu_seconds", quote_seconds)`), so the number on screen and the number reserved cannot drift. Keep the RTX 4090 label in one place (`train_quote.GPU_LABEL`) — T-254 prints it verbatim.
