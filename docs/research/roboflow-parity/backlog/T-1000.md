## User story
As a workspace owner, I want one Inference destination in the workspace rail that opens four tabs under
one host-picker header, so that engine installs, model downloads, sizing and segmentation are one place
rather than four hidden screens.

## UX flow (LabelDesk words)
1. **Workspace rail → Inference** — visible only to `owner`/`admin` and only when `task_inference` is on.
   [permission: absent for member, labeler, billing]. Route `/:ws/inference`.
2. **Hub header** — `PageHeader title="Inference"` with a host picker placeholder ("No host selected")
   and a short line: "Install inference engines, download models and size them against this host."
   [empty: no host has reported yet → the picker reads "No host has reported" and the tabs render their
   empty states].
3. **Four tabs** — `Engines`, `Models`, `Calculator`, `Segmentation`, kept in the URL as
   `?tab=engines|models|calculator|segmentation` so a refresh and a shared link land on the same tab.
   Each panel is a real empty state until its card lands: "No engine catalogue yet." / "No model
   catalogue yet." / "The calculator arrives with the sizing card." / "No segmentation model is
   provisioned on this host."
4. **Deep link to a foreign or disabled workspace** — the route renders the standard 404 page, never a
   blank shell. [error: flag off → the page is not registered at all].
5. **375 px** — the tab bar becomes a `Select`; the header wraps; the panel is full width.

## Acceptance criteria
- [ ] Owner/admin with the flag sees **Inference**; member, labeler and billing do not; flag off hides it.
- [ ] `/:ws/inference` opens on `Engines`, `?tab=calculator` opens on Calculator, unknown values fall
      back to Engines.
- [ ] The four panels render their real empty states, with no console error and no dead button.
- [ ] 375 px renders a select instead of the tab bar and no horizontal page scroll.
- [ ] Glass is used only on chrome; panels and tables are solid `Card`; no new token, hex or font size.
- [ ] Flag off ⇒ route not registered, rail entry absent, and the workspace index still renders.

## Notes for the implementer
Do not add a project-level nav entry: the hub is workspace-level and the segmentation handoff deep-links
into a project. Keep the tab state in the query string, not component state, so a deep link from a job
notification works. `Gate min="admin"` already exists (`routes/guards.tsx`); do not write a second role
check.
