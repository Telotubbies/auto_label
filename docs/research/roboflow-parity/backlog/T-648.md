## User story
As a safety officer, I want to write my standing questions once, press "Answer questions" on a filtered batch and then read and filter the answers where I already work, so that compliance findings are a column in my grid, not a spreadsheet beside it.

## UX flow (LabelDesk words)
1. **Classes & Tags → Question set** (`/:ws/:project/classes`) — a `Card` listing the questions in order, each with its text, an optional review tag and a remove button, plus "Add a question" (disabled at five). [empty: "No questions yet — add up to five yes/no questions"] [error: a blank question or a sixth is refused under the list]
2. **Dataset → select images → Answer questions** (`/:ws/:project/browse`) — a button in the existing bulk bar; with no selection it asks "Select images first" instead of answering the whole project. [loading: "Answering 4 questions on 120 images…" with a counter] [error: the gate refusal and the model error both render as one sentence with Try again]
3. **The grid** — one column per question, values `yes` / `no` / `—` (`unknown` and unanswered both read `—` with a tooltip), plus a chip row "vest: no" that writes `attr=vest:no` into the URL.
4. **Editor** (`/:ws/:project/images/:imageId`) — the image panel lists the answers with their source and time; a `no` that created a tag shows the tag chip.
5. **Flag off** — no Question set card, no Answer questions button, no answer columns.

## Backend changes
- Models/schema: none — T-647 owns `images.attributes` and `Project.settings["questions"]`.
- Routers: none new; this card calls `PUT .../questions`, `POST .../questions/answers` and passes `attr=key:value` to `GET .../images`.
- Services/jobs: none.
- Permissions + workspace isolation: the Question set card renders for `project.classes`; the answers button renders for `can('project.review')`; the grid reads only this project's images.
- Secrets/safefetch: none.
- OpenAPI: no.

## Acceptance criteria
- [ ] Three to five questions are authored once and saved; the list keeps their order and refuses a sixth or a blank.
- [ ] Answering a selection writes values that appear as columns and filter the grid through the URL.
- [ ] A `no` with a review tag shows the tag chip in the editor; unanswered and unknown both read `—` and are distinguishable on hover.
- [ ] Empty, loading and error states above all render, including no questions and no selection.
- [ ] Workspace A cannot read workspace B's answers: the grid only ever queries this project's images.
- [ ] Flag off ⇒ no card, no button, no columns, and the grid's query string is unchanged.

## Notes for the implementer
Answers are values, not shapes: never draw a box for a question. Keep one column per question with the question text in the header and the key in the tooltip; ordering follows the stored list so two people see the same table. The chip writes the same `attr=` parameter the server already filters on, so a saved link and a fresh chip produce one view.
