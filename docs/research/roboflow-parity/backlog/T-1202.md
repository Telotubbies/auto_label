## User story
As a buyer with one task in mind, I want to pick a project type in words I recognise, name the project and
land exactly where the work starts, so that I never have to guess which screen follows creation.

## UX flow (LabelDesk words)
1. **Workspace home** (`/:ws`) — "New project" is the one primary; the type cards carry an outcome
   sentence, not a model name.
2. **New project** — pick a type (object detection), name it, see the derived address before submit.
   [error: a duplicate name shows the taken address and suggests one].
3. **Create** — the dialog is busy, then closes; no full-page spinner.
4. **Project overview** (`/:ws/p/:project`) — the five stages with counts, and one primary "Upload images"
   (or "Label N images" when data exists). [empty: the fresh-project state, one next step].
5. **Upload** (`/:ws/p/:project/upload`) — the drag zone, the batch name default and the split chips.
   [empty: the accepted formats, the size cap and the demo-set shortcut].

## Acceptance criteria
- [ ] The new project exists after reload and its stage counts are zero, not blank.
- [ ] Steps ≤ 7 and time ≤ 90 s; the numbers are recorded.
- [ ] The duplicate-name error is inline, names the address, and keeps the typed name.
- [ ] No console error; the fresh project shows its empty state, not an empty table.
- [ ] UI only: the same flow at 375 px has no clipped primary and no horizontal scroll (uses the J2 spec
      at a 375 viewport, one extra test).
- [ ] Workspace isolation: the project is created in the seeded workspace and appears in no other; a
      second workspace's home is asserted empty for the new name.
- [ ] Flag off ⇒ the project index lands on the dataset grid and the create flow still completes.
- [ ] Keyboard only: type card, name and submit reachable in reading order.

## Notes for the implementer
Delete the project through the shipped delete action at the end only if it is reversible without a
confirmation loop the user would also face; otherwise use a unique name per run and leave it. Do not call
the API to create the project: the dialog is the subject.
