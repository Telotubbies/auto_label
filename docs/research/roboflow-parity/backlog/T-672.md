## User story
As an integrator commissioning 40 cameras, I want to type a subnet range, pick a camera from what answers, choose the stream profile the camera reports and prove the password with one test frame, so that a wrong password fails in the dialog instead of as a stream stuck in `reconnecting`.

## UX flow (LabelDesk words)
1. **Streams → New stream → `ค้นหากล้องในเครือข่าย`** (`/:ws/:project/streams`, the shipped `Modal`) — a second tab beside the URL field, asking for the subnet range, a user name and a password. [empty: the tab opens with the workspace allowlist hint, nothing has been probed]
2. **Probe** — `[loading: กำลังตรวจ 254 อะเดรส]` with a progress count, cancellable; the result is a table of devices: model, firmware, address. [empty: `ไม่มีกล้องตอบกลับ — ตรวจ VLAN หรือวาง URL เอง`] [error: `ช่วงเครือข่ายนี้ไม่อยู่ในรายการที่อนุญาต` when the range is outside `LD_STREAM_ALLOW_CIDR`]
3. **Pick a device → profiles** — a table of media profiles (main/sub) with resolution, codec and fps, read from the camera. [loading: `กำลังอ่านโปรไฟล์จากกล้อง`]
4. **`ทดสอบภาพ`** — one frame, its size and the round-trip time. [error: `รหัสผ่านไม่ถูกต้อง` (401)] [error: `ผู้ใช้กล้องไม่มีสิทธิ์ดูภาพ` (403)] [error: `ค้นเจออุปกรณ์แต่ไม่ส่งภาพ` (504)]
5. **`ใช้โปรไฟล์นี้`** — the dialog fills the Camera source field with the profile's URL, the password goes into it once, and saving seals the URL. The wall row afterwards reads `rtsp://camera-07 ••••@…` and the password never appears again. [error: `บันทึกไม่สำเร็จ — ตรวจ URL ของโปรไฟล์`]

## Backend changes
- Models/schema: none — discovery persists nothing, and the saved source goes through the existing sealed `Stream.source` column.
- Routers: `app/routers/stream_discovery.py` (new), prefix `/api/ws/{ws}/projects/{project}/streams/discover`, `dependencies=[Depends(require_flag("task_camera_discovery"))]`; `POST ""` `{cidr, username, password}` → `{devices: [{host, manufacturer, model, firmware, profiles}], probed, elapsed_ms}`; `POST "/profiles"` `{host, username, password}` → `{profiles: [{token, name, resolution, codec, fps, uri}]}`; `POST "/test"` `{source, username, password}` → `{status, roundtrip_ms, width, height, frame}` (one JPEG, base64, ≤ 400 KB). 400 for a range wider than `/24` or outside the allowlist, 401 wrong password, 403 media role missing, 504 discovery answered but no frame, 403 for a non-manager.
- Services/jobs: `app/streams/onvif.py` (new) — `probe(cidr, username, password, timeout=0.6, max_hosts=254, post=…) -> list[dict]`, `profiles(host, username, password)`, `test_frame(source, username, password)`, error classes `OnvifAuth`, `OnvifForbidden`, `OnvifTimeout`, `OnvifRefused`. SOAP over `http.client` against `/onvif/device_service` (GetDeviceInformation, GetProfiles, GetStreamUri), Digest auth. `test_frame` decodes one frame through the existing guard (`streams/guard.GuardedMediaProxy` for http(s), `manager.resolve_source` + `manager.pinned_url` for rtsp). No new dependency.
- Permissions + workspace isolation: `c.need("admin")` on all three routes; every probe target must resolve inside `config.STREAM_ALLOW_CIDR` through `streams/allowlist.allowed_stream_ip`, and an address outside it is refused before a socket opens. A stream id never crosses the workspace here because discovery creates nothing.
- Secrets/safefetch: `streams/allowlist.py` is the guard (the operator's `LD_STREAM_ALLOW_CIDR`, empty by default ⇒ no target reachable). The password is used in memory only, never logged, never echoed in an error body; the saved URL is sealed by `streams/creds.seal_source` on create and masked by `creds.mask_source` on read, so `services/secretbox.py` covers it at rest.
- OpenAPI: yes — three new routes and their schemas.

## Acceptance criteria
- [ ] A manager types a range inside the operator allowlist and gets the devices that answer, with model, firmware and address.
- [ ] Picking a device lists its media profiles with resolution, codec and fps, and `ทดสอบภาพ` returns one frame with a round-trip time.
- [ ] A wrong password, a camera user without the media role and a silent media path each produce their own message inside the dialog, and nothing is saved.
- [ ] Saving from a profile seals the URL; the row and every later response read `rtsp://camera-07 ••••@…`.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the discovery tab is absent, the URL field is the only path, and no discovery route exists.

## Notes for the implementer
Cap the range at 254 hosts and refuse anything wider — a `/16` probe is a port scan, not onboarding. Send the password only in the request body, keep it out of the audit row (`audit(..., host=..., probed=n)`), and treat a camera that answers discovery but sends no frame as 504 rather than a partial success. `LD_STREAM_ALLOW_CIDR` stays empty by default, so the feature is inert until an operator names the plant network; do not add a second CIDR setting. Copy: `streams.discover.open`=`ค้นหากล้องในเครือข่าย`, `streams.discover.probing`=`กำลังตรวจ {n} อะเดรส`, `streams.discover.empty`=`ไม่มีกล้องตอบกลับ — ตรวจ VLAN หรือวาง URL เอง`, `streams.discover.test`=`ทดสอบภาพ`, `streams.discover.use`=`ใช้โปรไฟล์นี้`, `streams.discover.err401`=`รหัสผ่านไม่ถูกต้อง`, `streams.discover.err403`=`ผู้ใช้กล้องไม่มีสิทธิ์ดูภาพ`, `streams.discover.errTimeout`=`ค้นเจออุปกรณ์แต่ไม่ส่งภาพ`, `streams.discover.rangeBlocked`=`ช่วงเครือข่ายนี้ไม่อยู่ในรายการที่อนุญาต`.
