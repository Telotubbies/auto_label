## User story
As an enterprise admin, I want to set the required groups, auto-join and the group-to-role mapping from one screen, so
that I can see what the directory will do to my members before it does it.

## UX flow (LabelDesk words)
1. **Settings → Members → `Directory sync`** (`/:ws/settings/directory`) — a `Groups` section: chip input for
   required group names, an `Add users automatically on sign-in` switch, and a note
   `Applies only when a user signs in through your identity provider.`
2. **Behaviour table** — a four-row read-only table that changes as the switches change:
   `Neither · Manual invite only`, `Auto-join only · every SSO user is added`, `Required groups only · non-matching
   members are removed, new users still need an invite`, `Both · matching users are added, non-matching removed`.
   The current row is highlighted.
3. **Role mapping** — rows of `Directory group` → `Custom role` with `Add mapping`, each removable; a duplicate group
   is refused inline.
4. **`[empty]`** no groups and auto-join off: `Manual invites only. Turn on auto-join to let the directory add people.`
5. **`[error]`** saving without an SSO config reads `Single sign-on is not set up for this workspace.` and links the SSO
   tab. A `409` from the server keeps the draft and names the field.
6. **Read-only** — without `workspace.update`, controls are dimmed with a lock and `Request access`.

## Backend changes
- Models/schema: none (T-430/T-431).
- Routers: `GET/PATCH /api/ws/{ws}/directory` `{required_groups, auto_join}` and
  `POST/DELETE /api/ws/{ws}/directory/roles` `{idp_group, custom_role_id}`; `409` when the workspace has no SSO config;
  `400` for an invalid group name or a custom role from another workspace.
- Services/jobs: `services/dir_sync.py` — `state(db, ws) -> dict` (groups, auto_join, mapping rows with role names,
  `combination` string computed server-side so the UI does not duplicate the rule).
- Permissions + workspace isolation: `workspace.update` for writes, `workspace.read` for reads; `custom_role_id` must
  belong to this workspace and exist at any level (a workspace role is applied at workspace level).
- Secrets/safefetch: none.
- OpenAPI: yes.
