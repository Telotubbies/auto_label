## User story
As a reviewer, I want the trusted labels and the submitted ones side by side with the differences listed, so that a rejection is evidence instead of an assertion.

## UX flow (LabelDesk words)
The panel is T-626; this card owns what it may show.
1. **`GET /quality/answer-key/{image_id}`** — `{has_key, key, submitted, conflicts, threshold}` where each conflict is `{kind: "missing"|"extra"|"class", class_id, class_name, other_class_id?, annotation_id, box}`. [empty: `conflicts: []` with `has_key: true` means "No conflicts on this image."]
2. **No key for the image** — 404 "No answer key for this project." and the review screen simply does not offer the overlay.
3. **A labeler calls it** — 403, and the response never carries `key`; the check is the permission, not the route shape.
4. **Threshold changed in Settings → Quality** — the same pair of drafts now yields `missing` + `extra` instead of a class swap, because matching uses the class threshold from T-610.
5. **A draft with no geometry on one side** — class-level annotations produce `missing`/`extra` rows with `box: null` and the panel lists them without a centre action.

## Backend changes
- Models/schema: none — the key is the existing `Honeypot.annotations`, the submission is `Image.annotations`; nothing new is stored.
- Routers: `routers/quality.py` — `GET "/answer-key/{image_id}"` → the payload above; 404 for an image outside this project or with no key, 403 for a caller without `project.review`.
- Services/jobs: `app/services/answer_key.py` — `conflicts(gt, submitted, threshold)` (greedy match at the class threshold; unmatched key rows → `missing`, unmatched submitted rows → `extra`, matched rows whose class differs → `class` with both class ids), `overlay(db, c, image)` composing the payload with class names and normalized boxes, `key_boxes(gt)` for the overlay. `services/submit_score.py` keeps using `match` only, so the hint path does not gain the conflict detail.
- Permissions + workspace isolation: `c.need("reviewer")`; the image is looked up by id **and** `project_id == c.project.id`, so a foreign image is a 404 before any key is read.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] A reviewer opens the answer key for an image and gets the key, the submission and one row per difference, each with class names and a box where one exists.
- [ ] A labeler's request is refused with 403 and the body never contains the key.
- [ ] The class threshold comes from Settings → Quality, so the same drafts can report a swap at 0.5 and missing+extra at 0.9.
- [ ] Empty, loading and error states above all render where the surface exists: `conflicts: []`, 404 no-key, 403 for a labeler.
- [ ] Workspace A cannot read workspace B's answer key (404, not 403, before any key is read).
- [ ] Flag off ⇒ no answer-key route and review mode behaves exactly as today.

## Notes for the implementer
Return the conflicts in a stable order — `missing`, then `extra`, then `class`, each by box top-left — so the panel does not reshuffle between two loads. Never include the key's total count in the labeler-facing score payload; this route is reviewer-only and stays that way.
