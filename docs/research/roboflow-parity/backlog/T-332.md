## User story
As a builder, I want the class found on a crop to replace the class the detector guessed, so that "which kind of helmet is this" is answered per object instead of per image.

## UX flow (LabelDesk words)
1. **Palette → "Replace classes"** — a block that takes `detections` and a `classes` source (the output of a classification model run on the crops) and writes `detections` with the new class on each box. Its config is one select for the source and one checkbox: "Keep the detector's class when the classifier is unsure."
2. **The two-stage recipe** — "Start from a recipe" offers `Detect → crop → classify → write back`, which fills the five nodes and wires them: model, crop, classifier, replace, visualise. The run panel result shows one box per object with the classified label.
3. **Unsure classification** — with the checkbox on, a crop whose top class is below the classifier's threshold keeps the detector's class and the result row carries `source: "detector"`. With it off, the box is dropped and the panel counts it: "2 objects skipped".
4. **Nested results** — `[error]` a crop whose detection carried a classification result already is refused at save: "Replace classes needs boxes with no class yet." [empty: no crop upstream → the block is disabled with "Add a crop block first."]

## Notes for the implementer
Matching by index is the bug this card exists to avoid: a crop block emits one item per box in detection order, but a classifier that filters anything shifts the list. Key on the crop's root box (`x, y, w, h`) rounded to 1e-4.
