## User story
As a labeler, I want to name one class and describe what it looks like on this image, so that open-vocabulary cases do not need a second taxonomy.

## UX flow (LabelDesk words)
1. **Editor → floating assist toolbar → "Find objects"** — a popover with: a class select limited to the project's classes, a one-line description field ("green umbrella"), a model choice between **Box model** and **Mask model** (only models the worker can run), and **Find objects**. [error: 402 → "No AI calls left on this plan" with the Usage link; 503 → "The model is not reachable right now"]
2. **Description semantics** — an empty description searches the class name; the hint says so. The class name is what gets saved; the description is only the prompt.
3. **Confidence** — the slider appears only for the mask model, because box models return everything at full confidence; the hint states that. Range `5–95%`, default 40%.
4. **Run** — `[loading]` "Looking for umbrella…" with a cancel that stops waiting; then the proposal bar opens with the count, the popover closes. A zero result keeps the popover open: "Nothing found — try a plainer description."
5. **Class locking** — when the project has class locking on (`settings.classes_locked`, T-164), the whole **Find objects** entry is hidden: free text could describe a class that does not exist, and the area's rule is that a locked taxonomy has no open-vocabulary door.
6. **One image, one class** — the request never spans images and never creates a class; adding a class is the existing inline field in the Classes panel.

## Backend changes
- Models/schema: none.
- Routers: `POST /api/images/{image_id}/find-objects` — body `{class_id: str, description: str = "", model_ref: str | None, confidence?: float}` → `{annotations, model, count}`; delegates to `services/prompt_detect.run` with a single-prompt `classes` list (the existing function, **no edit to that module**), so one metered AI call, the same 400/402/503 set, `404` for a cross-workspace image, and `400 "class locking is on"` is **not** needed server-side (the UI hides the entry; the server still validates the class id, which is enough).
- Services/jobs: none new — `prompt_detect.run` already accepts one class.
- Permissions + workspace isolation: `project.infer` + `image_ctx`; the class id is validated against the project, so a foreign class is 400.
- Secrets/safefetch: none.
- OpenAPI: yes — one route.

## Acceptance criteria
- [ ] One class plus a description runs one metered call and hands its results to the proposal bar; an empty description searches the class name.
- [ ] The confidence slider appears only for a mask model, and the hint explains why.
- [ ] With class locking on, the Find objects entry is absent from the toolbar.
- [ ] Nothing is saved unless a proposal is kept; a zero result keeps the popover open with retry copy.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no entry, no route (404), and every other tool is unchanged.
- [ ] Keyboard-only path: Tab to the toolbar → Enter → Tab class → Enter → type description → Enter on Find objects.

## Notes for the implementer
This is T-150's service with one prompt: do not fork a second inference path. The server does not enforce class locking here because a class id is always validated; the hidden entry is a UX rule, and the card states that rather than pretending the API forbids it.
