## User story
As a builder, I want the editor to wire compatible ports for me by default and to stop doing it when I say so, so that I spend my time on the pipeline instead of on remembering which port feeds which.

## UX flow (LabelDesk words)
1. **Mode switch, top-right of the canvas** — `Auto` (default), `Quick`, `Manual`, as a segmented control with one line each: "Wires compatible ports and repairs references", "Suggests a wire, applies on accept", "Nothing moves unless I move it". The choice persists per workflow in `localStorage` under `ld:wf-mode:<id>`.
2. **Auto, on connect** — dropping an edge on a compatible port also fills the node's other unfilled required inputs from the nearest earlier producer. **Auto, on insert** — inserting a block between two nodes rewires both sides. **Auto, on remove** — deleting a node reconnects its single input producer to its single output consumer; when that is ambiguous the editor asks, "Reconnect X to Y?" with Keep / Remove.
3. **Quick** — the same suggestions appear as a ghost edge with an "Apply" chip on it; nothing is written until the chip is pressed. [empty: no compatible producer upstream → the ghost edge is absent and the port shows "No source yet"] [loading: none] [error: an apply that would create a cycle is refused inline: "That wire would loop back to Crop."]
4. **Arrange** — one button in the toolbar, with a chevron: "Arrange now" and "Arrange automatically". Automatic re-lays out after every add or connect; dragging pauses it until the next add. Saved per workflow, locally, next to the layout.
5. **Manual** — the segmented control disables both behaviours; the sitemap button still offers one arrange pass.

## Tests to write first
pytest — `none: no backend surface`.
node — `apps/frontend/tests/workflow-wiring.test.mjs`:
- `test_auto_fills_every_required_port_from_the_nearest_producer` — inserting a filter after a model fills `detections` from that model, not from an earlier one.
- `test_auto_on_remove_reconnects_a_single_producer_to_a_single_consumer` — removing the middle of three nodes yields one edge, and removing a node with two consumers returns a question instead of an edge.
- `test_quick_writes_nothing_until_applied` — `fillRequired` under `quick` returns the same graph object identity and a suggestion list.
- `test_a_cycle_is_refused_before_the_edge_is_added` — `wouldCycle` is true for a wire back to an ancestor and the graph is unchanged.
- `test_mode_and_explicit_mode_survive_a_corrupt_store` — garbage in `ld:wf-mode:<id>` falls back to `auto`; `manual` disables both fill and repair.
- `test_automatic_arrange_is_paused_while_dragging` — `arrange(..., "auto")` after a drag returns the dragged positions unchanged.

## Acceptance criteria
- [ ] `Auto` wires on connect and on insert, and repairs downstream references on remove; `Quick` only suggests; `Manual` never edits edges.
- [ ] A wire that would create a cycle is refused inline and nothing is saved.
- [ ] The mode and the auto-arrange choice persist per workflow and degrade to defaults on a corrupt store.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — a bad wire is still refused by T-320's server validation.
- [ ] No flag: this card ships inside `task_322`, so turning that flag off removes the canvas and this with it.

## Notes for the implementer
"Nearest producer" means the producer with the longest path from the input node, which is what makes a crop-then-classify chain wire the crop rather than the original image. Do not add a fourth mode.
