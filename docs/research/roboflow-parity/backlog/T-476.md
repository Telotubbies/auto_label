## User story
As a workspace member, I want the left rail to list only the places I work and to find members, billing, audit and keys inside Settings, so that eleven destinations in five shouting groups stop hiding the three I use.

## UX flow (LabelDesk words)
1. **Workspace rail** — `Projects · Models · Deployments · Activity · Settings`, no ALL-CAPS group captions, no Playground, no second copy of Members, Plan & Usage or API Keys. A superadmin also sees `Admin`, which is the sixth item. [empty: a billing role keeps only `Settings` and lands on Settings → Plan & Usage, as today]
2. **Settings → Members / Plan & Usage / API Keys** — the governance surfaces that left the rail are tabs there, named exactly as they were in the rail, so the breadcrumb and the tab agree. `Audit log` arrives with T-400, not with this card. [error: a role without the tab keeps today's behaviour — the tab is absent, the route 404s]
3. **Playground** — reachable from the command palette and from Deploy's `Test` tab (T-479); the `/w/playground` URL still resolves.
4. **Role change** — a labeler keeps `Projects · Activity · Settings`; a billing user keeps `Settings` only.

## Notes for the implementer
This is the one place where REDESIGN contradicts itself: §3.2 draws seven labels and calls them six. Resolve it as *five plus Admin* — Projects, Models, Deployments, Activity, Settings, and Admin for a platform operator — because the brief's rule is "six items with governance inside Settings", and Members/Usage/Audit/Keys are exactly the governance set. Area 7's `T-380` and `T-389` say "the rail already points at this tab" in their Nav-entry field: that sentence becomes stale, their Settings tabs do not break. Do not add the Audit tab or the `/audit` redirect here — T-400 owns both.
