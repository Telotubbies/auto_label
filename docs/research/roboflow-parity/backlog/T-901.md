## User story
As a manager reading a finished run, I want the settings it was started with in one block I can copy, so that a
bad result can be explained without opening the worker log or guessing from the model name.

## UX flow (LabelDesk words)
1. **Models** (`/:ws/:p/models`) — select a run; the detail column gains a **Run settings** card above the tabs:
   dataset version, family and variant, epochs, image size, batch, max minutes, continued-from, and a dimmed
   `Recorded from the training request` footer. [empty: an old run with no job row renders
   `Parameters were not recorded for this run.` and the derived counts instead]
   [loading: four skeleton rows keep the card height] [error: the card renders `Parameters unavailable` with a
   retry button, never a blank card]
2. **Copy parameters** — the card's overflow menu copies the block as JSON (`{version, family, variant, epochs,
   imgsz, batch, max_minutes, resume_from}`) for a repeat run or a bug report.
3. **A labeler opens the same page** — the card is absent entirely (no dimmed card, no lock icon): label assist
   already gets the lean job (`routers/projects.py:37-42`).
4. **Insights → Training** — the run chip's title attribute carries `variant · epochs` so the curve can be
   attributed without leaving the tab. [empty: the chip renders without the suffix]

## Backend changes
- Models/schema: none — `Job.params.options` already holds every value (`routers/training.py:281-282`).
- Routers: `apps/backend/app/routers/training.py` — in `models()` (after `:159`) and in `get_model()`

- Services/jobs: `apps/backend/app/services/run_view.py` (new) —
  `run_params(m: TrainedModel, job: Job | None) -> dict` returns
  `{"source": "job"|"derived", "versionId", "family", "variant", "epochs", "imgsz", "batch", "max_minutes",
  "resume_from", "epochs_logged"}`; reads `job.params["options"]` (`handlers/training.py:78-81`) and falls back
  to `m.family`, `m.variant`, `m.arch` and `len(m.history)` with `source="derived"`. No writes, no job kind.
- Permissions + workspace isolation: `project.models` decides presence; a foreign project's model id answers 404
  through `_model()` (`routers/training.py:290-294`); a labeler receives `params: null` on every row.
- Secrets/safefetch: none.
- OpenAPI: yes — the `ModelItem` schema gains `params`; regenerate with `python tools/export_openapi.py` then
  `npm run gen:api-types`.

## Tests to write first
pytest — `apps/backend/tests/test_run_params.py`:
- `test_params_come_from_the_job_options` — a run whose job carries `{epochs: 30, imgsz: 640, batch: 8,
  variant: "yolo26n", resume_from: null}` → `GET /models` row `params.source == "job"` and the four values echo,
  `epochs_logged == len(history)`. (also covers the flag-on path)
- `test_a_run_without_a_job_derives_its_settings` — `job_id=None`, history of 12 rows → `source == "derived"`,
  `variant` from the row, `epochs_logged == 12`. (empty state)
- `test_a_labeler_gets_no_params` — the `project.infer`-only member sees `params: null` on every row and the
  detail route, while `project.models` sees the block.
- `test_the_endpoint_is_absent_when_the_flag_is_off` — with `task_mlruns` off, `GET /models` keeps its old
  payload (no `params` key) and answers 200.
- `test_a_foreign_project_model_is_404` — workspace B's token on workspace A's model id → 404.
- `test_reading_params_is_read_only` — no row, no job and no audit row is written by either read.

node — `apps/frontend/tests/run-params.test.mjs`:
- `test_only_recorded_fields_render` — feed the component's formatter a `source: "derived"` payload → the field
  list drops `batch`/`max_minutes` and keeps `variant`/`epochs_logged`.
- `test_the_empty_and_error_copies_are_exact` — the two strings above ship verbatim, and the error state offers a
  retry.

## Acceptance criteria
- [ ] A finished run shows its recorded settings without a second request (the list payload carries them).
- [ ] A run with no job row shows the derived block and says so; it never shows `0 epochs` for a run with history.
- [ ] A labeler never receives hyper-parameters, and the page renders as it does today for that role.
- [ ] The copy action yields stable JSON key order (`version, family, variant, epochs, imgsz, batch,
  max_minutes, resume_from`).
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
