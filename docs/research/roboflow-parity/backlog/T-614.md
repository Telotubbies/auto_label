## User story
As a labeler, I want to see how my saved work compares with the answer key and get two more tries with a short hint, so that I fix my own mistake inside the job instead of learning about it a week later in a review note.

## UX flow (LabelDesk words)
The dialog is T-615; this card owns what it may say and when.
1. **Score a save** — `POST /quality/score` with the current annotations returns `{score, target, attempt, attempts_left, verdict, hints}`; `verdict` is `accept` (at or above target), `retry` (below target with attempts left) or `final` (the last attempt). [empty: a fourth call returns 409 "No attempts left on this image — it goes to review with your score attached."]
2. **Hints** — at most three short lines taken from a fixed vocabulary, never a coordinate: "Some objects are missing.", "Some objects are extra.", "Person was labelled as Helmet." [error: a draft over the annotation bound returns `verdict: "accept"`, `reason: "oversized"`, so a scoring failure never blocks the submit]
3. **No answer key** — an ordinary image returns 404 "This image is not scored." and the editor submits exactly as today.
4. **Evidence on the image** — the image detail now carries `scored: true` so the editor knows to ask, and the score is visible to the reviewer with the verdict in T-625's view.

## Backend changes
- Models/schema: none — attempts are `HoneypotAttemptLog` rows (T-612) counted per `(honeypot_id, user_id)`; the cap is `MAX_ATTEMPTS = 3` in code.
- Routers: `routers/quality.py` — `POST "/score"` `{image_id, annotations: list[dict]}` → 200 `{score, target, attempt, attempts_left, verdict, hints, accepted}`; 404 for an image outside this project or without an answer key; 409 once the cap is reached; 422 for a malformed annotation list.
- Services/jobs: `app/services/answer_key.py` (new) — `match(gt, submitted, threshold)` (greedy IoU matcher returning `matched`, `missing`, `extra`, `swapped`), `hint_lines(matches, class_names)` (max three, stable order: missing → extra → swap); `app/services/submit_score.py` (new) — `score(db, c, image, annotations)` reading `quality_config.threshold_for` per class, `MAX_ATTEMPTS`, appending one attempt through `labeling_ops.log_attempt` (T-612), returning the payload; `routers/images.py::_image_with_annotations` gains `out["scored"]`. No worker job: one bounded pass over one draft.
- Permissions + workspace isolation: `c.need("annotator")` plus the existing `labeling_ops.assigned` check, so a labeler scores only their own image (403 otherwise); the project path makes a foreign project 404, and the image is re-checked against `c.project.id`.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] Scoring a saved draft returns a score, a target, the attempt number and at most three hints, and records the attempt.
- [ ] The fourth attempt is refused with 409 and the third carries `verdict: "final"`.
- [ ] A draft too large to score is accepted as if the feature were off, and the submit is never blocked by a scoring failure.
- [ ] Empty, loading and error states above all render where the surface exists: 404 no-key, 409 cap, 422 malformed; the dialog in T-615 renders them.
- [ ] Workspace A cannot score workspace B's image (404 for a foreign project, 403 for another person's image in this project).
- [ ] Flag off ⇒ no score route, no `scored` flag and the editor submits exactly as today.

## Notes for the implementer
The hint vocabulary is closed on purpose: `missing`, `extra`, `swapped` only, and a swap names two classes at most. Never return the key, the number of key annotations, or a box. Count attempts from `HoneypotAttemptLog`, not from `HoneypotAttempt` — the latter holds one row by design.
