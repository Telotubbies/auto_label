## User story
As an agronomist in an orchard with no signal, I want to shoot 200 photos into a named session, see the queue and delete the weak ones on the spot, so that the trip produces a dataset instead of a support ticket.

## UX flow (LabelDesk words)
1. **`เก็บข้อมูลภาคสนาม`** (`/:ws/:project/ops/capture`) — `เซสชันใหม่` names the session; the queue below starts empty and states the connection. [empty: `0 ภาพ · ไม่มีสัญญาณ`] [loading: `กำลังเปิดเซสชัน`] [error: `เปิดเซสชันไม่สำเร็จ — ลองอีกครั้ง`]
2. **Shoot** — each photo lands in the queue with its size, its geotag and a `รออัปโหลด` badge; the queue lives in the browser, so a reload keeps it. [error: `ไม่ได้รับตำแหน่ง — ภาพจะถูกบันทึกโดยไม่มีพิกัด` and the photo is kept]
3. **Review offline** — a thumbnail grid with `ลบภาพนี้`; nothing is deleted from the session until it syncs, and a deleted shot never costs bandwidth. [empty: `ยังไม่มีภาพในเซสชันนี้`]
4. **Sync** — back in range, `อัปโหลดเลย` asks the server which hashes it already holds, uploads only the missing ones and prints `กำลังอัปโหลด 137 จาก 200`. [loading: that line with the real numbers] [error: `อัปโหลดไม่สำเร็จ 3 ไฟล์` followed by one row per file with its reason — never a total alone]
5. **A finished session** — `ปิดเซสชัน` stamps the end and the session appears under the project's batches with its photo count and its centre point. [error: `ปิดเซสชันไม่สำเร็จ — ลองอีกครั้ง`]

## Backend changes
- Models/schema: `app/models/capture.py` (new) — `CaptureSession(id, workspace_id, project_id, name, device, started, ended, geo_center, note, created_by, created)` with `UniqueConstraint(project_id, name)`; register in `models/__init__.py`. `Image` gains `session_id VARCHAR(32)`, `geo_lat FLOAT`, `geo_lon FLOAT` — one `IMAGES` block at the end of `app/schema/dataset.py`.
- Routers: `app/routers/capture.py` (new), prefix `/api/ws/{ws}/projects/{project}/capture`, `dependencies=[Depends(require_flag("task_field_capture"))]`; `POST ""` `{name, device, geo_center?}` → 201, `GET ""?month=` (sessions with counts), `GET "/{id}"` (session + its images), `PATCH "/{id}"` `{note?, ended?}`, `DELETE "/{id}/files/{image_id}"` (before sync). `routers/images.py`'s `upload` gains two optional form fields `session_id` and `geo` and passes them into `ingest`. 400 for a duplicate session name, 422 for a `geo` outside ±90/±180, 404 for a foreign session or image.
- Services/jobs: `app/services/capture.py` (new) — `open_session`, `session_out`, `centre(images)` (mean of the geotagged photos, rounded to 4 decimals), `close(db, session)`, `attach(db, image, session_id, geo)`. Resume uses the existing `POST /uploads/check` — no new protocol, no new job.
- Permissions + workspace isolation: `project.upload` to open a session and upload into it, `project.read` to list; the session and every image are resolved through `workspace_id` + `project_id`, so a foreign id is 404 and the geotag is stored as data on our row, never as an authority.
- Secrets/safefetch: none — no URL is fetched; the image bytes go through the existing `ingest` validation (extension, size, decodability, hash) exactly as a desktop upload does.
- OpenAPI: yes — five routes and the two new form fields.

## Acceptance criteria
- [ ] A session is created, shot into and closed, and its photos carry the session and their geotag.
- [ ] The queue survives a reload, a shot can be deleted before sync, and a resume uploads only the hashes the server does not hold.
- [ ] Failures are listed per file with a reason, and a missing location is stated rather than silently dropped.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or upload into workspace B's session (404, not 403).
- [ ] Flag off ⇒ no route, no nav item, no session read, and the desktop upload is unchanged.

## Notes for the implementer
The queue is IndexedDB blobs in `captureQueue.ts`, not `localStorage`: a photo is megabytes and `localStorage` would corrupt or evict it. One session at a time is enough for a field trip — do not build a background sync service worker, and do not upload while offline (a retry loop against no network is how a 200-photo trip loses battery). `geo` is client-supplied: clamp it, store it, never trust it for anything else. Copy: `capture.title`=`เก็บข้อมูลภาคสนาม`, `capture.new`=`เซสชันใหม่`, `capture.empty`=`ยังไม่มีภาพในเซสชันนี้`, `capture.offline`=`ภาพ · ไม่มีสัญญาณ`, `capture.pending`=`รออัปโหลด`, `capture.delete`=`ลบภาพนี้`, `capture.sync`=`อัปโหลดเลย`, `capture.syncing`=`กำลังอัปโหลด {done} จาก {total}`, `capture.failed`=`อัปโหลดไม่สำเร็จ {n} ไฟล์`, `capture.noGeo`=`ไม่ได้รับตำแหน่ง — ภาพจะถูกบันทึกโดยไม่มีพิกัด`, `capture.close`=`ปิดเซสชัน`, `capture.loading`=`กำลังเปิดเซสชัน`, `capture.error`=`เปิดเซสชันไม่สำเร็จ — ลองอีกครั้ง`.
