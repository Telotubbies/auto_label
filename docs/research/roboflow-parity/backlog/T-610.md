## User story
As a QA lead, I want to say that boxes are judged at IoU 0.6 and that one class matters twice as much, so that two projects with different tolerances stop producing the same meaningless percentage.

## UX flow (LabelDesk words)
1. **Project → Settings → Quality** — one row per class from the project's class list: `Metric` (`IoU at the threshold` / `Exact match`), `Threshold` 0.10–0.95, `Weight` 0.1–5.0, and the class's annotation count for context. [empty: "Add a class before setting a quality rule."] [loading: three skeleton rows] [error: "These rules did not load." + `Retry`]
2. **Save** — "Saved. Scores taken before this change are out of date." plus `Recompute scores`. [loading: "Recomputing 12 jobs…"] [error: "A threshold must be between 0.10 and 0.95."]
3. **Consensus → New job** — the `IoU threshold` field is pre-filled from the project default and its hint reads "Default from Settings → Quality"; changing it affects that job only.
4. **A scored save** — honeypot and consensus scoring read the per-class threshold from this screen instead of the hard-coded 0.5.
5. **A class deleted from the project** — its row disappears on the next load; stored settings for a missing class are ignored, never an error.

## Backend changes
- Models/schema: none — the rules are `Project.settings["quality"]`, merged by the existing shallow settings merge in `routers/projects.py`. Shape: `{"default": {"metric": "iou", "threshold": 0.5, "weight": 1.0}, "classes": {"<class name>": {"metric": "iou"|"match", "threshold": 0.5, "weight": 1.0}}}`. No backfill: an absent key reads as the default.
- Routers: `routers/quality.py` (new), prefix `/api/ws/{ws}/projects/{project}/quality` — `GET ""` → `{default, classes: [{name, metric, threshold, weight, annotations}]}`; `PUT ""` `{default?, classes?}` → the same payload; `POST "/recompute"` → `{jobs}`. 422 for an unknown metric, a threshold outside 0.10–0.95, a weight outside 0.1–5.0, or a class name not in the project.
- Services/jobs: `services/quality_config.py` (new) — `DEFAULT_RULE`, `read(project)`, `validate(project, body)` (returns the merged dict or raises `HTTPException(422, …)` naming the class), `threshold_for(project, class_name)`, `weights(project)`, `recompute(db, project)` (clears `ConsensusJob.image_metrics` for the project's non-collecting jobs so the existing lazy read in `labeling_ops.job_detail` re-scores them). No worker job.
- Permissions + workspace isolation: `GET` needs `reviewer`, `PUT` and `recompute` need `manager`; every query goes through `project_ctx`, so a project id from another workspace is a 404, never a 403.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] Settings → Quality lists one row per class and saving it changes the threshold the next consensus and honeypot score uses.
- [ ] A threshold, weight or metric outside the accepted set is refused inline and by the API with the same message.
- [ ] `Recompute scores` clears the cached per-image agreement so the next job detail re-scores at the new threshold.
- [ ] Empty, loading and error states above all render: the no-class empty line, three skeleton rows, and the load/validation errors.
- [ ] Workspace A cannot read or write workspace B's quality rules (404, not 403, for a foreign project).
- [ ] Flag off ⇒ no Quality tab, no quality routes, and scoring keeps using the shipped 0.5 default.

## Notes for the implementer
Store class rules by class **name**, not id: a rename must not silently drop a rule, and the merge/draft code already speaks names in `_merged_annotation`. The default rule is what `labeling.py::honeypot_score` and `merge_sets` receive when a class has no row — do not change their signatures, pass the resolved float in.
