## User story
As a labeler, I want to see what a model suggests as clearly *not mine yet*, so that a half-reviewed suggestion set never reaches the dataset.

## UX flow (LabelDesk words)
1. **Canvas** — proposals render dashed in the class colour with a 40% fill and no handles; committed shapes stay solid, exactly as the existing AI-dash rule reads (`Editor.tsx:886`). A proposal that duplicates an existing same-class box (IoU ≥ 0.9) renders hatched with a "looks like an existing label" tooltip.
2. **Proposal bar** — a glass strip above the display bar: "5 suggestions · 2 of 5", **◀ / ▶** to step, **Keep**, **Delete**, **Keep all 5**, **Discard all**. The bar is the only place proposals are accepted, and every button carries its count. [empty: no proposals → the bar is absent]
3. **Step** — the stepped proposal becomes the selection: its class chip is active in the class picker, `1–9` relabels it, `Delete` drops it, and `Enter` keeps it and advances to the next.
4. **Edit before keeping** — a bbox proposal can be dragged on the canvas (its shape updates in place); a polygon or mask proposal can be kept, deleted or relabelled, but not reshaped — keeping it makes it an ordinary annotation that can then be edited with the full toolset.
5. **Keep all** — one click saves every remaining proposal as `source` retained from the model, one undo step, and the bar closes with a toast "5 suggestions kept".
6. **Discard** — drops the set with no save and no undo entry; navigating (`→`, back) discards silently, and the cheat sheet says so.
7. **Counts stay honest** — the Objects panel and the header count only committed annotations; the proposal bar is the only place a number includes uncommitted shapes.

## Acceptance criteria
- [ ] Proposals are visually distinct (dashed, no handles) and appear in no count except the proposal bar.
- [ ] Keep, Delete, step, Keep all and Discard all work from the bar and from the keyboard, with counts in every label.
- [ ] A kept proposal becomes an ordinary annotation with the model's source and confidence, in one undo step.
- [ ] Navigating away discards the set and no API write ever contained an unaccepted proposal.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — no endpoint.
- [ ] No flag: the layer is inert without a producer, so there is no flag-off surface.
- [ ] Keyboard-only path: proposals present → `Enter` keeps one and advances → `Enter` … → last one closes the bar.

## Notes for the implementer
Regenerate ids on accept: a model response's id must never collide with a stored annotation id. Proposals belong to the image that produced them — clear the set on image change, exactly like the smart-polygon state does today.
