## User story
As a project owner, I want to name the colleague who owns a project and its delete right, so that the destructive permission follows a person instead of "any admin".

## UX flow (LabelDesk words)
1. **Project card ⋮ → `Change owner`** (workspace home) and **Project settings → General → `Owner`** — both open the same dialog. The card shows an owner badge (`Owner: Nok`) only when a person owns it; otherwise nothing.
2. **Dialog** — title `Who owns “PPE Detection”?`; a searchable list of workspace members with their roles; selecting one shows `Nok gets the delete right for this project. You keep manager access.` Primary `Transfer ownership`, ghost `Cancel`. [empty: one-member workspace → `You are the only member. Invite a teammate first.` with a link to Members] [error: transfer to a non-member → `That person is not in this workspace.`; network → `Could not transfer — nothing changed.`]
3. **After transfer** — the initiator loses delete/transfer; the new owner sees `Change owner` and `Delete`; an admin still sees both but the confirm sheet says `This project is owned by Nok.`
4. **Hand back** — the owner can transfer to themselves back? No: `Hand back to the workspace` is a third option that clears the owner (delete right returns to workspace admins).

## Backend changes
- Models/schema: `projects.owner_id VARCHAR(32)` nullable FK `users.id` (`ondelete="SET NULL"`), null = workspace-owned — `ADD COLUMN` appended to `PROJECTS` in `app/schema/dataset.py`; `Project.owner_id` column; `project_out` returns `owner: {id, name} | null`.
- Routers: `POST /api/ws/{ws}/projects/{p}/owner` body `{user_id: str | null}` → 200 `{owner}`; 400 not a member of the workspace; 404 unknown project; `DELETE /projects/{p}` and the owner route require: caller is the owner, or workspace admin, or (when `owner_id` is null) an admin as today.
- Services/jobs: none — a three-line guard in `projects.py` plus one helper `can_manage_owner(ctx, project)`.
- Permissions + workspace isolation: `project.settings` to transfer; the target `user_id` must be a `Member` of the same workspace (404 otherwise, never 403); cross-workspace project slug 404s.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Notes for the implementer
`owner_id` is a user id, not a project-member row: a member removed from the workspace clears it through the FK. Do not add a fourth role to `ProjectMember`.
