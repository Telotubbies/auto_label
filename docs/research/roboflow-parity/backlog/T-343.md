## User story
As a developer prototyping on a camera, I want one object that takes a file, a webcam or an RTSP URL and hands me each prediction, so that the same script moves from my desk to the plant unchanged.

## UX flow (LabelDesk words)
1. **Start** — `LabelDesk().stream(project, name="Gate 3", model="trained:<id>", source="rtsp://…").run(on_prediction=print)` creates the stream through the API, starts it, and yields events as they arrive; the object exposes `.status`, `.stop()` and `.wait()`.
2. **A local clip** — `source="clip.mp4"` uploads the file once through the existing `upload-video` route and uses `file:videos/<name>`, so a laptop demo needs no camera and no new server.
3. **A webcam** — `source=0` is refused with "A webcam is not reachable from the server. Upload a clip, or point at a camera URL." and a `mode="local"` hint, because this SDK talks to a server and a server cannot see the developer's USB camera.
4. **`[loading]`** — `run()` prints nothing until the stream reports `live`; a stream that reports `error` raises `LabelDeskError` with the server's `lastError`.
5. **`[error]` a bad URL** — a non-allowed scheme or a private host is refused by the API; the SDK re-raises the server's sentence, never its own guess.
6. **Sinks** — `on_prediction` receives the event dict; `sink="console"` is the default and `sink=<callable>` receives the annotated snapshot URL, which the caller may fetch with their own key.

## Acceptance criteria
- [ ] One object covers a local clip and a camera URL, yielding one callback per event until stopped.
- [ ] A webcam index is refused with the reason and a next step, and no request is sent.
- [ ] Errors surface the server's sentence; `stop()` is safe to call twice; the module imports no video library.
- [ ] Empty, loading and error states above all render (client-side: the pre-`live` wait, the error raise, the webcam refusal).

- [ ] No flag: a new SDK object; nothing existing changes.

## Notes for the implementer
The customer's own video loop is a server concern in this product, so the SDK is a thin client over `routers/streams.py` — that is also why no new dependency appears. `sink="console"` prints one line per event (`ts, rule, summary`) and never the signed snapshot URL unless the caller asks for it.
