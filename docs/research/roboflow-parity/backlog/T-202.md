## User story
As an engineer building a detect-then-classify pipeline, I want each box to become its own classified image, so that a cheap crop classifier can sit behind the detector.

## UX flow (LabelDesk words)
1. **Wizard → step 3 → Isolate objects** — a switch with the consequence written next to it: "Each box becomes its own image labelled with its class; every other box in that image is discarded." [empty: off] [loading: n/a] [error: "Isolate objects cannot be combined with tiling." when both are on]
2. **Preview** — the panel switches to a grid of up to six crops with their class names, and the count line reads "1 source image → 7 crops". [empty: "No boxes on the sample image — nothing to isolate."]
3. **Project type** — the card is disabled with the reason "Isolate objects needs a detection or segmentation project." on a classification project.

## Backend changes
- Models/schema: none.
- Routers: none (recipe value); `POST /versions/preview` reports `isolate_crops`.
- Services/jobs: `app/services/imaging.py` — `isolate(im, anns) -> list[(crop_image, class_index, box)]`: crop each annotation's bounding box with 2% padding, clamp to the frame, skip crops under 16 px on a side; `versioning.generate` expands one source image into N items, each carrying a single `{"kind":"class"}` annotation and its class index, and records `stats.isolated_crops`.
- Permissions + workspace isolation: unchanged.
- Secrets/safefetch: none.
- OpenAPI: no.
- Flag: `task_190` off ⇒ `isolate_objects` rejected with 400 `op_unavailable`; conflicts with tiling stay a 400 either way.

## Notes for the implementer
A classification version writes class labels as `{"kind":"class"}` annotations — `export_folder` already reads `anns[:1]` for the folder name, so no exporter change is needed. Keep the source image's split for every crop, and never let the crops of one image straddle splits (leakage).
