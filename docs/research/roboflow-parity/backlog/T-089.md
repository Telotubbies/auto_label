## User story
As an ML engineer, I want to export exactly the images my query shows, in the format my trainer wants, so
that "the images I was looking at" is a durable selection instead of another download script.

## UX flow (LabelDesk words)
1. **Dataset · Images** — with a query or a selection, the selection bar shows **Export**. The dialog
   reads "412 images · COCO JSON · 1.8 GB estimated" and a format picker (the formats this project type
   supports, from `/versions/formats`). [loading: the estimate appears after one count request]
   [error: over the cap → "Exports are limited to 10,000 images — narrow the query"]
2. **Dataset · Images** — **Start export** closes the dialog; the tray row reads "Selection export · 34%"
   and the page stays usable.
3. **Dataset · Images** — when done the tray row offers **Download** (a signed zip) and names what it
   contains: "412 images · 12 classes · coco". [error: a failure names the file that stopped it]
4. **Dataset · Images** — an empty query exports the whole project after a confirm naming the count.
   [empty: the query matches nothing → the dialog reads "Nothing matches this query" and Start is disabled]

## Backend changes
- Models/schema: none.
- Routers: `apps/backend/app/routers/images.py`
  - `POST P/images/export` body `{query?: str, ids?: list[str], format: str}` → `202 {job}`;
    `400` for an unknown format or a format this project type cannot use; `422` above 10 000 images or a
    `query` that resolves to zero.
  - `GET P/images/export/{jid}` → the existing `job_out` plus `url` (signed) when done.
- Services/jobs:
  - `apps/backend/app/services/selection_export.py` (new) — `build(db, project, rows, fmt,
    out_dir, should_stop)` writes a temporary version-shaped directory (`manifest.json` with the same
    shape `services.versioning` produces: `{classes, type, items:[{file, split, width, height, anns}]}`,
    images hard-linked (`os.link`, copy on failure) under `<split>/<name>`), then calls
    `exporters.export(fmt, tmp_dir, out_dir)` and returns the zip path. The manifest keeps the project's
    split per image, so the zip honours splits without a rebalance.
  - Job kind `selection_export` with `params {format, query|ids}` in `handlers/versioning.py`; the handler
    re-resolves the query inside its own session (never trusts a client-supplied id list beyond the cap),
    reports progress per 50 images, and deletes the temp dir in `finally`.
- Permissions + workspace isolation: `c.perm("project.export")`; the handler re-reads the project by id +
  workspace and refuses a deleted one; rows come from `Image.project_id == project.id` only.
- Secrets/safefetch: none; the download uses the existing `sign_path` grant.
- OpenAPI: yes — two routes.

## Acceptance criteria
- [ ] The export contains exactly the query/selection result, in the chosen format, with the project's
      splits preserved.
- [ ] The dialog states count, format and an estimate before starting; over the cap it refuses with a
      narrowing hint.
- [ ] The job is followed in the tray and ends with a signed download link.
- [ ] A failure names the file that stopped it and leaves no partial zip.
- [ ] Empty/loading/error states above render.
- [ ] Flag off ⇒ no Export action and both routes 404.
- [ ] Workspace A cannot see or change workspace B's data (404 for a foreign project id; the signed URL is
      a single grant).

## Notes for the implementer
Reuse `exporters.export` and the versioning manifest shape — do not write a second COCO/YOLO serialiser.
Hard-link the source images instead of copying when the filesystem allows it; the temp directory is
deleted immediately after zipping.
