## User story
As someone testing a model, I want the sample image and the result first and the integration code second, so that I can see whether it finds my object before I read a single line of cURL.

## UX flow (LabelDesk words)
1. **Deploy & test** (`/:ws/:project/deploy`, two panes) — left pane fluid, right pane 400 px. The left pane opens on a drop zone that also accepts paste, a camera capture and "Use a sample" (T-314's own strip reusing `SampleStrip` from the Playground). [empty: no image and no model → one line, "Pick a model, then drop an image or use a sample."] [loading: the image renders with a 40 px skeleton where the result line will land] [error: the predict call fails → the image stays, the result area shows the message and "Try again", and the endpoint card is untouched]
2. **Result** — boxes drawn over the image, a confidence slider that re-filters without re-running, per-class toggles, and one latency line: "12 objects · 84 ms · 0.001 credits". Slider changes re-run only on pointer-up, as today (`Deploy.tsx:54`).
3. **Right pane** — T-313's endpoint card, then a streams mini-list: up to three streams of this project with their status chip and a link to `/:ws/:project/streams`; when `task_10b` is off the mini-list is absent, not empty.
4. **Model selector** — the header select keeps the current model list; a model whose status is not `ready` is not offered (the empty state names training as the next step).
