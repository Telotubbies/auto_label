## User story
As the person who trained a model, I want to write down what it detects and what it must not be used for, so that the next engineer inherits a sentence instead of guessing from the class list.

## UX flow (LabelDesk words)
1. **Model detail → About** — the description renders under the metadata line, paragraphs preserved. *Edit* swaps in a textarea with *Save* and *Cancel*, a 4 000-character counter and the rule "plain text — line breaks are kept". [empty: "No description yet — say what this model detects and what it should not be used for." with an *Add description* button] [loading: Save reads "Saving…" and the textarea stays editable] [error: "Not saved — retry" sits beside the button, the draft stays in the box and the stored text is unchanged]
2. **Version text** — a version's own description renders above its metrics; when it is empty the block shows the model-level text collapsed as "Inherited from the model". [empty: both empty ⇒ no block at all]
3. **Read-only roles** — a reader sees the text, with no *Edit*; a role without `project.models` gets no About block at all, matching the masked payload.
4. **Summary elsewhere** — the first 120 characters are offered to the Deploy page as a one-line summary above the tester. [empty: no description ⇒ no summary line, never an empty quote]

## Backend changes
- Models/schema: append `"description": "TEXT DEFAULT ''"` to `TRAINED_MODELS` in `apps/backend/app/schema/training.py`; add `description: Mapped[str] = mapped_column(Text, default="")` to `TrainedModel`.
- Routers: `PUT {P}/models/{mid}/description` body `{text: str}` → `{id, description}`; strips control characters except `\n` and `\t`, collapses three or more blank lines, **422** over 4 000 characters or on a body that is not a string. `model_out` gains `description`.
- Services/jobs: `apps/backend/app/services/model_text.py` (new) — `clean_text(raw) -> str` and `summary(text, limit=120) -> str` (cuts on a word boundary, appends an ellipsis only when cut).
- Permissions + workspace isolation: write needs `project.models` (the same grant the page needs); read follows the payload's masking; a foreign id is a 404 from `_model`.
- Secrets/safefetch: none.
- OpenAPI: yes — one route, one payload field; regenerate both files.

## Acceptance criteria
- [ ] A model and each of its versions can carry plain-text description that survives reload with its line breaks.
- [ ] Saving is one edit → save action with a visible counter, and a failed save keeps the draft.
- [ ] A reader sees the text with no edit control, and a role without `project.models` gets no block.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: none. Plain text, not Markdown: no renderer is installed and a description is two paragraphs (shortcut: no links, tables or bold, upgrade when a customer asks). Render with whitespace preserved and escape everything — a description is user text and must never be injected as HTML.
