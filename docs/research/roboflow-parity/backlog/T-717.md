## User story
As an electronics or safety QC engineer with a few hundred images and no ML team, I want one click to install a pack's classes, prompts, thresholds and station, so that the first pass/fail run is an upload rather than a week of configuration.

## UX flow (LabelDesk words)
1. **The catalogue** — `GET /packs` returns the two packs this deployment ships, with their classes, thresholds, station shape and what each still needs. [empty: a deployment with no pack file returns `[]` and the gallery says `ยังไม่มีชุดติดตั้งในเครื่องนี้`]
2. **Install** — `POST /packs/{id}/install` creates the classes (with T-640's synonyms and exclusions), the anomaly/station row with its five reason codes and its threshold, and records `project.settings["packs"]`. Each item reports `created`, `skipped` or `failed` with a reason. [loading: `กำลังติดตั้ง {item}` is drawn by T-718 per item] [error: `ติดตั้งไม่สำเร็จ — {reason}`]
3. **An existing class is skipped, not overwritten** — installing `ppe-safety` into a project that already has `helmet` keeps the site's own prompt and reports `skipped`.
4. **A second install is refused** — 409 `ชุดนี้ติดตั้งในโปรเจกต์นี้แล้ว` because the station would otherwise be duplicated. [error: that sentence, with the install date]
5. **Nothing is downloaded** — the pack's example dataset is a documentation pointer, never a fetch; an air-gapped install works.

## Backend changes
- Models/schema: none — `LabelClass.prompt` (T-640), `AnomalyStation` (`models/training.py`) and `PlantStation` (T-670) already hold the installed state; the install record rides in `project.settings["packs"]` as `[{id, installed_at, installed_by, station_id}]`.
- Routers: `app/routers/packs.py` (new), prefix `/api/ws/{ws}/projects/{project}/packs`, `dependencies=[Depends(require_flag("task_vertical_pack"))]`; `GET ""` → `{packs: [{id, name, sector, classes, station, needs, installed_at}], installed: [...]}`; `POST "/{id}/install"` → 201 `{items: [{kind, name, status, reason}], station_id}`. 404 for an unknown pack id, 409 for an already-installed pack, 400 when the project type cannot host the pack's station (`classification` for the IC pack's per-unit verdict), 403 for a labeler.
- Services/jobs: `app/services/packs.py` (new) — `CATALOGUE` (two dicts: `ppe-safety` with person / helmet / closed footwear / harness at 0.7 / 0.25 / 0.25 / 0.25 from `sam3_auto_label/config/ppe_4class.yaml`, and `ic-pcb` with burnt chip / damaged IC / scorched IC / cracked chip from `sam3_auto_label/ic_defect_pipeline.py`), `get(pack_id)`, `install(db, project, pack, user_id) -> list[dict]` using `projects.ensure_class` for classes and the T-670 station create path, `needs(pack, project) -> [str]` for the gallery's "still unset" list. No job; no download.
- Permissions + workspace isolation: `project.settings` (manager) to install, `project.read` to list; the project is resolved from the path and filtered by workspace, so another tenant's project is 404 and nothing is written.
- Secrets/safefetch: none — the catalogue is code, the example dataset is a sentence, and no URL is fetched at install or at first run.
- OpenAPI: yes — two routes and their schemas.

## Acceptance criteria
- [ ] One request installs a pack's classes with prompts, its station, its threshold and its reason codes, and reports each item.
- [ ] An existing class is skipped with its site-specific prompt intact; a second install is refused with 409.
- [ ] The install is offline-clean: no fetch, no download, and the example dataset is a sentence rather than a URL call.
- [ ] Empty, loading and error states above all render — an empty catalogue is `[]`, an unknown pack is 404 and a partial install reports the failed item.
- [ ] Workspace A cannot see or change workspace B's project or classes (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no catalogue, no install, and project creation is exactly today's.

## Notes for the implementer
The pack is data, not code that runs: `CATALOGUE` in one module, and the only things it writes are classes (`ensure_class`), prompts (T-640's field) and one station with `threshold`, `reject_action: "log"` and the five default reason codes. Never install a camera, a zone or a dataset: those are the human steps the gallery lists as "still unset", and a pack that silently bound a camera would be wrong on the first site it met. Thresholds come from the repo's own PPE config and are copied verbatim; do not retune them.
