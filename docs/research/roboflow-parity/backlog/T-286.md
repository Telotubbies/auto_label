## User story
As an ML engineer, I want the metrics table to fit my task and to say plainly when a task cannot be trained yet, so that "mAP" is never a number I have to reinterpret and no screen promises a model I cannot have.

## UX flow (LabelDesk words)
1. **Model → Evaluation → metric tiles** — the headline follows the task: detection shows *mAP@50:95*, instance segmentation shows *Mask AP* then *Mask AP50* then pixel mIoU, classification shows *Top-1* and *Top-5*. Each tile prints its unit and the cut-offs it used in a tooltip, never bare letters.
2. **Mask quality card** (segmentation only) — mIoU, pixel P/R/F1, boundary AP with its definition, the per-class IoU table and the pixel confusion matrix (rows ground truth, columns prediction, counts in px).
3. **Detailed metrics disclosure** — *Show detailed metrics* reveals boundary AP, per-class IoU and the pixel confusion; collapsed by default so the page still leads with four numbers.
4. **An evaluation from before the pixel metrics** — the card reads "Mask quality was not measured for this run." with a *Re-evaluate* button (T-283) and keeps every other panel intact. [empty: no masks in the split ⇒ "This split has boxes but no masks — pixel metrics need mask labels."]
5. **A keypoint project** — Models and Train each show one state instead of a form: "Keypoint projects cannot train yet — pose families are not installed. Annotate and version the data now; training lands with the pose adapter." with a link to Versions. [error: a keypoint project that somehow has a model renders it read-only without the confidence slider]

- **States** — [empty: a detection model renders no mask card at all]. [loading: the card renders a three-row skeleton while the insights payload arrives].

## Acceptance criteria
- [ ] The headline and the tiles follow the task; a segmentation model shows mIoU and boundary AP.
- [ ] Boundary and per-class IoU live behind one disclosure, not in the default four tiles.
- [ ] An old evaluation explains the missing block and offers the re-run.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ not applicable: this card ships no flag; it renders only what the payload already carries.
- [ ] Keypoint projects show the "cannot train yet" state on Train and Models; no flag involved, no form is rendered.
