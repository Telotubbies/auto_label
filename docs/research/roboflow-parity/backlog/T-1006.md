## User story
As a workspace admin, I want to review the exact commands, bytes and disk-after for a selection of
engines, then enqueue one confirmed job for that host, so that nothing installs by accident and nothing
user-typed reaches a shell.

## UX flow (LabelDesk words)
1. **Review install plan** — the Engines footer sends `{host, engines:[{id, version, runtime}]}` and the
   sheet shows: host, one step per engine with its argv in monospace, total bytes, free disk before and
   after, warnings, and any blocked row with the reason. [loading: the sheet opens with a spinner, not
   an empty box] [error: "The plan could not be built." + the server's sentence + Retry].
2. **Confirm** — a checkbox "I understand this installs software on <host>", then `Install`.
   [error: install without the checkbox → the button stays disabled; a plan that became stale (host
   inventory changed) returns 409 and the sheet re-plans].
3. **Already installed** — the step reads `Already installed at <version>`; the plan has nothing to do
   and `Install` is disabled with "Nothing to install."
4. **Another job is running** — 409 "An engine job is already running on this host." with its job id;
   the sheet offers `View job`.
5. **Uninstall** — row menu → `Uninstall`; the confirm sheet names the engine and host and the venv that
   will be removed; a system package is never touched.
6. **Host offline** — `Review install plan` is disabled with "This host is offline."

## Backend changes
- Models/schema: none.
- Routers (all admin, all confirm-gated):
  - `POST /engines/plan` → `{plan_id, host, steps, total_disk_mb, disk_free_gb, disk_after_gb,
    warnings, blocked, noop}`; no side effect.
  - `POST /engines/install` `{host, engines[], plan_id, confirm}` → `{job}`; 400 without `confirm`,
    409 on a stale plan or a running host job, 422 on an unknown engine/runtime.
  - `POST /engines/uninstall` `{host, id, confirm}` → `{job}`; 404 when the engine is not installed on
    that host.
- Services/jobs:
  - `apps/backend/app/services/inference_plan.py` (new) — `build(host, engines, inventory) -> dict`.
    Fixed argv per runtime, no interpolation of user strings:
    - `uv`: `["uv", "venv", "<engines>/<id>-<version>"]`, then
      `["uv", "pip", "install", "--python", "<engines>/<id>-<version>/bin/python", "<package>==<version>"]`.
    - `pip`: `["python", "-m", "venv", "<engines>/<id>-<version>"]`, then
      `["<engines>/<id>-<version>/bin/python", "-m", "pip", "install", "--no-input",
      "<package>==<version>"]`.
    - `docker`: `["docker", "pull", "<repo>@sha256:<digest>"]`.
    - uninstall: `["rm", "-rf", "<engines>/<id>-<version>"]` for venv runtimes, `["docker", "rmi",
      "<repo>@sha256:<digest>"]` for docker.
    `plan_id = sha256(canonical(host, steps, inventory_updated_at))[:16]`.
  - `apps/backend/app/services/inference_jobs.py` (new) — `enqueue_engine(db, c, host, action, engines,
    plan_id)`, `running_for_host(db, host)` (any `engine_apply`/`model_pull` in `queued|running`), and
    `payload(db, job)` returning `{host, action, engines, plan_id}` for `engine_apply` (T-1011 appends
    the `model_pull` branch to the same function).
  - `deps.audit(db, c.ws.id, c.user.id, "inference.engine_install" | "inference.engine_uninstall",
    host, {engines, plan_id, job_id})` on enqueue.
- Permissions + workspace isolation: `owner`/`admin`; `host` must be in this deployment's host list,
  else 404; the project-free job has `project_id=None`.
- Secrets/safefetch: none; no URL is fetched.
- OpenAPI: yes.

## Acceptance criteria
- [ ] The plan shows exact argv, bytes and disk after, and changes nothing on the host or the database.
- [ ] Install and uninstall need `confirm: true`; a stale plan and a busy host return 409 with the reason.
- [ ] No request field can add an argument, a path or a URL: only ids, catalogue versions and enums.
- [ ] One engine job at a time per host; other hosts are unaffected.
- [ ] Audit names host, engines, plan id and job id, and contains no token or absolute path.
- [ ] Admin-only; foreign host 404; flag off 404.

## Notes for the implementer
The plan is the contract: the worker re-validates `plan_id` against its own inventory and refuses a
mismatch rather than trusting the API. Keep `payload()` in the service so `routers/remote.py` gains one
dispatch line, not a branch per kind.
