## User story
As a video reviewer, I want a batch of videos marked with action segments by a model, so that a 30-minute clip does not need frame-by-frame scrubbing.

## UX flow (LabelDesk words)
1. **Videos → a batch → Auto label** (dialog is T-160) — the client posts actions (class + one line "when it happens"), a sample rate and the video selection. [loading: "Queueing…"] [error: 400 names the offending video (longer than 30 minutes, still extracting), the frame rate outside `0.5–12`, or a class from another project]
2. **Preview a range** — a range of at most 30 seconds is sampled at the same rate, scored and returned as proposed segments without saving anything; the response carries `frames_seen` so the dialog can show what the preview cost.
3. **Run** — the job is queued with `kind="video_autolabel"` and the chosen actions; existing segments of the touched classes in those videos are replaced, and the job reports per-video progress.
4. **Presence to segments** — a sampled frame marks a class present when the model returns at least one detection of it above the threshold; contiguous present samples become one segment, adjacent segments separated by less than 0.75 s are merged, and a segment shorter than 0.4 s is dropped. Segments carry status `review`.
5. **Cost** — one AI call per sampled frame, checked before each frame like the image job: at the allowance the run stops cleanly with `quota_clamped: true` and keeps the segments it already wrote. Cancel is honoured between frames. [error: a model runtime failure fails the job with a short message and keeps prior output]
6. **Sample-rate honesty** — the dialog states "8 frames a second catches short actions and costs more"; the estimate is `duration × fps` per video.
7. **Limits** — a video over 30 minutes is refused before the job starts; the whole selection is capped at 50 videos per run.

## Backend changes
- Models/schema: none beyond T-146; `Job.params` carries the request.
- Routers: `POST /api/ws/{ws}/projects/{project}/videos/autolabel` `{video_ids, actions: [{class_id, description}], sample_fps = 8, replace = true, threshold = 0.4}` → the Job; `POST /videos/autolabel/preview` `{video_id, actions, sample_fps, start_s, end_s}` → `{segments, frames_seen, model}` with `end_s - start_s ≤ 30`; both gated by `task_video_segments` **and** `task_video_autolabel`.
- Services/jobs: `services/video_autolabel.py` (new) — `validate_request(project, videos, actions, fps)` (duration ≤ 1800 s, fps 0.5–12, ≤ 50 videos, classes in project), `sample_times(start, end, fps)`, `segments_from_presence(times, presence, {merge_gap: 0.75, min_len: 0.4})`, `analyse(video_path, times, params, ...)` using `cv2.VideoCapture` and `adapters/refine.label_image` per sampled frame; `handlers/video_autolabel.py` (new) — `run_video_autolabel(job)` writing `VideoSegment` rows, metering one `ai_calls` per frame, honouring `w._cancelled`; registered by adding the module to `handlers/__init__.py`.
- Permissions + workspace isolation: `c.need("reviewer")` on both routes (it spends credits); videos are resolved through the project scope, so a foreign video id is 404; action class ids are validated against the project.
- Secrets/safefetch: none.
- OpenAPI: yes — two routes.

## Acceptance criteria
- [ ] A run queues one job that samples at the requested rate, writes segments for the touched classes only, and reports per-video progress.
- [ ] Contiguous presence merges, sub-0.4 s blips drop, and segments land in `review`.
- [ ] A preview of at most 30 seconds returns segments and `frames_seen` without writing anything.
- [ ] The allowance clamps the run cleanly and cancel stops between frames, both keeping earlier output.
- [ ] Empty, loading and error states above all render (client states are T-160's).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ both routes 404 and the Videos page is unchanged.
- [ ] Keyboard-only path: not applicable in this card.

## Notes for the implementer
Threshold decision: a frame counts as present when a detection of that class scores at or above `threshold` (default 0.4). Keep `segments_from_presence` pure and tested — the segment boundaries are the part users will argue about, not the inference.
