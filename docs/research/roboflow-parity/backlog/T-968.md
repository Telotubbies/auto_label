## User story
As an ML engineer whose training config lives in a repo, I want to point LabelDesk at that file and
have the trainer read it, so that the run is reproducible from the commit instead of from my memory
of a form.

## UX flow (LabelDesk words)
1. **Project → Train → "Use a spec from my repo"** — a paste box for the spec text and a file picker
   (`labeldesk.yaml`). [empty: no text yet — the box shows the smallest valid example, greyed] [loading:
   "reading the spec" while the parse runs] [error: the parse error names the line and the key, e.g.
   "line 6: `entry_points.train.command` is required"].
2. **Parsed preview** — the spec renders as the trainer's own fields: entry point rows with their
   parameters and defaults, the dataset reference, the model family. [empty: the file has no entry
   points — "add one `main` entry point to run this"] [loading: none, the payload is already in hand]
   [error: an unknown parameter type — the row is red and Run is disabled].
3. **Save** — "save this spec to the project" stores the parsed spec on the project so the next
   person sees it without the repo. A later edit to the file never rewrites a stored run.
4. `GET /api/ws/{ws}/projects/{project}/run-spec` returns the stored spec (or 404), `PUT` accepts the
   text and returns the parsed form or a 400 with `{line, key, message}`.

## Backend changes
- Models/schema: `projects.run_spec` JSON column, nullable, default NULL — one `ADD COLUMN` block in
  `app/schema/dataset.py` next to `PROJECTS`, registered in `schema.apply`. Backfill: none.
- Routers: `routers/projects.py` gains `get_run_spec` / `put_run_spec`; PUT body `{text: str}` (≤ 32 KB,
  422 above), returns `{spec: {...}}` or 400 `{line, key, message}`.
- Services/jobs: `app/services/run_spec.py` (new) — `parse(text) -> dict`, `validate(spec) -> dict`
  (raises `SpecError(line, key, message)`), `example()`. Accepted keys only: `name`, `entry_points`
  (≤ 8, each `command` + `parameters`), `dataset`, `model`. Parameter types: `string|float|int`.
- Permissions + workspace isolation: read needs `project.read`, write needs `project.settings`; the
  project is resolved by `project_ctx` (`deps.py:151-158`), so a foreign slug is a 404.
- Secrets/safefetch: none — the spec is text, never fetched from a URL.
- OpenAPI: yes.

- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
