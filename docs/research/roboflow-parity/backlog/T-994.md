## User story
As an agent that has looked at the data, I want to upload, label, auto-label, version, train and infer — but
only after I have been told what each one costs and only when the operator's key allows it — so that a
mistake costs a preview, not three credits.

## UX flow (LabelDesk words)
1. **The first call without `confirm`** — every spend/overwrite tool answers a dry run: what it would
   change, how many images, how many credits, and the sentence "call again with confirm: true". Nothing is
   written, nothing is charged.
2. **`write_annotations` with `confirm: true`** — the image's annotation set is replaced; the answer is
   `{"saved": n, "status": ...}`. [error: a bad shape → tool error with the API's field message; a `classId`
   from another project → 400].
3. **`run_auto_label` with `confirm: true`** — a job is queued and the agent polls `get_job`; the tool never
   waits. [error: no model → `choose a trained model`; 402 when the AI-call allowance is gone].
4. **`create_version`, `start_training`** — same shape: dry run with the credit cost, then a job id.
   [error: 402 names the plan; a version that is still generating is a 409 from the export path].
5. **`upload_image_url`** — no confirm, because it only adds: the API fetches the URL through `safefetch`
   (public addresses, 20 MB, 10 s) and dedupes on the image hash. [error: a blocked URL is a tool error with
   the API's reason, e.g. `URL points to a private or reserved address`].
6. **`predict_image`** — dry run shows 0.001 credits, then the predictions.
   [error: both `image_id` and `image_url` given → one readable tool error, not a silent choice].

## Backend changes
- Models/schema: none.
- Routers: none new — this card calls `/api/v1` and the routes added by T-990/T-991.
- Services/jobs: `apps/mcp/labeldesk_mcp/tools_write.py` (new):
  `register(server, api)` declares the six tools and appends `name -> scope` to `TOOL_SCOPES`
  (`upload`, `write` ×3, `train`, `infer`). One shared gate:
  `preview(tool, confirm, would: dict) -> dict` returns `{"dryRun": True, "tool": tool, **would,
  "next": "call again with confirm: true"}` when `confirm` is false and `None` when it is true.
  Each spend tool computes `would` from a cheap read it already has: annotation count via `get_image`, target
  count via `list_images(annotated="no")`, credits from the published table (3 / 0.5 / 0.01 per image /
  0.001). Every tool carries `readOnlyHint: false` and `destructiveHint` true only for `write_annotations`.
- Permissions + workspace isolation: scopes as above; the API still enforces them (a `write` key calling
  `start_training` gets the route's 403, surfaced as a tool error); ids resolved inside the key's workspace.
- Secrets/safefetch: no fetch in this process. `upload_image_url` sends the URL as the `image` form field to
  the hosted upload route, which is the only place `services/safefetch.py` runs.
- OpenAPI: no.

## Acceptance criteria
- [ ] All six tools refuse to act without `confirm: true` and report what they would have done and cost.
- [ ] With `confirm: true` the API's own validation, metering and 402 behave exactly as they do for a user.
- [ ] `upload_image_url` never downloads anything in the MCP process; the API's `safefetch` does, and its
      refusal text survives to the agent.
- [ ] No tool name can delete, and `write_annotations` is the only one marked destructive.
- [ ] Empty, loading and error states above all render as described (a dry run is a result, not an error).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the mounted endpoint is absent and the stdio behaviour is unchanged by this card.
- [ ] `ruff check apps/backend` clean; the full serial API suite passes.

## Notes for the implementer
The dry run is a normal result, not an error: the model must be able to read the cost and retry. Only a
refusal the caller cannot fix (a 403, a 404, a 402) becomes `isError: true`.
Credit costs are copied from `apps/backend/app/config.py:115` (`train: 3, version: 0.5,
autolabel_image: 0.01, infer: 0.001`); if that table changes, this one changes in the same PR — say so in
the tool description as "per the server's published costs", not as a promise.
