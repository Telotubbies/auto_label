## User story
As an ML engineer, I want to crop, shear and choose which way a 90° rotation goes, with boxes following the pixels, so that mounting-angle and framing variation is trained instead of guessed.

## UX flow (LabelDesk words)
1. **Wizard → step 4 → Add augmentation → Crop / Shear / 90° rotate** — each has only its bounded controls from the table. [empty: n/a] [loading: n/a] [error: "Degrees must be 0–180." inline]
2. **90° rotate** — three checkboxes *Clockwise · Counter-clockwise · Upside-down*; at least one stays on ("Pick at least one direction."). [error: "Pick at least one direction."]
3. **Crop** — one percent field *Drop up to N% of the area*, with the loss note: "Objects fully outside are dropped; partial objects are clipped." [error: "0–50%."]

## Backend changes
- Models/schema: none.
- Routers: none.
- Services/jobs: `app/services/imaging.py` — three ops: `crop` (random box of `1-drop` scale at a random position, then `_map_points` + `_clip`, dropping what falls outside), `shear` (affine shear with `PImage.transform(..., AFFINE)` and the matching inverse affine on normalised points; horizontal and vertical are independent draws), `rotate90` (cw / ccw / upside-down, using the existing transposes; `direction` may list several and one is drawn per image). `flip` keeps its current behaviour but moves into the dispatch table.
- Permissions + workspace isolation: unchanged.
- Secrets/safefetch: none.
- OpenAPI: no.
- Flag: `task_190` off ⇒ `crop`, `shear`, `rotate90.direction` are rejected (`aug_unknown_op`), and the legacy `rotate90: true` keeps 50/50 cw/ccw.

## Tests to write first
pytest — `apps/backend/tests/test_augment_geometry.py`:
- `test_crop_keeps_labels_after_the_cut` — a centred box survives with the transformed coordinates (±1e-3); a corner box outside the crop is dropped.
- `test_crop_never_produces_an_empty_image` — 200 draws with `drop: 10` always return a non-zero-size image.
- `test_shear_moves_boxes_with_the_pixels` — a centred square box after `shear horizontal 20` is a parallelogram-shaped bbox whose centre moves by the analytic amount.
- `test_upside_down_rotation_is_180` — `rotate90` with only `upside-down` equals `ROTATE_180` pixels and maps `(x,y) → (1-x, 1-y)`.
- `test_one_rotation_direction_is_drawn_per_image` — with cw+ccw enabled, two seeds produce both orientations and each output matches one of them exactly.
- `test_obb_and_polygon_stay_valid` — after crop and shear, obb width/height > 0 and polygon points inside `[0,1]`.
- `test_flag_off_rejects_the_new_ops` — `crop` → `aug_unknown_op`.

## Notes for the implementer
Shear in Pillow needs `inverse=True` handling care: transform the image with `AFFINE` and map points with the **inverse** matrix, or boxes will lean the wrong way. Write the matrix once, in one helper used by both.
