## User story
As a labeler, I want to convert a group of shapes to another kind, union overlapping masks and restack them, so that an object split by an occluder becomes one label instead of two.

## UX flow (LabelDesk words)
1. **Canvas, shapes selected → right-click** — a context menu opens at the pointer: **Duplicate**, **Convert to box**, **Convert to polygon**, **Convert to mask**, **Merge masks**, and the four order actions. Items that do not apply are disabled with a reason ("Merge needs two or more masks"). [empty: right-click on empty canvas keeps the browser menu suppressed and shows nothing]
2. **Convert** — converting runs on the server and replaces the selected annotations in place, keeping each id, class and source, and marks them `source: "human"` (a human chose the new kind). One undo step, one save. [loading: the menu closes and a small "Converting 3 shapes…" chip shows over the canvas] [error: a shape with fewer than three points cannot become a polygon → the toast names it and nothing changes]
3. **Convert to mask** — the polygon is rasterised at the image's own resolution, then RLE-encoded with the same validator as the brush; the resulting mask carries a box for culling and the Objects row switches kind.
4. **Merge masks** — enabled only when every selected shape is a mask. The union keeps the primary selection's class and colour, and the merged annotation takes the front-most position of the group. Overlapping holes are preserved as holes; disjoint parts become one mask with several components.
5. **Order** — "To front" moves the whole selection to the front preserving its relative order; Forward/Backward step the group one position; the Objects list shows the new stack positions.
6. **Objects panel parity** — the same actions appear in a **Selection** block for the keyboard user: Tab to the block, arrow the menu, `Enter` runs it.

## Backend changes
- Models/schema: none — converted shapes are ordinary annotations.
- Routers: new `POST /api/images/{image_id}/shape-convert` — body `{op: "convert"|"merge", annotation_ids: [str], to?: "bbox"|"polygon"|"mask", epsilon?: float}`; response `{annotations: [...]}` (the converted set, unsaved); `400` for an unknown op/target, an id not on this image, a mask target with `task_mask` off, or a merge of fewer than two masks; `422` when a polygon has fewer than three points.
- Services/jobs: `services/shape_convert.py` (new) — `to_polygon`, `to_bbox`, `to_mask` (cv2 fill at image resolution), `merge_masks` (numpy union), each returning the same shape dicts `_check_ann` accepts; `services/masks.py` (T-133) does the encoding.
- Permissions + workspace isolation: `image_ctx` write check (`project.annotate`) and the labeler assignment rule; a foreign image id is 404, and ids that belong to another image are 400.
- Secrets/safefetch: none.
- OpenAPI: yes — one new route.

## Acceptance criteria
- [ ] A selection can be converted to box, polygon or mask; each conversion keeps id and class, is one undo step and one save.
- [ ] Merging two or more masks yields their union with holes preserved, the primary class and the front-most position; a mixed selection cannot merge.
- [ ] Order actions apply to the whole group in the stated direction and are reflected in the Objects list immediately.
- [ ] Every disabled menu item states its reason; the same actions exist in the Objects panel for keyboard use.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ mask conversion and mask merge disappear from the menu; box ↔ polygon conversion still works.
- [ ] Keyboard-only path: select two masks in the Objects list → Tab to the Selection block → Enter on Merge.

## Notes for the implementer
The endpoint returns the converted annotations and does **not** write them: the editor replaces them in its own array and lets the normal autosave land, so the conversion participates in undo and in the T-121 stale guard like any other edit. Merge takes the primary's class from the client, not the largest mask.
