## User story
As a team shipping a pipeline, I want to store a test set and a list of rules once, so that "did this change break counting?" is a stored artifact rather than a manual check.

## UX flow (LabelDesk words)
1. **Models → Regression tab** — a list of suites: name, workflow, image source, check count, last run (result and time). [empty: "No regression suites yet — pin a few images with known answers and add a rule." with one primary *Create suite*] [loading: four row skeletons] [error: "Suites could not be loaded" + Retry]
2. **Create** — a dialog with four steps in one page: *What runs* (workflow), *What it runs on* (a dataset test split or pinned images, 5–200), *What must hold* (the check list, one row each), *When it may ship* (optional minimum pass rate). The primary is *Save suite*, not *Run* — running is a separate act.
3. **The check grammar is visible** — each row is a small sentence builder: "count of `<class>` is at least `N`", "`<field>` equals `value`", "response time is under `N` ms", "text contains `…`", "class `<x>` is present". Invalid combinations are refused inline with the reason, never silently dropped.
4. **Saving** — the suite appears in the list with "never run"; a *Run* action is T-293's.
5. **Editing** — a suite is editable until its first run; afterwards editing forks a new version number (`name` stays, `version` increments) so a past run keeps its own rules.

## Backend changes
- Models/schema: new tables in `apps/backend/app/models/training.py` — `EvalSuite`: `id`, `workspace_id` FK, `project_id` FK, `name` `VARCHAR(120)`, `version` `INTEGER DEFAULT 1`, `workflow_id` `VARCHAR(32)`, `source` JSON (`{kind:"split"|"images", version_id, split, image_ids}`), `checks` JSON (list of `{code, params}`), `gate_min_pass` `FLOAT NULL`, `created_by`, `created`, `updated`; `UNIQUE(project_id, name, version)`. `EvalRun` is T-293's. Register both names in `models/__init__.py`.
- Routers: new `apps/backend/app/routers/regression_evals.py` (registered in `routers/__init__.py`): `GET {P}/evals` → suites with `last_run`; `POST {P}/evals` → `201 suite`; `PATCH {P}/evals/{id}` → forks a version when the suite has runs; `DELETE {P}/evals/{id}`; **400** cases: an unknown check code ("unknown check 'count_lt'; valid: count_gte, count_eq, class_present, value_range, text_contains, latency_lte"), a source with fewer than 5 or more than 200 images, a missing workflow, a foreign `version_id`.
- Services/jobs: new `apps/backend/app/services/eval_checks.py` — `CHECKS` registry of `(code, params_schema, evaluate(output, params) -> bool, sentence(params))`; `validate(checks, classes) -> list[dict]` raising `ValueError`; `run_checks(output, checks) -> {passed, failed: [{code, sentence, expected, actual}]}`. Pure functions, no workflow import.
- Permissions + workspace isolation: read = `c.perm("project.review")`, write = `c.need("admin")`; every suite is project-scoped so a foreign id is 404.
- Secrets/safefetch: none — a check never calls out; the workflow it names does, under the workflow runner's existing guards.
- OpenAPI: yes — new router (regenerate both files).

## Acceptance criteria
- [ ] A suite stores a workflow, an image source, a validated check list and an optional gate.
- [ ] An invalid check, source size or workflow is a 400 naming what is valid.
- [ ] Editing a suite that has run forks a version instead of rewriting history.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ every route 404, no tab, no table.

## Notes for the implementer
Checks are data, never code — a string code plus typed params, evaluated by a closed registry. If a future check needs an expression, add a code; do not add an evaluator.
