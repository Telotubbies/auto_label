## User story
As a project lead about to hand numbers to a customer, I want the leak audit on the evaluation header, so that I see the inflated figure before I quote it.

## UX flow (LabelDesk words)
1. **Model page → Evaluation** (`/:ws/:project/models?model=<id>`) — the header row carries the `Leak audit` chip: `Hold-out clean`, `{n} cross-split pairs`, `Checking…`, or `Not scored yet`. [loading: `Checking…` with a spinner, the panel below renders normally]
2. **Open the audit** — a dialog lists the pairs with both thumbnails, their hash distance and their splits, then the `Score without leaks` action. [error: the audit request fails ⇒ "The audit could not run" with a retry; nothing else on the page is affected]
3. **The two numbers** — a comparison strip reads "0.68 without leaks, 0.74 as it stands" with the delta; when the audit says the sample is too thin, the strip prints the stated sentence and no second figure.
4. **Write the cleaned split** — a secondary action creates a version with `exclude_leakage` and lands the user on Versions with the new version's job visible in the tray. [loading: the button shows pending and then hands off to the existing version job]
5. **A model whose split is already clean** — the chip is green, `Score without leaks` is hidden, and the cleaned-version action is disabled with "This hold-out is already clean." [empty: no pairs renders one line, never an empty list]

## Notes for the implementer
Show the as-it-stands number first in the panel and the cleaned number only inside the audit — the stored score stays the headline, so no existing screenshot or report silently changes meaning. The cleaned-version action reuses the Versions wizard's own call (`settings: {exclude_leakage: true}`), never a bespoke route.
