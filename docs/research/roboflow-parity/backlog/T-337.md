## User story
As a plant engineer, I want each production event to say what kind of thing it was and carry the few fields my shift report needs, so that safety alerts and inventory counts stop living in one undifferentiated list.

## UX flow (LabelDesk words)
1. **Project settings → "Event vocabulary"** (`/:ws/:project/settings?tab=events`) — the five fixed types are shown read-only (`quality_check`, `inventory_count`, `safety_alert`, `operator_feedback`, `custom`), and the project adds up to eight metadata keys with a name, a type (`text`, `number`, `boolean`) and an example. Unknown keys sent with an event are dropped and counted, never stored.
2. **A rule carries a type** — each rule in the stream editor gains one select: "Event type", defaulting to `custom`. `[empty: a project with no vocabulary yet → the settings tab says "Add the fields your report needs. Nothing is required." and events still record their type]` `[error: a metadata key with a space or a symbol → inline "Use letters, digits and underscores."]`
3. **An event** — the timeline row shows its type as a chip before the rule label, and the detail sheet lists the metadata as key/value rows with their types. `[error: a rule whose type was removed from the vocabulary keeps the stored string and shows "(removed type)" instead of crashing]`
4. **The API** — `POST /streams/{sid}/events` (an external system pushing an event) accepts `{type, metadata, image?}` and validates against the project's vocabulary; a `custom` type needs no metadata.

## Backend changes
- Models/schema: `stream_events` gains `event_type VARCHAR(32) NOT NULL DEFAULT 'custom'` and `meta JSON` (nullable); `streams` gains nothing (the rule's type lives in its JSON). `ADD COLUMN` lines appended to `STREAM_EVENTS` in `app/schema/streams.py`. `projects.settings.event_vocabulary` holds the keys — no new table.
- Routers: `apps/backend/app/routers/streams.py` — `check_rules` accepts an optional `event_type` per rule; a new `POST /{sid}/events` accepts an externally pushed event (type, metadata, optional image through `services/safefetch` for a URL); `GET /{sid}/events` returns `event_type` and `meta` on each row.
- Services/jobs: `apps/backend/app/streams/event_types.py` (new) — `EVENT_TYPES`, `VOCABULARY_LIMITS = {"keys": 8, "value_chars": 200}`, `validate_vocabulary(keys) -> list[dict]`, `clean_metadata(vocabulary, raw) -> (meta, dropped)`, `type_of(rule) -> str`. `streams/manager.py` writes `event_type` and `meta` next to the existing `filter_fields` call.
- Permissions + workspace isolation: pushing an event needs `project.annotate` (it is a write) plus the existing `task_10b` flag; the stream is resolved inside the project as today.
- Secrets/safefetch: a pushed image URL goes through `safefetch.fetch`; base64 and multipart are also accepted, capped at 20 MB.
- OpenAPI: yes — one route and two fields.

## Acceptance criteria
- [ ] Every event records one of the five types, defaulting to `custom`, from a rule or from a pushed event.
- [ ] A project's vocabulary caps at eight typed keys; unknown keys and wrong types are refused with the key named, and nothing unknown is stored.
- [ ] A removed vocabulary key leaves old events readable.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no settings tab, no type select, today's event rows unchanged.

## Notes for the implementer
The five types are fixed, not user-defined: a free-text type would make the QA query unindexable. `custom` exists so a rule always has an answer, not so a project can invent six of them.
