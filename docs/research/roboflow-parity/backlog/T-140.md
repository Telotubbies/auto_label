## User story
As a labeler, I want to pick a model from three sources and say which project class each of its classes means, so that a foundation model's "hardhat" lands on my "helmet".

## UX flow (LabelDesk words)
1. **Editor top bar → assist button** — opens the picker. Three tabs, one per source: **Foundation models**, **Your models**, **Model zoo**. The tab that opens first is the last one used; with no trained model and no reachable foundation model, it opens on **Model zoo** and says "No model of yours is ready yet". [loading: a skeleton list per tab] [error: the registry read failed → "Models could not be loaded" with a retry, and Continue is disabled]
2. **Model list** — each row: name, family chip, licence, capabilities, and a trailing state. A model the workspace cannot run is listed but disabled with its reason in the row ("Not installed on this worker", "GPU busy", "Licence not accepted") — never hidden. [empty: a tab with no entries says "No model in this source yet" and links to Train]
3. **Pick a model → class step** (same sheet, step 2) — the model's classes, all ticked by default, each with a select mapping it to a project class. Model classes with no project equivalent offer **Create "helmet"** inline. Unticking drops that class from the output.
4. **Output shape** — segmentation projects choose **Polygons** or **Masks** (the choice is remembered in the session); detection projects show no control.
5. **Continue** — saves the session (T-139), runs assist on the current image, closes, and the top bar shows **Assist: <model>** with a chevron to reopen. **Stop assist** sits at the bottom of step 1 and deletes the session.
6. **Credit and permission states** — with `project.infer` missing, the button is absent; at the AI-call allowance the picker opens but Continue reads "No AI calls left on this plan" and links to Usage.
7. **Keyboard** — the tabs are arrow-key navigable, the class rows are checkbox + select pairs, and Continue carries the count it will produce ("Continue · 3 classes").

## Acceptance criteria
- [ ] The picker lists foundation, trained and zoo models with availability and a reason for every disabled row.
- [ ] The class step maps each model class to a project class, can create a missing class inline, and unticking drops that class from the payload.
- [ ] Segmentation projects choose polygon or mask output and the choice persists in the session.
- [ ] Continue saves the session, runs assist once and closes; Stop assist deletes it.
- [ ] Empty, loading and error states above all render, including "No model of yours is ready yet".
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — through T-139's scoped routes.
- [ ] Flag off ⇒ the one-click assist button from today is unchanged; the picker is not rendered.
- [ ] Keyboard-only path: Tab to assist → Enter → arrow tabs → Enter model → Tab class rows → Enter Continue.

## Notes for the implementer
The model list comes from `GET /registry` (`adapters/catalog.catalog`), which already carries `available` and `reason` — do not re-derive availability in the browser. Creating a class inline is the existing `POST /classes`; a 409 means it already exists, so adopt it.
