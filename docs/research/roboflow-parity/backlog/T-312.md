## User story
As an operator who cannot send images to someone else's server, I want the self-hosted server documented where deployment is chosen, so that I can install it without leaving the product or paying credits for it.

## UX flow (LabelDesk words)
1. **Deploy & test → Delivery options → "Your own server"** — a card with the one-line claim: "The same request shape, on your hardware. No credits are charged for an image you process yourself." A secondary "Read the install guide" opens the accordion in step 2, and "Copy the request" hands the cURL that points at `http://localhost:8010/predict`.
2. **Install accordion, four platforms** — `Docker (CPU / ONNX)`, `Docker (GPU / .pt)`, `docker compose`, `Jetson`. Each is one copyable block from the shipped files: the CPU and GPU `docker run` lines and the `--profile inference` compose line, with the mount path `./models:/models:ro`. Jetson carries the honest line "Cross-build only — this repository does not ship a tested Jetson image." [empty: no mount yet → "Put your exported files in `deploy/models/` first; the server refuses to start with an empty directory."] [loading: the copy button keeps its width and shows "Copied" for 2 s] [error: clipboard refused → the block is still selectable text, with "Select the text and copy it" instead of a silent no-op]
3. **What it accepts** — a two-column table: `GET /healthz` (models mounted, backends available) and `POST /predict` (`file`, `confidence`, `model`), plus "20 MB per image" and "one container serves one tenant, no API key". Response shape is the same `predictions · image · time` the hosted API returns, stated once.
4. **Where it does not help** — one line: "Weights you did not train here may carry their own licence; check the licence badge before you ship them." Links to the existing Models licence note instead of repeating it.

## Backend changes
- Models/schema: none.
- Routers: none — the copy is static and the commands come from the repository, so the product cannot drift into advertising a route the container does not serve.
- Services/jobs: none.
- Permissions + workspace isolation: inherits the Deploy screen's `project.models`; no new data.
- Secrets/safefetch: none — no host, token or key is printed. The example uses `localhost:8010`.
- OpenAPI: no.

## Tests to write first
pytest — `none: no backend surface`.
node — `apps/frontend/tests/deploy-selfhost.test.mjs`:
- `test_every_platform_block_is_copyable_and_non_empty` — all four `INSTALL` entries have a label, a hint and a command containing `apps/inference` or `docker compose`.
- `test_the_cpu_and_gpu_blocks_name_the_image_they_build` — the CPU block names `labeldesk-inference:cpu`, the GPU block `labeldesk-inference:gpu`.
- `test_jetson_says_it_is_not_a_published_image` — the Jetson hint contains "not a published image" and its command contains `linux/arm64`.
- `test_predict_curl_carries_no_key` — `predictCurl("http://localhost:8010", "ppe/best.onnx")` contains `-F "model=ppe/best.onnx"` and no `api_key`, `Authorization` or `Bearer`.
- `test_the_endpoint_table_lists_healthz_and_predict` — `ENDPOINTS` covers `GET /healthz` and `POST /predict` with the 20 MB cap on `predict`.

## Acceptance criteria
- [ ] The self-hosted row is reachable from the chooser and lands on a card that says no credits are charged.
- [ ] Four platform blocks copy the commands that exist in `deploy/docker-compose.yml` and `apps/inference/README.md`, and the Jetson block states it is not a published image.
- [ ] The response-shape line matches what the container returns (`predictions`, `image`, `time`), and no snippet contains a key or a real hostname.
- [ ] Empty, loading and error states above all render, including the empty model mount and a refused clipboard.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — no data is read here beyond the existing page.
- [ ] No flag: the section is reachable only from the chooser row, so a deployment that hides T-311 hides this with it.

## Notes for the implementer
Port `8010`, mount `/models`, image tags `labeldesk-inference:cpu` / `:gpu` are the shipped values (`deploy/docker-compose.yml:74-82`, `apps/inference/README.md:58-99`); do not invent a `pip install` CLI this repository does not have. Every command in this card must be copied from a file and re-checked by the test above, because a wrong command is worse than no card.
