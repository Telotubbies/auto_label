## User story
As an engineer who resumed a run for ten more epochs, I want the new run to point at the one it continued, so the
project does not read as two experiments that happened to share a name.

## UX flow (LabelDesk words)
1. **Models → a resumed run** — under **Run settings**, a lineage row: `Continued from <parent name> · 10 more
   epochs` with the parent's status dot, and on the parent `2 continuations`. [empty: a run started from
   pretrained weights renders no lineage row at all] [loading: the row reserves its height]
   [error: a parent that has since been deleted renders `Continued from a run that was deleted.` as plain text,
   with no link]
2. **Click the parent name** — navigates to `…/models?model=<parentId>` and the detail panel opens the parent;
   clicking *continuation* does the mirror.
3. **A chain of three** — the row shows the whole chain `A → B → C` on one line; the current run is bold and not a
   link, the others are links. A cycle can never render: the walk stops at the first repeat.
4. **Insights → Training** — the run chip's title adds `continued from <parent>`; selecting both parent and child
   is how the two segments are read as one curve today.

## Backend changes
- Models/schema: none — the relationship is already recorded in `Job.params.options.resume_from`
  (`routers/training.py:277-278`). Do **not** add a column: a second copy can disagree with the job.
- Routers: `apps/backend/app/routers/training.py` — in `models()` and `get_model()`, one line each:
  `d["parentId"] = run_view.parent_id(j)`, where `j` is the job already loaded at `:160` / `:307`.
- Services/jobs: `apps/backend/app/services/run_view.py` — add
  `parent_id(job: Job | None) -> str | None` reading `(job.params or {}).get("options", {}).get("resume_from")`,
  returning `None` for a missing job. No writes, no backfill.
- Permissions + workspace isolation: the parent id is only emitted when the caller may see the project's models;
  a parent in a foreign workspace cannot occur (train validates the parent's workspace at
  `routers/training.py:264-266`), and the front end resolves names from the list it holds, so an unknown parent
  renders as deleted rather than leaking a name.
- Secrets/safefetch: none.
- OpenAPI: yes — `ModelItem.parentId`; `python tools/export_openapi.py`, then `npm run gen:api-types`.

## Tests to write first
pytest — `apps/backend/tests/test_run_lineage.py`:
- `test_a_resumed_run_points_at_its_parent` — train with `resume_from=<ready model>` → the new row's `parentId`
  is the parent id and the parent row's `parentId` is null.
- `test_a_run_from_pretrained_has_no_parent` — no `resume_from` → `parentId` null (the empty state).
- `test_a_chain_of_three_is_walkable_from_one_list_call` — C resumes B, B resumes A → one `GET /models` is
  enough to walk C→B→A; assert the ids in order.
- `test_a_deleted_parent_leaves_the_child_addressable` — hard-delete A → C still 200 with `parentId` pointing at
  a missing row (the UI renders the deleted copy; the API does not 500).
- `test_a_foreign_project_model_is_404` — workspace B's token on workspace A's resumed run id → 404.

node — `apps/frontend/tests/run-lineage.test.mjs`:
- `test_the_chain_reads_root_to_leaf` — C→B→A → `['a','b','c']` with the current id last.
- `test_a_cycle_stops_at_the_first_repeat` — a→b→a → length 2, no infinite loop.
- `test_continuations_list_every_child_newest_first` — two children of one parent → both ids, newest first.
- `test_a_missing_parent_renders_the_deleted_copy` — the source ships
  `Continued from a run that was deleted.` and no anchor for an unknown id.

## Acceptance criteria
- [ ] A resumed run shows its parent and the parent shows its continuation count, from one list request.
- [ ] Clicking either side opens that run in the detail panel without a reload.
- [ ] A deleted or foreign parent never renders a link and never breaks the row.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: `5-F5.18` → T-005 (guard: "continue from the last checkpoint" is HAVE), `5-F5.8` → T-259 (the starting-weights
