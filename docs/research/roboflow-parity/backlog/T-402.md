## User story
As an admin, I want to forbid public projects and vendor training once, in one place, so that a member cannot
publish data by accident.

## UX flow (LabelDesk words)
1. `GET /api/ws/{ws}/policies` → `{policies: {allow_public_projects: bool, allow_vendor_training: bool},
   locked: {allow_public_projects: null | "plan" | "region" | "policy",
   allow_vendor_training: null | "plan" | "region" | "policy"}, updated: {by, at}}`.
2. `PATCH /api/ws/{ws}/policies` `{allow_public_projects?, allow_vendor_training?}` → the same shape; `409`
   `This setting is locked by your plan or region.` when the field is locked; `403` without `workspace.update`.
3. Defaults: both `true`. A workspace that has never written a row reads the defaults, so no backfill.
4. `[empty]` a workspace with no row is not an error — the payload is the two defaults.
5. `[error]` an unknown key in the body is a `422`, never silently ignored.

## Backend changes
- Models/schema: `Workspace.allow_public_projects: bool = True`, `Workspace.allow_vendor_training: bool = True`;
  `ADD COLUMN` additions to `WORKSPACES` in `app/schema/identity.py`
  (`"allow_public_projects": "BOOLEAN DEFAULT TRUE"`, `"allow_vendor_training": "BOOLEAN DEFAULT TRUE"`).
- Routers: `routers/workspaces.py` — the two routes above, both behind `workspace.update`; a foreign slug is 404
  from `ws_ctx`.
- Services/jobs: `app/services/workspace_policy.py` (new) — `DEFAULTS`, `POLICIES = tuple(DEFAULTS)`,
  `read(db, ws) -> dict`, `set_policies(db, ws, values, actor) -> dict`, `lock_reason(ws, key) -> str | None`
  (plan/region come from `config.PLANS` and `ws.data_region`; `None` today for every key, so the lock renders as
  reachable and the copy is ready when a lock exists), and `allows(db, ws, key) -> bool` for the enforcement sides.
- Permissions + workspace isolation: `workspace.update` (owner/admin); `allows()` is read by any member's path and
  only ever reads `c.ws`.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Frontend changes

- Feature flag: `task_policy_switches`; off ⇒ both routes 404 and `allows()` returns `True`.

## Acceptance criteria
- [ ] Both switches exist per workspace, default on, and can be set independently.
- [ ] A locked switch refuses the write with the lock sentence and does not change the stored value.
- [ ] Every change is audited with the previous and new value.
- [ ] Empty, loading and error states above all render (no row, 409 lock, 422 unknown key).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no routes, and every caller of `allows()` behaves as if both were true.

## Notes for the implementer
Two typed columns, not a JSON bag: the enforcement sides read a boolean, and a JSON bag would make every reader
re-parse. `lock_reason` returns `None` for every key today; wire the plan/region rule but do not invent a lock.
