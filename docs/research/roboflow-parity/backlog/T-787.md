## User story
As the person who has to quote an accuracy figure to a customer who will run their own acceptance test, I want the test split scored twice — once as it stands, once without images that also appear in train — so that I publish the honest number and its gap.

## UX flow (LabelDesk words)
1. **Model page → Evaluation** (`/:ws/:project/models?model=<id>`) — a `Leak audit` chip reads `Hold-out clean` or `{n} cross-split pairs`. [loading: the chip reads `Checking…` and does not block the evaluation panel] [empty: a model with no evaluation says `Not scored yet` and the action is disabled with its reason]
2. **Open it** — the dialog lists the offending pairs with both thumbnails and their hash distance, and states which split each side belongs to.
3. **Score without leaks** — runs the evaluation over the test split with the leaked images removed and prints both numbers with the difference: "0.68 without leaks, 0.74 as it stands". [error: too few clean test images ⇒ "Too few clean test images to trust a score." and no second number]
4. **Write the cleaned split as a new version** — creates a version whose settings carry `exclude_leakage`, so the next training and the next evaluation both use the cleaned hold-out. [loading: the normal version job runs and the job tray tracks it]
5. **A run whose split is already clean** — the chip is green, the dialog says `No cross-split near-duplicates in this hold-out.` and the cleaned-version action is disabled.

## Backend changes
- Models/schema: none — the audit is computed on demand and the cleaned split is a `Version` with a new setting key; `Version.stats` records `leakage_excluded`.
- Routers: new `app/routers/leak_audit.py` — `POST …/insights/models/{mid}/leak-audit` returning `{pairs, split_pairs, excluded, raw:{AP,AP50}, clean:{AP,AP50}|null, too_few, note}`; the cleaned split is created through the existing `POST …/versions` with `settings.exclude_leakage = true`.
- Services/jobs: `app/services/leak_audit.py` (new) — `audit(db, model)`; `services/evaluate.py` gains `exclude: set[str] | None` so the second pass skips the leaked test files instead of copying the version directory; `services/versioning.py` honours `settings['exclude_leakage']` by dropping test images whose pHash group also holds a train or valid image and counting them in `stats['leakage_excluded']`.
- Permissions + workspace isolation: `project.models` to audit; `reviewer` to create the cleaned version (existing rule); another workspace's model or version answers 404.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate both generated files.

## Tests to write first
pytest — `apps/backend/tests/test_leak_audit.py`:
- `test_audit_reports_the_gap` — a version where one near-duplicate sits in both train and test → `excluded` is 1, `raw.AP` differs from `clean.AP`, and `clean` is lower.
- `test_clean_split_says_clean` — a version without duplicates → `pairs` empty, `clean` equals `raw`, no error.
- `test_too_few_clean_test_images` — three of four test images leaked → `too_few` true, `clean` null, note states the number.
- `test_cleaned_version_excludes_leaked_test_images` — create a version with `exclude_leakage` → its manifest test split omits the leaked image and `stats.leakage_excluded` counts it.
- `test_other_workspace_model_is_404` — workspace B audits A's model → 404.
- `test_flag_off_is_404` — flag off → 404 and the setting is ignored by `generate`.
- `test_evaluate_exclude_skips_files` — `evaluate(..., exclude={'b.jpg'})` never scores `b.jpg`.

## Acceptance criteria
- [ ] The audit names the cross-split near-duplicate pairs for the model's own dataset version.
- [ ] Empty, loading and error states above all render as API states: a clean hold-out returns zero pairs, a thin sample returns its note.
- [ ] A second score computed without those images is returned beside the original, with the difference visible.
- [ ] Too few clean test images is stated as an untrustworthy score rather than a flattering number.
- [ ] A cleaned split can be written as a new version, and the next evaluation uses it.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no audit route and version generation is byte-for-byte today's.

## Notes for the implementer
Reuse `versioning.phash_groups()` — do not write a second Hamming loop, and do not add a dependency. The audit never writes `TrainedModel.metrics`: it is a what-if, and overwriting a stored score with a cleaned one would silently rewrite history. `too_few` is true when fewer than 30 test images survive or fewer than 3 remain, whichever is higher.
