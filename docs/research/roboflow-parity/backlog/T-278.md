## User story
As a reviewer, I want "4 missed, 2 wrong class, 18 correct" beside each class's AP, so that a ratio never hides whether I am looking at two objects or two hundred.

## UX flow (LabelDesk words)
1. **Model → Evaluation → Performance by class** — a table: class, correct, misclassified, missed, false positive, instances, and AP/AP50. The numbers are counts, the AP stays a ratio; the header states the threshold they were computed at.
2. **The slider drives it** — the evaluation's confidence slider recomputes every count live; the header reads "Counts at 0.45" and updates with the slider. [loading: the table keeps its rows and shimmers the numbers]
3. **A class with no ground truth** — the row exists and reads "not evaluated" in the AP columns with 0 instances, never a blank row. [empty: no per-image detections stored ⇒ one card: "Counts need stored per-image detections — this run did not keep them."]
4. **Sort** — clicking a column header sorts by that count; the default order is missed descending, so the worst class is first.
5. **Export** — the table exports CSV through the existing `DataTable` affordance.

- **States** — [error: a failed counts request leaves the AP table in place and adds one line with Retry].

## Backend changes
- Models/schema: none.
- Routers: `GET {P}/insights/models/{mid}?conf=0.45` gains an optional `conf` (clamped `0.05..0.95`, default the stored best F1) and returns `eval.per_class_counts: [{class, correct, misclassified, missed, false_positive, instances}]` plus `eval.counts_conf`.
- Services/jobs: `services/insights_eval.counts(detections, classes, conf) -> list[dict]` — class-agnostic matching at IoU ≥ 0.5 (the existing `match` with `same_class=False` semantics, copied from `evaluate._match`'s confusion pass): a prediction matched to a different-class ground truth counts once as `misclassified` for its own class and once as `missed` for the truth's class; unmatched truth → `missed`; unmatched prediction above `conf` → `false_positive`; same-class pair → `correct`. Called from `services/insights._build_model` when `has_detections`.
- Permissions + workspace isolation: `project.models` (unchanged, `_models_only`); foreign model → 404.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate both files.

## Tests to write first
pytest — `apps/backend/tests/test_eval_counts.py`:
- `test_a_matched_pair_is_correct` — one truth and one prediction, same class, IoU 0.9 → correct 1, everything else 0.
- `test_a_cross_class_match_counts_twice` — truth `helmet`, prediction `vest` at IoU 0.8 → helmet missed +1, vest misclassified +1, and neither class gets a false positive.
- `test_a_low_confidence_prediction_is_not_a_false_positive` — prediction at 0.2 with `conf=0.45` → no false positive.
- `test_counts_sum_to_instances_plus_predictions` — a mixed fixture: `correct + missed == instances` and `correct + misclassified + false_positive == predictions above conf`.
- `test_conf_parameter_changes_the_counts` — `conf=0.9` reduces `correct` versus `conf=0.2` on the same fixture.
- `test_a_class_without_ground_truth_reports_zero_instances` — a prediction-only class → `instances == 0`, `false_positive >= 1`.
- `test_a_classification_or_unevaluated_model_returns_an_empty_list` — no detections → `per_class_counts == []`, no error.
- `test_foreign_model_counts_is_a_404`.

- `test_join_keeps_every_class_and_marks_not_evaluated` — a counts row without AP renders "not evaluated".

## Notes for the implementer
Counts are per **instance**, not per image. Reuse the class-agnostic greedy matching that the confusion matrix already relies on; if you find a second matching implementation, delete the new one and call the old.
