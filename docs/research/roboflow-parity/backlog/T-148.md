## User story
As a reviewer, I want to approve or reject each action segment with a reason, and then hand the set to training, so that video work leaves the tool as data instead of drawings.

## UX flow (LabelDesk words)
1. **Project → Video → Actions → Review** — a list of every segment in the project with status `review`, oldest first: video name, class chip, `2.4–6.1 s`, author, age. [empty: "Nothing to review — every segment is decided"] [loading: skeleton rows] [error: message + retry]
2. **Decide** — `a` approves the focused row and advances (the same key as the image editor), `r` opens a reason field (**Wrong span**, **Wrong class**, **Action not present**) and rejects, `u` undoes the last decision in this session. Buttons do the same for pointer users. [error: a decision on an already-decided segment → the row refreshes and the toast says so]
3. **Rejected segments** — stay visible in the video's timeline with a reason tooltip and an **Edit** affordance that returns them to `review` after a change.
4. **Counts** — the review header reads "3 of 12 decided" and the video row shows `12 segments · 3 to review`.
5. **Export** — **Export segments** in the Actions header exports the current video, or the project's approved segments, as **JSON** or **CSV**; each row carries video, class, start, end and status. The file downloads directly (no job), and the button is disabled with "Nothing approved yet" when the filter is empty.
6. **Export honesty** — segments are exported from this surface, not from a dataset version: versions freeze frames, and claiming otherwise would be wrong. The export dialog says so in one line.

## Backend changes
- Models/schema: none beyond T-146.
- Routers: in `routers/segments.py` — `GET /segments?status=&video_id=&limit=` (project-wide review list) and `GET /videos/{vid}/segments/export?format=json|csv` plus `GET /segments/export?format=` for the project's approved set; both return `text/plain`/`application/json` with `Content-Disposition`.
- Services/jobs: `services/segment_export.py` (new) — `as_json(rows)`, `as_csv(rows)` with a stable column order (`video,class,start_s,end_s,status,note`).
- Permissions + workspace isolation: the review list and decisions need `project.review`; export needs `project.export`; every query filters `project_id` and `workspace_id`, so a foreign video id is 404.
- Secrets/safefetch: none.
- OpenAPI: yes — three routes.

## Acceptance criteria
- [ ] The review list shows every pending segment with video, class, span, author and age, and `a`/`r`/`u` behave as in the image editor.
- [ ] A rejection stores a reason and the segment stays visible with an Edit path back to review.
- [ ] Approval and rejection counts update on the list and on the video row.
- [ ] Export produces JSON or CSV with one row per segment and the documented columns, and refuses an empty approval set.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no Actions tab, no review list, no export.
- [ ] Keyboard-only path: Actions → Review → `a` `a` → `u` → Tab to Export → Enter.

## Notes for the implementer
CSV must quote the note field; a comma in a reviewer's reason is normal. Export is synchronous and streams from the query — do not create a job for a few thousand rows.
