## User story
As an integrator, I want a request outside the documented ranges to be refused with the field named, so that a typo costs me an error message and not a credit.

## UX flow (LabelDesk words)
1. **Deploy & test** — sending `confidence=1.5` from the tester returns "confidence must be between 0 and 1" above the result card, and the credit count in the header does not move. [empty: not applicable — the tester always has a value] [loading: unchanged] [error: the 422 sentence appears where the result would have been]
2. **Hosted predict** — `POST /api/v1/models/{ref}/predict?confidence=1.5` returns 422 naming `confidence` and its range; the response is the same shape whether the ref is a model id or an alias.
3. **Contract panel** — a parameter the guard refuses is marked "enforced" in T-926's table, so the page and the route cannot disagree.

## Backend changes
- Models/schema: none.
- Routers: `apps/backend/app/routers/training.py` — one `check_params(m, kwargs)` call at the top of `test_predict` (`:340`) and of `_hosted_infer` (`:623`), both **before** `charge(...)` and before `metering.check`, so a refused request is free.
- Services/jobs: `apps/backend/app/services/contract_guard.py` (new) — `check_params(model, supplied: dict) -> None` reading `services.model_contract.param_specs()` (T-926) for name/type/min/max, raising `ParamError(name, reason)`; `check_input(model, content_type, size) -> None` refusing a body larger than the documented 20 MB or a type the family cannot read. FastAPI's own `Query(ge=, le=)` strings are reused where they exist, so the message text comes from one place.
- Permissions + workspace isolation: unchanged — `project.infer` / `key_ws` as today; a foreign model id is already a 404 from `_model` / `_hosted_model`.
- Secrets/safefetch: none.
- OpenAPI: yes — `python tools/export_openapi.py`, `npm run gen:api-types` (the 422 shape is documented).

## Notes for the implementer
Overlap: none in Roboflow terms; in our own backlog the *declaration* is T-926 (`ML2-T2.7`), which explicitly places no validator — "the handler stays the enforcement point". This card is that enforcement, and it must read T-926's `param_specs()`, never a second table of ranges.
Keep the message user-facing and generic: name the parameter and its bounds, never the model path or the workspace.
