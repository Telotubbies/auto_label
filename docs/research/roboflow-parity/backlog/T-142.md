## User story
As a reviewer, I want to write the batch's rules once and split its images across two labelers, so that the instructions and the work arrive together instead of in a chat message that scrolls away.

## UX flow (LabelDesk words)
1. **Annotate board → To label lane → batch row menu** — **Instructions** opens a small editor prefilled with any note typed at upload. Saving stores it on the batch; a batch with instructions shows a one-line preview under its name. [empty: saving an empty field clears the preview] [error: over 2,000 characters → the counter turns destructive and Save is disabled]
2. **Assign** (T-143's sheet) — picking several people sends `set_assignees`; the batch's images are dealt round-robin, so each person gets the next image until the batch runs out. The board then shows one card per assignee, with the dwell counts split accordingly.
3. **Unassigned remainder** — images left with no assignee stay in the To label lane as their own card; nothing is silently dropped.
4. **Mid-job reassignment** — moving a card from Annotating with a new assignee list re-deals only that card's images (`assignee_id` filter), leaving the rest of the batch alone.
5. **Event for the notification sink** — the assignment writes one audit row `board.assign` carrying `{batch, assignees[], images}`; delivery to the people is area 7's sink (7-F7.49). This card does not build a notification inbox.
6. **Labeler view** — a card assigned to the viewer is labelled "Assigned to you" in its subtitle; the board can be filtered to that with the existing filter box.

## Backend changes
- Models/schema: `Batch.instructions` — `TEXT DEFAULT ''`, not null (`models/project.py`), plus a new `BATCHES = {"instructions": "TEXT DEFAULT ''"}` block in `app/schema/dataset.py` and its `STEPS` entry in `app/schema/__init__.py` (appended last, idempotent).
- Routers: `PATCH /api/ws/{ws}/projects/{project}/batches/{batch_id}` (new, in `images.py`) body `{instructions: str}` → trimmed, ≤ 2,000 chars, returns the batch; `GET /board` rows gain `instructions` (first 120 chars) and `assignees`; `BoardMove` (`images.py:380`) gains `set_assignees: list[str] = []` (≤ 20, every id a workspace member) and deals the matched images round-robin; `set_assignee` stays as the single-person alias.
- Services/jobs: `services/assignments.py` (new) — `deal(images, assignee_ids)` returning the per-image assignment and the counts, so the rule is testable without a request.
- Permissions + workspace isolation: `PATCH` requires `c.need("reviewer")`; every assignee id is checked against `Member` for **this** workspace (a foreign user id is 400); batch ids are filtered by `c.project.id`, so a foreign batch is 404.
- Secrets/safefetch: none.
- OpenAPI: yes — one route, two fields.

## Acceptance criteria
- [ ] A batch's instructions save, show as a preview on its card and survive a reload.
- [ ] Assigning two people splits the images round-robin into two cards with no image assigned twice; the remainder stays unassigned.
- [ ] Assignment writes one audit event naming the people and the image count, and never assigns a non-member.
- [ ] Reassignment from Annotating changes only that card's images.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: fields on the existing board.
- [ ] Keyboard-only path: board row menu → Instructions → type → Save → Assign.

## Notes for the implementer
The round-robin order is the images' `created` order, so two identical assigns produce the same split — a random deal makes a reassignment shuffle work that was already half done. Delivery of the assignment notice is 7-F7.49's job; publish the event and stop there.
