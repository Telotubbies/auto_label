## User story
As an ML engineer preparing an edge deployment, I want prune and INT8 as one job that reports accuracy, latency and size at each step, so that I can show "we lost 0.4 mAP and gained 3× speed" without re-measuring anything by hand.

## UX flow (LabelDesk words)
1. **`ปรับแต่งโมเดล`** (`POST /models/{mid}/optimise`, rendered by T-687) — the caller names a prune ratio (0–0.8), a calibration source (the model's version or a folder of images) and the steps to run (`prune`, `int8`). [empty: with no step selected the route is 400 and no job is queued]
2. **The job** — `[loading: กำลังตัด · กำลังคาลิเบรต · กำลังสร้าง]` with three stage progress values; a cancellation keeps the last completed artifact. [error: `คาลิเบรตด้วยภาพ 12 ภาพ — แนะนำ 200 ภาพ` is a warning, not a refusal, and the tests still run]
3. **The report** — a row per stage: `baseline`, `pruned`, `int8`, each with mAP50-95, median latency, p95 latency and size, plus which numbers were measured on this worker and which are unavailable with the reason. [error: `การทำ QAT ต้องมีลูปเทรนที่ตัว exporter ยังไม่รองรับ` when `qat` is requested — the request is refused, no row is invented]
4. **The artifacts** — `weights.optimised/pruned.pt` and the INT8 export beside the original weights; the original file is never overwritten, so a failed optimisation cannot break a serving model.

## Backend changes
- Models/schema: `TrainedModel` gains `optimisations JSON` (null) as one `ADD COLUMN` block in `app/schema/training.py` `TRAINED_MODELS`.
- Routers: `app/routers/optimise.py` (new), prefix `/api/ws/{ws}/projects/{project}`, `dependencies=[Depends(require_flag("task_optimise_report"))]`; `POST /models/{mid}/optimise` `{prune_ratio?, steps, calibration: "version"|"folder", folder?}` → 202 with the `Job`; `GET /models/{mid}/optimise` → `{stages: [{name, map5095, map50, latency_ms, p95_ms, size_mb, measured, note}], baseline, warning}`. 400 for an unknown step or `qat`, 400 for a ratio outside 0–0.8, 409 when a run is already queued for this model, 409 when the model is not ready.
- Services/jobs: `app/services/optimise.py` (new) — `plan(prune_ratio, steps)` (validated list), `prune(weights, ratio, out)` (`torch.nn.utils.prune.global_unstructured` L1 over `Conv2d`/`Linear` weights, then `prune.remove`, saved to a new checkpoint), `calibration_count(source)` and `small_set_warning(n)` (warns under 200, refuses under 1), `int8_export(weights, data, out)` through `edge.export_plan("tflite-int8")` and the existing adapter `export`, `measure(adapter, weights, image)` (five runs, median and p95). `app/handlers/optimise.py` (new) with `run_optimise(job)` in `handlers/__init__.py` `MODULES` and `optimise` in `config.LOCAL_JOB_KINDS`; the handler evaluates each stage through `services.evaluate` and stores the report on the model.
- Permissions + workspace isolation: `c.need("admin")` on both routes; the model is resolved through `workspace_id` + `project_id` and a foreign id is 404; the calibration folder must resolve inside `DATA_DIR` (the `retention._inside` check), so a caller cannot point the job at an arbitrary path.
- Secrets/safefetch: none — no URL is fetched; the folder path is confined to `DATA_DIR`.
- OpenAPI: yes — two routes and their schemas.

## Tests to write first

## Acceptance criteria
- [ ] One job runs prune then INT8, keeps the original weights intact and writes every artifact under a new directory.
- [ ] The report carries accuracy, median and p95 latency and size per stage, with the delta from the baseline.
- [ ] A calibration set under 200 images warns and still runs; an empty set and an unsupported step are refused with a sentence.
- [ ] Empty, loading and error states above all render — a number the worker could not measure reads `ไม่ได้วัด` with its reason, never `0`.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ both routes 404, no job kind, and the model page is today's.

## Notes for the implementer
Ship prune and INT8; **do not ship QAT** — quantisation-aware training needs a training loop the pinned exporter does not expose, so the route refuses `qat` with that reason instead of printing a number nobody measured. A stage that cannot be measured is reported as `measured: false` with its note; a zero would read as a catastrophic accuracy loss and is a lie. Copy: `optimise.title`=`ปรับแต่งโมเดล`, `optimise.pruning`=`กำลังตัด`, `optimise.calibrating`=`กำลังคาลิเบรต`, `optimise.building`=`กำลังสร้าง`, `optimise.smallSet`=`คาลิเบรตด้วยภาพ {n} ภาพ — แนะนำ 200 ภาพ`, `optimise.qatUnsupported`=`การทำ QAT ต้องมีลูปเทรนที่ตัว exporter ยังไม่รองรับ`, `optimise.notMeasured`=`ไม่ได้วัด`, `optimise.empty`=`ยังไม่มีขั้นตอนที่เลือก`.
