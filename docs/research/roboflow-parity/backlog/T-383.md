## User story
As an admin, I want to build a role by copying an existing one and ticking grouped permissions, so that a
contractor can label and view but not export, without reading 24 rows from scratch.

## UX flow (LabelDesk words)
1. **Settings → Roles → New role** — dialog `Create a custom role`: `Role name`; `Start from` (any built-in or
   custom role of the same level, plus `Blank`) with `Copy permissions`, which ticks that role's boxes.
2. **Grouped grid** — sections **Workspace & admin**, **Data**, **Labeling**, **Models**, **Workflows &
   deployment**; each permission is a checkbox row with the label and its key; `Select all` / `Clear all` per
   section; hovering a checkbox shows a one-line tooltip of what it grants.
3. **Dialog rules** — it closes only on `Create`/`Save` or `Cancel`: an outside click and `Esc` keep the draft
   and show `Your changes are still here — create the role or cancel.`
4. **Delete a role in use** — `⋯ → Delete role`; when members still hold it the dialog lists them
   (`3 members: Nok, Pim, Som`) and asks `Move them to` a same-level role before `Delete role` enables. The
   server refuses with `409` if the list changed meanwhile; the dialog re-reads and stays open.
5. `[empty]` no custom roles: `No custom roles yet.` + `Build a role for a precise job…` and the button.
6. `[loading]` `Saving…`/`Deleting…`; `[error]` a red line above the buttons quoting the server, draft intact.

## Backend changes
- Models/schema: none — `CustomRole` and `Member.custom_role_id` / `ProjectMember.custom_role_id` exist.
- Routers: `routers/rbac.py`: `DELETE /api/ws/{ws}/roles/{rid}` today clears assignments silently; it gains
  `?reassign_to=<role_id>` which moves every holder (members and project members) to that bundle before the
  delete, and answers `409 {"holders": [{"id", "name"}], "count": n}` when holders exist and no `reassign_to`
  was given. `GET /api/ws/{ws}/roles/{rid}/holders` → the same list for the dialog. Both 404 for a foreign id.
- Services/jobs: `role_holders(db, ws, rid)` in `routers/rbac.py`; `_validated` unchanged so an unknown
  permission is still a 400.
- Permissions + workspace isolation: `_role_admin` (owner/admin) already gates writes; holders are resolved
  inside `c.ws.id` only.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] A role can be started from any same-level role or from blank, and every permission is grouped with a tooltip.
- [ ] The dialog never discards an edit on an outside click or `Esc`.
- [ ] Deleting a role that still has holders requires an explicit reassignment and the list of affected people.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ today's modal and today's delete behaviour, unchanged.

## Notes for the implementer
Group by the permission's second token (`workspace.billing` → Workspace & admin; `project.export` → Data).
Tooltip text comes from the one `PERMISSION_LABELS` map plus a one-line description map in the same file — do
not add a third dictionary.
