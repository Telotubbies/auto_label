## User story
As an ML engineer, I want the confidence I tuned in the evaluation to be the number every caller gets by default, so that nobody rediscovers the right threshold in their own code.

## UX flow (LabelDesk words)
1. **Model → Evaluation → the confidence slider** — a new primary beside the slider: *Use 0.45 as this model's default*. Under it, the state line: "Currently serving 0.31 (best F1)."
2. **Per-class values** — a disclosure *Per class* lists each class with its own best threshold and a checkbox *Use per-class values*; the global value stays the fallback and the panel says so: "Classes without their own value use 0.45."
3. **Saving** — the primary enters a busy state, then the line becomes "Serving 0.45 · saved 12 Nov by you", and the page's badge changes from *Best F1* to *Custom*. [error: "The default was not saved" + the reason, the button re-enabled with the old value intact]
4. **Revert** — a secondary *Reset to best F1* restores `f1_best.conf` in one call.
5. **A caller overrides** — the Deploy page's testing pane and the API note both state the precedence: "Requests may send `confidence`; it overrides the global default, and per-class values still apply."
6. **Unevaluated model** — the panel explains instead of pretending: "This model has no evaluation, so it has no tuned default — callers get 0.4." with the *Run evaluation* entry (T-283).

- **States** — [empty: a model without an evaluation shows the 0.4 sentence instead of controls]. [loading: the save primary reads "Saving…" and the state line keeps the old value].

## Backend changes
- Models/schema: `trained_models.threshold FLOAT` (nullable), `trained_models.class_thresholds JSON` (default `{}`). Append both to `TRAINED_MODELS` in `apps/backend/app/schema/training.py`.
- Routers: `PUT {P}/models/{mid}/threshold` body `{threshold: float | null, class_thresholds: dict[str, float] = {}}` → `model_out` with `threshold`, `class_thresholds`, `threshold_source: "custom" | "best_f1" | "none"`; **400** when a value is outside `0.01..0.99` or a class name is not in `model.classes` ("unknown class 'x'"); **409** when the model is not `ready`; **404** for a foreign model. `null` resets to the evaluator's best F1.
- Services/jobs: `adapters/catalog.model_conf(m)` prefers `m.threshold` when set (0 < t < 1) and falls back to `eval.f1_best.conf` — the inference path already reads `Resolved.conf` (`base.Resolved.predict` sets `kw["conf"]` only when the caller did not pass one). Per-class: `Resolved.__post_init__`/`predict` filters the returned predictions with `class_thresholds.get(p["class"], conf)` — one post-filter in `base.py`, applied after any adapter, so every caller (test predict, hosted API, auto-label, batch inference) inherits it.
- Permissions + workspace isolation: `c.need("admin")` (it changes what production returns); a foreign model → 404.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate both files.

## Tests to write first

- `test_saved_threshold_is_the_one_inference_reads` — save 0.45, then `resolve("trained:<id>")` → `resolved.conf == 0.45` **and** a stubbed adapter receives `conf=0.45` from `predict()` with no explicit argument (the end-to-end proof the row demands).

- `test_unready_model_is_a_409_and_foreign_is_a_404`.
- `test_flag_off_reads_only_the_evaluated_value` — `task_277` off → the route 404s and a stored 0.45 is ignored by `model_conf`.

## Acceptance criteria
- [ ] The value saved in the panel is the value the inference path applies with no argument passed (test asserts both ends).
- [ ] Per-class values apply where present and the global value is the fallback; an explicit request `confidence` still wins for the global.
- [ ] Reset restores the evaluator's best-F1 value.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no controls, no route, today's `f1_best`-only behaviour.

## Notes for the implementer
The post-filter lives in `base.Resolved.predict` once — never in each adapter. Store the map as class **name** → float (a rename after evaluation must not silently drop the value; `classes_for` already handles renamed classes in charts).
