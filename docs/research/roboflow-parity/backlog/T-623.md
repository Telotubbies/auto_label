## User story
As a video annotator, I want one identity per object across frames, with a stated exit and a way to fix a wrong join, so that occlusion and re-entry stop producing duplicate identities that poison every tracking metric downstream.

## UX flow (LabelDesk words)
The list is T-624; this card owns the identity rules.
1. **`GET /videos/{vid}/tracks`** — one row per `trackId` in the video: class, frame range, keyframe count, derived count, `outside_from`. [empty: a video with no tracked frames returns `tracks: []`]
2. **`POST /videos/{vid}/tracks/{track_id}/outside {frame_index}`** — marks the track absent from that frame on; interpolation after it writes nothing for the track instead of inventing a box. [error: "That frame is before the track's first keyframe." (422)]
3. **`POST /videos/{vid}/tracks/{track_id}/split {frame_index}`** — renames the id from that frame onward (`<track>-2`, `<track>-3`) so two objects stop sharing one identity. [error: "A span over 240 frames cannot be interpolated." (409) when the split would exceed `MAX_INTERPOLATION_SPAN`]
4. **`POST /videos/{vid}/tracks/{track_id}/merge {into_track_id}`** — every row of the merged track takes the kept id; the merged track disappears from the list. [error: "Those tracks share no frame, so merging them would hide a gap." (409)]
5. **Interpolate** — unchanged, except an out-of-frame track is skipped and the response reports `skipped_tracks`.

## Backend changes
- Models/schema: none — identity lives in the existing annotation JSON (`trackId`, `keyframe`, new `outside: true` on the last in-frame keyframe). No `ADD COLUMN`, no new table.
- Routers: `routers/videos.py` — `GET "/videos/{vid}/tracks"`, `POST "/videos/{vid}/tracks/{track_id}/outside"` `{frame_index}`, `POST "/videos/{vid}/tracks/{track_id}/split"` `{frame_index}`, `POST "/videos/{vid}/tracks/{track_id}/merge"` `{into_track_id}`; all four gated by `require_flag("task_22")`. 404 for a video or track outside this project, 422 for a frame outside the video's sampled indexes, 409 for the span and no-shared-frame cases.
- Services/jobs: `app/services/track.py` — `tracks_for_video(db, video)` (scan `Image.frame_index`/`Image.annotations`, group by `trackId`, count keyframes and derived rows), `set_outside(db, video, track_id, frame_index)`, `split_track(db, video, track_id, frame_index)`, `merge_tracks(db, video, track_id, into_track_id)`; `app/services/video.py::interpolate_tracks` skips a track whose last keyframe carries `outside`. No new job kind.
- Permissions + workspace isolation: `c.need("annotator")` for outside and split, `c.need("reviewer")` for merge; `_get_video(c, vid)` already 404s a video from another project or workspace, and every frame is re-checked against `c.project.id`.

## Acceptance criteria
- [ ] The track list returns one row per object with its frame range, keyframe count and derived count.
- [ ] Marking outside stops interpolation after that frame without deleting the track or its earlier labels.
- [ ] Split renames from the chosen frame onward and merge folds every row onto the kept id, both counted and audited.
- [ ] Empty, loading and error states above all render where the surface exists: `tracks: []`, 409 for span and no-shared-frame, 422 for a bad frame, 404 for a foreign video.
- [ ] Workspace A cannot read or change workspace B's tracks (404, not 403).
- [ ] Flag off ⇒ no track routes and the timeline is byte-for-byte today's behaviour.

## Notes for the implementer
Keep the identity in the annotation JSON: a `tracks` table would need a migration for every existing video and would drift from the boxes it describes. `outside` belongs on the last in-frame keyframe only — a flag on every row makes "where does it leave" ambiguous.
