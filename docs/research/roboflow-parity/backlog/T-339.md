## User story
As an operator, I want to mark a production event right, wrong or unclear with an optional comment, so that the team learns from what the model got wrong instead of only from what it caught.

## UX flow (LabelDesk words)
1. **Event detail sheet** — a "Was this right?" row: three buttons, `Correct`, `Wrong`, `Unclear`, plus an optional comment box (240 chars) and "Save verdict". Saving is immediate and attributed to the signed-in user; the buttons show the saved state on reopen.
2. **List marker** — a green tick for correct, a red cross for wrong, a yellow dot for unclear, and nothing when no verdict exists. The `Reviewed` switch (today's boolean) stays as a separate, coarser signal; the verdict is what the QA report counts.
3. **History** — the sheet shows every verdict on this event as `who · verdict · when · comment`, newest first, because a disagreement is information. `[empty: no verdicts → the row says "No verdict yet."]`
4. **Remove** — a project manager can delete one history entry; the event's current marker becomes the next newest entry, or nothing. `[error: a non-manager pressing delete → 403 shown inline, the entry stays]`
5. **API-pushed verdicts** — an event pushed with `verdict` and no signed-in user is stored with `user_id: null` and renders as "Unknown" (`[error: an API verdict for an event of another project is 404]`).

## Backend changes
- Models/schema: `stream_events` gains `verdict VARCHAR(12) DEFAULT ''`, `verdict_by VARCHAR(32) DEFAULT ''`, `verdict_at FLOAT`, and the history lives in the existing `audit` table (`action="stream.verdict"`), so no second table. `ADD COLUMN` lines appended to `STREAM_EVENTS` in `app/schema/streams.py`.
- Routers: `apps/backend/app/routers/streams.py` — `POST /{sid}/events/{eid}/verdict` with `{verdict: "correct"|"wrong"|"unclear", comment}` (200 / 400 unknown verdict / 403 not a reviewer / 404 foreign event); `DELETE /{sid}/events/{eid}/verdict/{audit_id}` (manager only); `event_out` gains `verdict`, `verdict_by`, `verdict_at`.
- Services/jobs: `apps/backend/app/services/event_feedback.py` (new) — `VERDICTS = ("correct", "wrong", "unclear")`, `set_verdict(db, c, event, verdict, comment) -> dict` writing the column and one audit row atomically, `history(db, event) -> list[dict]` reading audit rows for that event, `clear(db, c, event, audit_id)` restoring the previous verdict.
- Permissions + workspace isolation: setting needs `project.review`; deleting needs the `manager` project role; the event is resolved through its stream, so a foreign id is 404.
- Secrets/safefetch: none — the comment is capped at 240 characters and stripped of control characters.
- OpenAPI: yes — two routes and three fields.

## Acceptance criteria
- [ ] A verdict saves in one click, is attributed, and the list marker reflects it.
- [ ] History lists every verdict with author and time; deleting one restores the previous verdict and is manager-only.
- [ ] An unknown verdict is refused, a foreign event is 404, and an API verdict renders as Unknown.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ today's `Reviewed` switch and no verdict surface.

## Notes for the implementer
Keep `reviewed` and `verdict` separate: reviewers already rely on the boolean, and a migration that merges them would rewrite history. The activity stream is the audit table — do not add a fourth place where verdicts live.
