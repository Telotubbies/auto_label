## User story
As the admin preparing a renewal conversation, I want weekly active labelers, images per labeler and the three people who never signed in, so that the renewal is argued with numbers from this workspace.

## UX flow (LabelDesk words)
1. **Settings → `Adoption`** (`/:ws/settings/adoption`, owner and admin only) — four tiles: weekly active labelers, images labelled per active labeler, median time from first label to approval, and invited members who never signed in. [empty: "Not enough activity yet — this view fills after seven days."] [loading: four skeleton tiles and a skeleton table] [error: "Couldn't load adoption numbers." + `Try again`]
2. **`Who has not started`** — a table: name, address, invited by, invited on, days waiting, and `Resend invite` per row; a resend reads "Sent again to <address>." [empty: "Everyone invited has signed in."]
3. **`Unused features`** — a short list of enabled surfaces this workspace has never used ("Streams: enabled, no camera configured"), each linking to the screen. [empty: "Every enabled feature has been used at least once."]
4. **A member who is not an admin** — the tab is absent from Settings entirely.
5. **Flag off** — the tab, the route and the API are all absent.

## Backend changes
- Models/schema: none — reads `Member`, `LoginEvent`, `Audit`, `Image`, `LabelEvent` and `Invite`.
- Routers: `app/routers/onboarding.py` — `GET /api/ws/{ws}/adoption` (tiles, never-signed-in rows, unused features; each figure carries `value` and `reason` when it is `null`), `POST /api/ws/{ws}/adoption/resend/{uid}` (200 with `{sent: true}`; 409 when the member has already signed in).
- Services/jobs: `app/services/adoption.py` (new) — `WEEK = 7 * 86400`, `weekly_active(db, ws, now) -> int` (distinct labelers with a label or review `Audit` row in the window), `images_per_labeler(db, ws, now) -> float | None`, `median_review_seconds(db, ws, now) -> float | None` (median of `Audit` approve time minus the image's first label time; `None` with `reason="not_enough_events"` under 20 samples), `never_signed_in(db, ws, now) -> list[dict]` (members older than 24 h with no `LoginEvent`), `unused_features(db, ws) -> list[dict]`.
- Permissions + workspace isolation: `workspace.members` for both routes (owner and admin); every query filters `Member.workspace_id == c.ws.id`; resend mails the address stored on the invite, never an address supplied by the client.
- Secrets/safefetch: none — `mailer.send` is the shipped transport; no password or token is returned by the payload, only "sent".
- OpenAPI: yes.

- `test_a_fresh_workspace_says_not_enough_activity` — one member, no audit rows → every tile is `null` with a `reason`, and `never_signed_in` lists the invited member.

## Acceptance criteria
- [ ] Four tiles render from real rows, each showing a reason instead of a number when the data is thin.
- [ ] Members who never signed in are listed, and `Resend invite` mails the stored address once.
- [ ] Owner and admin only; a labeler never sees the tab and the API answers 403.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no tab, no route, both endpoints 404, and the existing usage page is unchanged.

## Notes for the implementer
This is per-person activity, so the numbers must stay inside the workspace and the DPA's audit clause: no cross-workspace comparison, no export, and no "rank your labelers" list — reviewers who need per-labeler quality use the existing labeler stats, not this page. Keep `—` plus the reason as the only representation of an unknown figure; a zero here reads as "nobody works" and starts a renewal conversation on a false premise.
