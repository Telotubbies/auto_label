## User story
As a workspace admin, I want to store bucket keys once, name them and reuse them in every datasource so
that rotating a key is one edit instead of N connector edits.

## UX flow (LabelDesk words)
1. **Settings · Connectors · Credentials** — **Add credential** opens a form: name, kind (S3 / Google
   Cloud Storage / Azure Blob), and only the fields that kind needs (access key + secret, service-account
   JSON, or account name + key / SAS). [empty: "No credentials yet — add one, or let a datasource create
   one inline."]
2. **Settings · Connectors · Credentials** — saving returns a row with `Created`, `Last used` and a masked
   key (`AKIA…7Q2`); the secret value is never sent back. [loading: the save button keeps its width with a
   spinner] [error: a missing required field → inline error under that field, nothing saved]
3. **Settings · Connectors · Credentials** — row menu: **Rotate secret** (paste a new value; the row keeps
   its id so datasources keep working) and **Delete** (confirm names the datasources that reference it).
4. **Settings · Datasources · Connection** — the Credential dropdown lists these rows with a `+` that
   opens the same form in a sheet without losing the datasource form.

## Backend changes
- Models/schema: `apps/backend/app/models/storage.py` (new) with
  `Credential(id, workspace_id FK, name String(120), kind String(16), config JSON, created_by, created,
  updated, last_used)`, unique `(workspace_id, name)`; registered in `models/__init__.py`
  (import, re-export, `DOMAIN_MODULES`). No Alembic: `Base.metadata.create_all` creates the table.
- Routers: `apps/backend/app/routers/credentials.py` (new), prefix `/api/ws/{ws}`:
  - `GET /credentials` → rows with masked config (`services.credentials.public_config`).
  - `POST /credentials` `{name, kind, config}` → `201`; `400` on an unknown kind or a missing required
    field; `409` on a duplicate name.
  - `PATCH /credentials/{cid}` `{name?, config?}` → rotates/renames; `DELETE /credentials/{cid}` → `409`
    with `{usedBy: [{id, name}]}` when a datasource references it, `?force=false` default.
- Services/jobs:
  - `apps/backend/app/services/credentials.py` (new) — `REQUIRED_FIELDS` per kind,
    `validate(kind, config)`, `encrypt(config)` (via `secretbox.encrypt_config` over
    `connectors.SECRET_FIELDS`), `public_config(cred)` (mask every secret, expose `last4`),
    `touch(db, cred)` on use, `migrate_inline(db)` moving each connector's inline secrets into one
    credential named after the connector and rewriting `Connector.config["credential_id"]`.
  - `apps/backend/app/bootstrap.py` — one `credentials.migrate_inline` call after the secret migration.
  - `apps/backend/app/services/connectors.py` — `_config(conn)` prefers `credential_id` (decrypting
    through `credentials`) and falls back to inline fields for rows the backfill has not reached.
- Permissions + workspace isolation: `c.perm("workspace.connectors")` (owner/admin) for every route; a
  credential id from another workspace is 404 via `workspace_id == c.ws.id`.
- Secrets/safefetch: `services/secretbox.py` only; `migrate()` extended to re-encrypt `Credential.config`
  so `LD_SECRET_OLD` rotation covers the new table.
- OpenAPI: yes — four routes and one schema.

## Acceptance criteria
- [ ] A credential is created, listed masked, rotated and deleted without the secret ever crossing the API
      boundary twice.
- [ ] Deleting a credential in use is refused with the referencing datasources named.
- [ ] Inline connector secrets are migrated once, idempotently, and existing syncs keep working.
- [ ] `LD_SECRET_OLD` rotation re-encrypts the new table.
- [ ] Empty/loading/error states above render (no-credentials copy, inline field error, spinner width).
- [ ] Flag off ⇒ routes 404, connectors read inline config exactly as today.
- [ ] Workspace A cannot see or change workspace B's data (404 for a foreign credential id).

## Notes for the implementer
`Credential.config` stores exactly the same field names `connectors.SECRET_FIELDS` already encrypts, so
`_config` can swap one dict for the other without touching the S3/GCS/Azure clients. `last4` is computed
from the decrypted value at read time and only for display; never persist it.
