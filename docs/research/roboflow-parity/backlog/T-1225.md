## User story
As the merge captain, I want the Q3 findings across streams, settings, MCP, the inference hub and admin
triaged together, so that the least human-facing surfaces get the same evidence standard as the editor.

## UX flow (LabelDesk words)
1. **Collect** — the area-7 report and J9–J13; the MCP journey's tool errors count as UX evidence only
      where the message is shown to a person in the host.
2. **Dedupe and severity** — a missing scope, a silent key reveal or a cross-workspace read is S1 and goes
      to R7 before it is filed.
3. **Fix cards** — one stub per S1/S2; a security stub names the R7 reviewer and the failing test.
4. **Regression check** — rerun J1–J8 and areas 1–6; record the regression rate for the wave.
5. **Release note** — `docs/qa/releases/q3.md` with the full metric table and the security items.

## Acceptance criteria
- [ ] Every Q3 finding is filed or rejected with evidence; ids continue the sequence.
- [ ] Every security-shaped finding is S1 and carries the R7 escalation, not a product-only fix.
- [ ] The MCP findings quote the tool error a user would actually see; a raw 500 is a finding.
- [ ] Every S1/S2 has a dispatchable stub with exclusive files and a named failing test.
- [ ] The metric table covers J9–J13 and the P4 SUS-8 score; the P5 agent walkthrough is a pass/fail path.
- [ ] A rerun of J1–J8 is recorded; the regression count is in the note.
- [ ] Empty, loading and error states: the flag-off stream and hub, a revoked key, a refused console.
- [ ] Owner questions (Thai, real GPU, licence, engine download) are separated.
- [ ] Workspace isolation: a leak is S1 and blocks the wave release until fixed.

## Notes for the implementer
Do not treat "the agent could do it" as a pass for the human surfaces. The MCP journey proves the path; it
does not excuse a settings screen that a person cannot read.
