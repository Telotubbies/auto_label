## User story
As a project owner, I want one dialog that names what becomes public and asks me to confirm it, so that a licence choice and a warning live at the moment of publishing rather than in a help page.

## UX flow (LabelDesk words)
1. **Project card ⋮ → `Make public`** (workspace home) and **Project settings → General → `Make public`** — both open the same dialog. A private project shows `Make public`; a public project shows `Make private` in the same place.
2. **Dialog** — title `Publish “PPE Detection”`; line `Anyone with the link can see 128 images, 4 classes and the description.`; licence radio list (`CC BY 4.0` default, `CC BY-SA 4.0`, `CC0 1.0`, `MIT`, `Public Domain`); amber inline warning `Do not publish private data — faces, plates, screens, documents. A published page cannot be un-seen once it is copied.`; checkbox `I checked the images for personal data`; primary `Publish` disabled until the box is ticked. [empty: no description yet → extra line `Add a description so visitors know what this is.` with a link to the Description block]
3. **Success** — dialog closes, the card's lock icon becomes a globe, a toast `Published. /d/:ws/:project is live.` with `Copy link`. [error: 422 licence/ack → the sentence inline above the primary; 403 policy → `This workspace does not allow public projects.` and the primary disappears; network → `Could not publish — nothing changed.`]
4. **Make private** — confirm sheet: `Hide “PPE Detection” from the public page? The dataset stays; the link stops working.` Primary `Make private`, ghost `Cancel`.
5. **Settings → General** — the visibility select keeps working as today and now calls the same endpoints, so the two entries cannot disagree; its labels read `Private` / `Public` with the same warning line.

## Acceptance criteria
- [ ] Both entry points open the same dialog and produce the same result; a public project offers `Make private` in both.
- [ ] Publishing requires the acknowledgement checkbox and a licence; the resulting link is shown and copyable.
- [ ] Empty, loading and error states above all render (no description, 403, 422, network).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — the dialog sends only the current workspace's slug.
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
- [ ] The dialog copy is new LabelDesk text and names concrete risks (faces, plates, screens, documents).
