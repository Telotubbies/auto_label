## User story
As a reviewer, I want to keep the majority for most images but pick a named labeler's draft for the ones I know better, and to send a job to a share of a batch rather than a hand-picked list, so that consensus stops being all-or-nothing.

## UX flow (LabelDesk words)
1. **QA → Consensus → New job** — `Coverage`: `Every unlabeled image` or `A share of the batch` with a 1–100 % field and the live hint "≈ 10 of 40 unlabeled images". [empty: fewer people than K → "This project has 2 people who can label; K needs at least 3." with Create disabled] [loading: Create shows a spinner] [error: "This batch has no unlabeled images left."]
2. **Job row → Details** — the submitted drafts per image, each with author and label count, and a `Use this draft` action. The chosen row carries `Winner`. [loading: the row spinner while the choice is stored] [error: "That draft was not submitted by a member of this job."]
3. **Merge consensus** — the confirm reads "12 images merge · 2 use a reviewer's choice · images without a strict majority stay untouched", and the toast reads "Merged 12 · 2 overridden · 1 skipped".
4. **A job with no majority** — the merge returns 409 "No image reached a strict majority — review the drafts in the job detail." and every draft stays readable.
5. **Review queue** — merged and overridden images arrive in `review`, most disputed first, unchanged from today.

## Backend changes
- Models/schema: `ConsensusJob.image_overrides` JSON default `{}` (`image_id → user_id`) in `app/models/insights.py`; ADD COLUMN `image_overrides` in the `CONSENSUS_JOBS` block of `app/schema/dataset.py`. Existing rows read as `{}`; no backfill.
- Routers: `routers/labeling.py` — `POST /consensus/{job_id}/override` `{image_id, user_id}` → 200 `{image_id, user_id}`; 404 for a job or image outside this project/workspace; 409 when the job is already merged; 422 when that user did not submit that image. `POST /consensus` gains `coverage_pct: int = 0` (0 = every image; 1–100 = a share; 422 outside). The merge response gains `overridden`.
- Services/jobs: `services/labeling_ops.py` — `set_override(db, c, job, image_id, user_id)`; `create_job(..., coverage_pct)` takes `max(1, round(unlabeled * pct / 100))` images in `created, id` order; `merge_job` writes the overridden draft instead of the majority and counts `overridden`. No new job kind; the merge stays synchronous.
- Permissions + workspace isolation: `c.need("reviewer")` on the override route; `_job()` already 404s a job from another project or workspace, and the image is checked against `job.image_ids` before the user check, so a foreign id never reveals who is assigned where.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] A reviewer picks one draft for one image and the merge writes that draft instead of the majority, counting it as overridden.
- [ ] A job created with 25 % coverage takes a quarter of the unlabeled images, deterministically.
- [ ] An image with neither a majority nor an override is left untouched and listed in `no_consensus`.
- [ ] Empty, loading and error states above all render: the too-few-members empty line, the row spinner, and the 409/422 messages inline.
- [ ] Workspace A cannot override or merge workspace B's job (404, not 403).
- [ ] Flag off ⇒ no consensus tab, no override route, and the existing merge behaves exactly as today.

## Notes for the implementer
An override beats the majority even when it is the minority, and it must **not** be applied to an image whose drafts were never submitted. `coverage_pct` and an explicit `image_ids` list are mutually exclusive by precedence: an explicit list wins and the percentage is ignored, so a stale form never 422s. Do not add a second merge button — the existing `Merge consensus` gains the counts.
