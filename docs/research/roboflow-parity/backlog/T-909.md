## User story
As a team lead who checks "nightly runs above 0.6 mAP" every morning, I want to save that view under a name and
send the link, so a teammate sees the same rows without retyping the filter.

## UX flow (LabelDesk words)
1. **Models → Views** — a select beside the filter field: `All runs`, then saved views, then *Save current view…*.
   [empty: `No saved views yet. Save the current filter as a view.`] [loading: the select renders disabled for
   the first paint] [error: a stored view with an unparseable filter opens as `All runs` with a line saying
   `A saved view could not be restored.`]
2. **Save current view** — a small dialog: name (max 40 chars, unique per project, validated inline), the current
   filter preview as a chip row, and *Copy link after saving* ticked by default. Confirm → the view is active and
   the URL carries `?q=…` (the link reproduces it exactly).
3. **Open a shared link** — the URL's `?q=` restores the rows; the view name shows only in the sender's browser,
   and the select says `Custom filter` when the URL does not match a saved view.
4. **Delete a view** — the select's row menu offers *Delete*; a confirm removes it from the list only.

## Backend changes
- Models/schema: none — a view is the filter string plus the tab, and the filter is already a URL parameter.
- Routers: none.
- Services/jobs: none.
- Permissions + workspace isolation: nothing crosses the browser; a link carries only a filter string that the
  recipient's own permissions re-evaluate server-side (`GET /models?q=`), so a view can never widen access.
- Secrets/safefetch: none.
- OpenAPI: no.

## Frontend changes
- Route: none; the `models` route reads `?q=` (T-908) and this card adds nothing to the URL.
- Nav entry: none.
- Components: `apps/frontend/src/features/project/models/runViews.ts` (new) — the view record
  `{id, name, q, tab, created}`, `loadViews(ws, slug)`, `saveView`, `deleteView`, `MAX_VIEWS = 10`,
  `validateName(name, existing)` (1–40 chars, unique, no leading/trailing space), and a tolerant JSON read that

  the save dialog and the row menu; mounted with one line in `Models.tsx` beside the filter bar (owner T-263).
- API client: none.
- Feature flag: `task_mlruns` — off, no select renders and stored views are ignored (not deleted).

## Tests to write first
pytest — none: no backend surface.
node — `apps/frontend/tests/run-views.test.mjs`:
- `test_save_list_and_delete_round_trip` — two saves → both listed newest first; delete the first → one left.
- `test_names_are_unique_and_trimmed` — `" nightly "` collides with `"nightly"`, an empty name and a 41-char name
  are refused with their own messages.
- `test_the_cap_is_ten_and_the_oldest_is_not_silently_dropped` — the eleventh save is refused with
  `Delete a saved view first.` rather than overwriting.
- `test_corrupt_storage_returns_an_empty_list` — invalid JSON and a non-array value both yield `[]`.
- `test_a_url_filter_that_matches_no_view_reads_as_custom` — matching is on the normalised filter string, so a
  reordered clause is `Custom filter`, not a false match.

## Acceptance criteria
- [ ] Saving a view then reloading the page keeps the rows, the name and the active state.
- [ ] The link a user copies reproduces the same rows for a member with the same permissions.
- [ ] Corrupt or foreign-version storage never breaks the page; the select falls back to `All runs`.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: none — no existing card saves run-list state. `5-F5.27` → T-284 saves nothing; it adds a metric selector.
Views are per browser on purpose: a workspace-shared table would be a new entity for a preference, and the link
already carries the view. If the PM wants server-shared views later, the stored record is the migration input.
MLflow's view also stores column order and width; our run list has no column chooser, so a view stores the filter
and the tab only — say that in the UI, do not ship a column chooser.
