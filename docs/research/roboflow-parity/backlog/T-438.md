## User story
As a workspace lead, I want a notification to show what it costs in credits, so that a noisy rule does not quietly
drain the month.

## UX flow (LabelDesk words)
1. **Settings → Alerts** (existing tab) — each channel row gains `Cost: 0.01 credit per message` and a
   `Messages sent this cycle` counter with the credit total.
2. **Channel form** — the footer states `Each delivered message costs 0.01 credit; throttled or quiet-hour skips are
   free.` The number is read from the API, never typed into the component.
3. **Delivery history** — a delivered row shows `ok · 0.01 credit`; a `skipped` row shows `skipped · free`.
4. **`[empty]`** a channel with no deliveries: `No deliveries recorded yet — no credits spent.`
5. **`[error]` out of credits — the send is skipped, not half-sent: the delivery row is `skipped` with reason
   `credits`, and the UI shows `Not sent — credits are used up.` next to the row.
6. **`[loading]`** the cost line renders from the channel payload, so it never flashes a wrong number.

## Backend changes
- Models/schema: none — `AlertDelivery` gains nothing; the cost is written to `CreditEvent` (T-408) with
  `kind="alert"` and `meta={channel_id, kind}`.
- Routers: `routers/alerts.py` — channel payload gains `cost_per_message: float` and
  `spent_this_cycle: {messages, credits}`; `deliveries` payload gains `credits: float` per row (0 for skipped).
- Services/jobs: `config.CREDIT_COST` gains three keys in the existing table (`"alert_email": 0.01`,
  `"alert_slack": 0.01`, `"alert_line": 0.01`) — one source, no new mapping; `services/alerts.py` — `send()` calls
  `metering.record_credits` + `deps.charge` **before** the provider call when `_skip_reason` is `None`, and on a
  `402` records the delivery as `skipped` with reason `credits` and returns without raising.
- Permissions + workspace isolation: unchanged (`workspace.members`/admin for the channel routes); the ledger row is
  the workspace's.
- Secrets/safefetch: unchanged.
- OpenAPI: yes.

## Frontend changes
- Route: `/:ws/settings/alerts` (existing tab, rewritten rows).
- Components: `features/settings/alerts/ChannelCost.tsx` (new) — cost line and cycle totals; mounted in

- API client: `alertsApi` type widening (the calls stay inline in `Alerts.tsx`).
- Feature flag: `task_notify_cost`; off ⇒ no cost line, no charge, today's payload.

## Acceptance criteria
- [ ] Every delivered message charges one credit event; throttled and quiet-hour skips charge nothing.
- [ ] A channel shows its per-message cost and its cycle totals from the API.
- [ ] Out of credits means the message is skipped and marked, never half-sent.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no charge, no cost copy, alerts unchanged.

## Notes for the implementer
Charge before the provider call, not after: a provider that times out has still spent the message. The three cost keys
belong in the existing `CREDIT_COST` table so there is one place to read every credit price.
