## User story
As a team whose model keeps boxing the same bottle as a helmet, I want the crops the checker already rejected, marked as systematic and shipped as unlabelled background examples, so that the money spent rejecting them buys a better model instead of a log line.

## UX flow (LabelDesk words)
1. **Review → Rejected examples** (`/:ws/:project/qa?tab=rejected`) — a tab listing what the checker refused: "412 rejected, 380 not yet used". [empty: "no rejected boxes yet — run a checked auto-label batch first"]
2. **The grid** — one tile per rejection with its crop, the class it was asked for and the model's near-miss note; filter by class and by phrase.
3. **Promote** — tick the systematic ones and press "Use as hard negatives": they become unlabelled training images tagged `provenance:negative`. [error: "pick at least one rejection" and "this crop is already a hard negative"]
4. **Training** — the next version includes them in `train` even when "drop images with no annotations" is on, and the version summary reads "390 hard negatives".
5. **After training** — the panel shows a per-class delta when two comparable evaluations exist: "Helmet false positives 42 → 34 (−19 %)".
6. **Export** — "Download negative pack" produces a zip of the crops plus a JSON list of the phrases they were rejected for.
7. **Flag off** — no tab, no tags, no manifest change.

## Backend changes
- Models/schema: new module `app/models/negatives.py` with `HardNegative` (`id`, `workspace_id`, `project_id`, `check_id`, `class_id`, `phrase`, `crop`, `image_id`, `created`) registered in `models/__init__.py`; the promoted Image row is tagged `provenance:negative` and keeps `n_annotations == 0`.
- Routers: `GET /api/ws/{ws}/projects/{project}/hard-negatives` → `{"candidates": [{"id", "crop", "phrase", "class", "used"}], "used": n}`; `POST .../hard-negatives` (`ids` ≤ 200) → `{"promoted": n}`; `DELETE .../hard-negatives/{id}` → 200 (the image moves to trash); `POST .../hard-negatives/pack` → `{"url", "count"}` with a signed path. 400 for an unknown id or a duplicate, 403 for a non-reviewer.
- Services/jobs: `services/hard_negatives.py` (new) — `candidates(db, project, class_id=None)`, `promote(db, ws, project, ids)` copying each crop into the project as a tagged image row, `pack(db, project)` writing `DATA_DIR/exports/negatives/<project>.zip`, `deltas(db, project)` computing per-class false-positive change from the two most recent comparable `metrics.eval.confusion` payloads; `services/versioning.py` keeps `provenance:negative` images when `filter_null` is on.
- Permissions + workspace isolation: `reviewer` to read and promote; crops are only read through `box_checks` rows of this project, and a foreign id is 404.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate (`python tools/export_openapi.py`, `npm run gen:api-types`).

## Acceptance criteria
- [ ] Rejected boxes are listed with their crop, the phrase that failed and a used flag; the systematic ones become unlabelled training images tagged `provenance:negative`.
- [ ] The next version includes those images in `train` even with "drop empty images" on, and says how many it carried.
- [ ] A negative pack downloads as a zip with the crops and their phrases, and a per-class delta appears once two comparable evaluations exist.
- [ ] Empty, loading and error states above all render, including no rejections yet and no comparable model.
- [ ] Workspace A cannot read or promote workspace B's rejections (404 on a foreign id, crops only from this project's rows).
- [ ] Flag off ⇒ no tab, no tag, no version change.

## Notes for the implementer
The crop is the example, so promote the crop as its own background image rather than re-adding a box somewhere — a hard negative must be a picture where the class is absent. Keep the phrase beside every tile: "rejected as Helmet" is what makes a false positive fixable. The delta is a comparison of two evaluations on the same split or it is "not measured" — never a percentage across different data.
