## User story
As a reviewer, I want one sheet that says how many images and which classes I am about to approve, so that the biggest button on the board is never a blind click.

## UX flow (LabelDesk words)
1. **Annotate board → In review lane → batch row** — **Approve all** opens a confirm sheet, not a dropdown: title "Approve 16 images?", a class summary ("helmet 41 · vest 38 · person 12 · +2 more"), the batch name and the assignee. [empty: a batch with zero labelled images cannot be approved — the sheet explains "Nothing to approve — 9 images have no labels"]
2. **Confirm** — **Approve 16** runs the move, closes the sheet, moves the row to Approved and toasts "16 approved". [loading: the confirm button spins and the sheet cannot be dismissed by Escape while the move runs] [error: 409 with "3 images have no labels" → the sheet lists them and offers **Approve the 13 labelled**]
3. **Reject all** — the same sheet with a required reason field: preset chips **Wrong boxes**, **Missing labels**, **Wrong class**, **Blurry or unusable**, plus free text. Confirm reads **Reject 16**. [error: the batch is larger than 50 → the sheet refuses with "Reject in groups of 50 or fewer so every image carries your reason"]
4. **Per-image reject in the editor** — `r` in review mode (T-128) opens the same reason field inline; the comment lands on that image and the reviewer's note is visible in its Comments panel.
5. **Where the reason goes** — each rejected image gets one Comment authored by the reviewer, prefixed "Rejected: ", and one audit row records the batch move with the same text. Nothing is written for an approve.
6. **Selection action bar** — when the review queue view has images selected (2-F2.28's selection), **Approve N** and **Reject N** open the same sheet with the selected count, never a second copy of the logic.

## Backend changes
- Models/schema: none — `Comment` (`models/project.py:160`) already stores per-image notes and `BoardCard` is computed in `images.py:358`.
- Routers: `GET /api/ws/{ws}/projects/{project}/board` rows gain `classes: [{id, name, count}]` (top five by count, plus `more`); `POST /board/move` (`images.py:389`) gains `note: str | None`, and for `review → done` refuses `409 {"detail": "images without labels", "count": n, "imageIds": [...]}` unless `only_annotated: true`, with `note` length ≤ 500 and `review → annotating` capped at 50 images per call.
- Services/jobs: none — the move itself stays the one `board_move` SQL update.
- Permissions + workspace isolation: `c.need("reviewer")` as today; board reads and moves are scoped by `c.project.id`, and a batch id from another project is 404.
- Secrets/safefetch: none.
- OpenAPI: yes — board row shape and move body.

## Acceptance criteria
- [ ] Approve all and Reject all both open a sheet naming the count and the classes involved; no bulk decision happens on a single click.
- [ ] Approving a batch that contains unlabelled images is refused with their count, and the sheet offers the labelled subset.
- [ ] A bulk reject needs a reason, writes it to every rejected image and records one audit row; more than 50 images is refused with the limit.
- [ ] A per-image `r` in the editor uses the same reason field and the note appears in that image's Comments.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: an option on the existing board.
- [ ] Keyboard-only path: board → Tab to Approve all → Enter → sheet → Tab to Confirm → Enter.

## Notes for the implementer
The class summary is server-computed once per board read, not per card in the browser: a batch of 2,000 images must not ship 2,000 annotation blobs to draw five names. The reject reason is capped at 500 characters and stored verbatim.
