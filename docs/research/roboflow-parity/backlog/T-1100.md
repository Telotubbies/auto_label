## User story
As an agent client, I want each LabelDesk tool to say whether it only reads, changes data or deletes data, and to return typed results. My host can then ask a person before a write runs, and I can parse results without guessing.

## Changes
- `apps/mcp/labeldesk_mcp/server.py` and the `tools_*.py` files: every tool declares MCP annotations.
  - Read tools: `readOnlyHint: true`, `idempotentHint: true`, `openWorldHint: false`.
  - Write tools: `readOnlyHint: false` and `idempotentHint` set to its real behaviour.
  - Tools that delete or overwrite (labels replace, deployment delete, etc.): `destructiveHint: true`.
- Tools that return records also declare an `outputSchema` and return `structuredContent`, plus a one-line text summary. A list result is `{total, items}`.
- Destructive tools take `confirm: bool`. When it is false or missing, the tool runs nothing and returns a dry-run result that says what would change, so a host without confirmation UI still gets a safe default.
- Every tool description says when to use the tool and when not to, in one or two sentences.

## Tests (write first)
- `apps/backend/tests/test_mcp_hints.py`:
  - every registered tool has annotations;
  - every tool whose name starts with `list_`/`get_`, plus `whoami`, is read-only;
  - every tool in a fixed destructive set has `destructiveHint`;
  - a destructive tool without `confirm` makes no API call (the mocked transport sees zero requests);
  - list tools return `structuredContent` that validates against their `outputSchema`.

## Edge cases
- When a new tool is added without annotations, the test fails and names the tool.
- `confirm` must be the boolean `true`; a string `"true"` is rejected by the schema.

## Out of scope
OAuth for remote HTTP (T-1101) and rate limits (the API already limits per key).
