## User story
As a project manager, I want one list that mixes foundation models, my trained models and the zoo, and one control for what shape the labels take, so that I do not learn three flows or guess the output.

## UX flow (LabelDesk words)
1. **Annotate board → Auto Label → Model** — the plain select becomes a grouped listbox: **Your models**, **Model zoo**, **Vision-language**. Each row shows name, licence chip and capability chips; a model the worker cannot run is present but disabled with its reason as the second line ("Not installed on this worker", "GPU busy"), never removed. [empty: "No model reports detection, segmentation or open-vocabulary support yet" as today] [error: registry read failed → retry inside the field, Run disabled]
2. **Output shape** — beside the selected model (same row) a segmented pair **Masks · Polygons** appears only when the model can segment and the project is `instance-segmentation`; detection projects see **Boxes** as a static chip. The choice is stored per project (`settings.autolabel_output`) and re-selected on the next visit.
3. **Echo** — the summary sheet (T-132) repeats the chosen shape, so the last screen before spending names it.
4. **Refusals before the click** — a keypoint project lists only trained keypoint models; a vision-language model without SAM 3.1 keeps today's amber warning; a model with a licence the workspace has not accepted shows **Licence required** and its link. A project type that cannot auto-label at all explains it in place ("Auto-label needs a detection, segmentation or keypoint project").
5. **Persisted choice** — changing the model does not reset the output shape unless the new model cannot produce it; then it snaps to the supported one and says so.

## Backend changes
- Models/schema: none — the preference is `Project.settings` JSON (`models/project.py:32`).
- Routers: `AutoLabelIn` (`training.py:384`) gains `output: Literal["auto","box","polygon","mask"] = "auto"`; `_autolabel_target` refuses `mask` when `task_mask` is off (400), refuses a keypoint project with a non-trained or non-keypoint model (400), and persists the chosen output into `project.settings["autolabel_output"]` on a successful job start. No semantic-segmentation project type exists in `PROJECT_TYPES` (`models/common.py:10`), so that gate needs no code — a test pins the absence.
- Services/jobs: `adapters/refine.label_image` honours `output`: `polygon` forces polygons even when the adapter returns masks, `mask` keeps RLE (needs T-133's encoder), `box` collapses segmentation output to boxes.
- Permissions + workspace isolation: `c.need("reviewer")` unchanged; `resolve()` is called with `workspace_id`, so another workspace's trained model is reported as unknown.
- Secrets/safefetch: none.
- OpenAPI: yes — one field.

## Acceptance criteria
- [ ] One list shows trained, zoo and vision-language models, each with licence, capabilities and a visible reason when unavailable.
- [ ] The output shape control appears only where it applies, is remembered per project, and is echoed in the summary sheet.
- [ ] Mask output requires `task_mask`; a keypoint project refuses non-keypoint models before the job starts.
- [ ] An incompatible model is disabled with a reason rather than removed, and a licence-gated model says what is missing.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: the dialog ships; the mask option disappears when `task_mask` is off.
- [ ] Keyboard-only path: Auto Label → Tab into the listbox → arrows + Enter → Tab to the shape pair → arrows.

## Notes for the implementer
Persist only on a successful job start, not on every keystroke — a preview should not change a shared project setting. `output: "auto"` means "the adapter's natural shape", which stays the default for trained models.
