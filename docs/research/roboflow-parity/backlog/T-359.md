## User story
As an operator, I want a config change to be staged, approved and applied inside a maintenance window, so that one mistake does not roll out to a whole site at once.

## UX flow (LabelDesk words)
1. **Device → Config** — the current config as a form (model ref, stream list, sample rate, version pin). Saving answers one of three things and the panel shows which:
   - `Proposal created` — "Waiting for approval by a workspace admin." with Approve / Reject for admins and one line for everyone else.
   - `Approved, deferred` — "Applies during the next window: Saturday 02:00–04:00." with "Apply now" disabled unless the window is open.
   - `Applied` — "Applied 2 minutes ago. The device reports the new config on its next heartbeat."
2. **Proposal list** — one row per staged change: who asked, what changed (a two-column diff of the fields that differ), when it was approved, when it will apply. `[empty: no proposals → "No staged changes."]` `[loading: three skeleton rows]` `[error: a rejected proposal → "Rejected by <name>: <reason>." and the device keeps running the old config]`
3. **Nothing bypasses approval** — there is no `force apply` control, and the API refuses a direct write to a device's live config; the only write path is a proposal.
4. **Reading a config is not proof** — one line under the applied state: "The device reports its config on the next heartbeat. Reading it back does not prove the new one is running."
5. **Config history** — the last ten applied configs with their author and time, and a version pin with a conflict check: "Someone else changed this device. Reload before editing."

## Backend changes
- Models/schema: none beyond T-358's `config`, `config_history`, `commands` and `maintenance_window` columns.
- Routers: `apps/backend/app/routers/edge.py` — `PUT /api/ws/{ws}/edge-devices/{id}/config` (creates a proposal, never writes `config`), `POST …/config/{proposal}/approve`, `POST …/config/{proposal}/reject`, `GET …/config` (`{current, proposals, history, window}`), `GET /api/edge/devices/{id}/commands` (device token; returns queued commands and clears them on read).
- Services/jobs: `apps/backend/app/services/edge_config.py` (new) — `PROPOSAL_STATES = ("staged", "approved", "rejected", "applied", "superseded")`, `propose(db, device, patch, user) -> dict` refusing a stale `updated` (409 with "Reload before editing"), `approve(db, device, proposal, user)` setting `approved` + `deferred` when a window exists, `reject(...)`, `due(db, now) -> list[EdgeDevice]` returning devices whose approved proposal falls inside an open window, `apply(db, device)` writing `config`, appending to `config_history`, queueing one `apply_config` command and bumping the version pin, `window_open(device, now) -> bool`.
- Permissions + workspace isolation: propose needs `project.models`; approve and reject need the `workspace.update` permission (owner/admin), which is what makes the approval a second person; a device from another workspace is 404.
- Secrets/safefetch: a proposal carries no credential — the config schema excludes them; `commands` carry a config hash, never a token.
- OpenAPI: yes — five routes.

## Acceptance criteria
- [ ] A config save creates a proposal, never a live change, and states which of the three states it is in.
- [ ] Only a different workspace admin can approve; a rejection keeps the old config running and names the rejector.
- [ ] An approved change applies inside the maintenance window, writes history and queues exactly one command that the device reads once.
- [ ] Empty, loading and error states above all render, including a stale edit and a rejected proposal.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: with `task_358` off the device list and this panel are absent.

## Notes for the implementer
Approval is the product: the proposer cannot approve their own change, and no parameter bypasses the window. "Deferred" is a state, not a delay in the UI — the server refuses to apply outside the window, so a forged request cannot jump it.
