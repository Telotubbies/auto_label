## User story
As someone about to ship a model, I want the delivery options compared on one screen with one question that changes the answer, so that I pick a runtime instead of reading six product pages.

## UX flow (LabelDesk words)
1. **Deploy & test → "Delivery options"** (`/:ws/:project/deploy`, new tab above the test pane) — one comparison table: where it runs, accelerator, latency shape, what it bills, region, best for. Rows come from T-310 in its fixed order; the disabled ones are dimmed with their reason. [empty: never empty — six rows always render] [loading: six skeleton rows, same geometry] [error: "Delivery options could not load." plus "Try again"; the test pane below keeps working]
2. **The four questions** — one card, four radio groups in order: *One image at a time, or a pile?* → *An answer now, or a file later?* → *LabelDesk's machines, or yours?* → *You manage it, or a vendor?* Each answer hides the rows it rules out and leaves one recommended row with a "Best for this" tag. No answer defaults to nothing highlighted, so the first paint is neutral.
3. **A row's primary** — "Set this up" scrolls to the section that configures that runtime (hosted → the endpoint card, self-hosted → T-312's install block, batch → T-334's job dialog, stream → the Streams list, dedicated/edge → their disabled state). Copy under the table: "Only the first question changes the price shape: continuous video bills per hour, a one-off image bills per image."
4. **Cost line** — each row prints its billing unit in LabelDesk words ("per AI call", "no credits — your hardware", "per machine-hour") and links to T-349's rate table. The link is absent, not dead, when the flag is off.

## Acceptance criteria
- [ ] Six rows render with the columns from T-310, in catalogue order, disabled rows dimmed and readable.
- [ ] Answering the four questions leaves exactly one row tagged "Best for this"; changing an answer re-renders without a page load.
- [ ] "Set this up" reaches the matching section on the same screen and never navigates off it.
- [ ] The billing unit is LabelDesk wording, and the rate-table link appears only when `task_349` is on.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — nothing here writes; the catalogue call is `ws_ctx`-scoped.
- [ ] Flag off ⇒ no tab, no request for the catalogue, and today's deploy screen unchanged.

## Notes for the implementer
The four questions resolve in the fixed order *shape → timing → machines → management*; the first answer that rules a row out wins, so do not build a scoring matrix. `recommend` returns an id, never a row, so a runtime that disappears from the catalogue degrades to no recommendation instead of a crash.
