## User story
As a data scientist who trains outside LabelDesk, I want my notebook to create a run and log its parameters and
metrics into the project I am working on, so my experiment sits beside the production runs instead of in a
screenshot.

## UX flow (LabelDesk words)
1. **Settings → API keys** — an admin mints a key scoped to one project with the `train` scope (the existing key
   flow; the project-scoped variant already exists at `app/apikeys.py:58`).
2. **Notebook** — `POST /api/2.0/mlflow/runs/create` with `experiment_id: "<project-slug>"`, `run_name: "lr-sweep-3"`
   and `tags: {"labeldesk.note.content": "…"}` → 200 `{"run": {"info": {"run_id": "…", "status": "RUNNING"}}}`.
   [error: a key without the `train` scope → 403 `this key cannot start runs`; a key not bound to a project → 400
   `bind this key to a project to log runs`]
3. **Notebook, per epoch** — `POST /api/2.0/mlflow/runs/log-batch` with
   `metrics: [{key, value, step, timestamp}]`, `params`, `tags` in one call → 200, nothing echoed.
4. **Models** — the notebook run appears in the same list as a worker run, badged `External`, with its params and
   its curve; it has no checkpoint and no version, so *Deploy* and *Compare* are not offered.

## Backend changes
- Models/schema: new module `apps/backend/app/models/mlruns.py` — `ExternalRun`: `id` (`String(32)`,
  `new_id`), `workspace_id` (FK workspaces, index), `project_id` (FK projects, index), `name` (`String(255)`),
  `status` (`String(16)`, default `RUNNING`), `params` (JSON, default dict), `metrics` (JSON, default dict — the
  shape is `{key: [[step, value, ms], …]}`), `tags` (JSON, default dict), `note` (`String(2000)`, default `""`),
  `datasets` (JSON, default list — the `log-inputs` entries), `started` (`Float`), `ended` (`Float | None`),
  `deleted` (`Float | None`, used by the restore half in T-915). Registered in `app/models/__init__.py` (import + re-export +
  `DOMAIN_MODULES`). No `ADD COLUMN` block: it is a new table, created by `Base.metadata`.
- Routers: `apps/backend/app/routers/mlrun_api.py` (new), prefix `/api/2.0/mlflow`, mounted last in
  `ROUTERS` so it cannot shadow an existing route:
  - `POST /runs/create` → `{run: {info: {run_id, experiment_id, status, start_time, artifact_uri}}}`;
  - `POST /runs/log-batch` → `{metrics[], params[], tags[]}`, merges into the row, returns `{}`;
  - `POST /runs/log-parameter`, `POST /runs/log-metric` → single-value forms of the same;
  - `POST /runs/set-tag`, `POST /runs/delete-tag`;
  - `POST /runs/update` → `{run_id, status, end_time}` (FINISHED/FAILED/KILLED);
  - `GET /runs/get?run_id=` → `{run: {info, data: {metrics, params, tags}}}`.
- Services/jobs: `apps/backend/app/services/mlrun_wire.py` (new) — payload validation and mapping:
  `create_run(db, key, payload) -> dict`, `log_batch(db, key, payload)`, `update_run`, `get_run`; every metric
  append is capped at 5 000 points per key with the oldest dropped and `tags["labeldesk.truncated"] = "1"`.
- Permissions + workspace isolation: bearer API key only (`app/apikeys.py:79 resolve_key`), `KeyCtx.need("train")`
  for writes and `need("read")` for `runs/get`; a run id from another workspace answers 404 and never 403; the
  project comes from the key (`KeyCtx.project`, `:58`), never from the request body.
- Secrets/safefetch: none.
- OpenAPI: yes — `python tools/export_openapi.py`, then `npm run gen:api-types` (the wire routes are part of our
  document; a client reads the same JSON shapes).

## Tests to write first
pytest — `apps/backend/tests/test_mlrun_wire_runs.py`:
- `test_create_then_log_batch_round_trips` — create with `experiment_id=<slug>` → `run_id`; log-batch with two
  metrics (step 1 and 2), two params, one tag; `GET /runs/get` returns them in wire shape, with the metric series
  ordered by step. (also covers the flag-on path)
- `test_the_key_decides_the_project_not_the_body` — a key bound to project A sending `experiment_id` of project B →
  404; the body can never widen scope.
- `test_a_key_without_the_train_scope_is_403` — `read`-only key on `runs/log-metric` → 403 with
  `this key cannot start runs`, and nothing is written.
- `test_an_unproject_scoped_key_is_400` — a workspace key with no project → 400 `bind this key to a project to log
  runs`.
- `test_update_closes_the_run` — `runs/update` with `status: "FINISHED"` → `ended` set, a second update is a no-op
  that keeps the first end time.
- `test_a_metric_series_is_capped_and_flagged` — 5 001 points on one key → 5 000 kept, the oldest gone and
  `labeldesk.truncated` set.
- `test_the_flag_off_case_is_404` — flag off → every route 404.

node — none: `none: no frontend surface`.

## Acceptance criteria
- [ ] A `curl`-or-notebook session can create a run, log params/metrics/tags in one batch, close it and read it back.
- [ ] The project comes from the API key; no request body can reach another project or workspace (404, not 403).
- [ ] A run logged twice for the same step keeps both points in order, and a runaway series is capped and flagged.
- [ ] Empty, loading and error states above all render.
  (This card has no UI; the run list's own states cover the rows it creates.)
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: none — no existing card accepts external writes; `1-F5.4`/`7-F7.25` → T-038…T-040, T-087… own the key flow
this card only consumes.
A separate table is deliberate: `TrainedModel.version_id` is a non-null FK (`models/training.py:39`), and a notebook
run has no version, no weights and no task. Making that column nullable is impossible here (no Alembic) and would
put weight-less rows into the registry, deploy and compare paths.
Keep the wire JSON snake_case exactly as the client sends it — translating to camelCase is the UI's job, not this
route's.
