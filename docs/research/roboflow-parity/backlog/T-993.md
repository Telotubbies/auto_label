## User story
As an agent, I want to look at a project's data the way a person looks at the Dataset and Models screens —
filtered, paged, with ids — so that I can plan a labelling or training step without guessing.

## UX flow (LabelDesk words)
1. **"What am I allowed to see?"** — `whoami` first (already shipped in T-992), then `list_projects`.
2. **"Open one project."** — `get_project` returns classes **with ids**, `statusCounts`, image and model
   counts. [empty: a fresh project answers `classes: []`, `statusCounts: {}`] [error: an unknown slug is a
   tool error `project not found (HTTP 404)`].
3. **"Find the images I care about."** — `list_images` with `q`, `split`, `status`, `class_id`, `tag`,
   `batch_id`, `annotated`, `sort=review`, `offset`, `limit`. The response is a page plus `total`, so the
   agent pages deliberately instead of asking for everything. [empty: `{total: 0, items: []}`]
   [loading: one page per call; `limit` is capped at 200 by the server, below the route's 1000].
4. **"Look at one image."** — `get_image` returns the annotation set with `classId`, `shape`, `source` and
   `confidence`, so an agent can reason about quality before writing.
5. **"What exists already?"** — `list_versions`, `list_models`, `get_model`, `get_job`, `list_deployments`.
   [empty: `[]` per list] [error: a job or model id from another workspace is 404].

## Backend changes
- Models/schema: none.
- Routers: none — this card only consumes `/api/v1`.
- Services/jobs: `apps/mcp/labeldesk_mcp/tools_read.py` (new):
  `register(server, api)` declares the ten tools and appends each `name -> "read"` to `TOOL_SCOPES`.
  Each tool is one `api.call("<tool>", "<operation>", ...)` plus the argument pass-through; the paging cap
  (`min(max(limit, 1), 200)`) and the `sort` allow-list (`newest, oldest, name, most, least, review`) live
  in this file, because the route accepts more than an agent should ask for.
- Permissions + workspace isolation: the `read` scope on every route; ids resolved inside the key's
  workspace; a foreign id surfaces the route's 404 as a tool error.
- Secrets/safefetch: none; `api.scrub` runs on every result before it is returned.
- OpenAPI: no (no route changes).

## Notes for the implementer
`list_images` is the one tool an agent will call most; keep its description to what it does and what the
defaults mean (`sort=review` means "lowest-confidence AI work first", which is the label-quality loop).
Do not add a tool for semantic search: `task_27` is off by default and its route would answer 404.
