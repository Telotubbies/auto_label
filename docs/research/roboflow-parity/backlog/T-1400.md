## Problem
There is no Rust in this repository and no way to add a kernel without inventing a layout, a build, a
fallback and a gate policy on the fly. Without the fallback first, the first kernel would make Rust a
requirement to run the product, which the owner decision forbids.

## Design

**1. The crate** at `packages/labeldesk-core/` (PyO3 + maturin, `abi3-py311`, `cdylib`), with:

- `Cargo.toml` (`crate-type = ["cdylib"]`, `pyo3 = { features = ["abi3-py311", "extension-module"] }`),
  `Cargo.lock` committed.
- `pyproject.toml` (`build-backend = "maturin"`, `module-name = "labeldesk_core"`,
  `requires-python = ">=3.11"`).
- `deny.toml` — licence allowlist (MIT, Apache-2.0, BSD-2/3, ISC, Unicode-3.0, Zlib; deny GPL/AGPL/LGPL),
  duplicate crates denied, crates.io only.
- `src/lib.rs` — `#![deny(unsafe_code)]`, the `#[pymodule]` registration, and one helper that wraps a
  kernel body in `catch_unwind` and converts a panic into a `PyRuntimeError`.
- `src/boxes.rs` — **the one tiny function**: `box_iou(ax, ay, aw, ah, bx, by, bw, bh) -> f64`, ported
  from `app/services/boxes.py:10-17` (unclamped xywh, `0.0` when the union is empty).
- `README.md` — build and install on Windows (MSVC Build Tools), Linux/WSL (`build-essential`,
  `pkg-config`), `maturin build --release`, `pip install target/wheels/*.whl`, and how to run without
  Rust.

**2. The seam** — two files in the backend, one of which is the existing code moved unchanged:

- `apps/backend/app/kernels_py.py` — reference implementations. T-1400 contains `box_iou` only.
- `apps/backend/app/kernels.py` — the only importer of `labeldesk_core`:
  ```python
  try:
      if os.environ.get("LD_FORCE_PY_KERNELS"):
          raise ImportError("forced")
      from labeldesk_core import box_iou
      NATIVE = True
  except ImportError:
      from .kernels_py import box_iou
      NATIVE = False
  ```
  log one line at import when `NATIVE` is false; `LD_KERNELS_STRICT=1` turns an `ImportError` into a
  raised error (used by the parity test so a broken wheel cannot hide).

**3. The benchmark** `tools/perf/bench_kernels.py` (~70 lines): for each registered kernel, time the
Python and the native implementation over the seeded fixture inputs (T-1319's `perf-seed.json`), N warm
runs, report the median in ms and the speedup, `--json` to `docs/ops/perf/kernel-<sha>.json`, and
`--min-speedup 2` exits 1 below the rule. Runs in the nightly (T-1324), never in the gate.

**4. The CI job** `.github/workflows/ci.yml`, new `rust` job, parallel to `api`:

- `dtolnay/rust-toolchain@stable` (or the pinned toolchain file) + `Swatinem/rust-cache@v2`;
- build the wheel, `pip install` it, then `python -m pytest apps/backend/tests/test_kernels_parity.py -q`
  with `LD_KERNELS_STRICT=1`, and again with `LD_FORCE_PY_KERNELS=1`;
- `cargo clippy -- -D warnings`, `cargo test`, `cargo audit` and `cargo deny check`, both pinned to a
  fixed version and fetched as a checksum-verified binary (no third-party action beyond the toolchain and
  cache actions already listed in the report);
- upload `target/wheels/*.whl` as an artefact; add `rust` to the `gate` job's `needs` and result list.
- The `api` job is **not** made to depend on it: it keeps running the fallback, so the 15-minute gate
  does not grow.

**5. The image** — `apps/backend/Dockerfile` gains a `builder` stage (`rust:1-slim` +
`pip wheel packages/labeldesk-core`) and the runtime stage installs that one wheel. Nothing else from the
builder is copied. Without the wheel the app still runs on the fallback, so a build failure degrades
instead of breaking.

## Tests to write first
Rust (`cargo test`):
- `test_identical_boxes_give_one`, `test_disjoint_boxes_give_zero`, `test_zero_area_gives_zero`,
  `test_partial_overlap_matches_hand_computation`.
Python (`apps/backend/tests/test_kernels_parity.py`):
- `test_python_and_native_agree_on_200_random_boxes` — exact to `1e-9` relative, seeded.
- `test_fallback_is_used_when_forced` — `LD_FORCE_PY_KERNELS=1` selects `kernels_py`, and the result is
  identical.
- `test_strict_mode_raises_without_the_module` — `LD_KERNELS_STRICT=1` and no module → `ImportError`,
  proving the test cannot silently pass on the fallback.
- `test_boxes_module_reexports_the_kernel` — `services.boxes.box_iou is kernels.box_iou`, so callers
  (`evaluate`, `insights`, `health`, `suspects`) all move together.
`tools/tests/test_bench_kernels.py`:
- `test_bench_reports_both_paths_and_a_speedup`, `test_min_speedup_exits_nonzero_when_below`.

## Acceptance criteria
- [ ] `pip install packages/labeldesk-core` (or `maturin develop`) builds an `abi3` wheel on Windows and
      on Linux/WSL, and `python -c "import labeldesk_core"` works on both.
- [ ] With no wheel installed, the entire existing suite and every job run unchanged on the fallback; the
      startup log says which path is active.
- [ ] `pytest apps/backend/tests/test_kernels_parity.py` passes with `LD_KERNELS_STRICT=1` (native) and
      with `LD_FORCE_PY_KERNELS=1` (fallback).
- [ ] `cargo clippy -- -D warnings`, `cargo test`, `cargo audit` and `cargo deny check` are clean, and
      `cargo deny check licenses` fails when a GPL dependency is added (proved once by hand, then
      reverted).
- [ ] A deliberate `panic!()` in `box_iou` fails the job that called it and leaves the process alive with
      `LD_KERNELS_STRICT=1` — proved in the RED step, then reverted.
- [ ] `python tools/perf/bench_kernels.py --json` writes a file with both paths and a speedup for the one
      kernel.
- [ ] The `rust` job is required by `gate` and the `api` job does not depend on it; the gate's wall clock
      is unchanged (report the run id and both job durations).
- [ ] `apps/backend/Dockerfile` builds with only the wheel in the runtime stage; `docker run` starts and
      `/api/healthz` answers.
- [ ] No wheel, `target/` or `Cargo.lock`-adjacent binary is committed (`tools/check_large_files.py`
      passes).

## Notes for the implementer
Do not invent a second seam. `kernels.py` is the only file allowed to import `labeldesk_core`; a new card
adds a function to the two kernel modules and nothing else.

Measure the gate before and after: `rust` must be parallel, and `api` must not wait for it. If a reviewer
sees `needs: rust` on `api`, that is a finding.

The tiny `box_iou` exists to prove the pattern (build, dispatch, parity, audit), not to make anything
faster — say so in the report. Its own speedup is irrelevant and does not need to reach 2x; the rule binds
the kernel cards, not the skeleton.
