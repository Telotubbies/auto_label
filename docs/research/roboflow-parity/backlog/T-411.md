## User story
As a workspace lead, I want to model next month's credits and reopen the same model a week later, so that a budget
conversation does not restart from a spreadsheet.

## UX flow (LabelDesk words)
1. **Usage & billing → `Projection` tab** — two headline numbers: `Projected credits this cycle` and
   `Beyond the included allowance` (or `Within the allowance`). [loading: two skeletons] [error: retry line]
2. **`Customize assumptions`** — horizon (`End of this cycle`, `End of next cycle`, `3 months`, `1 year`, custom
   date), a historical basis (`Last 7 days`, `Last 30 days`, `Since cycle start`), and one editable rate per kind
   (`Training runs / week`, `Auto-labeled images / day`, `Inferences / day`, `Versions / week`).
3. **`Save scenario`** — name field, saved to the workspace; the list of saved scenarios sits under the form with
   `Open` and `Delete`. [empty: `No saved scenarios yet.`]
4. **Share** — `Copy link` produces `/:ws/settings/usage?tab=projection&scenario=<id>`; `Publish` requires a
   confirm that names the exposure: `A public scenario shows your cost assumptions to anyone with the link.`
5. **`[empty]`** no usage history: the projection card reads `Not enough history to project.` with
   `Use a custom rate instead` which opens the assumptions form.
6. **`[error]`** a horizon in the past is refused inline; a saved scenario whose basis data was purged renders
   `This scenario's basis is no longer available.` and stays open for editing.

## Backend changes
- Models/schema: new `ProjectionScenario` in `app/models/insights.py`:
  `id, workspace_id FK, name VARCHAR(120), horizon VARCHAR(16), basis VARCHAR(16), custom_until FLOAT null,
  rates JSON, public BOOLEAN default false, created_by, created` with `UniqueConstraint(workspace_id, name)`.
- Routers: `POST /api/ws/{ws}/usage/projection` (compute, no save) → `{credits, beyond_allowance, allowance,
  points: [{date, credits}]}`; `GET/POST /api/ws/{ws}/usage/scenarios`, `PATCH/DELETE /api/ws/{ws}/usage/scenarios/{sid}`,
  `POST .../{sid}/publish {public}`. `400` for a horizon in the past, `409` for a duplicate name.
- Services/jobs: `app/services/projection.py` (new) — `project(db, ws, horizon, basis, rates, until) -> dict`
  (per-kind daily average × horizon days × rate multiplier, clamped to a 366-day horizon) and `rates_from(db, ws, basis)`.
- Permissions + workspace isolation: `workspace.read` to compute; `workspace.billing` to save, publish or delete
  (a saved scenario is shared billing material); scenario ids from another workspace are 404.
- Secrets/safefetch: none — a published scenario contains rates and credits, no key or invoice data.
- OpenAPI: yes.

## Frontend changes
- Route: `/:ws/settings/usage?tab=projection` (new sub-tab, plus `&scenario=<id>` deep link).
- Components: `features/settings/usage/ProjectionPanel.tsx` (new) — headline numbers, assumptions form, saved list;
  `features/settings/usage/projectionMath.ts` (new) — `horizonDays(horizon, until, today)`, `multiplyRates(a, b)`,
  `beyondAllowance(projected, allowance)`.
- API client: `usageApi.project(ws, body)` and `usageApi.scenarios*` in `src/lib/api/usage.ts`.
- Feature flag: `task_projection`; off ⇒ no projection tab and no routes.

## Acceptance criteria
- [ ] A projection shows projected credits and the amount beyond the included allowance.
- [ ] Assumptions (horizon, basis, per-kind rates) can be edited and saved as a named scenario.
- [ ] A scenario can be reopened by link; publishing warns that cost assumptions become public.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no projection tab and no scenario routes.

## Notes for the implementer
The projection is arithmetic over the existing series — no ML, no provider, no price. Horizon is capped at 366 days
so a saved scenario cannot ask the API to build a decade of points.
