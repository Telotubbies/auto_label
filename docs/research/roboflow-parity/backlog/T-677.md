## User story
As a shift supervisor, I want a rule to evaluate only during production hours, so that cleaning, changeover and the night stop stop paging me and a shift count is not diluted by 24 hours of noise.

## UX flow (LabelDesk words)
1. **Stream detail → Zones & rules → a rule's `ช่วงเวลาทำงาน`** (`/:ws/:project/streams/:sid`, the rules tab) — a 7-day row of toggles and one from/to pair, defaulting to `ทั้งวัน (ค่าเริ่มต้น)`. [empty: a rule with no window reads `ทั้งวัน (ค่าเริ่มต้น)` and runs always, exactly as today]
2. **A window across midnight** — `22:00` to `06:00` is accepted and reads `22:00–06:00 (ข้ามคืน)`; the grid highlights the days the window starts on.
3. **Outside the window** — the rule is not evaluated and the stream's counters read `ปิดตามตาราง 1,204` so the silence is explained instead of looking like a dead camera. [loading: the counter is part of the 3 s status poll and reads `—` until the first tick]
4. **A shift template** — when the stream's station carries shift windows, `ใช้ตารางกะของสถานี` fills the rule from the matching shift (A/B/C) in one click. [error: `ช่วงเวลาต้องเป็น HH:MM และวันอย่างน้อยหนึ่งวัน`] [error: `เวลาเริ่มและสิ้นสุดต้องไม่เท่ากัน`]
5. **Saving** — invalid input keeps the previous window and the rule row shows the error inline; a saved window restarts the stream (the existing stop/start on `PATCH`).

## Backend changes
- Models/schema: none — the window rides in the rule JSON (`Stream.rules`), so no column and no backfill. Shape: `{"days": [0,1,2,3,4], "from": "06:00", "to": "14:00"}` with `days` 0 = Monday.
- Routers: `app/routers/streams.py::check_rules` normalises `active` for every non-VLM kind — 400 for a day outside 0–6, a time that is not `HH:MM`, `from == to`, or an empty `days`; rejects the field entirely with 404 while `task_rule_schedule` is off, so an off deployment cannot store a window it will ignore.
- Services/jobs: `app/streams/rules.py::Engine` gains `clock: Callable[[float], tuple[int, int, int]] = _local_clock` (weekday, hour, minute) and skips a rule whose window excludes the frame, counting `self.suppressed[rule_index] += 1`; `in_window(window, weekday, hour, minute)` is a pure module function (handles the midnight wrap and an all-day window). `app/streams/manager.py` reads `engine.suppressed` into the live status dict beside `fps`/`frames`, and `stream_out` exposes it as `suppressed`.
- Permissions + workspace isolation: the window is a rule field on a stream the caller already manages (`c.need("admin")` on `PATCH /streams/{sid}`); a stream from another workspace is 404 through the existing `_get`.
- Secrets/safefetch: none.
- OpenAPI: yes — `stream_out` gains `suppressed` and `check_rules` gains a field; regenerate both generated files.

## Tests to write first
pytest — `apps/backend/tests/test_rule_schedule.py`:
- `test_a_frame_outside_the_window_fires_nothing` — `Engine(rules=[zone rule 06:00–14:00], clock=fixed(03:00))` gets a matching prediction → `step` returns `[]` and `engine.suppressed[0] == 1`.
- `test_a_frame_inside_the_window_still_fires` — the same rule at 09:00 fires once with today's summary text, unchanged.
- `test_a_window_wraps_midnight` — `22:00–06:00` covers 02:00 and 23:00 and excludes 12:00; `describeWindow` in the node test agrees.
- `test_a_rule_without_a_window_is_always_on` — no `active` key → fires at 03:00, `suppressed[0] == 0` (today's behaviour).
- `test_a_bad_window_is_400` — `{"days": [], "from": "06:00", "to": "14:00"}`, `{"from": "6:00"}`, `{"from": "06:00", "to": "06:00"}` are all 400 on `PATCH /streams/{sid}`.
- `test_the_window_field_is_invisible_while_the_flag_is_off` — with `task_rule_schedule` off, a rule carrying `active` is 404.
- `test_stream_out_exposes_the_suppressed_count` — after a suppressed tick, `GET /streams/{sid}` returns `suppressed >= 1`.
node — `apps/frontend/tests/rule-schedule.test.mjs`:
- `test_in_window_handles_the_midnight_wrap` — `22:00–06:00` is true at 23:30 and 02:00, false at 12:00.
- `test_describe_window_reads_all_day_or_the_pair` — `undefined` → `ทั้งวัน (ค่าเริ่มต้น)`, `06:00–14:00` → `06:00–14:00 (ข้ามคืน)` only when `to <= from`.
- `test_from_shift_picks_the_shift_covering_now` — station shifts A/B/C at 15:00 yields B's window.
- `test_valid_window_rejects_an_inverted_or_empty_day_set` — `{days: [], …}` and `{from: 'x'}` are false.

## Acceptance criteria
- [ ] A rule stores a day/hour window and stops firing outside it, with the counter naming how many evaluations the schedule suppressed.
- [ ] A window that crosses midnight works, and a rule with no window behaves exactly as today.
- [ ] A malformed window is refused inline and by the API, and the previous window survives.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no time control, no counter, and every rule evaluates on every frame as today.

## Notes for the implementer
Evaluate the window per frame with the worker's local clock (`time.localtime`) and inject the clock in tests — never compute local time at rule-save time, or a rule saved during a DST-less Bangkok year silently shifts. The counter is the whole point: a scheduled rule that goes quiet without a number reads as a broken camera. Copy: `streams.schedule.title`=`ช่วงเวลาทำงาน`, `streams.schedule.allDay`=`ทั้งวัน (ค่าเริ่มต้น)`, `streams.schedule.wrap`=`{from}–{to} (ข้ามคืน)`, `streams.schedule.suppressed`=`ปิดตามตาราง {n}`, `streams.schedule.fromShift`=`ใช้ตารางกะของสถานี`, `streams.schedule.invalid`=`ช่วงเวลาต้องเป็น HH:MM และวันอย่างน้อยหนึ่งวัน`, `streams.schedule.badRange`=`เวลาเริ่มและสิ้นสุดต้องไม่เท่ากัน`.
