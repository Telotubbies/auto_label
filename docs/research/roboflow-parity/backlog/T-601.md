## User story
As a Thai reviewer, I want a date to read 17 พ.ย. 2569 and a count to read 1,204 the way my spreadsheet writes it, so that a timestamp never needs mental arithmetic and a number never reads as a different magnitude.

## UX flow (LabelDesk words)
1. **Any date on screen** — with the locale in Thai and the Buddhist-era preference on, `17 พ.ย. 2569`; with the era preference off, `17 พ.ย. 2026` in Thai month names and Greek numerals. [empty: a missing timestamp renders `—`, never `NaN` or `Invalid Date`]
2. **A per-workspace override** — an export bound for a foreign parent can be set to Gregorian in Settings → Appearance; the override is a stored preference, not a per-render flag, so two people opening the same export see the same date.
3. **A count beside a name** — grouped with `Intl.NumberFormat` (`1,204`), and a compact form for a chip (`1.2k`). Thai digits are not used in ids, counts, class names or API values; they are a display choice only where the label is prose.
4. **A duration** — `2 ชม. 15 น.` in Thai, `2 h 15 m` in English, with the same rounding rule as today. [error: a negative or unknown duration renders `—`]
5. **A relative time** — `3 วันที่แล้ว`, `เมื่อสักครู่`, following `Intl.RelativeTimeFormat` and the same thresholds the app already uses.

## Acceptance criteria
- [ ] Every date the app renders goes through `formatDate`/`formatDateTime`; a raw `toLocaleDateString` call outside these helpers fails the test.
- [ ] Thai dates show Buddhist years with the preference on and Gregorian with it off, with Thai month names in both.
- [ ] Counts are grouped, compact chips keep one decimal, and no id or API value is formatted.
- [ ] Empty, loading and error states above all render: a missing or invalid timestamp is `—`, and a loading row uses the skeleton, not `Invalid Date`.
- [ ] Workspace A cannot see workspace B's data — N/A: no request.
- [ ] Flag off ⇒ every formatter returns today's English/Gregorian output.

## Notes for the implementer
`Intl` already does the hard part: `new Intl.DateTimeFormat('th-TH', {calendar:'buddhist'})` and `new Intl.NumberFormat('th-TH')` are in every target browser and in Node 18+. Do not hand-build a year offset and do not add a date library. Keep the era preference where `theme.ts` already stores it; a second copy is how one screen shows 2569 and the next 2026.
