## User story
As a line manager, I want one board where I pick a line and a week and read yield, the five defects that cost the most and the lots behind them, so that I can say which shift and which lot to look at before I open anything else.

## UX flow (LabelDesk words)
1. **`ผลผลิตและของเสีย`** (`/:ws/:project/ops/yield`) — a line picker, a date range and a grouping switch (`ล็อต` / `ไลน์` / `กะ`); the tiles read `ตรวจแล้ว 1,204 · ผ่านครั้งแรก 96.6 % · ของเสีย 41`. [loading: `กำลังคำนวณอัตราผ่าน`] [error: `คำนวณไม่สำเร็จ — ลองอีกครั้ง`] [empty: `ยังไม่มีคำตัดสินในช่วงนี้` with a link to the station screen]
2. **The Pareto** — five rows, each a `Progress` bar with `รอยขีดข่วน 12 · 49 %`; a sixth-class remainder is shown as `อื่น ๆ` so the bars always sum to 100 %. [empty: no NG in the window reads `ช่วงนี้ไม่มีของเสีย` and the block collapses to one line]
3. **The lot table** — a dense solid table: lot, inspected, first-pass, NG, rework, delta against the previous lot. Clicking a row expands the units behind it, lazily, with the disposition and the class. [error: `โหลดรายละเอียดไม่สำเร็จ — ลองอีกครั้ง` inside the expanded row only]
4. **The retention refusal** — a range longer than the project's retention renders the API sentence in place of the board and keeps the pickers usable. [error: `ช่วงวันที่เกินระยะเก็บข้อมูลของโปรเจกต์ (30 วัน)`]
5. **A shift row with no decisions** — reads `กะนี้ยังไม่มีคำตัดสิน — สถานีทำงานแต่ยังไม่มีใครยืนยัน`, never `0 %`.

## Backend changes
- Models/schema: none.
- Routers: none — the board reads `GET /yield` and `GET /yield/lots/{id}/units`.
- Services/jobs: none.
- Permissions + workspace isolation: the route is `<PermGate perm="project.read">`, and the API filters by workspace, so another tenant's lot is 404 through T-712.
- Secrets/safefetch: none.
- OpenAPI: no — no route changes.

## Tests to write first
node — `apps/frontend/tests/yield-board.test.mjs`:
- `test_percent_prints_one_decimal_or_a_dash` — `pct(0.9661)` is `96.6 %`; `pct(null)` is `—`.
- `test_a_shift_with_no_decisions_reads_the_sentence` — `emptySentence({decided: 0})` is `กะนี้ยังไม่มีคำตัดสิน — สถานีทำงานแต่ยังไม่มีใครยืนยัน`.
- `test_delta_names_direction_and_the_previous_window` — `deltaSentence({fpy: .966, previous_fpy: .96})` is `+0.6 % จากช่วงก่อน`; no previous is `ไม่มีช่วงก่อนหน้าให้เทียบ`.
- `test_pareto_rows_always_sum_to_one_hundred` — five rows plus an `other` count → the rendered labels sum to `100 %`.
- `test_group_labels_map_every_key` — `lot`→`ล็อต`, `line`→`ไลน์`, `shift`→`กะ`, `all`→`ทั้งวัน`.
pytest — `apps/backend/tests/test_yield_board_contract.py`:
- `test_the_board_payload_has_every_field_it_draws` — `GET /yield` returns `rows`, `pareto`, `totals`, and a row carries `key`, `label`, `inspected`, `fpy`, `previous_fpy`, `empty` (none missing).
- `test_the_board_from_another_workspace_is_404` — a project id from another workspace is 404.

## Acceptance criteria
- [ ] The board shows tiles, a five-row Pareto and a lot table for the chosen grouping and range.
- [ ] A shift or lot with no decisions reads its sentence rather than a percentage.
- [ ] A lot row expands into the units behind it, and a failed expansion stays inside that row.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no Ops group, no route and no change to the stream analytics page.
