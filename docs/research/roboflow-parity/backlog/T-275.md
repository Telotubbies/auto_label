## User story
As a new user, I want the first quick model to appear without asking for it — once — so that the product proves itself before I learn what a version is.

## UX flow (LabelDesk words)
1. **Nothing on screen** — the offer is a background job, not a banner. The job tray shows "Quick model · queued" and then the model appears in *Models* with the badge *Quick model*.
2. **Model list hint** — the first quick model's detail card carries one line: "This is a rough first model — its recipe is fixed and small. Train a full model when you have more images." [empty: no model yet ⇒ today's empty state]
3. **Once per project, ever** — after one automatic quick model the sweep never auto-enqueues again for that project; the manual action (T-276) stays available. A deleted quick model does not re-arm it.
4. **A quiet failure** — if the automatic run fails (no worker, out of allowance), nothing is shown as an error; the model row reads *Failed* with its remedy and the next manual action is unaffected.
5. **A project with a real model** — a project that already has a ready fine-tuned model is skipped entirely.

- **States** — [loading: the tray shows the queued run; no page blocks] [error: a refused sweep writes nothing and leaves the project eligible for the next tick].

## Backend changes
- Models/schema: `projects.settings.quick_model_offered` (JSON, no new column) set to `true` the moment an automatic quick run is enqueued.
- Routers: none.
- Services/jobs: `services/quick_model.py` gains `sweep(db, limit=5) -> list[str]`: select projects that (a) are `object-detection`, (b) have `settings.quick_model_offered` unset, (c) have ≥ 20 approved, non-deleted images and ≤ 1,000, (d) have no `TrainedModel` row with `status in ('queued','training','ready')`, (e) have no active `train` job; for each, resolve the newest `ready` version or create the implicit one through T-260's helper and call `enqueue(...)`. Called from the worker's periodic tick beside `retention.sweep` (every `RETENTION_CHECK_S`), capped at 5 projects per tick.
- Permissions + workspace isolation: the sweep runs as the workspace owner context it builds itself (same pattern as other periodic jobs); it never crosses a workspace boundary because it queries per project row.
- Secrets/safefetch: none.
- OpenAPI: no.

## Acceptance criteria
- [ ] One automatic quick run per project, at most, and never for a project that already has a model or a run.
- [ ] The sweep is bounded per tick and idempotent.
- [ ] A quick model's card says what it is and what it is not.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the sweep is a no-op and the note is absent.

## Notes for the implementer
Arm the `quick_model_offered` flag when the run is *enqueued*, not when it succeeds — a failing worker must not produce a retry loop every hour. Skipping (too few images) must leave the flag unset so the next batch can trigger it.
