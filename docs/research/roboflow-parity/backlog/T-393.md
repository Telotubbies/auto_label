## User story
As an admin rotating a key, I want the dialog to list what will break before I commit, so that I can warn the
right people first.

## UX flow (LabelDesk words)
1. **`⋯ → Roll`** — dialog `Roll “line-3-gateway”?` with the sentence `A new value is issued immediately and the
   old one stops working. Name, permissions and notes stay the same.`
2. **Dependents list** — one line per item from the probe (`This key is the workspace default.`,
   `412 metered calls in the last 30 days.`). [empty: `Nothing in this workspace references this key.`]
   [loading: three skeleton lines while the probe runs] [error: `Could not check what depends on this key.` —
   treated as unknown, so the checkbox is required]
3. **Acknowledgement** — when anything is listed or the probe is incomplete, `Roll this key` stays disabled until
   `I understand what depends on this key` is ticked.
4. **After the roll** — the dialog swaps to `New value — copy it now`, the value in a mono block with `Copy`, and
   `Done`; the row behind gains `New` and a toast reads `“line-3-gateway” rolled. The previous value no longer works.`
5. **`[error]` on submit** — the sentence from the server stays in the dialog and the old value is still live.

## Notes for the implementer
An incomplete probe is a "yes" for the acknowledgement gate — silence is not evidence that nothing depends on
the key. The submit button label is `Roll this key`, never the generic "Confirm".
