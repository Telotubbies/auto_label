## User story
As a shift leader, I want four overlapping cameras to arrive as one alarm I can own, acknowledge with a note and snooze for an hour, so that nobody chases the same event twice and "why was this ignored" has an answer.

## UX flow (LabelDesk words)
1. **A control-room read of the queue** — `GET …/alarms/queue` returns groups ordered unacknowledged first, then newest; each group carries its members, the camera count and its ack state. [empty: `ไม่มีรายการค้างรับทราบ` plus the last-24-hour total, never a blank panel] [loading: the queue is one query, so the list shows the shipped skeleton rows until it lands]
2. **Acknowledgement** — `POST …/alarms/ack` records who, when and an optional note on every member of the group. [error: `มีคนอื่นรับทราบรายการนี้แล้ว` when another operator got there first — the response names them and the client re-reads the row]
3. **Assignment** — `POST …/alarms/assign` with `owner: "me"` sets the owner; an explicit user id is refused with 400 so the first version cannot assign to somebody who is not looking.
4. **Snooze** — `POST …/alarms/snooze` `{minutes, reason}` hides the group until the moment passes and keeps the reason. [error: `ต้องระบุเหตุผลก่อนเลื่อนการแจ้งเตือน`] [error: `เลื่อนได้ 1 ถึง 1440 นาที`]
5. **A snoozed group returns** — when `snooze_until` passes the group is back in the queue with `เลื่อนไว้ถึง 14:20` still readable, so the history is not a guess.

## Backend changes
- Models/schema: `StreamEvent` gains `ack_by VARCHAR(32)` (null), `ack_at FLOAT` (null), `ack_note VARCHAR(280) DEFAULT ''`, `owner_id VARCHAR(32)` (null), `snooze_until FLOAT` (null), `snooze_reason VARCHAR(200) DEFAULT ''` as one `ADD COLUMN` block in `app/schema/streams.py` `STREAM_EVENTS`.
- Routers: `app/routers/alarm_queue.py` (new), prefix `/api/ws/{ws}/projects/{project}/alarms`, `dependencies=[Depends(require_flag("task_alarm_queue"))]`; `GET /queue?since_hours=24` → `[{key, rule_label, zone, station, camera_count, first_ts, last_ts, event_ids, acked_by, acked_at, owner, snoozed_until, members}]`; `POST /ack` `{event_ids, note?}` → the refreshed group (409 when someone else acked first, body naming that user); `POST /assign` `{event_ids, owner: "me"}`; `POST /snooze` `{event_ids, minutes, reason}`. 400/422 for the documented bounds.
- Services/jobs: `app/services/alarm_queue.py` (new) — `group_key(event, window_s=30)` (`rule_label | zone | ts // 30`), `queue(db, project, now, since_hours=24, limit=500)` (read-time grouping, no writes, snoozed groups filtered out until `snooze_until`), `ack(db, events, user_id, note)` raising `AlreadyAcked(by)`, `assign(db, events, user_id)`, `snooze(db, events, minutes, reason)`. No job; the existing per-track `cooldown_s` in `streams/rules.py` is untouched and still stops one camera repeating itself.
- Permissions + workspace isolation: `GET /queue` needs `project.streams`; ack/assign/snooze need `project.review`; every query filters `workspace_id` **and** `project_id`, and an event id from another workspace is 404 before any write. Every state change writes an `audit()` row (`alarm.ack`, `alarm.snooze`).
- Secrets/safefetch: none.
- OpenAPI: yes — four new routes and their schemas.

## Acceptance criteria
- [ ] Events from four overlapping cameras with the same rule and zone inside 30 seconds arrive as one group that names its camera count.
- [ ] A group is acknowledged once with who, when and an optional note, and a second operator is told who beat them.
- [ ] Assign and snooze are stored with an owner and a reason, and a snoozed group returns with its reason intact.
- [ ] Empty, loading and error states above all render — the empty queue carries the last-24-hour count instead of a blank panel.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the queue routes 404 and the timeline behaves exactly as today.

## Notes for the implementer
Group at read time, not at write time: a stored `group_key` would need a backfill and would freeze a wrong 30-second boundary forever. The grouping key is `rule_label | zone_id | ts // 30` and **must** include the station, or two lines running the same rule merge into one alarm — the test above pins it. Snooze is a state with a reason, never a delete.
