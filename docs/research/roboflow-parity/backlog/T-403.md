## User story
As an admin, I want the workspace's data rules on the settings page I already visit, with a visible lock when the
plan or region forbids a change, so that I never learn a rule from a failed action.

## UX flow (LabelDesk words)
1. **Settings → Workspace → `Workspace policies`** — a card with two switch rows:
   `Allow public projects` (`Members can publish a project to a public page.`) and
   `Allow vendor training` (`Private-project images may be used to improve LabelDesk models. Read the licensing
   note before turning this off.`).
2. **Turn off `Allow public projects`** — no confirm; the row shows `Off` immediately and the sentence under it
   becomes `Publishing is blocked. Existing public projects stay public until someone makes them private.`
   [loading: the switch shows a small spinner and ignores further clicks] [error: the switch snaps back and a toast
   quotes the server sentence]
3. **Locked row** — the switch is dimmed with a lock icon and the tooltip `Locked by your plan or region — contact
   support.`; the row still states the current value.
4. **`[empty]`** a workspace that never set anything shows both switches `On` and the line `Defaults: both allowed.`
5. **Read-only** — a member without `workspace.update` sees both rows dimmed with a lock and `Request access`.

- [ ] Turning a switch off updates in place and the consequence sentence changes.
- [ ] A locked switch is visibly locked with a reason and cannot be toggled.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).

## Notes for the implementer
No dialog on the public-projects switch — the consequence lives in the sentence, which is cheaper than a confirm
nobody reads. The vendor-training switch's dialog is T-404, not this card.
