## User story
As a labeler on a flaky link, I want my edits kept on this device and retried, so that a dropped connection costs a retry rather than an afternoon.

## UX flow (LabelDesk words)
1. **Save fails with a network error** — the save bar turns to an offline state: "Offline — 2 images kept on this device" with **Retry now**; the canvas stays editable, and the queue holds the newest set for each image (a later save replaces an earlier one for the same image). [error: a browser storage quota failure → the bar says "This device is out of space — the current image is not queued" and the image is marked unsaved]
2. **Reconnect** — `online` replays the queue oldest-first; each success clears that image's entry and the bar counts down ("1 image left"); a retry is also available manually.
3. **Conflicts during replay** — a 409 from T-121 keeps the entry, stops the replay and opens the conflict bar for that image; other queued images continue. The queue never silently overwrites a newer row.
4. **Leaving the editor** — navigating with a queued image is allowed *only* after the entry is persisted to storage; the bar remains visible on the board as a workspace-free toast on the next image ("1 image is still waiting to save") until the queue empties.
5. **Reload** — a reload restores the queue and retries automatically; the entries are per device and per user, and are cleared on sign-out.
6. **Decode failure** — an image that cannot be decoded shows a canvas message: "This image could not be opened" with **Retry** and **Skip to next**; the annotations are untouched and the header save state is unaffected. [loading: Retry shows a spinner over the canvas]
7. **Never silent** — the queue has a hard cap of 20 images; the 21st is refused with the same out-of-space sentence, so nothing is dropped without the user seeing it.

## Acceptance criteria
- [ ] A network-failed save keeps the annotations on this device, says how many images are waiting, and offers Retry now.
- [ ] Reconnecting replays oldest-first, clears each success and stops at the first conflict without touching the rest.
- [ ] The queue survives a reload, is capped at 20 with a visible refusal, and is cleared on sign-out.
- [ ] An undecodable image shows Retry and Skip, leaving its annotations and save state alone.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — the replay never crosses the session's workspace.
- [ ] Flag off ⇒ a failed save behaves exactly as today; no queue, no banner.
- [ ] Keyboard-only path: failed save → Tab to Retry now → Enter; decode error → Tab to Skip → Enter.

## Notes for the implementer
`localStorage` is the right store here (small, synchronous, survives a crash); do not reach for IndexedDB for 20 arrays. Keys are `ld:offline:<userId>` so two people sharing a machine never see each other's edits, and the entry never contains the image URL or token.
