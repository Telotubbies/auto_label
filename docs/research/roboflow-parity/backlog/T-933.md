## User story
As a workspace member, I want a model to download as one folder that explains itself, and to be able to hand that folder to a colleague or a machine, so that a model is not trapped inside this product.

## UX flow (LabelDesk words)
1. **Model detail → Artefact** — "Download model" produces one zip. Inside: `model.json`, the weights file, `requirements.txt` and `README.txt`. [empty: a model still training shows the button disabled with "Available when training finishes"] [loading: the button reads "Packaging… <n>%" and the file list is dimmed] [error: 409 "The weights file is missing on disk" plus the storage path, so an operator can restore it]
2. **Models → Import a model** — the user drops the same zip; the dialog shows a per-file check (name, size, whether the checksum matches `model.json`) and then "Import". [empty: the drop zone reads "Drop a model folder or zip"] [loading: "Checking…" per file, one row at a time] [error: "This folder is missing model.json" / "weights checksum does not match" / 503 "Importing an external model needs the mlflow extra"]
3. **After import** — the model appears in Models like a trained one, with its family, task and classes read from the document; a document whose `family` is not installed is refused with the family named.

## Backend changes
- Models/schema: no new table. `TrainedModel` is reused; `runtime_refs` (`apps/backend/app/models/training.py:52`) stores `{"artefact": 1, "imported_from": "<sha256>"}`.
- Routers: `apps/backend/app/routers/models_artefact.py` (new) — `GET {P}/models/{mid}/artefact` returns a zip (`application/zip`); `POST {P}/models/import` accepts `multipart/form-data` with one `file`, returns the created model dict (201), 400 for a bad document, 409 for an existing checksum, 503 when the optional extra is absent. Both `project_ctx`.
- Services/jobs: `apps/backend/app/services/artefacts.py` (new) — `document(m: TrainedModel, db) -> dict`, `write_zip(m, db, out: Path) -> Path`, `read_zip(data: bytes, db, ws_id: str) -> dict`, `RUNTIMES = {"ultralytics", "hf", "rfdetr", "sam3", "tensorrt", "vlm"}`. Import proves the format by magic bytes per family, then writes the row and the weights under `DATA_DIR` (`apps/backend/app/config.py:36`) at the same relative layout the trainer already uses, so `TrainedModel.weights` stays a `DATA_DIR`-relative path (`apps/backend/app/models/training.py:48`) and `delete_model_files` (`apps/backend/app/services/erasure.py`) keeps working.
- Permissions + workspace isolation: `project.read` to download, `project.train` to import; the imported rows carry `workspace_id` and `project_id` from the context, never from the document.
- Secrets/safefetch: none — no URL is fetched; the zip is parsed in memory with a size cap of 2 GB and no path traversal (reject any member whose normalised path escapes the target).
- OpenAPI: yes — `python tools/export_openapi.py`, `npm run gen:api-types`.

## Acceptance criteria
- [ ] A ready model downloads as one zip with `model.json`, weights, `requirements.txt` and `README.txt`.
- [ ] The same zip imports back into another project as a ready model with the same family, task and classes.
- [ ] A document naming an uninstalled family is refused with that family's name, not a stack trace.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: 5-F5.31 → T-288 (`5-F5.31` weights upload) and 6-F6.37 → T-342 (load a model from Python) — T-288 imports weights into a *trained* model row, T-342 reads a model from our API. This card is the portable *folder*: document + weights, no API.
Backend also adds one `THIRD_PARTY_LICENSES.md` block for `mlflow-skinny` (Apache-2.0, https://github.com/mlflow/mlflow, pinned version), because reading a folder produced by that format needs it. It stays an optional extra in `apps/backend/requirements.txt` (commented line beside the `transformers` block at `:25`) and the route degrades with a reason: our own zip imports without it, a foreign one returns 503 "Importing an external model needs the mlflow extra". The library is smaller than the rebuild — flavour dispatch plus `_load_pyfunc` plus code paths is thousands of lines — and it is never imported at module scope.
`model.json` keys, in order: `artefact` (1), `family`, `variant`, `task`, `classes`, `input_kind`, `output_kind`, `contract` (null until T-934), `environment` (null until T-935), `licence`, `weights` (`{file, bytes, sha256}`), `created` (UTC ISO 8601).
