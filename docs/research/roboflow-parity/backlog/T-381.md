## User story
As a workspace admin, I want the API to refuse a role change or a leave that would strand the workspace, so
that a mis-click cannot empty the only admin seat.

## UX flow (LabelDesk words)
1. **Row menu → Change role** — a dialog with a role dropdown (the assignable roles from the roster API) and
   `Save`. The caller's own row has no role item at all; if a hand-crafted request arrives anyway the dialog
   shows `You cannot change your own role. Ask another admin.`
2. **Last admin leaves** — `Leave workspace` on the only admin → the confirm refuses with
   `You are the last admin. Promote someone to admin first.` and the button stays on the row.
3. **Owner row** — the owner's role is fixed: the dialog is not offered, and the API answers
   `The workspace owner is always an admin.`
4. `[error]` the dialog keeps the chosen role visible and shows the server sentence; nothing is saved.
5. `[loading]` `Save` shows `Saving…` and the row is disabled until the answer arrives.

## Backend changes
- Models/schema: none.
- Routers: `PATCH /api/ws/{ws}/members/{uid}` (`routers/workspaces.py`) gains:
  `409` when `body.role` would leave no `owner|admin` member other than the target;
  `400 you cannot change your own role` when `uid == c.user.id` and the role differs;
  the existing `400` for `uid == c.ws.owner_id` stays.
  `DELETE /api/ws/{ws}/members/{uid}` gains the same last-admin `409` when the target is an admin and no
  other `owner|admin` remains — evaluated on the workspace's member set, not on the caller's role.
- Services/jobs: `admins_left(db, ws, skip_uid) -> int` in `routers/workspaces.py` (one query, both routes).
- Permissions + workspace isolation: `workspace.members` for both routes; owner/admin may only act inside
  `c.ws.id`, and a `Member` row from another workspace is already a 404.
- Secrets/safefetch: none.
- OpenAPI: yes — two new documented error responses.

## Acceptance criteria
- [ ] An admin cannot change their own role; the dialog says what to do instead.
- [ ] The last admin cannot leave or be demoted, and the message names the action that unblocks it.
- [ ] Empty, loading and error states above all render (dialog error keeps the choice visible).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids, 409 for the guard).
- [ ] Flag off ⇒ today's inline role select and unguarded delete are unchanged.
- [ ] Every refusal leaves the member row untouched and writes no audit row.

## Notes for the implementer
The guard counts `owner` **and** `admin` rows and excludes the target; owner rows cannot exist twice because
ownership transfer is unsupported. Keep both messages as given — the row menu quotes them verbatim.
