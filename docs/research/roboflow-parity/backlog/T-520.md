## User story
As a labeller on a phone, I want the image grid to show tiles I can actually see and tap, and a count that
tells me how many of my images I am looking at, so that I trust both the grid and the number.

## UX flow (LabelDesk words)
1. **Dataset** (`/:ws/:project/browse`) at 1440 — five tiles per row, as today. The subtitle reads
   `40 images` with no filter, and `24 of 40 images match` when a filter is on. [empty: `No images yet`
   with `Upload images`] [loading: the existing skeleton rows] [error: the existing query error banner]
2. **Dataset at 375** — two tiles per row, then three at `sm`, four at `lg`, five at `xl`. Tile chrome
   (split chip, filename, class dots, count) stays inside the tile at every width.
3. **Scroll to the end** — the virtualiser loads the next page at the same threshold it uses today.

## Notes for the implementer
Options considered, in ponytail order:
1. **A measured `cols` + matching breakpoint classes (recommended).** One helper, one `useSyncExternalStore`
   on `matchMedia`, the virtualiser stays correct. ~30 lines.
2. **CSS-only `grid-cols-2 sm:grid-cols-3 …` with `cols` left at 5.** Rejected: the virtualiser would slice
   five items into a two-column row and leave holes.
3. **Drop virtualisation below `md`.** Rejected: a second render path and a second pagination trigger.

The subtitle is a claim about the user's data, so it changes with the filter, not with the page. `40` is
`project.images` from `useProject()`, already loaded. Keep `total === 1` singular.
