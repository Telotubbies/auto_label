## User story
As the lead of one production line, I want a ceiling on what this project may spend this month and a refusal that tells me who can raise it, so that a noisy neighbour cannot starve the other lines on the same contract.

## UX flow (LabelDesk words)
1. **A training run that fits** — the ceiling is read before the charge; nothing changes for the user.
2. **A training run that does not fit** — `[error: this run needs 3 credits and 180 credits are left in this workspace, but the project budget of 1,200 is exhausted — raise this project's budget or wait for the next cycle]` with 402; no `TrainedModel` row and no `Job` row is created.
3. **Threshold notices** — at 50, 80 and 100 % of the monthly budget the project records one notice per threshold per month ("This project has used 80% of its November budget."), visible in the audit log; a repeated request never writes a second row for the same threshold.
4. **No budget set** — every check passes exactly as today; the payload reports `budget: null`.
5. **Flag off** — no check anywhere and no notice rows.

## Backend changes
- Models/schema: none — the budget lives in `Project.settings["budget"] = {"credits": int, "alerts": [50, 80, 100], "notify": ["admin"|"channel"]}`, the JSON column `models/project.py:32` already stores per-project options.
- Routers: `app/routers/budgets.py` (new) — `GET /api/ws/{ws}/projects/{project}/budget` (`{budget, used, remaining, period, percent}`), `PATCH …/budget` (422 when `credits` is under 1 or over 1,000,000, or `alerts` is not an ascending subset of `[50, 80, 100]`), `GET …/budget/estimate?version_id=&epochs=&imgsz=` (`{credits, gpu_seconds, minutes}`), `GET /api/ws/{ws}/budgets` (every project's bar and burn rate for the Usage screen).
- Services/jobs: `app/services/budget.py` (new) — `KEY = "budget"`, `get(project)`, `set(project, body)`, `spend(db, project, since) -> float` (versions × `CREDIT_COST["version"]` + trained models × `CREDIT_COST["train"]` + autolabel `UsageEvent` rows × `CREDIT_COST["autolabel_image"]` for this project since the window), `remaining(db, project)`, `check(db, c, project, credits) -> None` raising the 402 with the sentence above, `notice(db, project, percent)` writing one `budget.notice` audit row per threshold per month, `estimate(version, epochs, imgsz)` returning `CREDIT_COST["train"]` and `training._gpu_estimate(...)/60`.
- Wiring: `app/routers/training.py` calls `budget.check` immediately before the four existing charge points (`:271` train, `:349` and `:636` infer, `:522` autolabel) and `budget.notice` after each successful charge.
- Permissions + workspace isolation: project managers read and write their own project's budget (`project.settings`), owners and admins read every project bar (`workspace.billing`); a project slug from another workspace is 404 through `project_ctx`.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] A project budget in credits is stored in `Project.settings` and read back with used, remaining and percent.
- [ ] A billable action that would exceed the budget answers 402 with the project sentence and creates no job.
- [ ] One notice row per threshold per month, never duplicated.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no check, no notice, all four routes 404, and every existing quota message is unchanged.

## Notes for the implementer
`spend()` is a sum of the charges this product actually made for the project — version, train and autolabel rows — not a new accounting path; if a new billable action ships, it must add its term here or the budget silently under-counts. The 402 is the pause: a budget kill switch that cancels a running job is a different card and a different promise.
