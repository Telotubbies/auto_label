## User story
As an ML engineer whose run hit its cap, I want the stop named, the spend shown, and the leftover cap to buy more epochs on the same model, so that a guarded run is a pause rather than a throwaway.

## UX flow (LabelDesk words)
1. **The run stops itself** — the row reads *Stopped early · cap reached* and the detail card says "Stopped at epoch 12 of 40 by the 2-credit cap. The best weights were kept."
2. **Spend** — the same card shows "1.8 of 2 credits used · 54 min GPU", live while running and final after the stop. [loading: the two numbers shimmer; the run's own numbers never read 0 while it is training]
3. **Continue** — a primary *Continue for 1 credit* appears when the model's leftover cap still covers the minimum; it starts a run from this model, in the same variant, with the same cap and the epochs that remain. The button's tooltip states "Starts a new run from this model's best weights. The previous run is untouched."
4. **Too little left** — the button is absent and the reason is printed: "0.2 credit left — the minimum run needs 1." plus a *Raise the cap* link to the same form prefilled.
5. **No cap at all** — no banner, no continue action; an uncapped run that ran out of the workspace allowance uses T-262's quota remedy instead.

- **States** — [empty: an uncapped model shows no banner and no continue action] [error: a refused continue prints the API sentence beside the button and leaves the model untouched].

## Backend changes
- Models/schema: `trained_models.credits_used FLOAT DEFAULT 0`, `trained_models.continued_from VARCHAR(32)` (nullable; plain column, no FK so a deleted parent cannot cascade a child away). Append both to `TRAINED_MODELS` in `apps/backend/app/schema/training.py`.
- Routers: `POST {P}/models/{mid}/continue` body `{credits: float | None}` → `201 model_out`; **400** when the remainder is below `train_quote.minimum_credits` ("0.2 credit left — the minimum run needs 1.0"), **409** when the model is not `ready`/`stopped`, **404** for a foreign model. The new run's `job.params.options` carries `checkpoint={kind:"previous", model_id:mid}` and the remaining epochs.
- Services/jobs: `handlers/training.py` — on a cap stop, set `tm.metrics.stop_reason = "cap"`, `tm.credits_used = round(gpu_seconds / 1800, 2)` (from the metered lease) and keep the checkpoint. `services/train_quote.remaining_credits(model) -> float` = `max(0, max_credits - credits_used)`; `can_continue(model) -> bool`.
- Permissions + workspace isolation: continue = `c.need("admin")` (it spends); a foreign model id → 404, a foreign project slug → 404.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] A cap stop is named on the row and the detail card, and the weights stay deployable.
- [ ] Spend is visible as two numbers and matches the metered GPU seconds divided by 1800.
- [ ] Continue starts a new run from the same model only when the remainder covers the minimum; otherwise it explains why.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no banner, no route, cap stop reads as "ready".

## Notes for the implementer
`credits_used` is derived at the end of a run from metered GPU seconds — never incremented per epoch in a second place. The child run links with `continued_from`, no FK: deleting the parent must not delete the child.
