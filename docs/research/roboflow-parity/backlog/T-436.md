## User story
As an admin, I want to connect our own vendor key for a hosted model, so that a pipeline can use it without an operator
editing the server's environment.

## UX flow (LabelDesk words)
1. **Settings → Integrations → `Hosted models`** (`/:ws/settings/integrations`) — one row per vendor
   (`OpenAI-compatible`, `Anthropic`, `Google`), each with a state chip `Not connected` / `Connected`, `Connect`,
   `Replace key`, `Disconnect`.
2. **Connect** — a dialog: `Base URL` (prefilled with the vendor default, editable for a gateway) and `API key`
   (write-only, hint `Stored encrypted. Never shown again.`), then `Save and test` which sends one tiny prompt.
   Success: `Connected · 412 ms.` Failure states: `The key was rejected (401).` / `The endpoint is not reachable.` /
   `That address is not allowed — use a public endpoint.`
3. **Disconnect** — confirm `Disconnect OpenAI-compatible? Pipelines using it fall back to the workspace's local model.`
4. **`[empty]`** no vendor connected: the card states `No hosted models are connected. Pipelines use the workspace's own
   model.` and the pickers in the pipeline editor show only local models.
5. **`[error]`** a key that fails the test is not saved; the dialog keeps the base URL and clears the key field.

## Backend changes
- Models/schema: new `VendorKey(id, workspace_id FK CASCADE, vendor VARCHAR(24), base_url VARCHAR(512),
  key_ciphertext TEXT, connected_at FLOAT null, last_status VARCHAR(24), created_by, created)` with
  `UniqueConstraint(workspace_id, vendor)` in `app/models/identity.py`.
- Routers: `app/routers/vendor_ai.py` (new) — `GET /api/ws/{ws}/vendors` (masked state only),
  `PUT /api/ws/{ws}/vendors/{vendor}` `{base_url, api_key}` (saves only after a successful test),
  `POST /api/ws/{ws}/vendors/{vendor}/test`, `DELETE /api/ws/{ws}/vendors/{vendor}`.
- Services/jobs: `app/services/vendor_ai.py` (new) — `VENDORS = ("openai_compatible", "anthropic", "google")`,
  `save(db, ws, vendor, base_url, api_key, actor)` (validate base URL with `safefetch.check_url`, encrypt the key with
  `secretbox`), `resolve(db, ws, vendor) -> dict | None` (decrypted key + base URL for the adapter, in memory only),
  `probe(resolved) -> tuple[bool, str, int]` (one 2-token request, 5 s timeout), `disconnect(db, ws, vendor, actor)`;
  `adapters/vlm_ad.py` gains one branch: a workspace-vendor configuration takes precedence over `LD_VLM_URL`.
- Permissions + workspace isolation: `workspace.update` (owner/admin) for every route; `resolve` filters the workspace.
- Secrets/safefetch: keys through `secretbox`; base URLs through `safefetch.check_url` on save and before each probe;
  no key is ever returned, not even a mask beyond `•••`.
- OpenAPI: yes.

## Acceptance criteria
- [ ] A vendor key can be connected per workspace and is only saved after a successful probe.
- [ ] The key is encrypted at rest and never returned; the base URL is SSRF-checked.
- [ ] Disconnecting falls back to the workspace's local model without breaking a pipeline.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no tab, no routes, env-based adapter exactly as today.

## Notes for the implementer
Test before save, not after: a stored key that does not work is worse than no key. The adapter branch is one
`if` — do not build a vendor registry abstraction for three names.
