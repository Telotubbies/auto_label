## User story
As a video labeler, I want an action's start and end saved against a class, so that "screwing from 2.4 s to 6.1 s" is expressible without inventing a project type.

## UX flow (LabelDesk words)
1. **Project → Video** (`/videos`, existing, `task_22`) — each video row gains a **Segments** count once the flag is on; the row's action opens the segment view (T-147). [empty: no video → the page's existing empty state]
2. **Creating a segment** — the client sends class, start and end in seconds. Accepted when `0 ≤ start < end ≤ duration`; rejected with a plain reason otherwise ("The end must be after the start", "The video is 42.0 s long").
3. **Editing** — dragging an edge or "set in/out" patches the same row; a segment keeps its id across edits so a reviewer's decision is not lost by a nudge.
4. **Deleting** — one row, confirmed in the UI, audited.
5. **Review state** — each segment carries `draft | review | approved | rejected`; a rejected segment stays visible with its reason and can be edited back to `review`. [error: a decision on a segment from another project → 404]
6. **No new project type** — segments attach to any project with videos; a project type gate would duplicate the work area 1 owns for project types.

## Backend changes
- Models/schema: new table `video_segments` (`models/segments.py`, new) — `id`, `workspace_id`, `project_id`, `video_id` (FK, cascade), `class_id` (FK to `classes`, cascade), `start_s`, `end_s` (float), `status` (`draft|review|approved|rejected`), `note` (text, reject reason), `created_by`, `created`, `updated`; index `(video_id, start_s)`; registered in `models/__init__.py`.
- Routers: new `app/routers/segments.py` (new) mounted at the project prefix — `GET /videos/{vid}/segments`, `POST /videos/{vid}/segments` `{class_id, start_s, end_s}`, `PATCH /segments/{sid}` `{class_id?, start_s?, end_s?, status?, note?}`, `DELETE /segments/{sid}`, `POST /videos/{vid}/segments/review` `{ids, approved, note?}`; `201` on create, `400` for a bad range or a class from another project, `404` for a foreign video/segment, `409` for an exact duplicate.
- Services/jobs: `services/segments.py` (new) — `validate_range(start, end, duration)`, `overlaps(rows)` (advisory, returned with the list), `decide(rows, ids, approved, note)`.
- Permissions + workspace isolation: `project_ctx` on every route; writes need `c.can("project.annotate")`, decisions need `project.review`; the video lookup filters `project_id` and `workspace_id`, so a foreign video is 404.
- Secrets/safefetch: none.
- OpenAPI: yes — five routes and two bodies.

## Acceptance criteria
- [ ] A segment saves with class and time range, lists in start order, and can be edited and deleted.
- [ ] A range that is empty, negative or past the duration is refused with a message naming the limit.
- [ ] Review decisions require `project.review`; a labeler can still create and edit their own segments.
- [ ] Two segments of different classes may overlap; an exact duplicate is refused.
- [ ] Empty, loading and error states above all render (an empty list is `[]`, never a 404).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ every route 404 and the Videos page behaves as today.
- [ ] Keyboard-only path: not applicable in this card.

## Notes for the implementer
Seconds are floats with two decimals — never frame numbers, because a 29.97 fps video would need a frame-rate convention nobody asked for. `duration` comes from `Video.duration`; a video still extracting returns 400 "the video is still being prepared".
