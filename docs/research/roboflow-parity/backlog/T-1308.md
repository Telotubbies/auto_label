# T-1308 — Security headers everywhere, and a closed `/api/metrics`

| Field | Value |
| --- | --- |
| Wave | O (security, monitoring, performance) |
| Area | Security (shared with monitoring) |
| Size | 2 agent-hours |
| Role | R3 backend + R4 frontend (config only) |
| Skills | ponytail, test-driven-development, verification-before-completion |
| R7 security review | yes — this card chooses what a browser is allowed to do |
| Depends on | T-1302 (`/api/metrics` exists and needs its token) |
| Feature flag | none; `LD_METRICS_TOKEN` unset ⇒ the route is 404 |

## Problem
The API middleware sets `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options` and an API CSP
(`app/main.py:66-76`); the SPA has a full CSP in `nginx.conf` and `vercel.json`. Missing:
`Permissions-Policy` and `Cross-Origin-Opener-Policy` on API responses, a CSP for the API that also
carries `report-uri`, HSTS in the bare `nginx.conf` path (it exists only where Caddy or Vercel
terminates TLS), and any protection on the new metrics route.

## Design
- `app/main.py` middleware (the same function, ~35 lines total):
  - `Permissions-Policy: camera=(), microphone=(), geolocation=(), display-capture=(), usb=()`;
  - `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Resource-Policy: same-origin` on
    `/api/*` **except** `/api/files/*` (signed image URLs are consumed by the SPA and by `<img>`, which
    is fine same-origin; the exception exists so an embedding client is a deliberate later decision);
  - keep `Cache-Control: no-store` and the `default-src 'none'` CSP on JSON routes;
  - add `Content-Security-Policy-Report-Only` only for the SPA (in `nginx.conf`), pointing at
    `/api/csp-report` — the endpoint logs one line and increments a counter, nothing else.
- `app/routers/health.py`-style small route `POST /api/csp-report` (in the same router module T-1301
  created, or in `metrics.py` if that reads better): accepts `application/csp-report` and
  `application/reports+json`, caps the body at 8 KB, logs `csp.violation` with `request_id`, never
  stores.
- `nginx.conf`: add `Strict-Transport-Security` and `Permissions-Policy` to both header blocks and the
  `Report-Only` CSP line. `vercel.json`: add `Permissions-Policy` and `Cross-Origin-Opener-Policy`.
- `deploy/Caddyfile`: unchanged (it already sends HSTS, drops `Server`, caps the body); add
  `Permissions-Policy` to the hardening snippet so a Caddy-only deployment matches.
- `/api/metrics` keeps its token check from T-1302; this card adds the test that it is 404 without one
  and that Caddy does not route it (assert the Caddyfile has no `/metrics` matcher).

## Tests to write first
`apps/backend/tests/test_sec_headers.py`:
- `test_every_api_response_has_the_header_set` — walk 6 representative routes (JSON, upload, file
  download, 401, 404, metrics) and assert the six headers.
- `test_files_route_is_allowed_to_differ` — the CORP exception only exists on `/api/files/*`.
- `test_api_csp_is_deny_all` — `default-src 'none'` and no `unsafe-inline`.
- `test_csp_report_route_caps_the_body` — 9 KB body ⇒ 413; a normal report logs one line.
- `test_csp_report_never_stores_or_echoes` — the response body is empty.
- `test_metrics_is_closed_without_a_token_and_not_routed_by_caddy` — 404 plus a Caddyfile parse.
- `test_no_server_header_leaks_uvicorn` — assert `Server` is absent or set by the proxy only.

## Acceptance criteria
- [ ] Six headers on every `/api/*` response; the documented exception is the file route only.
- [ ] The SPA sends HSTS and `Permissions-Policy` under nginx, Vercel and Caddy configurations.
- [ ] CSP violations from a real browser are logged with a request id; nothing is stored.
- [ ] `/api/metrics` is 404 without `LD_METRICS_TOKEN`, 200 with it, and no proxy route exposes it.
- [ ] No header introduces a console error in the SPA (Playwright smoke, screenshot in the report).

## Notes for the implementer
`Content-Security-Policy-Report-Only` on the SPA is a deprecation-avoiding choice: `report-to` needs a
`Report-To` group and a JSON body, which is more moving parts for one log line. Keep the report route
dumb. Do not add `unsafe-eval` anywhere; if the build needs it, that is a finding for the report, not a
header change.
