## User story
As a QC inspector, I want every pass, reject and rework stamped with the lot and my own id, so that a week later I can answer which lot it was, who passed it and what happened to that unit.

## UX flow (LabelDesk words)
1. **A lot is opened** — the inspector types or scans `LOT-2481` and the work order into the station screen's lot field; the lot becomes the current lot for that station and every following unit inherits it. [empty: `ยังไม่มีล็อตที่เปิดอยู่ — เปิดล็อตใหม่`]
2. **One unit is decided** — `ผ่าน`, `ไม่ผ่าน` or `ส่งซ่อม`, with a defect class for a reject and a reason plus a due date for a rework. [loading: `กำลังบันทึกคำตัดสิน` under a second] [error: `บันทึกไม่สำเร็จ — ลองอีกครั้ง` and the sheet stays open]
3. **A closed lot is refused** — a unit scanned into a lot that already shipped is 409 with `ล็อตนี้ปิดแล้ว — ยังบันทึกไม่ได้`; the unit is blocked, never silently accepted. [error: that sentence, in the destructive tone]
4. **The lot closes** — closing is refused while any unit has no disposition, and the message names the count: `ปิดล็อตไม่ได้ — ยังมี 4 ชิ้นที่ไม่มีคำตัดสิน`. [error: that sentence with the real number]
5. **Rework comes back** — a rework unit re-decided as `ผ่าน` keeps its rework history, so first-pass yield never counts it as a first-pass pass.

## Backend changes
- Models/schema: `app/models/lots.py` (new) — `Lot(id, workspace_id, project_id, number, work_order, origin, status, opened_by, opened_at, closed_by, closed_at, created)` with `UniqueConstraint(project_id, number)` and `status` `open|closed`; `LotUnit(id, lot_id, workspace_id, project_id, station_id, event_id, image_id, unit_ref, disposition, defect_class, reason, due_at, inspector_id, recorded_at, updated, reworks)` with `UniqueConstraint(lot_id, unit_ref)` and `disposition` `''|ok|ng|rework`. Register the module in `models/__init__.py` (import + name re-export + `DOMAIN_MODULES`); `Base.metadata.create_all` in `bootstrap.py` creates both tables, so there is no `ADD COLUMN` block.
- Routers: `app/routers/lots.py` (new), prefix `/api/ws/{ws}/projects/{project}/lots`, `dependencies=[Depends(require_flag("task_lot_record"))]`; `GET ""?status=&date=&station=` (lot + counts), `POST ""` `{number, work_order, origin}` → 201, `GET "/{id}"` (lot + `counts` + paged units), `POST "/{id}/units"` `{unit_ref, disposition, defect_class?, reason?, due_at?, event_id?, station_id?}` → the unit row, `POST "/{id}/close"`, `GET "/current?station="` → the open lot for a station or `null`. 400 for an unknown disposition, a reject without a class, a rework without a reason and a future-less `due_at`; 409 for a duplicate number, a closed lot and a close with undecided units; 404 for a foreign id.
- Services/jobs: `app/services/lots.py` (new) — `open_lot(db, project, body, user_id)`, `current(db, project, station_id)`, `record(db, lot, body, user_id) -> LotUnit` (last write wins, `reworks` incremented when the previous disposition was `rework`), `counts(lot) -> {ok, ng, rework, undecided, total}`, `close(db, lot, user_id)` raising when `undecided > 0`. When `event_id` is present it also calls `verdicts.record` so the timeline keeps one verdict per event. No job.
- Permissions + workspace isolation: `project.read` to read, `project.review` to record a unit, `project.settings` (manager) to open or close a lot; every lookup filters `workspace_id == c.ws.id and project_id == c.project.id`, so another workspace's lot id is 404 and nothing is written.
- Secrets/safefetch: none — no URL is fetched; `unit_ref` and `number` are validated as text (≤120 chars, no control characters) and `origin` as text ≤120.
- OpenAPI: yes — regenerate `python tools/export_openapi.py` and `npm run gen:api-types`.

## Acceptance criteria
- [ ] A lot is opened, units are recorded against it and it closes; a closed lot refuses new units.
- [ ] `ok`, `ng` and `rework` are the only dispositions, a reject needs a class and a rework needs a reason and a due date.
- [ ] A lot cannot close while a unit has no disposition, and the refusal names the count.
- [ ] Empty, loading and error states above all render — an empty lot returns `units: []` and `counts.total: 0`, and the closed-lot refusal is a 409 with a sentence.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the `/lots` prefix is 404, no table is queried, and the station screen behaves exactly as today.

## Notes for the implementer
One unit has one row keyed by `(lot_id, unit_ref)`; `unit_ref` is the scanned piece id, the code value or the event id, in that order of preference. The lot vocabulary is `ok|ng|rework` and it maps onto the event verdict as `ok → accept`, `ng → reject`, `rework → reject`: never add a third value to `StreamEvent.verdict`. A rework unit decided `ok` later keeps `reworks ≥ 1`, which is what makes first-pass yield differ from yield.
