## User story
As an ML engineer, I want every version to have a name I can quote and to be told before generating one that it
would freeze zero images, so that a run reference is never ambiguous and an empty version never exists.

## UX flow (LabelDesk words)
1. **Version list** — every row shows a name; a version created without one reads "Version 3 · auto" in the same
   style as a named one, and a tooltip says "Named automatically when you did not name it". [empty: no versions →
   "No frozen versions yet — generate one when your labels are ready", one primary] [loading: three row
   skeletons at row height]
2. **Version detail** — the title uses the same fallback; the recipe summary and image count sit under it.
3. **Wizard step 1** — the approved-image count is a live number. At 0 the step shows an inline alert "Nothing to
   freeze — 0 images are approved" with two actions: `Review 16 labels` (opens the review lane) and `Back`. The
   `Next` button stays disabled with the reason attached to it, not only in the alert. [loading: the count shows a
   skeleton, never "0" before the fetch resolves] [error: "Could not count approved images — Retry", Next stays
   disabled]
4. **Wizard step 1, 1–4 images** — a warning, not a block: "4 images is below the 20-image starting point; the
   model may learn little." with `Continue anyway`.
5. **Generate** — the created version opens its detail with the name already applied; the list does not show a
   blank row at any moment.

## Backend changes
- Models/schema: none — `Version.name` already nullable.
- Routers: `POST /api/projects/{id}/versions` keeps accepting an empty name; the **response** now always carries a
  non-empty `display_name` (`name or f"Version {number} · auto"`), and `GET /versions` items gain the same field.
  A zero-image version is refused with `422 {"detail": "no approved images to freeze"}` instead of an empty
  version (server truth, not only a disabled button).
- Services/jobs: `services/versioning.py` — the snapshot builder returns the count it froze; a zero count raises
  before any manifest write.
- Permissions + workspace isolation: unchanged; cross-workspace project id → 404.
- Secrets/safefetch: none.
- OpenAPI: yes — response field + 422; regenerate.

## Frontend changes

## Acceptance criteria
- [ ] No version row or title is ever blank.
- [ ] A zero-image wizard step explains why Next is disabled and offers the review lane.
- [ ] The server refuses a zero-image version even if the UI is bypassed.
- [ ] Empty, loading and error states above all render; the count is never a false zero.
- [ ] Workspace A cannot see or change workspace B's data (404).
- [ ] No flag: the fallback name and the guard ship unconditionally.

## Notes for the implementer
The fallback is a display field only; do not backfill `Version.name` (renaming history stays honest). The
20-image starting point is a named constant next to the existing version validation, not a magic number in the UI.
