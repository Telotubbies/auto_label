## User story
As a workspace admin, I want to create, test and watch a webhook from settings, so that "we can notify CI" is a screen instead of a curl command nobody remembers.

## UX flow (LabelDesk words)
1. **Settings → Webhooks** (workspace, admin only) — a table of endpoints: URL, event chips, state (active/paused), last delivery status and time, with *New webhook* in the header. [empty: "No webhooks yet — add one to notify a pipeline or a chat channel." + *New webhook*] [loading: four row skeletons] [error: "Webhooks could not be loaded" + Retry]
2. **New webhook** — a dialog with a URL field (https only, with the rule inline), an event picker grouped as *Jobs* (`job.done`), *Models* (`model.ready`, `model.version.created`, `model.tagged`, `model.alias.moved`, `model.deprecated`) and *Streams* (`stream.event`), and a *Signing secret* field with a *Generate* button. Saving shows the secret once with a copy button and the sentence "Store it now — it will not be shown again." [error: an empty event set or a non-https URL is refused inline with the reason] [loading: Save reads "Creating…" and the dialog stays open]
3. **Test** — a row action sends a sample payload and reports the status code inline on the row ("200 OK, 312 ms"). [error: a failed test shows the status and the error text, and writes the same delivery row a real event would]
4. **Pause and delete** — *Pause* toggles `active` without losing deliveries; *Delete* asks once and warns that pending deliveries are dropped. [error: deleting a webhook that a workflow references is still allowed, with the count of its delivery rows in the confirm]
5. **Deliveries** — expanding a row lists the last twenty deliveries with event, status, attempts and the next retry time. [empty: "No deliveries yet."] [loading: the expanded panel shows its own skeleton]

## Backend changes
- Models/schema: none — `Webhook(workspace_id, url, secret, events, active)` and `WebhookDelivery` already exist (`apps/backend/app/models/identity.py:162-187`), with create/list/update/delete/test/deliveries routes in `apps/backend/app/routers/webhooks.py`.
- Routers: none — confirm the deliveries route returns `attempts` and `next_attempt`; if a field is missing the card adds it to the response, nothing else.
- Services/jobs: none.
- Permissions + workspace isolation: the existing routes are workspace-scoped and admin-gated; the UI hides the tab from non-admins and a direct call stays a 403.
- Secrets/safefetch: the secret is generated in the browser with `crypto.getRandomValues` (32 bytes, base64url), posted once, and never returned by a GET; the existing `secretbox` encryption and `safefetch` rules stay the only backend paths.
- OpenAPI: no — no new contract in this card.

## Tests to write first
pytest — `none: no backend change` — `apps/backend/app/routers/webhooks.py` already returns every field this screen renders, and T-930 owns the event-name assertions.
node — `apps/frontend/tests/webhooks-ui.test.mjs`:
- `test_event_groups_cover_every_allowed_event` — the union of `EVENT_GROUPS` equals the seven backend names, with no duplicate.
- `test_url_validation_requires_https` — `http://x`, `ftp://x` and an empty string are invalid; `https://x/y` is valid.
- `test_can_test_requires_an_active_webhook` — a paused webhook reports false and the button is disabled.
- `test_delivery_line_names_status_and_attempts` — a failed row with two attempts reads "failed · 2 attempts" and never `undefined`.

## Acceptance criteria
- [ ] An admin can create, pause, test and delete a webhook, and sees the secret exactly once at creation.
- [ ] The event picker offers the three job/model/stream groups with all seven names, and refuses an empty set.
- [ ] Deliveries show event, status, attempts and next retry, with empty, loading and error states of their own.
- [ ] Empty, loading and error states above all render.
- [ ] A non-admin sees no tab, cannot reach the route, and a direct API call is a 403.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
