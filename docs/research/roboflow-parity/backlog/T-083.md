## User story
As a data engineer, I want a `photo_001.json` beside each image to become that image's metadata on every
sync, with a policy that keeps a human's correction, so that capture context arrives without an API call.

## UX flow (LabelDesk words)
1. **Upload** — dropping `photo_001.jpg` + `photo_001.json` imports the image with its metadata; the result
   sheet line reads "18 images carried metadata (24 keys)". [error: a sidecar over 256 KB or invalid JSON
   → that file is listed in the reasons as "sidecar ignored — too large / not valid JSON", the image still
   uploads]
2. **Settings · Project · Metadata sync** — a policy select: "Bucket wins (default) · Human wins ·
   Overwrite · Stop syncing a key after a human edit · Append new keys only", plus "Update metadata when
   the bucket copy is newer" (on). [empty: no datasource yet → the hint points at Connectors]
3. **Dataset · Images** — after a re-sync the value the policy protects is unchanged; a tooltip on the
   value reads "Edited by you — bucket updates are ignored while this policy is on". [loading: the row
   keeps its old value until the sync finishes]
4. **Image detail** — a human edit marks the key as human-owned; with **Stop syncing after a human edit**
   a later bucket change never overwrites it.

## Backend changes
- Models/schema: none beyond T-082's `Image.meta`; human-owned keys live under the reserved key
  `"_human"` (a list of key names) inside the same JSON map.
- Routers: `apps/backend/app/routers/projects.py` — `ProjectPatch` accepts
  `settings.metadata_sync = {policy, update_when_newer}` (validated; no new route); the project payload
  returns it.
- Services/jobs:
  - `apps/backend/app/services/sidecars.py` (new) — `read(name, data) -> dict | None` (only a JSON object,
    ≤ 256 KB, `.json` whose stem matches an image), `flatten(obj) -> dict` (nested keys joined with dots,
    depth ≤ 6, ≤ 50 keys, lists stringified with `[]`), `apply(img, incoming, policy, update_when_newer,
    object_stamp) -> dict` implementing the five policies against `meta["_human"]`.
  - `apps/backend/app/services/importers.py` — `Bundle.sidecars: dict[str, dict]`; `collect` routes a
    `.json` that is neither COCO nor Label Studio to `sidecars[stem] = raw` (one branch).
  - `apps/backend/app/routers/images.py` — `ingest(..., sidecars: dict[str, dict] | None = None)` applies
    `sidecars.apply` right after each image row is created; response gains `"withMetadata": n`.
  - `apps/backend/app/services/connectors.py` — `sync_job` pairs `*.json` objects with images by stem,
    fetches each sidecar (≤ 256 KB), and passes `sidecars` to `ingest`; `update_when_newer` compares the
    object's `last_modified` with `Image.updated`.
- Permissions + workspace isolation: unchanged; sidecars arrive only through the project-scoped upload or
  sync path, and metadata edits stay under T-082's rules.
- Secrets/safefetch: dumps go through the existing `safefetch.fetch_bytes` call for connector objects.
- OpenAPI: yes — `ingest` response key and the project settings shape.

## Acceptance criteria
- [ ] A sidecar beside an image is imported on upload and on connector sync; nested keys flatten with dots.
- [ ] The five policies behave as listed and human-owned keys are recorded once.
- [ ] A sidecar over 256 KB or invalid JSON is reported per file and never blocks the image.
- [ ] `update_when_newer` off means a re-sync never changes metadata.
- [ ] Empty/loading/error states above render (policy hint, per-file reason, human tooltip source).
- [ ] Flag off ⇒ sidecars ignored and today's upload response unchanged.
- [ ] Workspace A cannot see or change workspace B's data (404 for a foreign project; a sidecar only ever
      applies to the image in its own project).

## Notes for the implementer
`_human` is a reserved key: `image_out` must strip it, `clean_key` must refuse a key starting with `_`, and
`metadata:` filters must ignore it. Do not add a second column for human ownership.
