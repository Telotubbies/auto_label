## User story
As an engineer waiting for a GPU, I want to see which pool my job is in, who is ahead of it and when it starts, so that I can raise its priority instead of guessing.

## UX flow (LabelDesk words)
1. **Settings → Queues** (`/:ws/settings/queues`) — one card per pool with its GPU class, online worker count and depth; an offline pool reads `Offline since {time}`. [empty: "Nothing is waiting."] [loading: three skeleton pool cards] [error: "The queue could not be loaded" with a retry]
2. **Ordered rows** — waiting jobs in claim order with their priority chip, running jobs with elapsed time and the workspace they belong to; a `Move to front` action is offered to admins only. [error: the move fails ⇒ the row returns to its place and the sentence is shown on the row]
3. **Interrupt** — an admin may interrupt a running job to free the pool; the row then reads `Returning to the queue` until the worker releases the card.
4. **Start dialog** — Train and Auto-label carry a `Pool` picker and a `Priority` selector with the rule printed: "Interactive runs jump ahead of normal and overnight work; overnight runs wait for an idle pool." [empty: a workspace with one default pool shows it preselected and the picker collapses to a line]
5. **Quota message** — when the cap blocks a submission, the dialog prints the API's sentence with the running job's id and a link to Queues. [loading: the submit button shows pending while the quota is checked]

## Acceptance criteria
- [ ] Every pool shows its GPU class, worker state and depth, and an offline pool names when it was last seen.
- [ ] Waiting jobs are listed in claim order with priority chips; running jobs show elapsed time.
- [ ] An admin can move a queued job to the front or interrupt a running one, and both actions refresh the list.
- [ ] The Train and Auto-label dialogs offer pool and priority, print the rule, and show the cap sentence when blocked.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Empty, loading and error states above all render: an empty queue says so, pool cards skeleton, a failed load retries.
- [ ] Flag off ⇒ no Queues tab and no pool/priority controls in either dialog.

## Notes for the implementer
Render the API order verbatim — the client must not re-sort by priority or the page and the scheduler will disagree the moment the quota changes. `Move to front` moves within the pool only; it never crosses a pool boundary, because the worker on that pool cannot run another pool's job.
