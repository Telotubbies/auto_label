## User story
As a labeler, I want to type a class plus a short description and triage what comes back, so that a brand-new object type is one dialog away.

## UX flow (LabelDesk words)
1. **Editor → floating assist toolbar → "Find with a model"** — the dialog opens on the class step. Model row: a compact grouped list (Your models / Model zoo / Vision-language) with availability and its reason inline; the tab that opens first follows the F3.54 rule — a workspace with no trained model opens on the zoo, and a workspace with nothing runnable opens on Your models with "Nothing of yours is ready yet". [loading: registry skeleton] [error: registry retry inside the row]
2. **Class rows** — reuse T-130's rows: tick the classes to look for, edit each description (default = class name), set a threshold where the model reports confidence. **+ Add class** creates a project class inline and selects it. [empty: no classes → "Add a class first" with the same inline field]
3. **Label with AI** — one press, one metered call, button reads "Looking for 3 classes…" and can be cancelled (the client aborts; the server call still completes and is billed — the dialog says "Cancel stops waiting, not the call"). [error: 400/402/503 each render their own sentence; 402 links to Usage]
4. **Triage** — on success the dialog closes and the proposal bar (T-151) takes over with the count; the canvas shows dashed shapes. A zero result keeps the dialog open with "Nothing found on this image — try a different description or a lower threshold".
5. **Existing annotations are untouched** — the dialog states it once: "Suggestions are added only when you keep them. Nothing on this image changes." and the confirm cannot be reached without an explicit Keep.
6. **Hidden surface** — when the workspace cannot run any detection or segmentation model, the toolbar entry stays visible but disabled with the reason ("No model can detect objects on this worker"); with `task_prompt_detect` off the entry is absent.

## Acceptance criteria
- [ ] The dialog runs one class-prompt request, hands the result to the proposal bar and closes; a zero result keeps it open with the retry copy.
- [ ] Model availability and its reason are visible in the dialog; an unrunnable workspace shows a disabled toolbar entry with the reason.
- [ ] Adding a class inline selects it without leaving the editor, and the threshold/description reach the request.
- [ ] Nothing on the image changes until the user keeps a proposal.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no toolbar entry and no dialog; every existing tool is unchanged.
- [ ] Keyboard-only path: Tab to the toolbar → Enter → Tab model list → Enter → Tab classes → Enter on Label with AI → `Enter` keeps the first proposal.
