## User story
As a shift supervisor, I want the project rail to read top to bottom like the work does, so that "Dataset, Versions, Insights, Model insights" stop being four siblings I have to decode.

## UX flow (LabelDesk words)
1. **Any project screen** — the rail opens with the project switcher card (thumbnail, name, `Object detection · 24 approved`), then the three purpose groups `Data`, `Models`, `Deploy`. Each group header is sentence case at 12 px with a chevron; its rows carry the stage number, the label, a count pill, a state dot and one line of text. `Project settings` closes the rail below a rule, outside the groups.
2. **The current stage** — its row is the only tinted pill, and it carries a 1 px primary outline as well as the fill, so the outline does not rely on colour alone in a screenshot or a high-contrast theme. The stage's own page header owns the primary button. No `Train Model` anywhere in the chrome.
3. **A collapsed group** — the header keeps a summary of what is inside ("Data · 3 need you") and the rows are hidden, not unmounted from the DOM: they stay `hidden` with `aria-expanded="false"` on the header button so a screen reader and the nav test both still see the destination. A group that holds the active row cannot be collapsed shut — it reopens itself so the current page is never invisible.
4. **A stage the role cannot act on** — dimmed row, lock icon, `aria-label` ending "locked, request access", and a tooltip with the same sentence. Clicking it opens the request-access sheet, it does not redirect silently. [error: a role with no project permission at all gets the existing "You do not have access" panel, not an empty rail]
5. **A count changes while I work** — the stage dot pulses once (opacity only) and the count updates; under `prefers-reduced-motion` neither animates.
6. **Below 1024 px** — the panel collapses to the existing compact strip, which now renders the same groups as a two-level list with numbers and counts.

## Acceptance criteria
- [ ] Three collapsible groups render with the five numbered stages and the unnumbered destinations inside them; `Project settings` sits below the rule.
- [ ] The active row is the only tinted row, it also carries the 1 px primary outline, and the page header owns the primary button.
- [ ] A group collapses to its header with a summary count, its rows stay mounted, and the group holding the current route cannot be collapsed shut.
- [ ] A locked stage is dimmed, focusable, announced as locked and opens request-access — never a silent redirect.
- [ ] Below 1024 px the compact strip renders the same groups, numbers and counts.
- [ ] Empty, loading and error states above all render: a project with no data shows `—` counts and `not started`; while facts load, each row keeps its height with a skeleton count; a failed facts call shows the rail with `Retry` and no fake zeros.
- [ ] Workspace A cannot see workspace B's data: the rail reads only the current project's payload; a foreign slug renders "Project not found" instead of a rail.
- [ ] Flag off ⇒ the v2 grouped panel and its top-bar buttons render unchanged.

## Notes for the implementer
The stage dot is a `<span aria-hidden>` inside the row's accessible name — not a `<button>` — because it is not clickable. If a future count needs its own target, it gets a real button with its own label; the 44 px hit area comes from a `::before` inset so the visual height stays 32 px.
