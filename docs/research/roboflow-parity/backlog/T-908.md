## User story
As a reviewer triaging last week's runs, I want to type a filter and see chips of what I asked for, so I can tell
an empty result from a typo without leaving the page.

## UX flow (LabelDesk words)
1. **Models** (`/:ws/:p/models`) — above the run list, a filter field with a *Filters* hint button that opens a
   one-line cheat sheet (`status:ready`, `task:detect`, `variant:yolo26n`, `version:2`, `tag:nightly`,
   `metric:map50>=0.6`, `sort:-created`, `limit:20`). Enter applies; the URL becomes `?q=…` so a refresh and a
   shared link keep it. [empty: the unfiltered list with `Filter runs…` in the field, no chips]
   [loading: the rows dim and a thin progress line runs under the field; the field keeps focus]
   [error: an invalid clause underlines the token in the field, prints the server's message underneath, and the
   list keeps the previous results rather than emptying]
2. **After applying** — one chip per clause with its own `×`, a `N of M runs` count, and *Clear all*.
3. **No match** — the list area renders `No runs match this filter.` with *Clear filters*; a project with no runs
   at all keeps its own `No models yet.` empty state.
4. **Recent filters** — the last three applied filters as chips under the field, stored per user per project in
   `localStorage`; *Clear all* does not delete them.

## Tests to write first
pytest — none: no backend surface.
node — `apps/frontend/tests/run-query.test.mjs`:
- `test_every_clause_becomes_one_chip` — `tag:nightly metric:map50>=0.6 sort:-created` → three chips with field,
  op and value split correctly.
- `test_an_unknown_field_is_flagged_before_the_request` — `metricx:1` → one chip with `error` set and
  `applyable()` false, so no request is sent.
- `test_chips_round_trip_through_text` — `textFrom(chipsFrom(s)) === s` for a normalised input, and a chip's `×`
  removes exactly its clause.
- `test_recent_filters_keep_three_and_survive_a_broken_store` — four writes → three stored; a `localStorage` that
  throws returns `[]` instead of crashing the page.
- `test_the_url_carries_the_filter` — a non-empty filter encodes as `?q=…` and an empty one removes the parameter.

## Acceptance criteria
- [ ] Typing a filter and pressing Enter narrows the list, and the URL carries it.
- [ ] An invalid clause shows the server's message, keeps the previous rows and sends no second request.
- [ ] `No runs match this filter.` and `No models yet.` are distinct states with distinct actions.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: `5-F5.5`/`5-F5.36` → T-272 (search results on screen for *near-duplicate candidates*, a different list),
`5-F5.1` → T-263 (the run-list container this bar sits above).
Chips are derived from the text on every keystroke — do not keep a second source of truth, or `?q=` and the chips
will disagree after a back-button navigation. `localStorage` is per browser by design; a workspace-shared view is
T-909's job, not this card's.
