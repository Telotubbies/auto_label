## User story
As a builder, I want to test a pipeline that writes annotations without writing them, and to mute one node to isolate a failure, so that neither a test nor a bisect changes the project's data.

## UX flow (LabelDesk words)
1. **Run panel header → "Writes" switch** — on by default, one switch for all three media sources. Turning it off labels the button "Run without writing" and the result badge reads "Nothing was written." The saved workflow is unchanged, and the next run with the switch back on writes as usual.
2. **A node toggle** — each node's header carries a small switch, `aria-label="Disable Crop"`. A disabled node dims, keeps its fields and its edges, and shows the chip "Skipped". Its consumers show a warning: "Labels needs `image`; Crop is off."
3. **Save with a disabled node** — the definition stores `disabled: true` (T-320), so the mute survives a reload and applies to the invoke endpoint and a batch run too, not only to this browser.
4. **A pipeline whose sink is disabled** — `[error]` saving is refused: "The sink cannot be disabled." A pipeline whose only model is disabled is refused on run with "No model runs in this workflow." [empty: every node enabled → the "Skipped" chip appears nowhere] [loading: none]

## Backend changes
- Models/schema: none beyond T-320's `graph` (which carries `disabled`).
- Routers: `apps/backend/app/routers/workflows.py` — `POST /{workflow_id}/run` accepts `write_back: false` and passes it to the runner, which skips the `annotations` sink and still returns the detections. This is the API half of the switch, so the endpoint and a batch job obey it too.
- Services/jobs: `apps/backend/app/services/workflow_runner.py` — `run(..., write_back: bool = True)`; the `annotations` sink branch returns `annotations_added: 0` with `skipped: ["sink"]` when `write_back` is false. A disabled node is already skipped by T-321's plan.
- Permissions + workspace isolation: a `write_back: false` call needs only `project.infer`; the annotate check stays for a call that writes.
- Secrets/safefetch: none.
- OpenAPI: yes — one optional body field.

## Acceptance criteria
- [ ] The "Writes" switch suppresses every dataset write for one run, and the result says nothing was written.
- [ ] A disabled node is dimmed, keeps its config, survives save and is skipped by the editor, the endpoint and a batch run alike.
- [ ] Disabling the sink is refused, and a run with no enabled model is refused before any billable call.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: both switches live inside `task_31`, so the flag hides them with the editor.

## Notes for the implementer
Two different things: the write switch is a per-run argument (`write_back`), the node switch is part of the saved definition (`disabled`). Do not persist the write switch — it exists to protect a test, and a remembered "off" is how someone ships a pipeline that never writes.
