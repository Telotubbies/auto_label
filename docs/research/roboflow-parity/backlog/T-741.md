## User story
As an admin with a live session, I want a password or code prompt before a key is revoked, a project is purged or the workspace's region changes, so that an unlocked browser left on my desk cannot destroy anything in one click.

## UX flow (LabelDesk words)
1. **Settings → API Keys → `Revoke`** (`/:ws/settings/api`) — the row's button opens the step-up sheet instead of revoking. [loading: the button keeps its spinner while the ticket is minted] [error: "That password didn't work. Try again." under the field, focus returned to it]
2. **The sheet** — title `"Confirm it's you"` / `"ยืนยันว่าเป็นคุณ"`, one line naming the act ("Revoking the key `warehouse-cam` cannot be undone."), a password field, and a six-digit field only when the account has a second factor enrolled. `Enter` submits; `Esc` closes and nothing changes.
3. **A wrong code** — `"That code didn't work — check your authenticator and try again."` and the act stays undone.
4. **Success** — the ticket lives 5 minutes, the original request repeats with `X-Step-Up`, and the toast is the same one that ships today ("Key revoked").
5. **No factor enrolled and the workspace requires one** — the sheet reads `"This action needs a second factor, and none is enrolled."` / `"การทำรายการนี้ต้องใช้ปัจจัยที่สอง แต่ยังไม่ได้ลงทะเบียน"` with one link to `/:ws/settings/security`.
6. **An expired ticket** — a 403 `step_up_required` reopens the sheet with `"Your confirmation expired. Confirm again to continue."`; the first request is never retried silently.

## Backend changes
- Models/schema: none — a ticket is a short-lived JWT, exactly like the shipped MFA ticket, so no column and no table.
- Routers: `POST /api/auth/step-up` `{password, code?}` → `{ticket, expires}`; 401 `"that password didn't work"` for a bad password, 403 `{"code": "mfa_required"}` when a factor is enrolled and `code` is missing, 401 for a bad code, `limit(f"stepup:{u.id}", 5, 900)` on the route. The dependency `Depends(step_up)` is added to `DELETE /api/ws/{ws}/keys/{kid}`, `DELETE /api/ws/{ws}/trash/{pid}`, `PATCH /api/ws/{ws}/members/{uid}` and `PATCH /api/ws/{ws}/privacy`.
- Services/jobs: `app/services/stepup.py` (new) — `TTL = 300`, `issue(user_id) -> str`, `verify(ticket) -> str | None` (scope `stepup`, checked against the same `SECRET`), `consume(ticket, user_id, db) -> None` raising 403 `step_up_required` when absent, expired or minted for another user. The password branch reuses `verify_password`; the code branch reuses `routers/auth.py::_second_factor_ok` so a code cannot be spent twice.
- Permissions + workspace isolation: the ticket names a user, never a workspace; the route it unlocks still resolves the workspace through `ws_ctx`, so a ticket from workspace A cannot act in workspace B (404 there).
- Secrets/safefetch: `services/secretbox.py` and `security.SECRET` unchanged; the ticket is signed with `SECRET` and carries no secret of its own.
- OpenAPI: yes — one route, one header parameter (`X-Step-Up`) on four existing routes.

## Acceptance criteria
- [ ] Four destructive routes refuse without a step-up ticket and accept one minted in the last five minutes by the same user.
- [ ] The sheet asks for the second factor exactly when the account has one enrolled, and links to enrolment when a policy needs a factor that is missing.
- [ ] A wrong password or code leaves the act undone and keeps focus in the field.
- [ ] Empty, loading and error states above all render: the minting spinner, the field-level error and the "expired confirmation" reopen.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — a ticket does not widen the acting workspace.
- [ ] Flag off ⇒ no sheet, no gate on the four routes, and every button behaves as it does today.

## Notes for the implementer
Five minutes, one user, no replay to a different verb: the ticket is a claim, not a session, so it must not be accepted by `verify_access`. Reuse `_second_factor_ok` rather than reading `totp` again — a spent code must not unlock a second delete. Do not add a step-up prompt to label saves or uploads: this is the "destructive only" list, and a prompt on every action trains people to type their password without reading it.
