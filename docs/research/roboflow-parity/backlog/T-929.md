## User story
As a workspace admin, I want to keep one client's model visible to managers only, so that labelers and outside reviewers cannot download its weights or read its held-out evaluation while still seeing that it exists.

## UX flow (LabelDesk words)
1. **Model header → Access** (managers only) — a small panel with one select: *Everyone on the project* (default), *Managers*, *Admins*, and a sentence per choice ("Managers can download weights and read the evaluation; labelers see the name and status only."). [empty: a model that never changed its access says "This model follows the project's access — no exception set."] [loading: the select is disabled until the model payload resolves] [error: "Access not changed — retry" beside the select, the stored value untouched]
2. **Restricted row for a labeler** — the model is still listed with its name, dataset version and status; the score, weights button and evaluation tab are dimmed with a lock and the tooltip "Your role cannot see this model's results." [empty: no restricted model in the project ⇒ no lock renders anywhere]
3. **Direct call** — a labeler opening `GET models/{id}` or the weights URL gets **403** "Your role cannot see this model's results"; a manager of the same project gets the full payload.
4. **Export and TensorRT** — the export actions are absent for a role below the level, and the server refuses `POST …/export` with the same 403. [error: an export queued before the model was restricted keeps running: it is already an artefact of an authorised action, and the delivery link is not re-issued]
5. **Foreign workspace** — another workspace's model id stays a **404** everywhere, including the new gate.

## Backend changes
- Models/schema: append `"restricted_to": "VARCHAR(16) DEFAULT ''"` to `TRAINED_MODELS` in `apps/backend/app/schema/training.py`; add `restricted_to: Mapped[str] = mapped_column(String(16), default="")` to `TrainedModel`. Values: `''` (project), `managers`, `admins`.
- Routers: `PUT {P}/models/{mid}/access` body `{level: "" | "managers" | "admins"}` → `{id, restrictedTo}`; **422** on any other value, **403** for a caller below `admin` when the level is `admins`. `visible_model` and `get_model` consult the level; `POST …/export` and `POST …/predict` on the model id check it before doing work. `model_out` gains `restrictedTo`.
- Services/jobs: `apps/backend/app/services/model_access.py` (new) — `LEVELS = ("", "managers", "admins")`, `set_level(model, level) -> str`, `allows(model, level_of_caller) -> bool`, `mask(c, model) -> bool` where `c.role` is the project role the context already resolves.
- Permissions + workspace isolation: the level is checked after `_model`, so a foreign id is still a 404; inside the project an insufficient role is a 403 that names the model but never the weights path.
- Secrets/safefetch: none — the weights URL is only signed when `mask` is false, so a restricted row has no URL to leak.
- OpenAPI: yes — one route, one payload field; regenerate both files.

## Acceptance criteria
- [ ] A model can be restricted to managers or admins, and the stored level is visible only to managers.
- [ ] A masked row keeps its name and status with no weights URL, no evaluation and a lock that explains why.
- [ ] Detail, export and predict refuse a role below the level with a 403 naming the model, while a foreign workspace id stays a 404.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
