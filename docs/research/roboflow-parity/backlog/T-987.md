## User story
As a web developer, I want to call LabelDesk from JavaScript without hand-writing fetch calls, so that
a small tool or a customer portal can read its project list and run hosted inference.

## UX flow (LabelDesk words)
1. **Settings → Integrations → JavaScript** — `npm i @labeldesk/client`, then two snippets: server-side
   with a workspace key, browser-side with a publishable key calling `predict`. [empty: no publishable
   key — the browser tab is greyed with "browser calls need a publishable key" and a link] [loading:
   n/a] [error: a workspace key used in a browser — the API refuses with "publishable keys only" and the
   snippet says why, inline].
2. **Call site** — `const api = new LabelDesk({ baseUrl, key }); await api.projects.list()` returns the
   same shapes as `/api/v1`, with `error.code` on failures.
3. **Build** — `npm run gen` regenerates the client types from `apps/backend/openapi.json`; a schema
   change without regenerating turns CI red.

## Backend changes
- Models/schema: none.
- Routers: none.
- Services/jobs: `tools/export_client_js.py` (new) — reads `apps/backend/openapi.json` and writes
  `packages/sdk-js/src/generated.ts` (paths, methods, param and response types). No new runtime.
- Permissions + workspace isolation: unchanged — the client sends whatever key it is given; the server
  enforces workspace and scope, and publishable keys stay infer-only (`apikeys.py:1-6`).
- Secrets/safefetch: none — the browser build must never read `LABELDESK_API_KEY`; the constructor takes
  the key explicitly.
- OpenAPI: no change (consumes the existing file).

## Frontend changes
- Route: none.
- Nav entry: none.
- Components: none in the app shell.
- API client: `packages/sdk-js/src/client.ts` (new, hand-written, ~80 lines over generated types) —
  `new LabelDesk({baseUrl, key})`, `projects.list()`, `images.list(project, {cursor})`,
  `models.list()`, `predict(modelId, file, {confidence})`, `pipeline.status(runId)`; throws
  `LabelDeskError {status, code, detail}`.
- Feature flag: `task_987`; off ⇒ the Integrations tab and the generated package are absent from the
  build.

- [ ] A failed call throws an error carrying `status` and `code`.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
