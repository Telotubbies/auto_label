## User story
As a team lead, I want to pin the images and write the rules in one screen, so that the test exists before the change I am afraid of.

## UX flow (LabelDesk words)
1. **Models → Regression** (`?tab=evals`) — a table of suites: name, workflow, source, checks, last result with delta, and a row action *Run*. [empty: "No regression suites yet — pin a few images with known answers and add a rule." + *Create suite*] [loading: four rows] [error: "Suites could not be loaded" + Retry]
2. **Create suite dialog** — one column, four labelled sections: *What runs* (workflow select, with a note naming the model blocks it calls), *What it runs on* (a test split of a version, or up to 200 pinned images chosen from the dataset's existing selection), *What must hold* (the check list), *When it may ship* (a minimum pass rate, optional).
3. **Check rows** — each row: a code select, then its params as sentence slots ("count of [class ▾] is at least [N]"), a live preview of the sentence, and a remove button; *Add check* appends. An invalid row is disabled with the reason from the API's grammar. [empty: no checks ⇒ Save is disabled with "Add at least one check."]
4. **Saving and running** — *Save suite* closes with the row at "never run"; *Run* on the row asks for confirmation ("100 images · about 0.02 credit each") and then shows progress with the image count. [error: 402 shows the plan and the remedy in place of the confirmation]
5. **Pinned images** — choosing images uses the dataset's `selection` mechanism (a stored lasso) or a list of ids; the dialog states how many are pinned and refuses fewer than 5 with the count.

## Tests to write first
pytest — none: no backend surface in this card (the route and its tests belong to the card named under Depends on).
node — `apps/frontend/tests/eval-checks.test.mjs`:
- `test_every_check_code_has_a_sentence` — `CHECK_FORMS` covers `count_gte, count_eq, class_present, value_range, text_contains, latency_lte` and each `checkSentence` returns a non-empty sentence with the params filled.
- `test_a_missing_param_blocks_the_row` — `suiteErrors({checks:[{code:'count_gte', params:{}}]})` names the missing class and number.
- `test_no_checks_blocks_saving` — `suiteErrors({checks:[]})` says "Add at least one check."
- `test_pinned_images_below_five_is_refused` — 4 pinned → the count is in the message; 5 → no error.
- `test_run_estimate_multiplies_images_by_the_per_image_cost` — `runEstimate(100)` names 100 images and a credit figure.
- `test_delta_only_when_a_baseline_exists` — `lastResultLabel(run, null)` has no delta; with a baseline it has one with a sign.

## Acceptance criteria
- [ ] A suite can be created, edited (forking after a run) and run from one tab.
- [ ] The check builder only allows the six codes and shows the sentence that will be enforced.
- [ ] The run confirmation shows the image count and cost, and a 402 lands in the dialog rather than a toast.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no tab and no requests.

## Notes for the implementer
The check builder is a sentence with selects, not a JSON editor. Pinned images reuse the existing dataset `selection` URL mechanism; do not add an image picker of your own.
