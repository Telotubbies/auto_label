## User story
As a labeler starting a shift, I want one click from the board into a drawable image, so that finding my batch, pressing Annotate and waiting for a load stops being three steps.

## UX flow (LabelDesk words)
1. **`/p/:project/annotate`** — header primary is role-aware: `Start labelling` for a labeler, `Review 16` for a reviewer. Three lanes as lists of batch rows: **To label**, **In review**, **Approved**. Each row: batch name, image count, assignee, age, progress bar, and one primary that opens the **first image of that batch** in the editor. [empty: "No batches yet — upload images to create the first one" with `Upload images`]
2. **To label** — a row reads `Shift A · 40 images · Somchai · 2 h ago · 0/40` with `Start labelling`; the click opens `/p/:project/annotate/<firstImageId>?batch=…&status=annotating`.
3. **In review, 16 images** — the row's action is `Review 16`; the reviewer lands on the first image in review mode. `Approve all` is not a green button beside it — bulk approval lives in the selection bar and goes through T-129's confirm sheet that names the count and the classes. [error: a failed move keeps the row in place, shows an inline alert with the reason and offers `Retry`]
4. **Approved** — read-only rows with `View`; no bulk action that would un-approve from this list.
5. **Right rail** — `Your throughput today` (`12 approved · 3.4 / h`) and a `Shortcuts` link; the board itself is solid surface, no glass.
6. **375 px** — one lane at a time via a segmented control, rows full width, same actions. [loading: five row skeletons per lane]
