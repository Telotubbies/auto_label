## User story
As a labeler or an ML engineer, I want to predict what the upload will do before it runs — duplicates,
refusals, the split and the batch name — and to bring in a URL or a video's frames the same way, so that
the first upload is not a support ticket.

## UX flow (LabelDesk words)
1. **Upload** (`/:ws/p/:project/upload`) — the drop zone accepts browse, folder and drag; the pre-flight
   line counts accepted, duplicates and refused files before the button is pressed.
2. **Files chosen** — three small images show one duplicate and one refusal with the reason in place.
   [error: a refused format names the format and the accepted list].
3. **Batch and split** — the batch name defaults to the date and shift; the split chips are Auto
   80/10/10 or Manual later.
4. **Save and Continue** — the button is busy; the result sheet reads "Added 2 · duplicates 1 · failed 0"
   with per-file reasons.
5. **URL import** — the URL row validates scheme and host, then shows the same result sheet.
   [error: a private address is refused with a remedy sentence, never silently skipped].
6. **Video frames** — the frame-extraction dialog shows trim, fps and a hand-picked selection before the
   job; the job card counts frames as they arrive.
7. **View Dataset** — the new images are visible with the reviewer filter cleared; counts agree with the
   result sheet.

## Acceptance criteria
- [ ] One duplicate is counted before upload and the result sheet names it; nothing is silently skipped.
- [ ] A refused file names the format and the accepted list; the other files still upload.
- [ ] Steps ≤ 9 and time ≤ 180 s for the file leg; numbers recorded.
- [ ] The URL refusal is inline and the public URL leg shows the same result sheet shape.
- [ ] The frame dialog states what it will produce before it runs; cancelling leaves nothing behind.
- [ ] No console error; at 375 the drop zone and the result sheet stack without horizontal scroll.
- [ ] Empty, loading and error states: a fresh project's upload page, a busy submit, a refused file.
- [ ] Workspace isolation: an upload into workspace A is absent from workspace B's dataset.
- [ ] Flag off ⇒ the frame leg is skipped with a named reason and the file and URL legs still pass.

## Notes for the implementer
Do not upload a real video or fetch a real URL in CI. The URL POST and the frame job are fulfilled through
`stubApi`; the pre-flight, refusal, duplicate and result-sheet UI is real. `one.jpg` is shared with
`core-loop.spec.ts`; only the duplicate copy is this card's file.
