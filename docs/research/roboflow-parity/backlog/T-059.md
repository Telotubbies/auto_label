## User story
As a maintainer, I want one theme reader and one colour normaliser for every chart, so that a token change
does not have to be made twice and the two copies cannot drift into different colours on the same screen.

## UX flow (LabelDesk words)
None: no visible change intended. Every chart keeps its colours, its skeleton height and its empty state.
The only risk this card carries is a colour difference, so the acceptance is a visual diff, not a unit test
alone.

## Notes for the implementer
`cssColor` does its own oklch→sRGB maths; `toRgb` asks a 1×1 canvas. The canvas is the one the rest of the
app already uses, so `toRgb` wins — but only if the computed strings match for the eight tokens. Take a
screenshot of Overview in dark mode before and after; if any token shifts, stop and report rather than
"adjusting" a colour by eye. Do not merge the two `ChartCard`s in this card.
