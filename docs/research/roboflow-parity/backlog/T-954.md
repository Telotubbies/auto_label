## User story
As a support engineer, I want the steps of one inference call kept as a record, so that "this prediction was
slow" becomes "the preprocess span was 1.8 s" without reading logs.

## UX flow (LabelDesk words)
1. **Any prediction path** — a playground call, a hosted API predict or a batch-inference item writes one
   trace with spans for *decode*, *preprocess*, *inference*, *postprocess*, each with a start, an end and its
   own error if it failed. Nothing is shown to the user yet (T-955 draws it).
2. **Where a trace is reachable** — the trace list (T-955) and the trace id returned in an error body; this
   card stores the ids that make those links possible, and renders nothing. [empty: a report recorded before
   this card has no trace id, and the Traces screen simply lists what exists]
3. **A failed call** — the trace state is *error* and the failing span carries the exception class; the API
   returns the trace id in the error body so a support ticket can name it. [error: writing a trace must never
   fail the prediction — a trace write error is logged and the prediction still returns]
4. **Retention** — traces follow the project's `retention_days`; the read route refuses an expired id with
   404 and the panel says "this trace was removed by retention".

## Backend changes
- Models/schema: new table in `apps/backend/app/models/evaluation.py` — `Trace(id, workspace_id, project_id,
  kind, model_id NULL, image_id NULL, run_ref NULL, user_id NULL, session_id NULL, name, state, started,
  ended, duration_ms, tokens_in NULL, tokens_out NULL, tags JSON)`, index on `(project_id, started DESC)`;
  `Span(id, trace_id FK ondelete=CASCADE, parent_id NULL, name, ordinal, started, ended, duration_ms, state,
  attributes JSON, error TEXT NULL)`, index `(trace_id, ordinal)`.
- Routers: `GET {P}/traces/{trace_id}` → the trace and its spans in ordinal order (404 for a foreign or
  expired id, and the detail says which). No public write route: instrumentation calls the service directly.
- Services/jobs: `apps/backend/app/services/tracing.py` (new) — `start_trace(kind, **refs)` returning a
  context manager, `span(name, **attrs)` nested inside it, `record(...)` that writes trace and spans in one
  `db.commit()` after the request, and `sweep(project)` used by the retention pass to delete expired traces.
  Instrumentation points: `apps/backend/app/routers/playground.py:38` (`_run`), the batch worker, and the
  hosted predict at `apps/backend/app/routers/training.py:662` — each wraps its existing work, changing no
  behaviour on the success path.
- Permissions + workspace isolation: read `project.review`; the trace's `project_id` is checked, a mismatch is
  404. Traces carry no signed URLs.
- Secrets/safefetch: none. Dependency: none added (no `mlflow-skinny`), so no
  `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] Each playground, batch and hosted prediction writes exactly one trace whose spans cover decode,
      preprocess, inference and postprocess.
- [ ] A failed span marks the trace error and never changes the prediction's own response.
- [ ] A trace from another project or past retention is a 404.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
