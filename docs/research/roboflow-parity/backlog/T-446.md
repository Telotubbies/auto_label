## User story
As a procurement lead, I want one page that states our security posture, contracting items and region options, so that a
security questionnaire has a single source.

## UX flow (LabelDesk words)
1. **Settings → `Trust and compliance`** (`/:ws/settings/trust`, and linked from the DPA page) — sections:
   **Where your data is processed** (the workspace's declared region, with a link to Privacy), **Contracting**
   (`Data Processing Agreement` — download the filled DPA; `MSA and DPA` — "available on request", a mailto; `Security
   review` — "we answer questionnaires on request"), **Regional and sector options** (`United States`, `Singapore`,
   `Thailand` — the three values `DATA_REGIONS` actually supports, each with the sentence that it is a declaration),
   **Service level** (`Uptime target: TBD — set in your contract.`), **Health data** (`A BAA is not offered today;
   contact us before processing health data.`).
2. **`Go to DPA`** opens the existing generated agreement (`/legal/dpa`).
3. **`[empty]`** a workspace with no contract: the contracting section reads `No contract on file. Ask us for an MSA and
   DPA.` and the rest still renders.
4. **`[error]`** the DPA link failing shows `The agreement could not be generated. Try again or email
   privacy@labeldesk.dev.`
5. **Honesty rule** — no claim is made that the product does not implement: no "HIPAA compliant", no "99.99% SLA", no
   "ISO 27001". Anything unset reads `TBD` or `on request`.

## Backend changes
- Models/schema: none.
- Routers: `GET /api/ws/{ws}/trust` (`routers/privacy.py`) → `{region, region_label, regions, dpa_version,
  uptime_target: null, baa: false, subprocessors: [...]}`; the sub-processor list is static config so it cannot drift
  from the DPA text.
- Services/jobs: none.
- Permissions + workspace isolation: `workspace.read`; the region is the workspace's own declaration.
- Secrets/safefetch: none.
- OpenAPI: yes.
