## User story
As an engineer fitting a model onto a Jetson Nano, I want to name the target device and its budget before I spend a training run, so that I learn the model will not fit from the form instead of after paying for the run.

## UX flow (LabelDesk words)
1. **Train → `อุปกรณ์เป้าหมาย` as the first field** (`/:ws/:project/train`) — a `Select` of the shipped profiles plus `กำหนดเอง`; picking one prints its RAM, flash and latency budget under the field. [empty: `ยังไม่ได้เลือกอุปกรณ์เป้าหมาย`] [loading: the profile list is part of the page query and the select is disabled until it lands]
2. **`กำหนดเอง`** — three inputs (RAM MB, flash MB, latency ms) with the same bounds the API enforces; a value outside them keeps the run disabled. [error: `เพดานต้องอยู่ระหว่าง 1 และ 65536`] [error: `ไม่รู้จักอุปกรณ์นี้ — เลือกจากรายการ`]
3. **Start training** — the target and the budget are stored on the run and on the resulting model, so the leaderboard can later say "this model was trained for an Orin Nano, 8 GB".
4. **No target** — the run is still allowed and behaves exactly as today, reading `ไม่ได้ระบุอุปกรณ์เป้าหมาย` on the model; the card never blocks a run that used to work.

## Backend changes
- Models/schema: `TrainedModel` gains `target VARCHAR(64) DEFAULT ''` and `budget JSON` (null) as one `ADD COLUMN` block in `app/schema/training.py` `TRAINED_MODELS`; existing rows read `''` (no backfill needed, the value means "unknown").
- Routers: `app/routers/training.py::TrainIn` gains `target: str | None` and `budget: {ram_mb, flash_mb, latency_ms} | None`; `POST /train` validates them and copies both into `Job.params["options"]`; `app/routers/target.py` (new) `GET /deploy-targets` → `[{id, label, ram_mb, flash_mb, latency_ms, trt, cuda}]`. 422 for an unknown target or a budget outside 1–65536, 404 for the route while the flag is off.
- Services/jobs: `app/services/device_profile.py` (new) — `PROFILES` (Orin Nano 8 GB, Orin NX 16 GB, Xavier NX, x86 CPU + OpenVINO), `get_target(name)`, `normalise_budget(target, budget)`; `app/handlers/training.py::run_train` writes `model.target` and `model.budget` when it creates the model row, so a queued run that fails later still records what it was for.
- Permissions + workspace isolation: `POST /train` keeps `c.need("admin")`; `GET /deploy-targets` needs `project.train`; the target is a constant list, so nothing crosses a workspace, and the model columns are read through the existing project filter.
- Secrets/safefetch: none.
- OpenAPI: yes — one new route and two `TrainIn` fields.

## Tests to write first
pytest — `apps/backend/tests/test_deploy_target.py`:
- `test_a_named_target_is_stored_on_the_run_and_the_model` — `POST /train {target: "jetson-orin-nano-8gb"}` → the model row's `target` equals it and `budget` carries the profile's three numbers.
- `test_a_manual_budget_overrides_the_profile` — `budget: {ram_mb: 512, flash_mb: 4096, latency_ms: 40}` is stored verbatim.
- `test_an_unknown_target_is_422` — `target: "jetson-98"` is 422 and no job is queued.

- `test_targets_are_hidden_while_the_flag_is_off` — `GET /deploy-targets` is 404 with the flag off and `POST /train` with a `target` is 422 (unknown field cannot be stored while the surface is dark).

- `test_target_label_prints_ram_flash_and_latency` — `targetLabel({ram_mb: 8192, flash_mb: 65536, latency_ms: 33})` reads `8 GB · 64 GB · ≤ 33 ms`.

- `test_target_sentence_names_the_model_target_or_says_unknown` — `targetSentence({target: ''})` is `ไม่ได้ระบุอุปกรณ์เป้าหมาย`.
- `test_an_unknown_profile_is_named_in_the_error` — the select's fallback label is `ไม่รู้จักอุปกรณ์นี้ — เลือกจากรายการ`.

## Acceptance criteria
- [ ] The Train form asks for a deployment target first and prints the profile's RAM, flash and latency limits.
- [ ] A named target or a manual budget is stored on the run and on the resulting model, and an unknown target is refused with 422.
- [ ] A run with no target behaves exactly as today and its model says the target is unknown.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no target field, no target route, and Train is today's.

## Notes for the implementer
Four profiles, not a free-form device form: the numbers must be defensible, and a buyer comparing with a hardware-aware tuner will read them. Keep the target optional — a blocked run is worse than an untargeted one — but make the model page say `ไม่ได้ระบุอุปกรณ์เป้าหมาย` so the omission is visible. Copy: `train.target`=`อุปกรณ์เป้าหมาย`, `train.target.hint`=`โมเดลจะถูกวัดกับเพดานของอุปกรณ์นี้`, `train.target.empty`=`ยังไม่ได้เลือกอุปกรณ์เป้าหมาย`, `train.target.unknown`=`ไม่รู้จักอุปกรณ์นี้ — เลือกจากรายการ`, `train.target.manual`=`กำหนดเอง`, `train.budget`=`เพดานหน่วยความจำ`, `train.budget.range`=`เพดานต้องอยู่ระหว่าง 1 และ 65536`, `train.target.unset`=`ไม่ได้ระบุอุปกรณ์เป้าหมาย`.
