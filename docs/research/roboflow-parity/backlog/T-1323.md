# T-1323 — N+1 query guard in tests, slow-statement log in production

| Field | Value |
| --- | --- |
| Wave | O (security, monitoring, performance) |
| Area | Performance |
| Size | 3 agent-hours |
| Role | R3 backend |
| Skills | ponytail, test-driven-development, systematic-debugging, verification-before-completion |
| R7 security review | no — but the log line must not carry bound values (asserted) |
| Depends on | none |
| Feature flag | `LD_SLOW_SQL_MS` (0 = off, the default) |

## Problem
A list endpoint that issues one query per row passes every test and dies on a 10k grid. There is no
query counter, no N+1 guard and no slow-query log: `app/db.py` creates the engine and nothing else.

## Design
- `app/db.py` (~55 lines): a SQLAlchemy event pair (`before_cursor_execute`/`after_cursor_execute`) that
  keeps a counter on a contextvar and, when `LD_SLOW_SQL_MS > 0`, logs one `sql.slow` line with
  `duration_ms`, the statement's first 200 characters **with literals elided** (`str(statement)` after
  `compile(dialect, compile_kwargs={"literal_binds": False})`), the request id and the route. Bind
  parameters are never logged.
- `query_count()` context manager and `counted_queries(app)` test helper exported from the same module,
  so tests do not re-implement an event listener.
- Tests: `apps/backend/tests/test_perf_queries.py` — one case per hot endpoint, asserting an absolute
  ceiling **and** equality between `limit=10` and `limit=100`:
  - `GET …/images` (list), `GET …/images/{id}` (detail), `GET …/projects/{slug}` (status counts),
    `GET …/versions`, `GET …/jobs`, `GET …/audit/export` (first page), editor open.
  - A catch-all autouse fixture fails any test request above `queries_any` (200).
- `apps/backend/tests/test_slow_query.py` — threshold behaviour, redaction, one line per statement.
- `docs/DEPLOY.md` — one paragraph: set `LD_SLOW_SQL_MS=200` on a busy deployment, and for Postgres
  also `log_min_duration_statement=200`; where the output goes.

## Tests to write first
`apps/backend/tests/test_perf_queries.py`:
- `test_image_list_uses_a_bounded_number_of_queries` — ≤ 25.
- `test_image_list_query_count_does_not_grow_with_page_size` — 10 vs 100 identical.
- `test_project_detail_counts_in_one_query_set` — ≤ 8.
- `test_editor_open_is_under_sixty_queries`.
- `test_audit_export_first_page_is_bounded`.
- `test_the_catch_all_fixture_is_active` — a deliberately looped route in the test (a monkeypatched
  service that queries 250 times) trips the guard.

`apps/backend/tests/test_slow_query.py`:
- `test_no_log_below_the_threshold` (`LD_SLOW_SQL_MS=10000`).
- `test_one_line_above_the_threshold` with `duration_ms` and `request_id`.
- `test_bind_values_are_not_logged` — insert an email and a token as parameters; neither appears.
- `test_disabled_by_default`.

## Acceptance criteria
- [ ] Query counts are bounded for every hot endpoint, and page size does not change the count.
- [ ] The guard fails on a real N+1 (proved by the RED step: introduce a one-query-per-row loop in a
      temporary patch, watch it fail, revert).
- [ ] The slow log is off by default, one line per statement, carries a request id, and never a value.
- [ ] The autouse guard does not slow the suite by more than 5 % (number in the report).
- [ ] `LD_SLOW_SQL_MS` is documented for both SQLite and Postgres.

## Notes for the implementer
Register the listener on the engine created in `app/db.py`, not on the global `event` registry, or every
test process leaks a listener. Elide literals by compiling without `literal_binds`; never log
`parameters`. The catch-all fixture must be opt-out-able (`@pytest.mark.no_query_guard`) for tests that
intentionally loop, and each opt-out needs a reason in the test.
