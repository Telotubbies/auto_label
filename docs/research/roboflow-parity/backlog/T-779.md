## User story
As a labeler who cannot drag a mouse, I want to move and resize a box from the keyboard and tab straight past the sidebar, so that the core job is doable without a pointer — and I want CI to refuse the change that takes it away.

## UX flow (LabelDesk words)
1. **Skip link** — the first `Tab` on any page reveals "Skip to content" over the glass top bar; activating it moves focus to the `<main>` element, not to a pixel.
2. **Editor, box selected** (`/:ws/:project/annotate`) — `Alt` + arrow nudges the box one pixel, `Alt` + `Shift` + arrow resizes it from the selected handle; the geometry panel gains four resize buttons with names ("Widen by one pixel"), so a single pointer works too. [error: with no box selected the keys do nothing and the panel says "Select a box to adjust it."]
3. **Focus never hides** — the sticky toolbar and the right rail never cover the focused control, and each of the three resized layouts keeps the focus ring visible.
4. **Review queue announcement** — moving between images announces "3 of 12, image 4471, 2 boxes" through a polite live region.
5. **CI** — the `web-a11y` job runs the shipped `node scripts/a11y-scan.mjs` over twelve routes and fails on any serious or critical axe finding, and on any pair in `lib/contrast.ts` that drops below its threshold.
6. **Accessibility statement** — `Trust → Accessibility` lists what is supported, what is known to be missing, and how to report a barrier.

## Tests to write first

- none — no backend surface: the gate is a browser scan over routes that already exist, and T-490's scan covers the login it needs.

node — `apps/frontend/tests/a11y-keyboard.test.mjs`:
- `test_alt_arrow_nudges_one_pixel` — `keyAction({key:'ArrowRight', altKey:true})` is `nudge` with `dx: 1`, and the plain arrow key still maps to `none` so image navigation is untouched.
- `test_alt_shift_arrow_resizes_from_the_selected_handle` — `keyAction({key:'ArrowDown', altKey:true, shiftKey:true})` is `resize` on the active handle, and `resize(box, 'se', 0, 1)` grows height by one with the x unchanged.
- `test_resize_never_inverts_a_box` — `resize({x:10,y:10,w:4,h:4}, 'nw', 10, 10)` clamps to a minimum of one pixel and keeps `w`/`h` positive.
- `test_the_skip_link_is_the_first_focusable_child` — the `AppLayout` source holds `Skip to content` before `<AppSidebar` and `<main` carries `id="main"` and `tabIndex={-1}`.
- `test_the_gate_fails_on_serious` — `a11y-scan.mjs`'s `FAIL_ON` list contains `serious` and `critical`, and the script imports `@axe-core/playwright` rather than a second scanner.
- `test_the_statement_names_a_gap` — the rendered statement data has at least one `known_gap` row and one `report` row, so the page cannot ship as a bare claim.

## Acceptance criteria
- [ ] `Alt`+arrow nudges and `Alt`+`Shift`+arrow resizes a selected box, and plain arrows still change image.
- [ ] The first `Tab` offers `Skip to content`, which focuses `<main>`; the geometry panel offers a pointer alternative for the same resize.
- [ ] The `web-a11y` CI job fails on serious or critical findings over twelve routes and on a contrast pair below threshold.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: the gate, the skip link and the statement hold in every deployment, and no existing shortcut changes.

## Notes for the implementer
Extend `scripts/a11y-scan.mjs` from T-490 — a second scanner doubles the maintenance and halves the trust. `?` stays the editor's shortcut overlay, so the resize keys live on `Alt` (which the editor does not use) rather than on `Shift`+arrow, which the canvas already reads as a coarse nudge. The statement lists known gaps first; an accessibility page with no gaps is a page nobody tested.
