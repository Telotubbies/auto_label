## User story
As an ML engineer, I want to freeze a version's test split into a named set with a digest, so that every
model I score later is scored on exactly the same images.

## UX flow (LabelDesk words)
1. **Data → Evaluation sets** — `/:ws/p/:project/models` gains a sibling route
   `/:ws/p/:project/evaluation-sets`; the page lists name, images, annotations, digest prefix, "pinned
   12 Nov by you", and how many models have been scored on it. [empty: "No evaluation sets yet" with the
   sentence "Pin a version's test split to score every model on the same images" and the primary *Pin a
   set*] [loading: three skeleton rows, the header still rendered] [error: "Evaluation sets could not be
   loaded" with *Try again*]
2. **Pin a set** — the primary opens a dialog: version select, split select (default `test`, `valid` when
   test is empty), name, and a preview line "820 images · 4,910 annotations · 17 classes". [empty: a
   project with no version shows "Create a version first" and a link to *Data → Versions*, primary
   disabled]
3. **Confirm** — the row appears at the top with a *Pinned* badge and its digest; the digest is the same
   value the evaluation report will print.
4. **Delete** — the row's menu offers *Delete set*; a set a deployment's current result was computed on
   refuses with the alias named.

## Backend changes
- Models/schema: new table in `apps/backend/app/models/evaluation.py` (new) — `EvalSet(id, workspace_id,
  project_id, version_id, split, name, digest, images, annotations, classes JSON, created_by, created,
  archived_at NULL)`, unique `(project_id, name)`, both FKs `ondelete=CASCADE`. Registered by adding the
  module to `DOMAIN_MODULES` in `apps/backend/app/models/__init__.py`.
- Routers: new `apps/backend/app/routers/evaluation_sets.py` (new), `P = "/api/ws/{ws}/projects/{project}"`:
  `GET {P}/evaluation-sets` → `{sets: [{id, name, split, digest, images, annotations, classes, created,
  created_by, model_count}]}`; `POST {P}/evaluation-sets` body `{version_id, split, name}` → 201 with the
  row. 400 on an unknown version, a version whose status is not `ready`, a split with no images
  ("the test split is empty — pin the valid split instead"), or a duplicate name; 404 for a foreign
  version.
- Services/jobs: `apps/backend/app/services/evaluation_sets.py` (new) — `digest_of(version_dir, split)`
  hashes the sorted `(file_name, sha256)` pairs from the version's COCO manifest so the digest is stable
  across re-exports; `create(db, project, version, split, name, user_id)`; `get(db, project, set_id)`;
  `list_sets(db, project)`; `model_count(db, set_id)` counts distinct `trained_models.metrics->eval.set_id`.
  No job.
- Permissions + workspace isolation: read = `project.review` (the same gate as `insights`), write =
  `project.models`; a set id from another project or workspace is a 404.
- Secrets/safefetch: none. Dependency: none added (no `mlflow-skinny`), so no
  `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: yes — regenerate `apps/backend/openapi.json` and `apps/frontend/src/lib/api-types.gen.ts`
  (`python tools/export_openapi.py`, `npm run gen:api-types`).

## Tests to write first
pytest — `apps/backend/tests/test_evaluation_sets.py`:
- `test_pin_creates_a_set_with_a_stable_digest` — pin `test` twice on the same version → both rows carry
  the same digest; touching an image file's bytes and re-pinning → a different digest.
- `test_pin_refuses_an_empty_split_and_names_the_alternative` — a version with an empty test split → 400
  whose detail contains "valid split".
- `test_pin_refuses_a_duplicate_name_and_a_foreign_version` — same name twice → 400; another project's
  version id → 404.
- `test_reader_cannot_pin_but_can_list` — reviewer reads 200, posts 403; labeler gets 404 on both (no
  `project.review`).
- `test_flag_off_returns_404` — `task_mlruns` off → both routes 404 and no nav entry renders.
node — `apps/frontend/tests/evaluation-sets.test.mjs`:
- `test_set_row_formats_digest_and_counts` — a fixture → "820 images · 4,910 annotations · a91f2c3d".
- `test_pin_preview_warns_on_empty_split` — `pinPreview({stats:{test:0}})` → the disabled primary and the
  valid-split sentence.

## Acceptance criteria
- [ ] Pinning a version's split creates a set whose digest is reproducible across re-pins of unchanged data.
- [ ] An empty split, a duplicate name and a foreign version each fail with the documented status and sentence.
- [ ] A reviewer can list sets and cannot create or delete one.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: `5-F5.30` → T-292/T-293 (regression suites declare checks over a pinned version) and `4-F4.45` →
T-004 (version snapshot guard). Neither stores a named, reusable set — both would consume this one.
The digest is over file names and image bytes only, never over the annotation JSON: a relabelled image must
not silently invalidate every past score.
