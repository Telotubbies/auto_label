## User story
As a reviewer, I want to drop a note exactly where the problem is and have the thread resolve when it is fixed, so that "the third screw from the left" is a pin instead of a sentence.

## UX flow (LabelDesk words)
1. **Editor → inspector sheet → Comments → "Comment on image"** — enters pin mode: the cursor becomes a crosshair with a hint "Click the spot to comment on". Clicking drops a numbered pin and opens a composer at that point. [empty: an image with no comments says "No comments yet — pin the first one"] [error: post fails → the composer keeps the text with a Retry]
2. **Pin rendering** — numbered circular pins above the canvas at their normalised positions, in one accent colour, visible while shapes are hidden (they are review context, not annotations). Clicking a pin selects its thread; a thread with more than one message shows the reply count. [empty: no pins when the flag is off or no anchored comments exist]
3. **Threads** — the panel lists threads newest-first with author, relative time, message count and a **Resolved** chip; an unanchored comment (created from the panel) appears at the top as "General". Replies indent once; Enter posts, Shift+Enter is a newline.
4. **Resolve** — a reviewer or the thread's author resolves it; resolved threads collapse to one line with "Resolved by X" and the pin turns hollow grey. Reopening is one click. [error: resolving someone else's thread without `project.review` → 403 with a readable message]
5. **Delete** — only a resolved thread can be deleted, by its author or a reviewer, with a confirm; an unresolved thread must be resolved first, so a conversation cannot be erased mid-argument.
6. **Read-only images** — pins and threads are visible; composing new ones is allowed only with `project.annotate` on an editable image (a reviewer on an approved image can still resolve).
7. **Flag off** — comments are exactly as today (flat, no anchor, no resolve) and the pin mode button is absent.

## Backend changes
- Models/schema: `Comment` (`models/project.py:160`) gains `x`, `y` (nullable floats, normalised), `parent_id` (nullable self-FK, cascade), `resolved_at` (nullable float), `resolved_by` (nullable user id); column block appended to `app/schema/dataset.py` (`COMMENTS`) and its `STEPS` entry.
- Routers: `POST /images/{image_id}/comments` accepts `x`, `y`, `parent_id` (validated `0..1`, parent on the same image); `PATCH /comments/{cid}` `{resolved: bool}`; `DELETE /comments/{cid}`; `GET /images/{image_id}/comments` returns `{id, author, authorId, text, at, x, y, parentId, resolvedAt, resolvedBy, replies}`; `400` for a coordinate outside the image, `403` for a delete of an unresolved thread.
- Services/jobs: none beyond the route logic; `audit` rows for resolve and delete.
- Permissions + workspace isolation: read needs `project.read` through the image; write needs `project.annotate` (or `project.review` to resolve someone else's); the comment id is resolved through its image's project, so a foreign comment id is 404.
- Secrets/safefetch: none.
- OpenAPI: yes — two routes changed, one added.

## Acceptance criteria
- [ ] A comment can be pinned at a point, renders as a numbered pin, and clicking it focuses the thread.
- [ ] Replies nest under their parent with one indent level, and the thread shows its message count.
- [ ] Author or reviewer can resolve and reopen; resolved threads collapse and their pins turn hollow.
- [ ] Only a resolved thread can be deleted, with a confirm, and only by author or reviewer.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no pin mode, no coordinates accepted, resolve refused; flat comments behave as today.
- [ ] Keyboard-only path: Tab to Comments → Enter on "Comment on image" → click? — the point needs a pointer; the keyboard path is replying and resolving an existing thread.

## Notes for the implementer
`x`/`y` are normalised like every other shape, so a pin stays on the same pixel at any window size. Do not draw pins inside the culled shapes layer — a pin must survive `h` and a cull, which means its own non-listening layer above.
