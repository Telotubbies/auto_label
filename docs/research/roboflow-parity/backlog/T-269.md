## User story
As a team without an architecture expert, I want one run that tries a handful of plausible models and ranks them, so that choosing an architecture becomes reading a result instead of guessing.

## UX flow (LabelDesk words)
1. **Train → Recipe → Engine** — a two-option control: *Single model* (default) and *Search a few* ("trains up to 8 candidates, ranks them, keeps the best; costs about 6× one run"). The search option states its candidate count and total credits before anything is queued.
2. **Unsupported tasks** — the search option is dimmed with "Search is available for detection and instance segmentation." on classification projects.
3. **Too little validation data** — a blocker from T-262 in search mode: "Search needs at least 15 validation images — this version has 6." and the engine cannot be selected.
4. **Before submit** — the plan panel lists the candidates it will try ("YOLO26 Nano · RF-DETR Small · YOLO11 Medium · D-FINE Small …") with each one's estimated credits. [loading: four candidate skeletons] [error: "The search plan could not be computed" + reason and Retry]
5. **Two caps** — the search cap (the whole run) and the single-model cap (each candidate inherits it); leaving one empty leaves it uncapped, as the row requires.

- **States** — [empty: a band whose families are all unavailable plans nothing and the primary is disabled with that reason].

## Backend changes
- Models/schema: none in this card (T-270 adds the result rows).
- Routers: `POST {P}/train/quote` gains `engine: "fine_tune" | "search" = "fine_tune"` and, in search mode, returns `{plan: {candidates: [{variant, family, imgsz, minutes, credits}], total_credits, total_minutes, capped_at: n}}` beside the single-run numbers. `POST {P}/train` gains `engine` and `search: {band: "fast"|"standard"|"plus", credits: float | null, per_model_credits: float | null}`; **400** cases: search on classification ("search is available for detection and instance segmentation"), fewer than 15 validation images ("search needs at least 15 validation images — this version has 6"), a band outside the three values, a candidate count above the cap.
- Services/jobs: new `apps/backend/app/services/architecture_search.py`:
  - `BANDS = {"fast": 0.0, "standard": 0.5, "plus": 1.0}` (a latency band, not a price).
  - `SPACE` = ordered `(family, variant)` rows taken from `train_catalog` (never a second zoo): detection fast = `yolo26n, yolo11n, rf-detr nano`; standard adds `yolo26s, yolo11m, rf-detr small, d-fine small`; plus adds `yolo26m, rf-detr medium, rf-detr large`. Instance segmentation uses the `-seg` variants only.
  - `MAX_CANDIDATES = 8`; `plan(task, band, train_images, epochs, imgsz) -> dict` returns the ordered candidate list, each with the T-252 quote, and the totals.
  - `validate(task, version, band) -> None` raising `ValueError` with the sentences above; the 15-image rule reads `train_preflight.small_valid_split`.
- Permissions + workspace isolation: quote = `c.perm("project.read")`, start = `c.need("admin")`; the plan reveals only this project's version counts.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate both files.

## Tests to write first
pytest — `apps/backend/tests/test_architecture_search.py`:
- `test_fast_band_is_a_subset_of_standard` — every variant in `plan(task,"fast")` appears in `plan(task,"standard")`.
- `test_candidate_count_is_capped_at_eight` — a plus-band plan never returns more than 8 rows and reports `capped_at == 8`.
- `test_instance_segmentation_only_offers_seg_variants` — every candidate variant ends with `-seg`.
- `test_search_on_classification_is_a_400` — 400 "detection and instance segmentation"; no job.
- `test_search_with_fourteen_validation_images_is_a_400` — 14 → 400 containing "15"; 15 → 200.
- `test_quote_totals_equal_the_sum_of_the_candidates` — `total_credits == round(sum(c.credits), 2)` and every candidate has `credits > 0`.
- `test_two_caps_are_independent` — `{credits: null, per_model_credits: 1}` → the plan is uncapped overall and every candidate capped at 1; the stored job options keep both nulls where sent null.
- `test_flag_off_is_a_400` — `engine="search"` with `task_269` off → 400 "search is not available".
- `test_foreign_version_plan_is_a_400` — version of another project → 400 "pick a generated version".

## Acceptance criteria
- [ ] The search option states its candidate count and total credits before submit.
- [ ] The space comes from the catalogue, is capped at 8, and never offers a detection-only family to a segmentation project.
- [ ] Fewer than 15 validation images is a 400/blocker with the count in the sentence.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no engine control, `engine="search"` refused, quote unchanged.

## Notes for the implementer
The plan is deterministic: same task + band + counts ⇒ same ordered list, so a re-quote never re-rolls the price. Search is *one* job that trains candidates in order (T-270), not one job per candidate — the queue is one deep per project.
