## User story
As the platform, I want one server-owned list of installable engines, their exact pins, runtimes and
compatibility facts, plus the GPU presets the calculator uses, so that no client string can become a
shell argument and no two screens disagree about a version.

## UX flow (LabelDesk words)
The screen is T-1007; this card supplies its rows.
1. **Engines tab rows** — vLLM, SGLang, llama.cpp, TensorRT-LLM, ONNX Runtime GenAI and Triton Inference
   Server, each with a runtime choice where the engine supports more than one and a one-line "what it
   is for".
2. **Calculator GPU preset** — `RTX 4090 24 GB`, `A100 80 GB`, `H100 80 GB`, `L40S 48 GB`, `L4 24 GB`,
   `T4 16 GB`, `RTX 3090 24 GB`, `RTX A6000 48 GB`, `RTX 6000 Ada 48 GB`, `Jetson AGX Orin 64 GB`,
   `CPU only`, plus `Custom`.
3. **A pin that cannot be verified** — the row is absent from the catalogue rather than shown with
   `latest`; the empty state says "No pinned version for this engine yet." [empty: an engine with no
   verified pin].
4. **Custom GPU** — the preset list ends with `Custom`, which reveals VRAM, bandwidth and FP16 TFLOPS
   inputs (T-1005).

## Backend changes
- Models/schema: none.
- Routers: `GET /api/ws/{ws}/inference/catalog` → `{engines: [...], gpus: [...], sources: [...]}`.
  Public rows omit the install argv and the container digest; those are only returned by the plan
  endpoint (T-1006) to an admin.
- Services/jobs: `apps/backend/app/services/inference_catalog.py` (new).
  - `ENGINES: list[dict]` with `id, name, summary, version, runtimes, os, accelerator, min_driver,
    cuda_min, cuda_max, disk_mb, package, container, source_url, checked_on, notes`.
    Concrete rows:
    | id | name | runtimes | os | accelerator | constraints to verify at pin time |
    | --- | --- | --- | --- | --- | --- |
    | `vllm` | vLLM | `uv`, `pip`, `docker` | linux | nvidia | CUDA ≥ 12.x, driver ≥ the pin's torch matrix |
    | `sglang` | SGLang | `uv`, `pip`, `docker` | linux | nvidia | CUDA ≥ 12.x, `sglang[all]` |
    | `llamacpp` | llama.cpp | `uv`, `pip`, `docker` | linux, macos, windows | cpu, metal, nvidia, vulkan | GGUF only; no CUDA requirement; the pip runtime is the `llama-cpp-python` server |
    | `tensorrtllm` | TensorRT-LLM | `docker` (pip warned) | linux | nvidia | strict driver + CUDA + TensorRT match; engines per GPU |
    | `onnxruntime` | ONNX Runtime GenAI | `uv`, `pip` | all | cpu, nvidia, directml | LLM serving needs `onnxruntime-genai`, not `onnxruntime` alone |
    | `triton` | Triton Inference Server | `docker` | linux | nvidia | **not** the OpenAI Triton compiler; label the full product name |
  - `version` is an **exact** string resolved from `source_url` when the card is implemented (no
    `latest`, no range, no floating tag); `container` is a `repo@sha256:…` digest or `None`.
  - `GPUS: list[dict]` with `id, name, vram_gb, bw_gbs, fp16_tflops, source_url`:
    | id | VRAM | bandwidth | FP16 dense | source |
    | --- | --- | --- | --- | --- |
    | `rtx4090` | 24 | 1008 GB/s | 165 TFLOPS | NVIDIA RTX 4090 data sheet |
    | `rtx3090` | 24 | 936 GB/s | 71 TFLOPS | NVIDIA RTX 3090 data sheet |
    | `a6000` | 48 | 768 GB/s | 77 TFLOPS | NVIDIA RTX A6000 data sheet |
    | `rtx6000ada` | 48 | 960 GB/s | 91 TFLOPS | NVIDIA RTX 6000 Ada data sheet |
    | `l40s` | 48 | 864 GB/s | 181 TFLOPS | NVIDIA L40S data sheet |
    | `l4` | 24 | 300 GB/s | 121 TFLOPS | NVIDIA L4 data sheet |
    | `t4` | 16 | 320 GB/s | 65 TFLOPS | NVIDIA T4 data sheet |
    | `a100_80` | 80 | 2039 GB/s | 312 TFLOPS | NVIDIA A100 data sheet |
    | `h100_80` | 80 | 3350 GB/s | 989 TFLOPS | NVIDIA H100 SXM data sheet |
    | `orin64` | 64 | 204 GB/s | 85 TFLOPS | Jetson AGX Orin data sheet |
    | `cpu` | 0 | system | 0 | — |
    Every row carries `source_url`; the numbers are vendor figures rounded, and the card's test asserts
    the source is present so a future edit cannot add a mystery preset.
  - `public_catalog()`, `engine(id)`, `gpu(id)`, `install_spec(id, runtime)` (raises `KeyError` for an
    unknown id or a runtime the engine does not offer), `validate()`.
- Permissions + workspace isolation: `owner`/`admin` (403 otherwise); flag off 404 via the router.
- Secrets/safefetch: none; no URLs are fetched at request time (the source URL is text for the UI).
- OpenAPI: yes.

## Tests to write first
pytest — `apps/backend/tests/test_inference_catalog.py`:
- `test_every_engine_has_an_exact_pin_and_a_source` — for each row: `version` is non-empty, is not
  `latest`, matches `^[0-9]`, and `source_url` starts with `https://`.

  `@sha256:[0-9a-f]{64}$`; no `:latest`.

- `test_public_catalog_hides_the_install_argv_and_digest` — the response contains no `argv`, no

- `test_catalog_is_admin_only_and_flag_gated` — member 403; flag off 404.

## Acceptance criteria
- [ ] Six engines and eleven GPU presets are served from one module, every row sourced.
- [ ] No pin reads `latest`, every container is digest-pinned, and no install command reaches a
      non-admin response.
- [ ] An unknown engine or runtime raises, never falls back to a default package.
- [ ] Member 403 and flag off 404.
- [ ] The calculator's preset list and the Engines tab both read this one endpoint (no second copy).

## Notes for the implementer
Resolve every `version` and digest from the engine's own release page on the day you implement, and put
that date in `checked_on`. If a pin cannot be verified, leave the row out — a missing engine is a better
failure than a floating install. Do not add an `extra_args` field: nothing user-supplied may reach a
command.
