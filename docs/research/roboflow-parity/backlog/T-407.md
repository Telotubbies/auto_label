## User story
As an admin, I want the trash grouped by kind with who deleted each item and how many days are left, so that undo
is a decision rather than a guess.

## UX flow (LabelDesk words)
1. **Settings → Trash** (`/:ws/settings/trash`) — a `30-day window` line at the top and four groups
   (`Projects`, `Versions`, `Training runs`, `Workflows`), each a table: `Name`, `Deleted by`, `When`,
   `Days left`, checkbox, actions. [loading: a skeleton row per group] [error: `Could not load the trash.` + retry]
2. **Rows** — `Deleted by Nok · 3 days ago · 27 days left`; an unknown deleter reads
   `Deleted by a member who has since left.`; `days left` ≤ 3 renders in the warning tone.
3. **Selection** — a checkbox per row and per group header; the selection bar shows `Restore` (primary) and
   `Delete permanently` (danger) for the count. `Restore all` sits in the page header.
4. **Amber marker** — a row whose project owns the only copy of its images shows a warning icon with
   `Images used only here will be deleted at cleanup. Images shared with other projects survive.`
5. **Permanent delete** — a typed confirm: type `delete` then `Delete permanently`; the dialog lists the count and
   states `This cannot be undone.`
6. **`[empty]`** `The trash is empty.` and one line `Deleted projects, versions, runs and workflows wait here for 30
   days.`; a filtered/partial empty group is simply absent.
7. **Restore refusal** — a version whose project is still in the trash shows an inline line
   `Restore the parent project first.` with a link to the project row, and keeps the row selected.

control.
