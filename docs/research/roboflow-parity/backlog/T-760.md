## User story
As a data protection officer, I want to write one retention rule per data class, so that "frames 30 days, exports 7" is a record an auditor can read instead of a sentence in a contract.

## UX flow (LabelDesk words)
1. **Settings → Privacy → `Retention rules`** (`/:ws/settings/privacy`) — one `Card` lists rules newest first: scope, data class, clock, days and the day the rule took effect. [empty: "No rules yet — nothing is deleted automatically." with an `Add a rule` button] [loading: three skeleton rows] [error: "Couldn't load your retention rules." beside `Try again`]
2. **`Add a rule`** — a dialog: scope (this project, or the whole workspace), data class (frames, event clips, exports, drift samples), clock (captured or modified), days (7–3650), action (`Delete`, with `Anonymise` listed and disabled under it reading "Not available in this deployment"). `Save` stays disabled until a scope and a day count are chosen. [error: "Days must be a whole number between 7 and 3650."]
3. **Saved** — the row appears in place with "Saved — the next sweep uses this rule." and one audit entry.
4. **Remove a rule** — a confirm dialog states that the next sweep stops applying it and that already-deleted files are not restored.
5. **A member who is not an admin** — reads the same list with "Read only — an admin edits retention rules." and no `Add a rule` button. [error: a member who forces the POST sees "Retention rules are changed by a workspace admin."]

## Backend changes
- Models/schema: `app/models/policy.py` (new) — `RetentionRule(id, workspace_id, project_id nullable, data_class, clock, days, action, created_by, created, retired)`; register the module in `app/models/__init__.py`. No new column on `projects` in this card.
- Routers: `app/routers/policies.py` (new) — `GET /api/ws/{ws}/retention/rules` (list, newest first), `POST /api/ws/{ws}/retention/rules` (201; 422 on an unknown data class, clock or action, or days outside 7–3650), `DELETE /api/ws/{ws}/retention/rules/{rid}` (sets `retired=True`, returns 200 and keeps the row for the audit trail).
- Services/jobs: `app/services/policy_rules.py` (new) — `CLASSES`, `CLOCKS`, `ACTIONS`, `validate(body) -> dict`, `active(db, workspace_id)`, `for_project(db, workspace_id, project_id)`. No new job kind: the sweep stays `services/retention.run_retention` until T-761 changes what it reads.
- Permissions + workspace isolation: writes need `workspace.update` (the permission `routers/privacy.py:100` already uses for workspace-level privacy), reads need `workspace.read`; every statement filters `RetentionRule.workspace_id == c.ws.id`, and a rule id from another workspace answers 404, never 403.
- Secrets/safefetch: none.
- OpenAPI: yes — `python tools/export_openapi.py` and `npm run gen:api-types`.

## Tests to write first
pytest — `apps/backend/tests/test_retention_rules.py`:
- `test_a_rule_round_trips` — admin login → `POST` a whole-workspace frames/30-day/delete rule → 201, then `GET` lists it with `action="delete"` and `days=30`.
- `test_days_outside_the_range_are_422` — `POST` `days=3` and `days=4000` → both 422 carrying "7" and "3650" in the detail.
- `test_an_unknown_class_or_clock_is_422` — `POST` `data_class="vibes"` and `clock="opened"` → 422 naming the field.
- `test_anonymise_is_refused` — `POST` `action="anonymise"` → 422 with "not available in this deployment".
- `test_a_member_cannot_write_a_rule` — labeler login → `POST` → 403; the same labeler's `GET` still returns 200.
- `test_a_foreign_rule_is_404` — a rule created in a second workspace → `DELETE` it as the demo admin → 404, and the second workspace's row is still active.
- `test_flag_off_hides_both_routes` — with `task_retention_rules` absent from `LD_FLAGS_ON` and no override row → `GET` and `POST` both 404.

node — `apps/frontend/tests/retention-rules.test.mjs`:
- `test_day_validation_matches_the_api` — `ruleError({days: 3})` returns the range sentence, `ruleError({days: 30, project: 'x'})` returns `null`.
- `test_anonymise_is_listed_but_unavailable` — `RULE_ACTIONS` has `delete` with `available: true` and `anonymise` with `available: false` and a reason string.
- `test_scope_label_names_the_project_or_the_workspace` — `scopeLabel({project: null})` is "Whole workspace", `{project: 'ppe'}` is "Project ppe".

## Acceptance criteria
- [ ] An admin adds a 30-day frames rule and it survives a reload, with one audit row.
- [ ] Days, class, clock and action outside the allowed sets are refused with 422 and the field named.
- [ ] A non-admin sees the list read-only; a forced write answers 403.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no `Retention rules` section, both routes 404, and the existing per-project `retention_days` behaviour is unchanged.
