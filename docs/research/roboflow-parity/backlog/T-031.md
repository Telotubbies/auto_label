## User story
As a visitor, I want a browsable gallery that respects filters and links to a dataset page, so that finding reusable data is a route on this site rather than a guess.

## UX flow (LabelDesk words)
1. **Gallery** (`/datasets`) — public shell (the landing header, no app rail): title `Public datasets`, one search field, one `Filters` button with an active count, sort select. Result rows: name, description (2 lines + `more`), type chip, class chips, `128 images · 2 models · CC BY 4.0`, workspace name, and `Open` linking to `/d/:ws/:slug`.
2. **Filter panel** — type, image-count band, `Has a trained model`, licence. Applying closes the panel and updates the URL query so a filtered gallery is shareable. [empty: `Clear filters` restores the unfiltered list]
3. **States** — [loading: six skeleton rows matching final height] [error: `Could not load public datasets` + `Retry`] [empty: none published → the publish sentence; no match → `No datasets match these filters.`]
4. **Signed-in visitor** — the header shows the app switcher; the rows are identical (no extra controls on this page).
5. **Mobile 375** — rows stack (title, chips, meta), filters as a sheet, no horizontal scroll.

## Acceptance criteria
- [ ] `/datasets` renders for a signed-out visitor and never redirects to login while the flag is on.

- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — the page displays only what the public endpoint returns.
