## User story
As an engineer comparing models, I want to load a saved prompt, run it on an image and keep the comparison, so
that the answer to "which model handled this question better" is still there tomorrow.

## UX flow (LabelDesk words)
1. **Workspace → Playground** — the header gains a prompt selector: *No prompt* or one of the workspace's
   prompts; choosing one fills the question box and pins the version in the header — "using helmet-count v3".
   The question box becomes read-only with an *Edit as a new version* link. [empty: a workspace with no prompt
   shows "Save this question as a prompt" under the box, one click to T-964's create dialog] [error: the
   prompt list fails → the selector shows "prompts unavailable" and the free-text box still works]
2. **Run** — unchanged: up to three models, one image, latency per model, boxes with a confidence filter.
   [loading: each column shows its own spinner so a slow model does not block a fast one]
3. **Save comparison** — a secondary under the results stores the prompt version, the models, the image id, the
   latency and each output, and shows a toast with the run's id and a link.
4. **History** — a *Recent runs* strip above the image picker lists the last ten saved comparisons: prompt,
   models, image, date; clicking one reloads the same image and prompt into the page. [empty: "No saved
   comparisons yet"]
5. **Hand off to scoring** — a saved run offers *Add to evaluation set* (the image joins a set through T-963's
   path) and *Score this answer* (opens T-960's drawer). [error: a saved run whose image was deleted opens with
   the image slot saying "this image was deleted" and the stored outputs still readable]

## Backend changes
- Models/schema: `PlaygroundRun(id, workspace_id, image_id NULL, prompt_id NULL, prompt_version NULL,
  question TEXT, model_refs JSON, results JSON, created, created_by)` in
  `apps/backend/app/models/evaluation.py`, index `(workspace_id, created DESC)`.
- Routers: `POST {P}`-free — the playground router is workspace-scoped (`/api/ws/{ws}/playground`), so:
  `POST /api/ws/{ws}/playground/runs` body `{image_id, prompt_id?, prompt_version?, question, results}` →
  201 with the run; `GET /api/ws/{ws}/playground/runs?limit=10` → the strip. `DELETE
  /api/ws/{ws}/playground/runs/{id}`. 400 for an unknown prompt version, an empty question, more than three
  models in `results`, or an image outside the workspace; 404 for a foreign run.
- Services/jobs: `apps/backend/app/routers/playground.py` — `predict` gains an optional `prompt_ref` form field
  resolved through `services.prompts.resolve`, and returns the resolved `prompt: {id, name, version}` beside
  `results`; a new `save_run` writes the row. No job.
- Permissions + workspace isolation: any workspace member may run and save (the playground charges no credits,
  as today); a run or image from another workspace is a 404.
- Secrets/safefetch: none. Dependency: none added (no `mlflow-skinny`), so no
  `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] A prompt version can be loaded into the Playground and the response names the version it used.
- [ ] A comparison saves the prompt version, models, latencies and outputs, and reloads from history.
- [ ] History survives a deleted image, showing the stored outputs and a clear notice.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: none. The Playground already exists (`apps/frontend/src/features/playground/Playground.tsx:155`,
`apps/backend/app/routers/playground.py:75`); this card adds persistence and a prompt reference and changes no
inference behaviour.
`results` is stored as returned, including per-model errors: a saved comparison with a failed column is the
honest record of what happened, not a reason to refuse the save.
