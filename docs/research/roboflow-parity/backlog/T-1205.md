## User story
As a reviewer, I want to see what is waiting, approve or reject at keyboard speed, and be told exactly what
a bulk approval will touch, so that I never approve blind and never approve someone else's mistake in
bulk.

## UX flow (LabelDesk words)
1. **Annotate board** (`/:ws/p/:project/annotate`) — the "In review" lane names the count; the batch row
   shows progress, assignee and age. [empty: "Nothing waiting. Upload images or move a batch here."].
2. **First image** — the batch's primary opens the first image awaiting review.
3. **Approve** — one key approves and moves to the next; the review state is visible before the action and
   the saved state after it. [error: approving an image with no labels asks for the empty confirmation].
4. **Reject** — one key opens the reason list; the reason is required and is stored.
5. **Bulk approve** — the confirmation names the count and the classes involved; cancelling changes
   nothing. [error: a selection spanning two batches says so and asks for one batch].
6. **Board again** — the counts moved by exactly the number approved; no double count.

## Acceptance criteria
- [ ] Approve, reject and bulk approve move the counts by exactly the acted-on number.
- [ ] Every bulk action shows a sentence naming count and classes before it runs.
- [ ] Steps ≤ 8 and time ≤ 120 s; numbers recorded.
- [ ] A reject without a reason cannot complete; the reason is visible on the image afterwards.
- [ ] Empty, loading and error states: an empty lane, a busy bulk action, a refused empty approval.
- [ ] Keyboard only: approve, next, reject and the confirm are all reachable; focus is visible.
- [ ] No console error; the board has no double-submit on a slow response (`stubApi` delay once).
- [ ] Workspace isolation: an approval in workspace A leaves B's review count unchanged.
- [ ] Flag off ⇒ the review surface still works (this journey is not flag-gated); the consensus leg is
      absent.
