## User story
As the design and quality leads, I want one audit of settings, governance, the platform console and the
inference hub, so that the screens with the most consequence — money, access, audit, engine installs — are
the clearest, not the densest.

## UX flow (LabelDesk words)
1. **Settings** (`/:ws/settings/*`) — Account, Security, Appearance, Workspace, Members, Roles, Privacy,
   Alerts, API Keys, Plan & Usage, Trash; one tab row, no duplicate navigation.
2. **Members and roles** — roster, invite, last-admin guard, role descriptions in outcome words.
3. **API keys** — masked table, create with scopes, one-time reveal, revoke.
4. **Usage** — meter, cycle, projection, saved scenario.
5. **Audit** (`/:ws/audit`) — filters, expandable diff, denied actions.
6. **Platform console** (`/admin`) — workspaces, seats, usage, flags; the refusal for non-superadmins.
7. **Inference hub** (`/:ws/inference`) — calculator, engines, models, segmentation; the flag-off state.

## Acceptance criteria
- [ ] Every settings tab is reachable from one tab row; the rail does not duplicate the active tab (the
      A26 contract).
- [ ] The key reveal is one-time and the mask is the only value afterwards.
- [ ] Usage and audit numbers are readable together; no metric is a bare bar without role and value.
- [ ] A non-superadmin's console refusal is explicit and never a blank page.
- [ ] axe: 0 critical/serious; tables have headers and captions; the tab row is a real tablist.
- [ ] The 10 heuristics are scored per screen; no score < 3; the two worst are named.
- [ ] Findings are S1–S4 with evidence; each S1/S2 has a proposed fix card title.
- [ ] P4 walks the area, and P5 walks the hub's agent-facing states (tool absence, scope); SUS-8 recorded
      for P4.
- [ ] Empty, loading and error states: a one-person workspace, a busy invite, a seat limit, a failed audit
      fetch, a hub with no host inventory, the flag-off hub.
