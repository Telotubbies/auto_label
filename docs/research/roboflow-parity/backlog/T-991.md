## User story
As the person wiring an agent to LabelDesk, I want my key to start an auto-label job, create a dataset
version, list what is deployed and run a model on a stored image, so that the whole train-and-ship loop is
reachable from an agent without a browser session.

## UX flow (LabelDesk words)
API surface again; four requests and their states.
1. **`POST /api/v1/projects/{project}/autolabel`** — queue one auto-label job. [empty: no unannotated image
   → the job is still queued and finishes with zero images; the response is the job, not a 400]
   [error: no model and no prompt → 400 `choose a trained model`; a `classId`-less project for SAM → 400
   `add classes first`; `write` scope missing → 403].
2. **`POST /api/v1/projects/{project}/versions`** — build a version from the current annotations.
   [loading: the response is a `queued` version plus a job id, never a wait] [error: 402 `monthly credit
   limit reached on the Free plan` when the 0.5 credits are gone; tiling on a classification project → 400].
3. **`GET /api/v1/deployments`** — what is live, per project, with aliases and the models behind them.
   [empty: `projects: []` for a workspace with nothing deployed].
4. **`POST /api/v1/models/{model_id}/predict`** with `image_id` — score one image the project already
   holds. [error: an image id from another workspace is 404 `image not found`; an unknown model is 404
   `model not found`; 402 when the infer credits are gone].

## Notes for the implementer
The whole card is delegation: if a route body grows past the validation the API already does, it is
duplicating `training.autolabel` or `versions.create_version` — call them instead.
`GET /deployments` is workspace-wide on purpose (an agent asked "what is live?"), but it must return the
same lean/alias shape `services/deployments.workspace_state` already produces: no weights, no metrics a
`read` key could not get through `list_models`.
