## Problem
"Are we secure?" has no answer that cites a standard. The owner asked for a gap list against
**OWASP ASVS L2** and the **OWASP API Security Top 10** with each gap tied to a card. Without it, the
backlog cannot show that the important rows are covered, and a future auditor starts from zero.

## Design
`docs/ops/ASVS-GAPS.md` (new, ~180 lines), three tables plus a summary:

1. **ASVS 4.0.3 Level 2, chapter by chapter** (V1 architecture, V2 authentication, V3 session, V4
   access control, V5 validation, V6 cryptography, V7 error handling, V8 data protection, V9
   communication, V10 malicious code, V11 business logic, V12 files, V13 API, V14 configuration).
   One row per *requirement group* that is not obviously satisfied, not one row per requirement (that is
   286 rows nobody maintains): id, requirement in one line, current state, evidence, card or
   `accepted`.
2. **API Security Top 10 (2023)** — all ten rows, always present (API1 BOLA, API2 broken auth, API3
   object property, API4 resource consumption, API5 function-level auth, API6 business-flow abuse,
   API7 SSRF, API8 misconfiguration, API9 inventory, API10 unsafe consumption). Each with the specific
   route family it applies to here, the guard, and the card.
3. **Coverage summary** — counts per chapter: satisfied / guarded by a test / card / accepted.
4. **How to re-check** — the exact commands (ruff, pip-audit, the two security test files) and the two
   documents a reviewer reads.

The mapping is deliberately *narrow and honest*: a row is "satisfied" only when a test or a `path:line`
proves it. Everything else is a card id. There is no "partial".

## Tests to write first
Appended to `tools/tests/test_docs_ops.py`:
- `test_every_api_top_ten_row_exists` — API1…API10 all present, in order.
- `test_every_gap_row_has_a_card_or_accepted` — every non-satisfied row names a real card file or
  `accepted`.
- `test_no_row_claims_satisfied_without_evidence` — a "satisfied" row must contain a backticked path or
  a test file name.
- `test_summary_counts_match_the_tables` — the counts in §3 equal the rows counted by a regex.

## Acceptance criteria
- [ ] Ten API Top 10 rows, every ASVS L2 chapter that has a gap present.
- [ ] Every gap names a card that exists in `docs/research/roboflow-parity/backlog/`.
- [ ] Every "satisfied" row cites a test file or a `path:line`.
- [ ] The summary counts are mechanically derived and the guard proves it.
- [ ] Nothing is marked satisfied because "it is a standard library feature"; the cite is the proof.

## Notes for the implementer
Do not paste the ASVS text into the repo beyond a one-line paraphrase per row (the standard is
CC-BY-SA; a summary is fine, a copy is not useful). If a row needs a product decision (for example
"API4: no per-tenant quota"), write it as an owner question in the security plan rather than inventing
a card. Keep the file under 200 lines: it is a map, not a manual.
