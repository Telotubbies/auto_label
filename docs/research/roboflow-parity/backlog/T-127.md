## User story
As a labeler, I want to say "there is genuinely nothing here", so that a background frame becomes an intentional negative instead of an unlabelled image nobody looks at.

## UX flow (LabelDesk words)
1. **Editor tool column** — floating glass column on the canvas' right edge (REDESIGN §13.3), 12 slots in four bands: `V` select · `B` box · `P` polygon · `U` brush · `O` rotate ｜ `S` smart polygon · `K` keypoint · auto-label ｜ `C` comment · undo · redo ｜ **`N` Mark empty**. Mark empty is the last slot and never sits beside the drawing tools, so it cannot be hit by mistake while drawing. `n` is added to `SHORTCUT_ACTIONS` (default `n`, remappable like the others). Icon: `∅`. The hint over the canvas reads "Marked empty — nothing to label on this image".
2. **Press `n` on a normal image** — the image is marked empty, every annotation on it is cleared, the Objects list shows a distinct state, and the header pill reads **Empty**. One undo step restores both the flag and the annotations. [error: the save fails → the flag and the annotations revert together and the save bar from T-121 shows why]
3. **Press `n` on an already-empty image** — the flag clears and the image returns to unannotated ("Not labelled yet"; status `annotating`), so a mis-press is one key away. Annotations cleared by the first press are **not** restored by the second; the undo stack still holds them for this session.
4. **Objects tab** — the empty state becomes two different sentences: "Marked empty — this image is a negative sample" with an **Unmark** button, versus "No objects yet" with the drawing hint.
5. **Board and dataset** — the Annotate board's progress counts an empty image as annotated (it is a decision), and the dataset grid shows an "Empty" chip on the thumbnail. [empty: a project with no images keeps today's board empty state]
6. **Export** — an empty image exports as a background image with no label file, which is what a false-positive-prone model needs; nothing about it is silent, the version counts it in `images`.

## Acceptance criteria
- [ ] `n` marks an image empty, clears its annotations and shows the Empty state; a second `n` unmarks it.
- [ ] One undo restores the flag and the annotations together; the save bar never reports "Saved" before the write lands.
- [ ] An empty image counts as annotated on the board and appears in a new version as a background image with no label file.
- [ ] A viewer cannot mark empty (403 from the server) and the editor shows the tool disabled with the reason.
- [ ] Empty, loading and error states above all render: the Objects tab distinguishes "Marked empty" from "No objects yet".
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: the convention is always on; a flag-off mode would produce two meanings for an empty set.
- [ ] Keyboard-only path: open image → `n` → `n` → `Ctrl+Z` → `→`.

## Notes for the implementer
`marked_empty` is a decision, not a derivation: never recompute it from `n_annotations == 0`, or clearing a box would silently turn an image into a negative. Cleared annotations are recoverable only through the session undo stack and, after T-144 lands, the revision list.
