## User story
As someone tidying a workspace with a dozen projects, I want to drag cards onto folders and move a selection at once, so that organising does not mean a menu per project.

## UX flow (LabelDesk words)
1. **Workspace home** — every project card and folder card is draggable; while dragging, folder cards and the `All projects` crumb become drop targets with a 2 px primary outline. [empty: no folders → the crumb is the only target, and dropping there is a no-op]
2. **Drop a project on a folder** — the card moves; a toast `Moved “PPE Detection” to Safety.` with `Undo` for 6 s (undo re-issues the previous `folder_id`). [error: `Could not move — the project stayed where it was.`]
3. **Multi-select** — ⌘/Ctrl-click or the card checkbox adds to a selection (`2 selected` in a sticky bar with `Move to…`, `Clear`). Dragging any selected card drags all of them.
4. **Drag a folder onto a folder** — moved under it (nesting, T-025); dragging a folder to the crumb lifts it to the top level.
5. **Keyboard** — every card has a `Move to…` action in its ⋮ menu (existing) so the drag is never the only path; the menu lists folders plus `All projects`.

## Backend changes
- Models/schema: none — `PATCH /projects/{p} {folder_id}` exists.
- Routers: `PATCH /api/ws/{ws}/projects/{p}` accepts `folder_id`; a bulk form is not needed — the client issues one PATCH per selected project (bounded to 50).
- Services/jobs: none.
- Permissions + workspace isolation: admin (existing) — `folder_id` from another workspace is refused with 422 (`folder not in this workspace`) inside `projects.patch`, never silently accepted.
- Secrets/safefetch: none.
- OpenAPI: no route change (one validation message).

## Frontend changes
- Route: workspace home `/:ws`.
- Nav entry: none.

- API client: existing `patch` helpers; no new function.
- Feature flag: `task_a1_folder_drag`; off ⇒ no `draggable`, selection bar absent, the menu path is unchanged.

## Acceptance criteria
- [ ] Dropping one project or a selection on a folder persists the move and offers a 6 s undo.
- [ ] Dragging to `All projects` lifts the item to the top level; the ⋮ menu still does the same move.
- [ ] Empty and error states above all render (no folders, failed move keeps the card in place).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids); a foreign folder id is refused.
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged (menu-only moves).
- [ ] Keyboard-only users can complete the same move from the menu.

## Notes for the implementer
