## Problem
The four alerts the owner named need sources that do not exist: queue depth, job duration, worker
heartbeat age, disk free. GPU state exists in `gpu.scheduler.state()` but only the superadmin console
reads it. The job table is the queue (`app/worker.py:131-140`) and the heartbeat is a `Worker` row
(`services/heartbeat.py`) — the data is there, only the exposition is missing.

## Design
Everything lands in `app/metrics.py` (the module T-1302 created), in a marked section, so there is one
registry and one scrape.

- **Scrape-time gauges** (computed when `/api/metrics` is scraped, cached 5 s):
  - `labeldesk_jobs{status}` for `queued`, `running`, `failed_24h` — one `COUNT(*) … GROUP BY status`
    query, plus one for the 24 h failed window.
  - `labeldesk_job_oldest_queued_seconds` — `min(created)` over `queued`, 0 when empty.
  - `labeldesk_workers_online` — count of `Worker.last_seen > now - LD_WORKER_STALE_S`.
  - `labeldesk_worker_heartbeat_age_seconds{worker}` — one series per worker row (bounded by
    operators, not tenants).
  - `labeldesk_disk_free_bytes{volume="data"}`, `labeldesk_disk_used_ratio{volume="data"}` via
    `shutil.disk_usage(DATA_DIR)`; a missing dir yields no series, not a crash.
  - `labeldesk_gpu_vram_used_mb`, `labeldesk_gpu_budget_mb`, `labeldesk_gpu_leases` from
    `gpu.scheduler.state()`; absent when no driver.
- **Worker observations** (`app/worker.py`, three lines):
  - `labeldesk_job_duration_seconds{kind}` observed in `_set(... )` on a terminal status;
  - `labeldesk_job_outcomes_total{kind,status}` incremented for `done|failed|cancelled`;
  - on claim, nothing new — the queue gauges already show `running`.
- A failed gauge query logs once per scrape and keeps the previous value (no 500, no zero lie).

## Acceptance criteria
- [ ] `/api/metrics` carries every series in the monitoring plan §4.2 and nothing else.
- [ ] Scrape cost: p95 < 100 ms with 10 000 jobs (measured in the report, seeded locally).
- [ ] A broken gauge source degrades to a stale value and one log line, never a 500.
- [ ] No series and no label contains tenant data or an absolute path.
- [ ] Worker observations fire exactly once per terminal job.

## Notes for the implementer
Do not create a background thread to update gauges: scrape-time collection is cheaper and always
current. Do not label anything by workspace — the dashboard's job is platform health; per-tenant
numbers already live on the System health page (T-1314). Keep the 5 s cache so a 1 s scrape interval
cannot hammer SQLite.
