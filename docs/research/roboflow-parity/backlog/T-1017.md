## User story
As an owner, I want installs and downloads limited to my workspace's admins, bounded to this deployment,
and recorded with who, what, where and when, so that a host cannot be changed quietly and a leaked
session cannot install software.

## UX flow (LabelDesk words)
1. **Member or labeler** — no rail entry (T-1000) and, on a direct URL, the page's `Gate` renders the
   workspace home; every inference route answers 403 for a write and 404 outside the flag.
2. **Admin in the wrong workspace of a multi-tenant deployment** — every route 404s; the hub is not
   advertised. The operator's `LD_INFERENCE_WORKSPACE` decides which workspace owns the hosts.
3. **Audit log** — the existing Audit screen shows `inference.engine_install`,
   `inference.engine_uninstall`, `inference.model_download`, `inference.model_remove` with the host,
   catalogue id, version/variant and job id in `meta`; no token, no absolute path.
4. **Rate limit** — a fifth install request in a minute from one user returns 429 with a retry hint.
5. **Host scope** — a host id that is not in this deployment's inventory list is 404, including one
   guessed from another deployment.

## Backend changes
- Models/schema: none.
- Routers: no new routes; every inference route gains `Depends(require_ws_admin)` and the flag (already
  present) and calls the access helper.
- Services/jobs:
  - `apps/backend/app/services/inference_access.py` (extends T-1001) —
    `workspace_allowed(db, ws_id) -> bool` (env scope), `require_admin(c: Ctx)` (403 with
    `requires workspace admin`), `host_or_404(db, c, host)`, and
    `recent_actions(db, ws_id, user_id, action, window_s=60) -> int`.
  - `deps.audit(...)` calls on every enqueue **and** on terminal state (worker complete/fail updates the
    same job; the enqueue row is the authoritative "who asked"). `meta` = `{host, id, version|variant,
    job_id}`; no `argv`, no path, no token.
  - `MAX_ENQUEUES_PER_MIN = 4` per user per workspace for `install|download|uninstall|remove`; a fifth
    is `HTTPException(429, "too many inference actions; wait a minute")`.
  - A scrubbing helper `safe_log(text)` reused by T-1008/T-1011 already; this card asserts coverage on
    every route that echoes a worker message.
- Permissions + workspace isolation: `owner`/`admin`; all reads also admin (the hub is an admin
  surface); foreign host/project/job 404; flag off 404.
- Secrets/safefetch: no token in audit/log/error; a test seeds one.
- OpenAPI: no (no new route; the dependency changes are internal).

## Acceptance criteria
- [ ] Every inference route is admin-only, flag-gated and scope-gated; member/labeler 403; wrong
      workspace 404.
- [ ] Every write needs `confirm: true`; the action and its absence are both tested.
- [ ] One audit row per action names host, catalogue id, version/variant and job id, with no secret and
      no absolute path.
- [ ] A fifth action in a minute is 429; another user is unaffected.
- [ ] Worker-supplied text is scrubbed before it is stored or returned.
- [ ] A guessed host id is 404.

## Notes for the implementer
Put the check in one helper and call it from every route; a second copy is how one route forgets. Audit
on enqueue, not only on completion: a job that fails still had a person ask for it. The rate limit is
per user, not per workspace, so one admin cannot exhaust another's minute.
