## User story
As a developer, I want the key to come from an argument, an environment variable or a one-time login, in that order, so that a notebook, a container and a CI job all work without a config format to learn.

## UX flow (LabelDesk words)
1. **Precedence, documented once** — an explicit `api_key=` argument beats `LABELDESK_API_KEY`, which beats the cached login from `labeldesk auth login`. `labeldesk whoami --verbose` prints which source was used, never the value: "key from environment (8f2c…)".
2. **`labeldesk auth login`** — reads the key from stdin without echoing it, verifies it with `whoami`, then writes `~/.config/labeldesk/credentials.json` with mode `0600` and one line: "Stored for this user. `labeldesk auth logout` removes it."
3. **`[error]` a key that does not resolve** — the client raises `LabelDeskError(0, "no API key: pass --api-key, set LABELDESK_API_KEY, or run labeldesk auth login")` before any request, so a CI job fails in one second instead of after a timeout.
4. **`[empty]` no cached file** — the resolution order skips the file silently; no warning is printed for a path that was never used.
5. **Transport** — the key always travels in the `Authorization: Bearer` header, never in the query string, and `--api-key` is never echoed in `--json` output or in an error message.

## Acceptance criteria
- [ ] The three sources resolve in the documented order and `--verbose` names the one used without printing the key.
- [ ] A missing key fails before any request with the three ways to supply one.
- [ ] The cached file is owner-only on POSIX, and `auth logout` removes it.
- [ ] Empty, loading and error states above all render (client-side: missing key, missing file, refused login).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — a key for another workspace gets the server's 403, unchanged.
- [ ] No flag: additive resolution; an explicit argument behaves exactly as today.

## Notes for the implementer
`~/.config/labeldesk/credentials.json` or `%APPDATA%\labeldesk\credentials.json` — one file, one key, no profiles. Never write the key into a log line, an exception message or `--json` output, which is the mistake that survives the longest in a support ticket.
