## User story
As an enterprise admin, I want our logo, colours and loading image on the sign-in screen without a support ticket, so
that the product looks like ours to staff.

## UX flow (LabelDesk words)
1. No screen in this card. It stores one branding record per workspace: colours, logo reference, loading image
   reference and a revision number.
2. `[empty]` no record → the workspace uses the default LabelDesk theme; the sign-in screen is unchanged.
3. `[error]` an upload is refused when it is an SVG, larger than 2 MB, or not one of PNG/JPEG/GIF/WebP — with a named
   reason before anything is written.

## Backend changes
- Models/schema: new `Branding(workspace_id PK FK CASCADE, tokens JSON, logo_path VARCHAR(255) null,
  loading_path VARCHAR(255) null, revision INTEGER default 1, updated FLOAT)` in `app/models/identity.py` beside
  `WorkspaceFlag`.
- Routers: none in this card.
- Services/jobs: `app/services/branding.py` (new) — `TOKEN_KEYS` (accent, button, card_bg, card_border, wordmark,
  sidebar hover/selected/unselected text and icon, logo border), `ALLOWED_IMAGE = {"image/png": ".png",
  "image/jpeg": ".jpg", "image/gif": ".gif", "image/webp": ".webp"}`, `MAX_BYTES = 2 * 1024 * 1024`,
  `save_tokens(db, ws, tokens) -> Branding` (validates each value as a hex colour), `save_image(db, ws, kind, filename,
  data) -> Branding` (magic-byte check, writes under `DATA_DIR/branding/<ws>/<kind>.<ext>`, bumps `revision`),
  `resolve(db, ws) -> dict` (the payload the sign-in screen reads, with URLs not paths), `defaults() -> dict`.
- Permissions + workspace isolation: writes require `workspace.update`; the files live under the workspace's own
  directory and `resolve` never crosses workspaces.
- Secrets/safefetch: none — no remote image is fetched; an uploaded file is inspected by magic bytes, and SVG is
  refused because it can carry script.
- OpenAPI: no.

## Tests to write first
pytest — `apps/backend/tests/test_branding.py`:
- `test_defaults_when_no_record` — the resolver returns the default tokens and no image URLs.
- `test_svg_is_refused` — `image/svg+xml` → `ValueError` naming SVG.
- `test_oversized_image_is_refused` — 2 MB + 1 byte.
- `test_magic_bytes_must_match_the_extension` — a PNG header with a `.jpg` name is refused.
- `test_upload_bumps_the_revision` — two uploads → revision 2.
- `test_tokens_are_validated_as_colours` — `"red"` and `"#12"` refused.
- `test_branding_is_workspace_scoped` — A's logo path is never returned for B.
- `test_flag_off_returns_defaults_and_refuses_writes`.

## Acceptance criteria
- [ ] One branding record per workspace with a revision that changes on every save.
- [ ] Uploads accept only PNG/JPEG/GIF/WebP under 2 MB, and refuse SVG with a named reason.
- [ ] The resolver returns URLs, never filesystem paths, and defaults when unset.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ defaults everywhere and no write path.

## Notes for the implementer
SVG is refused because it is script-capable, not because of size. Validate by magic bytes — a content-type header from
a browser is a claim, not evidence.
