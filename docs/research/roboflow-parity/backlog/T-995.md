## User story
As an agent, I want the project summary, its class list and two ready-made task prompts as first-class MCP
content, so that I know the class ids and the review rules before I touch a label instead of discovering
them by trial.

## UX flow (LabelDesk words)
1. **`resources/list`** — three URIs: the workspace, a project summary, a project's classes.
   [empty: a workspace with no project lists only the workspace resource]
2. **`resources/read` on `labeldesk://workspace`** — name, plan, credits left, project count, the key's
   scopes, in Markdown a model can read in one glance.
3. **`resources/read` on `labeldesk://projects/{project}`** — the summary: type, image and model counts,
   status counts, and a class table with **ids**.
4. **`resources/read` on `labeldesk://projects/{project}/classes`** — just the class table: id, name,
   colour, image count. [error: an unknown or foreign project is an MCP error naming the URI, never an empty
   `contents` array].
5. **`prompts/list` + `prompts/get`** — `review_low_confidence_labels(project, threshold, limit)` and
   `audit_unannotated_batch(project, batch_id)`. Each returns one user message that carries the data it
   found (image ids, class names, counts) and the next step in words.

## Backend changes
- Models/schema: none.
- Routers: none.
- Services/jobs: `apps/mcp/labeldesk_mcp/meta.py` (new):
  - `register(server, api)` declares the three resources and two prompts (the SDK's `@mcp.resource(...)` and
    `@mcp.prompt()` decorators) and nothing else.
  - Project resources render from `get_project`; the class table renders from the same call, so there is one
    fetch and one shape. The workspace resource renders from `whoami` plus `list_projects`.
  - `review_low_confidence_labels` calls `list_images(sort="review", limit=limit)` and `get_project`, keeps
    the images whose annotations carry `confidence < threshold`, and lists them as `name — class (conf)`.
  - `audit_unannotated_batch` calls `list_images(annotated="no", batch_id=batch_id, limit=1)` for the count
    and `get_project` for the classes, and writes a five-step instruction ending in "run `run_auto_label`
    only after the operator confirms the cost".
  - Both prompts declare their arguments (`project` required, the rest optional with defaults) and never
    echo a raw API payload.
- Permissions + workspace isolation: `read` only; the same `api.call` seam, so a foreign project is the
  route's 404 and is re-raised as an MCP error.
- Secrets/safefetch: `api.scrub` on every rendered value; no `settings` in a resource.
- OpenAPI: no.

## Acceptance criteria
- [ ] Three resources and two prompts are listed and readable through a client session.
- [ ] The class table carries ids, and an unknown project is an error rather than empty content.
- [ ] No rendering contains `settings`, a key, a hash or a storage path.
- [ ] Both prompts end in a confirmable next step and never perform one themselves.
- [ ] Empty, loading and error states above all render as described.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off (T-996) ⇒ the whole endpoint is refused; this card adds no other surface.
- [ ] `ruff check apps/backend` clean; the full serial API suite passes.

## Notes for the implementer
Markdown, not JSON, is the point: a resource is what the model reads to understand the project. Keep each
rendering under ~2 KiB — the class table is the only part that can grow, and a project with 200 classes is a
sign the operator wants `classes` truncated to the 50 most used with a `(+150 more)` line, not paginated.
