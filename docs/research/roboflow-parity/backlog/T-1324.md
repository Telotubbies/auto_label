## Problem
The harness, baseline and frontend gate exist but nothing runs them on a schedule, and a run's numbers
live in a scrollback buffer. The owner cannot see progress across weeks, and a 10 % regression is only
found when someone remembers to run it.

## Design
**`.github/workflows/nightly-perf.yml`** (new) — `schedule: cron "0 3 * * *"`, `workflow_dispatch`, and
**not** referenced by the `gate` aggregator (no `paths` filter, so no required-check limbo):

1. Python 3.11 + CPU torch (same install as the `api` job) + `tools/perf/requirements-perf.txt`.
2. `python tools/perf/seed.py --reset`.
3. Start `uvicorn app.main:app --port 8011` with the seeded `DATABASE_URL`; wait on `/api/readyz` (60 s).
4. `locust --headless -f tools/perf/locustfile.py -u 20 -r 2 -t 5m --csv docs/ops/perf/runs/latest/api`.
5. `npm ci && npm run build` (the build already runs the bundle budget, T-1322), then
   `npx playwright test --project=perf`.
6. `python tools/perf/compare.py --run docs/ops/perf/runs/latest/run.json` (strict only when
   `runner.name` matches the `perf` self-hosted label; otherwise `shared_runner_pct`).
7. `python tools/perf/report.py` → `docs/ops/perf/report-<sha>.md` + `.json`, uploaded as an artefact
   (90 days), and the markdown also printed in the job summary.
8. `if: always()` — the report and logs upload even when the comparison fails, so a red night is
   readable.

**`tools/perf/report.py`** (new, ~110 lines) merges: Locust CSV (p50/p95/p99 per scenario), the Playwright
`vitals.json`, the bundle table, the query counts, the baseline block and the comparison verdict into one
markdown table per budget class plus a one-paragraph summary ("3 classes improved, 1 regressed 14 % —
`list_filtered` p95 690 ms vs baseline 605 ms"). JSON is the same data for `compare.py --run`.

**`tools/perf/run.ps1`** (new, ~20 lines) runs the same chain on the owner's Windows machine, where the
numbers are stable, and writes to the same run directory.

## Tests to write first
`tools/tests/test_perf_report.py`:
- `test_report_lists_every_budget_class` — from fixture CSVs, one row per class.
- `test_regressed_class_is_named_in_the_summary` — the sentence contains the class and the percentage.
- `test_missing_scenario_is_reported_not_omitted` — a scenario absent from the CSV appears as `missing`.
- `test_json_matches_the_markdown_numbers` — same values, so `compare.py` and a human agree.
- `test_report_includes_machine_and_commit`.
- `test_report_is_written_even_when_the_comparison_failed` (exit code is passed through, file exists).
`tools/tests/test_nightly_workflow.py` (same file, two cases):
- `test_workflow_is_scheduled_and_not_in_the_gate` — `on.schedule` present; no `gate` reference.
- `test_workflow_uploads_artifacts_with_if_always`.

## Acceptance criteria
- [ ] The workflow is scheduled, dispatches manually, and is not part of `gate`.
- [ ] A run produces `report-<sha>.md` and `.json` as artefacts within 25 minutes.
- [ ] The report names the runner class (shared vs dedicated) and the threshold used.
- [ ] A failing comparison still uploads the report and prints the delta table.
- [ ] `tools/perf/run.ps1` reproduces the same report locally in one command.
- [ ] The 15-minute merge gate is unchanged by this card.

## Notes for the implementer
Do not add the nightly to `gate`, and do not add a `paths` filter to it: a skipped required check blocks
a PR forever. Cache `npm` and `pip` but not the seeded database. Report percentages to one decimal and
always with the direction ("worse"/"better") — a bare `-14 %` has caused more arguments than any
regression.
