## User story
As a visitor or a teammate, I want to copy a dataset into my workspace and be told exactly why it failed when it does, so that "you already own this" and "you are out of quota" are different answers.

## UX flow (LabelDesk words)
1. **Copy request** — `POST` returns `202 {project: {slug}, job: {id}, poll: "/api/ws/{ws}/projects/{slug}/jobs/{id}"}` or one of the five errors below.
2. **Same-workspace clone** — `Clone` from a project menu copies into the same workspace, sources need `project.read`.
3. **Cross-workspace fork** — the source must be public; the copy records where it came from so a second attempt is refused.
4. **Errors, each with its own code and sentence** (the UI in T-037 renders them): 402 `This workspace is out of image quota or credits.` · 403 `That dataset is not public.` · 404 `No dataset at that address.` · 409 `This workspace already has a copy — open it instead.` · 422 `Name the new project, and start from a dataset address that includes the project.`
5. **Success** — a new project with classes, images, annotations, splits and tags; no versions, models or export settings are inherited.

## Backend changes
- Models/schema: `projects.forked_from VARCHAR(200)` (value `<ws>/<slug>` at fork time), null for an original — `ADD COLUMN` appended to `PROJECTS` in `app/schema/dataset.py`; `Project.forked_from` column.
- Routers: `routers/fork.py` (new), prefix `/api/ws/{ws}/projects`: `POST /{project}/clone` body `{name?: str, target_folder_id?: str | null, cross_workspace?: bool}` → 202 `{project, job, poll}` or the five errors; `GET /{project}/clone/{job}` is unnecessary (the existing project job route serves polling). `POST /api/ws/{ws}/forks` body `{source: "<ws>/<slug>", name: str}` for the public-page path, same errors.
- Services/jobs: `services/fork.py` (new) — `request(db, ctx, source_project, name, folder_id) -> (project, job)` validating in this order: 422 missing name/target → 404 unknown/wrong-workspace-hidden source → 403 cross-workspace and not public → 409 `forked_from` duplicate in target workspace → 402 plan/quota (project cap and image bytes) → create row + `Job(kind="clone", params={source_id, image_ids? })`. `run(db, job)` copies images (new rows, fresh paths, sha256 dedupe inside the new project), classes, annotations via `set_annotations`, splits, tags, and batch names; `handlers/projects.py` (new) registers `{"clone": run_clone}`; `clone` added to `LOCAL_JOB_KINDS`.
- Permissions + workspace isolation: target workspace from `ws_ctx`; `workspace.project.create` required; a source in the same workspace needs `project.read`; cross-workspace sources are read through an explicit `visibility == "public"` check, never the caller's role; the copied project belongs to the target only.
- Secrets/safefetch: none — bytes come from `DATA_DIR`, no network.
- OpenAPI: yes.

## Acceptance criteria
- [ ] A fork/clone returns 202 with a job and produces a project with images, classes, annotations, splits and tags, and no versions or export settings.
- [ ] The five failures return 402/403/404/409/422 respectively, each with its own sentence, and no partial project row is left behind.
- [ ] Empty and error states above all render (a source with zero images still forks into an empty project).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids); the only cross-workspace read is a public source.
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
- [ ] Copied files are independent of the source (no shared paths).

## Notes for the implementer
Validate in the documented order — the first failing check wins the code, so a private source with a taken name is 403, not 409. `forked_from` is a string, not an FK: the source may be deleted later and the copy must survive.
