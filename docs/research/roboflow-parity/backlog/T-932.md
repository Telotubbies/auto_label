## User story
As a workspace member, I want every model to tell me which runtimes can run it and what input it takes, so that an export or a test never fails for a reason I could have read first.

## UX flow (LabelDesk words)
1. **Models** (`/:ws/:project/models`) — the card gains one line under the class count, "Runs on ONNX Runtime and PyTorch · takes an image". [empty: unchanged "No models yet."] [loading: the existing skeleton cards] [error: if the models call fails, the existing inline retry line shows and the card renders without the new line]
2. **Model detail** — a "Runs on" block lists every family runtime for this artefact in a fixed order, each with a state (Ready / Not installed / Unavailable here) and, when not ready, the reason sentence the API returned. A runtime is dimmed with `aria-disabled="true"`, never hidden.
3. **Export** — the format list is filtered by the same table, so a classification model never offers a box-only format without saying why it is gone.

## Backend changes
- Models/schema: none. Capability is derived from `variant`/`task`/`family` on `TrainedModel`.
- Routers: `GET {P}/models/{mid}` in `apps/backend/app/routers/training.py` gains `capabilities: {"runtimes": [{"id", "label", "state", "reason"}], "input_kind", "output_kind"}` on the model dict built by `model_out` (`apps/backend/app/routers/training.py:90`); the list route adds `input_kind` only.
- Services/jobs: `apps/backend/app/adapters/base.py` — `Adapter` gains a `describe(variant) -> dict` member returning `{"input_kind": "image"|"image+prompt"|"text", "output_kind": "boxes"|"boxes+masks"|"labels"|"text", "runtimes": [...]}`; `apps/backend/app/services/capabilities.py` gains `runtimes_for(m, db) -> list[dict]` that reuses `services.runtime_state.describe` for the state and reason.
- Permissions + workspace isolation: `project_ctx` and `project.read` as today; a foreign model id already returns 404 through `_model`.
- Secrets/safefetch: none.
- OpenAPI: yes — `python tools/export_openapi.py`, `npm run gen:api-types`.

## Acceptance criteria
- [ ] Every model in the list shows which runtimes can run it and what input it takes.
- [ ] A runtime that is not installed is present, dimmed and carries the reason; it is never omitted.
- [ ] A classification model never renders a box-only export format as available.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged — no flag here: the three fields are additive and the block renders nothing on its own.

## Notes for the implementer
Overlap: 6-F6.1 → T-310, T-311. Those cards build the *delivery* catalogue; this one describes the *model family*. Do not merge the two lists — T-310's ids are transport (`hosted`, `edge`), these are runtimes (`ultralytics`, `onnx`, `tensorrt`). Runtime order is `RUNTIME_ORDER`, the constant this card adds to `capabilities.py`, never dict order.
