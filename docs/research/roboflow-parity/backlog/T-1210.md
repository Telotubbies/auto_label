## User story
As a workspace admin, I want to invite a teammate, issue a key with the scopes it needs and read what this
month costs, so that access and spend are one screen each and I never overshare a secret.

## UX flow (LabelDesk words)
1. **Settings → Members** (`/:ws/settings?tab=members`) — the roster shows seat, role and last active;
   the invite form takes an email and a role. [empty: "Just you" with the invite action].
2. **Invite** — the pending row appears with the role and a resend/cancel action.
   [error: an existing member says so in place; a seat limit names the limit].
3. **Remove / change role** — the last-admin guard refuses with the reason, not a silent failure.
4. **Settings → API keys** — the table shows name, scopes, last used and a masked value.
5. **Create key** — name and scopes, then the one-time reveal with a copy action and the sentence that it
   will not be shown again. [error: leaving the reveal without copying asks once].
6. **Revoke** — the row's state changes and the reveal never reappears; a revoked key's next call fails
   (asserted in T-1211, not here).
7. **Settings → Usage** — the meter, the cycle and the projection; a saved scenario is named and can be
   reopened.

## Acceptance criteria
- [ ] A pending invite appears with its role; an existing member's email is refused in place.
- [ ] A key is revealed exactly once, copies correctly and is masked afterwards, including after reload.
- [ ] Revoking a key changes its state and removes every trace of the secret from the DOM.
- [ ] Usage shows the meter, the cycle and a projection whose inputs are visible.
- [ ] Steps ≤ 9 and time ≤ 180 s; numbers recorded.
- [ ] Empty, loading and error states: a one-person workspace, a busy invite, a seat-limit refusal, a
      usage fetch failure with a retry.
- [ ] Keyboard only: invite, key create, reveal copy and revoke.
- [ ] No console error and no secret in the console, the trace or the network log after the reveal.
- [ ] Workspace isolation: a key created in A is absent in B; B's key page shows its own only.
- [ ] Flag off ⇒ not applicable; settings has no flag in this card.

## Notes for the implementer
The spec creates a unique invitee and one key per run, then revokes the key. Read the one-time value from
the reveal, use it nowhere, and assert the mask afterwards; a trace containing the plaintext is a test
failure (check the trace attachments in the global teardown).
