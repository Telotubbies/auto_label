## User story
As the person filling a thin class, I want to see the generated examples before they enter a version, reject the bad ones and keep the recipe, so that a synthetic fill is an auditable choice rather than a silent multiplier.

## UX flow (LabelDesk words)
1. **Coverage → a thin class → Add examples** (`/:ws/:project/insights?tab=coverage`) — a dialog with the method line ("Paste real crops using the masks you drew"), a count field (default 40), and the source count read out of the coverage row. [empty: "not enough masks for this class yet" and the button disabled] [error: "this class has no polygon labels — paste needs masks" with the SAM refine link]
2. **Build** — `[loading: "Building 24 of 40 images…" with the job progress]`; the dialog can be closed and the job continues, reported on the tags filter.
3. **Preview** — a strip of generated tiles with the pasted box drawn; each tile can be rejected, and "Regenerate rejected" builds replacements for the current selection.
4. **Accept** — the accepted images stay tagged `synthetic:<recipe>`; rejected ones move to trash; the recipe keeps its created count, accepted count and source ids.
5. **Later** — the Versions page marks a version's manifest with "12 synthetic images" and the dataset filter `tag=synthetic` lists them. [error: a version built before the flag shows no badge, never a wrong count]
6. **Flag off** — no Add examples button, no badge.

## Acceptance criteria
- [ ] A thin row offers Add examples, pre-flights the mask count and builds the requested number with a progress line.
- [ ] Generated tiles can be individually rejected, regenerated and accepted, and the recipe records what was kept.
- [ ] A version holding synthetic images says so, and the dataset filter `tag=synthetic` lists exactly those images.
- [ ] Empty, loading and error states above all render, including too few masks and a class without polygons.
- [ ] Workspace A cannot see workspace B's generated tiles or recipes (project-scoped requests only).
- [ ] Flag off ⇒ no button, no badge, no changed version summary.

## Notes for the implementer
Show the pasted box on every tile — a synthetic example that hides its own annotation is impossible to judge. Rejection is a trash move, not a hard delete, so a wrong click is recoverable. Never let the dialog offer a "render job" method: there is no renderer in this product yet, and an option that cannot run is worse than one method.
