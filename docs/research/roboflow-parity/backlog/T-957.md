## User story
As a workflow author, I want to mark one of my steps as a named span, so that my custom block shows up in the
trace under the name I chose instead of disappearing into the parent.

## UX flow, click by click.
1. **A workflow block** — the block editor's code/config pane gains one line in its help text: "steps you mark
   appear in the trace under the name you give". (No new screen.)
2. **The trace** — the marked step appears as its own span with its parent, name, duration and state; its
   arguments and return value are recorded as attributes. [empty: a step that returned nothing records
   "no output" rather than an empty attribute]
3. **A failing step** — the span is *error*, the exception class and message are stored, and the parent trace
   keeps running so the rest of the chain still reports.
4. **Truncation** — an argument over 4 KB is stored truncated with `truncated: true` and the byte count; the
   full value is never written. [error: a span opened outside any trace is created as its own root trace,
   never dropped]

## Backend changes
- Models/schema: none — spans reuse T-954's tables.
- Routers: none.
- Services/jobs: `apps/backend/app/services/tracing.py` gains `@traced(name=None)` and
  `with span(name, **attrs):`, both built on T-954's context, working for sync, async, generator and
  async-generator functions (one `inspect` check selects the wrapper); parent-child is detected from a
  `ContextVar` so threads and async tasks inherit it, and a call with no active trace starts a root trace of
  kind `manual`. Attributes go through `_trim(value)` which serialises with `json.dumps(..., default=str)`,
  truncates at 4 KB and sets `truncated`.
- Permissions + workspace isolation: inherited from the trace; a manual trace records the caller's
  `workspace_id` and `project_id` from the request context, and refuses (no-op, logged) without one.
- Secrets/safefetch: none. Dependency: none added (no `mlflow-skinny`), so no
  `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: no.
