## User story
As an outgoing shift supervisor, I want the open NG units, the reworks due, the dead cameras and the alerts nobody acknowledged counted for me, so that I type two lines of what a machine cannot know and the incoming shift reads one message instead of asking me in the car park.

## UX flow (LabelDesk words)
1. **`ส่งกะ`** (`/:ws/:project/ops/handover`) — the page opens on the shift that is ending, with the blocks already filled: `งานค้าง`, `ส่งซ่อม`, `กล้องออฟไลน์`, `แจ้งเตือนที่ยังไม่รับทราบ`, `ผลผลิตกะนี้`. [empty: `ยังไม่มีงานค้างในกะนี้` and the send button stays enabled, because "nothing open" is a brief worth sending] [loading: `กำลังรวบรวมสรุปกะ`] [error: `รวบรวมสรุปไม่สำเร็จ — ลองอีกครั้ง`]
2. **Each block links into the thing it counts** — `งานค้าง 4` opens the event list filtered to undecided units; `กล้องออฟไลน์ 1` opens that camera. [error: a block that cannot be counted reads `นับไม่ได้ — เปิดดูรายการ` rather than `0`]
3. **`หมายเหตุถึงกะถัดไป`** — a two-line free-text box, capped at 500 characters, saved with the brief.
4. **`ส่งเข้ากลุ่ม LINE`** — the brief is written to the shift log and pushed to the chosen channel; the page then shows `ส่งแล้ว · {time} · {channel}`. [loading: `กำลังส่งสรุปกะ`] [error: `ส่งไม่สำเร็จ — กลุ่ม LINE ยังไม่ได้ตั้งค่า` with a link to Settings → Alerts]
5. **The next shift** — its brief opens with a `สืบเนื่องจากกะก่อน` block listing the items still open from the previous brief.

## Backend changes
- Models/schema: `app/models/handover.py` (new) — `HandoverBrief(id, workspace_id, project_id, shift, work_date, since, until, blocks, notes, channel_id, status, sent_by, sent_at, created)` with `Index(project_id, work_date)`; `status` `draft|sent`; `blocks` JSON. Register the module in `models/__init__.py`; `create_all` makes the table, no `ADD COLUMN`.
- Routers: `app/routers/handover.py` (new), prefix `/api/ws/{ws}/projects/{project}/handover`, `dependencies=[Depends(require_flag("task_shift_handover"))]`; `GET "/preview?date&shift&tz_offset"` → `{shift, window, blocks: [...], carried: [...], yield, notes}`; `GET ""?month=` → the briefs of the month; `POST "/send"` `{date, shift, tz_offset, notes, channel_id}` → 201 `{id, status: "sent", sent_at}`; 400 `LINE group not configured` when the channel is missing or not `kind == "line"`, 422 for a bad date, a shift outside the station's codes or a note over 500 characters, 404 for a foreign channel.
- Services/jobs: `app/services/handover.py` (new) — `shift_window(db, project, station, date, shift, tz_offset)` importing `window_for` from `services/shift.py`, `blocks(db, project, window) -> list[dict]` (open NG units from T-710, reworks due inside the window, streams whose `status` is not running, alert deliveries with no acknowledgement from T-714), `carried(db, project, previous)` and `send(db, brief, channel, user_id)` calling `alerts.send(db, channel, event)` with the rendered Thai text — no second transport. No job.
- Permissions + workspace isolation: `project.streams` to preview and send (a manager or reviewer runs a shift); the channel must belong to the same workspace, and a project or channel id from another workspace is 404 before any send.
- Secrets/safefetch: `services/secretbox.py` — the LINE channel token is decrypted by `alerts.send` exactly as it is today; this card adds no secret, fetches no URL and calls no `safefetch` function of its own.
- OpenAPI: yes — three routes.

## Acceptance criteria
- [ ] The brief is filled from the shift's own state — open NG, reworks due, cameras offline, unacknowledged alerts, yield — with a link behind every count.
- [ ] A quiet shift still produces a brief, and the note is saved with it.
- [ ] Sending writes the brief to the shift log and pushes exactly one LINE message; without a channel it refuses and writes nothing.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see workspace B's channel, camera or brief (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no route, no nav item, no brief row and no outbound message.

## Notes for the implementer
R7: the message leaves the deployment, so it carries counts, the shift code, the lot numbers and the supervisor's display name — never a snapshot URL with a signature in it, and never a person's phone number. Retention: the brief row is kept with the project (swept by `services/retention.py` under `retention_days`); the LINE delivery row is the one `alerts` already keeps. If the renderer cannot reach the channel, the safe state is the 400: a brief that silently did not send is worse than one that asked for a channel.
