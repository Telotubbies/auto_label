## User story
As a person signing up, I want to name my workspace and see the link it will get before I submit, so that my team's address is right the first time instead of a derived name I have to live with.

## UX flow (LabelDesk words)
1. **Create account** (`/signup`) — the existing form. The "Workspace name" field gains a second line under it: `Your workspace link: /acme` with a status word. [empty: name blank → line shows the address that will be derived from the account name, greyed] [loading: `Checking…` while the debounced check runs] [error: `Taken — try acme-2` as a clickable suggestion that fills the name field, or `Use letters, numbers and dashes`].
2. **First run without a workspace** (`/` while `/me` lists no workspace) — the same one-form screen, now a shared component rather than a bare card: name, derived link line, primary "Continue". [loading: button keeps its width and reads `Creating…`] [error: inline `That address is taken` above the button, the typed name preserved].
3. **Landing** — submit creates account + workspace in one request and lands on `/:ws` (the assistant home once T-016 ships). No plan step here; that is T-011.

## Backend changes
- Models/schema: none. `workspaces.slug` is unique and already set by `unique_ws_slug` (`app/routers/auth.py:46`).
- Routers: `GET /api/workspaces/slug?name=<str>` (bearer required) → `{"slug": "acme", "available": true}`; 422 when the derived slug cannot satisfy `^[a-z0-9][a-z0-9-]{2,39}$`. `POST /api/workspaces` (`auth.py:482`) accepts an optional `slug`; 409 `{"detail": "that address is taken", "suggestion": "acme-2"}`; 422 for a reserved segment (`models`/`deployments`/`activity`/`settings`/`audit`/`admin`/`legal`/`qa` — same set as `RESERVED_WORKSPACE_SEGMENTS`).
- Services/jobs: `slugify_workspace(name)` and `slug_taken(db, slug)` live beside `unique_ws_slug` in `auth.py`; no new module.
- Permissions + workspace isolation: signed-in user only; the check returns availability and one suggestion, never another workspace's name or id. `POST /workspaces` keeps its current rule (any signed-in user may own one) and always creates a fresh workspace.
- Secrets/safefetch: none.
- OpenAPI: yes — one new GET and a widened `WorkspaceIn`.

## Frontend changes

## Acceptance criteria
- [ ] Signup and first-run both show the workspace link before submit and the link matches the created slug exactly.
- [ ] A taken or reserved address blocks submit with the suggestion inline; the typed name survives the error.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids); the slug check names no other workspace.
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged (plain name field, derived slug).

## Notes for the implementer
Slug cap is 80 characters in the column but the UI allows 40; refuse rather than truncate. The suggestion is always `<slug>-2`, incremented until free, one candidate only.
