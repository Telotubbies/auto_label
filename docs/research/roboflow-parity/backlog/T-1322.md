# T-1322 — Bundle budget: a ceiling per chunk in the existing build

| Field | Value |
| --- | --- |
| Wave | O (security, monitoring, performance) |
| Area | Performance |
| Size | 2 agent-hours |
| Role | R4 frontend + R13 performance engineer |
| Skills | ponytail, test-driven-development, react-best-practices, verification-before-completion |
| R7 security review | no |
| Depends on | T-1318 (the bundle section of `budgets.json`) |
| Feature flag | none |

## Problem
`vite build` prints chunk sizes and nothing reads them. `package.json` carries `echarts`,
`echarts-for-react`, `recharts`, `konva` and `react-konva`; one careless static import can double a
route's first paint with no gate to notice.

## Design
- `apps/frontend/vite.config.ts`: `build.manifest = true` (one line) so chunk identity is machine-readable.
- `apps/frontend/scripts/check-bundle.mjs` (new, ~60 lines): reads `dist/.vite/manifest.json` and
  `dist/assets/*.js`, computes **gzip** sizes, groups chunks into `entry`, `route` (dynamic imports) and
  `shared`, and compares against `budgets.json` → `bundle`. Prints a table
  (`chunk, kind, raw KB, gzip KB, budget, verdict`) and exits 1 on any overrun. A manifest without a
  matching asset file fails loudly (no silent pass).
- `package.json`: `"budget": "node scripts/check-bundle.mjs"`, and `build` becomes
  `gen-api-types --check && tsc -b && vite build && node scripts/check-bundle.mjs` — the ceiling fails
  the same command a developer already runs.
- `.github/workflows/ci.yml` web job: no new step needed (the build runs the check); add one line to the
  job comment so the failure mode is discoverable.
- If the current bundle already exceeds a ceiling, the card's RED step reports the real numbers and the
  PM decides: raise the ceiling (recording why) or split the import. The card does not silently accept.

## Files
Exclusive:
- `apps/frontend/scripts/check-bundle.mjs` (new)
- `apps/frontend/tests/bundle-budget.test.mjs` (new)
Shared (one line each):
- `apps/frontend/vite.config.ts` — `build.manifest = true`
- `apps/frontend/package.json` — `budget` script + `build` chain
- `.github/workflows/ci.yml` — one comment line (no behaviour change)

## Tests to write first
`apps/frontend/tests/bundle-budget.test.mjs` (node:test, pure functions over fixture manifests):
- `test_entry_within_budget_passes` / `test_entry_over_budget_fails_with_the_number`.
- `test_route_chunk_over_300_kb_fails`.
- `test_a_single_chunk_over_500_kb_fails_even_if_it_is_shared`.
- `test_cold_route_total_sums_entry_plus_route_plus_shared`.
- `test_missing_asset_for_a_manifest_entry_fails`.
- `test_gzip_size_is_used_not_raw_size` (a 900 KB raw / 200 KB gzip fixture passes).
- `test_budgets_come_from_the_json_file_not_a_literal`.

## Acceptance criteria
- [ ] `npm run build` fails when a chunk exceeds its class ceiling, with a table naming the chunk.
- [ ] Sizes are gzip, from the real manifest, on the real build.
- [ ] The failure message says which import to look at when the chunk maps to one route.
- [ ] Build time grows by < 1 s.
- [ ] The first run's numbers are in the report; any ceiling change is a PM decision, not a silent edit.

## Notes for the implementer
Do not add `rollup-plugin-visualizer` to the gate. Do not count CSS in the JS budget (report it
separately in the table for information). The cold-route total is entry + that route's chunk + shared
chunks it imports — compute it from the manifest's `imports`, not by guessing.
