## User story
As a visitor, I want to browse the public datasets on this deployment by type, size and whether a model exists, so that I can find reusable data without an account.

## UX flow (LabelDesk words)
1. **Discovery** (`/datasets`, signed out) — result list of public datasets: name, one-line description, type, `128 images`, `2 models`, licence chip, workspace name, class chips (max 6 + `+4`).
2. **Filters** — type, image-count band (`<100`, `100–1k`, `1k+`), `Has a trained model`, licence, sort (`Newest`, `Most images`, `Name`). One filter bar, one popover.
3. **Search** — free text over name + description. [empty: no public datasets at all → `No public datasets on this deployment yet. Publish one from a project menu.`; no match → `No datasets match these filters.` + `Clear filters`] [loading: 6 skeleton rows] [error: `Could not load public datasets — Retry`].

## Backend changes
- Models/schema: none — reads `projects`, `classes`, `trained_models`.
- Routers: `routers/discovery.py` (new), prefix `/api/public`: `GET /datasets` with `q, type, band, has_model, license, sort, cursor, limit` (≤48) → `{total, items: [{slug, workspace, name, description, type, images, models, classes: [names], license, created}]}`; no auth dependency; `Cache-Control: public, max-age=60`.
- Services/jobs: `services/discovery.py` (new) — `listing(db, params)` filters `visibility == "public"`, `deleted_at IS NULL`, and the workspace policy when it exists (7-F7.60 adds `allow_public_projects`; read it defensively with `getattr(ws, "allow_public_projects", True)` and leave a comment naming that card); `visible_fields(...)` drops everything not in the payload above.
- Permissions + workspace isolation: anonymous; **no** image bytes, internal ids, member names, file names or model weights in the payload — only the listed fields. A private project never appears, even by exact slug.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Frontend changes
- Client only: `discoveryApi.datasets(params)` in `src/lib/api/discovery.ts` (new). The page is T-031.

## Acceptance criteria
- [ ] Anonymous GET lists public projects only, with the documented field set and nothing else.
- [ ] Type, size band, has-model, licence and text filters all narrow the same total that paging uses.
- [ ] Empty and no-match are distinguishable (`total == 0` with and without filters is reported by the client).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids); here, a private project is invisible even by exact slug.
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
- [ ] A request for a private slug returns 404 on the detail endpoint (T-035), not "private".
