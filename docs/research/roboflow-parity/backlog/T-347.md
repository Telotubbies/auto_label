## User story
As an operator, I want to know which capture knob actually changes the picture for my camera type, so that lowering the frame rate in the app is not a silent no-op.

## UX flow (LabelDesk words)
1. **Stream detail → Zones & rules → "Capture"** — for an uploaded clip, one `Sample rate` control and one sentence: "Frames per second analysed from the file. The file itself is never re-encoded." For a camera URL, the section is read-only: "This camera sends an encoded stream; we do not re-encode it. Change the resolution and frame rate in the camera, then restart the stream." [empty: no capture info yet → the section shows the sentence and a disabled control] [loading: none] [error: a refused sample rate → inline "Use 0.5 to 30 frames per second." and the value reverts]
2. **A discovered (ONVIF) camera** — one extra button, "Read camera settings", that lists the profiles the camera reports and their resolution; the app does not offer to change them, and says so.
3. **Codec guidance** — one collapsible note: "For browser playback the camera should send H.264 baseline without B-frames. Another codec still records events; playback in the browser may not work."
4. **Applying** — saving a sample rate warns "This restarts the stream." once, because the worker reopens the capture.

## Acceptance criteria
- [ ] Each source kind shows the settings that apply to it and states the ones that do not.
- [ ] A camera URL shows no editable rate, one sentence explaining where to change it, and the codec note.
- [ ] A refused rate is refused inline and the stored value does not change; an applied change warns about the restart.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: a section inside the stream page, gated by `task_10b` with it.

## Notes for the implementer
Do not offer to write camera settings: applying them can restart the stream and a failed apply leaves the camera on its last settings, which is a support call nobody can debug. Reading profiles is enough to answer "what resolution am I actually getting".
