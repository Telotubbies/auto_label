## User story
As an integrator, I want to decide which fields my endpoint returns and in what order, so that the response contract is something I designed rather than something I discovered.

## UX flow (LabelDesk words)
1. **Canvas → Outputs node** — a list of candidate outputs, one row each: `detections`, `texts`, `events`, `image` (when a visualisation block exists). Each row has a drag handle, an eye toggle (include / exclude) and "Move up" / "Move down" buttons so the order is reachable by keyboard. [empty: only one model block → the list holds `detections` alone and says "Add a visualisation block to return an image."] [loading: the node paints three rows and fills them] [error: a saved order that names a field the graph no longer produces → the row is dropped on load with one line, "`image` was removed with its block."]
2. **Order is the response order** — after a run, the JSON tree renders in that order, and the response body's key order matches, so a diff between two runs is readable.
3. **Visual toggle** — the eye shows the larger render beside the JSON instead of under it; it is a view preference and never changes the payload.
4. **Contract** — `GET /workflows/{id}` returns `outputs` in the chosen order with `included: true|false`, and the invoke endpoint (T-316) returns only the included fields.

## Acceptance criteria
- [ ] The Outputs node lists every produced field, reorders by drag and by keyboard, and excludes with the eye.
- [ ] A run returns exactly the included fields in the saved order; an excluded field is absent.
- [ ] A field whose block was removed is dropped on load with one explanatory line, and the last included field cannot be excluded.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: a workflow saved before this card returns today's four keys.

## Notes for the implementer
`image` is only ever a candidate when a visualisation block produces it; the eye is a payload switch, the "larger render" toggle is a view switch and must not be stored in the definition.
