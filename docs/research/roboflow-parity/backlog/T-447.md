## User story
As an agency owner, I want my client workspaces grouped under one organization, so that I can compare them without an
operator's console.

## UX flow (LabelDesk words)
1. No screen in this card. It stores organizations and the link from a workspace to one organization.
2. Membership is derived, never stored twice: a person sees an organization when they hold `owner` or `admin` in at least
   one linked workspace, and the rollup only ever includes workspaces where they are a member.
3. `[empty]` no organization → every workspace behaves as today and no org route exists for it.
4. `[error]` linking a workspace that is already linked is a `409`; a link to another organization's workspace is a 404.

## Backend changes
- Models/schema: new `app/models/organization.py` (new) — `Organization(id, name VARCHAR(120) unique,
  created_by VARCHAR(32) null, created FLOAT)`; and `Workspace.organization_id: str | None`
  (`ForeignKey("organizations.id", ondelete="SET NULL")`, indexed) via `ADD COLUMN` in `app/schema/identity.py`.
- Routers: none in this card.
- Services/jobs: `app/services/organization.py` (new) — `create(db, name, actor) -> Organization`,
  `link(db, org, ws, actor)` (one org per workspace), `unlink`, `orgs_for_user(db, user) -> list[dict]`,
  `can_read(db, org, user) -> bool` (owner/admin in ≥1 linked workspace **and** a member of every workspace it returns),
  `workspaces_in(db, org) -> list[Workspace]`.
- Permissions + workspace isolation: linking requires `workspace.update` on the workspace **and** `can_read` on the
  organization; `can_read` is the only gate the later endpoints use.
- Secrets/safefetch: none.
- OpenAPI: no (no route).

- Feature flag: `task_org_rollup`; off ⇒ no organization rows are created or read.

## Acceptance criteria
- [ ] Workspaces can be grouped under one organization, one organization per workspace.
- [ ] Read access is derived from workspace roles and never from a stored org membership.
- [ ] Unlinking changes nothing about the workspace's data or members.
- [ ] Empty, loading and error states above all render (no org, duplicate link).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no organization rows created and no reads.

## Notes for the implementer
No `OrganizationMember` table: the membership that matters already exists as `Member`. Duplicating it would create two
answers to "can they see this org".
