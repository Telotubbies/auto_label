## User story
As the QA and usability lanes, I want one e2e harness that starts the real app with deterministic fake
workers, signs in, counts steps and time, enables a card's flags and runs axe, so that every journey spec
is a page of intent instead of a page of setup.

## UX flow (LabelDesk words)
1. **`npm run e2e`** — the smoke set starts the API through `apps/backend/e2e/app.py` and the web dev
   server, seeds the demo workspace, and runs every spec not tagged `@nightly`, under 10 minutes.
2. **`npm run e2e:nightly`** — the same servers, every spec including `@nightly`.
3. **A spec** — `signIn(page)`, `seeded.project`, `setFlags(request, ['task_470'])`, `record.step()` and
   `record.done()` from one import.
4. **A gated surface** — `setFlags` turns it on for the workspace before the first navigation.
   [error: an unknown flag answers 404 and the helper fails with the key named].
5. **A fake job** — training, auto-label, export and version jobs finish in under 200 ms with
   deterministic rows, so the job tray, progress and result pages are visible without a GPU.
6. **A missing backend** — the spec fails with the API log path in the message, not a timeout.

## Backend changes
- Models/schema: none.
- Routers: none.
- Services/jobs:
  - `apps/backend/e2e/app.py` (new): imports `app.main:app`, installs the fakes, and refuses to start
    unless `LD_E2E=1` and `LD_ENV` is not `production`. It is **outside the `app` package** on purpose:
    no fake code ships in the API image.
  - `apps/backend/e2e/fakes.py` (new): one deterministic `Adapter` (boxes and polygons derived from the
    image size, `validate_prediction`-clean), and instant handlers for `version`, `export`, `train`,
    `autolabel`, `infer_video`, `export_engine`, `extract_frames`, `engine_apply`, `model_pull`,
    `health`. Each writes the same rows the real handler writes and a three-line job log; `train` writes
    a metrics JSON with fixed mAP values so Compare has numbers.
  - The entrypoint swaps `worker.HANDLERS[kind]`, `worker.ADAPTERS` and `worker.scheduler` — the seams
    the pytest suite already uses — and nothing in `app/` changes behaviour.
- Permissions + workspace isolation: unchanged; the fakes run inside the same request context.
- Secrets/safefetch: no outbound request; the fake adapter never calls `safefetch`.
- OpenAPI: no.

## Tests to write first

- `test_the_fake_adapter_names_no_network` — no `requests`, `httpx`, `urllib` or socket in `fakes.py`.

node — `apps/frontend/tests/e2e-harness.test.mjs` (new):
- `test_record_counts_one_step_per_action` — fake clock and a stub page: three actions give three steps,
  time is the sum of the recorded deltas.
- `test_record_fails_on_a_missing_target` — a journey over its step or time target returns a failure.
- `test_setFlags_names_an_unknown_key` — a 404 message carries the flag key.

## Acceptance criteria
- [ ] `npm run e2e` passes on a clean checkout and finishes under 10 minutes; `npm run e2e:nightly` runs
      the tagged specs.
- [ ] The API starts only with `LD_E2E=1` and never with `LD_ENV=production`; no fake module is imported
      by `app.main`.
- [ ] `signIn`, `setFlags`, `record`, `axe`, `stubApi` and the seeded ids are importable from
      `e2e/fixtures/harness.ts`; a spec starts with one import.
- [ ] A fake train run completes in under 200 ms and its model appears on Compare with fixed metrics.
- [ ] No GPU, vLLM, SAM, network import or Ollama is touched; the socket test in the harness proves it.
- [ ] `core-loop.spec.ts` still passes unchanged with the new config.
- [ ] Empty, loading and error states: the harness can force each through `stubApi` and a delayed route.
- [ ] Flag off ⇒ `setFlags` is a no-op and the surface stays absent; the helper asserts the 404 for an
      unknown key.
- [ ] Workspace isolation: the harness never widens the seed; font and fixture paths stay inside `e2e/`.
- [ ] `ruff check apps/backend` clean; the full serial API suite passes.

## Notes for the implementer
The e2e entrypoint is the only new executable path. Keep the fakes boring and deterministic: same ids,
same boxes, same metrics on every run. MJPEG is a `page.route` fulfilment from `frame.jpg`, not a real
stream — the stream journey asserts the UI contract, not capture.
