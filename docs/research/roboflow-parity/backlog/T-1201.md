## User story
As a new buyer, I want to create an account and start a workspace without reading help, and as a
returning user I want a wrong password to cost me nothing but one retry, so that the first minute of the
product is the product, not a form.

## UX flow (LabelDesk words)
1. **Landing** (`/`) — the primary "Start free" opens **Create account**; "Log in" opens the login page.
2. **Create account** (`/signup`) — Full name, Work email, Password, Workspace name; the submit is busy
   while it runs and keeps its width. [empty: fields start empty] [error: a duplicate email says so next
   to the field, not in a toast].
3. **Workspace home** (`/:ws`) — the new account lands on its own empty workspace with one next step.
   [empty: the designed first-run state, not a blank page].
4. **Dev inbox** (`/__mail`) — the verification mail is the only message; its link returns to the app and
   says the address is verified.
5. **Sign out, sign in** (`/login`) — email + password; a wrong password shows one alert and keeps the
   email; the right one lands on the workspace.
6. **Forgot password** — the form confirms "if that address exists, a link was sent" and never reveals
   whether the account exists.

## Acceptance criteria
- [ ] The full round trip works on a clean seed: signup, verify from `/__mail`, sign out, wrong password,
      correct password.
- [ ] Steps ≤ 10 and time ≤ 240 s on the reference machine; the measured numbers are recorded.
- [ ] A duplicate email and a wrong password each show one inline error and keep the typed value.
- [ ] No console error or page error at any step; no horizontal scroll at 375 on `/signup` and `/login`.
- [ ] Empty, loading and error states above all render; the busy submit keeps its width.
- [ ] Keyboard only: every field and button reachable in order, focus visible.
- [ ] Workspace isolation: not this card's surface — the spec uses a unique email per run and deletes
      nothing it did not create.
- [ ] Flag off ⇒ not applicable: the auth surface has no flag; the spec asserts it is reachable with every
      flag off.

## Notes for the implementer
Read the verification link from `/__mail` as text; do not mint a token or call the verify route directly.
A unique email per run (`j1+<runId>@labeldesk.dev`) keeps repeat runs honest; the seed is not reset
between specs.
