## User story
As an agent host, I want to start one command that speaks MCP over stdio with my workspace key, so that the
agent sees the tools my key may use and nothing else — and never sees the key in its transcript.

## UX flow (LabelDesk words)
1. **Agent host config** — the operator adds `labeldesk-mcp` with `LABELDESK_API_KEY` and `LABELDESK_URL`.
   [error: no key → exit 2 and one stderr line `LABELDESK_API_KEY is not set`; never a prompt, never a
   stdout frame before the protocol starts].
2. **Handshake** — the host lists tools. `whoami` and `list_projects` appear for a `read` key; a tool whose
   scope the key lacks is **absent**, not present-and-403. [loading: the first list costs one local
   `/whoami` call, cached for that request] [error: a revoked key fails the list with one readable message
   `invalid api_key (HTTP 401)`].
3. **A tool call** — the agent calls `list_projects` and gets the same rows `/api/v1/projects` returns.
   [empty: a workspace with no project answers `[]`] [error: an API failure comes back as a tool result
   with `isError: true` and the API's own sentence, so the model can act on it].
4. **Any output** — no key, no hash, no project `settings`, no storage path.

## Backend changes
- Models/schema: none.
- Routers: none (the tools call `/api/v1`, which T-990 and T-991 extend).
- Services/jobs: the new app in `apps/mcp/`:
  - `labeldesk_mcp/api.py` — the one seam between MCP and LabelDesk:
    `Api(base_url=None, transport=None)`; `key()` returns the current key (`ContextVar`, falling back to
    `LABELDESK_API_KEY` only for stdio); `use(key)` sets it; `call(tool, operation, path_params=None,
    params=None, json=None, files=None, data=None)` builds a `LabelDesk(...)` for that key, sends
    `x-mcp-tool: <tool>` and `x-mcp-client: labeldesk-mcp/0.1.0` on every request, and turns a
    `LabelDeskError(status, detail)` into `ToolError(f"{detail} (HTTP {status})")` — a 0 status becomes
    `ToolError("cannot reach LabelDesk — check LABELDESK_URL")`;
    `scopes()` caches `whoami()["scopes"]` for the current request, and `enabled()` caches
    `whoami()["mcp"]` — the workspace's `task_992` switch, which every tool consults before calling the
    API and refuses with `ToolError("the MCP endpoint is not enabled for this workspace")` when off;
    `scrub(value)` drops the keys `settings, hash, sha256, password, token, secret, api_key, credentials`
    recursively and truncates strings over 8 KiB.
  - `labeldesk_mcp/server.py` — `build_server(api: Api) -> MCPServer` named `LabelDesk`, with instructions
    that say: this is a labeling product, ids are the API's ids, `project` is a slug, and a tool that
    spends credits refuses without `confirm: true`. `TOOL_SCOPES: dict[str, str]` is the registry every
    toolset appends to; `list_tools()` is overridden to drop a tool whose scope is not in `api.scopes()`.
    Two tools today: `whoami()` and `list_projects()`.
  - `labeldesk_mcp/__main__.py` — `main(argv=None)`: `--url`, `--api-key` (falls back to the environment),
    `--version`; stdio only in this card. Exit 2 with one stderr line when no key is available, exit 0 on
    a clean stdin close. Nothing but MCP frames on stdout.
  - `apps/mcp/pyproject.toml` — `name = "labeldesk-mcp"`, `requires-python = ">=3.11"`,
    `dependencies = ["mcp>=2.3,<3", "labeldesk-sdk", "httpx>=0.27"]`,
    `[project.scripts] labeldesk-mcp = "labeldesk_mcp.__main__:main"`.
- Permissions + workspace isolation: the key is the only identity; `scopes()` comes from the API, never from
  a local list; a tool absent from `tools/list` is still refused by the API if called directly.
- Secrets/safefetch: the key lives in a `ContextVar` and in `os.environ`, is never logged, never put in a
  tool result, and never written to a file. No URL is fetched by this process.
- OpenAPI: no.

## Notes for the implementer
One seam, two adapters: stdio reads the key from the environment once, HTTP (T-996) sets the same
`ContextVar` per POST; the in-memory tests set it directly. Do not add a third path.
`mcp` v2 renamed `FastMCP` to `MCPServer` and moved transport options onto `run()`/`streamable_http_app()`
(<https://py.sdk.modelcontextprotocol.io/migration/index.md>) — every v1 snippet on the web is wrong here.
`list_tools()` is the documented filter hook; the test above is the contract, so if the installed version
calls something else, override that instead and say so in the report.
`labeldesk-sdk` is not on PyPI: install it first (`pip install -e packages/sdk`) and `pip install -e
apps/mcp` resolves the name from the installed distribution. The suite imports the app by path, so CI needs
neither install.
`mcp` 2.x pulls `httpx2` alongside the SDK's `httpx`; they coexist, but do not hand an `httpx.Client` to
anything the MCP SDK expects (the SDK wants `httpx2` types) — the two clients never meet in this design.
