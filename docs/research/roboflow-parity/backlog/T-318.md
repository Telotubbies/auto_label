## User story
As whoever gets paged, I want one table that says what a failure means, whether retrying helps and whether it was billed, so that I stop guessing at two in the morning.

## UX flow (LabelDesk words)
1. **Deploy & test → "If a call fails"** — a collapsible section under the endpoint card. Two blocks: a status table and a go-live checklist. [empty: never empty] [loading: none — static text] [error: none]
2. **The status table** — four columns: *Code*, *What happened*, *Retry?*, *Billed?*. Rows: `400` bad payload — no — no; `401/403` key missing or out of scope — no, fix the key — no; `404` model or workflow not in this workspace — no — no; `402` plan allowance used up — no, upgrade or wait — no; `409` state conflict (alias not deployed, stream stopping) — yes after the state settles — no; `413` over 20 MB — no, resize — no; `422` a declared input is missing — no — no; `429` rate limited — yes, with backoff and jitter — no; `500/502/503` our side or a model that is not loaded — yes, with backoff — yes if the model ran.
3. **Backoff rule** — one sentence plus one 6-line Python block: retry only `429` and `5xx`, exponential from 0.5 s, cap 30 s, full jitter. Copy button on the block.
4. **Go-live checklist** — six tick lines the buyer can read against their own client: a timeout longer than a cold start (`x-model-cold-start`, T-317); retries only on `429`/`5xx`; images under 20 MB; the key from the environment, never the source; one warmup before a demo; a drift check scheduled.
5. **Where the numbers come from** — the "Billed?" column must agree with `config.CREDIT_COST` and `services/metering.py`; the card links to T-349's rate table rather than restating prices.

## Tests to write first
pytest — `none: no backend surface`.
node — `apps/frontend/tests/deploy-errors.test.mjs`:
- `test_every_documented_code_is_a_code_the_api_returns` — the set of `STATUS_ROWS[].code` equals the set the OpenAPI document lists for the predict and invoke routes (`401, 402, 404, 413, 422, 429, 500, 503` plus `400, 409`), read from `apps/frontend/src/lib/api-types.gen.ts` fixture text.
- `test_only_429_and_5xx_are_marked_retryable` — the `retry` column is a closed vocabulary and never says yes for `4xx` except `409` and `429`.
- `test_a_billing_question_is_answered_for_every_row` — each row's `billed` is one of "no", "yes", "yes if the model ran" — never empty.
- `test_the_backoff_snippet_retries_only_those_codes` — the generated Python contains `if r.status_code == 429 or r.status_code >= 500` and a `random.uniform` jitter.
- `test_the_checklist_covers_the_six_go_live_items` — six ids, each text present and unique.

## Acceptance criteria

## Notes for the implementer
Keep the table to the ten codes above; a code the API does not return is a lie the first support ticket will find. `409` is retry-after-state-change, not a blind retry — say so in the cell.
