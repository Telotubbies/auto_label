## User story
As an admin running several projects on two GPUs, I want jobs to name a pool with a priority and a per-workspace concurrency cap, so that an auto-label job does not wait behind a twelve-hour train and the team can see who is ahead.

## UX flow (LabelDesk words)
1. **Submission** — a train or auto-label job carries `pool_id` and `priority` (interactive / normal / overnight); the API refuses a pool that does not belong to the workspace. [error: an unknown pool is 422 naming it; a full quota is 409 "This workspace can run {n} GPU jobs at once." with the running job's id]
2. **Claim** — a worker only claims jobs whose pool matches its own advertised pool, highest priority first, then oldest. [loading: a job waiting because its pool has no online worker stays `queued` and says so in T-799]
3. **Quota** — the workspace cap (`quotas['gpu_concurrency']`, default 1) is counted across its running jobs; a cap of 1 with one running job leaves the second queued, never rejected.
4. **Interrupt** — an admin may interrupt a running job to free the pool: it is marked `preempted`, the run stops at the current epoch, and the job returns to `queued` carrying `resume_from` when a ready checkpoint of the same variant exists. [error: interrupting a job that already finished is 409]
5. **A preempted job** — on its next claim it resumes rather than restarting from scratch, and the model record is the same one.

## Acceptance criteria
- [ ] A job names a pool and a priority, and the scheduler claims by pool then priority then age.
- [ ] A per-workspace concurrency cap keeps the extra job queued and states the cap.
- [ ] Interrupting a running job returns it to the queue with its checkpoint reference instead of failing it.
- [ ] Empty, loading and error states above all render as API states: a pool with no worker never claims, a terminal interrupt is a stated conflict.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ creation-order claiming and today's job submission, with no pool fields read.

## Notes for the implementer
Priority is an integer (`0` overnight, `1` normal, `2` interactive) even though the UI shows three names — a string priority would sort alphabetically and quietly break the queue. The quota counts `running` rows only: a `cancelling` job still holds the card until the worker releases it.
