## User story
As an ML engineer, I want the image map coloured by what the model actually got wrong, so that "night shots of the loading bay" becomes a visible cluster instead of an average.

## UX flow (LabelDesk words)
1. **Insights → Embeddings → Colour by** — a fifth option *Model score* appears with a model selector beside it (the same list the evaluation tab uses). Selecting it colours every point by that model's per-image F1 on the evaluation split.
2. **Not evaluated yet** — the option is present but the selector shows "no evaluated model" and the map keeps its previous colouring with one note: "Colour by model score needs a finished evaluation." [empty: an evaluation whose images do not overlap the map ⇒ "None of this map's images are in that evaluation's split." and the colouring reverts]
3. **Coverage** — the legend states the join: "312 of 480 map points have a score; the rest are unlabelled images." Unscored points render in neutral grey, never as zero.
4. **Click a point** — T-282 opens the gallery worst-first; this card only supplies the numbers.

- **States** — [empty: a map with no overlap with the split returns every score null plus the coverage line]. [loading: the map block shows its skeleton while the join resolves] [error: a failed join is the embedding tab's own error line with Retry].

## Backend changes
- Models/schema: none.
- Routers: `GET {P}/insights/embedding?model=<mid>` (existing route, one new query param) → each point gains `model_score: float | null` and `model_rank: int | null`; the payload gains `model: {id, name, conf, scored, total}`. **404** for a model of another project.
- Services/jobs: `services/insights_eval.scores_by_image(db, m, files) -> dict[str, float]` — per-image F1 at `f1_best.conf` using the existing matching: `tp / (tp + 0.5(fp + fn))` style F1 per file; `services/insights.py::embedding_payload` joins it through `image_meta(db, m, detections, split)` (file → source image id) so a map point keyed by `image_id` finds its score. Rank is computed inside the model's scored subset (`0` = worst).
- Permissions + workspace isolation: the embedding endpoint is already `project.review`; the model argument is resolved with `project_id` scoping, so a foreign id is 404.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate both files.

## Tests to write first
pytest — `apps/backend/tests/test_eval_clusters.py`:
- `test_points_in_the_eval_split_carry_a_score` — an eval with two files and a map over the same images → two points with `model_score` in `[0, 1]`.
- `test_points_outside_the_split_are_null_not_zero` — a map image not in the eval → `model_score is None`, and it is excluded from `model.scored`.
- `test_a_perfect_image_scores_one_and_a_missed_image_zero` — a stub eval where one file matches fully and one misses everything → `1.0` and `0.0`.
- `test_rank_is_worst_first_within_the_scored_subset` — three scored points → the worst has `model_rank == 0`.
- `test_the_join_uses_the_manifest_not_the_live_split` — an image re-split after the evaluation still scores (the frozen manifest wins).
- `test_a_foreign_model_is_a_404` and `test_the_payload_states_the_coverage` — `model.scored <= model.total`, both ints.
- `test_flag_off_ignores_the_model_param` — points carry no `model_score` key.

## Acceptance criteria
- [ ] A map can be joined to one evaluated model, with a score per point where the splits overlap and null where they do not.
- [ ] Unscored points are neutral, never zero.
- [ ] The payload states coverage and the threshold used.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the parameter is ignored and points are unchanged.

## Notes for the implementer
The per-image F1 must use the *same* matching as the evaluation panel at the *same* threshold, or the map will contradict the numbers above it. Read `f1_best.conf` from the stored eval; do not re-derive it.
