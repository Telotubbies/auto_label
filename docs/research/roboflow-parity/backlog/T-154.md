## User story
As a labeler facing a tray of identical parts, I want to box one example and have the rest proposed, so that the twentieth washer is a click rather than a drag.

## UX flow (LabelDesk words)
1. **Editor → one or more boxes drawn → "Find all similar"** (controls are T-155) — the client sends the example annotation ids, any annotation the user flipped to negative, the class and the confidence. [loading: "Finding similar objects…" on the tool] [error: 402 at the allowance, 400 when no positive example exists, 503 when the detector is unreachable]
2. **What the server does** — one detector call restricted to the example class produces candidates across the image; each candidate crop and each example crop are embedded with the local CLIP encoder (`services/embeddings.embed_image`); a candidate's score is its similarity to the closest positive minus its similarity to the closest negative.
3. **Negative examples** — a candidate whose similarity to a negative exceeds its similarity to every positive is dropped, which is the documented way to kill systematic false positives (lower the threshold, then negate) rather than raising it.
4. **Threshold** — the confidence slider is applied to the combined score, so the same call can be re-filtered client-side without paying twice; the response carries per-proposal `score` and `similarity`.
5. **Resolution warning** — when the image is longer than 2,000 px and the example boxes cover under 5% of the frame, the response carries `warn: "The examples are small for this image — results may be coarse at full resolution"`, and the UI shows it once without blocking.
6. **Nothing is saved** — proposals only; the image's annotation set is unchanged by any response.
7. **Not a trained head** — the card states its limit in code and in the UI: this is similarity re-ranking of a single detection pass, not a per-image few-shot model.

## Backend changes
- Models/schema: none.
- Routers: `POST /api/images/{image_id}/box-prompt` — body `{class_id, positives: [annotation_id], negatives: [annotation_id] = [], model_ref?: str, confidence?: float}` → `{proposals: [{shape, classId, score, similarity, source}], warn?: str, model: str}`; `400` for an empty positives list, an id not on this image, negatives that are not the same class, or a class from another project; `402/503` as in T-150.

- Permissions + workspace isolation: `project.infer` + `image_ctx` (labeler assignment rule applies); annotation ids are looked up on this image only, so an id from another image is 400.
- Secrets/safefetch: none.

## Acceptance criteria
- [ ] One positive example plus one detector call returns scored proposals for the same class, with the score and the raw similarity both present.
- [ ] Negative examples remove candidates that resemble them more than the positives, and the threshold re-filters without another call.
- [ ] A small example on a large image produces the resolution warning once, without blocking.
- [ ] No response writes an annotation; 402 costs no call; every refusal is a distinct readable status.
- [ ] Empty, loading and error states above all render (client states are T-155's).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the route is 404 and the editor hides the tool.
- [ ] Keyboard-only path: not applicable in this card.
