## User story
As someone opening the workflow builder for the first time, I want a saved example with a sample image already loaded, so that my first result arrives before I understand what a block is.

## UX flow (LabelDesk words)
1. **Workflows, no workflow yet** — the empty state offers two paths: "Start with an example" (primary) and "Build one myself" (secondary). The primary creates `Example · detect and draw` from a template, saves it as v1 and opens the canvas with an image already selected. [empty: the project has no images either → the example still opens, and the run panel says "Upload one image to try this on your own photo."] [loading: "Creating your example…" over the canvas frame] [error: creation fails → the empty state returns with the server's sentence and both buttons still work]
2. **The example** — three nodes: a detection model (the project's first ready model, else the registry's first available zoo ref), a bounding-box visualisation and the Outputs node. One line above the canvas: "Press Run. The arrow points at what to change first."
3. **Run** — the run panel is pre-pointed at the project's newest image (or the Playground sample strip when the project has none) and the button reads "Run the example". The result appears as boxes plus JSON, in that order.
4. **What next** — after the first successful run, one dismissible line under the result: "Add a filter to keep only the classes you care about." with an "Add a filter" button that inserts the node wired to the model. Dismissing it stores `ld:wf-hint-dismissed:<id>`.
5. **Deep link** — `?example=1` on the workflows route creates the example once per project and then redirects to the workflow, so a support answer can be a URL.

## Acceptance criteria
- [ ] An empty project reaches a drawable result in five actions: open, "Start with an example", Run, look, dismiss the hint.
- [ ] The example never invents a model: it uses a ready model or an available zoo ref, and says which.
- [ ] A project with no images still opens the example and names the upload as the next step.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: the empty state is inside `task_31`.

## Notes for the implementer
One example, not a gallery: a catalogue of templates is a different product decision. Name it `Example · detect and draw` so a second visit can find it by name and not duplicate it.
