## User story
As an ML engineer who trains elsewhere, I want to bring a checkpoint in and have it validated before it can serve, so that my own pipeline is not a dead end and nobody's GPU runs a stranger's file.

## UX flow (LabelDesk words)
1. **Models → *Add external weights*** — a dialog: file drop, family select (only families whose adapter is installed), variant select from that family's sizes, name, dataset version, and the note "Weights stay in this workspace. Pick *Share* afterwards to use them from another project."
2. **Uploading** — progress per byte, then "Checking the file…" while the worker runs the check. [loading: the row appears immediately as *Checking* with a spinner] [error: "Upload failed" + the reason; nothing is registered]
3. **Rejected** — a rejected file states why, verbatim from the check: "This file is not a weights archive (a pickle that needs its own code)." with *Choose another file*. [error: an unsupported family is a 400 naming the installed families]
4. **Accepted** — the model appears with a *External weights* badge, its family/variant/licence, and the *Run evaluation* entry (T-283); it is not deployable until the check passes.
5. **A versioned upload** — the model lists under that version in *Versions*; a workspace-wide upload is deliberately not offered (see Notes).

- **States** — [empty: a project with no ready version refuses the upload with "Make a version first"].

## Backend changes
- Models/schema: `trained_models.uploaded BOOLEAN DEFAULT FALSE`, `trained_models.upload_meta JSON` (original file name, sha256, bytes, check result). Append to `TRAINED_MODELS` in `apps/backend/app/schema/training.py`.
- Routers: `POST {P}/models/upload` (multipart: `file`, `family`, `variant`, `name`, `version_id`) → `202 model_out` with `status="validating"`; **400** for an unsupported family ("this worker cannot run <family>; installed: <list>"), an unknown variant for that family, a name shorter than 2 characters, a missing/foreign `version_id`, and a file over `MAX_UPLOAD_MB` (**413**); the row is created *before* the response so the UI can poll.
- Services/jobs: new `apps/backend/app/services/weight_upload.py` — `ACCEPT = {".pt": ("zip", "pickle"), ".pth": ("zip", "pickle"), ".onnx": ("onnx",)}`; `sniff(data: bytes) -> str` returns `"zip"`, `"pickle"`, `"onnx"` or raises `ValueError("this file is not a weights archive")`; `store(db, project, file, meta) -> TrainedModel` writes `DATA_DIR/models/<id>/<safe name>` (never the client's path), records `sha256`, and enqueues job kind `weight_check`. Handler `run_weight_check(job)`: for a torch archive, `torch.load(path, map_location="cpu", weights_only=True)` inside the worker process — any non-tensor payload raises and the model becomes `failed` with `metrics.upload_error`; a `.onnx` file is checked for the `ONNX` protobuf magic and registered as **artefact only** (`runtime_refs.runnable = False`); success sets `status="ready"`, `uploaded=True`, `weights=<relative path>`.
- Permissions + workspace isolation: `c.need("admin")` (it can become a serving model); foreign `version_id` → 400; a model row is project-scoped so every read is 404 across workspaces.
- Secrets/safefetch: **no network** — the file is read from the request body with `MAX_UPLOAD_MB`; never a URL. No `secretbox` involvement (nothing to encrypt); the `sha256` is stored for audit.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] An uploaded file is stored under the data dir with a server-chosen name and a recorded sha256.
- [ ] Nothing is loadable until a worker proves the archive holds tensors only (`weights_only=True`); a code-bearing pickle is rejected and leaves no artifact.
- [ ] Unsupported families, sizes and unknown variants are 400/413 with the valid choices, before any file is kept.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ route 404, no badge, no check job.

## Notes for the implementer
Workspace-wide upload is **not** in this card: `TrainedModel.version_id` is non-null, and inventing a pseudo-version would lie in Versions. Upload versioned, then use T-257's *Share* for cross-project reuse. ONNX is an artefact on purpose — this repo has no ONNX runtime adapter.
