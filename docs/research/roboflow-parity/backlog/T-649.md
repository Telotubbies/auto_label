## User story
As a team lead with 8,000 unlabelled images, I want a caption and a handful of keywords per image that I can edit and filter, so that I can find and name the groups that matter before drawing a single box.

## UX flow (LabelDesk words)
1. **Dataset → select → Describe** (`/:ws/:project/browse`) — a bulk action; with no selection it says "Select images first". [error: the gate refusal or an unreachable model renders as one sentence with Try again]
2. **Running** — `[loading: "Describing 240 images — about 3 minutes"]`, with the cap sentence when the selection exceeds the batch cap: "Split this into batches of 500 or fewer."
3. **Rows** — each row gains a caption line and up to eight keyword chips; keywords the model was unsure of render greyed (`text-muted-foreground`) and are labelled "weak". [empty: an image with no caption reads "No description yet" and keeps its tag list untouched]
4. **Editing** — the caption is editable in the cell; a keyword can be accepted, edited or rejected with one click; "Accept all" applies the visible batch.
5. **Using it** — "contains wet floor" runs through the query box as a keyword filter; export gains an "include captions" toggle where the format supports a text field.
6. **Flag off** — no Describe action, no caption column, no keyword chips.

## Backend changes
- Models/schema: `images.caption` TEXT NOT NULL DEFAULT `''`, one `IMAGES["caption"] = "TEXT DEFAULT ''"` line in `app/schema/dataset.py`. Keywords are ordinary tags, so they reuse `images.tags` and the existing tag filter — no second store.
- Routers: `POST /api/ws/{ws}/projects/{project}/images/describe` (`image_ids` ≤ 500 or `batch_id`) → 202 job; `PATCH /api/images/{image_id}` already accepts a caption and tags through its existing body, so editing needs no new route; `GET .../images` returns `caption` in `image_out`.
- Services/jobs: `services/caption.py` (new) — `describe(vlm, im) -> {"caption": str, "keywords": [str]}` asking for one JSON object with ≤ 8 keywords, `weak(keyword, caption)` marking a keyword absent from the caption, `write(db, img, caption, keywords, keep=[])` merging tags without dropping human ones; job kind `caption` in `LOCAL_JOB_KINDS`, `run_job(job)` returning `{"described", "failed"}`.
- Permissions + workspace isolation: `reviewer` to run, `annotator` to edit a row they can see, `project.read` to read; `_visible()` keeps a labeler's unassigned images out, and a foreign image id is 404 through `image_ctx`.
- Secrets/safefetch: `services/secretbox.py` holds a hosted endpoint token if one is stored; no image leaves the deployment unless `workspaces.ai_egress` is true (`ai_egress.require` from T-640).
- OpenAPI: yes — regenerate (`python tools/export_openapi.py`, `npm run gen:api-types`).

## Acceptance criteria
- [ ] A selection is described in one job with a caption and up to eight keywords per image, and the keywords become ordinary tags that the existing tag filter finds.
- [ ] A human edits the caption or rejects a keyword inline, and a re-run never removes a human tag.
- [ ] A failed image is counted and keeps its previous caption.
- [ ] Empty, loading and error states above all render, including an image with no caption and an over-cap selection.
- [ ] Workspace A cannot describe or read workspace B's images (404, not 403).
- [ ] Flag off ⇒ no Describe action, no caption column, no chips, and tags are unchanged.

## Notes for the implementer
The caption is a triage aid, not a label: it never becomes an annotation and never enters a version manifest as a class. Keywords are capped at eight and stored as tags with a `tag:`-free plain string so the existing tag query works unchanged; weak keywords are shown but not auto-accepted. The rate sentence uses the measured call time, not a guess.
