## User story
As a site operator, I want a message when a camera goes quiet or drops offline, so that a dead feed is noticed before a
shift ends.

## UX flow (LabelDesk words)
1. **Settings → Alerts** — the channel list gains a `Watch for` block per channel with two switches:
   `Camera offline` (`A stream that was running has stopped or reported an error.`) and
   `No events for a while` (`A running stream has produced no rule event inside the window.`) plus a window field
   (`60 minutes`, `2 hours`, `12 hours`).
2. **A firing alert** — the message names the stream, the seconds since the last event and the project, and links to
   the stream page; it uses the same delivery row and throttle/quiet rules as a rule event.
3. **`[empty]`** no channels: the block is not shown at all; the operator sees today's alerts page.
4. **`[error]`** a stream already stopped is not "offline" again — one alert per transition, not one per tick.
5. **Quiet hours and throttle apply**; a suppressed alert is a `skipped` delivery, which is free (T-438).

## Backend changes
- Models/schema: none — `Stream.status`, `Stream.last_error` and `StreamEvent.ts` carry the signal;
  `AlertChannel.settings` JSON holds `watch: {offline: bool, silence: bool, silence_s: int}` validated in
  `alerts.validate_settings`.
- Routers: `routers/alerts.py` — `settings.watch` accepted on create/update (validated: `silence_s` in
  `{3600, 7200, 43200}`); the channel payload returns it.
- Services/jobs: `app/services/alert_silence.py` (new) — `check(db, now) -> list[dict]` scanning channels with a watch
  setting: for each stream in that workspace's projects, `offline` when `status != "running"` and the previous audit
  row (`stream.offline_alert`) is absent for this transition; `silence` when `status == "running"` and
  `now - max(StreamEvent.ts) > silence_s` and no `stream.silence_alert` audit row for the same day. Each alert calls
  `alerts.dispatch(db, ws, event)` with `event = {"kind": "stream.silence"|"stream.offline", "stream": name,
  "project": slug, "seconds": n}` and writes the dedupe audit row. One worker tick beside `retention.enqueue_if_due`.
- Permissions + workspace isolation: the scan iterates workspaces and never mixes their channels or streams; the
  dedupe key includes the workspace id.
- Secrets/safefetch: none.
- OpenAPI: yes (the settings block appears in the existing channel schema).

## Frontend changes

## Acceptance criteria
- [ ] A running stream that goes quiet past its window raises one alert per day, not one per tick.
- [ ] A stream that stops raises one offline alert per transition.
- [ ] Throttle, quiet hours and the credit cost of T-438 apply to these alerts unchanged.
- [ ] Empty, loading and error states above all render (no channels, no streams, suppressed alert).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no block, no scan, no alerts.
