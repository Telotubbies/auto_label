## User story
As a labeler, I want the project's questions as fields beside the image, so that a VQA answer is a keystroke rather than a spreadsheet edit.

## UX flow (LabelDesk words)
1. **Editor → right inspector sheet → Answers** (a new rail entry shown only when the project has prompts) — one field per prompt in the project's order: a text input, a number input, a yes/no segmented pair, or a choice select; a required prompt carries a dot and `aria-required`. [empty: a project with no prompts → the entry is absent] [loading: prompts and answers load together → three skeleton fields] [error: load failed → message with retry, the canvas unaffected]
2. **Type to answer** — values save 600 ms after the last keystroke; the panel header shows "Saving…" then "Saved", and a failed save keeps the value with a Retry beside the field rather than reverting it.
3. **Prefix prompts** — a prefix slot renders as a sentence with an inline input where `<SLOT>` sits: "A receipt totalling [ ] baht", so the labeler sees the sentence they are completing.
4. **Validation** — a number field rejects non-numeric input on blur with "This answer must be a number"; a required prompt left blank shows its dot in the destructive colour and a line "Required — needed before this image can be submitted".
5. **Submit wiring** — pressing Submit for review with a missing required answer focuses the first missing field and shows the server's message; the submit does not happen.
6. **Per-image** — answers are per image, never copied from the previous one; pressing `→` loads the next image's answers, and an empty answer set renders every field blank.
7. **Read-only images** — with `canEdit` false (T-164) the fields render as text with the same reason bar; the panel never writes.

## Acceptance criteria
- [ ] Every prompt renders the right control, including a prefix with an inline slot, in project order.
- [ ] Answers save on a debounce with an honest Saving/Saved/Retry state and never revert a typed value on failure.
- [ ] A missing required answer is marked and blocks submit-for-review with the question's name.
- [ ] On a read-only image the fields are text and no write is attempted.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no rail entry and no answers request; the editor is unchanged.
- [ ] Keyboard-only path: Tab to the rail → Enter on Answers → Tab fields → type → `Ctrl+S` writes, or wait for the debounce.

## Notes for the implementer
Answers are not annotations: they use their own endpoint and their own save state, so an answer save must never mark the annotation set dirty or trigger the annotation PUT. Keep the debounce timer per image and clear it on `→`.
