## User story
As a team lead, I want to send a workflow to a colleague or copy it into another project, so that a good pipeline spreads as a template instead of as a screenshot.

## UX flow (LabelDesk words)
1. **Share** — the editor's three-dot menu offers "Share…": a switch `Anyone with the link can view` (off by default), a `Copy link` button, and one line: "A shared workflow opens read-only. The recipient sees the blocks, never your images or your models." Turning it off revokes the link immediately.
2. **The shared page** — `/:ws/shared/workflow/:token` renders the definition read-only: the node list with names and parameters, the version number, and two actions, `Copy to my workspace` (signed-in members of the workspace) and `Download JSON`. `[empty]` [loading: three skeleton rows] [error: an unknown or revoked token → "This link is no longer available." with no definition and no workspace name]
3. **Fork** — "Copy to my workspace" asks which project, then creates a new workflow whose name is `<name> (copy)` with the same graph, one version, and every `trained:<id>` model ref re-mapped to the target project's first ready model or flagged `unresolved` so the save is refused until the person picks one. A copy never carries the share token.
4. **Folders** — the workflows list gains a folder chip list; the row menu offers "Move to folder" and a new folder can be created inline. Moving is one select; the folder only groups, it grants nothing.
5. **`[error]` a fork into a project without a ready model** — the copy still saves with the model node disabled and one line: "Pick a model for this block."

## Backend changes
- Models/schema: new module `apps/backend/app/models/sharing.py` — `WorkflowShare` (`id`, `workflow_id`, `workspace_id`, `token` unique, `created_by`, `created`, `revoked_at`); `workflows` gains `folder_id VARCHAR(32)` nullable. One `ADD COLUMN` line in `app/schema/dataset.py`'s `WORKFLOWS` block; the new table comes from its model module.
- Routers: `apps/backend/app/routers/workflow_sharing.py` (new) — `POST /api/ws/{ws}/projects/{project}/workflows/{id}/share` (create or re-enable), `DELETE …/share` (revoke), `POST …/fork` with `{target_project}`; plus a **public** read `GET /api/shared/workflows/{token}` that returns the definition without predictions, images, keys, workspace id or model weights — only names, block types, parameters and the version number.
- Services/jobs: `apps/backend/app/services/workflow_share.py` (new) — `mint(db, c, wf)`, `revoke(db, c, wf)`, `public_view(db, token) -> dict | None` (None for unknown or revoked), `fork(db, c, wf, target_project) -> Workflow` re-mapping refs and refusing a target project in another workspace.
- Permissions + workspace isolation: share/revoke need `project.models` on the source; fork needs `project.models` on the target; the public read is unauthenticated by design and is documented as such in OpenAPI; a token never leaks a project id, an image path or a model id.
- Secrets/safefetch: the token is 32 bytes from `secrets.token_urlsafe`; comparison is by exact string, never by prefix; the public response is built field-by-field, never by dumping the row.
- OpenAPI: yes — four routes, one public.

## Acceptance criteria
- [ ] Sharing mints one link, revoking kills it, and the public page shows the definition and nothing else.
- [ ] Fork copies the graph into a chosen project of the same workspace, remaps model refs and names the ones it could not resolve.
- [ ] Folders group workflows and grant nothing; a workflow can be moved in one action.
- [ ] Empty, loading and error states above all render, including a revoked token.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no share menu, no public route, no folder chips.

## Notes for the implementer
The token is the credential for the definition only: build the public response from an allow-list of fields, so a later column on `Workflow` cannot leak by default. Folder-scoped read/edit permissions are deliberately not in this card — this repo's folders carry no permission rows, and inventing a second ACL beside the project roles would give two sources of truth.
