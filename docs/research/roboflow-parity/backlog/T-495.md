## User story
As a reviewer comparing a split chip on the dataset with the same chip on a version page, I want one colour per meaning, so that `test` is not orange here and blue there and green in a third place.

## UX flow (LabelDesk words)
1. **Dataset and Versions** — the split chip reads `train`, `valid`, `test` with the same three tones in both screens, each with its name; no chip is a bare dot.
2. **Deploy predictions** — box colours come from `classColor(i)`, the same Okabe-Ito order the editor uses, so a class keeps its colour from labelling to inference. [empty: a prediction whose class is unknown gets the fallback colour plus the class name in the label]
3. **A status pill** — `done`, `running`, `queued`, `failed` map to the four semantic roles and always print the word.
4. **Dark mode and colour-blind check** — the tones come from tokens, so they re-derive with the theme; the chip keeps a text label in every tone. [error: an unknown status renders a neutral chip with the raw status word, never an empty chip]
