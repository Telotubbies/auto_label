## User story
As any project member, I want the product to say which of the five steps is done, blocked or next, so that I stop guessing whether a project is at upload, at review or ready to train.

## UX flow (LabelDesk words)
1. **Project rail** — three purpose groups, each collapsible, with the five numbered stages inside them in pipeline order: `Data` holds `① Upload`, `② Annotate`, `③ Dataset`, `Insights`, `Classes & tags`; `Models` holds `④ Train`, `Models`, `Model search`; `Deploy` holds `⑤ Deploy`, `Active learning`. `Project settings` sits below a rule, outside the groups. Each row carries a state (`done`, `needs you`, `blocked`, `not started`), a count badge and one line of text ("40 uploaded", "16 to review", "1 version · 24 approved", "last run failed", "not deployed yet"). A group header is sentence case, 12 px, and carries a summary count when collapsed ("3 need you").
2. **First visit to a project with 40 images and no labels** — stage 2 reads "needs you · 40 to label" and stage 3 shows "blocked by annotate". [empty: a project with no images shows stage 1 as `needs you` and stages 2–5 as `not started`]
3. **A failed training run** — stage 4 reads "blocked · last run failed" and links to the run list, not to a new run.
4. **A labeler** — sees upload (read), annotate and dataset; train and deploy render dimmed with a lock, per the permission rule.
5. **The primary label** — `primaryLabel()` returns one sentence for the header: "Label 40 images", "Review 16 labels", "Train on v2", "Test the model", "Upload 20 images".

## Acceptance criteria
- [ ] The rail renders three collapsible groups (`Data`, `Models`, `Deploy`) with the five numbered stages inside them, in the fixed order, each with a count badge, a state word and one line of text.
- [ ] A group collapses to its header and shows a summary ("3 need you") so no alert is hidden; the open/closed state persists for the session.
- [ ] No destination appears twice: Versions, Health, Streams and Test stay inside their stage as tabs, not as sibling rows.
- [ ] The state matches the data for all six combinations in the test table (empty, uploaded, in review, approved, versioned, trained).
- [ ] Numbers agree with Home: `40 uploaded · 24 approved` is the same pair in both places.
- [ ] A locked stage is dimmed *with a reason*, never dropped from the rail.
- [ ] Empty, loading and error states above all render: no images ⇒ `not started`; while `statusCounts` is missing ⇒ the stage shows a skeleton count, not zero; a failed `/versions` ⇒ `dataset: unknown` with retry, not `0 versions`.
- [ ] Workspace A cannot see workspace B's data: facts come from the project-scoped payload; a foreign slug 404s and no stage renders.
- [ ] Flag off ⇒ `projectNav` renders the v2 groups and no stage module is read.

## Notes for the implementer
`deploy` has no count in the API today — return `null` and render `—`, exactly as the frame draws it. Do not add a deployment field here: T-314 (area 6) owns the Deploy rebuild and any deployment record it introduces. State precedence is `blocked` before `needs-you` before `done`, so a failed run never reads as finished.
