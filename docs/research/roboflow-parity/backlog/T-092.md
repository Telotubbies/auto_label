## User story
As a reviewer, I want to fix a typo across 40,000 images by seeing the diff before it lands, and delete a
tag that no longer means anything, so that the vocabulary stays usable as the project grows.

## UX flow (LabelDesk words)
1. **Classes & tags · Tags** — the tag list shows name + image count, with checkboxes and a search filter.
   [empty: "No tags yet — tags are added at upload or from a selection."]
2. **Tags** — ticking rows enables **Rename** and **Delete**. Rename opens a table of the selected tags with
   an editable new name; case-only changes are pre-filled. [error: two tags renamed to the same name →
   "Two tags cannot share a name — rename them to the same tag to merge" and the **Review changes** button
   waits]
3. **Tags · Review changes** — a diff: "`helmet` → `Helmet` (12,480 images) · `vest` → `Helmet` merges
   (3,102 images)". [loading: the preview counts resolve per tag] [error: a tag changed since the preview →
   "The tag list changed — review again"]
4. **Tags · Confirm changes** — the rename lands as one request; the toast reads "Renamed 2 tags · 15,582
   images updated". Delete asks "Delete `old-cam` from 412 images? The tag disappears from the project."
   [empty after delete: the row disappears; the last tag removed shows the empty copy]

## Backend changes
- Models/schema: none — `Image.tags` JSON list stays the storage.
- Routers: `apps/backend/app/routers/projects.py`
  - `GET /{project}/tags/rename-preview?pairs=helmet:Helmet,vest:Helmet` →
    `{rows: [{from, to, images, collisions, suggestion}], totalImages}` (read-only; `suggestion` names the
    case-insensitive near match).
  - `POST /{project}/tags/rename` — keeps today's single-pair body and gains
    `pairs: list[{from, to}]` + `expectedTotal: int` (409 when the current total moved); applies in one
    transaction, bumps `Image.updated` per touched row (insights cache invalidation already relies on it).
  - `DELETE /{project}/tags/{name}` → `{images_updated}`; `404` when the tag does not exist.
- Services/jobs: none — 40k tag writes are one SQL pass per tag; no job (the existing rename is
  synchronous and the card keeps that contract).
- Permissions + workspace isolation: `c.need("reviewer")` (today's rule) on all three; every query filters
  `Image.project_id == c.project.id`, including soft-deleted rows (a revived image keeps its tags).
- Secrets/safefetch: none.
- OpenAPI: yes — two routes + extended body.

## Acceptance criteria
- [ ] Rename shows a diff with per-tag image counts and merge notes before it lands.
- [ ] A rename into an existing tag merges instead of creating a duplicate; a case-only change works.
- [ ] Delete removes the tag from every image in the project after a confirm naming the count.
- [ ] A stale preview is refused (409) instead of overwriting a colleague's change.
- [ ] Empty, loading and error states above render.
- [ ] Flag off ⇒ no Tags section and the routes 404.
- [ ] Workspace A cannot see or change workspace B's data (404 for a foreign project id).

## Notes for the implementer
Keep `POST /tags/rename`'s old single-pair body working — other callers and tests use it. Rename must not
resurrect a soft-deleted image or touch another project's rows.
