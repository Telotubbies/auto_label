# T-1300 — One request id, one JSON log line, browser to API to worker

| Field | Value |
| --- | --- |
| Wave | O (security, monitoring, performance) |
| Area | Monitoring |
| Size | 3 agent-hours |
| Role | R3 backend + R4 frontend |
| Skills | ponytail, test-driven-development, systematic-debugging, verification-before-completion |
| R7 security review | yes — log content is a data-exposure surface |
| Depends on | none |
| Feature flag | none (`LD_LOG_JSON=0` restores the text format) |

## Problem
`logging.basicConfig` writes `"%(asctime)s %(levelname)s %(name)s: %(message)s"` (`app/main.py:21`) and
nothing carries a request id. A user report ("my save failed") cannot be joined to a log line, and the
worker's line cannot be joined to the request that enqueued the job. Every later monitoring card needs
this seam first.

## Design
- `app/logging_setup.py` (new, ~85 lines): a `request_id` `contextvar`, a `_CtxFilter` that injects
  `request_id`, `user_id`, `workspace_id`, a `JsonFormatter` emitting the key set in the monitoring
  plan §4.1, and `install()` which configures the root logger once (idempotent) and honours
  `LD_LOG_JSON=0`.
- One ASGI middleware in the same module: read `X-Request-Id`, accept it only when it matches
  `^[A-Za-z0-9_-]{8,64}$`, otherwise `uuid4().hex[:16]`; set the contextvar; echo the header; log one
  `http.request` line with `method`, route template, `status`, `duration_ms`; reset the contextvar in
  a `finally`.
- Uvicorn access logging is disabled for `/api/*` only (the middleware now writes the richer line) and
  kept for everything else.
- `workspace_id`/`user_id` are filled by the deps layer when it resolves a context; the middleware
  leaves them empty for anonymous requests.
- Worker: `_claim` and `run_one` log `job_id`, `job.kind` and `worker_id`; the enqueue sites already log
  one line, which now carries both ids, so a job is joinable with one grep on `job_id`.
- Frontend `lib/api/client.ts`: generate `crypto.randomUUID().slice(0, 16)` per logical call, send it
  as `X-Request-Id` on `req`, `download` **and** `upload`, and reuse it across the 401→refresh retry.
  Show it in the error toast's `detail` line.

## Tests to write first
pytest — `tests/test_logging_request_id.py`:
- `test_supplied_request_id_is_echoed` — send `X-Request-Id: abc12345`, assert the header and the log
  record's `request_id`.
- `test_request_id_is_generated_when_absent_or_invalid` — absent, `"short"`, `"has space"`,
  2 000 chars and `"a\nb"` all produce a 16-hex id, and the bad header never reaches the log.
- `test_log_line_is_one_json_object` — `json.loads` on a captured line; the key set matches §4.1.
- `test_no_secret_in_the_log_line` — log in, upload, call a key route; assert `password`, `token`,
  `api_key` and the raw body never appear.
- `test_a_500_carries_the_traceback_on_the_same_request_id` — the exception line's `request_id`
  equals the response header's.
- `test_text_format_still_available` — `LD_LOG_JSON=0` produces the old format.
- `test_worker_job_lines_carry_job_id` — enqueue, run `run_one`, assert claim + terminal lines.

node — `apps/frontend/tests/request-id.test.mjs`:
- `test_each_call_sends_a_request_id` and `test_a_retry_reuses_the_same_id` against a stubbed `fetch`.
- `test_an_error_toast_shows_the_id` (pure formatter, no DOM).

## Acceptance criteria
- [ ] Every `/api/*` response carries `X-Request-Id`, generated or validated-honoured.
- [ ] One JSON object per log line, all keys present, no secret or raw body in any of them.
- [ ] A 500's traceback and its response header share one id.
- [ ] The worker's claim, progress and terminal lines all carry the `job_id`.
- [ ] `LD_LOG_JSON=0` restores today's text format; no test asserts on the text format elsewhere.
- [ ] The frontend sends the id on `req`, `download` and `upload`, and reuses it on refresh-retry.

## Notes for the implementer
Do not add a dependency: the stdlib formatter is enough. Do not log headers or bodies wholesale — the
one exception is a 5xx where the traceback is already logged. Route labels must be templates
(`request.scope["route"].path`), never the raw path: that is also the rule for T-1302's metric labels.
