## User story
As an existing user, I want every workflow I saved before the canvas to keep running unchanged, so that a new editor does not break a pipeline I already depend on.

## UX flow (LabelDesk words)
1. **A saved v1 workflow runs** — `POST /workflows/{id}/run` produces exactly today's `{detections, texts, events, annotations_added, quota_clamped, elapsed_ms}`, with no warning banner and no re-save prompt.
2. **A v2 workflow runs** — the same response; blocks are compiled in topological order, so a branch that produces nothing does not shift the indexes the response refers to.
3. **A disabled node** — `[loading]` a disabled block is a no-op in the compiled plan and its id still appears in `plan.skipped`, so the run panel can say "2 blocks skipped". [error: a graph whose sink is unreachable → 400 "the workflow has no path to its sink", before any model call]
4. **Restore** — restoring a v1 snapshot into a v2 workflow re-derives a graph from the snapshot's `blocks`; the version row records which manifest it came from.

## Backend changes
- Models/schema: none beyond T-320.
- Routers: `apps/backend/app/routers/workflows.py` — `POST /{workflow_id}/run` calls the compiler first; the response gains `plan: {version, order, skipped}` and nothing else changes.

- Permissions + workspace isolation: unchanged; the compiler never loads a model, so no new path to a foreign workspace exists.
- Secrets/safefetch: none.
- OpenAPI: yes — `run` response gains `plan`.

## Notes for the implementer
`workflow_runner.run` keeps validating the ordered block list; the compiler's job is to produce that list. Do not add edge awareness to the runner in this card — a second execution model behind the same response is how the two drift apart.
