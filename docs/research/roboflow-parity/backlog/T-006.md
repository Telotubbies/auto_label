## User story
As the reviewer of any area-6 PR, I want the deploy threshold, the block catalogue and the stream zone
rules pinned so a deploy-hub or workflow-canvas card cannot silently drop the confidence contract, the
`rule`/`sink` kinds, or the zone/line geometry the counters depend on.

## UX flow (LabelDesk words)
1. **Deploy & Test** — pick a ready model, upload or drop an image, drag the Confidence slider; the
   preview predictions re-render at that confidence and the cURL/Python/JavaScript/Image-URL tabs show
   the hosted endpoint. [empty: `No trained model to deploy yet.`] [loading: `Running inference…`]
2. **Workflows** — add a block, fill its required field, add the sink last, save (creates a version),
   restore an older version, run on one project image.
3. **Count → (draw)** — a `rule` block of kind `count` answers a count event; the documented detect →
   count → draw chain exists for detect and count, while the draw/viz blocks are still missing.
4. **Streams** — draw a polygon zone and a line on a still frame; a `zone` rule names an existing zone,
   a `line` rule carries `[x1,y1,x2,y2]` and a direction; deleting a zone is refused while a rule
   points at it.
5. **Alias** — `production` keeps pointing at one immutable model id; a second deploy records
   `previous_model_id` for rollback.

## Notes for the implementer

absent"): `services/workflows.py:18-20` has `model/filter/crop/ocr/rule/sink` and no viz type. This

one-line fix would interpolate `conf / 100` into the three snippets. That is `6-F6.8`'s work (runtime
picker rewrites snippets) and is out of scope for a test-only card; the guard asserts only the preview
path, which is what `6-F6.9` claims today.
Migration-sensitive HAVE facts: the predict route forwards `confidence` only when the form field is
present (`training.py:352-353`); `MAX_BLOCKS = 12`, `RULE_KINDS` and `SINK_KINDS` are the canvas's
vocabulary; a zone rule must name an existing `zone_id` (`streams.py:175-194`); alias rows store
`model_id` and keep `previous_model_id` for rollback (`services/deployments.py`, proven by
`test_deployments.py:148-180`).
