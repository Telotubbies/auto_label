## User story
As a defect team with forty images of a scratch that must not be confused with a dent, I want forty more train-only examples built from the masks I already drew, each carrying its recipe, so that the rare class gets instances rather than more brightness.

## UX flow (LabelDesk words)
1. **Coverage → a thin class → Add examples** (`/:ws/:project/insights?tab=coverage`, drawn by T-661) — the method is "paste real crops" for now; a render job is out of scope for this card. This card builds the images.
2. **Pre-flight** — the request states how many source masks the class has and how many fills are possible. [error: "this class has no polygon labels — paste needs masks" with the SAM refine link] [empty: "not enough source images for this class yet" when fewer than 3 masks exist]
3. **Running** — `[loading: "Building 40 of 120 images…"]`; a cancelled job leaves no half-written images.
4. **The result** — new image rows, `split="train"`, tagged `synthetic` and `synthetic:<recipe_id>`, each with only its pasted annotations and a provenance record naming the source image ids and the paste box.
5. **The next version** — every synthetic item carries `"synthetic": true` and its recipe in the manifest, so `provenance:synthetic` filters them later and an auditor can see which shots are not real.

## Backend changes
- Models/schema: new module `app/models/synthetic.py` with `SyntheticFill` (`id`, `workspace_id`, `project_id`, `class_id`, `count`, `seed`, `sources` JSON, `created`, `status`, `note`) registered in `models/__init__.py`; image provenance reuses `images.tags` plus the `source` field on each annotation.
- Routers: `POST /api/ws/{ws}/projects/{project}/synthetic-fill` (`class_id`, `count` 1–200, `seed`) → 202 job; `GET .../synthetic-fill` → the last 10 recipes with their generated counts; `DELETE .../synthetic-fill/{id}` → 200 and the generated images move to trash through the existing erasure path. 400 when the class has no polygon annotations or fewer than 3 source images, 404 for a foreign class id.
- Services/jobs: `services/synthetic.py` (new) — `source_masks(db, project, class_id)` (polygon annotations on train images, with their image paths), `destinations(db, project, count, seed)` (train images not carrying the class), `paste(im, mask_crop, ann, rng)` rejecting a placement whose IoA against an existing box is ≥ 0.3, `build(db, ws, project, recipe)` writing JPEGs under `DATA_DIR/images/<project>/` and `Image` rows; job kind `synthetic_fill` in `LOCAL_JOB_KINDS`; `services/versioning.py` adds `synthetic`/`recipe` to a manifest item when the source image is tagged.
- Permissions + workspace isolation: `project.review` to build, `reviewer` to delete a recipe; the class id and every source image are validated against `c.project.id` (404), and generated rows belong to the project that built them.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate (`python tools/export_openapi.py`, `npm run gen:api-types`).

## Acceptance criteria
- [ ] A thin class with polygon labels gains N train-only composited images, each tagged and each carrying its recipe and source ids.
- [ ] A paste that would overlap an existing box is rejected and replaced rather than written.
- [ ] A version built over synthetic images records them as synthetic in the manifest, so they are never mistaken for captured data.
- [ ] Empty, loading and error states above all render, including a class without masks and a class with too few sources.
- [ ] Workspace A cannot build from or delete workspace B's class (404 on a foreign class or recipe).
- [ ] Flag off ⇒ no route, no generated image, and version manifests are exactly as today.

## Notes for the implementer
Mask-based paste only: a bbox crop pasted with its background is how a scratch becomes a dent. Use the annotation's polygon as the alpha mask, place at a random valid position with IoA < 0.3, and never paste onto an image that already carries the class. Synthetic images are train-only and never enter `valid` or `test` — a generated example in the eval split is a rigged score.
