## User story
As an integrator, I want to add a camera by URL or by picking one on the network, and to know before I build that a phone preview cannot become a permanent deployment, so that I do not discover the limit after wiring a rule.

## UX flow (LabelDesk words)
1. **Streams → New stream → Source** — a source table replaces the single URL field: `Camera URL` (RTSP/RTSPS/HLS, permanent), `Uploaded clip` (permanent, loops), `Network camera (ONVIF)` (permanent, discovered), `Phone camera` (preview only, 5-minute link). One column states the lifetime and one states what it needs. [empty: no camera found by discovery → "No camera answered the discovery. Add it by URL instead."] [loading: discovery shows "Looking on the network…" with a cancel button] [error: `Rejected by the camera` with the reason; a refused credential leaves the camera on its last settings]
2. **Camera URL** — name, full URL, and separate username/password fields that are sealed server-side and never read back. A badge says `Password saved` after a save and `Password not set` before one.
3. **ONVIF discovery** — "Find cameras" probes the operator allowlist (`LD_STREAM_ALLOW_CIDR`) for ONVIF devices, lists `host · manufacturer · model`, then asks for credentials and a profile. Choosing a profile writes the equivalent RTSP URL.
4. **Phone camera** — a QR that encodes a one-time token valid for 5 minutes; the page states once: "A phone preview is a test source. It cannot be a deployment and it stops when the tab closes."
5. **Editing a live camera** — saving a changed source shows "This restarts the stream." before it happens.

## Backend changes
- Models/schema: `streams` gains `source_kind VARCHAR(16) DEFAULT 'url'` (`url | file | onvif | phone`); the credentials keep living inside the sealed `source` string, so no second secret column. One `ADD COLUMN` line in `app/schema/streams.py`'s `STREAMS` block.
- Routers: `apps/backend/app/routers/streams.py` — `POST /discover-onvif` (admin, `task_346`) returning `{devices: [{host, manufacturer, model, profiles}]}` for hosts inside `LD_STREAM_ALLOW_CIDR` only; `POST /phone-token` returning `{token, expires, url}`; `StreamIn`/`StreamPatch` accept `source_kind` and `username`/`password` separately, which are merged and sealed by `streams/creds.py`.
- Services/jobs: `apps/backend/app/streams/discovery.py` (new) — `probe(cidrs, timeout_s=3) -> list[dict]` using WS-Discovery over UDP multicast with a hard per-host timeout, `profiles(host, user, password) -> list[dict]` via ONVIF `GetProfiles`, `rtsp_for(profile) -> str`; every call is bounded and runs in a worker thread, never on the request loop.
- Permissions + workspace isolation: discovery and phone tokens need the project `admin` role; the phone token is single-use, bound to the creating user and expires in 300 s.
- Secrets/safefetch: credentials go through `streams/creds.seal_source`; `canonical_source` stays the only allowlist for what reaches FFmpeg; discovery never leaves the configured CIDR, and a host outside it is not probed.
- OpenAPI: yes — two routes and one body field.

## Tests to write first
pytest — `apps/backend/tests/test_stream_discovery.py`:
- `test_a_host_outside_the_allowlist_is_never_probed` — with an empty CIDR list the probe returns `[]` and sends no packet (assert on the patched socket).
- `test_credentials_are_sealed_and_never_returned` — creating with `username`/`password` stores `enc:v1:` in `source` and `stream_out` shows `•••@`.
- `test_a_phone_token_is_single_use_and_expires` — the token works once, a second use is 410, and after 300 s it is 410 as well.
- `test_discovery_needs_the_admin_role` — a reviewer gets 403.
- `test_a_refused_profile_leaves_the_camera_unchanged` — an ONVIF profile error leaves `source` byte-identical.
- `test_flag_off_keeps_the_url_only_path`.
node — `apps/frontend/tests/stream-sources.test.mjs`:
- `test_only_url_and_discovered_cameras_can_be_deployments` — `canBeDeployment` is true for `url`/`onvif`/`file`, false for `phone`.
- `test_every_kind_states_a_lifetime` — the four kinds each return a non-empty lifetime sentence.
- `test_the_password_badge_reflects_the_saved_state` — `passwordBadge(true)` is "Password saved" and `passwordBadge(false)` does not claim one.

## Acceptance criteria
- [ ] Four source kinds are offered with their lifetime and requirements stated before the camera is created.
- [ ] A URL with separate credentials seals the password and never returns it; discovery only probes allowlisted hosts.
- [ ] A phone preview is labelled as non-deployable and expires in five minutes.
- [ ] Empty, loading and error states above all render, including "no camera answered" and a rejected credential.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ today's URL field and clip upload.

## Notes for the implementer
No new dependency: ONVIF discovery is WS-Discovery over UDP plus two SOAP calls, which `requests`/`httpx` and `socket` already cover — do not add an `onvif` package for two requests. Phone preview reuses the uploaded-clip worker with a 5-minute token; it is a test source, so it never becomes a deployment.
