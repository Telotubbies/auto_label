## User story
As a data engineer, I want key/value attributes on each image (camera, shift, lot, quality score) that are
typed by what I type and filterable, so that capture context survives into exports instead of living in a
spreadsheet.

## UX flow (LabelDesk words)
1. **Image detail** — a metadata section with a key field and a value field; Enter adds the pair and the
   row shows its type ("quality_score · number · 82"). [empty: "No metadata on this image yet"]
   [error: `camera/id` → "Keys use letters, numbers, `_` and `.`; no `/`"]
2. **Image detail** — editing a value re-types it the same way; clearing a value deletes the key after a
   confirm that names the key. [loading: the image payload resolves before the rows render, so no value
   flashes as "none"]
3. **Dataset · Images** — select 120 images → **Add metadata** → key `shift`, value `night` → all 120 gain
   it; the toast reads "120 updated · 0 failed". [error: 1,200 selected → the action is refused with
   "Bulk metadata is limited to 1,000 images — narrow the selection"]
4. **Dataset · Images** — typing `metadata:quality_score>80` narrows the grid and the chip reads
   `quality_score > 80`.

## Backend changes
- Models/schema: `Image.meta JSON default dict` in `models/project.py` (attribute name `meta`; the ORM
  cannot use `metadata`), one `IMAGES` entry `"meta": "JSON"` in `schema/dataset.py`.
- Routers: `apps/backend/app/routers/images.py`
  - `image_out` gains `meta`.
  - `ImagePatch` gains `metadata: dict[str, object] | None`; a write merges (never replaces the whole map)
    and validates through `services.metadata`.
  - `POST P/images/metadata` body `{ids: list[str], metadata: dict, mode: "merge"|"replace"}` (cap 1 000,
    `422` above) → `{updated, failed: [{id, reason}]}`; per-id failures do not abort the batch.
- Services/jobs: `apps/backend/app/services/metadata.py` (new) —
  `clean_key(str) -> str`, `infer(value) -> str|int|float|bool`, `clean_map(dict) -> dict` (≤ 50 keys per
  image, key ≤ 64, string value ≤ 512, `null` dropped), `merge(existing, incoming, replace=False) -> dict`,
  `filter_sql(key, op, value)` for the query compiler (numeric compare when both sides are numbers, string
  equality otherwise, `json_extract`-free: compare against `Image.meta` via SQLAlchemy JSON indexing for
  Postgres and `json_extract` for SQLite — pick the expression from `db.bind.dialect.name`).
- Permissions + workspace isolation: single-image write through `image_ctx` (`project.annotate`, and the
  existing labeler-assignment guard); bulk needs `c.perm("project.review")` and filters
  `Image.project_id == c.project.id` so a foreign id is in `failed`, never written.
- Secrets/safefetch: none.
- OpenAPI: yes — one route, one field, one query selector enabled.

## Tests to write first
pytest — `apps/backend/tests/test_metadata.py`:
- `test_infer_types` — `"95"` → int, `"80.5"` → float, `"true"` → bool, `"cam001"` → str, `"  "` → dropped.
- `test_key_charset_and_length` — `camera/id`, `""`, and a 65-char key are refused; `capture.temperature` ok.
- `test_merge_keeps_untouched_keys` — existing `{a:1}` + `{b:2}` → both; `replace=True` → only `b`.
- `test_bulk_updates_and_reports_failures` — 3 ids where one belongs to another project → `updated=2`,
  `failed` names the foreign id with reason "not in this project".
- `test_bulk_cap_is_1000` — 1 001 ids → 422, nothing written.
- `test_metadata_filter_numeric_and_string` — `metadata:score>80` returns only the 82 image;
  `metadata:camera="cam001"` returns the exact match.
- `test_flag_off_404_and_selector_refused` — flag off → the bulk route 404s and `metadata:` raises 400.
- `test_cross_workspace_image_patch_refused` — another workspace's image id → the existing `image_ctx`
  refusal, row unchanged.

## Acceptance criteria
- [ ] Metadata keys and values are validated and typed as listed; `null` never persists.
- [ ] A single-image edit merges; a bulk edit reports successes and per-id failures in one response.
- [ ] `metadata:key="v"` and numeric comparisons filter the grid through the T-060 compiler.
- [ ] Keys survive into the image payload so T-089's export can read them.
- [ ] Empty/loading/error states above render (no-metadata copy, inline key error, bulk toast).
- [ ] Flag off ⇒ no field, no route, no selector.
- [ ] Workspace A cannot see or change workspace B's data (a foreign id is a reported failure, never a
      write; the project route answers 404).

## Notes for the implementer
Use `Image.meta`, never `Image.metadata` (SQLAlchemy reserves `metadata` on declarative classes). JSON
indexing differs by dialect; test both SQLite (the default) and Postgres if the suite runs there — do not
use a `LIKE` on the JSON text for numbers.
