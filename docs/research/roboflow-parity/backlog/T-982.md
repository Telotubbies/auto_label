## User story
As an integrator paging through images, I want a stable cursor and a machine-readable error code, so
that a list does not repeat rows when someone uploads during my loop and my code does not regex a
prose message.

## UX flow (LabelDesk words)
1. **SDK / API caller** — `client.images(project, cursor=page.next)` returns
   `{items, next, total}`; `next` is opaque and null on the last page. [empty: `{items: [], next: null,
   total: 0}` — the screen shows its own empty state] [loading: the caller's spinner; the server does
   not stream] [error: a malformed cursor is a 400 whose body is `{error: {code: "bad_cursor",
   message: "…"}}`, never a silent first page].
2. **Retry semantics** — an unknown page after a client restart is `bad_cursor` too, so the caller
   knows to start over instead of guessing.
3. **Error codes** — `not_found`, `forbidden`, `unauthorized`, `invalid`, `bad_cursor`, `conflict`,
   `payment_required`, `rate_limited`. `LabelDeskError` gains `.code`, and `.detail` keeps its meaning.

## Backend changes
- Models/schema: none.
- Routers: `routers/devapi.py` list routes (`list_images`, `list_projects`, `list_models`,
  `list_versions`) accept `cursor` and return `next`; `offset` keeps working for one release with a
  `Deprecation` header naming the replacement.
- Services/jobs: `app/services/page.py` (new) — `encode(kind, key) -> str`,
  `decode(raw, kind) -> tuple | None` (base64 of `"<created>|<id>"`, kind-prefixed so a cursor from one
  list cannot be replayed against another), `window(db, stmt, key_col, created_col, cursor, limit)`
  applying `(< created) OR (= created AND id < id)`; `app/errors.py` gains `ApiError(code, status,
  detail)` and one `@app.exception_handler` registered in `routers/devapi.py`'s module scope so the
  envelope applies only on `/api/v1`.
- Permissions + workspace isolation: unchanged — every query stays rooted at `k.ws.id`; a cursor never
  carries a tenant id (it is decoded and used only as a sort key).
- Secrets/safefetch: none.
- OpenAPI: yes.
