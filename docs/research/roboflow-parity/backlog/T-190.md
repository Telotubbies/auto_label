## User story
As a data engineer, I want one place that defines what a version recipe may contain and in which order it runs, so that the wizard and the API reject the same impossible combinations with the same words.

## UX flow (LabelDesk words)
This card has no screen of its own; it is the contract the next eleven cards render.
1. **Versions list** (`/:ws/:project/versions`) → *Generate new version*. [empty: the button is the only control once the other cards land] [loading: n/a] [error: n/a]
2. Every conflict code defined here becomes an inline message in the wizard (T-193) and a 400 body from `POST /versions` (T-191) — same code, same meaning.

## Acceptance criteria
- [ ] `recipe.normalize` accepts every settings shape already stored in `versions.settings` and returns a canonical dict without raising.
- [ ] `PIPELINE` is exactly `("tiling","crop","resize","isolate","grayscale","contrast")` and every preprocessing code above is reachable by a test.
- [ ] `max_outputs` is derived from `config.PLANS[ws.plan]` with the `ws.quotas` override honoured; no literal cap inside `recipe.py`.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ nothing changes: no route, no UI, the module is inert until T-191 calls it.
