## User story
As an ML engineer, I want the split step to name the trade-off I am choosing and let me leave while it runs,
so that I stop guessing what "rebalance" will do to my dataset.

## UX flow (LabelDesk words)
1. **Versions · Generate · Step 2** — the current split bar plus **Rebalance**. The dialog shows three
   percentage fields, a **Reset** to 70/20/10, and three policy cards with one-line consequences:
   "Move as few as possible — keeps your current split, moves the surplus", "Shuffle everything — a clean
   random assignment", "Balance each upload batch — every batch hits the ratios".
   [empty: no approved images yet → the dialog reads "Approve images first — rebalancing works on the
   dataset" and Apply is disabled]
2. **Rebalance dialog** — an optional class scope: a multi-select of classes with the hint "Only images
   whose classes are all selected can move". Choosing it locks the policy to the first card with a reason.
   [error: percentages ≠ 100 → "Percentages must add up to 100", Apply disabled]
3. **Rebalance dialog** — **Apply** closes the dialog; the tray row shows "Rebalancing splits · 48%" and the
   Step 2 bar updates when it finishes. [loading: the step's apply button keeps its width with a spinner]
4. **Rebalance dialog** — after completion the step reads "Moved 84 images · 412 / 118 / 59" and the
   existing "Keep current splits" option now matches those ratios. [error: a failed run leaves the old
   split and shows the reason with Retry]

## Acceptance criteria
- [ ] The three policies are described by consequence, not by name alone; Reset restores 70/20/10.
- [ ] Percentages must total 100 before Apply enables.
- [ ] Class scope locks the policy and says why.
- [ ] The run is followed in the job tray; the step's bar refreshes on completion and a failure keeps the
      old split.
- [ ] Empty, loading and error states above render.
- [ ] Flag off ⇒ no Rebalance control and Step 2 behaves as today.
- [ ] Workspace A cannot see or change workspace B's data: the job is project-scoped, and a foreign project
      never renders the step.

## Notes for the implementer
"Keep current splits" stays the default in Step 2 — rebalancing is an explicit act. Do not auto-apply
percentages on version create; T-100's endpoint is the only writer of `Image.split`.
