## User story
As someone who knows the name of the project or the page, I want to type it and press Enter, so that I stop hunting through two rails for a screen I visit twice a day.

## UX flow (LabelDesk words)
1. **Any screen, ⌘K or Ctrl-K** — a glass palette opens over the page with an input and three sections: `Pages`, `Projects`, and — inside a project — `Stages`. Typing filters all three. [empty: an empty query shows the four most recent pages the user opened this session, or the five stages inside a project]
2. **No match** — "Nothing matches “xyz”" with the hint "Try a project name or a page such as Versions". The palette stays open; the input keeps focus. [error: if the project list fails to load, the palette still searches pages and says "Projects are unavailable right now"]
3. **Keyboard only** — Down/Up move the highlight, Enter opens, Escape closes and returns focus to the trigger, Tab is trapped inside the dialog.
4. **A labeler typing "train"** — sees Train dimmed with a lock and the reason "Your role cannot train this project", not a silent absence.
5. **A result opens** — the palette closes and the route changes in one navigation; the query is cleared for the next open.

## Backend changes
- Models/schema: none.
- Routers: none — the palette searches `api.projects(ws)` and the static nav registry.
- Services/jobs: none.

## Frontend changes
- Route: none — results navigate with `projectPath()`.
- Nav entry: none; the palette consumes `workspaceNav`, `STAGES` and `SECONDARY`.
- Components:
  - `apps/frontend/src/components/shell/CommandPalette.tsx` (new) — dialog, input, listbox, keyboard handling, focus trap, recent-page memory in `sessionStorage`.
  - `apps/frontend/src/lib/palette.ts` (new) — `buildIndex({pages, projects, stages, role})`, `rank(items, query)`, `kindLabel(kind)`; pure, no React.
- Glass: the palette is `Glass strength="overlay"` — the same dialog surface the app already uses — with the highlighted row on `bg-accent text-accent-foreground` and a locked row dimmed by opacity plus its reason text. No new token.
- API client: `apps/frontend/src/lib/api/core.ts` — reuse `api.projects`; no new call.
- Feature flag: `task_470`; off ⇒ no trigger and no key handler.

## Acceptance criteria
- [ ] ⌘K / Ctrl-K opens the palette on any screen; Escape closes it and returns focus to the trigger.
- [ ] Typing filters pages, projects and stages; Enter opens the highlighted result in one navigation.
- [ ] A locked result renders dimmed with the reason and does not navigate.
- [ ] No-match copy differs from the empty-query state, and clearing the query restores the sections.
- [ ] Empty, loading and error states above all render: empty query shows recents/stages, a slow project list shows a skeleton row, a failed project list says "Projects are unavailable right now" and keeps pages searchable.
- [ ] Workspace A cannot see workspace B's data: the index is built from `/ws/{ws}/projects`, so a foreign project can never appear as a result.
- [ ] Flag off ⇒ no trigger, no key handler, no palette in the DOM.

## Notes for the implementer
No images, versions or runs in the index — those need a new endpoint each and the frames do not show them. Pages, projects and stages cover every route in the rail, which is the promise §3.1 makes.
