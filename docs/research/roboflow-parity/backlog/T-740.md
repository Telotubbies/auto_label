## User story
As a workspace admin, I want to set how long a session may sit idle and how long it may live at all, so that a laptop left in a locker or a shared factory tablet stops being a door into our footage.

## UX flow (LabelDesk words)
No screen in this card. What the user meets once T-743 renders the controls:
1. **Settings → Workspace → `Sign-in security`** (`/:ws/settings/workspace`) — the two numbers are read from this card's policy and shown with their consequence line. [loading: the card's existing "Loading security settings…" line] [error: "Could not load this workspace's security setting." with **Try again**]
2. **A tablet left alone past the idle limit** — the next request answers 401 `"Your session ended after 30 minutes of inactivity. Sign in again."`, the client clears the token and shows the sign-in form with the email prefilled. [empty: a session with no refresh yet is not idle — the clock starts at sign-in]
3. **A member's own sessions** — `GET /api/me/sessions` already lists devices; each row now carries `expires` and `absolute_expires` so the screen can print "signed out at 14:20" instead of "last active".
4. **An admin revoking a member's session** — `GET /api/ws/{ws}/members/{uid}/sessions` lists that member's devices; `DELETE …/sessions/{sid}` ends one. [empty: "This member has no sessions on this server."] [error: 404 when the id belongs to another workspace or another member]
5. **Any refusal** — a foreign member id answers 404, never 403, so an admin cannot probe another tenant's user ids.

## Backend changes
- Models/schema: `Workspace.session_policy JSON` (nullable; absent = the shipped defaults, so no backfill and every existing workspace keeps today's behaviour). Shape `{"idle_minutes": int, "absolute_hours": int}`. One key in the `WORKSPACES` block of `app/schema/identity.py` (`"session_policy": "JSON"`).
- Routers: no new route — `PATCH /api/ws/{ws}` (`WsPatch`) gains `session_policy: dict | None` (validated 400 with the accepted range, owner/admin only), and `GET /api/ws/{ws}` returns the effective policy; `GET /api/me/sessions` gains `expires` and `absolute_expires`; two new admin routes in `app/routers/workspaces.py`: `GET /api/ws/{ws}/members/{uid}/sessions` → `[{id, device, ip, last_seen, created}]`, `DELETE …/sessions/{sid}` → `{ok: true}` (404 for a foreign sid).
- Services/jobs: `app/services/session_policy.py` (new) — `DEFAULTS = {"idle_minutes": 60, "absolute_hours": 720}`, `parse(raw) -> dict` (clamps and rejects out-of-range: idle 5–1440, absolute 1–720), `limits(ws) -> tuple[int, int]` in seconds, `strictest_for_user(db, user_id) -> tuple[int, int]` (the minimum across every workspace the user belongs to; no membership → `DEFAULTS`), `expired(row, now) -> str | None` returning `"idle" | "absolute" | None`. `app/routers/auth.py::refresh` calls `expired()` before minting and deletes the row with a 401 whose detail names the reason; `app/routers/auth.py::tokens` stamps `RefreshToken.expires = min(now + REFRESH_TTL, now + absolute)`.
- Permissions + workspace isolation: `c.need("admin")` on both member-session routes (matching `set_role`); `Member` is resolved by `(c.ws.id, uid)` so another workspace's member is 404; `_workspace_ctx` already 404s an unknown slug.
- Secrets/safefetch: none — a policy is two integers, no URL and no credential.
- OpenAPI: yes — `WsPatch`, the workspace payload, `/me/sessions` rows and two member-session routes.

## Acceptance criteria
- [ ] A workspace stores an idle limit and an absolute limit, and refresh honours both with a 401 that names which one was hit.
- [ ] The strictest workspace policy applies to a user who belongs to several; no policy anywhere means today's 30-day session.
- [ ] An admin lists and revokes another member's sessions; a session id from another workspace or another member is 404.
- [ ] Empty, loading and error states above all render: no sessions is an empty list, the loading row is the shipped skeleton, a 401 shows the reason sentence on the sign-in form.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no policy is read or written, and a session lives exactly as long as it does today.

## Notes for the implementer
Idle is measured from `RefreshToken.last_seen`, which is written at sign-in and at every refresh — so the honest sentence is "idle since the last refresh", and a background tab that never requests keeps its session until the absolute limit. Do not touch `security.ACCESS_TTL` (15 minutes): it is already the tightest bound and shortening it breaks long training-page polls. `strictest_for_user` exists because one sign-in covers every workspace; a per-workspace expiry would sign a person out of the workspace they are working in.
