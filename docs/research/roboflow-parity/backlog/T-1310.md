## Problem
`audit()` covers 67 write sites and the export works, but six events are missing: **login**,
**failed login**, **logout** (they live only in `LoginEvent`, which is per user and not
workspace-scoped, so the workspace audit export cannot show them), **annotation save**, **image
delete** and **job cancel**. "Who deleted that batch / who kept trying to sign in / who cancelled the
training run" is unanswerable from one place.

## Design
Six `audit()` calls, no new table, no new route:
- `routers/auth.py`: `auth.login`, `auth.login_failed` (target = email, `meta.method`), `auth.logout`.
  Keep `LoginEvent` exactly as it is — it powers the per-user history screen.
- `routers/images.py`: `image.annotate` once per save with `count`, `replaced` and `source` (never the
  box coordinates — the annotation row already holds those), `image.delete` with the name.
- `routers/projects.py:523`: `job.cancel` with the job id, kind and previous status.
- `meta` never carries a password, token, signed URL or file path.

Also add the three names to the audit screen's action filter vocabulary if it is a closed list, and to
the CSV/JSON export test fixture.

## Tests to write first
`apps/backend/tests/test_audit_coverage.py`:
- `test_login_writes_one_audit_row_with_the_workspace` — after login, one row with `action="auth.login"`,
  the workspace id and the user id.
- `test_failed_login_is_recorded_without_the_password` — wrong password; `auth.login_failed` exists,
  and the serialised `meta` contains no password and no hash.
- `test_logout_is_recorded`.
- `test_annotation_save_is_one_row_per_save_not_per_box` — 40 boxes ⇒ one `image.annotate` row with
  `count=40`.
- `test_image_delete_names_the_image_and_no_path`.
- `test_job_cancel_records_the_previous_status`.
- `test_the_six_actions_appear_in_the_export` — CSV and JSON export contain them for an admin.
- `test_member_cannot_read_the_audit_log` — unchanged behaviour, asserted once here.

## Acceptance criteria
- [ ] All six actions are written, workspace-scoped, and read back through the existing export.
- [ ] No `meta` value contains a secret, hash, password, token, signed URL or absolute path.
- [ ] Annotation saves produce one row per save, so a 40-box save does not flood the table.
- [ ] A failed login is recorded even when the workspace cannot be resolved (workspace id may be
  empty; the email is the target).
- [ ] The existing audit tests and export tests still pass unchanged.

## Notes for the implementer
`audit()` needs a workspace id; on a failed login for an unknown email there is none — pass `""` and let
the row stand (the schema allows it, and the export filters by workspace, so it will be invisible to
tenants; say so in the report). Do not throttle these: a login is a rare event, unlike the API-key use
row that is throttled to one per minute.
