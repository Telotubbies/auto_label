## User story
As a reviewer, I want one search across every project in the workspace that pages with a cursor and names
the source project, so that "where did I put that photo" no longer means opening projects one by one.

## UX flow (LabelDesk words)
1. **Top bar** — a **Search** button (⌘K opens it when the palette ships) goes to `/:ws/search`.
2. **Search** — one input plus the same chip syntax; results are rows with thumbnail, name, project chip,
   split, status and age. [empty: "Search images across 6 projects — try `class:helmet` or `tag:night`"]
   [loading: 8 skeleton rows, the previous page stays visible]
3. **Search** — scrolling or **Load more** appends the next cursor page; the footer reads "30 of 412
   matches". [error: a malformed query → the inline message with the caret position, previous page kept]
4. **Search** — clicking a row opens the image in its own project's editor (the project chip is the
   context); a second link opens that project's dataset with the same query. [empty per project: a project
   with no match contributes nothing and is not listed in the "searched" summary]

## Backend changes
- Models/schema: none.
- Routers: `apps/backend/app/routers/search.py` (new), prefix `/api/ws/{ws}`:
  `POST /search` body `{query: str, cursor?: str, limit?: int (default 50, max 200)}` →
  `200 {items: [{imageId, name, project, projectName, thumbnail, split, status, created}], nextCursor,
  projects: [{slug, name, matches}], total}`; `400` for a malformed query (same `position` shape as
  T-061); `404` when the workspace is not the caller's.
- Services/jobs: `apps/backend/app/services/search.py` (new) —
  `parse_cursor(str) -> (created, id)`, `encode_cursor(created, id) -> str` (base64url of
  `created:id`), and `search(db, ws, ctx, query, cursor, limit)` that resolves the caller's readable
  projects (≤ 50, `Project.deleted_at IS NULL`), compiles the query per project through
  `services.query.compile`, applies `assignee_id == user` for a labeler, orders by `(created desc, id)`
  and merges the per-project pages until `limit`; `total` comes from the same per-project counts.
- Permissions + workspace isolation: `ws_ctx` membership; each project is included only when it lives in
  that workspace and the caller's project role grants `project.read`; a labeler's rows are their own
  assignments, and honeypot counts are blanked in the payload (`annotationCount=0`), matching the list
  route.
- Secrets/safefetch: none.
- OpenAPI: yes — one route.

## Acceptance criteria
- [ ] One query returns rows from every readable project, each naming its project.
- [ ] Cursor paging appends without repeats or gaps and stops with a null cursor.
- [ ] A labeler's results contain only their assignments; a project without read rights is skipped.
- [ ] A malformed query shows the caret message and keeps the previous page.
- [ ] Empty, loading and error states above render.
- [ ] Flag off ⇒ no button, and `/:ws/search` redirects to Home.
- [ ] Workspace A cannot see or change workspace B's data (404 for a foreign workspace slug).

## Notes for the implementer
Do not build the full command palette here: a button and a page are enough, and the palette card can call
`POST /search` unchanged. The cursor is `(created, id)` so two images uploaded in the same second still
page deterministically. `project:` / `dataset:` selectors are not part of this route — the search already
spans every readable project and each row carries a project chip; a query containing one returns 400 with
"Search all projects, then filter by project in the results" rather than silently ignoring it.
