## User story
As a buyer, I want the credit rate per action and per plan laid out before I commit, so that I can forecast a month instead of asking for a quote.

## UX flow (LabelDesk words)
1. **Deploy & test → "What it costs"** — one table built from the server, never from a hard-coded list: `Action · Credits · Unit`, rows for a hosted inference call, a dataset write from the workflow sink, one auto-labelled image, one training run, one version build. A second table shows the plan's included allowance (`AI calls`, `GPU seconds`, `stream hours`, `storage`) and the credits included. [empty: a deployment with no plan data → "Costs appear once the plan is set." and no numbers] [loading: two skeleton tables] [error: "Costs could not load." with "Try again"; the rest of the page keeps working]
2. **Volume note** — one worked line computed from the server's own numbers: "1,000 images on the hosted API = 1 credit. 10,000 = 10 credits." The arithmetic is a pure function of the rate, so it cannot drift.
3. **The billing unit is stated where it is unusual** — streams bill per hour of processing and storage bills per byte, so those two rows say so in words, and the table footer reads: "Included credits do not roll over. A refused request (402, 413, 429, 5xx) is not billed."
4. **No checkout** — the page links to `/:ws/settings/usage` for the workspace's real usage and to the plan page. It contains no price, no card form and no payment provider.

## Backend changes
- Models/schema: none.
- Routers: `apps/backend/app/routers/runtimes.py` — `GET /api/ws/{ws}/costs` returning `{actions: [{id, label, credits, unit}], plan: {id, label, includes: {...}}, notes: [...]}` read from `config.CREDIT_COST` and `config.PLANS`.
- Services/jobs: `apps/backend/app/services/credit_rates.py` (new) — `ACTIONS` mapping each credit key to a label and a unit (`per image`, `per run`, `per version`, `per call`), `rows() -> list[dict]`, `plan_for(ws) -> dict` (allowance only, no money), `worked_example(credits, n) -> str` and `refusal_notes()`.
- Permissions + workspace isolation: `ws_ctx`; the payload carries the workspace's own plan and nothing about another tenant.
- Secrets/safefetch: none.
- OpenAPI: yes — one route.

## Tests to write first
pytest — `apps/backend/tests/test_credit_rates.py`:
- `test_every_credit_key_has_a_label_and_a_unit` — the set of ids equals `CREDIT_COST`'s keys, so a new charge cannot ship unpriced in the UI.
- `test_the_rows_match_the_configured_rates` — changing `CREDIT_COST["infer"]` in a monkeypatch changes the row, proving nothing is hard-coded.
- `test_the_plan_block_carries_allowances_and_no_money` — the payload has `ai_calls`/`gpu_seconds`/`stream_hours`/`storage_bytes` and no key named `price`, `cost`, `currency` or `amount`.
- `test_the_worked_example_scales_linearly` — 1,000 → 1 credit at 0.001 each; 10,000 → 10.
- `test_another_workspace_plan_never_leaks` — two workspaces on different plans get their own `plan.label`.
- `test_flag_off_is_404`.
node — `apps/frontend/tests/cost-table.test.mjs`:
- `test_the_unit_is_spelled_out` — `unitLabel("call")` is "per call", `("image")` is "per image".
- `test_the_worked_line_pluralises_once` — one image reads "1 credit", two read "2 credits".
- `test_a_refused_request_note_is_present` — `rowsFor` output includes the note listing 402/413/429/5xx as unbilled.

## Acceptance criteria
- [ ] Every charged action appears with its credit amount and unit, read from configuration.
- [ ] The plan block shows allowances and credits only — no price, no currency, no checkout.
- [ ] The worked line is computed, and the refusal note names the codes that are not billed.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no section and the route is 404.

## Notes for the implementer
No payment provider, no price and no charge is added by this card: the three owner decisions (provider, plan price, self-host licence) are still open, and this is disclosure of the rates the product already meters. Flag off by default so the numbers can be reviewed before a buyer reads them.
