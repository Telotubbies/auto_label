## User story
As a platform engineer, I want a signed event when a version is registered, tagged, aliased or deprecated, so that a CI pipeline can promote or roll back without polling our API.

## UX flow (LabelDesk words)
1. **Subscribe** — a webhook created today with events can also select `model.version.created`, `model.tagged`, `model.alias.moved`, `model.deprecated`; the API accepts them and rejects anything else with the existing 400 that lists the allowed set. [empty: a webhook with no registry event simply never fires for one] [error: an unknown event name is refused with the list, not silently dropped]
2. **Receive** — registering a version POSTs `{event, workspace_id, project_id, model: {id, name, version}, actor, at}` with the existing HMAC header and timestamp. [error: a non-2xx target records a delivery row with the status and retries with backoff, exactly as `job.done` does today]
3. **Inspect** — the delivery log lists the event name beside the model name, so a failed promotion is visible without reading worker logs.
4. **Admin only** — creating or testing a webhook stays a workspace-admin action; a non-admin gets today's 403.
5. **No new egress rule** — the URL still goes through the SSRF-guarded fetcher and the secret stays encrypted.

## Backend changes
- Models/schema: none — extend `WEBHOOK_EVENTS` in `apps/backend/app/models/common.py` with the four names (the tuple is already the single source the router validates against).
- Routers: no route change; `POST {P}/models/{mid}/register`, `PUT …/tags/{key}`, `POST …/deprecate` and the alias routes call one emit helper after their transaction commits.
- Services/jobs: `apps/backend/app/services/registry_events.py` (new) — `version_created(db, model, user_id) -> int`, `tagged(db, model, key, user_id) -> int`, `alias_moved(db, project, alias, model, user_id) -> int`, `deprecated(db, model, user_id) -> int`; each builds the envelope, calls `webhooks.emit` and swallows-and-logs any failure so a notification never fails the write (the same contract as `apps/backend/app/handlers/training.py:176`).
- Permissions + workspace isolation: the envelope carries the workspace and project ids, and `emit` only selects that workspace's webhooks; a model id from another workspace is still a 404 before any emit.
- Secrets/safefetch: reuses `services/secretbox.py` for the signing secret and `services/safefetch.py` inside delivery; no new secret handling.
- OpenAPI: no — no contract change.

## Acceptance criteria
- [ ] The four registry events are accepted by the webhook API and delivered with the workspace, project, model and actor in the envelope.
- [ ] Delivery uses the existing HMAC, retry and SSRF guards, and a failing target never fails the registry write.
- [ ] A webhook subscribed only to registry events receives nothing from another workspace.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
