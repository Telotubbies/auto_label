## User story
As a supplier handing a model to a plant's OT team, I want one page per model — intended use, what it must not be used for, known failure modes and a contact — that downloads with the weights, so that the receiving team has the caveats without asking us.

## UX flow (LabelDesk words)
1. **Model page → Card tab** (`/:ws/:project/models?model=<id>&tab=card`) — a draft is pre-filled from what the system knows: version, class list, evaluation numbers, licence, training date and the slice results. The four prose fields are empty and marked required. [empty: the first visit shows the generated draft and what is missing, never a blank page]
2. **Publish** — blocked until `Intended use`, `Not for`, `Known failure modes` and `Contact` are filled; the response returns the frozen revision and the model page names it. [error: an empty field is named in the API detail and the form focuses it]
3. **Edit after publish** — saving creates revision 2 as a draft; revision 1 keeps its text and its publish time, and the model page names the live revision.
4. **Download bundle** — one zip with `best.pt` (or the HF directory listing when there is no single file), `model-card.md` and `evaluation.json`. [error: a model without weights answers 409 "This model has no downloadable weights."]
5. **A model trained before this shipped** — the tab generates the draft from stored metrics only, and the card says 2 numbers are missing rather than inventing them.

## Backend changes
- Models/schema: `ModelCard` (`id, workspace_id, project_id, model_id, revision, status, intended_use, not_for, failure_modes, contact, facts(JSON), created_by, created, published`), unique on `(model_id, revision)`, in a new `app/models/cards.py`; a new table needs no `ADD COLUMN`.
- Routers: new `app/routers/model_cards.py` — `GET …/models/{mid}/card` (live revision plus a draft when one exists), `POST …/models/{mid}/card` (create or update the draft, 201), `POST …/models/{mid}/card/publish` (freeze the draft, 422 naming missing fields), `GET …/models/{mid}/card.md` and `GET …/models/{mid}/bundle` (streamed zip, 409 without weights).
- Services/jobs: `app/services/model_card.py` (new) — `facts(db, model)` (version, classes, eval headline, licence, created, slice summary, leak-audit state when stored), `render_markdown(card, facts)`, `bundle_path(db, model)` writing the zip into `DATA_DIR/cards/<model>/` with `zipfile` from the standard library.
- Permissions + workspace isolation: `project.models` for read and download, `admin` to publish; a model, card or bundle id from another workspace answers 404.
- Secrets/safefetch: no secret; the bundle is served through the existing signed-file pattern and never through a public URL.
- OpenAPI: yes — regenerate both generated files.

## Tests to write first
pytest — `apps/backend/tests/test_model_card.py`:
- `test_draft_is_prefilled_from_stored_facts` — a ready model with an evaluation → `GET …/card` returns a draft whose `facts.classes` and `facts.AP` match the model, with all four prose fields empty.
- `test_publish_requires_four_fields` — publish with `contact` empty → 422 naming `contact`, no published revision.
- `test_publish_freezes_and_edit_creates_revision_two` — publish revision 1, then save a new intended use → revision 2 is a draft and revision 1 keeps its text.
- `test_bundle_contains_weights_card_and_evaluation` — bundle → the zip lists `model-card.md`, `evaluation.json` and a weights entry.
- `test_bundle_without_weights_is_409` — a model with no weights → 409.
- `test_other_workspace_card_is_404` — workspace B reads A's card and bundle → 404.
- `test_flag_off_is_404` — flag off → 404 on all card routes.

## Acceptance criteria
- [ ] One card document per model, pre-filled from stored facts and authored in four required prose fields.
- [ ] Publishing is refused until all four fields are filled, and names the missing ones.
- [ ] A published revision is frozen; a later edit becomes a new revision and the model page names the live one.
- [ ] The bundle contains the weights, the card and the evaluation JSON, and refuses a model without weights.
- [ ] Empty, loading and error states above all render as API states: a model with no card returns a generated draft, a missing field is a named 422.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no card routes and the existing weights download is unchanged.

## Notes for the implementer
Facts are generated, prose is authored — never let the user edit a generated number into the card text. The zip is built once per (model, revision) and cached under `DATA_DIR/cards/`, rebuilt when the live revision changes; `zipfile` and `markdown` are not dependencies (write Markdown as plain text). A published revision is append-only: no update path, only a new revision.
