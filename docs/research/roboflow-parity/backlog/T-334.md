## User story
As a reviewer, I want to run a trained model over the images I just filtered and see that exact set again later, so that "which four thousand images did this run on" stays answerable.

## UX flow (LabelDesk words)
1. **Dataset → selection bar → "Run model"** — the existing bar (`Dataset.tsx:141-153`) gains one button beside Auto label. It opens a dialog with the count, a model select (registry refs with an `available` flag and a reason), an output choice (`CSV`, `COCO`, `Write to dataset`) and a name that defaults to `Run · <date>`. [empty: nothing selected → the button is not rendered, because the bar is not rendered] [loading: the dialog's registry list shows a spinner] [error: more than 500 picked → the dialog says "Pick up to 500 images per run." and the Run button stays disabled]
2. **Run** — the dialog closes and a job row appears in the project's job list with `n images`; the job tray carries it while the person keeps working.
3. **Re-open the set** — the finished job's row shows "Source · 214 picked images" and an "Open in Dataset" link that restores the same selection (`?selection=<token>` where the token is the job id). [error: the images were deleted since → the link opens the dataset with one line, "18 of this run's images were deleted."]
4. **Refused shapes** — a VLM with the dataset output, or a classification model with COCO, is refused in the dialog by the same rules the API already enforces (`routers/batch_inference.py:58-65`), before the job starts.

- Permissions + workspace isolation: `project.infer` as today; every id is filtered by `Image.project_id == project.id`, so another project's id is silently absent rather than readable.
- Secrets/safefetch: none.
- OpenAPI: yes — one enum value and one field.

## Acceptance criteria
- [ ] The selection bar runs a model over exactly the picked images (≤500) and reports the count.
- [ ] A foreign id, a deleted image or an unsupported output never reads or writes outside the project, and each is explained.
- [ ] The finished job names its source and reopens the same selection from the dataset.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no button, no dialog, and every existing batch source still runs.

## Notes for the implementer
The selection is a list of ids, not a stored query — a saved query would silently change its meaning as images arrive. Cap at 500 because the job is one metered model call per image and the runner already stops at `MAX_IMAGES`.
