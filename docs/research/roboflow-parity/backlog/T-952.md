## User story
As an ML engineer, I want to score predictions another team produced without running their model, so that a
vendor's export is judged on our test set instead of on their own numbers.

## UX flow, click by click.
1. **Models → Evaluation → Score a prediction file** — a dialog: file drop (COCO results JSON `[{image_id,
   category_id, bbox, score}]` or a CSV of `file,class,confidence,x,y,w,h`) and the set to score against.
   [empty: no set exists yet ⇒ "Pin an evaluation set first" with the link, drop zone disabled]
2. **Map the columns** — for a CSV, one select per required field with a three-row preview. For a COCO file
   the mapping is read from the file and shown read-only. [error: "row 14 has no image name" naming the row
   and keeping the file in the dialog]
3. **Score** — *Score* runs the same metric pass as a model evaluation and opens the result in place. The
   panel is badged *External predictions* with the file name and its digest, and the sentence "no model was
   run for these numbers". [loading: a determinate bar per 1,000 rows; the dialog cannot be closed mid-run
   without a confirm]
4. **Compare** — the result appears in the compare picker next to trained models, marked *external*, so
   nobody mistakes it for a live model. [empty: a file whose classes share nothing with the set aborts with
   "no shared classes" and lists both sides]
5. **Delete** — the result can be discarded, which removes the stored report and its row from the picker.

## Backend changes
- Models/schema: no new table — the report is stored as a `TrainedModel`-shaped row? No: it is not a model.
  New table in `apps/backend/app/models/evaluation.py`: `ExternalResult(id, workspace_id, project_id,
  set_id, name, digest, report JSON, created, created_by)`, FK `set_id` `ondelete=CASCADE`.
- Routers: `POST {P}/evaluation-sets/{set_id}/external-results` multipart `file` + `name` + optional
  `columns` (JSON) → 201 with `{id, report}`; `GET {P}/external-results` → `{results: [{id, name, digest,
  set_id, summary}]}`; `DELETE {P}/external-results/{id}` → 204. 400 for an unparsable file, a missing
  required column, a class not in the set, or more than 200,000 rows; 413 above 25 MB; 404 for a foreign set.
- Services/jobs: `apps/backend/app/services/external_results.py` (new) — `parse_coco_results(bytes, set)`,
  `parse_csv(bytes, columns, set)`, both returning COCO detection records keyed to the set's image ids, then
  reusing `services.evaluate._coco_stats`, `_sweep` and `_confusion` on the set's ground truth (no inference
  call). Runs inline: a 200k-row file is a few seconds of pycocotools, so no job kind is needed.
- Permissions + workspace isolation: `c.need("admin")` to score and delete, `project.review` to list; a
  foreign set or result is a 404.
- Secrets/safefetch: none — the upload is a request body, never fetched from a URL. Dependency: none added
  (no `mlflow-skinny`), so no `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] A COCO results file and a CSV both produce a full metric report against a pinned set.
- [ ] The report is labelled external, carries the file digest and never claims a model was run.
- [ ] Oversized files, missing columns and class mismatches each fail with the documented status and sentence.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: `5-F5.29` → T-290 evaluates *uploaded weights* (a model we run); this scores predictions nobody can
run. `apps/backend/app/services/importers.py` parses COCO *annotations* with a different goal and must not be
extended — its `_coco` normalises labels into shapes, ours keeps scores and boxes.
Bound the parse before the metrics: `MAX_ROWS` and `MAX_BYTES` are checked before pycocotools is imported into
the call.
