## User story
As the customer's operations lead, I want one URL that answers "is it just me" before I file a ticket, so that a slow morning is a refresh rather than an hour of email.

## UX flow (LabelDesk words)
1. **Public `/status`** (no login) — overall state at the top ("All components operating normally", "Partial outage", "Maintenance"), then one row per component: API, Database, Worker, GPU, Model server, Queue. Each row has a state chip and a short factual detail ("1 online / 2 total"). [empty: a component with no reading reads "No reading yet" and is not counted as healthy] [loading: every row renders a skeleton bar so a slow page never looks down] [error: "The status page could not load. This is not a signal about the platform." with `Try again`]
2. **`Updated`** — one line: "Sampled 42 s ago. Sampling stops while the worker is down, and the page says so."
3. **`Subscribe by email`** — one field; the confirmation reads "Check your inbox to confirm." (the delivery side is T-773's card).
4. **A degraded component** — its row turns to the warning tone with the word "Degraded" beside the colour and the detail that caused it.
5. **Flag off** — `/status` renders the signed-out 404 page and the endpoint 404s.

## Backend changes
- Models/schema: `StatusSample(id, component, state, detail, checked)` appended to `app/models/incidents.py`; index on `(component, checked)` created in `app/bootstrap.py` next to the existing `ix_stream_events_stream_ts`.
- Routers: `app/routers/status_page.py` (new) — `GET /api/public/status` (no auth: `{overall, components: [{name, state, detail, checked}], sampled_at, sampled_ago, history_days}`), `GET /api/public/status/history?days=90` (per-component bars, one entry per calendar day with the worst state that day).
- Services/jobs: `app/services/health_components.py` (new) — the six component functions moved out of `routers/admin.py` (`_database_component`, `_worker_component`, `_gpu_component`, `_vllm_component`, `_queue_component` and the `api` row) exposed as `components(db) -> list[dict]`; `routers/admin.py` delegates in one line each so the two pages cannot drift. `app/services/status_page.py` (new) — `SAMPLE_EVERY = 60`, `sample(db, force=False) -> int` (writes one row per component when the newest sample is older than the interval), `overall(rows)`, `public_state(db)`, `history(db, days)`. `app/worker.py` calls `status_page.sample()` once inside the existing `RETENTION_CHECK_S` block in `loop()`, so sampling does not depend on visitors.
- Permissions + workspace isolation: the endpoints are public and carry no tenant data — no workspace id, no customer name, no queue payload; the per-workspace admin page keeps `require_superadmin`.
- Secrets/safefetch: none — component details are counts and state words, never a connection string or a URL with credentials.
- OpenAPI: yes.

## Tests to write first
pytest — `apps/backend/tests/test_public_status.py`:
- `test_the_public_page_needs_no_session` — `GET /api/public/status` with no token → 200, six components, `overall` in the four allowed words.
- `test_the_page_carries_no_tenant_data` — the body holds no workspace slug, email or project name.
- `test_sampling_is_rate_limited_to_one_row_per_component` — call `sample()` twice inside the interval → the second returns 0 and the table has six rows, not twelve.
- `test_sampling_skips_when_the_newest_row_is_fresh` — a sample 30 s old → `sample()` returns 0 and `checked` is unchanged.
- `test_a_component_with_no_sample_reads_no_reading` — delete every sample for `gpu` → the component reports `state="unknown"` with "No reading yet" and is excluded from `overall`.
- `test_history_returns_one_entry_per_day_with_the_worst_state` — three samples in one day (operational, degraded, operational) → exactly one entry for that day, `degraded`.
- `test_flag_off_hides_the_page_and_the_endpoints` — with `task_public_status` off → `GET /status` page payload and `GET /history` both 404.
- `test_the_admin_endpoint_still_answers` — a superadmin still reads `/api/admin/status` with the same six components after the move.

node — `apps/frontend/tests/status-view.test.mjs`:
- `test_overall_takes_the_worst_component` — `overallLabel({components: [{state:'operational'},{state:'degraded'}]})` is "Partial outage".
- `test_unknown_is_not_healthy` — a payload of one `unknown` component reads "No reading yet" and the overall is "Status unknown", never "operating normally".
- `test_ago_line_names_the_pause` — `agoLine(t, t + 3600)` contains "hour" and "sampling stops while the worker is down".

## Acceptance criteria
- [ ] A signed-out visitor reads overall state and six component rows with no workspace data in the payload.
- [ ] Samples are written at most once per minute per component and also while nobody is looking.
- [ ] A component with no sample reads "No reading yet" and never counts as healthy.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no page, both endpoints 404, and `/api/admin/status` reads exactly as today.
