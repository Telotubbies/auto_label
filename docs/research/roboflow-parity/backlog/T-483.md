## User story
As a project manager opening a project, I want one screen that says which step is done, which is blocked and what to do next, so that I stop inferring the pipeline from a grid of thumbnails.

## UX flow (LabelDesk words)
1. **`/:ws/p/:project`** — header with the project name, type, `24 approved` and one primary (`Label 40 images`), then five numbered cards left to right: Upload, Annotate, Dataset, Train, Deploy. Each card shows a state chip, a count, one explanation sentence and one action. [empty: a project with no images shows Upload as the only enabled card and the others as `not started` with the action "after upload"]
2. **Annotate card, 16 in review** — chip `needs you`, count `16`, sentence "16 labels are waiting for approval", action `Review 16`.
3. **Train card, last run failed** — chip `blocked`, sentence "The last run failed at epoch 4 — open the run to read the log", action `Open run`. [error: a card whose count fails to load shows `—` and a `Retry` link in place of the count]
4. **A labeler** — Train and Deploy cards render dimmed with a lock and "Request access", never hidden, so the pipeline is learned once.
5. **Below 768 px** — the board becomes a vertical stepper: five rows, each with dot, count and one action (T-491 draws the shell).

## Acceptance criteria
- [ ] `/:ws/p/:project` renders the overview, not the grid, and the rail's stage ② matches the Annotate card's numbers.
- [ ] Every card carries a state chip, a count, one sentence and exactly one action.
- [ ] Locked stages render dimmed with a reason; no card is hidden from a role.
- [ ] The board is an ordered list, heading order is `h1` then five `h2`, and a card is reachable with Tab then Enter.
- [ ] Empty, loading and error states above all render: no images ⇒ four `not started` cards; loading ⇒ five card skeletons of the same height; a failed count ⇒ `—` with `Retry`.
- [ ] Workspace A cannot see workspace B's data: a foreign slug renders "Project not found", and no card shows another workspace's numbers.
- [ ] Flag off ⇒ the project index redirects to the dataset grid exactly as today.
