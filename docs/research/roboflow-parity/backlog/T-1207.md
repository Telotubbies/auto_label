## User story
As an ML engineer, I want to start a run with the cost and time visible, watch it finish, and see whether
it beat the previous model on the same test split, so that "better" is a number I can defend, not a
feeling.

## UX flow (LabelDesk words)
1. **Train** (`/:ws/p/:project/train`) — block 1 picks a version with its health chip; block 2 is three
   promises (Fast / Balanced / Accurate) with epochs, size, ETA and credits; block 3 names the output.
   [error: starting without a version names what is missing; a second active run is refused].
2. **Start Training** — the summary card states time, credits and device before the click; after it, the
   page becomes the run view with live loss and a job-tray entry.
3. **Run completes** — the run card shows the stage sequence, the test metrics and a link to Compare.
   [error: a stopped run keeps its best checkpoint and says so].
4. **Models → Compare** (`/:ws/p/:project/models`) — the accuracy-versus-latency chart selects a run; the
   metric tiles and the confusion matrix follow the selection.
5. **Compare with the previous run** — the delta is visible per metric; a run trained on another version is
   marked "not directly comparable".
6. **What to fix next** — each recommendation opens the filtered dataset it names.

## Acceptance criteria
- [ ] The summary states time, credits and device before the run starts; the estimate never reads zero.
- [ ] The run's stages advance on screen and end in a result with a test metric.
- [ ] Compare shows at least two runs, their delta on the same split, and the not-comparable marker across
      versions.
- [ ] Selecting a run changes the tiles and the matrix together; no stale number survives the switch.
- [ ] Steps ≤ 10 and time ≤ 240 s; numbers recorded.
- [ ] Empty, loading and error states: no version, no runs yet, a busy start, a stopped run, a failed run
      with a remedy.
- [ ] No console error; the page states that metrics came from the run, not from a re-evaluation.
- [ ] Workspace isolation: a run in workspace A is absent from B's run list.
- [ ] Flag off ⇒ the train surface is unchanged; the card adds no flag.

## Notes for the implementer
The fixed metrics must differ enough for a delta (for example mAP50 0.703 vs 0.612) and must be labelled
as run numbers. Do not assert a GPU name or a real duration; the harness is a fake worker and the card
must not turn that into a product claim.
