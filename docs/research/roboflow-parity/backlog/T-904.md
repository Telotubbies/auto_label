## User story
As an engineer choosing between six runs that traded mAP for recall in different ways, I want one chart where each
run is a line crossing every metric, so I can see the run that wins on the axes I care about instead of reading six
line charts one at a time.

## UX flow (LabelDesk words)
1. **Insights → Training** — below the three curve groups, a fourth full-width card **Every metric at once**:
   one vertical axis per numeric key of the selected runs, one polyline per run, coloured by the same run colour
   used in the curves. [empty: fewer than two runs selected renders `Pick at least two runs to compare across
   metrics.`] [loading: a chart skeleton of the same height] [error: a run missing a key draws a gap and the
   caption names the missing axes]
2. **Hover an axis** — the axis label shows the metric plus its value range; hovering a line dims the others
   (emphasis focus) and the tooltip names the run.
3. **Chart card actions** — *Export CSV* gives `Run, <metric labels…>` with one row per run; JSON gives
   `{axes:[{key,label,min,max}], runs:[{id,name,values[]}]}`; the table view lists the same grid for screen
   readers and for copy-paste into a report.
4. **A loss axis** — loss axes are inverted (lowest at the top) so "higher is better" reads the same on every axis,
   and the axis label says `lower is better`.

## Tests to write first
pytest — none: no backend surface.
node — `apps/frontend/tests/parallel-runs.test.mjs`:
- `test_one_axis_per_key_and_one_line_per_run` — two runs × three keys → `option.parallelAxis.length === 3`,
  `option.series[0].data.length === 2`, every data row has three numbers or `null`.
- `test_the_latest_epoch_wins` — a history whose key climbs 0.4 → 0.7 → `latestValues` reports 0.7, and a key
  present only at epoch 2 is not carried forward from epoch 1.
- `test_a_loss_axis_is_inverted` — `train/loss` gets `inverse: true` and a `lower is better` label, while
  `metrics/mAP50(B)` does not.
- `test_a_missing_key_becomes_a_gap_not_a_zero` — a run whose history lacks a key contributes `null` at that
  index (the chart must not read as a real 0).
- `test_csv_has_a_header_per_key_and_a_row_per_run` — header `['Run', …labels]`, two data rows, labels matching
  the axis labels.

## Acceptance criteria
- [ ] The chart renders 2–6 runs against every numeric key of the selection, using the same colours as the curves.
- [ ] A missing value is a gap in the line and `null` in the export — never `0`.
- [ ] Loss axes are inverted and labelled; quality axes are not.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
