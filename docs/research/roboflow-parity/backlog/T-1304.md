## Problem
Workspace isolation is enforced per query (`docs/architecture/overview.md:41`), and the evidence is
scattered across `test_rbac.py`, `test_task24_security.py`, `test_mcp_isolation.py` and a dozen route
tests. There is no matrix that says "every resource kind, every principal type, foreign id ⇒ 404".
A new route inherits no test, and a missing `workspace_id` filter returns someone else's row quietly.

## Design
One file, one parameter table, two principals.

- Build workspace A (owner + member + labeler) and workspace B (owner) with one row of **every**
  resource kind: project, image, annotation, version, model, job, stream, connector, webhook, alert
  channel, workflow, API key, audit export, deployment alias, video, event-search frame.
- `FOREIGN = [(method, url_template, payload), …]` — one row per kind, ids taken from workspace B.
- Two principals: A's **session** (owner) and A's **API key** (`ld_`). Both must get **404**, never
  403-with-a-body, never 200, and never a row from B.
- Auth-bypass table: no `Authorization`, `Bearer garbage`, expired access token (mint with `exp` in the
  past), tampered signature (flip one base64 char), a revoked key, a deleted user's token, a
  publishable key (`ld_pub_`) on every write route and on `/api/v1` non-`infer` routes, a refresh token
  replayed after rotation, and a signed file URL for a foreign path.
- Also assert the **positive** case for each row: A's own id returns 200/204, so a route that 404s
  everything cannot pass the matrix.
- A `pytest.mark.parametrize` id names the kind, so the failure report says `image`, `webhook`, …

## Tests to write first
`apps/backend/tests/test_sec_idor.py`:
- `test_foreign_id_is_404_for_every_resource_kind` — the parameterised matrix, session principal.
- `test_foreign_id_is_404_for_an_api_key` — the same table with `x-api-key`.
- `test_own_id_is_200_for_every_resource_kind` — the control row.
- `test_no_foreign_row_appears_in_a_list` — B's names never appear in A's lists, search and exports.
- `test_a_foreign_file_url_is_403` — signed URL for `ws_b/…` used by A.
- `test_refresh_replay_after_rotation_is_401`.
- `test_publishable_key_cannot_reach_a_write_route` — every write route in the table.
- `test_expired_and_tampered_tokens_are_401` — and the body carries no decoded claim.
- `test_a_deleted_users_token_is_401`.
- `test_matrix_covers_every_router` — walk `app.routes`, and fail if a router's prefix family has no row
  in the table (a hard-coded allowlist of intentional omissions: `/api/auth/*`, `/api/health*`,
  `/api/metrics`).

## Acceptance criteria
- [ ] Every listed kind returns 404 for a foreign id under both principals, and 200 for its own id.
- [ ] No refusal body contains a foreign name, id echo or exception text.
- [ ] The coverage test fails when a new router file is added without a matrix row.
- [ ] The whole file runs in under 25 s on the seeded SQLite database.
- [ ] No production code change, unless a real leak is found; then the fix is a separate one-line
      change in the same branch, named in the report.

## Notes for the implementer
If the matrix finds a real leak, stop and report it to the PM before "fixing" it silently: the fix may
belong to another wave's file. Keep the table data-driven — a reviewer must be able to add a kind by
adding one tuple. Do not assert on 403 vs 404 for the *foreign* case; 404 is the contract everywhere
(`apikeys.KeyCtx.project`, `routers/*`), and 403 is only for a missing scope.
