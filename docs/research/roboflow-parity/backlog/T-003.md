## User story
As the reviewer of any area-3 PR, I want the editor's shipped data contracts pinned — a saved box keeps
its class and source, a smart click keeps its negatives, review lands AI work in the Review column, and
the objects list keeps hide/lock/order — so an assist or review card cannot silently rewrite them.

## UX flow (LabelDesk words)
1. **Editor** — a card on the board or a grid tile opens `/:ws/:project/images/:imageId`; the header
   carries previous/next and approve/submit, the rail carries box/polygon/smart-polygon/keypoints, and
   the drawer lists objects, tags and history.
2. **Box** — drag → the class picker opens; type to filter, Enter commits; Esc cancels a just-drawn box.
3. **Smart polygon** — click outside the object to grow, click a wrongly-included area to shrink, then
   accept; the polygon is committed as one annotation.
4. **Keypoints** — a saved skeleton's points take visibility `visible / occluded / deleted`, and the
   values survive save and reload.
5. **Proposals** — AI shapes carry `source` + `confidence`; the drawer shows the source chip, so a
   proposal is visibly not a human label.
6. **Auto-label** — a preview runs on 3–5 samples and writes nothing; the batch job applies labels.
7. **Board** — a labeler submits their own work (`annotating → review`); only a reviewer approves
   (`review → done`) or rejects (`review → annotating`).
8. **Objects** — rows paint front-most first; each row hides, locks and deletes, and the order actions
   move the selection through the stack.
9. **Shortcuts** — `v b p s k` and the fixed `← → Enter Esc Ctrl+Z` set stay bound; remapping keeps the
   documented clash rules.

## Notes for the implementer
Do not assert a labeler's honeypot counts anywhere in this file: the API deliberately blanks them
(`app/routers/images.py:205-210,280-290`), and `test_labeling_qa.py` owns that rule.
The smart-polygon assertion must monkeypatch the service function, not run SAM (`LD_SAM_ENABLED=0` in
`conftest.py:30`). The `source` default for a human save is `"human"` (`images.py:502-504`); a proposal
is any other source with an optional `confidence` — that is the HAVE fact behind the dashed/solid
distinction, which lives in the canvas and is not unit-testable here.
Migration-sensitive HAVE facts: annotation `source` defaults to `human` and is trimmed to 64 chars;
keypoint visibility is only `0|1|2`; class names pass `clean_class_name` and a duplicate is 409; the
review gate is `labeler && annotating → review` (`images.py:394-396`); `ObjectList` order is paint
order, front-most first (`editor-g5.test.mjs` pins the pure rule).
