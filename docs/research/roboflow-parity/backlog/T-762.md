## User story
As the champion running a pilot in a factory, I want a sandbox copy of the workspace that cannot alert a LINE group or attach to a running camera, so that a trial can be demonstrated without touching the line.

## UX flow (LabelDesk words)
1. **Settings → Workspace → `Environments`** (`/:ws/settings/workspace`) — one `Card` reads "This workspace is production." with `Create sandbox` under it, and the line "A sandbox has its own projects, models and test keys; nothing it does can reach production." [loading: the card renders a skeleton row] [error: "Couldn't read this workspace's environment." + `Try again`]
2. **`Create sandbox` in this deployment** — the button answers with the copy "Sandbox environments are not available in this deployment." and the action stays visibly disabled; no half-created workspace appears.
3. **Inside a sandbox** — a sticky strip under the top bar reads "Sandbox — alerts suppressed, no billing" with the workspace name, on every page of that workspace. [loading: the strip renders as a solid bar with no text until the environment answers, never a flash of "production"]
4. **The workspace switcher** — a sandbox workspace is listed with the chip "Sandbox" beside its name; production keeps the existing chip-free row.
5. **Flag off** — no Environments card, no strip, no chip, and every route answers 404.

## Backend changes
- Models/schema: `workspaces` gains `environment VARCHAR(16) DEFAULT 'production'` and `sandbox_of VARCHAR(32) DEFAULT ''` in `app/schema/identity.py` (`WORKSPACES`); existing rows default to production, no backfill.
- Routers: `app/routers/environments.py` (new) — `GET /api/ws/{ws}/environment` returns `{environment, sandbox_of, available, reason}`; `POST /api/ws/{ws}/environment/sandbox` returns 201 with the new slug through the mock driver, or 409 with `{"code": "not_available"}` and the copy above.
- Services/jobs: `app/services/environments.py` (new) — `EnvironmentDriver` protocol (`create_sandbox(c, name) -> str`, `promote_preview(c, project) -> dict`, `promote_apply(c, plan, approver_id) -> dict`), `MockEnvironmentDriver` (copies project shells only, no image bytes), `UnavailableEnvironmentDriver` (raises 409), `driver_for(settings) -> EnvironmentDriver`, `is_sandbox(ws) -> bool`, `environment_of(db, workspace_id) -> str`. No vendor SDK and no import of one.
- Permissions + workspace isolation: `workspace.update` for `POST`; `GET` needs `workspace.read`; the driver only receives the context of the calling workspace, so a sandbox under another workspace is never addressed by id from the client.
- Secrets/safefetch: none — no credential leaves the process; the mock driver writes only rows in the caller's workspace.
- OpenAPI: yes.

## Tests to write first
pytest — `apps/backend/tests/test_environments.py`:
- `test_a_workspace_defaults_to_production` — a fresh workspace → `GET /environment` is `{"environment": "production", "sandbox_of": ""}`.
- `test_creating_a_sandbox_uses_the_mock_driver` — with `LD_ENV_DRIVER=mock` → `POST …/environment/sandbox` returns 201, the new workspace slug ends `-sandbox`, its `sandbox_of` names the caller and its `environment` is `"sandbox"`.
- `test_the_default_driver_refuses_with_copy` — with the default driver → `POST` returns 409, `code == "not_available"`, and no new workspace row exists.
- `test_a_labeler_cannot_create_a_sandbox` — labeler login → `POST` → 403.
- `test_a_sandbox_of_another_workspace_is_not_reachable` — workspace A's `GET /environment` never reports workspace B's sandbox (`sandbox_of` is empty).
- `test_flag_off_hides_both_routes` — with `task_environments` off → `GET` and `POST` both 404.

node — `apps/frontend/tests/environment-mode.test.mjs`:
- `test_production_has_no_strip` — `isSandbox('production')` is false and `stripText('production', 'ACME')` is `''`.
- `test_sandbox_strip_names_the_mode_and_the_two_suppressions` — `stripText('sandbox', 'ACME')` contains "Sandbox", "alerts suppressed" and "no billing".
- `test_unavailable_copy_is_one_sentence` — `unavailableCopy('not_available')` is "Sandbox environments are not available in this deployment." and every driver state returns a non-empty sentence, never `undefined`.

## Acceptance criteria
- [ ] A workspace reads its environment, and a sandbox created through the mock driver is stamped `sandbox` with `sandbox_of` set.
- [ ] With no driver configured, `Create sandbox` refuses with the deployment sentence and creates nothing.
- [ ] A sandbox page always carries the strip; production never does.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no card, no strip, no chip, both routes 404, and every existing workspace still behaves as production.

## Notes for the implementer
Interface-first by owner rule: the driver protocol is the deliverable, the mock is what the suite exercises, and the default driver answers "not available in this deployment" rather than pretending. Do not import boto3, an Azure or a GCS client here — `services/connectors.py` already proves how to keep those optional, and production sandboxing (a second cluster) is not this card.
