## User story
As a labeler, I want the model I picked and the class mapping I approved to keep running on every image I open, so that I set the assist once per batch.

## UX flow (LabelDesk words)
1. **Editor → `Label assist`, in the Labels panel** (the top-bar assist button at `Editor.tsx:844-848` moves here in the v3e layout, REDESIGN §13.3; the canvas tool column carries `auto-label` for the batch sheet) — the first image the user enables assist on goes through the picker (T-140). Saving the picker writes a session for this user in this project.
2. **Every later image** — opening an image fires one assist call that uses the stored session, so boxes are already there when the canvas paints. [loading: a small "Assisting…" chip top-left; the canvas is usable while it runs] [error: the model is unavailable → the chip becomes "Assist unavailable — open the picker" and no request is retried in a loop]
3. **Change or stop** — the picker's **Stop assist** deletes the session; changing the model or mapping replaces it. The choice is per user: a teammate's session is untouched.
4. **Credit guard** — each assisted image is one metered AI call; at the allowance the call returns 402 and the chip reads "AI calls used up on this plan" with a link to Usage, once per image, not per retry.
5. **Failure isolation** — a failed assist never blocks drawing, never marks the image dirty and never writes an annotation: predictions are returned to the client and become proposals (T-151) that the user accepts.

## Backend changes
- Models/schema: new table `assist_sessions` (`models/assist.py`, new) — `id`, `workspace_id`, `project_id`, `user_id` (unique together with project), `model_ref`, `class_map` (JSON: model class name → project class id), `class_names` (JSON), `output` (`polygon | mask | box`), `confidence`, `created`, `updated`; registered in `models/__init__.py` (`DOMAIN_MODULES`) and created by the model registry — no column block needed for a new table.
- Routers: `GET /api/ws/{ws}/projects/{project}/assist-session` → the caller's session or `null`; `PUT` (body `{model_ref, class_map, class_names, output, confidence}`) validates every mapped class id against the project and the model ref against `resolve(ref, db, workspace_id=…)`; `DELETE` clears it. `POST /api/images/{image_id}/label-assist` gains `use_session: bool = false` and accepts a `model_ref` (not only `model_id`), returning `{annotations, session}`.
- Services/jobs: `services/assist_session.py` (new) — `get`, `put`, `clear`, `resolve_for_image(session, project_classes) -> (ref, by_name, output)`; the existing `label_assist` route gains `metering.check(db, ws, "ai_calls", 1)` before the call and `metering.record(..., kind="label_assist")` after, with `402` surfaced as today's `HTTPException`.
- Permissions + workspace isolation: `project.infer` via `c.can` (as the editor's model query already requires); the session row is scoped by workspace, project and user, so another user's or workspace's session is simply absent (GET returns null, PUT cannot write across scope); a foreign project slug is 404.
- Secrets/safefetch: none — model refs are resolved through `adapters/catalog.resolve`, which never accepts a path.
- OpenAPI: yes — three routes and one body.

## Acceptance criteria
- [ ] Enabling assist stores a session for that user and project, and every later image in the same project is assisted without opening the picker.
- [ ] A teammate's session is unaffected; changing the model or mapping replaces only the caller's session.
- [ ] Each assisted image costs one metered AI call, and at the allowance the call returns 402 with a per-image message rather than a retry loop.
- [ ] Assist predictions never become saved annotations without the proposal accept step.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no session is read or written; the previous one-click assist behaves exactly as today.
- [ ] Keyboard-only path: open image → Tab to the assist button → Enter (picker from T-140) → `→` shows boxes.

## Notes for the implementer
One row per (project, user) with a unique constraint — a session is a preference, not a log. Do not auto-run assist when the project has no classes or the image already has annotations from a human: the first wastes a call, the second hides work.
