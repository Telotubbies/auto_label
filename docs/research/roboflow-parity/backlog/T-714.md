## User story
As a site supervisor who lives in LINE, I want the alert to carry the snapshot and an acknowledge button, and the next person paged only if nobody taps it, so that an ignored alert and a handled one stop looking identical in the log.

## UX flow (LabelDesk words)
1. **The message** — one LINE Flex bubble: title, zone, time, the snapshot, and a quick reply `รับทราบ` whose postback carries the delivery id and its signature. [empty: an event with no snapshot says `ไม่มีภาพ — กล้องบันทึกไม่ทัน` inside the bubble instead of a broken image]
2. **A tap** — LINE posts to `/api/line/postback`; a valid signature writes `รับทราบแล้วโดย {name} เมื่อ {time}` against that delivery and stops the ladder. [error: `ลายเซ็นไม่ถูกต้อง` is a 401, an audit row and no state change — never swallowed]
3. **No tap** — after the channel's `wait_s`, tier two is sent to the second channel and the delivery records `tier: 2` and a new `next_tier_at`. [error: `ไม่ได้ตั้งช่องทางขั้นที่ 2` is logged once and the incident stays open]
4. **A channel with no secret** — a `channel_secret` is required to verify a postback, so an escalation policy is refused with `ต้องมี channel secret ของ LINE ก่อนตั้งนโยบายยกระดับ`; delivery stays one-way and says so in Settings. [error: that sentence]
5. **Downgrade is safe** — if verification or the ladder fails, the incident remains unacknowledged and keeps escalating; it is never closed by a failure.

## Backend changes
- Models/schema: `app/models/alerts.py` — `AlertDelivery` gains `tier INTEGER DEFAULT 0`, `event_id VARCHAR(32) DEFAULT ''`, `next_tier_at FLOAT`, `acked_at FLOAT`; new `AlertAck(id, delivery_id, workspace_id, channel_id, line_user_id, tier, created)` with `UniqueConstraint(delivery_id, tier)`. One `ALERT_DELIVERIES` block at the end of `app/schema/streams.py` plus one `("alert_deliveries", streams.ALERT_DELIVERIES)` line in `app/schema/__init__.py` (there is no alerts module in `STEPS` today); `alert_acks` is a new table, so `create_all` makes it.
- Routers: `app/routers/line.py` (new) — `POST /api/line/postback`, no session; resolves the channel from the body's `destination`, checks `flags.is_enabled("task_alert_ladder", db, channel.workspace_id)` (404 when off), verifies `X-Line-Signature` with the channel secret, and returns 200 `{}` to LINE on success. 401 for a bad signature, 404 for an unknown destination, 409 for an ack of a delivery that is already acked at that tier.
- Services/jobs: `app/services/alerts.py` — `_line_flex(event, snapshot_url, delivery_id, sig)`; `_send_line` sends `{"type": "flex"}` with the quick reply; `sign_ack(delivery_id, secret)` and `verify_postback(body, signature, secret)` (HMAC-SHA256, base64, `hmac.compare_digest`); `ack(db, delivery, line_user_id, user_id)`; `escalate_due(db, at)` sending tier 2 and 3 at most; `validate_settings` accepts `escalation: {tiers: [{wait_s, channel_id}]}` (≤ 3 tiers, `wait_s` 60–3600, channel must be in the workspace) and refuses it without a stored `channel_secret`. `app/worker.py` gains `_escalate_alerts()` beside `_schedule_ops`, self-throttled to every 30 s.
- Permissions + workspace isolation: the postback has no user, so the channel row is the tenancy boundary — a delivery id belonging to another channel is 404 and writes nothing; the policy editor stays `c.need("admin")` on the existing channel routes.
- Secrets/safefetch: `services/secretbox.py` — `SECRET_FIELDS["line"]` grows `channel_secret`, encrypted like the token and masked on read; `services/safefetch.py` — the reply/push call still goes through `safefetch.post`, and no other URL is fetched. Nothing about the postback is fetched.
- OpenAPI: yes — one new route and the `event_id`/`tier` fields on the delivery schema.

## Acceptance criteria
- [ ] A LINE alert carries the snapshot and an acknowledge quick reply whose postback is signed per delivery.
- [ ] A valid tap writes who acknowledged and when and stops the ladder; an invalid one is a 401, an audit row and no state change.
- [ ] Tier two fires only after the configured wait and only when nobody acknowledged, and an incident is never closed by a failure.
- [ ] Empty, loading and error states above all render — an event with no snapshot says so inside the bubble, and a policy without a secret is refused with a sentence.
- [ ] Workspace A cannot acknowledge or read workspace B's delivery (404, not 403).
- [ ] Flag off ⇒ no postback route, text messages as today, no tier ever sent.

## Notes for the implementer
R7: this is the only unauthenticated route in the product, so it does exactly three things — verify HMAC-SHA256 over the raw body with the channel's own secret, resolve one delivery from that channel, and write one ack. Verify against the **raw bytes** (`await request.body()`), never a re-serialised dict; use `hmac.compare_digest`; never log the body. Stored and how long: the ack row (delivery id, LINE user id, tier, timestamp) lives with the delivery for 365 days and is swept with it; the delivery row keeps the event summary it already keeps. A missing secret, a failed verification or an unreachable tier-two channel all degrade to "still unacknowledged and still escalating" — the ladder may over-page, it may never under-page. Caps: 3 tiers, wait 60–3600 s.
