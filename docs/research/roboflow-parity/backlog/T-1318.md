## Problem
No number exists for any route, page, bundle or job, so "slow" is an opinion and no card can be accepted
or rejected on evidence. Every later card in this area needs one source of truth.

## Design
`docs/ops/perf/budgets.json` (new) holds every threshold; `docs/ops/PERF-BUDGETS.md` (new, ~70 lines)
explains how each number is measured and why it sits where it does. Schema:

```json
{"schema": 1,
 "api": {"auth_write": {"p95_ms": 500, "p99_ms": 900, "example": "POST /api/auth/login"}, …},
 "pages": {"dataset": {"lcp_ms": 2500, "inp_ms": 250, "cls": 0.10, "route": "/:ws/p/:slug/dataset"}, …},
 "bundle": {"entry_kb": 400, "route_kb": 300, "chunk_kb": 500, "cold_route_kb": 900},
 "jobs": {"claim_p95_s": 3, "version_10k_s": 120, "export_1k_s": 30, "drain_100_s": 600},
 "db": {"queries_list": 25, "queries_editor": 60, "queries_any": 200, "slow_ms": 200},
 "regression": {"pct": 10, "shared_runner_pct": 25}}
```

- Every class in the performance plan §4.1 is present, with a human `example` so a reader knows which
  route the number belongs to.
- Values are the plan's **ceilings**, marked `"kind": "ceiling"`; T-1320 adds a measured `baseline.json`
  next to them and the owner decides the ratchet (Q2).
- One validator (`tools/tests/test_perf_budgets.py`) so a typo fails CI rather than silently disabling a
  comparison.

## Files
Exclusive:
- `docs/ops/perf/budgets.json` (new)
- `docs/ops/PERF-BUDGETS.md` (new)
- `tools/tests/test_perf_budgets.py` (new)
Shared: none.

## Tests to write first
`tools/tests/test_perf_budgets.py`:
- `test_schema_version_is_1_and_every_section_exists`.
- `test_every_api_class_has_p95_p99_and_an_example_route`.
- `test_p99_is_greater_than_p95_everywhere`.
- `test_every_page_has_lcp_inp_cls_and_a_route`.
- `test_bundle_floors_are_below_ceilings` — route ≤ cold route, entry ≤ cold route.
- `test_db_query_budgets_are_ordered` — list ≤ editor ≤ any.
- `test_regression_pct_is_10_and_shared_is_higher` — the documented pair.
- `test_no_class_is_missing_from_the_plan` — the doc's table headings and the JSON keys match (regex).

## Acceptance criteria
- [ ] Every class in the plan §4.1 appears in the JSON with a route example.
- [ ] Each value is described in the markdown with how it is measured (tool, warm/cold, p75/p95).
- [ ] The validator fails on a missing class, an inverted percentile or a zero value.
- [ ] No script hard-codes a threshold: `tools/perf/` and the frontend check read this file.
- [ ] The file states the machine assumptions (single API process, 20 users, SQLite/Postgres note).

## Notes for the implementer
Numbers here are ceilings, not measurements — say so at the top of both files so nobody quotes a
ceiling as a result. Do not invent a per-route budget for all ~330 routes: the fourteen classes are the
contract, everything else inherits its class. Keep the JSON flat enough that a diff is readable.
