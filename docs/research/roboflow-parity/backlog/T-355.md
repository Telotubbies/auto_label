## User story
As an operator, I want to start a batch job, watch it advance and download its result, so that "run this over last month's footage" is a form and a progress bar rather than a terminal.

## UX flow (LabelDesk words)
1. **Deployments → Batch** (a tab on the deployments page) — a job list: name, source (`Batch · Gate 3`, `Video · gate3.mp4`, `Prefix · line-a/`, `Selection · 214 picked`), output, progress, status chip, age. `[empty: no jobs → "No batch jobs yet. Run a model or a workflow over stored images." with a New batch job button]` `[loading: four skeleton rows]` `[error: "Batch jobs could not load." with "Try again"]`
2. **New batch job dialog** — workflow *or* model (one radio), source (a batch select, a video select, a prefix field, or "the current selection" when opened from the dataset), output, name. The dialog lists the refusal reasons from the server before Run is pressed: too many images, an unsupported output, a workflow with the wrong input shape.
3. **A running job** — progress with `n of m`, an ETA from the observed rate, Cancel, and a link to the source (`Open in Dataset` for a selection or a batch, `Open the video` for frames). Cancelling asks once: "Stop after the current image?"
4. **A finished job** — `Download` for CSV/COCO/JSONL, `Open the batch` for a dataset output, and the numbers: "412 images · 1,904 predictions · 3 failed". `[error: a job that failed]` shows the reason and, for a partial artefact, still offers the download with "partial — 214 of 412".
5. **A blocked plan** — when the allowance is exhausted the dialog says "The plan's AI-call allowance is used up." and Run is disabled, rather than failing after the first image.

## Tests to write first
pytest — `none: no backend surface`.
node — `apps/frontend/tests/batch-view.test.mjs`:
- `test_four_source_kinds_are_offered` — `SOURCES` ids are batch, video, connector, selection, and each has a label.
- `test_the_refusal_prefers_the_cheapest_fix_first` — with an unsupported output and too many images, `refusal` returns the output reason first (it is a one-click fix).
- `test_the_eta_is_linear_on_observed_rate` — 10 of 100 after 5 s reads about 45 s remaining.
- `test_a_partial_artefact_is_labelled_partial` — `partialLabel({images: 412, processed: 214})` contains "partial" and both numbers.
- `test_the_summary_names_failures` — `summary({images: 412, predictions: 1904, failed: 3})` includes "3 failed" and drops a zero clause.

## Acceptance criteria
- [ ] The job list shows source, output, progress and status, and a finished job offers its artefact.
- [ ] The dialog refuses an unsupported combination before Run, with the one-click fix named first.
- [ ] A cancelled or failed job keeps its partial artefact downloadable and says it is partial.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: with `task_36` off the tab is absent.

## Notes for the implementer
One tab, not a page: the Deployments screen already answers "what is running"; a batch job is another row on it. The ETA is an estimate from the observed rate and must disappear when the rate is zero rather than showing "∞".
