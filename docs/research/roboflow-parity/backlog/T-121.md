## User story
As a labeler, I want the editor to finish its save before it lets me leave, and to tell me when someone else saved this image while I was drawing, so that a dropped autosave never silently discards work.

## UX flow (LabelDesk words)
1. **Editor header save state** — one honest indicator instead of the current two words: "Saving…" (spinner) → "Saved" (check) → "Unsaved changes" → "Save failed — retry" (button). [error: save fails three times → the bar turns destructive and stays until a retry succeeds]
2. **Leaving** — `→`/`←`, the back arrow, the thumbnail strip and `Esc` all call one `flushAndGo(target)`: a dirty image is saved first, then the navigation happens. If the save fails, navigation is cancelled and the bar explains why. [empty: nothing dirty → navigate immediately]
3. **Reload / tab close** — `beforeunload` warns only when the last flush failed (the browser's own text; LabelDesk does not fake it).
4. **Second editor on the same image** — a save whose `base_updated` no longer matches the row returns 409. The editor freezes local edits, shows a non-dismissable bar: "This image changed in another tab or by a teammate." with **Reload theirs** and **Keep mine (overwrite)**. Choosing either resolves the state before more drawing is allowed. [loading: reload fetches the image payload] [error: reload fails → the bar stays with its retry]
5. **Board** — nothing changes; the card counts move only after a committed save.

## Backend changes

- Routers: `PUT /api/images/{image_id}/annotations` (`images.py:534`) request gains `base_updated: float | None = None`; when present and `abs(img.updated - base_updated) > 1e-6`, respond `409 {"detail": "image changed since it was loaded", "updated": <row>}` and write nothing. ## Acceptance criteria
- [ ] A dirty image is saved before any arrow, back, thumbnail or `Esc` navigation; a failed save cancels the navigation and keeps the user on the image.
- [ ] The save state reads exactly one of Saving / Saved / Unsaved changes / Save failed at any moment, and never says "Saved" while a request is in flight.
- [ ] A second save built on a stale `updated` returns 409, keeps the stored set intact, and the editor offers Reload / Keep mine.
- [ ] `Keep mine` writes once over the newer row and the conflict bar clears; `Reload theirs` discards local edits only after the click.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: the guard is always on; there is no flag-off state to render.
- [ ] Keyboard-only path: draw → `→` (flush) → back arrow via Tab+Enter (flush) → reload warning only after a failed flush.

## Notes for the implementer
`base_updated` is the `updated` value the client received with the image payload, echoed back unchanged. The 409 body carries the current `updated` so the client can resolve without a second round trip. Do not compare timestamps on the client to decide a conflict: the server decides, the client only renders it.
