## User story
As a developer of an external tool, I want users to sign in with LabelDesk and grant a narrow scope, so that
integrations stop asking for a long-lived workspace key.

## UX flow (LabelDesk words)
1. An app sends the user to `GET /api/oauth/authorize?client_id&redirect_uri&response_type=code&scope&state&code_challenge&code_challenge_method=S256`.
2. Signed out → the existing sign-in screen with a `return_to`; signed in → the consent screen (T-429) whose approval
   posts back here. A denied consent redirects to `redirect_uri?error=access_denied&state=…`.
3. A valid request answers `302` to `redirect_uri?code=<one-time>&state=…`; the code lives 60 seconds and is single-use.
4. `400` with a plain `error` code for `unsupported_response_type`, `invalid_scope`, `invalid_client`,
   `invalid_redirect_uri`; the redirect is only followed when the client and URI are already registered.
5. `[error]` an unregistered client never redirects — it renders `This application is not registered.` on the
   authorize page, so a lookalike cannot use the redirect to phish.

## Backend changes
- Models/schema: new `app/models/oauth.py` (new) — `OAuthClient(id, workspace_id FK nullable (null = platform-wide app),
  name VARCHAR(120), client_id VARCHAR(64) unique, client_secret_hash VARCHAR(64), redirect_uris JSON,
  scopes JSON, created_by, created, revoked_at FLOAT null)`;
  `OAuthCode(code_hash PK, client_id, workspace_id, user_id, scope JSON, challenge VARCHAR(128), expires FLOAT,
  used BOOLEAN)`. Register in `models/__init__.py`.
- Routers: `app/routers/oauth.py` (new) — `router = APIRouter(prefix="/api/oauth", tags=["oauth"])` with
  `GET /authorize` and, for a workspace admin, `POST/GET/PATCH/DELETE /api/ws/{ws}/oauth-clients` (create returns the
  client secret once; rotate returns a new one).
- Services/jobs: `app/services/oauth.py` (new) — `SCOPES = ("read", "upload", "infer", "train", "streams:read")`
  (the last is read-only video access), `validate_client(client_id, redirect_uri)`, `validate_scope(scope)`,
  `issue_code(client, user, ws, scope, challenge) -> str` (stores the sha256 of the code), `consume_code(code) -> row`,
  `pkce_ok(verifier, challenge)`, `client_secret_hash(secret)`.
- Permissions + workspace isolation: an authorize request resolves the workspace from the client's registration; a
  platform-wide client names the workspace in a signed `state` only after consent, never from the query string.
- Secrets/safefetch: client secrets are stored as sha256 hashes (never encrypted, never returned but once); redirect
  URIs are compared exactly after registration, so no server-side fetch happens.
- OpenAPI: yes.

## Acceptance criteria
- [ ] A registered client can obtain a one-time, 60-second authorization code bound to a member and a scope set.
- [ ] An unregistered client or redirect URI never redirects; the failure is shown on our own page.
- [ ] Scopes are a closed list and a client secret is shown once, stored hashed.
- [ ] Empty, loading and error states above all render (no clients, denied consent, invalid request).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no OAuth routes and no way to register an app.

## Notes for the implementer
PKCE is mandatory for public clients and the code is one-time: both are what stop a leaked redirect from becoming a
token. Keep the scope list to five entries; `admin` is not a scope.
