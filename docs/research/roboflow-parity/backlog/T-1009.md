## User story
As a workspace admin, I want to follow an install job's phase and log, cancel it if it is wrong, and
uninstall an engine afterwards, so that a failed install is diagnosable instead of a support ticket.

## UX flow (LabelDesk words)
1. **Job cards** — above the engines table, one card per active engine job: host, phase
   (`Installing vLLM`), percent, the last 5 log lines in a monospace block, `View log`, `Cancel`.
   [empty: "No engine job is running." one line] [loading: one skeleton card] [error: "This job did not
   load." + Retry].
2. **Log sheet** — full-height sheet with the last 200 lines, timestamps off by default, `Copy log`,
   and a footer that names the job id. [empty: a job that produced no output yet says "Waiting for the
   worker…"].
3. **Cancel** — confirm "Stop this install on <host>? The half-built environment is removed."; the card
   reads `Cancelling…` until the worker acknowledges, then `Cancelled`.
4. **Failed** — card shows `Install failed` with the safe reason and `Copy log`; the failing engine is
   named; earlier successes are listed in the sheet.
5. **Done** — card auto-dismisses after 5 s; the engines table refetches and the row reads `Installed
   <version>`, with `Uninstall` in its row menu.
6. **Uninstall runs** — the same card shape with phase `Removing vLLM`; on done the row returns to
   `Not installed`.
7. **Refresh** — a reload re-reads active jobs and renders the same cards (no toast-only state).

## Backend changes
- Models/schema: none.
- Routers (`apps/backend/app/routers/inference.py`):
  - `GET /jobs/{id}` → the job with `kind, status, progress, phase, log, error, result.engines, created,
    finished`; scoped to the workspace, 404 for a foreign id.
  - `GET /jobs?status=active` → the workspace's `engine_apply`/`model_pull` jobs in `queued|running|
    cancelling`, newest first, capped at 20.
  - `POST /jobs/{id}/cancel` → sets `cancelling` (no-op when already terminal); 404 foreign; admin only.
- Services/jobs: none new; reuse the `Job` row and `result.log/phase` from T-1008. A small
  `job_view(row)` shaper drops `params` (it holds argv).
- Permissions + workspace isolation: admin only; `Job.workspace_id == c.ws.id`; a foreign job id is 404.
- Secrets/safefetch: none; the shaper never returns `params`, and the log is already redacted at write.
- OpenAPI: yes.

## Acceptance criteria
- [ ] Active jobs render with phase, percent, last lines, `View log` and `Cancel`.
- [ ] Cancel requires a confirm, shows `Cancelling…`, and settles on the worker's acknowledgement.
- [ ] Failure names the failing engine, keeps the log, and offers copy.
- [ ] On done the engines table refetches and the row reads `Installed`; uninstall returns it to
      `Not installed`.
- [ ] A reload restores active job cards; no state lives only in a toast.
- [ ] `params` (argv) is never returned to the browser; a foreign job is 404.
- [ ] Empty/loading/error states render; 375 px keeps the log readable and the sheet full-height.

## Notes for the implementer
Poll only while at least one job is active; a 2 s poll on an idle tab is a battery and log problem.
Do not stream over SSE — the existing job endpoint is the pattern and proxies break long streams.
