## Finding (FAIL)
`apps/backend/app/routers/auth.py::requested_plan` returns any tier in `PLANS`. With `task_a1_plan_choice` on, a signup that sends `plan: "pro"` creates a workspace on Pro with no payment.

Billing (wave D) is still a mock with its flag off, waiting on the owner (INDEX §4.1/§4.3), and the owner has not set prices.

## Fix (smallest)
- A new workspace always starts on `free`, or on the trial tier if `config.PLANS` defines one.
- A paid choice is stored only as the requested plan, as one field or the existing `Workspace.settings` key that the code already reads. No new table.
- The `PlanPicker` copy says that paid plans start from Settings → Plan once billing is available. It must state no prices.
- Settings → Plan shows the requested plan but does not apply it.

## Tests first
- Signup with `plan: "pro"` and the flag on: the workspace plan is `free` (or trial), and the requested plan is recorded.
- An unknown plan returns 422. The flag off still means `free`.
- No code path grants a paid tier without the billing provider; the test greps the router.
- The T-011 tests and the J1 journey stay green.
