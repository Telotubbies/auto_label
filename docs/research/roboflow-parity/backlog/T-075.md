## User story
As an MLOps engineer, I want one call that creates the project if needed, uploads a directory or a zip with
bounded concurrency, retries transient failures and can return a task id instead of waiting, so that a CI
job is one command with machine-readable output.

## UX flow (LabelDesk words)
1. **Terminal** — `labeldesk upload ./ppe-data -p ppe-v2 --create-project --workers 8` prints
   `{"status":"done","uploaded":1840,"duplicates":12,"failed":0,"project":"ppe-v2"}` with `--json`.
   [empty: a directory with no images → `{"status":"done","uploaded":0}` and exit 0]
   [error: 402 plan limit → `error: image limit reached on the Free plan`, exit code 1]
2. **Terminal** — `--no-wait --zip-upload` prints `{"taskId":"…","uploadUrl":"…"}` and exits 0; the caller
   polls `labeldesk task <id>` (or its own HTTP client). [error: a server without the session route →
   one line "server does not support deferred upload; uploading inline" and the inline path runs]
3. **Terminal** — a transient 502 on one file is retried with backoff; after `--retries 3` it is counted in
   `failed` with its reason, and the rest of the batch still lands. [loading: a progress line every 25
   files when stdout is a TTY]
4. **Terminal** — `labeldesk upload photo.jpg -p demo --is-prediction` sends the image to review instead of
   the dataset, so model output never lands as ground truth.

## Backend changes
- Models/schema: none.
- Routers: none new.
- Services/jobs: SDK/CLI only.
  - `packages/sdk/labeldesk/client.py`:
    - `upload(project, paths, batch_name, split, tags, num_workers=10, num_retries=0,
      is_prediction=False)` — expands a directory (`glob` over `imaging`-equivalent extensions), chunks at
      2,000 files (the server cap), `ThreadPoolExecutor(max_workers=min(num_workers, 25))`, retries
      `httpx.TransportError`/5xx with `0.5 * 2**n` backoff, aggregates `{uploaded, duplicates, annotated,
      failed}`; `is_prediction=True` sends `to_dataset=false`.
    - `ensure_project(name, type="object-detection")` — `GET /projects`, create via
      `POST /workspaces/{ws}/projects` when absent, idempotent on slug.
    - `deferred_upload(project, archive_path, ...)` — `POST …/uploads/sessions`, `PUT` the bytes with the
      returned headers (no bearer token), returns `{taskId}`.
  - `packages/sdk/labeldesk/cli.py`: `upload` gains `--workers/-c` (default 10), `--retries/-r` (0),
    `--no-wait`, `--zip-upload`, `--is-prediction`, `--create-project`; path argument auto-detects file,
    directory or `.zip`; `task <id>` subcommand polls a task and prints its state.
- Permissions + workspace isolation: the API-key scopes do the work (`upload`, `read`); the SDK never
  takes a project id it did not receive from the API.
- Secrets/safefetch: none.
- OpenAPI: no (client only; the generated operation map must be regenerated by the existing `gen_sdk.py`
  run only if route names changed — none did here).

## Acceptance criteria
- [ ] A directory, a single file and a zip all upload from the same command; a 2,000+ file directory is
      chunked rather than refused.
- [ ] Concurrency is bounded at 25, retries use exponential backoff, and exhausted retries are reported
      per file without aborting the batch.
- [ ] `--create-project` creates the destination once; an existing slug is reused.
- [ ] `--no-wait` prints a task id and exits 0; a server without the session route falls back inline with
      one explanatory line.
- [ ] `--is-prediction` keeps the image out of the dataset; a video path is refused with the "extract
      frames first" line.
- [ ] Empty/loading/error states above render (progress line, error line, exit codes).
- [ ] Flag off ⇒ nothing changes: the SDK only talks to routes the workspace already has enabled.
- [ ] Workspace A cannot see or change workspace B's data: the key's project lookup 404s as today.

## Notes for the implementer
Do not add a `requests`/`tqdm` dependency: `httpx` and `concurrent.futures` are already there. `--no-wait`
is only meaningful with `--zip-upload` (a loose-file upload has no single task); refuse the combination
with one line rather than inventing a batch task id.
