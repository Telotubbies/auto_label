## User story
As a trainer, I want a brushed mask to reach the dataset and the export as a usable polygon, so that a pixel-painted label is not silently dropped the moment a version is built.

## UX flow (LabelDesk words)
1. **Dataset → Versions → New version** — an image with two mask annotations is included like any other approved image; the version's stats gain a line "2 masks vectorised" so nothing is silent.
2. **Version detail** — the class counts include the mask's class; the image is listed with its other labels.
3. **Export (COCO / YOLO seg)** — a mask becomes one polygon per connected component; the image's `mask` annotation still exists on the row unchanged, so a later re-export can be exact again.
4. **Augmented versions** — a geometric augmentation applies to the vectorised polygon, so a flipped version never carries an untransformed bitmask. [error: a mask with no component large enough for three points is dropped from the training item and counted as "1 mask skipped" — never written as an empty label]
5. **Flag off** — a version built with `task_mask` off still converts any stored mask; the flag gates the tool, not the data path.

## Acceptance criteria
- [ ] A mask annotation reaches a new version as a polygon and the version stats name the conversion.
- [ ] COCO and YOLO-segmentation exports carry the mask as geometry, and no export ever writes an empty label file.
- [ ] Geometric augmentation transforms the vectorised polygon, never an unrotated bitmap.
- [ ] The stored mask on the image row is unchanged by version creation, so a later re-export is exact.
- [ ] Empty, loading and error states above all render: a mask with no usable component is counted as skipped, not shown as a label.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the brush tool is absent; a stored mask still converts and exports.
- [ ] Keyboard-only path: not applicable; the flow is a version build and an export.

## Notes for the implementer
`segment.mask_to_polygon` picks the largest contour; reuse it for the single-component case and only walk `RETR_EXTERNAL` yourself when a mask has more than one blob. Holes are dropped — record that as `mask_holes_dropped` if a component's `RETR_CCOMP` child exists, so the loss is visible.
