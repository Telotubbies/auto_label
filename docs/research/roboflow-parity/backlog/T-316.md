## User story
As an integrator, I want to POST an image to a workflow's own URL and get its declared outputs back, so that a whole pipeline is callable without a client-side chain of model calls.

## UX flow (LabelDesk words)
1. **Workflows → Deploy** (T-319's panel) — the workflow's endpoint appears with the same wrapped URL treatment as T-313: `/api/v1/ws/{ws}/workflows/{workflowId}/invoke`. Copy, then paste. [empty: no published version → the URL is replaced by "Publish a version to get this endpoint." and no copy button] [loading: a first call to an idle model pays the load; the panel shows "Warming up…" from T-317's header] [error: a 422 lists the missing input keys by name]
2. **The call** — `POST` with `Authorization: Bearer $LABELDESK_API_KEY`, `Content-Type: application/json`, `{"inputs": {"image": {"type": "url", "value": "https://…"}, "confidence": 0.4}}`. A multipart `file` field is accepted for the `image` input instead of a URL.
3. **The answer** — the same envelope shape as model inference (`T-310`) plus the workflow's own outputs: `{runtime: "hosted", request_id, envelope: 1, outputs: {detections: [...], texts: [...], events: [...]}, time}`. The sink decides whether annotations were written; `annotations_added` appears only when that sink ran.

## Backend changes
- Models/schema: none — the invoked definition is the workflow's published blocks (T-328) or its current blocks while T-328 is off.
- Routers: `apps/backend/app/routers/workflow_api.py` (new) — `POST /api/v1/ws/{ws_slug}/workflows/{workflow_id}/invoke`, key auth via `key_ws(db, api_key, request, "infer")` (reuses `routers/training.py:560`), statuses 200 / 400 (bad body, unknown key in `inputs`) / 401 (bad key) / 404 (workflow not in the key's workspace, or not published) / 402 (AI-call quota) / 413 (>20 MB image) / 422 (missing required input) / 503 (model unavailable).
- Services/jobs: `apps/backend/app/services/workflow_invoke.py` (new) — `payload_for(contract, body, image_bytes) -> dict` mapping `inputs` onto the declared keys and rejecting unknown keys; `invoke(db, ws, wf, image, c) -> dict` calling `workflow_runner.run(...)` and wrapping the result with `runtimes.envelope`; the `annotations` sink requires an explicit `write_back: true` in the body and then checks `project.annotate` on the key's scopes before any call is spent.
- Permissions + workspace isolation: the key's scope must include `infer`; the workflow is looked up by `id` **and** `workspace_id` from the key, so another tenant's id reads as 404. Workspace members calling without a key get 401, never a session fallback.
- Secrets/safefetch: `image` URLs go through `services/safefetch.fetch` (blocked hosts raise 400), exactly like `routers/training.py:566`.
- OpenAPI: yes — new route with `openapi_extra={"x-scopes": ["infer"]}`.

## Tests to write first
pytest — `apps/backend/tests/test_workflow_invoke.py`:
- `test_invoke_returns_the_declared_outputs` — a model+sink workflow invoked with a small PNG returns `outputs.detections` and `envelope: 1`, and `request_id` is a 16-char id.
- `test_an_unknown_input_key_is_400` — `{"inputs": {"imageg": …}}` is refused by name, before any model call (assert zero `ai_calls` rows).
- `test_a_missing_required_input_is_422` — no `image` key lists `image` in the detail.
- `test_another_workspace_id_is_404` — the same key calling a foreign workflow id gets 404, not 403.
- `test_the_annotations_sink_needs_a_write_scope` — a key with `infer` and no `infer`-plus-annotate path returns 403 and writes nothing; `write_back: true` without `project.annotate` is 403.
- `test_flag_off_is_404` — with `task_316` off the route answers 404 and the workflow still runs from the editor.
- `test_an_image_url_goes_through_safefetch` — a loopback URL returns 400 and no request leaves the process.

## Acceptance criteria
- [ ] A published workflow answers on its own URL with the declared outputs and T-310's envelope fields.
- [ ] Unknown or missing inputs fail before a model call and name the key; a foreign workspace id is 404.
- [ ] `write_back: true` is refused for a key without dataset write access, and nothing is written.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — asserted by the foreign-id test.
- [ ] Flag off ⇒ the route is 404 and the editor is unchanged.

## Notes for the implementer
One endpoint serves every workflow; the payload shape comes from T-315's contract, never from a per-task route. The 20 MB cap is the same constant the self-hosted container uses (`apps/inference/main.py:36`), so a request that works against `localhost:8010` works here.
