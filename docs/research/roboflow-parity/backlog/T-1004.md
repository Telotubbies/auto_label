## User story
As a workspace admin, I want to enter a model, a precision, a context and a batch and get per-GPU
memory, a fits verdict and a tokens/s estimate with its assumptions, so that the buying and deployment
question is answered before anyone downloads 15 GB.

## UX flow (LabelDesk words)
The screen is T-1005; this card defines the answer it renders.
1. **Estimate** — request carries model geometry (params, active params, layers, KV heads, head dim),
   quantisation, context, batch, concurrent users, prompt/output tokens, GPU preset or custom, GPU
   count, tensor parallel, engine overhead, usable fraction.
2. **Result** — `{per_gpu: {weights_gb, kv_gb, activations_gb, overhead_gb, total_gb, usable_gb},
   total_gb, fits, verdict, throughput: {memory_bound_tps, compute_bound_tps, estimate_tps,
   low_tps, high_tps}, ttft_ms, assumptions: [...], sources: [...]}`.
3. **Invalid input** — 422 naming the field: "KV heads (4) must divide by tensor parallel (3).",
   "Context must be between 128 and 1,000,000.", "Concurrent users must be at least 1."
4. **No GPU preset** — `custom` carries VRAM, bandwidth and TFLOPS; a preset ignores those fields and
   uses the catalogue row.

## Backend changes
- Models/schema: none (nothing stored).
- Routers: `POST /api/ws/{ws}/inference/estimate` → the result above. Admin-only.
- Services/jobs: `apps/backend/app/services/inference_estimate.py` (new).
  - `EstimateIn` (pydantic): `model: {params_b, active_params_b?, layers, kv_heads, head_dim}`, `quant`
    (`fp32|bf16|fp16|fp8|int8|int4|gguf_q8|gguf_q4_k_m`), `context`, `batch`, `users`, `prompt_tokens`,
    `output_tokens`, `gpu: {preset} | {vram_gb, bw_gbs, fp16_tflops}`, `gpu_count`, `tensor_parallel`,
    `engine` (catalogue id → overhead), `usable` (0.5–1.0, default from the engine).
  - `estimate(body) -> dict` implementing PLAN §2.3 exactly: `W = P·b_w`; `kv_token = 2·L·H_kv·d·b_kv`;
    `KV = kv_token·s·B`; `A = max(0.05·W, 256 MiB)·(1 + 0.02·B)`; `O` from the engine row;
    `M = W/TP + KV/TP + A + O`; fit against `usable·V`; memory-bound `B·0.7·BW / W`;
    compute-bound `TP·F·0.25 / (2·P_a)`; estimate `0.8·min`, range `0.6…1.2`; TTFT per PLAN §2.3 item 9.
  - `bytes_per_weight(quant)` table: fp32 4, bf16/fp16 2, fp8/int8 1, int4 0.5, gguf_q8 1.0625,
    gguf_q4_k_m 0.6; `bytes_per_kv` = 2 unless `fp8`, then 1.
  - Validation: finite positive numbers, ranges (`params_b` 0.01–2,000; `layers` 1–200; `kv_heads`
    1–256; `head_dim` 8–512; `context` 128–1,000,000; `batch` 1–1,024; `users` 1–10,000;
    `gpu_count` 1–64; `tensor_parallel` 1 ≤ TP ≤ gpu_count and `kv_heads % TP == 0`;
    `usable` 0.5–1.0).
  - `assumptions` is a fixed list of strings naming every default and factor, and `sources` carries the
    three URLs from PLAN §2.3. No personalised advice, no "recommended".
- Permissions + workspace isolation: admin only; flag off 404. No ids are read, so there is nothing to
  leak across workspaces.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Tests to write first
pytest — `apps/backend/tests/test_inference_estimate.py`:
- `test_worked_example_matches_the_plan` — the PLAN §2.3 fixture (7.6B BF16, 28 layers, 4 KV heads,
  head dim 128, 8192 context, batch 4, RTX 4090, TP 1, vLLM) → weights ≈ 14.2 GiB, KV ≈ 1.75 GiB,
  total ≈ 18.7 GiB, fits, memory-bound ≈ 166 tok/s, estimate ≈ 133 tok/s (±1%).
- `test_tensor_parallel_divides_weights_and_kv` — the same at TP 2 → per-GPU weights and KV halve,
  activations and overhead do not, total drops.
- `test_kv_heads_must_divide_by_tensor_parallel` — 4 KV heads, TP 3 → 422 naming both numbers.
- `test_does_not_fit_names_the_deficit` — a 70B FP16 on a 24 GB card → `fits: false` and the verdict
  contains the shortfall.
- `test_quantisation_changes_the_weight_term` — int4 weights are 1/4 of bf16 for the same params.
- `test_context_and_batch_drive_the_kv_term` — doubling context doubles KV; doubling batch doubles KV.
- `test_bounds_are_422` — context 0, batch 0, usable 1.5, TP > GPU count.
- `test_assumptions_and_sources_are_always_returned` — non-empty, three source URLs, every assumption
  names its default.
- `test_member_is_403_and_flag_off_is_404`.

## Acceptance criteria
- [ ] The worked example in PLAN §2.3 reproduces within 1%.
- [ ] TP divides weights and KV only; activations and overhead stay per-GPU.
- [ ] Every result carries assumptions and the three sources; nothing is stored.
- [ ] KV heads not divisible by TP is a 422 that names both values.
- [ ] Quantisation and context/batch change the result in the direction the formulas say.
- [ ] Admin-only; flag off 404.

## Notes for the implementer
Do not add a `recommended` field or a "best GPU" list; the module answers a question, it does not sell.
Keep the arithmetic in one function with no I/O so the worked example can be a table-driven test.
`gguf_q4_k_m` is 4.8 bits per weight and `gguf_q8_0` is 8.5, converted to bytes here — put that
conversion in the quant table, not in prose.
