## User story
As a team lead about to start a run, I want the credits and minutes on the button and a one-click request to the person who owns the contract, so that the wall I hit has a door in it.

## UX flow (LabelDesk words)
1. **Train screen** (`/:ws/:project/train`) — above `Start training`, one line: "≈ 3 credits, 42 min" with "180 credits left in this project this month" beside it. [loading: the line reads "calculating…" and the button stays enabled, because the estimate is advisory] [error: "The estimate is unavailable — training still works." never blocks the click]
2. **Not enough budget** — the button is replaced by `[error: needs 3 credits, the project has 1 — raise this project's budget or wait for the next cycle]` and a `Request more` button that opens a one-field dialog (amount, note) and sends "Sent to your workspace admin — reference BR-<id>." [empty: the note is optional]
3. **Project Settings → `Budget` tab** (`/:ws/:project/settings?tab=budget`) — monthly credits, alert thresholds as three switches at 50/80/100, and a bar of used/remaining with the burn line "projected to exceed the budget on the 22nd". [empty: "No budget set — this project spends from the workspace plan."] [loading: skeleton rows] [error: "Couldn't load this project's budget." + `Try again`]
4. **Settings → Plan & Usage → `Budgets`** (`/:ws/settings/usage`) — one row per project: a `Progress` bar, used/credits, burn rate and the projected day. [empty: "No project has a budget yet."]
5. **Read-only for a labeler** — the tab shows the bar with "Only a project manager can change this."

## Backend changes
- Models/schema: none.
- Routers: `app/routers/budgets.py` — `POST …/budget/request` (201 with `{reference}`, 422 on a non-positive amount) appending one `audit` row with `action="budget.request"` and mailing the workspace owner through `app/mailer.send`.
- Services/jobs: `app/services/budget_request.py` (new) — `request_more(db, c, project, amount, note) -> str` (reference from `new_id()`, one audit row, one `mailer.send` to the workspace owner), `summary(db, ws)` returning the per-project bars for the Usage screen.
- Permissions + workspace isolation: `POST …/budget/request` needs `project.settings` (any manager); the recipient is resolved server-side from the workspace owner; a project slug from another workspace is 404.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] The Train button carries credits and minutes before the click, and an unavailable estimate never blocks training.
- [ ] An exhausted budget replaces the button with the sentence and a working `Request more` that mails the owner.
- [ ] The Budget tab saves a ceiling and thresholds, and the Usage tab lists one bar per budgeted project.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no tab, no estimate line, no budgets section, and the Train screen is exactly as today.

## Notes for the implementer
The estimate is advisory and must never disable the button: the API is the authority and already answers 402, so a failed estimate that blocks a run would be a new way to break training. Keep `Train.tsx:122`'s "Costs 3 credits." sentence as the fallback when the estimate request fails, rather than printing an error where a cost belongs.
