## User story
As a compliance lead, I want a stated list of what the log records and a test that proves each category writes, so
that "we log everything the auditor asked about" is evidence, not an assertion.

## UX flow (LabelDesk words)
1. The audit screen's catalogue filter is built from one registry, so every action the API can write is offered in
   the `Action` list and nothing else is. An action with no writer never appears.
2. Categories the registry names, grouped: **People** (invites, joins, role changes, default role, folder access),
   **Roles**, **Folders**, **Projects and data** (upload, approve, delete, split, version delete/restore, export),
   **Workflows** (create, publish, delete, restore), **Training** (start, stop, weights download), **Devices and
   streams** (create, start/stop, event to dataset, event deletion), **Keys** (create, update, protect, disable,
   roll, revoke, metadata), **Integrations** (webhook, connector, alert, OAuth app, SIEM), **Billing** (plan, cap,
   cancel, invoices).
3. `[empty]` an action that would fall outside the registry is a `500` in tests, not a silent log line: the writer
   test enumerates every literal action string in `app/`.
4. `[error]` the API's `/audit/catalogue` route returns `{groups: [{name, actions: [{action, label}]}]}`; the UI
   filter uses it, so an unknown action is never offered.

## Backend changes
- Models/schema: none.
- Routers: `GET /api/ws/{ws}/audit/catalogue` in `routers/audit.py` → the grouped registry (read with
  `workspace.audit`).
- Services/jobs: `app/services/audit_actions.py` (new) — `ACTIONS: dict[str, tuple[str, ...]]` (group → action names,
  the single source for the UI and the coverage test), `label(action) -> str`, `groups() -> list[dict]`.
  Plus the missing writers this area owns: `workflow.publish` / `workflow.delete` / `workflow.restore` (one line in
  `routers/workflows.py` per path), `export.dataset` (the export job in `handlers/versioning.py`), and
  `label.approve` alongside the existing `image.review` where a review decision changes status.
- Permissions + workspace isolation: `workspace.audit`; the catalogue is static, the writers use `c.ws.id`.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Frontend changes
- API client: `governanceApi.auditCatalogue(ws)` in `src/lib/api/governance.ts`.
- The `Action` list in `AuditFilters.tsx` (T-400) reads the catalogue instead of a hard-coded array.
- Feature flag: `task_audit_coverage`; off ⇒ the catalogue route 404s and the filter falls back to free text.

## Acceptance criteria
- [ ] One registry lists every action the API can write, grouped by the categories an auditor asks about.
- [ ] A coverage test fails when a writer emits an action the registry does not know.
- [ ] Workflow publish/delete, dataset export and label approval write audit rows.
- [ ] Empty, loading and error states above all render (empty group, unknown action refused by the test).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no catalogue route; existing writers unchanged.

## Notes for the implementer
The scan test is the point of the card: it reads every `audit(` call site and compares against `ACTIONS`. Keep the
groups to nine; a tenth group means a category an auditor will ask about and the UI has nowhere to put.
