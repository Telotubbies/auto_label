## User story
As a reviewer, I want to rename an ingest, merge two fragments and delete an empty upload, so that "the
April batch" means one card on the board instead of three look-alikes.

## UX flow (LabelDesk words)
1. **Annotate board** — each card's ⋮ menu: **Rename**, **Merge with…**, **Delete** (Delete only on
   Unassigned). [empty: a card with no images cannot exist; a column with no cards shows "Empty"]
2. **Rename** — inline dialog with the current name; Enter saves; the card and the batch filter update.
   [error: an empty name → "A batch needs a name", save disabled]
3. **Merge with…** — a list of other batches with image counts; picking ≥ 2 shows
   "The largest batch keeps its name and absorbs the rest: `2026-11-17 · shift` (412 images)."
   [loading: the counts resolve per ticked batch] [error: batches from different source videos →
   "These batches come from different videos and cannot merge"]
4. **Delete** — confirm names the count and the consequence:
   "Delete this batch and its 12 unassigned images? This cannot be undone." [error: a batch with annotating
   or review images → "Move these images to Unassigned first", nothing deleted]

## Backend changes
- Models/schema: none (`Batch.name`, `Image.batch_id` already exist).
- Routers: `apps/backend/app/routers/projects.py`
  - `PATCH /{project}/batches/{bid}` `{name}` → `{id, name}`; `404` for a foreign batch.
  - `POST /{project}/batches/merge` `{ids: list[str] (≥2)}` → `{batch, moved}`; the survivor is the batch
    with the most live images (tie: oldest `created`); `409` when the set mixes source videos (live images
    carry different non-null `video_id`) or includes a managed review queue (a batch whose images all sit
    in `review` and belong to a consensus job — leave that refusal to the existing review code).
  - `DELETE /{project}/batches/{bid}` → `{removed_images}`; `409` unless every image is `unassigned`;
    deletion reuses the bulk-delete body (bytes first, meter refund, `deleted_at`), never a new eraser.
- Services/jobs: none.
- Permissions + workspace isolation: `c.need("reviewer")` on all three; batch lookups filter
  `Batch.project_id == c.project.id`.
- Secrets/safefetch: none.
- OpenAPI: yes — three routes.

## Acceptance criteria
- [ ] Rename, merge and delete work from the board; merge names the survivor before it runs.
- [ ] Merge is refused across source videos or managed review queues, and the copy says why.
- [ ] Delete is refused unless every image is unassigned, and an allowed delete refunds storage.
- [ ] The batch filter and the card counts agree after every action.
- [ ] Empty, loading and error states above render.
- [ ] Flag off ⇒ no ⋮ menu and the routes 404.
- [ ] Workspace A cannot see or change workspace B's data (404 for a foreign batch id).

## Notes for the implementer
"Managed review queue" means a batch whose images belong to a consensus job; reuse
`labeling_ops.latest_assignment` or the existing review guard rather than inventing an ownership rule.
Merge must move images with one `UPDATE`, not per-row saves.
