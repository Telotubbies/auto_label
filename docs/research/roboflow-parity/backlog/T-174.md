## User story
As a labeler who works at two desks, I want my key map to follow my account, so that the muscle memory I built
on one machine is there on the other.

## UX flow (LabelDesk words)
1. **Editor · keyboard panel** — the remap table opens with the account's map (or the default when never
   changed) and a line "Saved to your account". [loading: the table renders defaults immediately and swaps in
   the saved map when it arrives; no flicker of the whole panel]
2. **Change a binding** — a clash is refused inline as today; a valid change saves on blur with "Saved" and
   updates the live handler without a reload. [error: save fails → the row reverts, the panel says "Not saved —
   your change is only on this browser" and offers Retry]
3. **Second device** — opening the editor uses the stored map; a local map from before this shipped is adopted
   once (if the account has none) and then becomes the account map.
4. **Reset** — `Reset to defaults` asks for confirmation inline ("This replaces your account map") and saves.
5. **Signed out / offline** — the last map known to the browser is used for the session and a chip says
   "Local key map until you are back online".

## Backend changes
- Models/schema: `User.shortcuts` JSON column (nullable, default null) via one block in `app/schema/identity.py`.
- Routers: `GET /api/me/preferences` → `{"shortcuts": {...} | null}`; `PATCH /api/me/preferences` accepts
  `{"shortcuts": {...}}` and validates the shape (action → single key + modifiers, no duplicates across
  actions, max 40 entries) → 422 with the offending action on failure.
- Services/jobs: none.
- Permissions + workspace isolation: the route is user-scoped, not workspace-scoped; a token from another user
  can never read or write this row (asserted).
- Secrets/safefetch: none.
- OpenAPI: yes — new route; regenerate.

## Frontend changes
- Route: unchanged (editor).
- Nav entry: none.
- Components: `ShortcutModal.tsx` — load/save/migrate/reset states; `shortcuts.ts` — `mergeMaps(defaults,
  stored)` and `validateMap()` pure helpers, used by both the panel and the editor handler.
- API client: `lib/api/core.ts` — `getPreferences()`, `patchPreferences()`.
- Feature flag: none.

## Acceptance criteria
- [ ] A remap saves to the account and appears on a second browser profile.
- [ ] A clash is refused before saving, with the same message as today.
- [ ] A failed save never leaves the UI claiming success; the local change is labelled as local.
- [ ] Empty, loading and error states above all render; defaults render before the fetch resolves.
- [ ] Another user can never read or write this preference (asserted).
- [ ] No flag: the local map keeps working when the account has none.

## Notes for the implementer
Keep the stored shape identical to the existing local map (`{action: "key"}` / `{action: "mod+key"}`) so the
migration is a copy, not a translation. Do not add per-project overrides.
