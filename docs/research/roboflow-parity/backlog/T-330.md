## User story
As a builder, I want the version list to mark the one that is live and to let me name a good one, so that "what is production running" is answered without opening the API.

## UX flow (LabelDesk words)
1. **Editor → right rail → Versions** (`WorkflowVersions`, `apps/frontend/src/features/project/WorkflowVersions.tsx`) — the list as today, plus one chip per row: `Live` on the published number, `Draft` on the newest saved number when it is ahead, nothing otherwise. [empty: a workflow with one saved version shows one row with both `Live` and `Draft` absent and the line "Not published yet."] [loading: three skeleton rows] [error: "Versions could not load." with "Try again"; the editor keeps the loaded definition]
2. **Rename** — the row's three-dot menu offers Rename; the field is inline, 60 characters, and an empty name is refused. The rename changes the note on that version row only, so the definition is untouched.
3. **Restore** — the existing restore copies the snapshot into a **new** version and loads it into the editor unsaved; the toast says "Restored v3 into the editor · save to keep it". The list refreshes with `Draft v8` while `Live` stays on v7.
4. **Bounded history** — the list shows the twenty most recent versions with "Show older" paging, and each row prints its note, author and age. [error: paging past the end → the button disappears rather than repeating a request]

## Acceptance criteria
- [ ] The published number carries `Live`; a newer saved number carries `Draft`; the two chips never appear on the same row without the draft being ahead.
- [ ] Rename changes one version's note and nothing else; an empty name is refused inline.
- [ ] Restore keeps the live version unchanged, loads the snapshot unsaved and says so.
- [ ] Empty, loading and error states above all render, including the end of paging.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ today's version list, restore only.

## Notes for the implementer
`Live` must come from `published_version`, not from "the newest version", because that is the whole point of T-328. Twenty per page is the number; do not paginate with a cursor this list cannot key on.
