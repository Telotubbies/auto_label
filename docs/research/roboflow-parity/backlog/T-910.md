## User story
As an engineer whose epoch 20 took four times longer than epoch 3, I want the GPU and memory numbers from inside
the run, so I can tell "the box was thrashing" from "the data loader is the bottleneck" without shelling into the
worker.

## UX flow (LabelDesk words)
1. **Insights → Training** — a fourth chart group **System**, after Other metrics, with GPU utilisation, GPU
   memory, worker CPU and free disk, on the same epoch axis and the same run colours. [empty: a run trained before
   this card, or on a worker without the sampler, renders the group absent]
   [loading: unchanged skeletons] [error: a run whose worker had no GPU renders the CPU/disk series and no GPU
   series — never a flat zero line]
2. **Models → a run → Run settings** — a dimmed `Resources` line: `GPU avg 61% · peak 8.1 GB · disk free 42 GB`.
   [empty: `No resource samples for this run.`] [error: a failed sample is absent, not `0`]
3. **Export** — the CSV carries the `system/*` keys like any other metric, so a report can plot them.
4. **A run on the remote GPU worker** — the same keys appear, whatever the host (the sampler degrades, it does
   not fail).

## Backend changes
- Models/schema: none — the keys land inside the existing `history` JSON array (`models/training.py:46`), which is
  exactly what makes them chart for free (`services/insights.py:672-685`).
- Routers: `apps/backend/app/routers/training.py` — one line when enqueuing: the job's options record
  `"system_metrics": is_enabled("task_mlruns", c.db, c.ws.id)` next to `:277-282`, so a run keeps the policy it
  started with.
- Services/jobs:
  - `apps/backend/app/services/system_metrics.py` (new) — `sample() -> dict[str, float]` returning
    `system/gpu_util_percent`, `system/gpu_mem_used_mb`, `system/gpu_mem_total_mb`, `system/gpu_temp_c`,
    `system/cpu_percent`, `system/mem_used_mb`, `system/mem_percent`, `system/disk_free_mb`. Implementation:
    optional `import psutil` (guarded, `try/except ImportError`) for CPU/memory/disk, else `shutil.disk_usage`
    only; GPU through one `subprocess.run(["nvidia-smi", "--query-gpu=utilization.gpu,memory.used,memory.total,temperature.gpu",
    "--format=csv,noheader,nounits"], timeout=2)` with every failure swallowed. `enabled(opts) -> bool`.
  - `apps/backend/app/handlers/training.py:90-96` — inside the epoch callback, when `enabled(opts)`:
    `metrics = {**metrics, **system_metrics.sample()}`, so the same `update(…)values(history=history)` writes them
    (one expression; merges cleanly with T-902's `t` key).
  - `apps/backend/app/services/insights.py:672-685` — a fourth bucket: keys starting with `system/` go to group
    `system`, before `other`.
  - `apps/backend/requirements.txt` — one line `psutil>=5.9` with a comment that it is optional at runtime.
- Permissions + workspace isolation: nothing new is exposed — the samples ride the existing `project.models`
  payload; the sampler runs in the worker's own process.
- Secrets/safefetch: none; `nvidia-smi` is invoked with a fixed argument list, no shell, and never with user input.
- OpenAPI: no (no route, no schema change).

## Tests to write first
pytest — `apps/backend/tests/test_system_metrics.py`:
- `test_sample_reports_disk_even_without_psutil` — monkeypatch `psutil` away → the dict contains
  `system/disk_free_mb` and no `cpu_percent` key (never a `0`). (also covers the empty case)
- `test_a_missing_nvidia_smi_is_not_an_error` — monkeypatch `subprocess.run` to raise `FileNotFoundError` → no
  `system/gpu_*` keys and no exception.
- `test_epoch_rows_carry_system_keys_and_no_extra_series_leak` — enable the policy, drive one epoch →
  `history[0]["system/disk_free_mb"]` is a float; `GET /insights/training` lists the key under group `system` and
  `other` still holds only genuinely other keys.
- `test_the_policy_is_recorded_at_enqueue_and_off_means_no_keys` — flag on → `job.params.options.system_metrics`
  is true; flag off → no `system/*` key is written and the payload's key list is unchanged.
- `test_a_failed_sample_never_fails_the_epoch` — make `sample()` raise → the epoch row is still written with its
  model metrics and the job continues.
- `test_a_foreign_run_is_still_404` — workspace B's token on workspace A's run → 404.

node — none: no frontend surface beyond a group entry asserted by T-900's guard file (extend that guard's group
list in the same PR).

## Acceptance criteria
- [ ] A GPU run shows utilisations and memory per epoch; a CPU-only run shows CPU and disk without GPU lines.
- [ ] A worker without `psutil` or `nvidia-smi` still trains and still registers the model.
- [ ] No `0` is ever written for a sample that could not be taken.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: none — `5-F5.19` → T-266 shows the *credit* spend, not host resources.
Sampling happens once per epoch, not on a background timer: our runs are read on the epoch axis, and a 10-second
thread inside the worker would outlive a cancelled job. Record that as `shortcut: per-epoch sampling, upgrade to a
timer if sub-epoch throttling ever matters`.
`psutil` is optional on purpose (`requirements.txt` gets the line, the import stays guarded) — MLflow treats the
same dependency the same way for the same reason (`/docs/latest/ml/tracking/system-metrics/`).
