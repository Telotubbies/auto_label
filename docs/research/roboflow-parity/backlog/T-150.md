## User story
As a labeler, I want to describe a class and get proposals on the open image, so that a new object type does not need an existing model.

## UX flow (LabelDesk words)
1. **Editor → assist area → "Find with a model"** (the dialog is T-152) — the client sends the chosen model, one prompt per class (name + description) and each class's threshold. [loading: the dialog shows "Looking for 3 classes…" with a cancel; cancel aborts the request]
2. **Result** — the response carries plain annotations with `source` (`sam3`, `vlm+sam3`, `ultralytics:<variant>`) and a `confidence` where the model reports one. Nothing is saved; the client turns them into proposals (T-151).
3. **Empty result** — `annotations: []` is a success, not an error: the dialog says "Nothing found on this image — try a different description or a lower threshold".
4. **Refusals** — an unknown class, a class from another project, a model that cannot detect, a vision-language model without SAM 3.1, or a model the worker cannot run: 400 with the reason, before any call. At the allowance: 402. [error: a model runtime failure is 503 with the adapter's message, never a stack trace]
5. **Credit** — one AI call per invocation, metered with `kind="prompt_detect"` and checked before the call so a 402 costs nothing.
6. **One image only** — the route touches the open image, never a batch; a batch is auto-label's job.

## Backend changes
- Models/schema: none.
- Routers: new `POST /api/images/{image_id}/prompt-detect` — body `{model_ref: str, classes: [{class_id, description, threshold?}], confidence?: float}` → `{annotations: [...], model: str, count: int}`; `400/402/503` as above; `404` for a cross-workspace image; registered in `images.py` next to `label-assist`.
- Services/jobs: `services/prompt_detect.py` (new) — `resolve_target(c, body)` (validates classes against the project, resolves through `adapters/catalog.resolve(..., workspace_id=…)`, refuses a classification project), `run(image, body, classes)` which builds the `label_image` params (`class_prompts` from T-130) and returns proposals without writing.
- Permissions + workspace isolation: `project.infer` via `c.can`, `image_ctx` for the image (labelers only on assigned images); a class id from another project → 400, a foreign image id → 404.
- Secrets/safefetch: none — model refs go through `resolve`, never a path.
- OpenAPI: yes — one route.

## Acceptance criteria
- [ ] One request with up to 24 class prompts costs exactly one metered AI call and returns proposals with source and confidence.
- [ ] An empty result is a success; every refusal (class, project type, model, allowance, runtime) is a distinct readable status before or during the call, with nothing written.
- [ ] Nothing is saved by this route: the image's annotation count is unchanged after any response.
- [ ] The model is resolved per workspace, so another tenant's trained model is reported as unknown.
- [ ] Empty, loading and error states above all render (client states are T-152's).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the route is 404 and the dialog entry is absent.
- [ ] Keyboard-only path: not applicable in this card.

## Notes for the implementer
Reuse `adapters/refine.label_image` rather than writing a second inference path — it already handles SAM 3.1 refinement for VLM boxes and returns editor-shaped annotations. The cap is 24 classes per request, matching `MAX_SUGGEST_CLASSES`.
