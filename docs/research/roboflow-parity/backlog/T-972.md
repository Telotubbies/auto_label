## User story
As an ML engineer, I want to say "run this on the 4090 box" or "leave it to whichever worker is free",
so that a long training run does not land on a machine that is about to be rebooted.

## UX flow (LabelDesk words)
1. **Project → Train → Where** — a select: "this server" (default) or a named worker, each row showing
   GPU, last heartbeat age and its current job. [empty: no workers registered — "train on this server"
   is preselected and a one-line hint explains how to add a worker] [loading: skeleton rows while the
   worker list loads] [error: the chosen worker went offline between picking and submitting — submit
   is refused with "worker `gpu-2` is offline" and nothing is charged or queued].
2. **Job tray → run row** — shows the executor ("this server" / "gpu-2") and, for a remote claim, the
   last heartbeat. A reaped job reads "the worker stopped reporting", not "failed".
3. **Admin → Settings → Workers** — the same list with token state (never the token), last seen, and
   a disable toggle. [empty: "no worker has connected yet" with the install line] [loading: skeleton]
   [error: 403 for a non-admin, rendered as a lock on the row, not a blank page].

## Backend changes
- Models/schema: new table `workers` in `app/models/training.py` — `id`, `workspace_id` (FK, indexed),
  `name` (unique per workspace), `gpu`, `last_seen`, `disabled` (bool, default false), `created`.
  Registered in `models/__init__.py`; no `ADD COLUMN` block needed (new table).
- Routers: `routers/remote.py` `claim` reports `worker_name` + `gpu` and touches `workers.last_seen`
  (upsert by name); `routers/training.py` train accepts `executor: "local" | "<worker name>"`, refuses
  a disabled or stale (> 5 min) worker with 409, and stores the pin on `Job.params.executor_pin`;
  `routers/workspaces.py` gains `GET /workers` (list) and `PATCH /workers/{id}` (disable).
- Services/jobs: `app/services/workers.py` (new) — `list_workers(db, ws)`, `resolve(db, ws, name) ->
  Worker | None` (stale/disabled → None), `touch(db, ws, name, gpu)`. `worker.py` claim path respects
  the pin (`Job.params.executor_pin` must equal the claiming worker's name when set).
- Permissions + workspace isolation: listing needs `workspace.read`; disable needs `workspace.update`;
  pinning needs `project.train`; every statement rooted at `ws.id`, foreign worker id → 404.
- Secrets/safefetch: none — the worker token stays in the header (`remote.py:33`), never stored here.
- OpenAPI: yes.

## Acceptance criteria
- [ ] A pinned run is only claimable by the named worker; an unpinned run by any enabled worker.
- [ ] The job row names its executor, and a reaped claim reads "stopped reporting".
- [ ] An offline or disabled worker cannot be chosen, in the UI or by the API.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
