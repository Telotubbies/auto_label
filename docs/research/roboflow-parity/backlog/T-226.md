## User story
As an engineer, I want the export list to match my project type and to include a CLIP-style image+caption format, so that I do not download a detection format for a classification project or hand-build captions.

## UX flow (LabelDesk words)
1. **Export dialog** — the chips are the server's list: object detection gains `darknet`, `retinanet`, `tfrecord` (T-227/T-228), instance segmentation gains `yolov5-obb` and `png-mask-semantic` (T-229), semantic segmentation gains `png-mask-semantic`, classification gains `clip`, multi-label classification gains `multiclass` + `clip`. [empty: as T-224] [error: as T-224]
2. **Multi-label project** — chooses between *Multi-label CSV* and *Folder* and *CLIP*; the single-label folder exporter is not offered.
3. **Class names** — every format writes the project's class names verbatim; the folder exporter keeps its `path_segment` guard and refuses a name it cannot use as a directory.
4. **README** — every ZIP carries `README.labeldesk.txt` naming the format, the classes and the image count.

## Notes for the implementer
Use the existing `_copy` + `_check_stop` helpers so a cancelled export still cleans up. The CLIP caption is `"<class> <x> <y> <w> <h>"` per annotation in **normalised** coordinates, one line each — the format that CLIP-style trainers ingest, and the only one where a segmentation project can carry polygons as text.
