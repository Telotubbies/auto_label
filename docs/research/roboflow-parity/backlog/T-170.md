## User story
As a quality lead, I want a class to carry its own fields (severity, colour, part id), so that a labeler sees only the fields valid for that class instead of four generic flags.

## UX flow (LabelDesk words)
1. **Classes & tags → a class row → Attributes** — a small editor listing that class's fields: key (slug), label, type (`yes/no`, `choice`, `number`, `text`), options for a choice, required flag; add, reorder and remove. [empty: "No fields — this class uses only the four general flags"] [error: duplicate key or a choice with no options → inline, Save disabled]
2. **Editor → Attributes panel** — with a shape selected, the panel shows the selected class's fields first (a checkbox, a select, a number input or a text input), then a collapsed **General flags** group with the existing occluded/truncated/difficult/crowd toggles. A required field left empty is marked and blocks submit-for-review like a missing prompt answer. [empty: no selection → "Select a shape to see its attributes"]
3. **Saving** — toggling or typing saves with the annotation set (one undo step, one debounce). A value that does not match the type is refused by the server with the field's label, and the panel reverts that field with the message. [error: the field keeps focus and shows the server sentence]
4. **Changing a class's fields** — removing a field keeps existing values on annotations (they become unrendered but preserved), which the confirm states: "Values on 42 annotations are kept, not deleted."
5. **Copy behaviour** — duplicating a shape (T-122) copies its attribute values; repeat-previous keeps them too.
6. **Export** — COCO annotations carry an `attributes` object when present, and a class's field definitions are listed in the dataset manifest, so a consumer can interpret the values.
7. **When the flag is off** — only the four general flags exist, exactly as today, and defined fields are neither rendered nor validated (their stored values survive untouched).

## Backend changes
- Models/schema: `LabelClass.attributes` — JSON, nullable (`models/project.py`), plus a `CLASSES` append in `app/schema/dataset.py` (`"attributes": "JSON"`); no backfill.
- Routers: `PATCH /classes/{cid}` accepts `attributes` and validates through the new service; `PUT /annotations` values are validated against the selected class's definitions (unknown key, wrong type, over-long string → 400 naming the field's label).
- Services/jobs: `services/class_attrs.py` (new) — `clean_defs(defs)` (≤ 20 fields, slug keys ≤ 40, unique, choice needs 2–20 options, labels ≤ 60), `validate_values(class_row, attributes)`, `required_missing(class_row, attributes)`.
- Permissions + workspace isolation: definitions need `project.classes`; values ride the existing annotation save (`project.annotate`); class ids are project-scoped.
- Secrets/safefetch: none.
- OpenAPI: yes — the class body and the annotation body gain documented optional fields.

## Frontend changes
- Route: unchanged.
- Nav entry: none.
- Components: `features/editor/ClassAttributeFields.tsx` (new) — typed field rendering, required state, server-message revert; `Panels.tsx` — one block: render class fields above the general flags; `Classes.tsx` — one block: the definitions editor per class.
- API client: unchanged (`patch` on classes; annotations already save `attributes`).
- Feature flag: `task_class_attrs`; off ⇒ only the four general flags render and the definitions editor is absent.

## Acceptance criteria
- [ ] A class can define up to twenty typed fields and the editor shows only the selected class's fields plus the general flags.
- [ ] Values save with the annotation set, are type-checked by the server, and a failed value reverts alone with the field's label.
- [ ] Removing a field never deletes stored values, and a required field blocks submit-for-review.
- [ ] Duplicate and repeat-previous copy attribute values.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ only the four general flags render; stored definitions and values are untouched.
- [ ] Keyboard-only path: select a shape → Tab to the fields → Space on a checkbox → Tab to a select → arrows.

## Notes for the implementer
The four general flags stay valid on every class even with the flag on — hundreds of existing annotations carry them, and a migration that rejects them would break uploads. COCO's `attributes` key is an extension; label it as such in the export manifest.
