## User story
As a reviewer inheriting 4,000 auto-labels, I want the 300 boxes the machine itself doubted kept on the image with the question that failed, so that I can confirm or dismiss evidence instead of trusting a deletion I cannot audit.

## UX flow (LabelDesk words)
1. **Auto label** (`/:ws/:project/annotate`) — the checkbox reads "Check each box with the model", hint "One model call per box. A box it cannot confirm stays on the image, flagged for you." Off by default. [error: the checker is unreachable ⇒ the run continues, boxes end `unchecked`, nothing is deleted]
2. **The job banner** — after the run: "412 boxes checked · 38 doubtful · 12 unchecked", from the job result.
3. **Review** (`/:ws/:project/images/:id?review=true`) — a doubtful box draws with the warning tone and a dashed outline; the image panel carries a strip: "The checker could not confirm this as Helmet — the crop looks like a bicycle helmet" with Confirm, Dismiss and "Dismiss all doubtful". [empty: "No doubtful boxes on this image"] [loading: the strip waits on the image payload, never on a second request]
4. **Confirm** — clears the flag through the normal annotation save; **Dismiss** removes the box. Neither writes a second row.
5. **Flag off** — the checkbox keeps today's wording and a box the checker rejects is dropped as it is now.

## Backend changes
- Models/schema: new table `box_checks` — `id`, `workspace_id`, `project_id`, `image_id`, `annotation_id`, `class_id`, `phrase`, `verdict` (`doubtful` only), `reason`, `crop` (relative path), `created`; module `app/models/checks.py` registered in `models/__init__.py`. The annotation JSON gains `check: "confirmed" | "doubtful" | "unchecked"` and `checkReason` — no column, annotations already live as JSON.
- Routers: none new. Confirm and Dismiss ride on the existing `PUT /api/images/{image_id}/annotations`; the counts ride on `GET /api/ws/{ws}/projects/{project}/jobs/{jid}`. 404 for an image of another workspace, through the existing `image_ctx`.
- Services/jobs: `services/box_check.py` (new) — `check(vlm, im, box, cls) -> {"verdict", "reason"}`, `stamp(ann, verdict, reason)`, `record(db, ws_id, project_id, image_id, ann, reason, crop_bytes)` writing `DATA_DIR/box_checks/<project>/<image>-<ann>.jpg` once (idempotent by annotation id); `adapters/vlm_ad.py` — `verify_reason(im, box, cls) -> tuple[bool, str]` asking for `{"answer": "yes"|"no", "reason": "one short sentence"}`; `adapters/refine.py` — both verify sites stamp instead of `continue`, and return `{"confirmed", "doubtful", "unchecked"}` through `label_image`'s `stats`; `handlers/training.py` sums them into the job result.
- Permissions + workspace isolation: the job stays `reviewer`; the editor save stays `annotator` on the assigned image; `box_checks` rows are only read through a project-scoped query, so a foreign id is 404 and a labeler sees no reason text for an image that is not theirs.
- Secrets/safefetch: none new — the endpoint is the existing `LD_VLM_URL`, now behind T-640's `ai_egress.require`; `services/secretbox.py` holds a hosted endpoint token if one is ever stored, and no crop leaves the deployment.
- OpenAPI: no — no route or schema change (the annotation JSON is free-form and `Job.result` is already open).

## Acceptance criteria
- [ ] A box the checker cannot confirm stays on the image, carries the question's reason, and appears in the job banner's doubtful count.
- [ ] A reviewer confirms or dismisses it from the image panel; the rejected crop and its reason survive for later harvest.
- [ ] A checker that is unreachable leaves boxes `unchecked` and fails nothing.
- [ ] Empty, loading and error states above all render, including an image with no doubtful box.
- [ ] Workspace A cannot see workspace B's flagged boxes or crops (404 on a foreign image id).
- [ ] Flag off ⇒ the old copy, the old deletion, and no new rows or files.

## Notes for the implementer
`unchecked` is a third state on purpose: a checker outage must not read as approval. One row and one crop per (annotation, run) — key the file by annotation id so a re-run overwrites rather than accumulates. The reason is one short sentence in the model's own words, capped at 140 characters, and it is evidence, never UI prose to be trusted blindly.
