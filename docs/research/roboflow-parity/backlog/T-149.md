## User story
As a keypoint project manager, I want to click a point, name it and connect a bone, so that a twenty-joint skeleton is not typed blindly from memory.

## UX flow (LabelDesk words)
1. **Project → Classes & tags → a class row → Edit skeleton** — a modal with a canvas, a joint list and a bone list. The canvas uses the class's sample image or, when none exists, a neutral 4:3 grid. [empty: no joints → the canvas shows "Click to place the first joint"] [loading: the class's images are fetched for the backdrop → skeleton over the grid]
2. **Place** — click the canvas to add a joint at that normalised position; the new row in the joint list takes focus with a suggested name (`joint_1`) selected for typing.
3. **Connect** — select joint A, then **Connect** and joint B (or shift-click B) creates a bone with a default colour from the theme; the bone list row has a colour swatch, and the canvas line repaints with it.
4. **Move** — dragging a joint updates its default position; positions are saved with the skeleton so a new annotation of this class starts with the real layout, not a 0.5/0.5 grid.
5. **Delete** — removing a joint removes its bones and renumbers the remaining indices; the flip order and the existing annotations of that class are not touched (a saved annotation keeps its own point count and shows a warning chip "skeleton has 18 joints, annotation has 20").
6. **Flip order** — **Suggest from symmetry** fills `flip_idx` by mirroring names with left/right pairs and x positions; it is a suggestion the user can edit, and an invalid order blocks Save.
7. **Advanced tab** — the existing comma/newline textarea stays for bulk paste, with the same validation and a "switch to canvas" link that parses the text into points.
8. **Save** — the payload is the same `skeleton` JSON plus two new optional keys (`edge_colors`, `defaults`); a 400 names the first problem ("Bone 3-9 points outside the joint list").

## Acceptance criteria
- [ ] A skeleton can be built entirely on the canvas: place, name, connect, colour, drag and delete, and Save persists it.
- [ ] Default joint positions are saved so a new annotation of that class starts with the real layout.
- [ ] Deleting a joint renumbers the rest and removes only its bones; existing annotations are never rewritten.
- [ ] The Advanced textarea stays available, parses into the canvas, and the same validation runs for both.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the textarea modal is exactly as today; no canvas editor is rendered.
- [ ] Keyboard-only path: Edit skeleton → Tab joint list → Enter to select → Tab to Connect → Enter → pick a second joint.

## Notes for the implementer
`edge_colors` and `defaults` are optional so every existing skeleton keeps working; a skeleton without defaults still places joints at 0.5/0.5 as today. Colour is per bone — that is what makes a 20-bone skeleton readable, and the editor already draws edges.
