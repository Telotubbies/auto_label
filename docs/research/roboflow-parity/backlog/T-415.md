## User story
As a finance contact, I want the card, the billing details and every invoice in one place, so that a month-end close
does not need support.

## UX flow (LabelDesk words)
1. **Plan & billing → `Payment and invoices`** — `Go to portal` (primary) opens the provider's hosted page in a new
   tab; the tooltip reads `Opens our payment provider in a new tab.` When the provider is the mock, the button is
   `Set up payment` and opens the mock page that states `No payment provider is connected yet.`
2. **Billing details** — a read-only summary (`Billing email`, `Address`, `Tax ID`) with `Update information`, which
   opens the same portal; under the mock it opens a local form that saves nothing and says so.
3. **Invoices** — a table: `Invoice`, `Period`, `Amount`, `Status`, `Issued`, and per row `Download invoice`,
   `Download receipt`. [loading: three skeleton rows] [error: `Could not load invoices.` + retry]
   [empty: `No invoices yet. They appear here after the first paid cycle.`]
4. **`View more`** — loads the next page (25 per page); a search box filters by invoice number client-side.
5. **`[error]` a portal redirect failure** — `Could not open the payment portal.` with a copyable link underneath,
   so a popup blocker never traps the user.

## Backend changes
- Models/schema: none (`BillingInvoice` from T-412).
- Routers: `GET /api/ws/{ws}/billing/invoices?limit&offset&q` → `{rows: [...], total}`;
  `POST /api/ws/{ws}/billing/portal` → `{url}` from `provider.create_portal(account)`; `400 not_configured` while
  the provider is a mock without a customer id.
- Services/jobs: `services/billing.py` — `invoices(db, ws, limit, offset, q)`, `portal_url(db, ws)`;
  `MockProvider.create_portal` returns the local `/settings/billing?mock=portal` path (no network).
- Permissions + workspace isolation: `workspace.billing` for both; invoice rows filter `workspace_id`.
- Secrets/safefetch: the hosted URL is provider-issued and opened as-is; it is not fetched server-side, so
  `safefetch` is not involved.
- OpenAPI: yes.
