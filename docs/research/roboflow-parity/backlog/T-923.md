## User story
As a reviewer, I want to see and edit a version's tags where I read its metrics, so that approving a model is one click on the screen where I judge it.

## UX flow (LabelDesk words)
1. **Model detail header → tags** — the version's tags render as `key:value` chips under the metadata line; *Edit tags* opens a two-column editor (Key, Value) with *Save* and *Cancel*. Saving one row writes only that key. [empty: "No tags yet — add one to record why this version is (or is not) deployable."] [loading: the editor is read-only until the existing map resolves, then one row at a time shows a spinner while saving] [error: two rows with the same key, or a blank key, is refused inline with the row marked and nothing saved]
2. **Delete a tag** — the chip's × asks once and removes only that key; the chip disappears immediately and comes back if the call fails, with a toast naming the tag. [error: "Tag not removed — retry" and the chip returns filled]
3. **Filter by tag** — a *Filter* control beside the tags offers the project's tag keys and values as two small selects; choosing both sets `?tag=validation_status:approved` and the rail narrows. [empty: a tag with no matching version shows "No model carries validation_status:approved." + *Clear filter*] [loading: the rail dims, the previous results stay]
4. **Model-level summary** — above the version list, the union of the group's tags is shown read-only with a count of versions carrying each, so a group can be judged without opening every version.
5. **Permission** — a reader sees the chips and the filter but no *Edit tags*; the control is dimmed with a lock, not silently absent.
