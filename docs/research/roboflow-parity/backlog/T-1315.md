## Problem
There is no tenant-facing health screen at all; the only operational screen is the superadmin console.

## Design
Route `/:ws/system`, `Gate min="admin"`, footer nav entry **System** beside Admin (owner/admin only,
not superadmin). One page, five solid `Card`s, no chart library:

1. **Header** — `PageHeader title="System"`, subtitle "Queue, workers and disk for this workspace",
   a **Refresh** button and a "Updated 3 s ago" line; auto-refresh every 10 s while the tab is visible.
2. **Queue card** — four tiles (Queued, Running, Oldest queued, Failed 24 h), the oldest-queued tile
   turns amber past 10 min; below it the 20 most recent active jobs (kind, status, progress bar, age)
   reusing the row markup from `AdminConsole.tsx:120-132`.
3. **Workers card** — online count, per-row host, heartbeat age, current job; a worker older than
   `LD_WORKER_STALE_S` shows an "offline" badge. One line when `workers_scope === "platform"`:
   "Workers are shared by every workspace in this deployment."
4. **Storage card** — free GB, a `Progress` used-ratio bar, and a line that turns red under 5 GB
   matching the alert threshold.
5. **API card** — requests and errors in the last 5 minutes plus p95, or "Not available in this
   deployment" when `api` is `null`; a **Copy request id** button from the last failed call.

States, all real: loading (`Spinner` row, `role="status"`), error (`ErrorLine` with retry, never a blank
page), empty ("Nothing is queued."), stale (amber "No update for 60 s", data still shown), 403 (the
existing pattern: the nav entry is absent and the route renders the standard 404).

Visual rules: glass stays on the top bar and the rail only; cards, tables and bars are solid
(`Card`, `Progress`) per `design/labeldesk-v3/VISUAL-OVERRIDE.md`; no new token, hex, font size or
component. 375 px: one column, tiles 2×2, no horizontal scroll, tables become stacked rows.

## Acceptance criteria
- [ ] Owner/admin see **System** in the footer rail; member, labeler and billing do not, and the route
      renders the standard 404 for them.
- [ ] Five cards, all four data states (loading, empty, error, stale) demonstrated in the report.
- [ ] Amber at 10 min queued, red under 5 GB, both matching the alert thresholds.
- [ ] 375 px: single column, no horizontal scroll, tap targets ≥ 40 px.
- [ ] Light and dark both pass WCAG AA text contrast on glass — the v3 audit's 11–12 px grey failure is
      not repeated.
- [ ] No new dependency, no new primitive, no chart library.

## Notes for the implementer
Read `AdminConsole.tsx` first and copy its row/progress/stat markup rather than inventing a second
visual language; the difference is scope (one workspace) and permission (owner/admin), not style. Do not
embed Grafana. Do not add a second polling library — `useQuery` with `refetchInterval: 10_000` is
already in the stack. Use `Gate min="admin"`; do not write a second role check.
