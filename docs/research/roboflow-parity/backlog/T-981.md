## User story
As someone integrating LabelDesk, I want to ask the server which API versions it speaks, so that my
client can refuse or warn instead of failing in a way I have to reverse-engineer.

## UX flow (LabelDesk words)
1. **`GET /api/version`** — `{service: "labeldesk", version: "1.4.0", api: {v1: {status: "stable",
   since: "1.0.0"}, mlflow_wire: {status: "experimental", since: "1.5.0"}}, min_client: "1.0.0"}`.
   No authentication: it is the thing a client calls before it has a credential. [empty: n/a] [loading:
   n/a] [error: n/a — the route cannot fail except with a 404 when the flag is off].
2. **`labeldesk doctor`** (T-986) prints the server's answer next to the SDK's own supported version and
   warns on a major mismatch.
3. **Docs** — `docs/api/versioning.md` states the promise in three sentences: additive changes are
   minor, removals wait one minor release behind a deprecation warning header, `v1` is stable.

## Acceptance criteria
- [ ] `GET /api/version` answers without a credential and matches the OpenAPI `info.version`.
- [ ] The documented compatibility promise names what is stable (`v1`) and what is experimental.
- [ ] Turning the flag off removes the route and changes nothing else.

## Notes for the implementer

in both places, or the two will disagree within a release.
