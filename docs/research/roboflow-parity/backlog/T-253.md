## User story
As a team lead, I want to cap one run in credits and be told the smallest cap that still produces a model, so that a runaway search cannot empty the month.

## UX flow (LabelDesk words)
1. **Train → Output → Credit cap** — an optional number field under the estimate, prefilled empty ("No cap"). Under it: "Smallest cap: 1 credit (6 min)."
2. **Below the floor** — typing 0.2 turns the field red with "The cap must be at least 1 credit — below that a run cannot produce a model." and Start disables; the typed value is kept so the user can fix it.
3. **Below the estimate but above the floor** — allowed, with a note: "The run will probably stop early and keep its best weights."
4. **Server says no** — the API answers the same rule as a **400** so a replayed request cannot bypass the field.

- **States** — the cap field is T-254's: [empty: cap omitted ⇒ the row stores NULL and the field reads "No cap"] [loading: the quote the cap is validated against may still be computing, so the field keeps its value] [error: the 400 text renders under the field and the value is kept so it can be fixed].

## Backend changes
- Models/schema: `trained_models.max_credits FLOAT` (nullable; empty = uncapped). Add to the `TRAINED_MODELS` block in `apps/backend/app/schema/training.py` — `"max_credits": "FLOAT"` — appended at the end of the dict so `schema.apply` order for existing rows is unchanged.
- Routers: `POST {P}/train` body gains `max_credits: float | None = None`; **400** when `0 < max_credits < quote.minimum_credits` ("the cap must be at least {minimum} credit(s) — below that a run cannot produce a model") and **400** when `max_credits <= 0`. The stored `Job.params.options` carries `max_credits` so a retry/continuation reads the same value.
- Services/jobs: `handlers/training.py::run_train` converts the cap into the existing budget check: `budget = min(metering.remaining(...), max_credits * train_quote.CREDIT_GPU_SECONDS)`; `_over_budget` already stops a lease past its budget, so the cap reuses that path. A stop by cap keeps `best.pt` and registers a model (T-263 adds the visible reason and the continuation).
- Permissions + workspace isolation: unchanged (`c.need("admin")` on `POST /train`); the quote the cap is validated against reads only this project's version.
- Secrets/safefetch: none.
- OpenAPI: yes — `TrainIn` and `model_out` change (regenerate both files).

## Acceptance criteria
- [ ] A cap below the runnable floor is refused by the API with a message naming the floor.
- [ ] A valid cap is stored on the model row and on the job so a continuation reuses it.
- [ ] The handler's lease budget is the smaller of the workspace allowance and the cap in seconds.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no field is sent, `max_credits` is NULL, and the run behaves as today.

## Notes for the implementer
One conversion function only: `max_credits × 1800`. Never store seconds on the model row — a later change to the credit rate would silently rewrite history.
