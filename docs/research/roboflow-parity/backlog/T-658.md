## User story
As a team choosing between a cheap detector and a foundation model, I want only the images where the two disagree, ranked by how far apart they are, so that a reviewer spends their afternoon on the images that actually decide the choice.

## UX flow (LabelDesk words)
1. **Annotate board → Compare models** (`/:ws/:project/annotate`) — pick model A, model B and a sample size (100 / 300 / 500); the card states the call cost before running. [empty: fewer than two ready models ⇒ "Two ready models are needed to compare" with the models link]
2. **Running** — `[loading: "Comparing 300 images — 600 model calls"]` with a counter; `[error: the first model that failed, by name, with Try again]`.
3. **Agreement** — `[empty: "the two models agree on every sampled image"]` when nothing differs; otherwise a summary line per class and a table of images sorted by distance.
4. **A row** — thumbnail, distance, and the reasons in words: "A has 2 boxes here, B has none", "class differs: Vest vs Jacket", "mean IoU shift 0.21".
5. **The diff view** — A's boxes in one class colour and B's in the next, overlaid on the image, opened in the editor.
6. **Send the top 50 to Review** — moves those images to `review` with the tag `compare:ab` and stores both models' predictions so the reviewer sees the argument, not one answer.
7. **Flag off** — no card on the board.

## Backend changes
- Models/schema: none — both prediction sets are stored in `Job.result["pairs"]`, which the row already keeps.
- Routers: `POST /api/ws/{ws}/projects/{project}/compare` (`ref_a`, `ref_b`, `sample` ∈ {100, 300, 500}, `batch_id` or `image_ids`) → 202 job; `GET .../jobs/{jid}` returns the result, which the board already polls. 400 when a ref is unknown or the same on both sides, 409 when the two models' tasks differ, 403 for a non-reviewer, 404 for a foreign batch.
- Services/jobs: `services/disagreement.py` (new) — `pairs_for(db, project, body)` selecting the sample deterministically (newest first, capped), `run_pair(r_a, r_b, im)` returning each side's predictions, `diff(a, b, iou=0.5) -> {"missing", "extra", "class_mismatch", "iou_shift", "distance"}` where `distance` is a 0–1 blend of the four counts against the larger side, `summarise(pairs, classes)` giving per-class agreement and per-model call counts; job kind `compare` in `LOCAL_JOB_KINDS`.
- Permissions + workspace isolation: `reviewer` to queue, `project.read` to read a finished comparison; both refs resolve through `resolve(..., workspace_id=c.ws.id)` so a trained model from another workspace cannot be named, and the batch query is project-scoped (404 otherwise).
- Secrets/safefetch: `services/secretbox.py` holds a hosted endpoint token if one is stored; a VLM as model B goes through `ai_egress.require` (T-640), so no image leaves the deployment without `workspaces.ai_egress`.
- OpenAPI: yes — regenerate (`python tools/export_openapi.py`, `npm run gen:api-types`).

## Acceptance criteria
- [ ] Two models run over the same sampled images and only the images that differ are listed, sorted by distance.
- [ ] Each row says what differs in words, and the diff view shows both models' boxes overlaid.
- [ ] The top 50 can be sent to review with both prediction sets stored, and the summary reports per-class agreement.
- [ ] Empty, loading and error states above all render: full agreement, a running comparison with a counter, one model failing by name.
- [ ] Workspace A cannot compare against workspace B's models or batch (unknown ref 400, foreign batch 404).
- [ ] Flag off ⇒ no card, no route, and the board is unchanged.

## Notes for the implementer
`distance` is the reviewer's sort key, not a metric to publish as accuracy: it blends missing, extra, class mismatch and IoU shift against the larger side, capped at 1.0. Run the sample through the existing `resolve().predict` path so a trained model, a zoo model and a VLM all behave the same; never invent a ground truth to break a tie.
