## User story
As a reviewer, I want the create call to refuse a contradictory recipe with the reason the form already showed, and the wizard to know my plan's multiplier cap, so that a bad recipe never costs a credit.

## UX flow (LabelDesk words)
1. **Wizard → Create** — the client sends the recipe; a 400 body carries `{"detail": "<message>", "code": "<code>", "field": "preprocessing.tiling"}` so the wizard can point at the step it owns. [empty: n/a] [loading: the button keeps its width and reads "Generating…"] [error: the message is shown on the offending step, never only as a toast]
2. **Wizard → Output size** — the multiplier options come from `GET /versions/limits`, so a plan with a 3× cap never renders a 5× option. [loading: the select shows the default 3 while the limit loads] [error: limits unavailable ⇒ the select is disabled with "Could not load your plan limits — retry"]

## Acceptance criteria
- [ ] A conflicting recipe is rejected before any credit is charged and the body carries `code` + `field`.
- [ ] `GET /versions/limits` answers from `config.PLANS` (+ `ws.quotas` override) and needs only project read.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ `GET /versions/limits` is 404 and create behaves exactly as before.

## Notes for the implementer
Reject with 400, not 422: the wizard already renders 400 bodies inline and `ApiError` keeps `detail` as an object only when the body is JSON. Never truncate the message — the node copy is keyed by `code`, so the English text may differ between sides but the code may not.
