## User story
As a member of a company with SSO, I want to sign in with our IdP instead of a password, so that access follows our
directory.

## UX flow (LabelDesk words)
1. **Sign-in screen** — a `Continue with single sign-on` button under the password form. Clicking it reveals one field
   `Work email` and `Continue`; the button disappears while this is open.
2. **Known domain** — the browser is sent to the workspace's IdP with `state` and a PKCE challenge; on return the app
   shows `Signing you in…` and lands on the workspace. [loading: the button shows a spinner]
3. **Unknown domain or SSO off** — inline `This domain does not use single sign-on. Sign in with your password instead.`
   and the email field keeps the value. [error: IdP rejected the sign-in → `Your identity provider did not confirm this
   sign-in. Try again, or ask your admin.`]
4. **No membership** — a verified identity with no member row and no auto-join → `You are signed in, but this workspace
   has not added you yet. Ask an admin to invite you.`
5. **`[empty]`** a workspace with SSO off shows no SSO button at all (the component reads the public config).
6. `state` is single-use and expires in 10 minutes; a replayed callback shows the error line and no session.

## Backend changes
- Models/schema: none — a short-lived `LoginEvent(method="oidc")` row records the attempt; `state` lives in a signed,
  `HttpOnly` cookie (`security` helpers), not a table.
- Routers: `app/routers/auth.py` (shared) — `GET /api/auth/config` gains `sso: bool` (any workspace has it enabled);
  `POST /api/auth/sso/lookup` `{email}` → `{issuer, client_id, authorize_url}` or `404 This domain does not use single
  sign-on.`; `GET /api/auth/sso/callback?code&state` → exchanges the code at the issuer's token endpoint
  (`http.client`, 10 s timeout), verifies the id_token with the existing `oidc.verify_oidc` against the workspace's
  issuer/client id, resolves the user by `email`, requires or creates a `Member` per the directory rules (T-432),
  and returns the same token bundle `tokens()` produces.
- Services/jobs: `app/services/sso_login.py` (new) — `authorize_url(config, redirect_uri, state, challenge)`,
  `exchange(config, code, verifier) -> dict`, `verify_id_token(config, id_token) -> dict` (wraps
  `oidc.verify_oidc` with a per-call issuer instead of the env one), `state_cookie()/read_state()`, `pkce_pair()`.
- Permissions + workspace isolation: the callback resolves the workspace from the signed state cookie, never from a
  request body; a state from workspace A cannot mint a session in B. Membership is required unless auto-join applies.
- Secrets/safefetch: the client secret is decrypted with `secretbox` for the token exchange only; the IdP endpoints come
  from discovery at the configured issuer, and the issuer host is the admin's verified domain path — `safefetch.check_url`
  runs on the discovery URL when SSO is enabled.
- OpenAPI: yes.

## Frontend changes
- Route: `/login` (existing screen) gains the button; `/sso/callback` is handled by the same `Auth.tsx` branch that reads
  the query string.
- Components: `features/auth/SsoButton.tsx` (new) — button, email field, inline sentences;
  `features/auth/ssoError.ts` (new) — `messageFor(code)` for the four outcomes.
- API client: `authApi.ssoLookup(email)` and `authApi.ssoCallback(params)` in `src/lib/api/core.ts`.
- Feature flag: `task_sso`; off ⇒ no button, no lookup route.

## Acceptance criteria
- [ ] One button on the sign-in screen starts SSO for a known domain and names an unknown one inline.
- [ ] The callback verifies a single-use state, exchanges the code and issues the same session the password path does.
- [ ] A verified identity with no membership is told what to do, and auto-join only applies when configured.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no button, no routes, password sign-in unchanged.

## Notes for the implementer
State + PKCE, both single-use; the state cookie is the only thing that names the workspace. Reuse `oidc.verify_oidc` by
adding a per-call issuer seam rather than a second verifier.
