## User story
As a QA lead, I want to filter production events by type, class, verdict and time, and to see how far back the answers can go, so that a report never silently describes a partial window.

## UX flow (LabelDesk words)
1. **Stream detail → Events** — one filter bar above the timeline: type chips (`All`, then the five types), the existing rule/class/reviewed selects, and a range (`24 h`, `7 d`, `14 d` — never longer than `lookback_days`). [empty: no events at all → "No events yet. Start the stream; events appear here as soon as a rule fires."] [empty after filtering: "No events match these 3 filters." with "Clear filters"] [error: the list fails → "Events could not load." with "Try again"]
2. **The lookback line** — one sentence under the bar: "This project keeps events for 14 days." When the selected range is clamped, the sentence says "…so this view starts 14 days ago."
3. **Row** — the type chip, the rule label, the time, the classes and, once T-339 lands, the verdict marker. A metadata key from the vocabulary appears as one `key: value` line.
4. **Copy the query** — a secondary action produces the exact API call for the current filters, so a report owner can rerun it in a script.
5. **Paging** — 50 rows per page with `offset`; the total is printed once: "312 events · showing 1–50".

## Tests to write first
pytest — `apps/backend/tests/test_event_query.py`:
- `test_a_window_is_clamped_to_the_lookback` — asking for 90 days on a 14-day project returns `lookback_days: 14` and only 14 days of rows.
- `test_event_type_filters_before_paging` — 60 events of two types with a type filter returns `total` for that type only.
- `test_since_and_until_are_inclusive_at_the_edges` — a row exactly at `since` is included, one a second earlier is not.
- `test_an_unknown_type_is_400` — a type outside the five is refused rather than returning nothing.
- `test_lookback_days_is_present_on_every_response` — an empty result still carries the field, so a client can state the window.
- `test_a_foreign_stream_is_404`.
node — `apps/frontend/tests/event-filters.test.mjs`:
- `test_to_query_drops_empty_filters` — `toQuery({type: "", cls: "helmet"})` contains `class=helmet` and no `type=`.
- `test_the_clamp_label_names_the_window` — `clampLabel(14, true)` says the view starts 14 days ago; `clampLabel(14, false)` does not.
- `test_has_filters_counts_only_meaningful_ones` — the default range alone is not "filtered", so the no-match state does not appear on a healthy stream.
- `test_three_filters_read_as_three` — the no-match copy counts the active filters.

- [ ] The no-match state counts the active filters and offers "Clear filters", distinct from "No events yet".

## Notes for the implementer
`lookback_days` comes from the retention setting, not from the data — the point is that a report can be honest before anyone queries it. Do not add a saved-view system here; that is area 2's query surface.
