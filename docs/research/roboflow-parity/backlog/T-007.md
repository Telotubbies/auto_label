## User story
As the reviewer of any area-7 PR, I want member removal, the usage/limits read, the one-time key reveal
and the first-run workspace pinned so an RBAC, billing or key-lifecycle card cannot change who can be
removed, drop a meter, or make a key readable after creation.

## UX flow (LabelDesk words)
1. **Members** — the roster shows name, email, role, joined date and an owner badge; a non-owner row has
   Remove, your own row reads Leave. The owner row has no control at all.
2. **Plan & Usage** — plan label, credits used/of limit, then the four meters (GPU time, stream hours,
   AI calls, storage) with used/limit bars, plus projects and seats against the plan. [empty: a fresh
   workspace shows zeros, not an error]
3. **API keys** — Create key; the dialog says `Copy your new key now — it won't be shown again.`; the
   table afterwards shows prefix, created, last used and Revoke only. A publishable key is browser-safe
   and cannot manage anything.
4. **First run** — a signed-up account owns one workspace as its admin on the free plan; Settings offers
   `Create a workspace` for a second one.
5. **Sign-in → workspace** — every workspace page reads the caller's role; a non-member gets 403, a
   missing workspace 404.

## Notes for the implementer
The documented "last admin cannot leave" rule is satisfied structurally here: the owner is always an
admin and can never be removed (`app/routers/workspaces.py:217-218`), so no workspace can lose its last
admin. Assert the owner rule, not an invented `last admin` message — a later card that adds a real
last-admin check should extend this test rather than replace it.
`test_e2e.py` already proves signup creates an admin workspace, but that module trains a model; the
guard's own signup test exists so a broken signup fails in seconds, not after a CPU training run.
Migration-sensitive HAVE facts: a key value is returned only by `POST /keys` and stored as
`hash` + `prefix` (`workspaces.py:263-270`); `publishable` forces `["infer"]` and starts `ld_pub_`;
`scopes = None` (legacy) means all scopes; owner removal and demotion are both refused; usage `seats`
counts `Member` rows and `projects` excludes `deleted_at` rows (`workspaces.py:25-35`).
