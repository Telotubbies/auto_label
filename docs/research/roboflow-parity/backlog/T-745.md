## User story
As an admin removing a departing labeler, I want to see everything still attached to that account and hand each item to someone else, so that a camera stops alerting to a LINE account that was closed with the employment.

## UX flow (LabelDesk words)
1. **Settings → Members → a member's row → `Remove`** (`/:ws/settings/members`) — when anything still depends on the account, the confirm is replaced by the sweep sheet titled `"Somchai still owns 4 things"` / `"คุณสมชายยังเป็นเจ้าของ 4 รายการ"`, with `"Reassign each one, or revoke it, before removing this account."`
2. **The sweep rows** — grouped by kind, each with a `Reassign to…` `Select` of the remaining members: `Projects where they are the only manager` (3), `API keys they created` (1), `Alert channels pointing at their LINE account` (1), `Saved dashboards` (2), `Images assigned to them` (41 — one button, `Unassign`). [loading: five skeleton rows] [error: "Could not load what this account owns." + **Try again**]
3. **`Reassign all to…`** — one `Select` plus one `Reassign` button, for the common case of handing everything to the new shift lead; the result toast reads `"Moved 4 items to Nok."`
4. **Nothing depends on the account** — the sheet reads `"Nothing depends on this account."` and removal proceeds on one confirm. [empty: that sentence, and the Remove button is not hidden]
5. **A key that cannot be moved** — an `ApiKey` has no owner column in the old rows (`created_by` is null): the row reads `"An older key with no recorded owner"` and offers `Revoke` only.
6. **The audit** — one `member.reassign` row per item and one `member.remove` row, both naming the departing account.

## Backend changes
- Models/schema: none — every dependency is a column that already exists (`ProjectMember.role`, `ApiKey.created_by`, `AlertChannel.created_by`, `Dashboard.created_by`, `Image.assignee_id`).
- Routers: `app/routers/offboarding.py` (new), prefix `/api/ws/{ws}`, `dependencies=[Depends(require_flag("task_ownership_transfer"))]` — `GET /members/{uid}/dependencies` → `{projects_only_manager: [{project, name}], api_keys: [{id, name, created}], alert_channels: [{id, name, kind}], dashboards: [{id, name, project}], assigned_images: int}`; `POST /members/{uid}/reassign` `{kind, id?, to}` → `{moved: int}` (`kind` in `project|api_key|alert|dashboard|images`; `id` omitted means every row of that kind). `DELETE /api/ws/{ws}/members/{uid}` in `workspaces.py` answers 409 `{"code": "owns_dependencies", "dependencies": {…}}` when anything remains, unless the caller passes `?force=true`.
- Services/jobs: `app/services/offboarding.py` (new) — `dependencies(db, ws, uid) -> dict` (one query per kind, workspace-scoped), `reassign(db, ws, uid, kind, item_id, to_uid) -> int` (the target must be a member of the same workspace; `project` rewrites `ProjectMember.user_id` keeping `role="manager"`, `api_key`/`alert`/`dashboard` rewrite `created_by`, `images` clears `assignee_id`), `blockers(db, ws, uid) -> int`.
- Permissions + workspace isolation: `c.need("admin")` on all three; every query filters `workspace_id == c.ws.id` and every id is resolved inside it, so a foreign member id is 404; a target user who is not a member is 400.
- Secrets/safefetch: none — an alert channel's credentials stay in `config` and are never returned by the sweep (the row shows name and kind only).
- OpenAPI: yes — two new routes and the 409 body on member removal.

- Glass: the sweep is `Modal` (`Glass strength="overlay"`); each group is a `Card` row with a `Select` and a `Button`; counts use `Badge`; the departing-account tone is `chipTone('status', 'queued')`; `text-sm`/`text-xs`, `lucide-react` (`UserMinus`, `ArrowRightLeft`), no new token.
- Feature flag: `task_ownership_transfer` off ⇒ the sweep route is 404, `Remove` behaves as today (it clears assignee and project roles and succeeds) and no sheet is offered.

## Acceptance criteria
- [ ] Removing a member who still owns something is blocked with the full list inline, and the removal succeeds once every group is handled.
- [ ] Each row offers `Reassign to…` or `Revoke`/`Unassign`, and each move writes one audit row naming both accounts.
- [ ] `Reassign all to…` moves every item of the chosen kind and reports the count.
- [ ] Empty, loading and error states above all render: "Nothing depends on this account.", the skeleton, and the load error with **Try again**.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no sweep, no 409, and removal works exactly as it does today.

## Notes for the implementer
`ApiKey.created_by` and `AlertChannel.created_by` are nullable on old rows: show them as "no recorded owner" and offer revoke, never invent an owner from the workspace.
