## User story
As a reviewer, I want to see what one real image looks like after my preprocessing plus the exact image count I will get, so that a clipped label or a 40× tiling blow-up is caught before generation.

## UX flow (LabelDesk words)
1. **Wizard → step 3** — changing any step calls preview for the current sample image. [empty: "Pick a source image to preview" when the project has no image yet] [loading: the panel keeps its aspect box and shows a shimmer] [error: "Preview failed — generation still works; the numbers below are estimates"]
2. **Wizard → step 4/5** — the same call, without `image_id`, returns the counts only, so the estimate and the tile count share one request. [loading: the estimate shows "calculating…"] [error: "Could not estimate this recipe" with the reason code]
3. **Wizard → tag rules** — the response's `pool` block feeds the "N images match these rules" line, including the zero case: "No images match these tag rules — adjust or reset."

## Backend changes
- Models/schema: none; the endpoint only reads `Image`, `LabelClass`, `Project`.
- Routers: `apps/backend/app/routers/versions.py` — `POST "/preview"` body `{"settings": dict, "image_id": str | None}` → `{"conflicts":[…], "warnings":[…], "pool": {"total": n, "by_split": {…}, "nulls_kept": n, "nulls_dropped": n}, "estimate": {"train": n, "valid": n, "test": n, "total": n, "exact": bool}, "tiles": {"count": n | null, "reason": str}, "sample": {"data_url": "data:image/jpeg;base64,…", "width": w, "height": h, "anns": [...]} | null}`; 400 when `image_id` belongs to another project.
- Services/jobs: `app/services/recipe.py` gains `pool(db, project, recipe)` (tag rules + class surgery applied to the row list, no pixels) and `sample(db, project, recipe, image_id)`; `estimate` multiplies the train split by `outputs` exactly as `versioning.generate` will (`1 + outputs - 1` copies for train only, `filter_null`/null policy applied first). Sample render reuses `imaging.preprocess` + `tiling.tile_annotations` on one image, downscaled to ≤768 px, JPEG q80.
- Permissions + workspace isolation: `c.need("reviewer")` — preview is a create-shaped read; a foreign project slug is 404 via `project_ctx`, a foreign image id is 400 with `code == "image_not_in_project"`.
- Secrets/safefetch: none (no outbound call, no URL fetching).
- OpenAPI: yes — regenerate both files.

- `test_image_from_another_project_is_a_400` — `code == "image_not_in_project"`.
- `test_flag_off_is_404` — `task_190` off → 404 and no job, no version row.

node — none: no frontend surface in this card; the estimate helper lands in `src/lib/recipe.ts` under T-193, which tests it there.

## Acceptance criteria
- [ ] One request returns conflicts, warnings, pool counts, estimate and (optionally) a rendered sample with transformed annotations.
- [ ] The sample never exceeds 768 px on its long side and never returns more than the pipeline would produce.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ route 404, wizard falls back to the static counts it shows today.

## Notes for the implementer
Return the sample as a base64 data URL: a real file would need a new storage path and a sweeper. Cap the decode with `PImage.MAX_IMAGE_PIXELS` already set at 120 MP; skip the render and return `sample: null` with `warnings: [{"code":"image_too_large"}]` above 12 MP.
