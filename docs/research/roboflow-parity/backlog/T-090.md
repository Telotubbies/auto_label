## User story
As a reviewer, I want to type "forklift without a driver" and get the nearest images even when nothing is
labelled, so that "find what I forgot to label" is one sentence instead of a class taxonomy.

## UX flow (LabelDesk words)
1. **Dataset · Images** — the search box accepts a **Describe** chip: typing free text with the chip on
   sends it as a description, not a filename. [loading: 12 skeletons and a line "Ranking 3,000 images…"]
2. **Dataset · Images** — results are ordered by closeness and the chip reads
   "Described: forklift without a driver ×"; a caption states "Ranked by image similarity — not filtered
   by labels". [empty: "Nothing close enough — try fewer words or a different scene"]
3. **Dataset · Images** — combining with a negation (`Description + no class:helmet`) returns the nearest
   unlabelled candidates; a hint line offers "Only unlabelled" as a one-click filter.
4. **Dataset · Images** — on an install without the CLIP model the same chip falls back to keyword matching
   and says so: "Keyword match on file names — install the image model for description search."
   [error: the feature cache is unreadable → the fallback message, never a blank grid]

## Backend changes
- Models/schema: none.
- Routers: `apps/backend/app/routers/images.py` — `GET P/images` gains `text: str = ""` and
  `text_unlabelled: bool = False`; when `text` is set the route ranks through `services.semantic` and
  applies `annotated=no` for the hint; the response gains
  `"textMode": "clip"|"keyword"` and `"textSampled": bool`. `text` and a `q` free-text query are additive
  (both must match), so a description can be combined with chips.
- Services/jobs: `apps/backend/app/services/semantic.py` (new) —
  `available() -> bool` (reuses `insights_embedding._clip_backend` without loading it if untried),
  `embed_text(text) -> np.ndarray | None` (CLIP `get_text_features`, normalised),
  `rank(db, project, text, limit, unlabelled_only) -> (rows, mode, sampled)` — image vectors from
  `services.similar.vectors` (T-088) over the same 3 000-image bound, cosine ordering, `keyword(db, ...)`
  fallback scoring `Image.name ILIKE` plus class-name hits. No job is enqueued; a cold cache ranks the
  bounded sample and reports `sampled=true`.
- Permissions + workspace isolation: `project.read`; the labeler `_visible` rule and honeypot blanking wrap
  the ranked rows exactly as they wrap the normal list.
- Secrets/safefetch: none.
- OpenAPI: yes — two parameters, two response keys.

## Acceptance criteria
- [ ] A description returns images ordered by closeness even when none are labelled.
- [ ] Without the CLIP model the same input returns a keyword ranking and says so; never a blank grid.
- [ ] Combining the description with chips and with "only unlabelled" narrows correctly.
- [ ] Sampling over 3 000 images is disclosed.
- [ ] Empty, loading and error states above render.
- [ ] Flag off ⇒ no Describe chip and `text` behaves as today (ignored).
- [ ] Workspace A cannot see or change workspace B's data (404 for a foreign project; labeler rules hold).

## Notes for the implementer
The free-text *query* stays a filename match (T-060); only the `text` parameter is semantic, so two
different behaviours never share one input silently. Do not add an embedding job here — T-088's bounded
descriptor path and the existing insights cache are enough.
