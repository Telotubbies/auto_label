## User story
As an enterprise admin, I want to grant a role, a person or a directory group access to one folder, so that an
outsourced team can work on one site without seeing the rest of the workspace.

## UX flow (LabelDesk words)
1. This card ships no screen. It ships the shape every later screen reads: a folder has grants, a grant names
   a subject (role, auth group or member) and an access word (`read`, `write`), and an auth group carries the
   identity-provider group names it maps to.
2. A workspace with no rows behaves exactly as today: every member sees every folder. [empty: no grant rows
   → the folder is visible to all members, which is the sentence T-387 renders]
3. `[error]` a duplicate grant (same folder, same subject) is rejected by the unique constraint, not by a check
   in the route, so two tabs cannot create it twice.

## Backend changes
- Models/schema: new module `app/models/access.py` (new):
  `FolderPermission(id, workspace_id FK, folder_id FK folders.id CASCADE, subject_type VARCHAR(8) [role|group|member], subject_id VARCHAR(32), access VARCHAR(8) [read|write], created_by, created)` with
  `UniqueConstraint(folder_id, subject_type, subject_id)`;
  `AuthGroup(id, workspace_id FK, name VARCHAR(80), idp_groups JSON, created_by, created)` with
  `UniqueConstraint(workspace_id, name)`;
  `AuthGroupMember(id, group_id FK auth_groups.id CASCADE, user_id FK users.id CASCADE, source VARCHAR(8) [manual|sso], created)` with
  `UniqueConstraint(group_id, user_id)`.
  Register the module in `models/__init__.py` (`DOMAIN_MODULES` + re-exports). No existing table changes, so
  `schema/__init__.py` needs no block — the tables are created by `Base.metadata.create_all`; a new workspace
  gets none of them and reads as "open".
- Routers: none in this card.
- Services/jobs: `app/services/folder_access.py` (new) — `ACCESS = ("read", "write")`, `SUBJECTS = ("role","group","member")`,
  `validate_grant(subject_type, subject_id, access) -> None` (raises `ValueError`), `grants_for(db, folder_id) -> list`,
  `set_grants(db, ws, folder_id, grants, actor_id)` (replace-all, one transaction), `folder_is_open(db, folder_id) -> bool`.
- Permissions + workspace isolation: every helper takes the workspace id and filters on it; a folder id from
  another workspace resolves to no rows, so the caller's 404 is uniform.
- Secrets/safefetch: none.
- OpenAPI: no (no route yet).

## Tests to write first
pytest — `apps/backend/tests/test_folder_access_model.py`:
- `test_grant_shape_is_validated` — `subject_type="user"` or `access="admin"` → `ValueError`.
- `test_duplicate_grant_is_rejected_by_the_database` — two identical inserts → `IntegrityError` on the second.
- `test_set_grants_replaces_the_whole_set` — three grants written, then two → exactly two rows remain.
- `test_folder_is_open_without_rows` — a folder with no grants reports open, which is today's behaviour.
- `test_a_folder_from_another_workspace_writes_nothing` — folder id of workspace B under A's id → no row, no error.
- `test_flag_off_leaves_the_tables_unread` — flag off → `folder_is_open` returns `True` for every folder.

## Acceptance criteria
- [ ] Grants and groups are stored with one unique row per (folder, subject) and (group, member).
- [ ] A workspace with no rows is indistinguishable from today for every member.
- [ ] Workspace A cannot see or change workspace B's data (a folder id from another workspace can never create or read a grant).
- [ ] Flag off ⇒ the module is never consulted and every folder stays open.
- [ ] `models/__init__.py` registration means `Base.metadata` contains all three tables in a fresh database.
- [ ] Existing-database test: `apply(engine)` on an old schema leaves the tables creatable and all old rows readable.

## Notes for the implementer
Three tables, no more: a grant is (folder, subject, access) — do not add a per-project permission table, projects
inherit their folder. `access` has exactly two values; the "admin" idea is the workspace `workspace.update`
permission, not a folder grant.
