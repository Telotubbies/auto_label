## User story
As a data scientist with a notebook already using an MLflow client, I want experiments to resolve by name
against my workspace, so that `mlflow.set_experiment("qa-sweep")` works before my first `start_run`.

## UX flow (LabelDesk words)
1. **Settings → Integrations → "Log from Python"** — the page shows `MLFLOW_TRACKING_URI=<base>/api/2.0/mlflow`,
   `MLFLOW_TRACKING_USERNAME=<workspace slug>`, `MLFLOW_TRACKING_PASSWORD=<a workspace key>` and a
   four-line snippet. [empty: no key yet — "create a key first", the snippet is greyed] [loading: n/a]
   [error: a key from another workspace — a "Test" button says "this key belongs to a different
   workspace" instead of explaining a 404]
2. **Notebook** — `mlflow.set_experiment("qa-sweep")` creates the experiment on first use and returns its
   id; `experiments/get-by-name` finds it on every later run. [empty: `experiments/search` on a fresh
   workspace returns the project's `default` experiment, never an empty page]
3. **Wrong shape** — an unknown `experiment_id` returns `404 {"error_code": "RESOURCE_DOES_NOT_EXIST",
   "message": "…"}`, so their client raises `MlflowException` rather than failing to parse.
4. **Revoked key** — 401 in the same envelope; the notebook shows "the key used by this session was
   revoked".
5. **Models** — the run the notebook then creates lands in that experiment and is visible in the project's
   run list, badged `External`, with no checkpoint and no version.

## Backend changes
- Models/schema: none — T-914 owns `ExternalRun` (`apps/backend/app/models/mlruns.py`) and T-978 owns
  `experiments`. This card maps an experiment name to a project-scoped experiment row and adds no table.
- Routers: **extend the router T-914 creates**, `app/routers/mlrun_api.py` (Shared, T-914 owns it), with
  `experiments/create|get|get-by-name|search` and `runs/get`'s experiment join. Do **not** create a second
  router under the same prefix: one `/api/2.0/mlflow` mount, one `wire_ctx` dependency.
- Auth (one boundary, ours): T-914's `wire_ctx` already parses `Authorization: Basic base64(user:pass)`
  and takes **pass** as the workspace key, or `Bearer` / `x-api-key`, through `apikeys.resolve_key`. This
  card adds `user == workspace slug` when `user` is present, else 401, and nothing else.
- Services/jobs: `app/services/mlflow_shapes.py` (new) — field mapping only: `experiment_out(exp)`,
  `error(code, message)`, and the `run_out(run)` join that names the experiment. No business logic.
- Permissions + workspace isolation: the key's workspace is the only workspace reachable; an experiment
  or run id from another workspace is `RESOURCE_DOES_NOT_EXIST` (404), never 403.
- Secrets/safefetch: none — the key never appears in a response or a log line.
- OpenAPI: no (wire routes carry `include_in_schema=False`; the `/api/v1` contract is the supported one).

## Acceptance criteria
- [ ] `set_experiment` on a fresh project creates one experiment and every later `get-by-name` resolves it.
- [ ] The snippet page shows the tracking URI, the slug and a key placeholder, never a stored key value.
- [ ] Every failure uses the wire error envelope; a foreign id is `RESOURCE_DOES_NOT_EXIST`.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
