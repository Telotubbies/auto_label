## User story
As a security engineer, I want audit events streamed to our collector with a test event I can search for, so that a
security review passes without a two-team debugging session.

## UX flow (LabelDesk words)
1. `GET /api/ws/{ws}/siem` → `{enabled, endpoint, protocol: "grpc"|"http", headers_masked: {"authorization": "•••"},
   last_status: {ok, at, code} | null}`; a stored header value is never returned.
2. `PUT /api/ws/{ws}/siem` `{enabled, endpoint, protocol, headers}` → 200; `400` names the exact problem
   (`endpoint must be an https URL`, `http protocol needs the /v1/logs path`, `headers must be a JSON object`).
3. `POST /api/ws/{ws}/siem/test` `{endpoint, protocol, headers}` — sends **one** OTLP record with the unsaved form
   values, `audit.action = test_connection`, and answers `{ok, status, latency_ms}`; a failure answers 200 with
   `{ok: false, reason: "connection_refused"|"unauthorized"|"tls"|"path_mismatch"|"timeout"}` (a dead collector is a
   report, not a 5xx).
4. Every save writes `siem.config_updated` with the endpoint host only (never headers).
5. `[empty]` never configured → `{enabled: false, endpoint: null, last_status: null}`.
6. `[error]` a `safefetch`-blocked endpoint (loopback, private range, metadata) → `400 endpoint is not allowed`.

## Backend changes
- Models/schema: new `SiemConfig(workspace_id PK FK CASCADE, enabled BOOLEAN, endpoint VARCHAR(1024),
  protocol VARCHAR(8), headers TEXT, updated FLOAT)` in `app/models/insights.py`; headers stored through
  `services/secretbox.encrypt`.
- Routers: `app/routers/siem.py` (new) — prefix `/api/ws/{ws}/siem`, the three routes above.
- Services/jobs: `app/services/siem.py` (new) — `validate(endpoint, protocol)` (scheme + `/v1/logs` rule + `safefetch.check_url`),
  `build_record(action, payload) -> dict` (OTLP JSON: `resourceLogs[0].scopeLogs[0].logRecords[0]` with
  `attributes: [{key: "audit.action", value: {stringValue}}]`), `send(config, record) -> tuple[bool, str, int]`
  (one `http.client` POST, 5 s timeout, no retry — the test must be fast), `stream(db, ws, action, target, meta)`
  called from `deps.audit` when enabled (fire-and-forget on a bounded background call; a failure updates
  `last_status` and never raises into the request).
- Permissions + workspace isolation: `workspace.update` for read/write/test (owner/admin); the endpoint is
  workspace-scoped and one workspace can never read another's config.
- Secrets/safefetch: `safefetch.check_url` on save and on test; headers encrypted with `secretbox`; the payload
  carries no secret value.
- OpenAPI: yes.

## Frontend changes
- API client: `siemApi.get/put/test` in `src/lib/api/siem.ts` (new); the tab is T-422.
- Feature flag: `task_siem`; off ⇒ all three routes 404 and `audit()` never streams.

## Acceptance criteria
- [ ] A collector can be configured per workspace with protocol, endpoint and masked headers.
- [ ] `Test connection` sends one real record using unsaved values and names each failure cause.
- [ ] Headers are encrypted at rest and never returned; the endpoint is SSRF-checked.
- [ ] Empty, loading and error states above all render (never configured, every named failure).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no routes, no streaming, audit unchanged.

## Notes for the implementer
One attempt, no retry: the test connection is a 30-second check, not a queue. `audit.action = test_connection` is the
searchable key the docs promise — keep that literal.
