## User story
As an integrations engineer, I want to push pixels once, then attach labels later against the returned id,
and have a second writer's stale write fail so that two services never overwrite each other silently.

## UX flow (LabelDesk words)
1. **Developer API** — `POST /api/v1/projects/{project}/upload?image=<https url>` or a base64 body returns
   `{id, annotationGroupVersion}`; the image appears in **Annotate · Unassigned**. [empty: no labels sent
   yet → the returned image is `annotationCount: 0`] [loading: the URL fetch is synchronous; the response
   arrives when the bytes are stored] [error: private URL → 400 with the one public sentence; unreadable
   bytes → the existing 400]
2. **Developer API** — `POST …/images/{id}/annotations` with an annotation file (or raw JSON) attaches
   labels; `addToDataset=true` (default) moves the image to the dataset, `false` keeps its board column.
   [error: a class id from another project → 400, nothing written]
3. **Developer API** — a second write sends the `annotationGroupVersion` it read; a stale value returns
   `409 {"detail": "the labels changed since you read them", "annotationGroupVersion": <current>}` and
   the caller re-reads instead of overwriting. [error: 409 as above]
4. **Editor** — a human edit after an API write follows the same rule: the panel's save carries the
   version and a conflict shows "Someone changed these labels — reload", never a silent overwrite.

## Backend changes
- Models/schema: none — the version is derived (`int(img.updated * 1000)`), so it moves on every write
  without a new column.
- Routers:
  - `apps/backend/app/routers/devapi.py`
    - `POST /projects/{project}/upload` gains `image: str = ""` (public URL, fetched through
      `services/safefetch.fetch_bytes`, 20 MB cap) and `body_base64: str = ""` (exactly one of
      `files`, `image`, `body_base64`; two → 400). Returns `image_out(...)` plus
      `annotationGroupVersion`.
    - `POST /projects/{project}/images/{image_id}/annotations` (new) — multipart `file` (annotation file
      for this image, matched by the stored file name through `importers`) **or** JSON
      `{annotations: [...], addToDataset: bool, expectedGroupVersion?: int}`; validation reuses
      `routers.images._check_ann` and `_check_class_ids`; stale version → 409 with the current value.
    - `GET /projects/{project}/images/{image_id}` returns `annotationGroupVersion`.
  - `apps/backend/app/routers/images.py` — `image_out` gains `annotationGroupVersion`;
    `AnnotationsIn` gains `expectedGroupVersion: int | None`; `save_annotations` compares it before the
    write and raises 409 with the current value; `409` body carries `annotationGroupVersion`.
- Services/jobs: none; smart-polygon/label-assist paths keep working because they write through the same
  `labeling_ops.save_annotations`.
- Permissions + workspace isolation: key scopes (`upload` for the upload variants, `read` for GET,
  `upload` for the attach); `KeyCtx.project(slug)` already 404s a project outside the key's workspace,
  and the image lookup filters `project_id`.
- Secrets/safefetch: `services/safefetch.fetch_bytes` only; no redirects; no key sent.
- OpenAPI: yes — new routes, new fields.

## Acceptance criteria
- [ ] Upload accepts exactly one of multipart files, base64 body or public URL, and returns the id plus
      the version.
- [ ] Annotation files attach against the stored file name; a foreign class id is rejected.
- [ ] `addToDataset` decides the board column, and the default matches today's behaviour.
- [ ] A stale `expectedGroupVersion` is a 409 that names the current version; the row is unchanged.
- [ ] Empty/loading/error states above render (the developer surface is JSON; the editor conflict line is
      the human state).
- [ ] Flag off ⇒ the dev API attach/URL routes 404; the internal annotation save is unchanged.
- [ ] Workspace A cannot see or change workspace B's data (the key's project lookup 404s; a foreign image
      id is not found for that key).

## Notes for the implementer
`annotationGroupVersion` is a timestamp in milliseconds derived from `Image.updated`; do not add a
counter column. It changes on every annotation write because `set_annotations` bumps `updated` — verify
that in the test rather than assuming it.
