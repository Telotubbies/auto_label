## User story
As an operator, I want to install one extra package to support a new model family, so that adding a runtime is an install and not a fork of the API.

## UX flow (LabelDesk words)
1. **Settings → Model runtimes** — the installed families are listed with their version, their state and the models that need them. [empty: "Only the built-in families are installed."] [loading: three skeleton rows] [error: a family that raises on import is listed as Failed with its message, and the rest of the page still renders]
2. **Models** — a model whose family is not installed shows "Runtime <family> is not installed on this server" with the export alternative, instead of failing at predict time.
3. **Nothing is installed silently** — the page says which package provides a family, so an operator knows what to install.

## Backend changes
- Models/schema: none.
- Routers: `GET /api/ws/{ws}/families` (new, `ws_ctx`) returns `{"families": [{"id", "version", "state", "models", "reason", "package"}], "legacy": 1}` in a fixed order: built-ins first, then discovered ones sorted by id.
- Services/jobs: `apps/backend/app/adapters/plugins.py` (new) — `discover() -> list[dict]` reading `importlib.metadata.entry_points(group="labeldesk.adapters")`, importing each in a `try/except Exception` that records the failure instead of raising, and registering through the existing `register()` (`apps/backend/app/adapters/base.py:46`). `apps/backend/app/adapters/__init__.py` calls `discover()` once at import, after the six built-ins. A plugin's `describe()` (T-932) is validated on registration: a family missing it is rejected with its name.
- Permissions + workspace isolation: `ws_ctx` and `workspace.read`; the payload carries family ids and counts only, no project names.
- Secrets/safefetch: none.
- OpenAPI: yes — `python tools/export_openapi.py`, `npm run gen:api-types`.

## Acceptance criteria
- [ ] Installing a package that declares the entry-point group adds its family with no code change in the repo.
- [ ] A plugin that raises on import is listed as Failed and never prevents startup.
- [ ] A model whose family is missing says so on Models, with the export alternative.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged — no flag here: with no plugin installed the page lists exactly the six built-ins and the rest of the product is unchanged.

## Notes for the implementer
Overlap: none. Do not build a marketplace, a signature check or a sandbox: the group name is the whole contract, and anything stronger is a second product.
Discovery must not run per request — module import time only, so a bad plugin is a startup-time failure that is reported, not a per-request one.
