## User story
As a project manager, I want to describe each class in words and set its own strictness, so that "helmet" and "person" do not have to share one prompt and one threshold.

## UX flow (LabelDesk words)
1. **Annotate board → Auto Label → Class prompts** (`AutoLabelDialog.tsx:201-233`) — each selected class becomes a row with the class chip, a description field defaulting to the class name, and a threshold slider `5–95%` defaulting to the batch value. [empty: no classes → the existing "Add classes first" panel] [loading: classes still loading → the row list is a skeleton, the Run button disabled]
2. **Description rules** — the description is what the model searches for, the class name is what gets saved. Two classes with the same non-empty description show an inline warning on both rows and disable Preview/Run with "Two classes share a description — make them different." Empty description falls back to the class name.
3. **Model that ignores descriptions** — a trained model greys the description fields with the hint "A trained model uses its own classes"; thresholds stay editable.
4. **Threshold semantics** — the slider is per class; the API receives every class's value; predictions below their class threshold are dropped *after* the model call, so one call still covers the batch. A model that returns everything at full confidence (VLM) hides its sliders with the existing note.
5. **Preview confidences** — under the thumbnail strip, a list of the selected sample's predictions: class chip, a `92%`-style chip per detection, grouped as "helmet 92, 88, 71". A sample with no predictions shows the existing "No annotations found" line. [error: a class threshold of 95% on every class → the preview legitimately empties; the copy says "No detections passed the thresholds" rather than blaming the prompt]
6. **Carried into the job** — the same values are sent with the run, and the summary sheet (T-132) echoes them as "threshold 40% · helmet 55%, vest 40%".

## Backend changes
- Models/schema: none — job params are JSON (`Job.params`, `handlers/training.py:201`).
- Routers: `POST /autolabel` and `POST /autolabel/preview` (`training.py:460,474`) accept `class_prompts: dict[str,str]` and `class_confidence: dict[str,float]`; `400` for an unknown class id, a threshold outside `0.01–0.99`, or two classes with the same trimmed description. `GET /autolabel/preview` rows keep `confidence` on each annotation.
- Services/jobs: `adapters/refine.label_image` (`refine.py:121`) resolves `name → description` for SAM 3.1 and VLM prompts (`prompt` still wins when set) and post-filters predictions whose own class threshold is higher than their score; the adapter is called with the lowest threshold in the set so nothing is lost before filtering.
- Permissions + workspace isolation: `c.need("reviewer")` unchanged; class ids are validated against `c.project.id`, so another project's class id is 400 and a foreign project slug is 404.
- Secrets/safefetch: none.
- OpenAPI: yes — two request bodies.

## Acceptance criteria
- [ ] Each selected class has its own description (defaulting to the class name) and its own threshold, and both reach the job unchanged.
- [ ] Two classes with the same description block Preview and Run with an inline warning on both rows.
- [ ] A trained model ignores descriptions, keeps thresholds, and says why the fields are disabled.
- [ ] The preview lists each detection's confidence grouped by class, and an emptied preview blames the thresholds, not the prompt.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: an option inside the existing dialog.
- [ ] Keyboard-only path: board → Auto Label → Tab through class rows → type a description → arrow the slider → Preview.

## Notes for the implementer
Confidence filtering happens after the call, never by running the model once per class — the current job spends one credit per image and must keep doing so. Trim and case-fold descriptions before the duplicate check so "Red helmet" and "red helmet " collide.
