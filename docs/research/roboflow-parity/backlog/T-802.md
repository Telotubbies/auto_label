## User story
As an ML engineer on the fourth iteration of a class that will not learn, I want to give a range per field and a trial budget, so that the machine finds the learning rate instead of me guessing it five times.

## UX flow (LabelDesk words)
1. **Train** (`/:ws/:project/train`) — a `Sweep` submission carries one row per parameter (fixed value, list, or min/max), a metric to maximise, and a cap in trials or minutes. [loading: the estimate is recomputed on each keystroke, so the price is never stale] [error: a space with no varying field ⇒ 422 "A sweep needs at least one parameter with more than one value."]
2. **Estimate** — the response returns the trial count, the per-trial estimate and the total credits; a space over the cap is refused with the numbers.
3. **Start** — one job per trial is queued, each carrying its own configuration fingerprint; the budget is metered before the first trial runs.
4. **Pruning** — a trial whose best metric is below the incumbent's by the margin after the patience window is stopped at the epoch boundary and marked `pruned`, never `failed`. [error: the budget runs out ⇒ the sweep ends cleanly, the best trial is kept and the remainder is refunded]
5. **Winner** — `Make this the run` promotes one trial's model to the run of record; the other trials stay readable.

## Backend changes
- Models/schema: `Sweep` (`id, workspace_id, project_id, version_id, space(JSON), metric, budget_trials, budget_minutes, status, best_model_id, created_by, created, finished`) in a new `app/models/sweeps.py`; each trial is an existing `Job(kind='train')` carrying `params.sweep_id` and its own `options`.
- Routers: new `app/routers/sweeps.py` — `POST …/sweeps` `{version_id, variant, space, metric, budget_trials, budget_minutes}` → `{sweep, trials:[job_out], estimate}` (422 over the cap), `GET …/sweeps`, `GET …/sweeps/{id}`, `POST …/sweeps/{id}/winner` `{trial_id}`.
- Services/jobs: `app/services/sweeps.py` (new) — `space_size(space)` (capped at 20), `sample(space, n, seed=42)` deterministic, `estimate(...)` reusing `_gpu_estimate`, `start(db, ws, project, body, user)`, `prune_check(metric_value, incumbent, epoch) -> bool`; `handlers/training.py` consults `prune_check` per epoch for a job with `sweep_id` and raises `Cancelled` with `result.pruned` set.
- Permissions + workspace isolation: `admin` to start a sweep and to promote a winner; a version, sweep or trial from another workspace answers 404.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate both generated files.

## Tests to write first
pytest — `apps/backend/tests/test_param_sweep.py`:
- `test_space_sampling_is_deterministic` — the same space and seed twice → identical option sets.
- `test_space_over_twenty_trials_is_422` — `epochs` 1..50 → 422 naming the cap.
- `test_estimate_matches_the_trial_count` — three sampled trials → `estimate.trials` 3 and `estimate.credits` = 3 × the train cost.
- `test_start_queues_one_job_per_trial` — start → N `train` jobs, each with `sweep_id` and its own options.
- `test_a_losing_trial_is_pruned_not_failed` — a metric 40 % below the incumbent after the patience window → job `cancelled` with `pruned` true.
- `test_budget_exhaustion_keeps_the_best_trial` — budget cut after two trials → sweep `done`, `best_model_id` set, the remainder refunded.
- `test_cross_workspace_sweep_is_404` and `test_flag_off_is_404`.

## Acceptance criteria
- [ ] A sweep names one space, one metric and one budget, and returns the trial count and the price before anything runs.
- [ ] Each trial is an ordinary train job with its own stored configuration, visible in the run ledger.
- [ ] A losing trial is pruned at an epoch boundary and marked pruned, never failed.
- [ ] Budget exhaustion ends the sweep cleanly with the best trial kept and the remainder refunded.
- [ ] Empty, loading and error states above all render as API states: a one-value space is a named 422, a sweep with no trial yet returns an empty trial list.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no sweep routes and a train submission creates exactly one run.

## Notes for the implementer
Owner-hold: BEYOND §4 names this as a non-goal; do not schedule until the owner overrules it. Sample the space with a fixed seed and cap it at 20 trials: an uncapped search on a metered GPU is how a demo becomes an invoice. Pruning needs three consecutive epochs below `incumbent × 0.6` before it stops a trial, so one noisy epoch never kills a run that would have recovered.
