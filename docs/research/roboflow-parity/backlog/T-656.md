## User story
As a site-safety annotator working through a 30-minute clip, I want to type one phrase and get one track per instance with an id that survives a re-run, so that a false track is deleted once instead of two hundred boxes frame by frame.

## UX flow (LabelDesk words)
1. **Video** (`/:ws/:project/videos`) — "Track a concept" takes a text prompt ("person without helmet") or a seed box, plus a frame to start from. [error: "SAM 3.1 is not available on this worker" before any frame is read] [empty: a video whose frames are still extracting says so and disables the button]
2. **Running** — `[loading: "Tracking frame 120 of 1,800…"]`; the job is cancellable through the existing job tray.
3. **The result** — one track per instance across up to 120 frames per call, each annotation carrying `trackId`, `keyframe` on the first frame and a `score`; an unmatched instance starts a new track rather than stealing an id.
4. **Re-run** — a re-run keeps human edits: a frame with a keyframe or a human edit is never overwritten, exactly like `track.merge_track` today.
5. **Deleting a track** — one call removes every interpolated frame of that track and leaves keyframes alone.

## Backend changes
- Models/schema: none — `trackId` and `keyframe` already live in the annotation JSON and `lib/types.ts` already declares them.
- Routers: `POST /api/ws/{ws}/projects/{project}/videos/{vid}/track-concept` (`prompt` or `seed_annotation_id`, `start_frame`, `direction: "forward"|"backward"`, `frames` 1–120) → 202 job; `POST .../videos/{vid}/tracks/{track_id}/delete` → `{"removed": n}`; both behind the existing `require_flag("task_22")`. 400 when neither prompt nor seed is given, 409 when SAM is unavailable, 404 for a track id not in this video.
- Services/jobs: `services/concept_track.py` (new) — `track_concept(frames, prompt_or_seed, sam_text, direction) -> list[dict]` running `segment.sam_text` per frame, matching each new box to the previous frame by greedy IoU ≥ 0.5 (new id above the threshold), `ids(video_id, seq)` minting `tc<seq>`; job kind `track_concept` handled by `run_track_concept(job)` in `handlers/streams.py`, which writes through `set_annotations` and `track.merge_track`.
- Permissions + workspace isolation: `project.annotate` to start, `_assigned` semantics preserved so a labeler only tracks their own frames; the video id is checked against `c.project.id` (404), and the route is flag-gated like every other video route.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate (`python tools/export_openapi.py`, `npm run gen:api-types`).

## Acceptance criteria
- [ ] One prompt or seed produces one track per instance with a stable id, a keyframe and a per-frame score across up to 120 frames.
- [ ] A re-run never overwrites a human edit or a keyframe, and a track can be deleted in one action.
- [ ] A worker without SAM refuses with 409 before reading a single frame.
- [ ] Empty, loading and error states above all render: frames still extracting, a job in progress, an unavailable model.
- [ ] Workspace A cannot track or delete tracks in workspace B's video (404 on a foreign video or track id).
- [ ] Flag off (`task_22`) ⇒ the routes are 404 and no track data is written.

## Notes for the implementer
Match by IoU on the previous frame with a 0.5 floor and never let two live tracks claim the same box — a wrong merge is worse than a short track. `tc<seq>` ids are minted per video and per run, so deleting and re-running produces a clean set instead of resurrecting a half-deleted one. Keyframes are the reviewer's work: they win, always.
