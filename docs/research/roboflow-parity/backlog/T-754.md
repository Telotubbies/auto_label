## User story
As a DPO preparing for an audit, I want the register as a table I can correct in place and a file I can hand over, so that answering a questionnaire stops meaning rebuilding the same facts by hand.

## UX flow (LabelDesk words)
1. **Compliance → `Processing register`** (`/:ws/compliance`) — the second tab. One row per project with the auto-filled facts (retention, face blur, biometrics, images) and editable `Purpose`, `Data categories`, `Recipients`, `Cross-border`, `Next review`. [loading: the shipped skeleton rows] [empty: "No projects yet — the register fills itself from your first project." / "ยังไม่มีโปรเจกต์ — ทะเบียนจะเริ่มจากโปรเจกต์แรกของคุณ"] [error: "Could not load the register." + **Try again**]
2. **An incomplete row** — a `Badge` reads `"Purpose not recorded"` in the warning tone, and the row's editor opens on that field with the hint `"Why this footage is collected, in your own words."` / `"เหตุใดจึงเก็บภาพนี้ ในถ้อยคำของคุณเอง"`
3. **A biometrics project with no basis** — the row prints `"Biometrics is on and no legal basis is recorded."` and one line of explanation: `"Uploads are refused until a basis is written here and in the project's privacy settings."` with a link to `/:ws/p/:project/settings?tab=privacy`.
4. **`Add transfer`** — a `Modal`: destination, recipient, basis (`Select`, empty by default with "Choose a basis"), the signed date, and a document name. Saving with no basis is refused inline: `"Choose the basis your adviser recorded for this transfer."`
5. **`Consents`** — a section under the table: subject label, purpose, given date, and a `Withdraw` action that writes a second row and reads `"Withdrawn 17 Nov 2026 — the original record stays."`
6. **`Download CSV`** and **`Print`** — the CSV is the shipped download helper; `Print` opens the browser's print dialog on a print stylesheet so an auditor gets a PDF with the workspace name and the date in the header, and no glass, no sidebar, no buttons.

## Acceptance criteria
- [ ] The register shows one row per live project with the auto-filled facts and the editable fields, and saves a row in place.
- [ ] A missing purpose and a biometrics project without a basis are flagged, with the refusal explained and a link to the settings that fix it.
- [ ] A transfer is added with an explicitly chosen basis; a consent withdrawal adds a row and leaves the original.
- [ ] Empty, loading and error states above all render: no projects, the skeleton, the load error with **Try again**, and the inline "choose a basis" refusal.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — a 404 renders the neutral sentence.
- [ ] Flag off ⇒ no register tab and no register read; the Compliance page shows Requests only.

## Notes for the implementer
Owner-gated: the purposes, categories, recipients and bases printed here are the customer's declarations, and LabelDesk must not suggest one — the basis `Select` starts empty by design (INDEX §4.3). Print, do not generate a PDF: the repository has no PDF library (BEYOND §5 lists that gap), and a browser print with a print stylesheet produces the same page an auditor accepts without adding a dependency. Keep the CSV column order identical to the table's, or the two documents will disagree in front of the auditor.
