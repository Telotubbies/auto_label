## User story
As the reviewer of any area-4 PR, I want a version's immutability, numbering, train-only augmentation
and cached export pinned so that a recipe/preview/export card cannot make an existing version change
after the fact or rebuild an artefact that already exists.

## UX flow (LabelDesk words)
1. **Versions** — rows are newest-first with number, name (or `v{n}`), counts, created time and the
   exports/trainings that came from them. [empty: create prompt] [loading: generating row with progress]
   [error: failed row keeps the reason]
2. **Wizard** — five numbered steps (Source, Train/Test Split, Preprocessing, Augmentation, Create);
   each step is reachable from the strip; step 1 prints the approved-image count; step 2 blocks a total
   that is not 100.
3. **Generate** — the recipe (resize/grayscale/contrast), the splits and the per-image labels are frozen
   into the version; later edits to the project never reach it.
4. **Augmentation** — copies are written under `train/` only; valid and test keep their source images.
5. **Export** — the format list is filtered by project type; the same request twice reuses the existing
   artefact; a version still generating answers 409.
6. **Analytics** — class balance per split, dimension/ratio insights, and a version-to-version diff are
   read from stored aggregates with an explicit staleness flag.

## Notes for the implementer
Do not re-assert the hash/leakage/cache-concurrency rules: `tests/test_versioning_v2.py` owns them
(`test_same_inputs_same_hash`, `test_cached_export_built_once`,
`test_cached_export_concurrent_builders`). This card adds only what that file does not cover.
The 409 for a generating version is a real behaviour (`app/routers/versions.py:118-119`), not a plan.
`versioning.generate` writes `recipe.json` and `manifest.json` under `DATA_DIR/versions/<id>`; point the
test at the shared `DATA_DIR` from `conftest.py` and clean the version directory in teardown — the same
pattern `test_versioning_v2.py:56-58` uses.
Migration-sensitive HAVE facts: version `number` is `max+1` per project and never reused
(`versions.py:65`); the fallback label is `v{n}` (`versions.py:31`); the manifest is the frozen truth,
so no later card may rewrite `items`/`splits`/`version_hash` in place; augmentation runs only when
`split == "train"` (`services/versioning.py:170-174`); export dedupe keys on
`(project, version_id, format)` with status queued/running/done (`versions.py:122-126`).
