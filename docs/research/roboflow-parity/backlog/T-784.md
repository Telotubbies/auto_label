## User story
As the person asked "where did this model come from" during an incident, I want the run node to carry its dataset, its configuration and everything it feeds, so that I can answer and rebuild from the same screen instead of reading the worker log.

## UX flow (LabelDesk words)
1. **Insights → Lineage** (`/:ws/:project/lineage`) — click a run node; the side panel shows version number, image and annotation counts, the version hash, the stored configuration, the evaluation summary, and every downstream consumer (aliases, streams) with its current state. [empty: a node with no downstream consumer says "Not deployed" instead of rendering nothing] [empty: a run older than the stored configuration says "This run predates stored configurations."]
2. **Re-run with these inputs** — seeds the Train form from that version and configuration and names the source run above the form. [loading: the button shows its pending state while the configuration is fetched] [error: the configuration cannot be read ⇒ the button is disabled with "The configuration for this run is unavailable."]
3. **Open the exact images** — jumps to the dataset grid filtered to that version's frozen manifest, so the pictures are the ones the model saw. [empty: a version whose files were deleted shows the grid's own empty state, not a blank page]
4. **A failed run node** — the same panel, with the failure sentence where the evaluation would be and the retry action from T-795.
5. **A node with no version** (a model imported outside the queue) — says "No dataset version recorded." and hides both actions.

## Backend changes
- Models/schema: none — the payload grows from rows that already exist.
- Routers: none new; `GET …/insights/lineage` returns the richer node.
- Services/jobs: `services/insights_lineage.py` — the run node gains `counts: {images, annotations, epochs}`, `metrics: {AP, AP50}`, `detail: {config, version_hash, version_number, consumers:[{kind,label,state}]}`; a model node gains the same `consumers` list; alias consumers come from `DeploymentAlias`/`DeploymentEvent`, stream consumers from the existing edges.
- Permissions + workspace isolation: unchanged (`project.review` via the insights router); a project id from another workspace answers 404 as today.
- Secrets/safefetch: none — no signed URL is added in this card.
- OpenAPI: no — no route or schema change.

## Tests to write first
pytest — `apps/backend/tests/test_lineage_inputs.py`:
- `test_run_node_carries_config_and_version_counts` — a trained model with a stored config → the run node's `detail.config.epochs` matches and `counts.images` equals the manifest's source images.
- `test_consumers_list_alias_and_stream_with_state` — promote the model to production and attach a stream → consumers name `production` and the stream, each with a state.
- `test_node_without_consumers_says_not_deployed` — a model with no alias and no stream → `consumers` is `[]` and the payload carries no fabricated row.
- `test_other_workspace_project_is_404` — workspace B reads A's lineage → 404.
- `test_flag_off_keeps_the_old_payload` — flag off → the node has no `config` key and no `consumers` key.
node — `apps/frontend/tests/lineage-inputs.test.mjs`:
- `test_can_rerun_needs_a_version_and_a_config` — a run node with both → true; missing either → false.
- `test_rerun_href_seeds_the_train_form` — `rerunHref('acme','parts',{id:'run:1',detail:{}})` equals `/acme/parts/train?fromModel=1`.
- `test_consumer_rows_label_not_deployed` — an empty consumer list renders one row with the `not deployed` label.
- `test_images_href_targets_the_version_filter` — a version node produces `/acme/parts/browse?version=v9`.

## Acceptance criteria
- [ ] A run node shows its version, image and annotation counts, version hash, configuration, evaluation summary and downstream consumers.
- [ ] A node with no consumer says "Not deployed"; a run without a stored configuration says so instead of showing `{}`.
- [ ] Both actions work: re-run opens Train prefilled from that run, and open-images lands on the frozen version's grid.
- [ ] Empty, loading and error states above all render: a missing configuration disables the re-run action with its reason.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the panel renders today's counts and metrics only, with no actions.

## Notes for the implementer
The image count on a run node is the version's manifest source images (an augmented copy is not a new picture) — reuse `_version_edges`, do not count rows. Consumers are read from the alias and stream tables at request time, never copied into the node at build time, so a later promotion is visible without a rebuild.
