## User story
As a reviewer, I want one drop target that tells me exactly what will happen before I spend upload time
and exactly what happened after, so that "I dropped 936 and only 120 saved" never happens again.

## UX flow (LabelDesk words)
1. **Upload** — one large drop zone (drag, **Select files**, **Select folder**, **Use camera** when
   `task_67` is on, **Add from URL** when `task_66` is on). [empty: the zone shows the three accepted
   shapes — images, folders, one .zip — and a "Try the 40-image demo set" secondary link]
2. **Upload** — after picking, the pre-flight card states the outcome before the request:
   "40 images · 3 duplicates will be skipped · 0 too large", plus "1 archive (18,400 files) will import
   in the background" when a big zip is present. Each row of the first 300 can be removed with a ×.
   [loading: per-row hashes resolve in place, counts tick up] [error: an unsupported extension is named
   in the line "2 files ignored (psd, gif)" and excluded from every count]
3. **Upload** — batch name (defaults to `2026-11-17 · shift`), split radio chips (Auto 80/10/10 ·
   Use folder names · All train), tags, and the replace-annotations switch from T-063.
   [error: zero importable files → the primary is disabled with the reason in the hint]
4. **Upload** — confirming shows one progress bar for the inline chunk loop; an archive over the
   threshold switches to "Archive import started — follow it in the job tray" and the page is free.
   [loading: "Uploading 62%" with a determinate bar]
5. **Upload result sheet** — "Added 37 · duplicates 3 · failed 0" with format line ("Recognised: COCO
   JSON"), class renames, orphan label files, the grouped failure reasons, and one primary
   **Send to Annotate** plus "View dataset". [error: "Added 37, failed 3 — see reasons" with a
   retry-failed-files action]

## Backend changes
- Models/schema: none.
- Routers: none new — the page consumes `POST P/upload` (T-063 field), `POST P/uploads/archive` and
  `POST P/uploads/from-url` (T-066).
- Services/jobs: none.
- Permissions + workspace isolation: every call goes through `project_ctx`/`project.upload`; a foreign
  project is a 404 and the page renders "Project not found" without leaking the name.
- Secrets/safefetch: none here (the URL fetch is T-066's `safefetch` path).
- OpenAPI: no.

## Acceptance criteria
- [ ] The pre-flight line names images, skipped duplicates, too-large files and ignored extensions before
      any bytes leave the browser.
- [ ] A big archive starts a job and frees the page; a small batch still shows one progress bar and a
      result sheet.
- [ ] The result sheet distinguishes added / duplicates / failed, names reasons and offers the next step
      ("Send to Annotate").
- [ ] The replace-annotations switch sends its field and its confirmation names the affected count.
- [ ] Empty, loading and error states above render (empty drop zone, per-row resolving, failure sheet).
- [ ] Flag off (all four) ⇒ the page renders and behaves exactly as today.
- [ ] Workspace A cannot see or change workspace B's data (404 for a cross-workspace project id).
