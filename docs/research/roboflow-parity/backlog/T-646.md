## User story
As a QA lead, I want to pick a rubric, run it on a filtered slice or the suspect queue, and read one row per label with a reason I can act on, so that a complaint is answered by evidence instead of by another full read of the images.

## UX flow (LabelDesk words)
1. **Project → Review → Judge** (`/:ws/:project/qa?tab=judge`) — the tab appears beside Review queue and Consensus for anyone with `project.review`. [empty: "No judge run yet — pick a rubric and a scope"]
2. **Rubric** — three default questions, each editable and removable down to one; "Add a question" stops at five. [error: an empty question is refused under the field]
3. **Scope** — "Current filter", "Selection" (disabled at zero selected images) or "Suspect queue"; a limit field defaults to 200 and caps at 500.
4. **Run** — `[loading: "Judged 120 of 500" with a progress bar]`, `[error: "vLLM not reachable at …" plus Try again]`; the panel keeps the previous run's table dimmed while a new one runs.
5. **Results** — verdict (`pass`/`fail`), reason, score, "Open in editor"; a filter to failures only, and a per-class summary line. A human confirm/dismiss column stays separate from the judge's verdict.
6. **Flag off** — no tab and no request.

## Acceptance criteria
- [ ] A reviewer edits the rubric, picks a scope and runs it; the panel shows progress and then one row per label with verdict, reason and score.
- [ ] Failures can be filtered and opened in the editor; a human confirm/dismiss is visually separate from the judge's verdict.
- [ ] An unreachable model shows the error with Try again and keeps the previous run readable.
- [ ] Empty, loading and error states above all render, including no run yet and a run with nothing in scope.
- [ ] Workspace A cannot read workspace B's runs: every id comes from this project's own list response.
- [ ] Flag off ⇒ no tab, no request, and the Review page is exactly as today.

## Notes for the implementer
Score is not a percentage of correctness — show it as a 0–1 bar on the viridis ramp and keep the reason beside it, because the sentence is what a reviewer acts on. Never auto-dismiss a box from this table: a judge disagreement is information, and the dismiss action lives in the editor.
