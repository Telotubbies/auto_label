## User story
As a reviewer, I want to record the answer a good model would give for an image, so that a judge can be graded
against a person instead of against its own opinion.

## UX flow (LabelDesk words)
1. **Data → Evaluation sets → a set → Expected answers** — a column beside each row: the question asked, a text
   box for the accepted answer, and a second for "must not say". Rows come from the set's images. [empty: rows
   without an expectation show *Add expected answer* and the header states "88 of 120 have expected answers"]
2. **Fill from a review** — on a suspect row or in the Playground, *Save as expected answer* writes the human
   answer back to the set row it came from, with a toast naming the set. [error: "this image is not in an
   evaluation set" with the link to pin one]
3. **Use** — judges that need a reference light up for rows that have one (T-960's `needs_reference`), and the
   drawer prints "n = 88 have expected answers".
4. **Change** — editing an expectation on a pinned set writes a new set version (T-946's digest is unchanged,
   a `revision` counter moves) so an old score still explains itself. [empty: a set with no expectations shows
   the column header and nothing else, not a broken table]

## Backend changes
- Models/schema: new table `SetExpectation(id, eval_set_id FK ondelete=CASCADE, image_id, question TEXT NULL,
  expected TEXT, forbidden TEXT NULL, source, revision, created, created_by, updated)` unique `(eval_set_id,
  image_id)` in `apps/backend/app/models/evaluation.py`; `EvalSet` gains `revision INT DEFAULT 0` (one entry in
  a new `VERSIONS`-style block? no — `EvalSet` is created by T-946, so the column is added there and this card
  only bumps it).
- Routers: `GET {P}/evaluation-sets/{id}/expectations` → `{rows: [{image_id, file, question, expected,
  forbidden, source}], counts: {with_expected, total}}`; `PUT {P}/evaluation-sets/{id}/expectations/{image_id}`
  body `{question?, expected, forbidden?}` → the row, and `revision` + 1 on the set; `DELETE` → removes the
  expectation (the row stays). 400 for an empty `expected`, an image not in the set, or more than 2,000
  characters; 404 for a foreign set.
- Services/jobs: `apps/backend/app/services/evaluation_sets.py` gains `expectations(db, set_id)`,
  `put_expectation(...)`, `from_review(db, project, image_id, answer, user_id)` (finds the sets containing the
  image and writes the expectation, or raises `NotInASet`). No job.
- Permissions + workspace isolation: read `project.review`, write `project.annotate` (a reviewer's act), and a
  labeler may write only for images assigned to them (same rule as the annotation write path); foreign ids 404.
- Secrets/safefetch: none. Dependency: none added (no `mlflow-skinny`), so no
  `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] A reviewer can record an accepted answer per image in a set, and the counts header states coverage.
- [ ] A save from a review writes to every set containing that image, or names the absence of a set.
- [ ] Editing an expectation bumps the set's revision and never rewrites a stored score.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
