## User story
As an ML engineer, I want to switch the yardstick and see which scores are out of date, so that the comparison I ship is on the metric my task is judged by.

## UX flow (LabelDesk words)
1. **Model insights → Compare** (`/:ws/:project/model-insights?tab=compare`) — the metric selector sits above the charts, defaulting by task; the scatter's axes and the frontier follow it. The selected metric is in the URL (`&metric=map75`).
2. **Speed vs accuracy** — the scatter keeps latency on x and the chosen metric on y with the unit in the axis name; hollow markers are dominated models; clicking a point opens its card (existing behaviour).
3. **Update panel** — "2 models need an evaluation update" with *Run* per row and *Update all*; queued/training models appear as "waiting for training". [empty: all current ⇒ no panel] [loading: the panel shows two skeleton rows] [error: "Could not start the evaluation" + reason, the row keeps its state]
4. **Next-step states** — before any result the tab shows one of three blocks with a single primary: *Train a model* (no models at all), *Run evaluations* (models, none evaluated), *Update evaluations* (all stale). [empty: fewer than two comparable models keeps today's "Not enough evaluated models" with the same link]
5. **No evaluation access** — a viewer without `project.models` sees one sentence: "Comparing models needs the Models permission — ask a project manager." instead of an upgrade prompt (there is no plan gate here).
