## User story
As an ML engineer on a segmentation project, I want pixel IoU and boundary AP beside the box AP, so that "the mask is sloppy but the box is right" is measurable instead of argued about.

## UX flow (LabelDesk words)
1. **Model → Evaluation → Mask quality** — a card that appears only for instance-segmentation models: headline *mIoU* with the pixel threshold named, then pixel precision / recall / F1, then *boundary AP* with its one-line definition ("matches mask outlines rather than filled areas"), then a per-class IoU table.
2. **Pixel confusion** — a compact matrix in pixel counts (rows ground truth, columns prediction) with the same class colours as the box matrix; hovering reads "12,480 px".
3. **Units are named** — every number carries "px" or "%"; the card's subtitle states "Counted over the evaluation split at confidence 0.45 and IoU 0.5 for matching."
4. **A detection model** — the card is absent (not empty).
5. **An old evaluation** — a segmentation eval stored before this card shows "Mask quality was not measured for this run — re-evaluate to add it." with the T-283 entry. [empty: no masks in the ground truth ⇒ "This split has boxes but no masks — pixel metrics need mask labels."]

- **States** — [empty: a split with no masks stores `pixel: null` with the note the UI renders]. [loading: the card is absent until the evaluation payload carries `pixel`] [error: a rasterisation failure degrades one number, never the whole evaluation].

## Backend changes
- Models/schema: none — results live in `metrics.eval.pixel` and bump `METRICS_VERSION` to 3.
- Routers: none (the eval payload is read through the existing model and insights routes).
- Services/jobs: `services/evaluate.py` — for `task == "segment"`, after the per-class block compute `pixel = _pixel_metrics(records, names, f1_best["conf"])`:
  - rasterise each GT mask from its COCO segmentation (`mask_utils.frPyObjects` + `merge`, or decode compressed RLE) and each prediction mask from its polygon (`_poly_mask`), at the image's own size;
  - per class: `intersection`, `union`, `gt_px`, `pred_px` counted with numpy on the flat arrays (no per-pixel Python loop);
  - `mIoU` = mean of per-class IoU over classes with `gt_px > 0`; `pixel_precision/recall/f1` from summed TP/FP/FN at the same threshold; `confusion_px` = a `(n+1, n+1)` int matrix where the last row/column is background;
  - guard: skip an image (and count it) when rasterisation raises; report `skipped_images`.
  - boundary AP: derive each mask's ring with the same rasteriser (`ring = mask & ~erode(mask)` using numpy shifts, no scipy), encode rings as RLE (`mask_utils.encode`) and run one extra `COCOeval(..., "segm")` pass; store `pixel.boundary_ap`, `pixel.boundary_ap50` and `pixel.boundary_basis` ("IoU 0.5 on 1-px rings"). A failure to build rings degrades to `boundary_ap: null` with `boundary_note`, never a failed evaluation.
- Permissions + workspace isolation: unchanged (`project.models` for the eval payload).
- Secrets/safefetch: none.
- OpenAPI: yes — `eval.pixel` in the model and insights payloads (regenerate both files).

## Tests to write first
pytest — `apps/backend/tests/test_eval_pixel.py`:
- `test_two_perfect_masks_give_miou_one` — a 100×100 GT mask and an identical prediction → `mIoU == 1.0`, precision/recall 1.0.
- `test_half_overlap_gives_the_expected_iou` — two 100×100 squares overlapping by half → IoU ≈ 0.333 (±0.01) and F1 ≈ 0.5.
- `test_pixel_confusion_counts_add_up` — `sum(confusion_px.flat) >= gt_px + pred_px - tp` and the diagonal equals `tp`.
- `test_a_class_without_gt_masks_is_excluded_from_miou` — predicted-only class → not in the mean, listed with `gt_px == 0`.
- `test_a_detection_evaluation_has_no_pixel_block` — `task="detect"` → `"pixel" not in ev`.
- `test_an_unrasterisable_mask_is_skipped_and_counted` — a degenerate polygon → `skipped_images == 1`, no exception, other classes still measured.
- `test_boundary_ap_is_lower_than_mask_ap_on_a_ragged_mask` — a GT square versus a prediction with a ragged edge → `boundary_ap < mask AP` and both in `[0, 1]`.
- `test_boundary_ap_is_null_when_rings_cannot_be_built` — stub the ring builder to raise → `boundary_ap is None`, `boundary_note` non-empty, the rest of the card still present.
- `test_metric_version_is_bumped` — a fresh segmentation eval stores `metric_version == 3` so T-283 flags older ones stale.
node — none: no frontend surface in this card.

## Acceptance criteria
- [ ] A segmentation evaluation stores mIoU, pixel P/R/F1, per-class IoU, a pixel confusion matrix and a boundary AP.
- [ ] A detection evaluation stores none of it and the payload is unchanged for detection.
- [ ] A mask that cannot be rasterised, or a ring that cannot be built, degrades that one number instead of failing the evaluation.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ not applicable: this card ships no flag; the payload is additive and old clients ignore it.

## Notes for the implementer
There is no semantic-segmentation project type in this repo (`PROJECT_TYPES`), so "mIoU" here means *pixel IoU over the masks of an instance-segmentation evaluation* — say so in the card copy, do not invent a project type. Count with numpy on flat arrays; a per-pixel loop over a 4 MP split will time out the worker.
