## User story
As a workspace admin, I want a standing join link per role and invites that expire visibly, so that I can add a shift of labelers without typing ten addresses.

## UX flow (LabelDesk words)

*Screen this contract serves:* Settings → Members → **Join links** (the panel is T-039's card; this card owns the
contract behind it). States the panel must show: no link for a role → "No link yet · Create one"; creating →
button busy, form disabled; a rotated link visited by a teammate → the 410 sentence on a plain page with a
`Request a new link` action; an expired invite → the 410 sentence and `Ask an admin to resend`.

1. **Create a join link** — `POST /join-links {role}` → `{id, role, url: "/join/<token>", created}`; one active link per role (creating again when one exists returns 409 `This role already has a join link — rotate it instead.`).
2. **Rotate** — `DELETE /join-links/{id}` then create; the old URL answers 410 `This join link was replaced. Ask an admin for the new one.`
3. **Accept** — `GET /api/join/{token}` (anonymous) → `{workspace: {name, slug}, role}`; `POST /api/join/{token}/accept` (signed in) → adds a `Member` with the link's role, 409 `You are already a member.`, 402 when the seat limit is reached, 410 for a rotated link.
4. **Invite expiry** — email invites expire 72 h after sending. `GET /members` adds `expires` and `expired: bool` per invite; accepting an expired invite → 410 `This invite expired. Ask an admin to resend it.`
5. **Resend** — `POST /invites/{token}/resend` → new token + expiry, mail sent again, 409 when already accepted.

## Backend changes
- Models/schema: `models/identity.py` gains `JoinLink(id, workspace_id, role, token unique, created_by, created, active)`; `Invite.expires FLOAT` column. `ADD COLUMN` `INVITES = {"expires": "FLOAT"}` plus a `STEPS` row `("invites", identity.INVITES)`; backfill on read: `expires = created + 259200` when null (one line in `services/join_links.py`).
- Routers: `routers/join.py` (new) prefix `/api`: `GET /join/{token}`, `POST /join/{token}/accept`; admin routes `GET/POST /api/ws/{ws}/join-links`, `DELETE /api/ws/{ws}/join-links/{id}` (rotate) — both routers in one module, register the second via `EXTRA_ROUTERS`. `routers/workspaces.py`: invite payload gains `expires`/`expired`, `POST /invites/{token}/resend`, and `accept` refuses an expired token.
- Services/jobs: `services/join_links.py` (new) — `create`, `rotate`, `resolve(token)`, `accept(db, token, user)` (seat check via `plan(ws)["seats"]` and pending invites), `expiry(invite)`, `resend(db, invite)`.
- Permissions + workspace isolation: admin-only management (`workspace.members`); `accept` works across workspaces because the token names it, and the resulting Member row is created under that workspace only; a token from another workspace can never grant a role here.
- Secrets/safefetch: none — tokens are `secrets.token_urlsafe(24)`, stored as-is (they are single-purpose and rotatable).
- OpenAPI: yes.

## Acceptance criteria
- [ ] One active join link per role; a reused token adds exactly one membership with the link's role.
- [ ] Invites expire after 72 h, the list shows the expiry, and resend issues a working token.
- [ ] Empty and error states above all render (no link yet, 409/410/402 copies).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids); a token only ever grants membership in its own workspace.
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged (email invites only, no expiry column written).
- [ ] A join link cannot grant `owner` or `admin` from a `billing` request and cannot exceed the seat cap.

## Notes for the implementer
Roles a link may carry: the same `ASSIGNABLE` tuple as invites, minus ownership. Expiry is 259 200 s, not "3 days" spelled anywhere in the API.
