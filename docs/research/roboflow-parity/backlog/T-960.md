## User story
As an ML engineer shipping a VLM feature, I want a fixed set of quality axes scored automatically on real
images, so that "the answers look fine" becomes a number I can regress.

## UX flow (LabelDesk words)
1. **Playground → a VLM answer → Score this answer** — a drawer lists the axes that apply: *Answers the
   question*, *Grounded in what is visible*, *Says it cannot tell when it cannot*. Each row says what it
   checks and which model will judge. [empty: a detector result with no text shows "this result has no text
   to judge" and the drawer has no axes]
2. **Run** — *Run 3 axes* queues one call per axis; verdicts arrive one at a time as compact rows: pass/fail,
   one-line reason, and the text that was judged. [loading: the axis row shows a shimmer where the verdict
   will be; returned axes stay put]
3. **A failure** — "the judge model is unavailable" on that axis, never a silent pass, and *Retry axis*.
4. **A judge that answers prose instead of a verdict** — the axis is *error* with "the judge returned an
   unreadable verdict", and the raw answer is kept for the admin.
5. **Summary** — over a chosen sample, a pass rate per axis with the sample size: "grounded 0.82 on n = 40".

## Backend changes
- Models/schema: `JudgeAxis(key PK-ish, label, description, needs_reference BOOL, prompt TEXT, version INT)`
  seeded from a module constant in `apps/backend/app/services/judges.py` (new) — not a user table, so a
  built-in axis is code, and its version is stamped on every assessment. Plus `Assessment(id, workspace_id,
  project_id, trace_id FK ondelete=CASCADE, axis, axis_version, value JSON, reason TEXT, state, judged_by,
  created)` in `apps/backend/app/models/evaluation.py`, unique `(trace_id, axis, axis_version)`.
- Routers: `POST {P}/traces/{id}/judge` body `{axes: [str]}` → 202 `{queued: [{axis}]}`; `GET
  {P}/traces/{id}/assessments` → `{assessments: [{axis, state, value, reason, axis_version}]}`; `GET
  {P}/insights/judges?days=&model=` → `{axes: [{axis, passed, total, rate}]}`. 400 for an unknown axis, 409
  when the trace has no answer text, 404 for a foreign trace.
- Services/jobs: `apps/backend/app/services/judges.py` (new) — `AXES` (three entries: `grounded`,
  `answers_question`, `knows_its_limits`), `judge(db, trace, axis) -> Assessment` calling
  `ADAPTERS["vlm"].ask(im, prompt)` with `response_format={"type":"json_object"}` and parsing
  `{"verdict": bool, "reason": str}`; a parse failure is `state="error"`. The image is loaded through
  `services.imaging.open_image` from the trace's `image_id`; a missing image is `state="error"` with the reason.
  Runs inline (one call per axis, under two seconds), so no job kind.
- Permissions + workspace isolation: `project.models` to judge (it spends a model call), `project.review` to
  read; a foreign trace is a 404.
- Secrets/safefetch: none — the VLM URL is configured in `apps/backend/config.py` as it is today.
  Dependency: none added (no `mlflow-skinny`), so no `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] The three built-in axes score a real VLM answer and store a verdict with a reason and an axis version.
- [ ] An unreadable judge answer, a missing image and an unreachable model all land as `error`, never a pass.
- [ ] A summary reports a rate per axis with the completed sample size.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
