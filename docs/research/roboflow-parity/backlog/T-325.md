## User story
As a builder iterating on a visualisation block, I want the expensive model result reused while I change what is drawn, so that each tweak does not pay for the upstream run again.

## UX flow (LabelDesk words)
1. **Run panel → gear → "Reuse earlier results (block cache)"** — one switch, off by default. When on, every node carries a badge: `Cached` or `Not cached`.
2. **Second run with only a downstream change** — the panel skips the cached nodes, prints "Reused 2 blocks · 1 ran", and the result is identical for the reused part.
3. **Uncache one node** — select a node, "Run this again" clears only that node's entry and its dependents, and the next run re-executes them. [empty: no cached run yet → the control is disabled with "Run once first."] [loading: "Reusing…" replaces the per-frame progress for the cached part] [error: the cached entry is older than the saved definition → the cache clears itself and says "The workflow changed, so nothing could be reused."]
4. **What is never cached** — sinks, dataset writes, secrets, custom code and disabled blocks always run, and the panel says so in one line: "Writes and secrets always run; a cached block never skips a side effect."
5. **Scope** — the cache lives in this browser tab's memory for this workflow. It has no effect on batch jobs, on the invoke endpoint or on a stream; the gear line says "Test runs only."

## Backend changes
None: the cache is a client-side reuse of a previous response body, and the "always run" rule is enforced by the client never marking those node types cacheable. No schema, router or metering change.

## Tests to write first
pytest — `none: no backend surface`.
node — `apps/frontend/tests/workflow-cache.test.mjs`:
- `test_sinks_and_disabled_nodes_are_never_cacheable` — `CACHEABLE` excludes `sink`, and every disabled node is planned as `run`.
- `test_a_downstream_change_reuses_the_upstream_entries` — changing only a visualisation node's config plans the model as `reuse` and the visualisation as `run`.
- `test_uncache_clears_dependents_in_order` — invalidating the model clears the crop and the visualisation after it and nothing before it.
- `test_an_entry_older_than_the_saved_definition_is_stale` — `isStale(entry, savedAt)` is true when the workflow's `updated` moved, and the whole cache is dropped.
- `test_the_cache_key_changes_with_the_input` — a different image id produces a different `entryKey` so a cached run cannot answer for another image.

## Acceptance criteria
- [ ] With the cache on, a second run reuses every cacheable upstream node and reports how many ran.
- [ ] Uncache on one node re-runs it and its dependents only.
- [ ] Sinks, writes, secrets and disabled blocks always run, and the panel says so.
- [ ] Empty, loading and error states above all render, including "Run once first" and a stale-entry clear.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — the cache is memory-only and keyed by definition and input.
- [ ] No flag: the switch is an option inside the run panel and does nothing to deployed workflows.

## Notes for the implementer
Key the cache on the input (image id or frame), the node id and the saved `updated` timestamp; anything less lets a stale box survive a definition change. Memory only — no `localStorage`, because a cached prediction is model output, not a preference.
