## User story
As an ML engineer, I want to name what a run starts from and to see the risky choice labelled risky, so that "why is this model worse than the last one" has an answer on the model page.

## UX flow (LabelDesk words)
1. **Train → Output → Starting weights** — five rows with one line each: *Continue a model here* (only when a ready model of the same variant exists), *COCO weights* (default, "the usual starting point"), *Shared checkpoint* ("from another project — pick one"), *ImageNet weights* (classification only), *Random weights* (advanced, "usually worse; only for a controlled experiment").
2. **Nothing to continue from** — the first row is dimmed with "No finished model of this variant yet." and the default stays COCO. [empty: the shared list is empty ⇒ "No shared checkpoints — share one from the workspace Models page."] [loading: the shared row shows a spinner while the workspace catalogue loads] [error: the catalogue fails ⇒ the shared row says "Unavailable right now" and stays disabled]
3. **Random weights** — lives inside Advanced, never the default, with the warning line and a confirm on selection ("Random init cannot use pretrained features. Continue?").
4. **Recorded on the model** — the model page's recipe line reads "Started from COCO weights" / "Started from v2 / YOLO26 Nano (this project)" / "Started from a random initialisation", so the choice is re-readable after the run.

## Backend changes
- Models/schema: none — the choice is stored in `job.params.options.checkpoint` (JSON) and copied to `TrainedModel.metrics.checkpoint` at register time. `resume_from` stays accepted for old clients and maps to `checkpoint: {kind: "previous", model_id}`.
- Routers: `POST {P}/train` body gains `checkpoint: {kind: str, model_id: str | None}`. Validation, each a **400** with its own sentence: `previous` needs a `ready` same-variant model **of this project**; `shared` is T-258's rule; `imagenet` only for `task == "classify"`; `random` only for families whose adapter exposes a yaml start (`ultralytics`); anything else names the four valid kinds. Encoded as `services/train_recipe.checkpoint_kind(task, family, request, db, project)` returning normalised `{kind, model_id, weights}`.
- Services/jobs: `handlers/training.py::_start_weights` (in `ultralytics_ad`) gains the kinds: `random` → `f"{variant}.yaml"`, `imagenet` → `f"{base}-cls.pt"`, `coco` → today's default, `previous`/`shared` → the resolved weights path (T-258 copies shared weights to `start.pt`). The existing `resume_from` path stays untouched for replay.
- Permissions + workspace isolation: unchanged (`c.need("admin")`); the model id a checkpoint names is resolved inside the workspace, so a foreign id is "unknown checkpoint" (400), never a 404 echoing an id.
- Secrets/safefetch: none.
- OpenAPI: yes — `TrainIn.checkpoint` (regenerate both files).

## Acceptance criteria
- [ ] Five checkpoint kinds render with their one-line meaning; only the valid ones are selectable.
- [ ] Random init is never the default and always asks once.
- [ ] An invalid kind is a 400 naming the valid kinds — never a run that silently starts from COCO.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ today's "Continue from model" select and the implicit COCO start.

## Notes for the implementer
"Previous" means *this project* — a cross-project start is the shared kind and must not be silently accepted here. Keep the model-page sentence to one of the three strings in the UX flow; no free-form checkpoint text.
