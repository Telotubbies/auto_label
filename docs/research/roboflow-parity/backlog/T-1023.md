## Goal
Ollama is the first and default engine in the Engines tab, and Ollama model tags are pullable in the
Models tab, following PLAN §12.

## Changes
- Catalogue: an `ollama` engine row first in order, `default: true`; install via the official Docker image
  pinned by digest (preferred) or the official Linux install script pinned by version + sha256; health check
  `GET /api/version` on the worker's loopback only (never exposed by the API).
- Model catalogue: rows with `engine: "ollama"` and a tag (start with `qwen3:4b`, `qwen3:8b`, `gemma3:4b`,
  `llama3.2:3b`); pull runs on the worker as `ollama pull <tag>` built from the catalogue, `shell=False`;
  the one-model-per-host rule (PLAN §12.4) applies to tags too.
- VRAM estimator: Ollama tags map to their GGUF quant (Q4_K_M by default) so the calculator works for them.

## Tests (first)
- The engines list starts with `ollama` and it is the default selection.
- An Ollama install plan is built only from the catalogue (no client string reaches argv).
- A tag outside the catalogue is refused (422).
- Pulling a second model on a host that already holds one is refused with the "remove the current model
  first" message.
- All of it against an HTTP fake of the Ollama API and the T-1019 mocked installer — **never a real Ollama,
  never a real download** on the developer machine or in CI.
