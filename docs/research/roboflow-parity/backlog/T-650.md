## User story
As a dataset lead, I want the map to group similar images into named clusters and to turn one cluster into a tag, a review batch or a class, so that the 2,000 near-identical images and the one dense unlabelled group stop being rediscovered every week.

## UX flow (LabelDesk words)
1. **Insights → Embeddings** (`/:ws/:project/insights?tab=embeddings`) — a "Group into clusters" button beside "Re-embed". [empty: no map built yet ⇒ the button is disabled with "Build the map first"] [loading: "Grouping 3,000 images…" with the existing progress pattern; the map stays readable]
2. **Stale map** — `[error: the map is older than the dataset — re-embed before grouping]` and the button disabled, matching the existing stale banner.
3. **Cluster list** — one row per cluster: size, share of the map, dominant class (or "unlabelled"), unlabelled share. Clicking a row isolates it on the scatter; hovering previews it.
4. **Naming** — a name field per row writes "wet floor / night"; the name survives a rebuild while the signature matches and is dropped (not guessed) when it does not.
5. **Acting on a cluster** — a lasso (or a row) offers "Tag…", "Send to review", "Add to collection", and on a classification project "Label as <class>". [error: a selection over 1,000 images says so and acts on the first 1,000, exactly like the existing lasso hand-off]
6. **Footer** — "3 clusters have no annotations" links to the grid filtered by that cluster.
7. **Flag off** — no cluster button, no list, and the scatter is exactly today's.

## Backend changes
- Models/schema: none — cluster names live in `Project.settings["clusters"] = {"<map_signature>": {"<cluster_key>": "<name>"}}`; membership is derived, never stored.
- Routers: `GET /api/ws/{ws}/projects/{project}/insights/embedding/clusters?k=` in the existing `routers/insights.py` → `{"signature", "k", "clusters": [{"key", "size", "share", "class", "unlabelled_share", "name", "image_ids": [≤ 200]}], "points": {"<image_id>": "<cluster_key>"}}`; `PUT .../insights/embedding/clusters/names` with `{"signature", "names": {"<key>": "<name>"}}` → 200; 409 when the map signature has changed, 400 for a name over 40 characters.
- Services/jobs: `services/clusters.py` (new) — `k_for(n)` (round √(n/2), clamped 2–40), `kmeans(matrix, k, seed=42, iters=25)` deterministic in numpy, `group(db, project, signature)` reading `insights_embedding.load_feature` per sha and skipping images without a cached vector (counted as `unplaced`), `describe(db, project, groups)` computing dominant class and unlabelled share from `Image.annotations`.
- Permissions + workspace isolation: `project.review` to read, `project.review` to name; every id resolves inside `project_ctx`, so another project's signature returns an empty list rather than foreign points.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate (`python tools/export_openapi.py`, `npm run gen:api-types`).

## Tests to write first
pytest — `apps/backend/tests/test_clusters.py`:
- `test_k_is_bounded` — `k_for(10) == 2`, `k_for(3000) == 39`, never above 40.
- `test_kmeans_is_deterministic` — the same matrix twice yields identical labels and keys.
- `test_two_obvious_groups_split` — two tight blobs of 40 points each → two clusters, no mixed member.
- `test_images_without_a_cached_vector_are_counted_not_guessed` — five of ten images have features → `unplaced == 5`, clusters cover the other five.
- `test_names_survive_a_matching_signature` — PUT two names, GET again with the same signature → both present.
- `test_names_are_dropped_on_a_new_signature` — a rebuild changes the signature → names read empty, no collision of old keys.
- `test_name_too_long_is_400` and `test_labeler_cannot_name_clusters` (403).
- `test_flag_off_is_404`.
node — `apps/frontend/tests/clusters.test.mjs`:
- `test_rows_sort_by_unlabelled_share` — the row with the highest unlabelled share comes first.
- `test_action_needs_a_selection` — zero selected points disables Tag and Send to review.
- `test_classification_only_action` — "Label as" exists for a classification project and is absent for object detection.
- `test_cap_notice_over_one_thousand` — 1,200 selected points shows the first-1,000 notice.

## Acceptance criteria
- [ ] Grouping a built map produces clusters with size, share, dominant class and unlabelled share, and the same map groups identically twice.
- [ ] A cluster can be named, isolated, and turned into a tag, a review batch, a collection (or a class on a classification project) from the map.
- [ ] A stale map refuses grouping with the re-embed sentence; an empty map disables the button.
- [ ] Empty, loading and error states above all render, including `unplaced` images and a cluster with no annotations.
- [ ] Workspace A cannot read workspace B's clusters (every request is project-scoped; a foreign signature returns nothing).
- [ ] Flag off ⇒ no cluster button, no list, and the scatter is byte-for-byte today's behaviour.

## Notes for the implementer
Cluster keys are derived from the sorted member ids (first 12 hex of a sha256), not from an index that shifts when one image is added. `k` is deterministic from the point count so two people pressing the button see one answer; never let the client choose `k` beyond an override of ±50 %. Names belong to the signature — a rebuild is a new map and honestly forgets them.
