## User story
As an MLOps engineer, I want to pick a connected bucket inside the export dialog and see the delivery land, so that the handoff to training infrastructure is one click and its outcome is visible.

## UX flow (LabelDesk words)
1. **Export dialog → Send to storage** — the destination list from `GET /versions/export-destinations`, each row: name, kind, and a *Send* button; unsupported kinds are dimmed with their reason. [empty: "No storage connected yet — an admin can add one under Settings → Integrations."] [loading: skeleton rows] [error: "Could not load storage destinations — retry"]
2. **Send** — the active row becomes "Sending… 60%" (the export job's progress), then "Delivered to exports/v3/coco.zip" with a *Copy key* action. [error: the bucket's refusal message inline; the local ZIP stays downloadable]
3. **Upload failed after a successful build** — the dialog says "ZIP built, upload failed: <reason>" and offers *Retry upload*, which re-posts the same destination (the API returns the existing export job and retries the upload only).
4. **Permission** — the section is absent without `project.export`, and the whole dialog is unreachable behind the route guard.

## Notes for the implementer
Never render `connector.config` — the API does not send it and the UI must not ask. Show the object key exactly as returned; do not build it client-side, or a re-export will point at a path that does not exist.
