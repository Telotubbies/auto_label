## User story
As a reviewer, I want a single media grid for the whole workspace with one filter bar, so that finding a duplicate or a misfiled image does not mean guessing which project holds it.

## UX flow (LabelDesk words)
1. **Asset library** (`/:ws/assets`) — header `Assets` with `N images across M projects`, one search input, one `Filters` button carrying an active-count badge, one sort select (`Newest`, `Name`, `Most annotations`). Filter popover: project, type, class, tag, annotated (yes/no), size bucket, aspect bucket, annotation count, date range.
2. **Grid** — 2–4 columns by width, 13 px captions, class names on hover, a project chip on each tile. Clicking a tile opens the project's editor at that image (`/:ws/p/:project/annotate/:imageId`). [empty: workspace with no images → `No images in this workspace yet. Upload into a project to see them here.` + `Open projects`; filters excluding all → `No images match these 3 filters.` + `Clear filters`] [loading: 12 tile skeletons, filter bar interactive] [error: `Could not search assets` + `Retry`, query preserved].
3. **Raw toggle** — a `Query` switch shows the structured filters as one editable string (the parser arrives with `1-F4.3`; until then the field is read-only and explains `Filters become a query string once the query language ships.`). [empty: no filters → the string is blank]
4. **Paging** — `Load more` appends 60; the count line stays the server total. Selection is T-028's bar.
5. **Mobile 375** — one column of tiles, filters as a full-height sheet, no horizontal scroll.
