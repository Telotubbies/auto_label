## User story
As a reviewer, I want to edit an image's attributes in the editor and apply one attribute to a selection
from the grid, so that "this lot was night shift" is two clicks and stays searchable.

## UX flow (LabelDesk words)
1. **Editor · right inspector · Metadata** — a list of key/value rows with a type chip
   (`quality_score · number · 82`, `camera · text · cam001`), a key field and a value field, and an **Add**
   button; Enter in either field adds. [empty: "No metadata yet — add the first key."]
   [loading: rows resolve with the image; the panel shows 3 skeleton lines]
2. **Editor · Metadata** — a human-owned key shows a lock chip "Edited by you" and, when the policy is
   "Bucket wins", a sub-line "Bucket updates still apply". Removing a key asks once:
   "Remove `quality_score` from this image?" [error: a bad key or value shows the server sentence inline
   and keeps the typed text]
3. **Dataset · Images** — with a selection, the bar's **Add metadata** opens a dialog: key, value, and
   "Replace existing values for these keys" (off). Applying shows "120 updated · 0 failed"; a partial
   failure expands to the list of ids and reasons. [error: selection over 1,000 → the button explains the
   cap and offers "narrow with a filter"]
4. **Dataset · Images** — the Filters popover's metadata section autocompletes keys and values from what
   exists in the project. [empty: no keys yet → the section is absent]

## Backend changes
- Models/schema: none in this card.
- Routers: none new — consumes T-082's patch and bulk route; key/value suggestions come from the existing
  `/images` payload (collect distinct keys client-side from the loaded page) plus a `GET P/images/meta-keys`
  read added here: `{keys: [{key, type, sample}]}` (read-only, ≤ 200 keys).
- Services/jobs: none.
- Permissions + workspace isolation: the read is under `project.read`; writes are T-082's rules; the panel
  hides its edit controls without `project.annotate`.
- Secrets/safefetch: none.
- OpenAPI: yes — one read route.

## Acceptance criteria
- [ ] The editor lists, adds, edits and removes metadata with type chips and the human-owned lock.
- [ ] A bad key is refused inline before the request and again by the server without losing the typed text.
- [ ] The bulk dialog applies to the selection, honours the replace switch, and names partial failures.
- [ ] The metadata filter section autocompletes from real keys and disappears when none exist.
- [ ] Empty, loading and error states above render.
- [ ] Flag off ⇒ no metadata surface in the editor, grid or filters.
- [ ] Workspace A cannot see or change workspace B's data (404 for a foreign project id; values render only
      for the loaded project).
