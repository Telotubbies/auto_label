## User story
As a person creating my first workspace, I want to choose the tier I am starting on in the same form, so that I do not have to hunt through settings later to understand what I have.

## UX flow (LabelDesk words)
1. **Create account / first run** — beneath the workspace name, three tonal chips: `Free`, `Pro`, `Enterprise`, one line of what each unlocks ("3 projects · 30 credits" read from the plan limits). No price, no card field, nothing charges. [empty: nothing → `Free` is preselected] [error: none possible; selection is local until submit].
2. **Submit** — `Creating…` keeps width; success lands on `/:ws` with a one-time inline note `Started on Free. You can change this in Settings → Plan & Usage.` (no toast wall).
3. **Settings → Plan & Usage** — unchanged; the plan already appears there. Changing a plan still needs the platform operator.

## Backend changes
- Models/schema: none; `workspaces.plan` exists and `config.PLANS` is the source of limits.
- Routers: `POST /api/workspaces` accepts `plan`; accepted values are `config.PLANS` keys; only honoured when `task_a1_plan_choice` is on, otherwise ignored (the workspace starts on `free`). `GET /api/workspaces/plans` → `[{id, label, projects, credits, seats}]`, flag-gated.
- Services/jobs: none.
- Permissions + workspace isolation: plan choice is creation-time only and cannot touch another workspace; `PATCH /api/ws/{ws}` keeps its superadmin-only plan rule, so this card adds no self-serve upgrade path.
- Secrets/safefetch: none — no payment provider, no credentials, no charge.
- OpenAPI: yes.

## Frontend changes
- Route: `/signup` and the first-run screen (T-010's form).
- Nav entry: none.
- Components: `features/onboarding/PlanPicker.tsx` (new) — chip row + one-line limit text; rendered inside `WorkspaceForm` when the flag is on.
- API client: `coreApi.plans()` in `src/lib/api/core.ts`.
- Feature flag: `task_a1_plan_choice`; off ⇒ no chips and the request sends no plan (workspace starts Free).
