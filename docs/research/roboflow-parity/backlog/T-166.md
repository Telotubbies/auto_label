## User story
As a dataset owner, I want a project to ask a question per image and store the answer, so that VQA and VLM fine-tuning data can be authored without drawing anything.

## UX flow (LabelDesk words)
1. **Classes & tags → Prompts card** (the admin UI is T-168) — a prompt is either a **question** ("What is the total on this receipt?") or a **prefix** with one `<SLOT>` ("A receipt totalling <SLOT> baht"), plus an answer type (`text`, `number`, `yes/no`, `choice` with options), a required flag and an order.
2. **Editor** — every prompt appears as a field in the Answers panel (T-167); a required prompt with no answer blocks nothing until the image is submitted for review, and the block names it.
3. **Saving an answer** — the PUT carries the whole answer map for the image; unknown prompt ids are 400, a value that does not match its type is 400 with the field named, and an empty string clears the answer. [error: the server message is shown inline under the field]
4. **Required enforcement** — submitting an image for review (or approving it) with a missing required answer returns 400 `"required answer missing: What is the total?"`, so a multimodal image cannot enter the dataset half-answered.
5. **Deleting a prompt** — removes its prompt row and keeps existing answers readable until the deletion is confirmed with "answers to this prompt on 42 images will be deleted"; a soft path (disable) is not offered because a disabled prompt still needs an answer type.
6. **Flag off** — no prompt can be created or read; an image payload has no answers key.

## Backend changes
- Models/schema: new tables (`models/prompts.py`, new) — `prompts` (`id`, `workspace_id`, `project_id`, `key` slug unique per project, `kind`, `text`, `answer_type`, `choices` JSON, `required`, `position`, `created`, `updated`) and `prompt_answers` (`id`, `workspace_id`, `project_id`, `image_id` FK cascade, `prompt_id` FK cascade, `value` JSON, `updated_by`, `updated`, unique `(image_id, prompt_id)`); registered in `models/__init__.py`.
- Routers: new `app/routers/prompts.py` (new) — `GET/POST /prompts`, `PATCH/DELETE /prompts/{pid}`, `GET /images/{image_id}/answers`, `PUT /images/{image_id}/answers`; registered in `routers/__init__.py`.
- Services/jobs: `services/prompts.py` (new) — `clean_prompt(body)` (key slug, `<SLOT>` exactly once for a prefix, choices only for `choice`), `validate_value(prompt, value)`, `missing_required(db, image, answers)`, `answers_for(image)`.
- Permissions + workspace isolation: prompt CRUD needs `project.classes`; answers need `project.annotate` on an assigned image (`image_ctx`); every query filters project and workspace, so foreign prompt/image ids are 404.
- Secrets/safefetch: none.
- OpenAPI: yes — six routes.

## Acceptance criteria
- [ ] A project can hold ordered question and prefix prompts, each with a type, required flag and optional choices.
- [ ] An image's answers save and reload as one map, validated per prompt type, with unknown ids refused.
- [ ] A required prompt without an answer blocks submit-for-review with the question named.
- [ ] Deleting a prompt removes its answers and states the count before doing so.
- [ ] Empty, loading and error states above all render (an image with no prompts returns `{}`).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ every route 404 and the image payload has no answers key.
- [ ] Keyboard-only path: not applicable in this card.

## Notes for the implementer
Answers are a table, not a JSON column on `Image`: a required-answer query across a batch must not hydrate every annotation blob. `value` is JSON so a number stays a number; the type rule lives in one `validate_value`, never in the router.
