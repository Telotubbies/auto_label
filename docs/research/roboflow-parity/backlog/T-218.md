## User story
As a reviewer, I want the generating card to say which phase is running, so that a long build looks alive instead of stalled.

## UX flow (LabelDesk words)
1. **Version row / detail while generating** — the progress bar is labelled with the phase: *Collecting images · Preprocessing · Augmenting · Writing · Finalising*, plus `42%`. [empty: queued → "Waiting for a worker"] [loading: n/a] [error: the failure message replaces the phase]
2. **Job tray** — the same label on the tray item, so the phase is visible after leaving the page.
3. **Cancel** — the phase stops updating and the row reads "Cancelled — nothing was written."

## Backend changes
- Models/schema: none — the phase rides in `Job.result` while the job runs (`{"phase": "augment", "of": 3}`); `run_one` replaces `result` with the handler's dict on completion, so no stale phase survives. No column, no migration.
- Routers: `job_out` already serialises `result`; no change. `GET /versions` therefore carries the phase for free.
- Services/jobs: `app/services/versioning.py` — `generate(db, v, progress=lambda fraction, phase: None, should_stop=None)` reports `("collect", 0.0)` once, then per image `("preprocess"|"augment", f)`, then `("write", 0.95)` before the manifest and `("finalise", 1.0)`. `app/handlers/versioning.py` — `run_version` passes `lambda f, phase: w._set(job.id, progress=round(f*100,1), result={"phase": phase, "of": 3})`.
- Permissions + workspace isolation: unchanged; the job row is already project-scoped by `version_out`.
- Secrets/safefetch: none.
- OpenAPI: no (a free-form dict gained a key).
- Flag: `task_217` off ⇒ the same phases are written (harmless) but the UI ignores them.

## Acceptance criteria
- [ ] Five phases are reported in order and the job payload exposes them while running; a finished job carries its stats instead.
- [ ] Cancelling mid-build still leaves no ready version and no files.
- [ ] Empty, loading and error states above all render (queued, running, cancelled, failed).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ phases are written but nothing in the UI changes.

## Notes for the implementer
`result` is the cheapest carrier and needs no schema: `run_one` overwrites it on completion, so the only rule is *always send the whole dict*. Keep the fractions coarse (three decimals) — the row re-renders on every poll.
