## User story
As a data engineer, I want the upload to tell me which format it recognised and how it renamed my
classes so that a wrong guess is visible in the result instead of a silent change to my ontology.

## UX flow (LabelDesk words)
1. **Upload** — after the batch is sent, the result sheet gains a line
   "Recognised: COCO JSON · 12 label files" or "Recognised: YOLO txt + data.yaml".
   [empty: no label files → the line reads "Images only — nothing to import"]
2. **Upload** — when a class name is rewritten the sheet lists it:
   "Renamed 2 classes: `person/worker` → `person-worker`, `helmet|red` → `helmetred`".
   [loading: shown only after the upload resolves]
3. **Dataset · Classes & tags** — the renamed class appears once; a second upload with the same source
   name maps onto the existing class instead of creating a duplicate. [error: an annotation file that
   cannot be parsed is named in the reason list with its parser ("YOLO txt line 4: expected 5 values") and
   the images still upload]

## Backend changes
- Models/schema: none.
- Routers: `apps/backend/app/routers/images.py` — `ingest` return gains `"format": str`,
  `"classRenames": [{"from": str, "to": str}]`; no new endpoint.
- Services/jobs:
  - `apps/backend/app/services/importers.py` — `Bundle` gains `format: str`; `collect()` sets it from the
    evidence (COCO JSON, Label Studio, YOLO + names file, Pascal VOC XML, CVAT XML, classification
    folders, none) using a first-match table, and every emitted class name passes through
    `normalise_class()`.
  - `apps/backend/app/services/import_normalize.py` (new) —
    `normalise_class(name: str) -> str`: trim, collapse whitespace to one space, replace `/.[]#~*` with
    `-`, drop `|'"`, collapse repeats, strip leading/trailing `-.`, max 120 chars;
    `record_renames(pairs) -> list[dict]` de-duplicated by source name.
  - Split detection stays `importers.split_of` (allow-list `train valid val test`, case-insensitive).
- Permissions + workspace isolation: unchanged route, `c.need("reviewer")`, project-scoped hash lookup.
- Secrets/safefetch: none.
- OpenAPI: yes — the ingest response shape is in `openapi.json`.

## Acceptance criteria
- [ ] The response names the recognised format, or "none" for images only.
- [ ] Class names are normalised on the way in, and the response lists each distinct rewrite once.
- [ ] A second upload of the same source class maps to the existing class (no duplicate row).
- [ ] Unmatched split folder names fall back to the request's split exactly as today, with no warning
      invented here (the split-at-ingest behaviour is guard `T-005`; T-068 owns the visible pre-flight line).
- [ ] Empty/loading/error states above render (the "no label files" line, no spinner left behind).
- [ ] Flag off ⇒ names are stored verbatim and the response fields are absent.
- [ ] Workspace A cannot see or change workspace B's data (404 for cross-workspace project ids).

## Notes for the implementer
Normalisation runs *before* `ensure_class`, so an existing class whose stored name is already normalised
is reused. Never rewrite an existing `LabelClass.name` here — T-092 (tag/class cleanup) is the only place
a stored name changes.
