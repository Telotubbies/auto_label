## User story
As a reviewer, I want `a`, `r` and `u` to decide and to take back the last decision, so that a batch review is a scan rather than a form.

## UX flow (LabelDesk words)
1. **Editor in review mode** (`?review=true` from the board's Review button; banner at `Editor.tsx:869`) — `a` approves, `r` rejects, `u` undoes the last decision. Each decision saves a dirty image first, then advances to the next image in the review queue. [empty: the queue's last image → a toast "That was the last image in review" and the editor returns to the board] [loading: a decision in flight disables the keys and shows the spinner on the button] [error: the server refuses → stay on the image, toast the reason, no advance]
2. **Honest approve** — Approve is disabled, with a reason, while the annotation set is still loading, while a save is in flight, after a failed save, and on an image with zero labels that is not marked empty. `title` reads "Approve needs a saved label set — or mark the image empty".
3. **`u` undo** — takes the reviewer back to the image just decided, clears its review state and puts it back in `annotating`, then restores the queue position. Only the most recent decision in this browser session is recoverable; the toast says "Review decision undone". [error: the image was deleted meanwhile → toast, skip]
4. **`Shift+A` for labelers** — outside review mode, `Shift+A` submits the current image for review (today's button, `Editor.tsx:849`), and on the dataset side a reviewer's `Shift+A` adds it to the dataset.
5. **Cheat sheet** — `?` lists `a` Approve, `r` Reject, `u` Undo decision, `Shift+A` Submit for review, with their review-mode condition.

## Backend changes
- Models/schema: none — `Image.review` (`models/project.py:109`) already holds `approved | rejected | null`.
- Routers: `POST /api/images/{image_id}/review` (`images.py:604`) gains `base_updated: float | None` (same stale guard as T-121) and the rule `approved && n_annotations == 0 && !marked_empty` → `400 "approve needs at least one label, or mark the image empty"`; a new `DELETE /api/images/{image_id}/review` clears `review` to null, sets `status = "annotating"`, writes an audit row `image.review_undo`, and returns the image payload.
- Services/jobs: none.
- Permissions + workspace isolation: both routes call `c.need("reviewer")` / `project.review`, and `_assigned` keeps labelers off unassigned images; a foreign image id is 404.
- Secrets/safefetch: none.
- OpenAPI: yes — new method and field.

## Acceptance criteria
- [ ] `a` and `r` decide and advance in review mode only; `u` returns to the previous image, clears its decision and restores the queue position.
- [ ] Approve is impossible before the annotation set loads, during a save, after a failed save, and on a zero-label image that is not marked empty — each with its stated reason.
- [ ] `Shift+A` submits for review for a labeler and adds to the dataset for a reviewer.
- [ ] Every decision is audited and a rejected image reappears in the Annotate column immediately.
- [ ] Empty, loading and error states above all render, including "last image in review".
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: the review surface already ships; there is no flag-off variant.
- [ ] Keyboard-only path: board → Review → `a` → `a` → `u` → `r` → board.

## Notes for the implementer
The undo stack is session-local and one deep by design — a server-side undo of arbitrary decisions needs the revision history in T-144 and is not this card. `u` re-opens the image before clearing, so the reviewer sees what they are taking back.
