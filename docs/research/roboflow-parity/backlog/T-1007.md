## User story
As a workspace admin, I want to tick engines for a host, read why one is blocked and what the install
will do, then confirm it in a sheet that names the host, so that a one-click install is still a
deliberate one.

## UX flow (LabelDesk words)
1. **Engines tab** — host picker in the header (from `GET /hosts`), then a table: checkbox, engine,
   pinned version, runtime select (`uv` / `pip` / `docker`), OS/accelerator, disk, status
   (`Not installed` / `Installed <version>`), compatibility badge + reason.
   [loading: header skeleton + five skeleton rows] [error: "Engines did not load for this host." +
   Retry] [permission: the whole tab is absent without the flag].
2. **Selection** — a compatible or warning row can be ticked; a blocked row's checkbox is disabled and
   a lock icon sits beside the reason. Selecting a different host clears the selection with the notice
   "Selection cleared: you changed host."
3. **Footer** — "2 engines · 9.4 GB to install · 812 GB free" and `Review install plan` (disabled at
   zero with "Select an engine first.").
4. **Plan sheet** — host, one block per engine with runtime and argv in a monospace, total bytes, disk
   before/after, warnings, and the acknowledgement checkbox. `Install` is disabled until the checkbox
   is ticked and while the request runs. [error: inline sentence from the API, job id when 409].
5. **After confirm** — the sheet closes, the row shows `Queued` with a small spinner, and the tab shows
   a one-line "Install queued on <host>. Open the job to follow the log." (T-1009 adds the live card
   with logs and cancel.)
6. **Uninstall** — `Installed` rows offer a row menu → `Uninstall` → a second confirm sheet naming the
   engine and the virtual environment to remove.
7. **Host offline / allow_install false** — the footer explains "This host has not enabled installs
   (`LD_ALLOW_ENGINE_INSTALL=1`)." and `Review install plan` is disabled.
8. **Empty** — no host: "Start a worker, then pick it here." with the command; no engines in the
   catalogue: "No engine has a verified pin yet."

- `test_blocked_rows_cannot_be_selected` — `selectable({status:'blocked'})` is false; `ok`/`warn` true.

  unchanged.
- `test_footer_says_why_the_action_is_disabled` — zero selected → "Select an engine first."; offline →
  "This host is offline."; `allowInstall: false` → the `LD_ALLOW_ENGINE_INSTALL=1` sentence.
- `test_argv_is_shown_verbatim_and_never_joined_into_a_shell_line` — `argvText` returns the list joined
  by spaces **for display only**, and a test asserts the component never sends that string back.
- `test_uninstall_is_only_offered_for_an_installed_row` — `rowStatusCopy({installed:false})` has no
  uninstall action.
- `test_changing_host_clears_the_selection` — pure reducer returns an empty set and the notice.

## Acceptance criteria
- [ ] Rows render compatibility, version, runtime and disk; blocked rows are unselectable with a reason.
- [ ] Footer totals are correct and the action states exactly why it is disabled.
- [ ] The plan sheet shows the argv, bytes, disk after and the acknowledgement; `Install` needs it.
- [ ] A 409 (busy host or stale plan) renders inline and offers the running job or a re-plan.
- [ ] Uninstall requires a second confirm naming the engine and host.
- [ ] Empty, loading, error, offline and `allow_install=false` states all render.
- [ ] 375 px: the table scrolls horizontally with the engine name sticky; the sheet is full-height.
- [ ] No new token, hex, font size or icon library; glass only on sheet/footer.

## Notes for the implementer
Keep the host picker in `InferenceHub`, not in each tab: Models and Segmentation need the same choice
and a second picker would drift. The acknowledgement checkbox is a real gate, not decoration — the
button is disabled, not merely warned.
