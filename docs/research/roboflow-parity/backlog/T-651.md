## User story
As the person freezing a version, I want one table that says which class is short against a target I set, so that "can harness ship this week" is a row I can read instead of arithmetic on a bar chart.

## UX flow (LabelDesk words)
1. **Insights → Coverage** (`/:ws/:project/insights?tab=coverage`) — a new tab beside Data quality. [empty: "Label something first — coverage needs at least one annotation" with a link to the board] [loading: the page skeleton the Insights tabs already use]
2. **The table** — one row per class: images containing it, instances, share of the dataset, singles (images with exactly one instance), clusters it never appears in, and a thin flag when instances are under the target. Sorted thinnest first.
3. **The target** — one number field, default 100, saved on the project; changing it re-renders without a scan. [error: a target below 1 is refused under the field]
4. **Row actions** — click the row to filter the grid to that class; "missing" view filters to images *without* it; "Export CSV" downloads the table as shown.
5. **Version summary** — the same table rides in the version summary card, with the target line, so a frozen version carries its own gap record.
6. **Flag off** — no tab and no table.

## Backend changes
- Models/schema: none — the target lives in `Project.settings["coverage_target"]` (default 100).
- Routers: `GET /api/ws/{ws}/projects/{project}/insights/coverage?version=&target=` in the existing `routers/insights.py` → `{"target", "classes": [{"id", "name", "color", "images", "instances", "share", "singles", "missing_clusters", "thin"}], "clusters": n, "unplaced": n}`; 400 when the target is below 1; the project PATCH accepts `coverage_target`.
- Services/jobs: `services/coverage.py` (new) — `report(db, project, version=None, target=100)` built from `ImageClass`, `Image.annotations` and `clusters.group` membership; `singles(db, project)` counts images with exactly one instance of the class; `missing_clusters(groups, rows)` counts clusters with no member carrying the class; `thin(instances, target)` is `instances < target`.
- Permissions + workspace isolation: `project.review` to read, `project.classes`-level admin to write the target through the project PATCH (existing `c.need("admin")` on that route); the version id is validated against the project (`_version()` in `routers/insights.py` already returns 404).
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate (`python tools/export_openapi.py`, `npm run gen:api-types`).

## Acceptance criteria
- [ ] The report lists every class with images, instances, share, singles, missing clusters and a thin flag against a target stored on the project.
- [ ] Changing the target re-sorts the table without a scan; a target below 1 is refused.
- [ ] A row filters the grid to that class, the missing view filters to images without it, and the CSV matches the table on screen.
- [ ] Empty, loading and error states above all render, including no annotations and no built map.
- [ ] Workspace A cannot read workspace B's coverage (project-scoped query; a foreign version id is 404).
- [ ] Flag off ⇒ no Coverage tab and no endpoint.

## Notes for the implementer
`thin` is instances against the target, not images — a class seen once in a thousand images is a gap even if its image count looks healthy, and state that in the caption. When no embedding map exists, `missing_clusters` is 0 with `unplaced` naming why, never a fake zero-gap verdict. CSV uses the same column order as the table, `—` for missing cluster data.
