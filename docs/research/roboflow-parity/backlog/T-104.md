## User story
As a labeler or reviewer, I want the screens to say when a number was measured, which rule decided my split,
and what a deletion keeps, so that I can trust the report instead of reconciling it by hand.

## UX flow (LabelDesk words)
1. **Health report** — under the ring, one line: "Measured 12 min ago · 40 images changed since — re-run for a
   fresh number" with `Re-run`. [empty: no report yet → "No health report yet · Run the first scan", one button]
   [loading: the line reads "Measuring…" and the ring keeps its last value, dimmed] [error: "Last scan failed ·
   Retry" and the previous numbers stay visible with their own timestamp]
2. **Insights tabs** — the same freshness line, same component, same wording; clicking it opens the health tab.
3. **Dataset split badge** — an image whose folder name did not match the split rule shows a warning chip
   "Auto split · folder name not recognised" next to its split badge; hover names the accepted names
   (`train`, `valid`, `test`) and the 70/10/20 fallback that was applied. [empty: no image in view → nothing]
4. **Upload result sheet** — the same warning is counted once: "3 files fell back to the automatic split".
5. **Delete confirm** — the dialog states the survival rule in one sentence before the destructive button:
   "Annotations and versions stay; these 4 images leave every dataset view." Shared-file cases add
   "2 images are shared with another project and will stay there." [error: the delete fails → the dialog stays
   open with the server sentence and a Retry, nothing is optimistically removed]

## Backend changes
- Models/schema: none.
- Routers: `POST /api/projects/{id}/images` ingest response gains `split_rule: "folder" | "auto"` and
  `split_folder: str | null` per accepted file (batch summary gains `split_fallback: int`);
  `DELETE /api/projects/{id}/images` response gains `kept_shared: int` and `removed: int`. No new route.
- Services/jobs: `services/imaging` untouched; `split_of` stays the single decision point and its return is
  surfaced, not recomputed in the UI.
- Permissions + workspace isolation: unchanged paths (`images.py:322-331`); cross-workspace ids still 404.
- Secrets/safefetch: none.
- OpenAPI: yes — response fields only; regenerate on the branch.

## Notes for the implementer
