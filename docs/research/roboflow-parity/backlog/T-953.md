## User story
As an ML engineer, I want a paired difference with a confidence interval between two models on the same
test set, so that I stop shipping a model because one number was 0.03 higher.

## UX flow, click by click.
1. **Models → Compare** — with two to four models selected, a new *Difference* table sits under the charts:
   one row per metric with baseline, candidate, difference, 95% interval, and a verdict — *better*, *worse*,
   *no difference*, *too few examples*. [empty: fewer than six shared images ⇒ the verdict column reads
   "not enough shared images to compare" and no interval is printed] [loading: the table shows a spinner row
   while the interval is computed, the charts below are already interactive]
2. **Sort and filter** — sort by absolute difference; the table uses the same class colours as the charts.
3. **Where it changed** — clicking a row narrows the disagreement strip to the images that flipped for that
   metric, each opened side by side.
4. **Copy the sentence** — *Copy summary* yields "AP50 +0.04, 95% CI [0.01, 0.07], p = 0.02 on n = 200".
   [error: models evaluated on different sets ⇒ the table refuses with "these models were scored on
   different sets — pin one set and re-run" and links the set]
5. **Two runs of the same model** — the same table answers "is this retrain noise?" with the delta of a model
   against itself.

## Backend changes
- Models/schema: none — computed on read from `trained_models.metrics["eval"]`.
- Routers: `GET {P}/insights/compare` (T-283 extends it) gains `delta: {metric: {n_paired, baseline_mean,
  candidate_mean, diff, ci_low, ci_high, p_value, method, ties, verdict, set_id}}`, computed pairwise against
  the first selected model. 409 with the "different sets" sentence when the reports' `set_digest` differ and
  both are present.
- Services/jobs: `apps/backend/app/services/compare_stats.py` (new) — `pair_rows(a, b)` matches per-image
  records by `image_id` (never by index), `paired_delta(values_a, values_b, greater_is_better,
  resamples=2000, seed=0)` returns a percentile bootstrap interval for the mean difference plus a paired
  t-test p-value for numeric metrics and an exact McNemar-style count for binary ones; `verdict(...)` maps
  interval and p to the four words. Deterministic: the seed is fixed so the same payload always prints the
  same interval. No job.
- Permissions + workspace isolation: unchanged (`project.models` to read compare); foreign model ids 404.
- Secrets/safefetch: none. Dependency: none added (no `mlflow-skinny`, no scipy) — the bootstrap and the
  t-test are thirty lines against `statistics`/`math`, so no `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: yes — regenerate both files.

## Tests to write first
pytest — `apps/backend/tests/test_compare_stats.py`:
- `test_a_clean_improvement_is_better` — 30 images, candidate correct where baseline was wrong on 20 and
  never the reverse → `diff > 0`, `ci_low > 0`, `verdict == "better"`.
- `test_identical_models_are_no_difference` — the same report twice → `diff == 0`, `ties == n_paired`,
  `verdict == "no_difference"` and no p printed.
- `test_five_shared_images_is_too_few` — 5 paired rows → `verdict == "too_few"`, no interval.
- `test_rows_pair_on_image_id_not_index` — the same images in a different order → the same delta as sorted
  input.
- `test_different_sets_is_409_naming_the_sets`.
- `test_the_interval_is_deterministic` — two calls → byte-identical payload.
- `test_flag_off_omits_delta` — `task_mlruns` off → no `delta` key.

- `test_verdict_words_and_tones` — four verdicts → their words and tones; `too_few` never green.

  n = 200".

## Acceptance criteria
- [ ] Two models on one set produce a paired delta, interval, p-value and one of the four verdicts.
- [ ] Fewer than six paired rows, or two different sets, produce the documented sentences and no interval.
- [ ] Rows pair on image id, so a re-ordered report yields the same numbers.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
