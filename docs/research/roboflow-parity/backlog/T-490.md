## User story
As the reviewer of a redesign, I want proof that the ten screens pass axe with zero critical findings and that a box can be drawn and approved without a pointer, so that "accessible" is evidence, not a claim.

## UX flow (LabelDesk words)
1. **Run `node scripts/a11y-scan.mjs`** — it signs in, visits Home, overview, Upload, Annotate, editor, Dataset, Versions, Train, Models and Deploy at 1440 and 375, in light and dark, with and without reduced transparency, and prints one line per route: critical, serious, other. [error: a route that cannot load prints its status and fails the run instead of passing silently]
2. **Run `node scripts/keyboard-path.mjs`** — it opens an image from the board, draws a box with `B`, presses `→` for the next image and `A` to approve, using only keys, and asserts the image changed and the status became approved. [error: a missing shortcut fails with the step that did not fire]
3. **Contrast, in two places** — the suite measures the pairs the browser actually paints: the `oklch()` fallbacks in `index.css` as text, and the live computed colours the scan reads back from the running app after `applyTheme()` has derived them from the seed. Both use one `contrastRatio()` from `lib/contrast.ts`; a pair that drops below its threshold fails with the two colour strings. [error: a token that resolves to `transparent` or a gradient is reported as "unmeasurable", never silently passed]
4. **A human reads `docs/a11y/keyboard-path.md`** — the documented order (rail → header primary → content → row actions), the shortcuts and the escape hatches.

## Tests to write first
pytest — `apps/backend/tests/test_a11y_scan.py`:
- none — no backend surface: the harness drives the browser against endpoints that already exist.
node — `apps/frontend/tests/contrast-math.test.mjs`:
- `test_body_and_muted_pairs_pass` — from the `index.css` fallbacks, `--foreground` on `--background` and `--muted-foreground` on `--muted` each meet 4.5:1.
- `test_status_and_chip_pairs_pass` — `--success`, `--warning` and `--destructive` text on `--card` meet 4.5:1, and `bg-success/15`-style chips are measured as the composited fill, not as the raw hue.
- `test_button_ring_and_input_pass` — `--primary-foreground` on `--primary` meets 4.5:1; `--ring` and `--input` on `--card` meet 3:1.
- `test_ratio_is_symmetric_and_bounded` — `contrastRatio(a,b) === contrastRatio(b,a)`, 21 for black on white, 1 for a colour on itself.
- `test_unmeasurable_values_are_reported_not_skipped` — `parseColour('transparent')` and a gradient return `null`, and the runner lists them as failures with the selector.
- `test_scan_covers_ten_routes_and_both_widths` — the script's route table has ten entries and the width list is `[1440, 375]` (source assertion), so a screen cannot quietly drop out of the audit.

## Acceptance criteria
- [ ] `node scripts/a11y-scan.mjs` reports zero critical and zero serious findings on the ten routes at 1440 and 375, light and dark.
- [ ] `node scripts/keyboard-path.mjs` completes open → draw → next → approve with no pointer and asserts the approved status.
- [ ] Every pair in `PAIRS` is asserted against the colours the app really paints, so a token or seed change that breaks one fails a test.
- [ ] `docs/a11y/keyboard-path.md` documents the focus order and every shortcut the path uses.
- [ ] Empty, loading and error states above all render: the scan runs on a project with data and on an empty project, and the empty project's findings are reported separately.
- [ ] Workspace A cannot see workspace B's data: the scan uses one demo workspace and asserts a 404 page for a foreign slug in the same run.
- [ ] No flag: the harness is the gate for every other E card.

## Notes for the implementer
Measure the app, not the design file: REDESIGN §10.2's twelve hex pairs (`#1B1A21`, `#FCFBFF`, `#5B4BE0`, …) are the frames' colours, and the running app derives every role from the HCT seed `#3b6cf6`, so those literals describe nothing that ships. Read `index.css`'s `oklch()` fallbacks for the static half and the browser's computed values for the derived half. `color-contrast` "incomplete" is a failure here, not a warning — `scripts/contrast-audit.mjs` already pixel-samples it, so run it for any route axe marks incomplete and record the result in the PR.
