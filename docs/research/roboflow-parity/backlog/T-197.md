## User story
As a data engineer, I want to stretch, centre-crop or pad (black, white, mirrored) to an exact size and keep every box where the object actually is, so that an aspect-critical dataset is neither distorted nor starved.

## UX flow (LabelDesk words)
1. **Wizard → step 3 → Resize** — width, height, and a mode select with six entries: *Stretch to exact*, *Fill (centre crop)*, *Fit within (black edges)*, *Fit within (white edges)*, *Fit within (mirror edges)*, *Fit within (keep aspect)*. Each option carries its trade-off in the label's hint: "edges are cropped", "letterboxed in black", "mirrored padding", "longest side = target". [empty: resize off] [loading: n/a] [error: "Width and height are required." under the fields]
2. **Preview** — the sample panel (T-199) redraws with boxes hugging the object in every mode.
3. **Downsize only** — with the default "Never enlarge" on, an image smaller than the target keeps its own size and the preview says "kept 480×360 — smaller than the target". [empty: n/a] [error: n/a]

## Notes for the implementer
`fill` is crop-then-resize: compute the centre square in source pixels, crop, then resize — never resize first, or the labels drift on non-square sources. Reuse `_map_points` with the existing `(W,H,NW,NH)` arguments so obb corners stay exact.
