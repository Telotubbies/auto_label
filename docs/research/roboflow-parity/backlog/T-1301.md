# T-1301 — `/healthz` and `/readyz`, and a Compose that waits for them

| Field | Value |
| --- | --- |
| Wave | O (security, monitoring, performance) |
| Area | Monitoring |
| Size | 2 agent-hours |
| Role | R3 backend |
| Skills | ponytail, test-driven-development, verification-before-completion |
| R7 security review | no — the payload is four booleans, no internals |
| Depends on | T-1300 (the readyz line is logged with a request id) |
| Feature flag | none |

## Problem
`GET /api/health` returns `{"ok":true,"service":"labeldesk"}` without touching the database
(`app/main.py:84-86`). The Compose stack has no `api` healthcheck at all, so `web` starts serving
before the API can answer, and the recovery runbook's "verify health" step reports green while the
queue is wedged or the data volume is full.

## Design
- `app/routers/health.py` (new, ~55 lines):
  - `GET /api/healthz` → `{"ok": true}`, no dependency, no DB, no disk touch. Liveness only.
  - `GET /api/readyz` → runs four checks and answers 200 or 503 with
    `{"ok": bool, "checks": {"db": bool, "data_dir": bool, "secret": bool, "worker": bool}}`:
    - `db`: `SELECT 1` through the session factory, 2 s budget;
    - `data_dir`: write and delete a 1-byte temp file under `DATA_DIR`;
    - `secret`: `bool(SECRET)` (never its length or value);
    - `worker`: `Worker` row for this process fresher than `LD_WORKER_STALE_S` when
      `LD_EMBEDDED_WORKER=1`, else `true` (a separate worker process reports itself).
  - Both rate-limited (30/min/IP) through `ratelimit.limit`, and neither appears in a non-GET form.
- Each check is one function returning `bool`, so a failure names itself in the payload and in the log
  line without leaking a path, a DSN or an exception string.
- Keep `GET /api/health` exactly as it is (runbooks and `docs/DEPLOY.md` quote its payload).
- `deploy/docker-compose.yml`: `api` gains
  `healthcheck: test: ["CMD", "python", "-c", "import urllib.request;urllib.request.urlopen('http://localhost:8000/api/readyz')"]`,
  `interval: 10s`, `timeout: 4s`, `retries: 6`, `start_period: 30s`; `web` gains
  `depends_on: api: {condition: service_healthy}`.

## Files
Exclusive:

## Tests to write first
`apps/backend/tests/test_healthz.py`:
- `test_healthz_touches_no_database` — monkeypatch the session factory to raise; `/api/healthz` is 200.
- `test_healthz_is_200_when_the_app_is_up` — plain call.
- `test_readyz_is_200_when_every_check_passes`.
- `test_readyz_is_503_and_names_the_failing_check` — one broken dependency per case: DSN to a closed
  port, `DATA_DIR` made read-only (skip on Windows), `SECRET=""`, a stale worker row.
- `test_readyz_never_leaks_internals` — no DSN, no path, no exception text in the body or the log.
- `test_health_still_answers_the_documented_payload` — `{"ok":true,"service":"labeldesk"}`.
- `test_readyz_is_rate_limited` — the 31st call in a minute is 429.
- `test_compose_api_has_a_readyz_healthcheck` — parse `deploy/docker-compose.yml` (yaml) and assert the
  healthcheck command mentions `/api/readyz` and `web` depends on `service_healthy`.

## Acceptance criteria
- [ ] `/api/healthz` answers 200 with no database access.
- [ ] `/api/readyz` answers 200 when healthy and 503 naming the failing check otherwise.
- [ ] Neither endpoint reveals a path, a DSN, a secret or a stack trace.
- [ ] `GET /api/health` is unchanged.
- [ ] `docker compose up -d` starts `web` only after `api` is ready; `docker compose config` parses.
- [ ] Both endpoints are in `openapi.json` and the generated TS types.

## Notes for the implementer
Do not make `/api/readyz` superadmin-only: Caddy, Compose and the runbook call it without a session.
Its information content is four booleans, which is the whole reason to keep it to booleans. Do not add
an `X-Forwarded-For` trust rule here — that belongs to rate limiting (T-1309).
