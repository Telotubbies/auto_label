## User story
As an operator, I want `labeldesk` for platform work and the inference container for runtime work, with stable exit codes, so that a shell script can tell success from an auth failure.

## UX flow (LabelDesk words)
1. **The boundary, printed once** — `labeldesk --help` opens with one line: "`labeldesk` manages projects, datasets, models and jobs. To run a model on your own hardware, use the inference container (`labeldesk doctor` prints the command)." No second binary, no mixed vocabulary.
2. **Platform commands** — today's `whoami`, `models`, `upload`, `export`, `train`, `predict`, plus `workflow list|run|deploy`, `batch create|status|abort`, `job list|wait`, and `key list` (read-only here; rotation is area 7's).
3. **Every command has `--json`** — one line of JSON on stdout, human text otherwise; `--no-wait` returns the job id immediately, `--wait` polls and prints the result.
4. **Exit codes** — `0` success, `1` error, `2` auth (401/403), `3` not found (404). `[error: a 402 quota refusal]` prints "the plan's allowance is used up" and exits `1`. `[empty: no jobs]` prints "No jobs." and exits `0`.
5. **`labeldesk doctor`** — one command that prints the API base URL, whether the key resolves (`whoami`), the key's scopes, and the exact `docker run` line for the self-hosted server.

## Acceptance criteria
- [ ] Four exit codes are stable and documented, and every command honours `--json`.
- [ ] `--no-wait` returns an id, `--wait` returns the finished result, and the two are one flag apart.
- [ ] `--help` states which tool does runtime work, and `doctor` prints the container command.
- [ ] Empty, loading and error states above all render (empty job list, quota refusal, auth failure).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — a 404 maps to exit 3 and keeps the server's sentence on stderr.
- [ ] No flag: additive commands; existing command names and output shapes are unchanged.

## Notes for the implementer
Do not create a second entry point. `labeldesk infer` stays the hosted single-image call it already is; the runtime-side work belongs to the container, and the help line is the only place that says so.
