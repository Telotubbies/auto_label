## User story
As a workspace lead, I want to know which camera fleet, folder or person burned the credits, so that the next
budget conversation starts from evidence.

## UX flow (LabelDesk words)
1. **Usage & billing → Overview → `Attribution`** — a segmented control `API keys` / `Folders` / `Members` and the
   same date range as the chart.
2. **API keys** — rows `key name · credits · share %` with a bar. [empty: the segment is hidden, not shown as zero]
3. **Folders** — a collapsible list (folder, its credits, project count) with a checkbox per folder; deselecting a
   folder removes its direct usage while its children stay — roll-up is the default, not a mode.
4. **Members** — spend per person plus a synthetic last row `Workspace usage (no member)` for storage, background
   jobs and plain API-key traffic, with the note `The member rows do not add up to the total — that row is why.`
   An auth-group dropdown narrows the list.
5. **Usage type** — a two-level drill-down (`Training › by project`, `Inference › by model`) that only lists
   categories which actually recorded usage.
6. **`[empty]`** a segment with no data disappears; if every segment is empty the whole card reads
   `No attribution for this range.` + `Clear range`. `[loading]` three skeleton rows per segment.

## Backend changes
- Models/schema: none beyond T-408. Two stamps are added where events are written:
  `UsageEvent.meta["user_id"]` and `meta["api_key_id"]` (the latter exists from T-398 for hosted inference);
  `metering.record(...)` accepts `meta` already, so the call sites pass the actor.
- Routers: `GET /api/ws/{ws}/usage/attribution?since&until&by=key|folder|member&group=` →
  `{by, rows: [{id, label, credits, share}], rollup: [{folder_id?, label, credits, children: [...]}], unknown: {credits}}`;
  `by=member` also returns `no_member_credits`.
- Services/jobs: `services/metering.py` — `attribution(db, ws, since, until, by, group=None) -> dict` (one grouped
  query per dimension, joined to `Project` for the folder and to `ApiKey`/`User` for labels; events without an
  actor land in the unknown bucket).
- Permissions + workspace isolation: `workspace.read`; every join carries `workspace_id`.
- Secrets/safefetch: none — key labels are names, never values.
- OpenAPI: yes.

## Acceptance criteria
- [ ] Spend can be read by key, folder and member for one range, with shares that sum to the range total.
- [ ] The no-member bucket exists and the panel states that member rows do not sum to the total.
- [ ] Folder roll-up is the default and deselecting a parent keeps its children.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no attribution card and no route.

## Notes for the implementer
The unknown bucket is not a bug to hide: it is storage, background jobs and key-only traffic. Label it
`Workspace usage (no member)` and never fold it into a person's row.
