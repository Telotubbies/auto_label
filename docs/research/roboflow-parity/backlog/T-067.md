## User story
As a field engineer, I want to shoot a single frame or one frame every N seconds from the laptop on my
desk so that a station's training data never has to round-trip through my phone gallery.

## UX flow (LabelDesk words)
1. **Upload** — "Use camera" opens a sheet: device picker (default camera first). [error: no camera or
   permission denied → "No camera available — allow camera access in the browser, or drop files
   instead", with the drop target still on screen]
2. **Upload · camera sheet** — mode chips **Photo**, **Interval** and **Clip**; Interval takes seconds per
   frame (0.2–60) and stops at 1,000 frames. A live line reads "Every 2 s · up to 30 frames in 60 s".
   [loading: a dimmed viewfinder with a spinner until the stream starts]
3. **Upload · camera sheet** — Photo: the shutter adds one 1280×720 JPEG to the sheet as a thumbnail;
   Interval: **Start** captures until stopped or the cap, then "Added 14 frames to upload"; Clip: records
   up to 300 s and adds one video file ("Add video to upload"), after which the frame-extraction dialog
   (T-072) decides which frames become images. [error: the recorder cannot produce a supported container →
   "This browser cannot record video — use Photo or upload a file"]
4. **Upload** — the sheet's files join the normal pre-flight list with their timestamps as names; the
   batch name field is unchanged. [empty: closing the sheet with nothing captured adds nothing]

- Route: none (rendered inside `/:ws/p/:project/upload`).
- Nav entry: none.
- Components:
  - `apps/frontend/src/features/project/CameraCapture.tsx` (new) — gets a `MediaStream` via
    `getUserMedia({video: {deviceId}})`, draws to an `OffscreenCanvas`, converts to `File` via
    `canvas.convertToBlob({type: "image/jpeg", quality: 0.9})`, `onCapture(files: File[])`; Clip mode uses
    `MediaRecorder` on the same stream (300 s timer, one `.webm` file), handles
    `NotAllowedError`/`NotFoundError` and a missing `MediaRecorder.isTypeSupported` with the copy above;
    releases the tracks and stops the recorder on close and on unmount.
  - `apps/frontend/src/lib/capture.ts` (new) — pure: `intervalPlan(secondsPerFrame, durationS)` →
    `{frames, capped}` (cap 1,000), `clipPlan(elapsedS)` → `{remaining, capped}` (cap 300),
    `captureName(index, at)` → `camera_20261117_143012_003.jpg`.
- API client: none.
- Feature flag: `task_67` via `useFlag`; off ⇒ the "Use camera" button is absent.

## Acceptance criteria
- [ ] "Use camera" is present only with the flag on and only when `navigator.mediaDevices` exists.
- [ ] Photo mode adds exactly one file per shutter press; interval mode adds the planned count and stops
      at 1,000; clip mode adds one video file and stops at 300 s.
- [ ] Denied permission and a missing device each show a readable message and leave the drop target usable.
- [ ] Closing the sheet stops the stream (no camera light left on) and adds no file.
- [ ] Empty, loading and error states above render.
- [ ] Flag off ⇒ no camera entry point anywhere on Upload.
- [ ] Workspace A cannot see or change workspace B's data: captured files upload only through the
      project-scoped route (404 otherwise).

## Notes for the implementer
Capture at 1280×720 maximum so a laptop camera cannot blow the upload budget. Clip mode produces WebM when
MP4 is unavailable — the backend accepts `.webm` (`VIDEO_EXT`), and the extraction dialog is the next step,
not a second recorder. No audio track is captured.
