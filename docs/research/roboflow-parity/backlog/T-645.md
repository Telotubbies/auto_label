## User story
As a QA lead answering a complaint about forty labels, I want a rubric run that returns a verdict, one line of reasoning and a score per annotation, so that I can filter the failures and defend a decision without re-reading forty images.

## UX flow (LabelDesk words)
1. **Settings → Privacy** (`/:ws/settings/privacy`) — one admin row, "Allow images and prompts to be analysed on a hosted model", off by default, with the sentence "Off means only a model running inside this deployment is used." Turning it on is audited. [error: a non-admin sees the row read-only with "Only an administrator can change this"]
2. **Project → Review → Judge** (`/:ws/:project/qa?tab=judge`) — the rubric picker shows three default questions and is editable. [empty: "No judge run yet — pick a rubric and a scope"]
3. **Scope** — filter, current selection, or the suspect queue; pressing Run queues a job and the panel counts items as they finish. [loading: "Judged 120 of 500"] [error: "vLLM not reachable at …" with Try again]
4. **Results** — a table of verdict / reason / score / open in editor, filterable to failures, saved as a report row per run.
5. **Flag off** — no Judge tab, no rubric endpoint, no settings row.

## Backend changes
- Models/schema: new module `app/models/judge.py` with `JudgeRun` (`id`, `workspace_id`, `project_id`, `rubric` JSON, `scope` JSON, `status`, `counts` JSON, `created_by`, `created`) and `JudgeVerdict` (`id`, `run_id`, `project_id`, `image_id`, `annotation_id`, `verdict`, `reason`, `score`, `created`), registered in `models/__init__.py`. The hosted-model switch is `workspaces.ai_egress` from T-640 — no second column.
- Routers: new `app/routers/judge.py` — `POST /api/ws/{ws}/projects/{project}/judge` (rubric with 1–5 questions, `scope: {"kind": "filter"|"selection"|"suspects", ...}`, `limit` ≤ 500) → 202 with the run; `GET .../judge` → the last 10 runs; `GET .../judge/{run_id}` → run plus verdict rows; 422 for an empty rubric, 409 "image analysis on a hosted model is off for this workspace" when the gate refuses, 403 for a non-reviewer, 404 for another workspace's run.
- Services/jobs: `services/judge.py` (new) — `DEFAULT_RUBRIC` (class right / box tight / object fully inside), `scope_images(db, project, scope, limit)`, `judge_one(vlm, im, ann, rubric) -> {"verdict", "reason", "score"}`, `run_job(job)` writing one `JudgeVerdict` per annotation and `counts` on the run; job kind `judge` added to `LOCAL_JOB_KINDS`; `adapters/vlm_ad.py` gains `judge(im, box, cls, rubric)` returning a JSON-schema-constrained object; the crop uses the existing 15 % margin.
- Permissions + workspace isolation: `reviewer` to queue and read a run, `project.models` not required; every query is scoped by `project_ctx` and the run id is checked against `c.project.id` (404 otherwise).
- Secrets/safefetch: `services/secretbox.py` — a hosted endpoint token, if an operator stores one in a workspace row, is encrypted through `secretbox.encrypt`/`decrypt`; this card stores no key, and no crop leaves the deployment unless `workspaces.ai_egress` is on.
- OpenAPI: yes — regenerate (`python tools/export_openapi.py`, `npm run gen:api-types`).

## Acceptance criteria
- [ ] A rubric of one to five questions runs over a filter, a selection or the suspect queue and stores one row per annotation with verdict, reason and score.
- [ ] A failing item is counted and does not abort the run; an unreachable model reports a readable error with Try again.
- [ ] A workspace admin can allow or refuse analysis on a hosted model; refusing keeps every later judge call at 409.
- [ ] Empty, loading and error states above all render, including a run with no annotations in scope.
- [ ] Workspace A cannot read or queue workspace B's runs (404, not 403).
- [ ] Flag off ⇒ the tab, the endpoint and the settings row are absent and no stored data is read.

## Notes for the implementer
The judge answers about a crop, not an image: reuse the 15 % margin from `vlm_ad.verify` so the question "is the box tight" sees the same framing. Score is the model's own 0–1 confidence in its verdict, never a copy of the detector's confidence. `verdict` is `pass` or `fail`; a human confirm/dismiss stays a separate field so a judge disagreement is visible.
