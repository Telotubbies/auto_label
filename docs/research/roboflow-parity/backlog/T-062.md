## User story
As a reviewer, I want one search box, one Filters button with a count and three saved views instead of
eight dropdowns so that the grid is the work again and my slice survives a page refresh.

## UX flow (LabelDesk words)
1. **Dataset · Images** — header reads "40 uploaded · 24 approved"; below it one row: search input,
   **Filters** button with a badge (`Filters · 3`), **Saved views** chips
   ("Needs review", "Missing negatives", "Test set"). [empty: no images at all → "No images yet —
   upload 20 images or start from the 40-image demo set."] [loading: 12 tile skeletons, filter row
   stays interactive]
2. **Dataset · Images** — pressing **Filters** opens a popover with status, split, class, tag, batch,
   annotation count, size (MP), aspect and quality; each row applies immediately and the badge counts
   active filters. [empty inside popover: a class/tag list with no values yet reads "No tags yet"]
3. **Dataset · Images** — the chosen slice becomes a readable line of chips above the grid
   (`split: test ×`, `class: helmet ≥ 2 ×`); each chip removes its own term from the query.
4. **Dataset · Images** — no results now reads "No images match these 3 filters" with **Clear filters**,
   never the upload empty state. [error: the grid shows "Could not load images — retry" and keeps the
   filter row]
5. **Dataset · Images** — clicking a saved view sets `?q=` and `?view=needs-review`; the chip stays
   pressed, and the URL can be pasted to a colleague.

      return for its own workspace (404 otherwise).

## Notes for the implementer
Saved views are URL presets, nothing else — do not add a backend table for them (the evidence records
that saved views do not exist in the source product; LabelDesk's URL is the saved view). Keep the
reviewer-default `status=done` behaviour: `needs-review` is the only view that overrides it.
