## User story
As a workspace admin, I want to tag, move or delete a mixed selection across projects in one action, so that a cleanup does not become one project at a time.

## UX flow (LabelDesk words)
1. **Select tiles** — a checkbox appears on hover and is always present in the keyboard path; the sticky bar reads `12 selected · 3 projects` with `Tag`, `Add to project`, `Delete`, `Clear`. [empty: nothing selected → no sticky bar]
2. **Tag** — one field, comma separated; `Apply` writes to every selected image and reports `Tagged 12 images. 1 failed — no permission in Line A.` [error: partial failure is reported per project, never silently dropped]
3. **Add to project** — pick a destination project; the response says `Copied 12 images. 3 were duplicates and were skipped.` (SHA-256 check reused from upload).
4. **Delete** — confirm sheet names the count and the projects: `Remove 12 images from 3 projects? They go to each project's deleted state and can be restored by an admin.` [error: any project where the caller is not a reviewer is listed and skipped, with the action still applying to the rest]
5. **Run a workflow / export** — both live in T-029 (they need select-all); the bar shows them disabled with the reason `Export needs Select all.`

## Backend changes
- Models/schema: none.
- Routers: `routers/assets.py` gains `POST /bulk` body `{ids: [str], action: "tag"|"untag"|"add_to_project"|"delete", value?: str, target_project?: str}` → `{applied: n, skipped: [{project, reason}], changed_projects: n}`; caps `ids` at 5 000.
- Services/jobs: `services/asset_bulk.py` (new) — resolves each id's project, checks `project.review` (tag/delete) or `project.annotate` (add_to_project), then reuses `images.set_annotations`/tag writes and the upload dedupe (`sha256` pre-check) for copies; one transaction per project, committed in order, so a later failure leaves earlier projects applied and reported.
- Permissions + workspace isolation: ids outside the caller's readable projects are skipped with a reason, never 403 for the batch; a `target_project` outside the workspace 404s.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] Tag, add-to-project and delete apply to a mixed selection and report applied/skipped per project.
- [ ] A permission gap skips that project and still completes the rest; it never fails the whole batch.
- [ ] Empty and error states above all render (no selection bar; partial-failure list).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
- [ ] Delete is a soft delete, consistent with the project grid.

## Notes for the implementer
Do not invent a second dedupe rule: call the same `sha256` check the upload path uses. Commit per project, then report — a global rollback would hide which project succeeded.
