## User story
As a security engineer, I want to prove one write into our bucket before we commit, and to see whether the key we own was used successfully, so that a failed policy is caught in the trial rather than on the first incident.

## UX flow (LabelDesk words)
1. **Settings → Storage → `Connect a bucket`** (`/:ws/settings/storage`) — fields: endpoint, bucket, region, prefix, and either an access key pair or a role name. `Save` is disabled until endpoint, bucket and one credential form are present. [error: "That endpoint is not a public HTTPS address." beside the field]
2. **`Test write`** — creates and deletes one probe object under the prefix, then reports "Wrote and deleted a probe object in 214 ms." [loading: a spinner in the button and "Testing…" beside it] [error: "The bucket policy denies PutObject on acme/brand/." for a denial, "The bucket answered 404 — check the name and region." for a miss, "This deployment cannot reach a customer bucket yet." for the unavailable driver]
3. **`Use as the primary store`** — disabled in this card with "Switching the primary store needs the migration step; it is not available in this deployment." and the existing-data warning written out in full.
4. **`Key reference`** — ARN and region fields, then the state row: "Last successful decrypt — never" or a timestamp, plus "If the key is disabled, exports pause and the page says so." [error: "That ARN is not a key ARN — it should start arn:aws:kms:."]
5. **A disabled key** — the Storage card shows the destructive banner "Key disabled — exports paused" and the export dialog refuses rather than producing a partial bundle.

## Backend changes
- Models/schema: no new table — `bucket_config` and `kms_ref` already exist from T-768; both are written encrypted.
- Routers: `app/routers/storage.py` — `PUT /api/ws/{ws}/storage/bucket` (422 on a non-HTTPS endpoint, an empty bucket or a prefix with `..`), `POST …/storage/bucket/test` (200 `{ok, ms}` or 409 with `{code: denied|not_found|not_available}`), `PUT …/storage/key` (422 on a non-KMS ARN), `GET …/storage/key/state` (`{state, last_decrypt}`), `POST …/storage/mode` accepts `bucket` only when a probe has succeeded for the current config.
- Services/jobs: `app/services/bucket_probe.py` (new) — `PROBE_KEY = "labeldesk-probe.txt"`, `probe(driver, prefix) -> dict` (put, read back, delete, measure ms), `classify(error) -> str` mapping driver exceptions to the three codes, `denied_copy(code, prefix) -> str`. `services/storage_driver.MockBucketDriver` gains a `deny` switch so the suite can produce each code; `UnavailableDriver` raises the unavailable code.
- Permissions + workspace isolation: `workspace.update` for every write, `workspace.read` for the state; `bucket_config` is only ever read for the calling workspace and is written through `secretbox.encrypt_config(config, ("access_key", "secret_key"))`.
- Secrets/safefetch: `services/secretbox.encrypt_config` on write and `decrypt` on use; `services/safefetch.check_url` validates the endpoint before it is stored, so a bucket endpoint cannot be an internal address.
- OpenAPI: yes.

## Tests to write first
pytest — `apps/backend/tests/test_bucket_probe.py`:
- `test_the_probe_writes_reads_and_deletes_one_object` — mock driver → `POST …/bucket/test` → `ok` is True, the mock holds no probe key afterwards, and `ms` is a number.
- `test_a_denied_putobject_names_the_prefix` — mock driver with `deny="denied"` and prefix `acme/brand` → 409 `code=="denied"` and the copy contains `acme/brand/`.
- `test_the_unavailable_driver_answers_not_available` — the default driver → 409 `code=="not_available"` and nothing is written anywhere.
- `test_an_http_endpoint_is_422` — `endpoint="http://s3.example"` → 422; `"https://s3.example"` → 200.
- `test_credentials_are_stored_encrypted` — after `PUT …/bucket`, the raw `workspaces.bucket_config` value for the secret does not contain the plaintext, and `secretbox.decrypt` recovers it.
- `test_a_non_kms_arn_is_422` — `arn:aws:s3:::acme` → 422 with the `arn:aws:kms:` sentence; a valid ARN stores `last_decrypt: null`.
- `test_primary_store_requires_a_passing_probe` — `POST …/storage/mode {"mode":"bucket"}` before any probe → 409; after a passing probe → 200.
- `test_flag_off_hides_every_route` — with the flag off → all five routes 404.

node — `apps/frontend/tests/bucket-probe.test.mjs`:
- `test_each_denial_code_has_one_sentence` — `denialCopy('denied','acme/')`, `('not_found')` and `('not_available')` each return a distinct non-empty sentence.
- `test_the_probe_result_names_the_latency` — `probeLine({ok: true, ms: 214})` reads "214 ms".
- `test_a_key_with_no_decrypt_reads_never` — `keyStateLine({last_decrypt: null})` reads "Last successful decrypt — never".

## Acceptance criteria
- [ ] A bucket config is saved with its credential encrypted and never echoed back.
- [ ] `Test write` reports latency on success and one of three named denials on failure.
- [ ] Switching the primary store is refused until a probe has passed for the current configuration.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no bucket form, no key card, all routes 404, and storage stays `DATA_DIR`.

## Notes for the implementer
Owner-gated: whether we may hold a customer's bucket credential at all, and what "disable the key and our access stops" means in the contract (INDEX §4.3). The probe runs through the driver, so this deployment answers "not available" instead of pretending; do not add boto3 to make the demo greener. `safefetch.check_url` is mandatory on the endpoint — a bucket URL is an SSRF target the day it ships.
