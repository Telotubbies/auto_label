## User story
As a workflow author, I want the pipeline to post its result to my endpoint, so that a detection reaches my own system
without a separate integration.

## UX flow (LabelDesk words)
1. **Workflow editor → `Add step` → `Send to a URL`** — a block with `URL`, `Method` (POST/PUT), `Headers` (key/value
   rows), `Body` (`JSON` or `Multipart`), `Include the annotated image` (multipart only), a field-mapping list
   (`body.results[].class` ← `detections[].label`) and `Timeout` (1–30 s, default 5).
2. **Delivery mode** — `Wait for the answer` (default, debugging) or `Fire and forget` with the warning
   `In fire-and-forget mode a failure is never reported to the run.`
3. **Cooldown** — `Minimum seconds between calls` (default 5, 0 disables); a burst is throttled and the run records
   `throttled: true` instead of calling.
4. **Run result** — the sink step shows `Sent · 200 · 84 ms` or `Failed · connection refused`; a blocked destination
   shows `That address is not allowed — use a public endpoint.`
5. **`[empty]`** a workflow with no sink still returns its result in the API response; the block is optional.
6. **`[error]`** a destination that redirects is refused (`Redirects are not followed.`), and an air-gapped deployment
   refuses the block at save time with `Outbound calls are disabled in this deployment.`

## Backend changes
- Models/schema: none — the block lives in `Workflow.blocks` JSON (validated at save).
- Routers: `routers/workflows.py` — the existing validate-on-save path accepts `{"type": "sink", "kind": "webhook",
  "url", "method", "headers", "body", "timeout_s", "cooldown_s", "mode"}`; `400` with the field name for each rule.
- Services/jobs: `services/workflows.py` — `BLOCK_TYPES` unchanged, `SINK_KINDS` gains `"webhook"`, and `_block`
  validates the new fields (URL via `safefetch.check_url`, header names against a control-character denylist,
  `timeout_s` 1–30, `cooldown_s` 0–3600); `services/webhook_sink.py` (new) — `send(block, payload, image_bytes=None)
  -> dict` (one `http.client` call with the pinned connection logic reused from `safefetch`, no redirects, response
  body capped at 64 KB), `throttled(db, workflow_id, cooldown_s) -> bool` using the last `Job` for that workflow;
  `services/workflow_runner.py` executes the block and records `{status, http_status, ms, throttled, error}`.
- Permissions + workspace isolation: the block belongs to a workflow inside `c.ws`; the sink call carries no credential
  from the workspace and never includes a key or a member's data beyond the run payload.
- Secrets/safefetch: URL checked by `safefetch.check_url` at save **and** at call time (DNS can change); no redirect is
  followed; headers are stored in the workflow JSON, so the UI warns `Do not put a secret here — use the webhook
  subscription if you need signing.`
- OpenAPI: yes (the workflow schema is described in the existing route).

## Frontend changes
- Route: `/:ws/p/:project/workflows/:id` (existing editor).
- Components: `features/workflows/WebhookSinkForm.tsx` (new) — the block form; mounted by the existing block editor.

## Acceptance criteria
- [ ] A workflow can post its result (or a multipart image) to a public URL and reports the outcome on the run.
- [ ] Private, loopback and redirecting destinations are refused at save and at call time.
- [ ] Fire-and-forget never reports a delivery failure as a run failure; cooldown suppresses bursts.
- [ ] Empty, loading and error states above all render (no sink, refused destination, throttled).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the block is not offered and cannot be saved.

## Notes for the implementer
Reuse `safefetch`'s pinned-connection helper rather than writing a second HTTP client; the check runs twice because DNS
can change between save and call. Fire-and-forget means "the request is queued", not "the request succeeded".
