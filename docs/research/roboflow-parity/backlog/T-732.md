## User story
As an IT engineer at a bank that will never let a frame leave the building, I want to install from one archive, paste one licence file and see it verified locally, so that air-gapped is a deployment rather than a promise.

## UX flow (LabelDesk words)
1. **No licence** — the deployment still starts and reports `ยังไม่มีใบอนุญาต — ใช้งานได้ 30 วันเพื่อทดลอง` with the machine fingerprint on screen, so the customer can send us the string. [empty: that sentence and the fingerprint]
2. **Upload a licence** — a signed JSON file is verified on the box; on success the state reads `ใบอนุญาตใช้ได้ถึง {date} · เหลือ {n} วัน · {seats} ที่นั่ง`. [loading: `กำลังตรวจใบอนุญาต`] [error: `ลายเซ็นไม่ถูกต้อง — ปฏิเสธไฟล์` and nothing is stored]
3. **A licence for another machine** — 409 `ใบอนุญาตนี้ออกให้เครื่องอื่น — ส่งลายนิ้วมือเครื่องนี้ให้ผู้ให้บริการ`. [error: that sentence with the current fingerprint]
4. **Expiry** — after the expiry date there is a 90-day grace, then `หมดอายุแล้ว — โหมดอ่านอย่างเดียว`: writes are refused with 402 and every export and download still works, because a customer's data is never held hostage. [error: that sentence on every write attempt]
5. **Nothing calls home** — a verification is local arithmetic over the file; the health line records `ตรวจสอบล่าสุด {time}` and never an outbound request.

## Backend changes
- Models/schema: none — the licence is a file under `DATA_DIR/licence.json` and the install identity under `DATA_DIR/instance.json`; state is read on demand and cached for 60 s.
- Routers: `app/routers/licence.py` (new), prefix `/api/licence`; `GET ""` (authenticated, any member) → `{status, expires, days_left, seats, features, fingerprint, last_verified}`; `POST ""` (owner or admin, `multipart` file ≤ 64 KB) → the same state or 400; `DELETE ""` (owner) → `{status: "missing"}`. 400 for a malformed file, 401 for a bad signature, 409 for a fingerprint mismatch.
- Services/jobs: `app/services/licence.py` (new) — `LicenceProvider` protocol with `FileLicenceProvider` (Ed25519 verify through `cryptography`, the public key from `LD_LICENCE_PUBKEY`) and `MockLicenceProvider` (deterministic, tests only); `machine_fingerprint()` (sha256 of the install id and the hostname, 16 hex characters); `parse(file) -> Licence`; `state() -> dict`; `read_only()`; `require_write(db)` dependency helper. No job, no scheduler, no network call anywhere in the module.
- Permissions + workspace isolation: the licence is deployment-wide, so `GET` needs only an authenticated member and `POST`/`DELETE` need `workspace.update` on the deployment's home workspace; an unlicensed deployment never 404s a read to hide the state.
- Secrets/safefetch: `services/secretbox.py` — not used, because the box holds only a **public** key; the licence payload is a signature and a claims object and nothing secret. `services/safefetch.py` — deliberately not called: an air-gapped install must verify with the cable out, and a test asserts no outbound call happens.
- OpenAPI: yes — three routes and their state schema.

- `test_a_signed_file_verifies_and_reports_its_claims` — sign a payload with a generated Ed25519 key, point `LD_LICENCE_PUBKEY` at it → `GET /api/licence` reads `status: "valid"`, the expiry, the seats and the features.
- `test_a_tampered_payload_is_401_and_stores_nothing` — flip one claim byte → 401 `ลายเซ็นไม่ถูกต้อง` and `DATA_DIR/licence.json` does not exist.

- `test_no_licence_is_a_thirty_day_trial_not_an_error` — no file → `status: "missing"` with `trial_days_left: 30` and writes allowed.
- `test_verification_never_calls_out` — with `safefetch.post` replaced by a raising stub, `GET /api/licence` still answers.
- `test_the_routes_are_hidden_while_the_flag_is_off` — 404 for the three routes and `read_only()` false.
- `test_a_member_cannot_upload_a_licence` — a member token is 403 on `POST`, 200 on `GET`.

## Acceptance criteria
- [ ] A signed licence verifies locally and its expiry, seats and features are reported; a tampered file is refused and nothing is stored.
- [ ] A licence issued to another machine is refused with the current fingerprint in the message.
- [ ] Expiry has a 90-day grace, then writes are 402 while exports and downloads keep working.
- [ ] Empty, loading and error states above all render — no licence is a stated 30-day trial, never a 500.
- [ ] Workspace A cannot see or change workspace B's data — N/A for the licence itself (one deployment-wide state and no route accepts a workspace id), and every other route keeps 404, not 403, for a foreign id.
- [ ] Flag off ⇒ the three routes 404, no read-only mode exists and the product is unchanged.

## Notes for the implementer
Owner-gated: whether LabelDesk licenses self-hosted inference and/or weights, and under what terms (INDEX §4.3, decision 3). Until the owner rules, this card ships the interface, a mock provider and the verifier, sets no price and charges nothing. R7: the box holds only a public key, the licence file is an Ed25519 signature over a claims object, the fingerprint is a hash of the install id and the hostname, and the state is cached for 60 s. Stored and how long: `DATA_DIR/licence.json` and `DATA_DIR/instance.json` until the customer deletes them; the state is not a secret and is readable by any authenticated member so a support call can start with the fingerprint. Failure direction: a bad signature stores nothing and leaves the previous licence in force; an expired one never deletes data and never blocks an export — the safe state of a licence check is "still readable, no longer writable", because holding a customer's dataset behind a clock is not a business model. `deploy/offline/verify.py` is a thin CLI over the same `FileLicenceProvider`, never a second parser.
