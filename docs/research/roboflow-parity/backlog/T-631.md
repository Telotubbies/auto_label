## User story
As a customer whose label is not a box, I want to add a severity, a disposition and a required note, so that the inspection lives in the annotation instead of a spreadsheet beside the product.

## UX flow (LabelDesk words)
The builder is T-632; this card owns the document, its validation and the export shape.
1. **`GET /form`** — `{controls, version, usage}` where each control is `{key, kind, label, help, required, default, options[], scope, class_id}`. [empty: `controls: []` means the project has no extra fields and the editor looks exactly as today]
2. **`PUT /form`** — validates the whole document; a control kind outside `text|number|select|checkbox|rating`, a duplicate key, an empty label, or a `select` without options is refused with the index. [error: "Field 2 needs at least one option."]
3. **Removing a control already on labels** — 412 with the count per key: `{"detail": "This field is used by 3 labels — remove it from them first.", "in_use": {"severity": 3}}` and nothing is written.
4. **A save that misses a required field** — 422 "severity is required." and the image is untouched.
5. **Export** — every `annotation.fields` key rides along with the annotation in the existing JSON export; no new export format.

## Backend changes
- Models/schema: new `app/models/label_forms.py` with `LabelForm` (`id`, `workspace_id`, `project_id` unique FK CASCADE, `controls` JSON default `[]`, `version` Integer default 1, `created_by`, `created`, `updated`), registered in `app/models/__init__.py`. Table via `create_all`; no `ADD COLUMN` block. Annotation values live at `annotation["fields"] = {key: value}` — free JSON already.
- Routers: `routers/forms.py` (new), prefix `/api/ws/{ws}/projects/{project}/form` — `GET ""` (needs `annotator`) and `PUT ""` `{controls}` (needs `manager`); 422 for the shape errors above, 412 for a removal in use, 404 for a foreign project. Save-time validation is one call added to `routers/images.py::save_annotations`.
- Services/jobs: `app/services/label_form.py` (new) — `DEFAULT_CONTROLS = []`, `read(db, project)`, `validate(controls)` (returns the normalized list or raises 422 with the index), `usage(db, project_id, keys)` (counts `Image.annotations` carrying each key, bounded to 5000 images), `check_annotations(db, c, anns)` (required present, `select` value inside `options`, number is a number, rating 1–5 → 422 naming the label). No job kind.
- Permissions + workspace isolation: `GET` needs `annotator` so the editor can render the form for a labeler, `PUT` needs `manager`; `usage` and every row are filtered by `c.project.id`, so a foreign project is a 404.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] A manager saves a document of controls and `GET` returns it in order with its version.
- [ ] A malformed control is refused as a whole, naming the index, and nothing is written.
- [ ] Removing a control that annotations still carry is 412 with a per-key count.
- [ ] Empty, loading and error states above all render where the surface exists: `controls: []`, the 412 body, the 422 required-field sentence.
- [ ] Workspace A cannot read or write workspace B's form (404, not 403).
- [ ] Flag off ⇒ no form routes and annotation saves behave exactly as today.

## Notes for the implementer
Keep the document a list, not a tree: nested groups are the feature nobody asked for and the export gets a new shape for free. Values go in `annotation["fields"]` so the existing annotation contract, `ImageClass` counting and the JSON export all keep working untouched.
