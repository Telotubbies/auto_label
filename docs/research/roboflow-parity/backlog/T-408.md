## User story
As an admin reconciling a surprise charge, I want one row per credit charge with the feature and the minute, so
that "where did 40 credits go" is answerable without a support ticket.

## UX flow (LabelDesk words)
1. **Settings → Usage & billing → `Charges`** (`/:ws/settings/usage?tab=charges`) — a date range
   (`This cycle` / custom `From`/`To`), a `Feature` multi-select (`Training`, `Auto-label`, `Inference`,
   `Versions`) and `Search`. [loading: eight skeleton rows] [error: `Could not load charges.` + `Try again`]
2. **Table** — `When` (date + UTC clock), `Feature`, `Project`, `Credits`, `Actor`; newest first, endless scroll
   with the same cursor as the audit table. Footer: `412 charges · 64.20 credits`.
3. **`[empty]`** `No credit usage in this range.` with `Clear filters` when filtered, otherwise `Charges appear here
   as soon as this workspace trains, auto-labels or runs inference.`
4. **One link out** — a header link `How credits work` to the trust page (T-446) and an `Audit log` button that
   opens the security log, because the two logs are deliberately separate.
5. **`[error]`** a bad date range is a `400` shown inline under `From`; the table keeps its last rows.

## Backend changes
- Models/schema: new `CreditEvent` in `app/models/insights.py`:
  `id, workspace_id FK, project_id FK projects.id nullable, kind VARCHAR(24), credits FLOAT, meta JSON, created FLOAT`
  with `Index("ix_credit_events_ws_created", "workspace_id", "created")`. Registered by the existing
  `models/insights.py` re-export (`DOMAIN_MODULES` already includes it), so no `models/__init__.py` block is needed
  beyond the name re-export.
- Routers: `GET /api/ws/{ws}/usage/charges?since&until&kind&q&cursor&limit` in `routers/workspaces.py` →
  `{rows: [{id, created, kind, project: {slug, name} | null, credits, actor}], next, totals: {credits, count}}`.
- Services/jobs: `services/metering.py` gains `record_credits(db, ws, kind, credits, project_id=None, **meta)` and
  `ledger(db, ws, since, until, kinds, q, cursor, limit)`; `deps.charge(db, ws, amount, kind="")` writes the ledger
  row in the same transaction, and the four call sites pass their kind (`train`, `autolabel`, `infer`, `version`).
- Permissions + workspace isolation: `workspace.read`; every query filters `workspace_id == c.ws.id`.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] Every credit charge creates one ledger row with kind, project, credits and actor.
- [ ] The ledger sums to the same number the usage page shows for the cycle.
- [ ] The consumption log is separate from the security audit log and links to it.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no ledger route, no charges sub-tab, charging unchanged.

## Notes for the implementer
Write the ledger row inside `charge()` so a charge can never exist without a receipt. `kind` is the same literal
the credit table in `config.CREDIT_COST` uses; do not invent a second vocabulary.
