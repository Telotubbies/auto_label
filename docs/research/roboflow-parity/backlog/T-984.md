## User story
As a data scientist whose script calls `log_metric` one value at a time, I want the single-verb calls and
`list_artifacts` to work, so that an older training script needs no rewrite.

## UX flow (LabelDesk words)
1. **Notebook** — `mlflow.log_metric("map", .71, step=3)` and `mlflow.log_param("lr", 0.001)`; each is one
   POST and the run's history grows by exactly one point. [empty: a run with no metrics — the run detail
   says "no metrics logged yet"] [error: a metric name over 250 characters or a non-numeric value returns
   `INVALID_PARAMETER_VALUE` in the wire envelope]
2. **Tags** — `set_tag("team", "vision")` adds or replaces one key; `delete_tag` removes only that key and
   leaves the rest. [error: deleting a tag that is not there is 200 and idempotent, not a 404]
3. **Artifacts** — `client.list_artifacts(run_id)` lists what the run stored with `path`, `is_dir` and
   `file_size`; a download goes through the existing signed-file route, never a raw path.
4. **Wrong key** — a `read`-only key gets 403 in the envelope on every write verb; a foreign run id is
   `RESOURCE_DOES_NOT_EXIST`.

## Backend changes
- Models/schema: none — T-914 owns `ExternalRun` and `mlrun_wire.py`'s writers; area 1 owns the metric and
  param storage (`ML1-T1.2`, `ML1-T1.3`).
- Routers: **extend T-914's** `app/routers/mlrun_api.py` (Shared) with `runs/log-metric`,
  `runs/log-parameter`, `runs/set-tag`, `runs/delete-tag` and `artifacts/list`. Do not add `log-batch`,
  `runs/search` or `metrics/get-history`: T-914 and T-915 already own them.
- Services/jobs: `app/services/mlrun_wire.py` (T-914, Shared) — the single-verb calls are one-entry calls
  to the batch writers, so the 5 000-point cap and the `labeldesk.truncated` tag behave identically.
  `app/services/mlflow_shapes.py` (T-983, Shared) — `file_info(path, size) -> dict`.
- Permissions + workspace isolation: `train` scope for the write verbs, `read` for `artifacts/list`; the
  workspace comes from the key, so a foreign run id is a 404 in the envelope.
- Secrets/safefetch: none; artifact paths resolve through the existing signed-file route
  (`main.py:89-98`), so no absolute path can be read and no bucket credential is exposed.
- OpenAPI: no (wire routes stay out of the schema).

## Acceptance criteria
- [ ] Single-value logging from a third-party client lands in the same store as `log-batch`.
- [ ] `delete_tag` is idempotent and touches no other key.
- [ ] `artifacts/list` reports path, directory flag and byte size, and no absolute path leaves the server.
- [ ] A read-only key cannot write, and a foreign run id is 404 in the envelope.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
