## User story
As an ML engineer, I want the trainer to accept the parameters the spec declares, typed and
defaulted, so that a typo is a sentence before a run instead of a wasted GPU hour.

## UX flow (LabelDesk words)
1. **Project → Train → Parameters** — after a spec is loaded, its parameters appear as typed inputs
   (number stepper for `float`/`int`, text for `string`) prefilled with their defaults. [empty: the
   spec declares no parameters — the section collapses to "this spec takes no parameters"] [loading:
   the last run's values are fetched to prefill, fields disabled] [error: a value fails its type —
   the field is red with "must be a whole number", Run disabled, no request sent].
2. **Resolved plan** — a read-only block above the Run button lists every parameter with its value and
   source: `default`, `you`, or `last run`. [empty: n/a once a spec is loaded] [loading: n/a] [error:
   a parameter was removed from the spec since the last run — "epochs is no longer in this spec", the
   value dropped, not silently kept].
3. **CLI** — `labeldesk train --spec labeldesk.yaml --set epochs=60 --set lr=0.01`; `--set epochs=sixty`
   prints the same sentence as the UI and exits 2. The plan is printed before the request.
4. **Server** — an unknown or mistyped parameter is a 422 whose body names the parameter, and the
   request creates no job row.

## Backend changes
- Models/schema: none — resolved parameters travel in `Job.params` (`models/training.py:24-25`).
- Routers: `routers/training.py` train handler validates `params` against the project's stored spec
  before inserting a `Job`; unknown key or wrong type → 422 with
  `{detail: [{loc: ["body", "params", "<name>"], msg: "..."}]}` in the existing FastAPI shape.
- Services/jobs: `app/services/run_spec.py` (from T-968) gains
  `coerce(spec, entry_point, values) -> dict` (fills defaults, raises `SpecError`) and
  `plan(spec, entry_point, values) -> [{key, value, source}]` (source = `default|given|last_run`).
- Permissions + workspace isolation: `project.train` on submit, `project.read` on the plan preview;
  project resolved by `project_ctx`.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Frontend changes

## Acceptance criteria
- [ ] Every spec parameter renders as a typed input with its default filled in.
- [ ] The plan shows value and source for each parameter before submit.
- [ ] A wrong type is refused in the UI and by the API, and no job row is created.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
