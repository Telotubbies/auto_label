## User story
As an operator, I want the stream to say whether the camera is offline or the job stopped, and to stop retrying after repeated failures, so that a dead camera does not loop forever and a healthy camera with a stopped job is diagnosable.

## UX flow (LabelDesk words)
1. **Streams list and detail** — one state word per stream: `Waiting for video`, `Starting`, `Processing`, `Reconnecting`, `Paused (GPU busy)`, `Needs attention`, `Stopped`, `Failed`. The chip carries a dot, the word and an `aria-label`; colour is never the only signal. [empty: a stream that has never started reads `Stopped`, never `Waiting for video`] [loading: a new stream shows `Starting` for at most 10 s, then `Needs attention` with the last error] [error: a fatal model error shows `Failed` with the server's sentence]
2. **Frame counts prove "Processing"** — the detail shows `frames` and `inferences` beside the state, so "Processing" with a frozen count is visibly wrong.
3. **Recovery pauses** — after 5 consecutive failures, 15 minutes without a processed frame, or 10 starts in one hour, the state becomes `Needs attention` and the worker stops retrying; the detail states which of the three tripped: "Stopped retrying: 5 failures in a row." A camera drop alone never trips it — a stream waiting for video stays `Reconnecting`.
4. **Recovery re-arms** — 30 s of steady processing resets the failure counter, and a person pressing Start clears the attention state deliberately.
5. **No email here** — the panel links to the workspace's alert channels for an offline notice; delivery is area 7's surface, and this card never sends a message.

## Backend changes
- Models/schema: `streams` gains `failures INTEGER DEFAULT 0`, `starts JSON` (timestamps of the last hour), `attention VARCHAR(64) DEFAULT ''` (why it stopped retrying). `ADD COLUMN` lines in `app/schema/streams.py`'s `STREAMS` block.
- Routers: `apps/backend/app/routers/streams.py` — `stream_out` returns `state` (the new vocabulary) beside the existing `status`, plus `attention` and `failures`; `GET /{sid}` unchanged otherwise.
- Services/jobs: `apps/backend/app/streams/state.py` (new) — `STATES`, `to_state(status, live) -> str`, `POLICY = {"failures": 5, "silent_s": 900, "starts_per_hour": 10}`, `note_failure(row, reason) -> bool` (True when the policy trips), `note_start(row, now) -> bool`, `note_processed(row, now)` resetting the counters, `attention_reason(row) -> str`. `streams/manager.py` calls `note_failure` in `_fail` and in the reconnect path, `note_start` in `start`, `note_processed` when a frame is inferred, and stops the worker when the policy trips.
- Permissions + workspace isolation: unchanged (`project.streams` to read, `admin` to write).
- Secrets/safefetch: none.
- OpenAPI: yes — three fields on the stream payload.

## Acceptance criteria
- [ ] One state word per stream from the closed vocabulary, with frames and inferences beside it.
- [ ] Five failures, fifteen silent minutes or ten starts an hour stop the retries and name which tripped, while a plain camera drop stays `Reconnecting`.
- [ ] Thirty seconds of processing re-arms recovery; the existing `status` field is untouched for current clients.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: inside `task_10b`, so that flag hides the whole surface.

## Notes for the implementer
`state` is derived and `status` stays stored: the worker's statuses are its own vocabulary and renaming them would break the existing tests and any client reading `status`. The offline email is area 7's; this card only produces the reason a notice would quote.
