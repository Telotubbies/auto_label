## User story
As a reviewer, I want the new version's page to list what it added, removed and moved since the previous one, so that the reason to make a new version is visible on the page itself.

## UX flow (LabelDesk words)
1. **Version detail → What changed** — the panel defaults to comparing this version against the one before it, with two selects to change base and target. [empty: "This is the first version — there is nothing to compare it against."] [loading: three skeleton lines] [error: "Comparison needs review access — ask a reviewer to share the diff." for a role with export but not review]
2. **Summary line** — "Added 6 · removed 2 · split moves 4 · version hash changed" with the hash comparison read from the response.
3. **Lists** — added (thumb, name, split), removed, and split moves (`train → valid`), each capped at 8 with "Show all" — the same structure the Insights "Versions & ops" tab already uses, but scoped to this version.
4. **Empty lists inside a real diff** — "No images added." / "No images removed." / "No images changed split." rather than an empty box.
5. **Version still generating** — the panel is not mounted (the detail page shows progress only).

## Acceptance criteria
- [ ] The panel compares against the previous version by default, lists added/removed/moved, and reports the hash comparison.
- [ ] A missing previous version and a 403 both render as panel states, not toasts.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no panel and no diff request.

## Notes for the implementer
Do not fetch the diff for a non-ready version: the manifest may be half-written and `version_diff` raises "version has no manifest yet". Gate the query on `status === 'ready'`.
