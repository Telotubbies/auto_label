## Problem
The following tests pass alone and fail only inside the full serial `python -m pytest -q` run in apps/backend (about 1590 tests, 12-15 minutes):
- `tests/test_anomaly.py::test_training_failure_does_not_leak_internals_into_the_station`
- `tests/test_event_search.py::test_unreadable_frame_file_does_not_fail_the_search`
- `tests/test_event_search.py::test_frame_of_a_deleted_image_is_not_served_and_not_reindexed`
- `tests/test_health.py::test_missing_box_found_when_model_predicts_unlabeled_object`
- `tests/test_mcp_write_tools.py::test_auto_label_with_no_ai_call_allowance_is_the_apis_402` (fails after the other `tests/test_mcp_*.py` files; quota state probably leaks between them)

The cause is probably state leaking from earlier tests (a shared SQLite DB, job queue, worker threads, module caches or flags), or wall-clock waits under load.

## Steps
1. Reproduce. Run the full suite with `-p no:randomly` and `--durations=0`. Then bisect the files that run before each failing test until a two-file run reproduces the failure. Record the minimal pair in the report.
2. Fix the cause in the leaking fixture or test: isolate state, reset the queue, poll instead of sleeping. Never skip, mark xfail, or loosen an assertion.
3. Prove it. The minimal pair passes, then the full serial suite passes twice in a row. Never use xdist.

## Files
Only `apps/backend/tests/**` and `apps/backend/tests/conftest.py`. Production code changes only if the leak is a real bug, and the report must say so.
