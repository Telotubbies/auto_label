## User story
As an engineer comparing two runs of the same 30 epochs, I want to know when each point was recorded, so I can
tell "epoch 20 was slow because the box was busy" from "epoch 20 was slow because the learning rate was wrong".

## UX flow (LabelDesk words)
1. **Insights → Training** (`/:ws/:p/model-insights?tab=training`) — hover a point on any curve; the tooltip reads
   `run · metric` then `epoch 12 · 14:02:11 — 0.712` instead of a bare value. [empty: a run recorded before this
   card has no time and the tooltip drops the middle segment] [loading: unchanged skeletons]
   [error: `Training curves could not be loaded` + retry, unchanged]
2. **Chart card → Export CSV** — the CSV gains a `Time` column (ISO 8601, empty for old rows) next to
   `Epoch, Run, Metric, Value`, so a spreadsheet can plot time as well as epochs.
3. **Chart card → table view** — the same column appears in the accessible table, right after `Epoch`.
4. **A 3-hour run** — the x-axis stays epoch (a step axis is what makes two runs comparable); the wall clock is
   a tooltip/export detail, not a second axis.

- Secrets/safefetch: none.
- OpenAPI: no (response is an untyped dict; no schema change).

## Acceptance criteria
- [ ] A new run's tooltip shows the wall clock of the hovered epoch; an old run's tooltip omits it silently.
- [ ] The `t` key never appears as a selectable metric group or chart series.
- [ ] CSV, JSON and the table view all carry the same points in the same order.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: `5-F5.16` → T-005 (the guard pins group order and copy; this card adds a column, it does not rename any).
Keep the third tuple element `t`: a `{value, t}` object would change every series consumer, while ECharts ignores
`value[2]` on a cartesian value axis. Do not add a second x-axis — the epoch axis is what makes two runs
comparable, and that is the documented step contract (`/docs/latest/ml/tracking/tracking-api/`).
