## User story
As a project owner, I want agreement broken down by class and by the pair of labels people keep swapping, so that "is this dataset ready" is answered on one screen instead of in a spreadsheet after export.

## UX flow (LabelDesk words)
The screen is T-617; this card owns the numbers behind it.
1. **`GET /quality/report?days=30`** — returns `classes`, `pairs`, `members` and `jobs`. [empty: a project with no consensus job returns `jobs: 0` and empty arrays, plus `next_action: "consensus"` so the screen can name the next step]
2. **Per class** — agreement over the annotations of that class only, with the image and annotation counts that produced it.
3. **Swapped pairs** — two annotations matched at or above the class threshold with different classes, counted once per pair of drafts, sorted by count then name.
4. **Member matrix** — pairwise agreement between every two members who submitted a draft in the window; symmetric, diagonal 1.0, members ordered by name.
5. **A window with nothing in it** — `classes: []`, `pairs: []`, `members: {users: [], matrix: []}` and `jobs: 0`. [error: `days` outside 7–90 → 422 "Choose a window between 7 and 90 days."]

## Backend changes
- Models/schema: none — the report reads `ConsensusAssignment.annotations`, `ConsensusJob.image_metrics` and `ImageClass` as they are; no cached copy is stored, so no `ADD COLUMN` and no backfill.
- Routers: `routers/quality.py` — `GET "/report"` (`days: int = 30`) → `{window_days, jobs, classes: [{class_id, name, agreement, images, annotations}], pairs: [{a, b, count}], members: {users: [{user_id, name}], matrix: [[float]]}, next_action}`; 422 outside 7–90.
- Services/jobs: `app/services/quality_report.py` (new) — `report(db, project_id, days)` reads at most the 20 newest `ready`/`merged` jobs in the window, prepares each draft once, and computes per-class `sets_agreement`, confusion pairs from a greedy match at the class threshold, and the member matrix from pairwise `sets_agreement`; bounded at 5000 submitted annotations, over which the response carries `truncated: true`. No worker job.
- Permissions + workspace isolation: `c.need("reviewer")`; the query filters `project_id == c.project.id`, and `project_ctx` makes a foreign project a 404.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] The report returns agreement for every class present in the window's drafts, with the counts behind each number.
- [ ] A box labelled with two different classes by two labelers appears once in `pairs` with the two class names.
- [ ] The member matrix is symmetric, has a unit diagonal and only names members who submitted in the window.
- [ ] Empty, loading and error states above all render where the surface exists: `jobs: 0` with `next_action`, 422 for the window, 403 for a labeler.
- [ ] Workspace A cannot read workspace B's report (404, not 403).
- [ ] Flag off ⇒ no report route and the QA hub behaves exactly as today.

## Notes for the implementer
Score per class, never a single number scaled by weight — weights belong to the overall figure the report also returns. Reuse `services/labeling.py`'s `_prepared` and `_sets_agreement` through a small public wrapper rather than copying the matcher; a second matcher would drift on polygons.
