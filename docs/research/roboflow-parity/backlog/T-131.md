## User story
As a project manager, I want an itemised estimate and one explicit choice about labels already on the images, so that a batch cannot quietly overspend or delete work.

## UX flow (LabelDesk words)
1. **Annotate board → Auto Label → Label batch** — before the summary sheet opens, the client asks for an estimate. [loading: the primary button shows "Estimating…"] [error: the estimate call fails → the sheet still opens but Confirm is disabled with "Could not estimate the cost — try again"]
2. **Estimate contents** — images in scope, AI calls (= images), credits (`images × 0.01`), the workspace's remaining AI calls this month, and one line "This fits your remaining 4,120 AI calls" or "This needs 2,300 more AI calls than you have left". A job that does not fit refuses to start server-side too (`402`), so a stale tab cannot overspend.
3. **Existing-label policy** — three radios in the same sheet: **Merge into existing labels** (default), **Keep images as they are** (skip annotated images), **Replace existing labels**. Merge copies only predictions that do not overlap an existing same-class annotation at IoU ≥ 0.5; it never deletes a human box.
4. **Partial batches** — when every image in scope is unannotated the policy block collapses to one line "Every image in this batch is unlabelled" and the choice is not asked.
5. **After confirm** — the job's params record the policy, the estimate and the operator, and the board banner names the policy ("Auto-labelling 40 images · merge").
6. **Refusal** — a 402 from the job start reaches the sheet as "Not enough AI calls left on this plan" with a link to Usage, never as a raw error toast.

## Backend changes
- Models/schema: none — the policy lives in `Job.params` JSON.
- Routers: new `POST /api/ws/{ws}/projects/{project}/autolabel/estimate` (same body as `AutoLabelIn`) → `{images, ai_calls, credits, remaining, affordable, reason, policy_default}`; `AutoLabelIn` (`training.py:384`) gains `existing: Literal["keep","merge","replace"] = "merge"`, and `only_unannotated` stays as the legacy alias for `keep` (one release, mapped in the validator).
- Services/jobs: `services/autolabel_plan.py` (new) — `scope_count`, `estimate`, `apply_policy(existing, predicted, mode, iou=0.5)`; `handlers/training.py:201` replaces the `only_unannotated` filter and the blind `existing + anns` append with `apply_policy`, using `health_scan.iou` for the overlap test.
- Permissions + workspace isolation: `c.need("reviewer")` on the estimate (it reads project scope and the workspace meter); class ids and image ids are validated against `c.project.id`; a foreign project slug is 404.
- Secrets/safefetch: none.
- OpenAPI: yes — one route and two fields.

## Acceptance criteria
- [ ] The estimate names images, AI calls, credits, the remaining allowance and whether it fits, before the job can start.
- [ ] A job that does not fit is refused by the server with 402 even if the client shows an old estimate.
- [ ] Merge adds only non-overlapping predictions at IoU ≥ 0.5 and never removes a human annotation; Keep skips annotated images; Replace overwrites deliberately.
- [ ] The chosen policy is visible on the board banner and recorded in the job params.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: fields on the existing job and dialog.
- [ ] Keyboard-only path: Auto Label → Tab to the policy radios → arrow → Tab to Label batch.

## Notes for the implementer
`0.01` credits per image is `CREDIT_COST["autolabel_image"]` (`config.py:108`) — read it, never hard-code. There is no token meter in this codebase, so the estimate shows credits only; do not invent a token line.
