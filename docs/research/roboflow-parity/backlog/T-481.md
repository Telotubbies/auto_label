## User story
As a reviewer, I want to see what is running across every project without opening a project page, so that a long export is a status I can check, not a page I have to keep.

## UX flow (LabelDesk words)
1. **Any workspace screen** — the `Jobs` button opens a glass panel listing active jobs (`Version · PPE`, `Training · Helmets`), each with a determinate bar and `62% · ~4 min left`; finished jobs show their result line for one dismissal. [empty: "Nothing is running. Uploads, versions, training and exports appear here."]
2. **A job finishes while the panel is closed** — the button shows a dot; opening the panel shows the result line and a `Dismiss` per row. [error: a failed job shows "Failed — <reason>" and a `Retry` link to its page; the panel never blocks the route]
3. **Escape or a click outside** — closes the panel and returns focus to the `Jobs` button.
4. **A job for another workspace** — never appears: the list is `/ws/{ws}/jobs` for the workspace in the URL.

## Tests to write first
pytest — `apps/backend/tests/test_job_tray.py`:
- none — no backend surface: the endpoint and its workspace scoping already ship.
node — `apps/frontend/tests/job-tray.test.mjs`:
- `test_active_count_ignores_finished_jobs` — queued/running/cancelling count; done/failed/cancelled do not.
- `test_eta_label_uses_progress_and_elapsed` — a 62% run after 4 min reads `~2 min left`; under 5% elapsed returns `estimating`.
- `test_result_line_separates_project_with_a_middle_dot` — `Training · Helmets` uses U+00B7 and the file contains no corrupted Thai bytes.
- `test_cancel_uses_the_jobs_own_project` — `cancelPath('acme', job)` builds `/ws/acme/projects/<job.project>/jobs/<job.id>/cancel`, so a workspace panel can cancel a job without knowing the route it came from.
- `test_panel_is_a_labelled_dialog` — `role="dialog"`, `aria-modal="false"`, a focus trap, and Escape returns focus to the trigger (source assertions).

## Acceptance criteria
- [ ] The tray lists every active job in the workspace with progress and an ETA, across projects.
- [ ] A finished or failed job keeps its result line until dismissed; a failed job offers `Retry` to its page.
- [ ] Closing the panel restores focus to the `Jobs` button, and Escape and an outside click both close it.
- [ ] A page navigation does not cancel or duplicate a job row (the panel is not route-owned).
- [ ] Empty, loading and error states above all render: the empty sentence, three skeleton rows while loading, and an inline "Could not load jobs — retry" that keeps the panel open.
- [ ] Workspace A cannot see workspace B's data: the list comes from `/ws/{ws}/jobs`; a hand-typed foreign slug never mounts the shell.
- [ ] Flag off ⇒ the old bottom-right tray renders and the icon is absent.

## Notes for the implementer
One source per job list: the workspace panel reads `/ws/{ws}/jobs`, and the board keeps its project-scoped call for autolabel progress. Do not merge them into a new endpoint — the two exist for different reasons and the panel must survive leaving a project.
