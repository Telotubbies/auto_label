## User story
As an admin, I want to set who can see a folder from the folder itself, and to name the groups my identity
provider sends, so that an outsourced team gets exactly one folder.

## UX flow (LabelDesk words)
1. **Projects → folder card `⋯` → `Set permissions`** — a dialog: `Who can see “Site A”?`, one row per current
   grant (label, access select `Can view`/`Can edit`, `Remove`), an `Add` row with a subject picker
   (`Role`, `Auth group`, `Member`) and an access select, then `Save permissions`. The footer states
   `Everyone else in the workspace will not see this folder.`
2. **Locked state** — without `workspace.update` the dialog is read-only: dimmed controls, a lock and
   `Request access` (v3 rule), never a silent redirect.
3. **Settings → Auth groups** (`/:ws/settings/auth-groups`, visible only when at least one folder grant exists) —
   rows of `Name`, `IdP group names`, `Members`, `⋯ → Edit / Delete`; `Create auth group` dialog with `Name`
   and a repeating `IdP group name` field. Members carry a `Manual` or `SSO` badge.
4. **`[empty]`** no groups: `No auth groups yet.` + `Create the first group to share a folder with a team.`
5. **`[loading]`** skeleton rows; **`[error]`** `Could not load folder access.` + retry, with the dialog's draft
   kept when a save fails (`409` re-reads and names the subject).

## Acceptance criteria
- [ ] A folder's grants can be read, edited, added and saved from the folder card.
- [ ] The auth-groups screen creates, edits and deletes a group and shows each member's `Manual`/`SSO` source.
- [ ] A caller without `workspace.update` sees the panel read-only with a lock and `Request access`.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ neither the menu item nor the tab exists.
