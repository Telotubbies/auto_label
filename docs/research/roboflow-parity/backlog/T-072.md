## User story
As a video annotator, I want to see a filmstrip, trim the dead head and tail, and pick the frames that
matter before the job starts so that the dataset holds the moments I need at a cost I chose.

## UX flow (LabelDesk words)
1. **Video** — choosing an MP4/MOV opens **Extract frames** for that file: a filmstrip of 24 thumbnails,
   two trim handles, an interval slider from 60 fps down to one frame per 60 s, and a live line
   "Every 2 s · 00:30 → 04:00 · 106 frames". [loading: thumbnails stream in left to right; the line shows
   "Calculating…" until the first is ready] [error: the browser cannot decode the file →
   "This browser cannot decode that video — re-encode it as H.264 MP4", with the file still listed]
2. **Video** — dragging a handle moves the window; the count updates without a request (duration × rate).
   Trimming below 1 s or past the end snaps to the nearest valid bound.
3. **Video** — **Manual selection**: `M` adds the current moment, `,` and `.` step one frame,
   `Shift+←`/`Shift+→` jump between picks; the strip marks each pick with a chip and the count reads
   "106 frames · 3 hand-picked". Pressing `M` twice on the same moment adds nothing. [error: a pick
   outside the trim window is refused with "Pick 00:12 is outside the trimmed range"]
4. **Video** — **Queue another** keeps the dialog open for the next file with the same interval applied;
   a file with manual picks gets its own dialog. [empty: closing with no file leaves the list unchanged]
5. **Video** — **Start extraction** uploads with the mode, window and picks, closes the dialog and leaves
   a tray row "Extracting frames". [loading: upload progress, then job progress in the tray]

## Notes for the implementer
The estimate is multiplication, not a server round-trip: `every_s` and `target_fps` are both
duration-based, so the server's plan route is only used when the dialog is opened for an already-uploaded
video. Manual picks travel as seconds (`picks_s`); the server converts with the probed fps.
