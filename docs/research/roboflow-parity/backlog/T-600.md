## User story
As the engineer adding a screen, I want one message catalogue and one `t()` call, so that a string is written once, translated once, and every later screen inherits Thai without a second mechanism.

## UX flow (LabelDesk words)
1. **Settings → Appearance → `Language`** — `ไทย` / `English`, defaulting to the browser's `navigator.language`. Changing it re-renders the open screen without losing the project, the editor image or unsaved filter state. [loading: the first paint keeps the current language's font, so nothing jumps]
2. **A screen that reads the catalogue** — its title, actions, empty line, no-match line and error line come from `t('screen.key')`, and a missing key renders the English string plus a console warning in dev only.
3. **A Thai browser with the flag off** — the app renders exactly as today: English strings, the same Thai-capable font stack. [error: an untranslated key shows the English sentence, never an empty string or the raw key]
4. **A shared link** — `?lang=th` is not honoured; the preference belongs to the account, not to a URL anybody can send.

## Frontend changes
- Route: none.
- Nav entry: none.
- Components:
  - `apps/frontend/src/lib/i18n.ts` (new) — `LOCALES = ['en','th']`, `MESSAGES: Record<Locale, Record<string,string>>`, `t(key, values?)` with `{n}` interpolation and an English fallback, `useT()` bound to `useThemePrefs()`, `localeTag()` (`th-TH` / `en-GB`). No provider, no dependency.
  - `apps/frontend/src/lib/theme.ts` — `ThemePrefs` gains `locale: Locale` (default from `navigator.language`), persisted by the existing `setThemePrefs`.
  - `apps/frontend/src/lib/theme.ts` — `dateLocale()` reads the new preference instead of returning a constant.
  - `apps/frontend/src/features/settings/Settings.tsx` — one row under Appearance, beside the Buddhist-era toggle.
  - `apps/frontend/src/index.css` — no change: the Anuphan/Noto Sans Thai stack and `:lang(th)` rules already ship.
- Glass: no new surface — the setting row is a `Card` row like its neighbours, and the switcher is the shipped `Select`. No new token.
- API client: none.
- Feature flag: `task_thai_locale`; off ⇒ `t()` returns the English entry and the Language row is absent.

## Tests to write first
pytest — `apps/backend/tests/test_thai_locale_flag.py`:
- `test_flag_off_keeps_english` — with `task_thai_locale` absent, the flag reader returns False and the locale preference resolves to `en`.
- `test_flag_is_registered_once` — `FLAGS` contains exactly one `task_thai_locale` entry.
node — `apps/frontend/tests/i18n.test.mjs`:
- `test_every_thai_key_exists_in_english` — both dictionaries have the same key set; a missing English key fails with the key.
- `test_thai_values_contain_thai_and_no_transliteration` — every `th` value matches `/[\u0E00-\u0E7F]/`.
- `test_missing_key_falls_back_to_english` — `t('does.not.exist')` returns the key's English text or the key, never `undefined` and never `''`.
- `test_interpolation_leaves_unknown_tokens` — `t('x', {})` keeps `{n}` visible.
- `test_date_locale_follows_the_preference` — `localeTag('th')` is `th-TH`, `localeTag('en')` is `en-GB`.
- `test_no_provider_or_dependency` — no `react-i18next`/`i18next` import and no context provider in `i18n.ts`.

## Acceptance criteria
- [ ] A user switches to ไทย in Settings and the open screen re-renders in Thai without a reload and without losing state.
- [ ] Every string on a converted screen comes from `t()`; no screen keeps a duplicate literal.
- [ ] An untranslated key renders English, and the dev console names the key.
- [ ] Empty, loading and error states above all render: their three strings are catalogue entries, and a missing one is the English sentence.
- [ ] Workspace A cannot see or change workspace B's data — N/A: a preference is stored per user in the browser.
- [ ] Flag off ⇒ no Language row, English strings everywhere, and the app behaves exactly as today.

## Notes for the implementer
This card creates the catalogue; `T-494` (E-finish) adopts it for the ten screens rather than creating `lib/copy.ts`, and every later wave-F card adds its own keys to the same file — one catalogue, never a per-feature dictionary. Do not add a locale to the URL and do not add RTL: BEYOND §4 rules out a second locale framework, and Thai is a left-to-right script.
