## User story
As a workspace admin arriving from the Inference Hub, I want the Auto label dialog to open with the
segmentation model I chose already selected, so that the handoff is a click rather than a hunt through
the model dropdown.

## UX flow (LabelDesk words)
1. **Arrive from the hub** — `/:ws/p/<project>/dataset?autolabel=sam3%3Asam3.1` opens the existing
   Auto label dialog once, with `sam3:sam3.1` selected and its classes/prompt defaults applied.
2. **Unavailable model** — the ref is in the registry but `available: false`: the dialog opens with that
   row selected, the existing reason line renders, and `Run` stays disabled. [error: the shipped
   "This model is not available on the worker." path].
3. **Unknown ref** — not in the registry (renamed, deleted): the dialog opens with the default model and
   a one-line notice "The model from the link is not available in this project; the default is
   selected." The bad parameter is cleared from the URL.
4. **Parameter cleanup** — after the dialog opens, `autolabel` is removed from the URL with
   `replace: true`, so a refresh does not reopen it and the back button does not trap the user.
5. **No parameter** — the dialog behaves exactly as today (default model, clean slate).
6. **Deep link to a project the caller cannot open** — the project route's existing permission gate
   answers, not this dialog.

## Acceptance criteria
- [ ] The link opens the dialog once with the chosen model selected and its defaults applied.
- [ ] An unavailable model is selected with the existing reason and a disabled Run.
- [ ] An unknown model falls back to the default, shows one notice, and clears the parameter.
- [ ] The parameter is removed with `replace: true`; refresh does not reopen the dialog.
- [ ] Without the parameter, the dialog is byte-for-byte today's behaviour (the existing autolabel
      tests still pass).
- [ ] No new visual primitive, token or dependency.

## Notes for the implementer
The dialog resets on `open` and project change; `initialRef` must be applied in that same effect, or a
project switch will carry a model from another project. Keep the ref untouched when the registry has not
loaded yet: the effect already waits on `registryQ.data`.
