## User story
As an ops lead who knows the outcome but not the prompt, the threshold or the model, I want to write one sentence, approve a plan I can edit, see twenty trial images and then let it run, so that the negotiation happens before the batch instead of after a wrong run.

## UX flow (LabelDesk words)
1. **Annotate board → New job** (`/:ws/:project/annotate`, drawn by T-664) — one text box plus a batch. This card turns the sentence into a plan. [error: "I could not read a target class list from that sentence — name the objects you want"]
2. **The plan** — classes and their prompts, the model, the review policy, the trial size (20), the call budget and a one-line note per row; each row is editable, and the plan is stored before anything runs. [empty: a plan with no class is refused with the sentence to fix]
3. **Trial** — `[loading: "Running 20 of 20 trial images…"]`; the result is a yield table per class plus three sample images and the escalated count.
4. **Approve** — the batch runs with the plan as its params and the plan snapshot kept as the audit record; **Revise** returns the editable card.
5. **Report** — labelled, escalated, skipped with a reason, spend in `ai_calls`, and the escalations as an ordinary review batch with a named reviewer.
6. **Flag off** — no New job button and no endpoint.

## Backend changes
- Models/schema: new module `app/models/agents.py` with `AgentRun` (`id`, `workspace_id`, `project_id`, `prompt`, `plan` JSON, `status`, `trial` JSON, `result` JSON, `budget_calls`, `spent_calls`, `job_id`, `created_by`, `created`) registered in `models/__init__.py`.
- Routers: new `app/routers/agent.py` — `POST /api/ws/{ws}/projects/{project}/agent/plan` (`prompt`, `batch_id`) → 201 with the run and its plan; `POST .../agent/{rid}/plan` (an edited plan) → 200; `POST .../agent/{rid}/trial` → 202; `GET .../agent/{rid}` → run, pilot and report; `POST .../agent/{rid}/approve` → 202 and the `autolabel` job with `params.agent_run_id`; `POST .../agent/{rid}/cancel` → 200. 422 for a plan without a class or with a model that cannot run, 409 when the estimated calls exceed `budget_calls` or the egress gate refuses, 403 for a non-reviewer, 404 for a foreign run.
- Services/jobs: `services/agent_plan.py` (new) — `PLAN_SCHEMA` (classes with prompts, model_ref, bands, trial_size 5–50, budget_calls), `plan(vlm, prompt, classes, batch)` asking for that schema, `validate(db, project, plan)` (classes exist or are named, the ref resolves, bands sane, trial within the batch), `trial(db, ws, run)` scoring `trial_size` images through `label_image` and returning `{yield, escalated, samples}`, `report(db, run)`; job kind `agent_trial` in `LOCAL_JOB_KINDS`, approve enqueues the existing `autolabel` kind so one runner does the labelling.
- Permissions + workspace isolation: `reviewer` for every step; the run carries `project_id` and every later step checks it (404 for a foreign run), and the plan's model ref must resolve inside `c.ws.id`.
- Secrets/safefetch: `services/secretbox.py` holds a hosted endpoint token if one is stored; the prompt and the trial crops reach the endpoint only through `ai_egress.require` (T-640), so nothing leaves the deployment without `workspaces.ai_egress`.
- OpenAPI: yes — regenerate (`python tools/export_openapi.py`, `npm run gen:api-types`).

## Acceptance criteria
- [ ] One sentence plus a batch produces an editable plan with classes, prompts, model, review policy, trial size and budget, stored before any work starts.
- [ ] A trial over twenty images returns a per-class yield, three samples and an escalated count, and the plan can be revised before approval.
- [ ] Approval runs exactly one `autolabel` job with the plan as its params, and the report separates labelled, escalated and skipped with the spend.
- [ ] Empty, loading and error states above all render, including an unreadable sentence, a budget overrun and a refused gate.
- [ ] Workspace A cannot read or approve workspace B's run (404), and a model from another workspace cannot be named in a plan.
- [ ] Flag off ⇒ no New job button, no route, and the board is unchanged.

## Notes for the implementer
The plan is the contract: store it before the trial, keep the approved snapshot on the run, and never let the runner re-derive a band from the sentence. Reuse the existing `autolabel` job for the approved run so there is one labelling path, one metering path and one report shape — the agent plans, it does not label.
