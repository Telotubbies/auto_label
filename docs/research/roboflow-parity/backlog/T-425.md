## User story
As an IT admin, I want to add our domain, publish one record and see Pending / Verified / Failed per domain, so that a
typo is visible on the same tab that started the setup.

## UX flow (LabelDesk words)
1. **Settings → Members → `Single sign-on`** (`/:ws/settings/sso`) — two cards. **Domain verification**: `Add domain`
   (input + button), then one row per domain: the name, a state chip `Pending` / `Verified` / `Failed`, the record
   name and value with a copy button, `Verify now`, and `Remove`.
2. **`Failed` state** — the row states the reason in words (`No TXT record found at _labeldesk-sso.acme.co.th.` /
   `The record exists but its value differs.`) and keeps `Verify now` as the primary action; a `Failed` row shows the
   expected value so the two can be compared.
3. **Identity provider card** — `Set up SSO` (available only with one verified domain), then `Provider`, `Issuer URL`,
   `Client ID`, `Client secret` (write-only, placeholder `Stored — leave blank to keep`), `Save`, and `Enable single
   sign-on`. When enabled the card header reads `Active` with `Manage` replacing the CTA.
4. **`[empty]`** before setup both cards are plain placeholders: `No domains yet.` / `Add your company's email domain
   to begin.` and `Connect your identity provider after a domain is verified.`
5. **`[loading]`** one skeleton row per card; **`[error]`** `Could not load single sign-on settings.` + retry; a
   verification failure is not a page error.
6. **Read-only** — without `workspace.update` every control is dimmed with a lock and `Request access`.

- [ ] A failed verification states why and keeps verification one click away.
- [ ] The IdP card requires a verified domain, keeps a stored secret, and shows `Active` when enabled.

- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no SSO tab and no link from Members.

## Notes for the implementer
`Verify now` is the only primary action on a pending/failed row; the DNS text is monospace and copyable because admins
paste it into a registrar. The secret field never renders a value, only `Stored`.
