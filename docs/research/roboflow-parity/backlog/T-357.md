## User story
As an operator, I want to restart a stream or every stream at once and see the last thirty things that happened to it, so that a recovery is one press and its cause is on the same screen.

## UX flow (LabelDesk words)
1. **Streams list header** — `Restart all` appears only when at least one stream is not `Processing`; pressing it asks "Restart 4 streams? Anything mid-frame finishes first." and reports "4 restarted · 1 still stopping". `[loading: the button keeps its width and shows a spinner]` `[error: a stream that refuses → "Camera 3 is still stopping; try again in a moment." and the rest are restarted]`
2. **Stream detail header** — `Restart` beside Stop; it stops and starts in one action and says "Restarted · waiting for video" until the first frame arrives.
3. **Stop with a confirm** — Stop asks once and names the consequence: "Stop Gate 3? Capture ends and processing is billed only for the time it ran."
4. **Activity tab** — a third tab beside Events and Zones & rules: the last 30 lifecycle changes — started, stopped, restarted, reconnecting, needs attention, settings changed — each with time, actor and a one-line reason. It is explicitly not prediction history: the empty state says "No changes yet. Starts, stops and settings edits appear here." `[empty]` `[loading: five skeleton rows]` `[error: "Activity could not load." with "Try again"]`
5. **Needs attention** — the detail shows the reason from T-356 and puts `Restart` first, so the recovery is the loudest control on a broken stream.

## Backend changes
- Models/schema: none — lifecycle changes are the existing `audit` rows with `action LIKE 'stream.%'`.
- Routers: `apps/backend/app/routers/streams.py` — `POST /restart-all` (admin) returning `{restarted: [...], draining: [...]}`; `POST /{sid}/restart` = stop then start with the same draining guard as `update_stream` (409 when the previous worker has not exited); `GET /{sid}/activity?limit=30` reading audit rows for this stream.
- Services/jobs: `apps/backend/app/services/stream_activity.py` (new) — `LABELS` mapping audit actions to operator words, `recent(db, stream, limit=30) -> list[dict]`, `restart_all(db, c, project) -> dict` looping the manager with the shared 0.25 s budget and one audit row per stream.
- Permissions + workspace isolation: `admin` for restart and restart-all; `project.streams` for the activity read; every id is project-scoped.
- Secrets/safefetch: none — no audit row carries a camera URL (the existing rows already mask it).
- OpenAPI: yes — three routes.

## Acceptance criteria

- [ ] The Activity tab lists the last 30 lifecycle changes only, newest first, with actor and reason, and never a camera URL.
- [ ] A stream that is draining is refused with a retry, not started twice.

- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: inside `task_10b`.

## Notes for the implementer
Restart is stop-then-start through `manager`, not a new worker path: a second worker under one stream id duplicates capture and events, which the manager already refuses. Activity reads audit rows; do not add a second lifecycle table.
