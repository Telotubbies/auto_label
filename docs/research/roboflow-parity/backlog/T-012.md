## User story
As a first-time user, I want to describe what I am building once, in three short questions, so that the assistant starts from my brief instead of making me repeat it in a chat box.

## UX flow (LabelDesk words)
1. **Setup** (`/:ws/setup`) — one question per step, progress `1 of 3`: "What are you building?" / "What should happen with the result?" / "What images or video do you already have?". Each step has **Back**, **Skip this question**, and a `Use an example` link that fills editable sample text. [empty: textarea blank and step not required → Next stays enabled] [loading: none on this screen; submit shows `Saving…`] [error: >600 characters → inline `Keep it under 600 characters`; network failure → the step keeps its text and shows `Could not save — try again`].
2. **Finish** — `Continue` stores answers and navigates to the assistant home; with T-014 the stored answers become the first assistant message. Skipping all three opens the assistant with no brief, which is allowed.
3. **Returning users** — `/setup` after the first workspace is a redirect to `/:ws`; only the caller's first workspace ever sees the questions.

## Backend changes
- Models/schema: `workspaces.onboarding` JSON, nullable, no backfill — `ADD COLUMN` `{"onboarding": "JSON"}` appended to `WORKSPACES` in `app/schema/identity.py` (registered already as the `workspaces` step).
- Routers: `GET /api/ws/{ws}/setup` → `{questions: [{key, prompt, example}], answers: {building, outcome, data}, asked: bool}`; `PUT /api/ws/{ws}/setup` body `{building?, outcome?, data?}` (strings ≤600, trimmed) → `{answers, asked: true}`; 409 `setup is already answered` when `asked` is true — answers are write-once.
- Services/jobs: `services/onboarding.py` (new) — `QUESTIONS` table (key, prompt, example), `read(db, ws)`, `save(db, ws, answers, user)`, `is_first_workspace(db, user, ws)`. The three prompts/examples live here, not in the UI, so the assistant reads the same text.
- Permissions + workspace isolation: `ws_ctx` only; `save` requires `workspace.read` plus the first-workspace rule; a workspace slug from another tenant 404s via `ws_ctx`, and an id in the body is never accepted.
- Secrets/safefetch: none — no LLM call on this card.
- OpenAPI: yes.

## Frontend changes
- Route: `/:ws/setup` registered in `routes/workspace.routes.tsx`; `/` first-run redirects here when `setup.asked` is false and the flag is on.

- Feature flag: `task_a1_setup_questions`; off ⇒ `/setup` redirects to `/:ws` and the field stays null.

## Tests to write first
pytest — `apps/backend/tests/test_onboarding.py`:
- `test_answers_are_saved_and_asked_flips` — PUT the three answers → GET returns them and `asked: true`.
- `test_long_answer_is_refused` — 601 characters → 422, nothing written.
- `test_second_workspace_cannot_run_setup` — the same user creates a second workspace → PUT answers → 409 and `onboarding` stays null (only the first workspace asks).
- `test_cross_workspace_setup_is_404` — a slug not in the caller's membership → 404 (never 403).
- `test_flag_off_has_no_routes` — flag off → both routes 404 and `workspaces.onboarding` stays null.

node — `apps/frontend/tests/setup-questions.test.mjs`:
- `test_step_order_and_skip` — steps advance, skip leaves the answer empty, back preserves text.
- `test_example_fills_editable_text` — example text lands in the textarea and stays editable.

## Acceptance criteria
- [ ] Three questions appear one at a time on the first workspace only, with back, per-question skip and example text.
- [ ] Answers survive a reload (stored server-side), and skipping all three is a valid finish.
- [ ] Empty, loading and error states above all render (including the 600-character refusal).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged (`/setup` redirects, no column written).

## Notes for the implementer
Answers are the assistant's first message, so store `{building, outcome, data}` verbatim — no summarising on the server. `asked` is set by the PUT, not by visiting the page.
