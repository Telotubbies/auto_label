## User story
As a team lead, I want to retire a version with a written reason and keep it downloadable, so that the history of what we shipped survives the cleanup and nobody deploys an old model by accident.

## UX flow (LabelDesk words)
1. **Version row menu → Deprecate…** — a dialog takes one optional reason (280 characters, e.g. "superseded by v4 — recall on small helmets"), states that the version stays downloadable, and writes the flag. [empty: a version that is already deprecated opens the same dialog in *Reinstate* mode] [loading: the row stays visible with a spinner until the write returns] [error: "Not deprecated — retry" leaves the row unchanged and keeps the typed reason]
2. **Deprecated chip** — the version row shows a muted *Deprecated* chip with the reason on hover and the actor in the tooltip; the group still lists its score. [empty: nothing deprecated ⇒ no chip, no filter option]
3. **Deploy & Test** — the model picker leaves deprecated versions out of the default list and offers *Show deprecated* at the bottom; picking one shows "This version is deprecated: <reason>" above the tester and the hosted-API card. [error: calling the API with a deprecated model id still works and returns a `deprecation` header, because a caller may be pinned deliberately]
4. **Compare** — a deprecated version stays selectable in Insights; it is the historical evidence, not a live candidate.
5. **Reinstate** — clears the flag and appends a lifecycle row (who, when, from → to); no stage vocabulary ever appears.

## Backend changes
- Models/schema: append `"deprecated": "BOOLEAN DEFAULT FALSE"`, `"deprecated_reason": "VARCHAR(280) DEFAULT ''"`, `"deprecated_by": "VARCHAR(32) DEFAULT ''"`, `"deprecated_at": "FLOAT DEFAULT 0"` to `TRAINED_MODELS` in `apps/backend/app/schema/training.py`; add the four `Mapped` columns to `TrainedModel`.
- Routers: `POST {P}/models/{mid}/deprecate` body `{deprecated: bool, reason: str = ""}` → `{id, deprecated, deprecatedReason, deprecatedBy, deprecatedAt}`; **409** when the model is not `ready` or already deleted, **422** when the reason exceeds 280 or is empty on a `true` call only if the caller also sends `require_reason`. `model_out` gains `deprecated`, `deprecatedReason`, `deprecatedBy`.
- Services/jobs: `apps/backend/app/services/model_lifecycle.py` (new) — `deprecate(db, model, user_id, reason) -> TrainedModel`, `reinstate(db, model, user_id) -> TrainedModel`, `is_live(model) -> bool`; writes one audit row each way.
- Permissions + workspace isolation: `c.need("admin")` for both directions (same level as delete); reads unchanged; a foreign id is a 404 from `_model`.
- Secrets/safefetch: none.
- OpenAPI: yes — one route, four payload fields; regenerate both files.

## Acceptance criteria
- [ ] Deprecating writes a flag, a reason, an actor and a timestamp, and the version stays downloadable and callable.
- [ ] The Deploy picker hides deprecated versions by default and shows the notice when one is chosen deliberately.
- [ ] Reinstate clears the flag and appends history; no stage name appears anywhere in the UI.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
