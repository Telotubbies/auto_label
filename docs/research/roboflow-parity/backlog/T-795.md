## User story
As anyone whose first run on a new dataset died at epoch 3, I want the run page to quote the useful line, suggest one concrete change and retry with the same settings, so that a failure is a fix instead of a support thread.

## UX flow (LabelDesk words)
1. **Model page → a failed run** (`/:ws/:project/models?model=<id>`) — the banner quotes the extracted line ("out of memory", "bad label file", "missing class") instead of a stack trace, with `What to change` and `Retry with the same settings` beside it. [error: no extractable line ⇒ the banner states "Training stopped before it reported a reason." and keeps the console link]
2. **Console tab** — the last 2 000 lines with an option to show timestamps and `Copy all`; every line passes the existing sanitiser so no absolute path or model-server URL reaches the screen. [empty: "This run reported no console output." for a run that never started]
3. **What to change** — one or two concrete edits with the field named and pre-set (for an out-of-memory failure: `batch 16 → 8`), each linking into Train with that value applied. [loading: the suggestion is computed from the stored error, so it appears with the banner]
4. **Retry** — opens Train with the same version, architecture and arguments, and states that the previous weights survive if the rerun is worse.
5. **A failure before compute started** — the banner adds "It failed before training started, so nothing was charged." [error: a run still training shows no banner at all]

## Backend changes
- Models/schema: none — the console lives on `Job.result['console']` (bounded), the failure sentence on `Job.error`.
- Routers: `GET …/jobs/{jid}/console?timestamps=` in `routers/runs.py` → `{lines, truncated, bytes_sanitised}`; `GET …/jobs/{jid}/failure` → `{reason, suggestion:{field, from, to, text}, before_compute}`.
- Services/jobs: `app/services/joblog.py` (new) — a `logging.Handler` with a bounded 2 000-line ring buffer, `install(job_id)` / `capture(job_id)` context manager run by `worker.run_one`, flushed into `job.result['console']` on a terminal status; `app/services/diagnosis.py` (new) — `explain(error, job) -> (reason, suggestion)` mapping OOM, missing class, unreadable label file and a stalled watchdog to one sentence and one field edit.
- Permissions + workspace isolation: `project.models` to read console and failure; a job id from another project or workspace answers 404.
- Secrets/safefetch: the console is sanitised through `errors.safe_text` per line before it is stored; nothing raw is persisted.
- OpenAPI: yes — regenerate both generated files.

## Acceptance criteria
- [ ] A failed run quotes one useful line, offers one or two named edits, and retries with the same version and arguments.
- [ ] The console shows the last 2 000 lines, with a timestamp toggle and copy-all, and contains no absolute path or URL.
- [ ] A failure before compute started says so and states that nothing was charged.
- [ ] Empty, loading and error states above all render: no extractable reason states that, and a run that never started has its own console line.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ today's single-line failure card, no console route and no capture.

## Notes for the implementer
Sanitise on write, not on read: a stored console that still holds a machine path is one `GET` away from a customer. The retry never re-charges for the failed attempt — it is a new run and a new charge, and the panel says so in one line rather than a footnote.
