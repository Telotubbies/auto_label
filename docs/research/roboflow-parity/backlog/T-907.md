## User story
As a team lead with 200 runs, I want to type `tag:nightly metric:map50>=0.6 sort:-map50 limit:20` and get exactly
those runs, so the list is a question I ask rather than a wall I scroll.

## UX flow (LabelDesk words)
1. **Models → filter field** — type a clause; the list narrows on Enter (the UI is T-908). Server side, the
   contract is: any number of space-separated clauses, all ANDed, plus at most one `sort:` and one `limit:`.
   [empty: a valid filter that matches nothing returns `{"items": [], "total": 0}` — the screen's job is to say
   `No runs match this filter.`] [loading: n/a on the server] [error: an unknown field or a malformed comparator
   returns 400 with the offending token and the field list]
2. **`tag:nightly`** — matches runs whose tags contain the key `nightly`; `tag:line=3` matches the value.
3. **`metric:map50>=0.6`** — matches on the stored headline metric; a run with no evaluation simply does not match.
4. **`sort:-created`** — newest first; `limit:20` caps the page at 20 (hard ceiling 200).

## Backend changes
- Models/schema: none.
- Routers: `apps/backend/app/routers/training.py` — `GET …/models` gains `q: str = Query("")` and returns
  `{"items": [...], "total": n}` **only when `q` is present** (an empty `q` keeps today's bare list response, so
  nothing that exists today changes shape). Bad input → 400 with
  `{"detail": "Unknown field 'metricx' — use status:, task:, variant:, version:, tag:, metric:, sort:, limit:"}`.
- Services/jobs: `apps/backend/app/services/run_filter.py` (new) —
  - `parse(text: str) -> RunFilter` with `RunFilter.clauses: list[Clause]`, `.order: tuple[str, bool] | None`,
    `.limit: int | None`; raises `FilterError(token, message)`.
  - Grammar, v1: `status:<value>`, `task:<value>`, `variant:<value>`, `version:<number>`, `tag:<key>` /
    `tag:<key>=<value>`, `metric:<key><op><number>` (`> >= < <= =`), bare words → `name ILIKE %word%` (and the
    note, once T-906's column exists), `sort:[-]created|name|metric:<key>`, `limit:<n≤200>`.
  - `apply(stmt, f, project_id)` returns the narrowed `select` — SQLAlchemy only, JSON access through
    `column[key].as_string()` so PostgreSQL and SQLite compile it (`TrainedModel.tags`, `TrainedModel.metrics`),
    and `Version.number` through one join.
  - Explicitly **not** in v1: `param:` and `epochs:` (see Notes).
- Permissions + workspace isolation: the route keeps `project.infer` (`:150`) and the project scope; `run_filter`
  never sees a project id it did not receive from `project_ctx`, so a filter cannot cross a workspace.
- Secrets/safefetch: none.
- OpenAPI: yes — the query parameter and the `{items,total}` shape; `python tools/export_openapi.py`, then
  `npm run gen:api-types`.

## Acceptance criteria
- [ ] Every documented clause returns exactly the runs that satisfy it, and `total` agrees with `items`.
- [ ] An unknown field, a bad comparator or `limit:0` answers 400 with a message a user can act on.
- [ ] The list endpoint without `q` is byte-for-byte today's response.
- [ ] Empty, loading and error states above all render.
  (The empty page is the client's state and the 400 is the error; neither is a server 500.)
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: none — the image query language (`2-F2.27`, area 2) is a different corpus and a different parser; do not
import it, and do not add `OR`.
`param:` and `epochs:` are deliberately out of v1: the training options live in `Job.params` JSON, and compiling
them portably would mean dialect-specific JSON. `variant:`/`version:`/`task:`/`metric:` already answer the
questions a user asks of a run list. If a reviewer wants `epochs>=N`, it arrives with a stored `epochs` column, not
with Python filtering after the fact.
Return `{items,total}` only for `q`; changing the default response shape would break `api.models()` callers
(`lib/api/models.ts:10`, `features/project/Models.tsx:150`, `Train.tsx:20`).
