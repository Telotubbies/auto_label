## User story
As an admin, I want to see the sign-in and sidebar previews while I change colours, and to discard a half-finished
theme, so that a bad palette never reaches my staff.

## UX flow (LabelDesk words)
1. **Settings → Appearance → `Custom branding`** (`/:ws/settings/branding`) — two columns: controls on the left,
   a live preview on the right (sign-in card + sidebar strip). A note reads
   `Applies to everyone who signs in to this workspace.`
2. **Controls** — `Logo` (upload, PNG/JPEG/GIF/WebP up to 2 MB, with `Remove`), `Loading image`, and swatch groups:
   Sign-in (accent, card background, card border, button, wordmark), Sidebar (hover background, selected text, selected
   icon, unselected text, unselected icon, logo border).
3. **Save / discard** — `Save changes` (primary) and `Discard changes` (secondary, disabled while clean); the header
   states `Unsaved changes` while dirty. Navigating away with unsaved changes asks
   `Leave without saving your branding?`
4. **`[empty]`** no customisation: every control shows the default value with a `Default` chip and `Discard changes`
   resets to it.
5. **`[error]`** an SVG or oversized file prints the exact reason under the upload (`SVG is not supported.` /
   `That file is larger than 2 MB.`); a colour that is not a hex value is flagged inline.
6. **`[loading]`** the preview shows the last saved theme with a subtle skeleton on the swatches.

## Notes for the implementer
The preview must render from the in-memory draft, not from a saved copy — otherwise "live preview" is a lie. Keep the
swatch list to the eleven keys the service validates. Each key writes an **existing** role variable — `--primary`,
`--card`, `--border`, `--popover`, `--sidebar`, `--sidebar-accent`, `--sidebar-foreground`, `--sidebar-primary` — through
`applyTheme()`'s role map, so a branded workspace is the same glass system with a different seed, never a second palette
and never a new token name (`VISUAL-OVERRIDE.md` §1, §5).
