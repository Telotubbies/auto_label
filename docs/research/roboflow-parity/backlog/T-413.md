## User story
As a workspace owner, I want to read my plan, start a checkout and have the provider's confirmation applied once, so
that the plan on screen matches what was paid for.

## UX flow (LabelDesk words)
1. `GET /api/ws/{ws}/billing` → `{plan: {code, label, cycle, cancels_at}, catalogue: {packs: [...], addons: [...]},
   account: {provider, has_payment_method, prepaid_credits, flex: {enabled, cap_usd}}, invoices_url}`.
   `has_payment_method` is `false` under the mock.
2. `POST /api/ws/{ws}/billing/checkout` `{pack_code, kind: "pack"|"addon"}` → `{checkout_id, url}` where `url` is the
   mock's own confirmation path when the provider is a mock; `409 not_configured` while a price is `TBD`.
3. `POST /api/ws/{ws}/billing/cancel` `{at_period_end: true}` → `{plan, ends_at}` (T-416 owns the screens).
4. `POST /api/billing/webhook` (public, no bearer) — the provider posts an event; `webhook_verify` validates it,
   the event id is stored in `BillingEvent` (unique) so a replay changes nothing, and the handler applies
   `checkout.completed` / `payment.failed` / `subscription.cancelled` / `invoice.paid`.
   Unknown event kinds are stored and ignored; a bad signature is `400` with no detail.
5. `[error]` `409 {"code": "not_configured"}` when the ladder has no price; `402 declined` maps to
   `BillingError("declined")` with the same body shape.
6. Every billing state change writes an audit row (`billing.checkout`, `billing.cancel`, `billing.webhook`).

## Backend changes
- Models/schema: none (T-412).
- Routers: `app/routers/billing.py` (new) — prefix `/api`, routes `GET /ws/{ws}/billing`,
  `POST /ws/{ws}/billing/checkout`, `POST /ws/{ws}/billing/cancel`, `POST /billing/webhook`. The webhook route is the
  only unauthenticated one and carries no workspace id: the workspace is resolved from the verified event.
- Services/jobs: `services/billing.py` — `state(db, ws) -> dict`, `checkout(db, ws, pack_code, kind, actor) -> dict`,
  `apply_event(db, event) -> dict` (idempotent on `provider_event_id`), `cancel(db, ws, at_period_end, actor)`.
  Applying `checkout.completed` writes the plan code and cycle on `BillingAccount` and, for an add-on, its flag.
- Permissions + workspace isolation: reads `workspace.read`; checkout/cancel `workspace.billing`; the webhook has no
  session and may only touch the workspace named in the verified event.
- Secrets/safefetch: no outbound network call; `webhook_verify` is pure. If a provider secret exists later it is read
  from `config`, never from the database.
- OpenAPI: yes.

## Acceptance criteria
- [ ] The billing state is readable with the catalogue, and no price is invented when none is configured.
- [ ] A checkout answers `409 not_configured` while prices are unset and a mock URL when a test price exists.
- [ ] The webhook verifies, is idempotent by event id, and only touches the workspace the event names.
- [ ] Empty, loading and error states above all render (unconfigured, declined, replayed event).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ all four routes 404, including the unauthenticated one.

## Notes for the implementer
The webhook is the only unauthenticated route in this area: it must stay behind the flag, verify before parsing
further, and answer a flat `400` on failure. Owner decisions (provider, ladder, self-host licence) are still open —
nothing here names a vendor or a currency amount.
