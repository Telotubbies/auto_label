## User story
As a reviewer, I want to decide, at upload time, whether labels inside a re-uploaded folder replace the
stored ones so that a corrected export updates my dataset instead of silently doing nothing.

## UX flow (LabelDesk words)
1. **Upload** — after files are picked (T-067), a checkbox sits under the split chips:
   "Replace annotations on images already in this project" — off by default; classification projects
   show it ticked and disabled with the hint "Classification labels are replaced on re-upload".
   [empty: no duplicate hashes in the pick yet → the row reads "No existing images to replace"]
   [loading: the row appears only once the pre-flight has finished hashing]
2. **Upload** — confirming with the switch on shows a second line in the confirmation:
   "12 existing images will have their labels replaced." [error: the user cancels → nothing is sent]
3. **Upload result sheet** — labels that named no image in the upload are reported per file:
   "3 label files matched no image — see reasons" and each row names the file and the expected image
   stem.

## Backend changes
- Models/schema: none.
- Routers: `apps/backend/app/routers/images.py`
  - `POST P/upload` gains `annotation_overwrite: bool = Form(False)`; passed to `ingest`.
  - `ingest(..., annotation_overwrite=False)` — when a hash already exists in the project and
    `annotation_overwrite` is true, the existing row's labels are replaced from
    `importers.annotations_for(...)` via `set_annotations`, `status` set to `review` (or `done` when
    `to_dataset` and a stored review already approved it), and the image is counted in a new
    `replaced` field. When false, today's "duplicate skipped" behaviour is untouched. Classification
    projects always replace.
  - Response gains `"replaced": n` and `"orphanLabels": [{"file": str, "reason": "no image with this name"}]`
    (label files collected by `importers.collect` that matched no image path).
- Services/jobs: keep every check in `ingest` (2-F2.9) — size, plan and unreadable rules stay in the one
  place; this card adds no new refusal rule.
- Permissions + workspace isolation: `c.need("reviewer")` unchanged; the hash lookup is
  `Image.project_id == c.project.id`; another workspace's project is a 404 from `project_ctx`.
- Secrets/safefetch: none.
- OpenAPI: yes — the multipart form field and response fields change.

## Acceptance criteria
- [ ] Re-uploading labelled images with the switch on updates labels and reports `replaced`.
- [ ] With the switch off, a duplicate is skipped and the stored labels are unchanged.
- [ ] Label files that match no image are listed by name, and the rest of the batch still lands.
- [ ] The existing refusals (oversize, plan limit, unreadable) still come from `ingest` only — no second
      rule set in the new branch.
- [ ] Empty/loading/error states above render (inline confirm line, result-sheet reason list).
- [ ] Flag off ⇒ the field is ignored and behaviour is exactly today's.
- [ ] Workspace A cannot see or change workspace B's data (404 for cross-workspace project ids).

## Notes for the implementer
A removed image is not a duplicate: `Image.deleted_at` rows are excluded from `known`, so re-uploading a
deleted image still takes the normal insert path (F2.35/T-097 owns revival). Only live duplicates reach
the replace branch.
