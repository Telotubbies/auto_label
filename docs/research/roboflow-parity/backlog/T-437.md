## User story
As a workspace lead, I want a hosted model's token use converted to credits at a published rate, so that one
burn-down covers local GPU time and vendor calls.

## UX flow (LabelDesk words)
1. **Settings → Integrations → `Hosted models` → `Rates`** — a read-only table per connected vendor/model:
   `1 credit buys` + `N input tokens` / `M output tokens` / `K images (OCR)`. A vendor with no published rate shows
   `No rate published for this model — calls are not metered.`
2. **A metered call** writes one `CreditEvent(kind="vendor_ai")` with `meta={vendor, model, input_tokens,
   output_tokens}`, so the ledger (T-408) and attribution (T-410) name it.
3. **Out of credits** — a call that would cross the allowance fails with the existing 402 path and the message
   `Hosted-model credits are used up. See your credit options.` linking T-419's banner actions.
4. **`[empty]`** no rate for the selected model: the pipeline step shows `Not metered.` and still runs.
5. **`[error]`** a vendor that reports tokens as 0 (cached or errored call) writes no ledger row, so the balance never
   moves for a failed call.

## Backend changes
- Models/schema: none — `CreditEvent` from T-408, `VendorKey` from T-436.
- Routers: `GET /api/ws/{ws}/vendors/rates` → `{rows: [{vendor, model, credits_per_1k_input, credits_per_1k_output,
  credits_per_image}]}`; reads `config.VENDOR_RATES`.
- Services/jobs: `config.py` gains `VENDOR_RATES: dict[tuple[str, str], dict] = {}` with a comment that the table is
  **empty until the owner publishes rates** (no invented numbers); `services/vendor_ai.py` — `cost(vendor, model,
  usage) -> float | None` returns `None` when no rate exists, else credits from the published table;
  `services/vendor_ai.py` records through `metering.record_credits(db, ws, "vendor_ai", credits, project_id,
  vendor=…, model=…, input_tokens=…, output_tokens=…)` and calls `deps.charge(db, ws, credits, kind="vendor_ai")`.
- Permissions + workspace isolation: rates are static config; metering writes the workspace's ledger only.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] The rate table is configuration with an empty default; no rate is invented.
- [ ] A metered vendor call writes one credit event naming vendor and model, and charges the same amount.
- [ ] A call with no tokens or no published rate charges nothing and says so in the UI.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no rate route and no metering.

## Notes for the implementer
The table ships empty on purpose: vendor token rates are a commercial decision the owner has not made. One function
reads it, so publishing rates later is a config change and no code change.
