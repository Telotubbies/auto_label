## User story
As a reviewer, I want to point at what the preview got wrong and press one button, so that the next preview is a correction rather than a new guess.

## UX flow (LabelDesk words)
1. **Auto Label → Preview → click a sample thumbnail** — the sample opens enlarged inside the dialog with its labels drawn as outlines (box, polygon, mask box) in class colours. [loading: the sample image decodes → skeleton box] [empty: a sample with no detections shows "Nothing found here" and only the missing-object action]
2. **Click a label** — a small menu: **Wrong class** (with a class select), **Should not detect this**, **Keep this**. The chosen verdict is stored as feedback and the label gains a badge (× for reject, ✓ for keep, a swap arrow for wrong class). [error: the record fails to save → the badge reverts and a toast says the feedback was not saved]
3. **Flag missing object** — toggles a crosshair mode; clicking the image posts a record with the class the user expects (a select) and an optional note, and draws a hollow marker there.
4. **Feedback list** — under the sample: "3 notes" listing the verdicts with the image name and a delete (removing a record is allowed until a revision uses it).
5. **Update preview** — sends the current params plus the batch; on success the preview re-runs with the returned params, the explanation appears above the strip ("Tightened the helmet description; kept the threshold"), and the chips show the new count. [loading: "Rewriting the prompt…" then the normal preview spinner] [error: 503 → "The prompt assistant needs a vision model on this worker" and the old preview stays]
6. **Thread** — a header row shows "Chat with the preview · 3 messages" and **Start a new chat** resets the notes; returning to the batch shows the same thread.
7. **Honesty** — the panel states what a revision can change: "The assistant can rewrite the prompt and thresholds. It cannot change your model, batch or classes."

## Acceptance criteria
- [ ] Clicking a preview label offers the three verdicts; each saves against the batch and badges the label.
- [ ] Flag missing object stores a normalised point and an expected class, and draws a marker.
- [ ] Update preview re-runs with the server's revised params and shows the explanation and the new count.
- [ ] The panel names exactly what a revision can and cannot change, and a failed revision leaves the old preview intact.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the panel is absent and the existing preview strip behaves as today.
- [ ] Keyboard-only path: Preview → Tab to a sample → Enter → Tab to a label button → Enter → choose verdict with arrows → Tab to Update preview.
