## User story
As a workspace manager, I want to upload my checker, enable it per project and see why it failed, so that the rule stays in code we own and I never have to run a listener myself.

## UX flow (LabelDesk words)
1. **Project → Settings → Extensions** — a list of installed packages: name, events, enabled switch, size, and `Run history`. [empty: "No extensions yet — upload a single .py entry file to enforce a rule on save."] [loading: three skeleton rows] [error: "These extensions did not load." + `Retry`]
2. **`Upload`** — file picker restricted to `.py`, a name field and three event checkboxes (`Label submitted`, `Label reviewed`, `Label skipped`); the file size is checked before the request. [error: "Package over the size limit." or "Only a single .py entry file is accepted."]
3. **`Test on one image`** — an image picker, then the run appears at the top of the history as `running` and settles into `done` or `failed` with its output. [loading: the row pulses until the run finishes] [error: "No runner available — start a worker and try again."]
4. **A failed run** — expands to the error tail and the payload preview, with the sentence "The label was saved; only the checker failed." [empty: "This package has not run yet."]
5. **`Disable`** — the switch turns the extension off and the history keeps every past run for audit.

## Acceptance criteria
- [ ] Settings → Extensions lists installed packages, their events and their enabled state.
- [ ] Uploading a package over the limit or with the wrong extension is refused before the request leaves the browser and again by the API.
- [ ] `Test on one image` shows the run settle into `done` or `failed`, and a failure states that the label was saved.
- [ ] Empty, loading and error states above all render: no-extensions line, no-runs line, the pulsing running row, the 413/409/422 sentences.
- [ ] Workspace A cannot see workspace B's extensions: the tab only calls this project's route and the nav hides Settings from a non-manager.
- [ ] Flag off ⇒ no Extensions tab and no request.

## Notes for the implementer
Owner-hold: BEYOND §4 names this as a non-goal; do not schedule until the owner overrules it.
Do not offer a requirements field, a zip upload or a "test all events" button — one file, three events, one run log is the whole scope, and the empty state should read like an option nobody has taken yet.
