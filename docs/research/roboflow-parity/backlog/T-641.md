## User story
As a reviewer preparing a batch, I want to open a class row and add the names the floor uses plus the ones that must never match, and to turn a customer's checklist into classes in one paste, so that the fifth plant starts from working wording instead of from zero.

## UX flow (LabelDesk words)
1. **Auto label → Class prompts** (`/:ws/:project/annotate`) — each class row is a checkbox plus a "Wording" disclosure. Opening it shows synonym chips, exclusion chips, one note line and Save. [empty: "Uses the class name only" with an "Add a synonym" field] [loading: the checkbox list paints first, the disclosure shows a skeleton row per class] [error: a rejected chip is the server's sentence under the field, and nothing is saved]
2. **A phrase used on two classes** — typing "bicycle helmet" as an exclusion on Helmet while Bike owns it as a synonym shows `[error: "bicycle helmet" is an exclusion on Helmet and a synonym on Bike]` and disables Preview and Run until one side is removed.
3. **Preview** — the per-class count line gains a separate "excluded" figure, so a class that only worked because of its exclusions is visible before the run.
4. **Classes & Tags → "Build from a list"** (`/:ws/:project/classes`) — paste lines of `name, phrase; phrase`, press Test: a table per line shows images with at least one hit, median boxes and a collision with an existing class. [empty: "Nothing pasted yet"; Test disabled] [loading: "Testing 6 lines on 20 samples…"] [error: 2 lines without a name are listed and skipped, never silently dropped]
5. **"Create 4 classes"** — classes appear with their packs attached; a zero-yield line keeps its row with "try a shorter phrase" instead of being deleted.
6. **Flag off** — the disclosure, the excluded count and the whole Classes panel are absent.

## Backend changes
- Models/schema: none — T-640 owns `classes.prompt` and its validation.
- Routers: none new; this card calls `PATCH .../classes/{cid}`, `POST .../classes` and `POST .../autolabel/preview`, and reads `stats.excluded` from the preview response.
- Services/jobs: none.
- Permissions + workspace isolation: the dialog is already reviewer-gated on the board (`canManage`); a class write needs `project.classes` and the UI hides the disclosure without it, but the server stays the authority.
- Secrets/safefetch: none.
- OpenAPI: no — no route or schema change beyond T-640's.

## Acceptance criteria
- [ ] A reviewer adds a synonym and an exclusion to one class, saves, and the next preview shows the class plus a separate excluded count.
- [ ] A phrase owned by another class blocks Preview and Run with a message naming both classes.
- [ ] A pasted checklist previews per line and creates the classes with packs attached; a zero-yield line is kept with a hint, never deleted.
- [ ] Empty, loading and error states above all render, including a class with no pack and a paste with no name.
- [ ] Workspace A cannot see or change workspace B's classes (404): the panel reads only this project's class list.
- [ ] Flag off ⇒ no Wording disclosure, no excluded column, no Build-from-a-list panel, and the dialog behaves as today.

## Notes for the implementer
The disclosure is closed by default so the dialog keeps its height; only one row is open at a time. Save is per class, not per batch — the pack belongs to the class, which is the whole point of the card. When Preview is blocked by a collision, name the class the phrase already belongs to; never invent a suggestion.
