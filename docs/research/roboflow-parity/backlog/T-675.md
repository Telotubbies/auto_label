## User story
As a quality engineer, I want each reject to carry the reason the plant defined and the piece or lot id, so that I can say "34 % rejected because of flash" and trace one bad lot, instead of only "34 % rejected".

## UX flow (LabelDesk words)
1. **A verdict is recorded from a stream event** — the operator's Accept or Reject lands with a reason, the operator and a time; the timeline row then reads `ไม่อนุมัติ · รอยขีดข่วน · LOT-2481`. [empty: an event with no verdict reads `ยังไม่ตัดสิน`, never `ผ่าน`]
2. **The reason list comes from the station** — five plant defaults (`รอยขีดข่วน`, `บุบ`, `ปนเปื้อน`, `ชิ้นส่วนผิด`, `อื่น ๆ`) until the station defines its own, which T-671 edits. [error: `เหตุผลนี้ไม่ได้อยู่ในรายการของสถานี` when a reject arrives with an unknown code]
3. **A reject without a reason is refused** — the API answers 400 and the operator screen keeps the sheet open. [loading: the button shows `กำลังบันทึก` under a second and the next frame loads itself]
4. **The breakdown** — the events list gains a reason filter and a per-reason count (`รอยขีดข่วน 12 · บุบ 4 · ปนเปื้อน 2`), read from the summary route T-676 renders. [empty: `ยังไม่มีคำตัดสินในช่วงนี้`]

## Backend changes
- Models/schema: `StreamEvent` gains `verdict VARCHAR(8) DEFAULT ''` (`accept|reject`), `reason VARCHAR(64) DEFAULT ''`, `piece_id VARCHAR(120) DEFAULT ''`, `operator_id VARCHAR(32)` (null), `verdict_at FLOAT` (null), as one `ADD COLUMN` block in `app/schema/streams.py` `STREAM_EVENTS`; `list_events` gains `verdict=`, `reason=` and `piece=` filters over the new columns (a `piece` filter is a `LIKE` on `piece_id`).
- Routers: `app/routers/verdicts.py` (new), prefix `/api/ws/{ws}/projects/{project}`, `dependencies=[Depends(require_flag("task_operator_verdict"))]`; `POST /streams/{sid}/events/{eid}/verdict` `{verdict, reason?, piece_id?}` → the event; `GET /streams/{sid}/verdicts/summary?start&end` → `{accept, reject, decided, by_reason: [{reason, n}], undecided}`; `GET /verdict-reasons?stream=` → `{reasons: [str], source: "station"|"project"}`. 400 reject without a reason or with a reason outside the list, 400 `piece_id` longer than 120 chars or with control characters, 422 verdict outside `accept|reject`.
- Services/jobs: `app/services/verdicts.py` (new) — `DEFAULT_REASONS = ("scratch", "dent", "contamination", "wrong part", "other")`, `effective_reasons(db, project, stream)`, `record(db, event, body, user_id) -> StreamEvent` (last verdict wins, `operator_id` and `verdict_at` overwritten in the same write), `summary(db, stream_id, start, end)` with `by_reason` ordered by count descending then code. `event_out` gains `verdict`, `reason`, `piece_id`, `operator`, `verdict_at`.
- Permissions + workspace isolation: `POST` needs `project.review` (manager or reviewer — a labeler cannot decide a piece, which the card states in the operator screen's disabled state); `GET /summary` needs `project.streams`; the event is resolved through the stream, and the stream through `workspace_id` + `project_id`, so a foreign event id is 404 before any write.
- Secrets/safefetch: none — no URL is fetched; `piece_id` is validated as text (length, no control characters) and rendered escaped.
- OpenAPI: yes — three new routes and `event_out` changes shape.

## Acceptance criteria
- [ ] A reviewer records accept or reject with a reason and an optional piece id, and the event keeps who decided and when.
- [ ] A reject without a known reason is refused with 400 and the event keeps its previous verdict.
- [ ] The summary counts accepts, rejects, undecided and the reasons in descending order.
- [ ] Empty, loading and error states above all render — an undecided event reads `ยังไม่ตัดสิน` and an empty window reads `ยังไม่มีคำตัดสินในช่วงนี้`.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the verdict routes 404, `event_out` keeps today's shape and `reviewed` is the only vocabulary.

## Notes for the implementer
`reviewed` stays exactly as it is: a verdict is a new field, not a rename, so every existing timeline, filter and export keeps working while the flag is on. The reason list is read from the station when the stream has one and from `project.settings["verdict_reasons"]` otherwise; never accept a free-text reason from the API — the whole point is a countable vocabulary. `verdict_at` is server time; do not trust a client clock in a factory with a wrong timezone.
