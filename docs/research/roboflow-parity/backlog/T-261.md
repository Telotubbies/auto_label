## User story
As an ML engineer, I want the dataset block to tell me which data the run will use and whether it is good enough, in one glance, so that I do not discover a thin validation split after paying for the run.

## UX flow (LabelDesk words)
1. **Train → 1 Dataset** — a two-option control (*Current dataset* / *Saved version*), then the relevant detail. [empty: no approved images ⇒ "No approved images yet — approve a batch to train." + one primary to Annotate; no options] [loading: a two-line skeleton for the counts; the control is usable] [error: "The dataset could not be read" + Retry; the option that failed is the only one disabled]
2. **Health chip** — beside the selected dataset: green "Ready" / amber "2 warnings" / red "3 blockers", with the count linking to the expanded list (T-262's `PreflightList`). Clicking a chip opens the list; it never navigates away.
3. **Saved version selected** — the recipe summary renders read-only through T-256's `RecipeLockRows`: "Resize 640 · stretch · frozen at generation". *Current dataset* selected — the same rows show the project's stored defaults with an edit note ("Applies to the version this run creates").
4. **Version row detail** — images, train/valid/test counts, class count, and the age ("created 3 days ago"), so a stale version is visible before it is trained.
5. **A version still generating** — the option is dimmed with "v5 is still generating (62%)" and cannot be selected. [error: a failed version prints "v5 failed — open Versions for the reason"]

## Acceptance criteria
- [ ] The block offers current-or-version and states exactly which data the run will train on.
- [ ] A health chip shows blocker/warning counts and opens the list in place.
- [ ] A saved version's recipe rows are visibly read-only with the reason; current mode says the rows apply to the version this run creates.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ today's select-only block, no chip, no two-option control.

## Notes for the implementer
The chip never blocks — only blockers do, and T-262 owns that decision. One source of numbers: the preflight payload; do not recompute split counts from `Version.stats` in the component.
