## User story
As a reviewer, I want the query I typed to drive the same grid, the header counts and the "select all
matching" action so that a filter is one durable thing instead of a set of hidden dropdowns.

## UX flow (LabelDesk words)
1. **Dataset · Images** — the grid requests `?q=<query>` plus any legacy filter still in the URL.
   [loading: the count line shows "…" and the grid keeps 12 tile skeletons] [empty: "No images match
   this query" + "Clear filters" (T-062)]
2. **Dataset · Images** — the response echoes the parsed query so the box can underline the offending
   term instead of guessing. [error: 400 with `detail.position` → the message in T-060's UX step 2]
3. **Dataset · Images** — the user presses "Select all matching"; the bar says "All 412 images in this
   query are selected" and a bulk action applies to those 412, not the 24 tiles loaded.

## Backend changes
- Models/schema: none.
- Routers: `apps/backend/app/routers/images.py`
  - `GET P/images` gains `query: str = ""`; when non-empty it is compiled by `services.query` and
    ANDed with the legacy parameters (legacy params keep working untouched). Response gains
    `"query": {"text": str, "termCount": int}`; a `QueryError` becomes
    `HTTPException(400, detail={"message": ..., "position": ...})` via `JSONResponse`.
  - `POST P/images/bulk` gains `query: str | None`; when set, the server resolves the ids itself
    (cap 10 000; above → 422 with the count). `ids` and `query` are mutually exclusive (400).
  - Both routes keep `Depends(project_ctx)` and the whole route file is decorated with the T-060 flag
    check (`require_flag("task_60")` on the query branch only, so legacy calls still work when off).
- Services/jobs: reuse `services/query.compile`; no new job.
- Permissions + workspace isolation: `project.read` for the list; the bulk branch keeps
  `c.need("reviewer")` for every action it already gates. A project id from another workspace is a
  404 from `project_ctx`; the id set returned by a query is built from `Image.project_id` only.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate `openapi.json` and `api-types.gen.ts`.

## Acceptance criteria
- [ ] A query and legacy filters together narrow the grid; removing the query restores the old result.
- [ ] Bulk-by-query touches every matching image, not the loaded page, and stops at 10 000 with 422.
- [ ] A malformed query returns 400 with a caret position; the previous result stays visible.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404 for cross-workspace project ids).
- [ ] Flag off ⇒ `query` is rejected 404, the legacy parameters behave exactly as today.
