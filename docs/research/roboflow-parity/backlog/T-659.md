## User story
As a team that can afford a foundation model once but not at inference, I want a student-versus-teacher table on a held-out slice and a promotion that refuses a failing class, so that distillation is proven by one artefact instead of two mAP numbers computed on different data.

## UX flow (LabelDesk words)
1. **Models → a trained model → Teacher agreement** (`/:ws/:project/models`) — "Compare with the teacher on 100 held-out images" with the split named (test by default). [empty: no teacher-sourced labels on that split ⇒ "This split has no teacher labels — auto-label it first"]
2. **Running** — `[loading: "Running the student on 100 images…"]`, `[error: "the model has no weights yet"]`.
3. **The table** — per class: agreement %, student-only boxes, teacher-only boxes, mean IoU on matches, and a note where the student wins. Labels keep their origin (`sam3`, `vlm+sam3`, model), so the teacher column is auditable.
4. **Promoting** (`/:ws/deployments`) — with a threshold set on the project, "Deploy" refuses when agreement is under it: "Helmet is at 71 % against a 85 % threshold" and offers "Deploy anyway" behind a reason field. [error: the refusal names the failing classes, never just a number]
5. **Flag off** — no agreement row, no refusal, and promotion is exactly as today.

## Backend changes
- Models/schema: none — the result is stored on `TrainedModel.metrics["teacher_agreement"]` (JSON already on the row); the threshold lives in `Project.settings["teacher_gate"] = {"min_agreement": 0.85, "split": "test"}`, default off (`null`).
- Routers: `POST /api/ws/{ws}/projects/{project}/models/{mid}/teacher-agreement` → 202 job; `GET .../models/{mid}` already returns `metrics`, so the table needs no second read; `PUT .../deployments/{alias}` gains `override: bool = False` and `reason: str = ""`, returning 409 "teacher agreement below the threshold" (with `classes` in the body) unless the override carries a non-empty reason, which is audited as `model.deploy.override`.
- Services/jobs: `services/teacher_agreement.py` (new) — `teacher_labels(db, project, version, split)` collecting annotations whose `source` is not `human`, `student_boxes(student, image)` from `resolve(f"trained:{mid}")`, `compare(teacher, student, iou=0.5)` returning per-class `{agreement, student_only, teacher_only, mean_iou, student_wins}`; job kind `teacher_agreement` in `LOCAL_JOB_KINDS`; the gate is a pure `gate(metrics, settings) -> {"pass", "failing": [...]}`.
- Permissions + workspace isolation: `project.models` to run and read, `admin` to override a promotion (the route already needs `admin`); the model id is checked against `c.project.id` (404), and a version id from another project never reaches the job.
- Secrets/safefetch: none — the teacher is not re-run; its stored labels are read, and the student runs locally.
- OpenAPI: yes — regenerate (`python tools/export_openapi.py`, `npm run gen:api-types`).

## Acceptance criteria
- [ ] A student is compared with the stored teacher labels on a held-out split, per class, with agreement, both-only counts and mean IoU on matches.
- [ ] Promotion refuses below the project's threshold and names every failing class, and an override requires a written reason that is audited.
- [ ] A split with no teacher labels says so instead of showing zero percentages.
- [ ] Empty, loading and error states above all render, including a model with no weights yet.
- [ ] Workspace A cannot run or read workspace B's agreement (404 on a foreign model id).
- [ ] Flag off ⇒ no agreement block, no threshold and no refusal on promotion.

## Notes for the implementer
The teacher is never re-run: its labels are already stamped with their origin by `adapters/refine.py`, so this is a comparison of stored evidence. IoU 0.5 marks a match, the same threshold the evaluation uses; a student-only box is not automatically wrong — say so in the note where the student wins. The gate is off until a manager sets a threshold, so no existing promotion changes.
