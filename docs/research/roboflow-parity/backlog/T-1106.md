## Finding
`apps/frontend/src/components/ui.tsx` (`Modal`) puts `role="dialog" aria-modal="true"` on the panel but gives it no accessible name. axe reports `aria-dialog-name` (serious) on every modal, in light, dark and at 375 px.

## Change
The modal's title heading gets a stable id from `useId()`, and the panel points to it with `aria-labelledby`. A modal without a visible title must take an `aria-label` prop. Make that prop required in the type when there is no `title`, so the compiler catches a dialog that has no name.

## Tests (first)
- A node test checks that `Modal` wires `aria-labelledby` to its title id and accepts `aria-label`.
- A type-level check: a `Modal` with neither a title nor an aria-label fails `tsc` (one `@ts-expect-error` line in a test file).
- e2e: an axe scan of the new-project dialog reports zero `aria-dialog-name` violations. Use the T-1200 harness axe helper.
- Every existing `Modal` call site compiles; list them in the report.
