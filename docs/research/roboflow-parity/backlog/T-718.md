## User story
As a QC engineer, I want to see exactly what a pack will create — the classes, the thresholds, the station — and what it will still need from me, before I press install, so that "one click" is not a surprise.

## UX flow (LabelDesk words)
1. **`ชุดติดตั้งสำเร็จรูป`** (`/:ws/:project/ops/packs`) — two cards, one per shipped pack, each with its class chips, its threshold per class, the station it creates and a list of what stays manual (`เพิ่มกล้อง`, `วาดโซน`, `อัปโหลดภาพดี`). [empty: `ยังไม่มีชุดติดตั้งในเครื่องนี้`] [loading: `กำลังโหลดชุดติดตั้ง`] [error: `โหลดชุดติดตั้งไม่สำเร็จ — ลองอีกครั้ง`]
2. **Install** — `ติดตั้ง` becomes a per-item progress list, one row per class and one for the station, each moving from `กำลังติดตั้ง` to `สร้างแล้ว` or `มีอยู่แล้ว`. [error: `ติดตั้งไม่สำเร็จ — {reason}` under the failing row, and the rest of the items stay as they finished]
3. **An installed pack** — the card shows `ติดตั้งแล้ว · {date}` and the button becomes `ติดตั้งแล้ว` (disabled), with the station name linked to the station page. [error: the 409 from a double submit renders the same disabled state, never a duplicate]
4. **A pack that does not fit this project** — the IC/PCB pack on an object-detection project reads `ชุดนี้ต้องใช้โปรเจกต์แบบจำแนกภาพ — สร้างโปรเจกต์ใหม่ก่อน` and the button is dimmed with the lock line.
5. **A labeler** — every install button is dimmed with `ต้องมีสิทธิ์ผู้จัดการโปรเจกต์เพื่อติดตั้ง`, per the permission = dimmed + lock rule.

## Backend changes
- Models/schema: none.
- Routers: none — the page reads `GET /packs` and posts `POST /packs/{id}/install`.
- Services/jobs: none.
- Permissions + workspace isolation: the route is `<PermGate perm="project.read">`; buttons are disabled unless `can('project.settings')` and the API enforces the same rule with 403. A project id from another workspace is 404 through T-717.
- Secrets/safefetch: none.
- OpenAPI: no — no route changes.

## Acceptance criteria
- [ ] Each pack card states its classes, thresholds, station and the manual steps that remain before a first run.
- [ ] Installing shows one row per item, and a skipped class says so rather than pretending it was created.
- [ ] An installed pack shows its date and cannot be installed twice from the UI.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no gallery, no Ops item, and `Home.tsx` is unchanged.
