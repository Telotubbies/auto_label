## User story
As a reviewer, I want to drag a box on the annotation heat map and land on exactly the images annotated
there, so that "everything is bottom-left" becomes a filterable list instead of an observation.

## UX flow (LabelDesk words)
1. **Dataset · Health** — the heat map already renders 100 cells (10 × 10) from `/analytics`.
   [loading: the map's cells are skeleton blocks until analytics resolves] [empty: no images → the map is
   replaced by the upload prompt the page already shows]
2. **Dataset · Health** — dragging across cells highlights the rectangle and shows "Selecting 412
   annotations in 3 × 2 cells…". [error: a drag that selects no annotation → "No annotations in that
   region — try a larger box"]
3. **Dataset · Images** — after release the grid opens filtered to those images with a chip
   "Annotation region · 3 × 2 cells ×", and the count matches the cell sums. [loading: 12 tile skeletons]
4. **Dataset · Images** — removing the chip restores the previous view; the selection also works as a
   `selection` token for bulk actions.

## Backend changes
- Models/schema: none.
- Routers: `apps/backend/app/routers/insights.py` —
  `POST /heat-selection` body `{rows: [r0, r1], cols: [c0, c1]}` (0–9, inclusive) →
  `200 {token, count}`; `400` for out-of-range cells; reuses `insights.save_selection` so the grid's
  existing `?selection=<token>` path needs no change.
- Services/jobs: `apps/backend/app/services/insights.py` — one function
  `heat_selection(db, project, rows, cols) -> list[str]` walking the same centre calculation
  `routers/projects._analytics` uses (`bbox` centre, polygon centroid), so the map and the filter can never
  disagree.
- Permissions + workspace isolation: `project.read` (the analytics endpoint it complements allows any
  project member; labelers still get only their assigned images through the existing `selection` +
  `_visible` path); rows come from `Image.project_id == c.project.id`.
- Secrets/safefetch: none.
- OpenAPI: yes — one route.

## Acceptance criteria
- [ ] A cell or rectangle maps to the same images the heat map counted, using one shared centre rule.
- [ ] The response is a selection token the existing grid filter already understands.
- [ ] An empty region returns zero with a valid token, not an error.
- [ ] Out-of-range cells are a 400.
- [ ] Empty/loading/error states above render (map skeletons, empty-region copy, chip).
- [ ] Flag off ⇒ no route and no dragging.
- [ ] Workspace A cannot see or change workspace B's data (404 for a foreign project id; labeler scope
      preserved).

## Notes for the implementer

already resolves inside one project. Share the centre calculation with `routers/projects._analytics` by
extracting it rather than copying the four lines.
