## User story
As an engineer with a 512 MB budget, I want one table of this project's models with their measured accuracy, latency and size, the Pareto front marked and the binding constraint named, so that I choose something that runs instead of the most accurate thing that does not fit.

## UX flow (LabelDesk words)
1. **Train → `หาค่าที่เหมาะกับอุปกรณ์`** (`/:ws/:project/train`, under the target field) — `[loading: วัดแล้ว 7/24 · ดีที่สุด 0.81 mAP @ 41 ms]` while the job measures each ready model on this worker. [empty: `ยังไม่มีโมเดลที่วัดได้ — เทรนหนึ่งโมเดลก่อน`]
2. **The table** — one row per ready model: mAP, median latency (`วัดบนเครื่องนี้`), p95, size, RAM estimate (`ประมาณจากขนาดไฟล์`), a `พอดี` / `ไม่พอดี` chip and a Pareto marker. Sortable by accuracy, latency and size.
3. **Nothing fits** — the panel answers `ไม่มีค่าที่พอดีกับ 512 MB — ต่ำสุดที่วัดได้ 610 MB` and names which limit binds (flash or RAM, never both). [error: `วัดไม่สำเร็จ — อะแดปเตอร์ไม่พร้อม` when a model cannot be loaded]
4. **`ใช้ตัวนี้`** — prefills the Train form with that model as `continue from`, its variant and the target, and scrolls to the start button; nothing trains until the user presses start.
5. **`วัดใหม่`** — re-runs the measurement over models measured before the last training finished, and keeps the earlier numbers visible while it runs.

## Backend changes
- Models/schema: none — results are written to `TrainedModel.metrics["target_search"]` (`{latency_ms, p95_ms, size_mb, ram_est_mb, measured_on, at}`) and read by the candidates route.
- Routers: `app/routers/target.py` (T-684 created it) gains `POST /deploy-targets/{target}/search` → 202 with the job, and `GET /deploy-targets/{target}/candidates` → `{target, budget, fits_any, binding, rows: [{model_id, name, map, latency_ms, p95_ms, size_mb, ram_est_mb, fits, pareto, measured_on}]}`; `GET` returns 400 with `binding` when nothing fits.
- Services/jobs: `app/services/target_search.py` (new) — `measure(adapter, model, image) -> {median_ms, p95_ms}` (five warm runs on one stored image), `fits(row, budget) -> (bool, "flash"|"ram"|"latency"|"")`, `pareto(rows)` (a row is on the front when no other row is better on both mAP and latency), `candidates(db, project, target)`. `app/handlers/target_search.py` (new) with `run_target_search(job)` in `handlers/__init__.py` `MODULES` and `target_search` in `config.LOCAL_JOB_KINDS`.
- Permissions + workspace isolation: search needs `c.need("admin")`; candidates need `project.train`; every model is read through `workspace_id` + `project_id`, and a target name is a constant, so no request can widen the set.
- Secrets/safefetch: none — weights and one stored image are local.
- OpenAPI: yes — two routes and their schemas.

## Acceptance criteria
- [ ] The search measures each ready model on this worker and shows accuracy, median and p95 latency, size and a RAM estimate in one sortable table.
- [ ] The Pareto front is marked and every row carries a `พอดี` / `ไม่พอดี` chip against the target budget.
- [ ] When nothing fits, the panel names the binding limit and the smallest measured size, and `ใช้ตัวนี้` still works on a row.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no search panel, no candidates route, and Train is today's.

## Notes for the implementer
Measure, do not promise: latency comes from five warm forward passes on this worker and the row says so; the RAM number is `2 × artifact size` and the row says `ประมาณจากขนาดไฟล์`. Pareto is a marker on top of a normal sort, never a filter — a user must be able to pick an off-front row deliberately. Copy: `train.search.find`=`หาค่าที่เหมาะกับอุปกรณ์`, `train.search.running`=`วัดแล้ว {n}/{total} · ดีที่สุด {map} @ {ms} ms`, `train.search.empty`=`ยังไม่มีโมเดลที่วัดได้ — เทรนหนึ่งโมเดลก่อน`, `train.search.noneFits`=`ไม่มีค่าที่พอดีกับ {mb} MB — ต่ำสุดที่วัดได้ {lowest} MB`, `train.search.measuredOn`=`วัดบนเครื่องนี้`, `train.search.estimated`=`ประมาณจากขนาดไฟล์`, `train.search.use`=`ใช้ตัวนี้`, `train.search.again`=`วัดใหม่`, `train.search.failed`=`วัดไม่สำเร็จ — อะแดปเตอร์ไม่พร้อม`, `train.search.fits`=`พอดี`, `train.search.overBudget`=`ไม่พอดี`.
