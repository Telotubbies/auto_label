## User story
As an admin, I want "select all 940 matches" and one export that matches the query exactly, so that a download is reproducible and I cannot accidentally export a stale 60-tile page.

## UX flow (LabelDesk words)
1. **Selection bar** — next to the count: `Select all 940 matching`. Clicking it turns the bar into `All 940 matches selected · Clear`. The destructive and expensive actions (`Delete`, `Export`, `Run a workflow`) stay disabled until this click, so a workspace-wide delete needs one extra deliberate step.
2. **Export** — `Export` opens a sheet: format chips (`Images + annotations (COCO)`, `Images only (ZIP)`), the sentence `940 images from 7 projects`, and `Start export`. The job appears in the job tray as `Export · 940 images` with progress and a download link on completion. [empty: zero matches → `Export` disabled with `Nothing matches this query.`] [loading: button reads `Starting…`, then the job takes over] [error: `You need export rights in Line A. Ask an admin, or clear that project from the query.`]
3. **Delete all matches** — confirm sheet requires typing the count (`940`) before the destructive button enables.
4. **Job finishes** — the tray row links to the zip; the zip contains `manifest.json` (query echoed) and one folder per project.

## Backend changes
- Models/schema: none — `jobs` already stores `params` and `result`.
- Routers: `routers/assets.py` gains `POST /export` body `{filters: {...}, format: "coco"|"zip", ids?: [str], all: bool}` → `{job: {id, kind, status}}`; resolves ids at request time (cap 20 000) and stores them in `job.params`; 403 with `{projects: [...]}` when any included project lacks `project.export` for the caller; 409 when a job with the same id-set is already queued.
- Services/jobs: `services/asset_export.py` (new) — `run(job)`: copies bytes + a manifest, writes the zip under `DATA_DIR/exports/ws/<job id>/`, sets `job.result = {"path", "images", "projects", "format"}`; `handlers/assets.py` (new) exposes `run_assets_export` and registers `{"assets_export": run_assets_export}`; `assets_export` added to `LOCAL_JOB_KINDS` in `config.py`.
- Permissions + workspace isolation: `workspace.read` plus `project.export` on every included project (owners/admins inherit it); a foreign workspace slug 404s; the job runs under `job.workspace_id` only.
- Secrets/safefetch: none — no external fetch; signing reuses `security.sign_path` for the download URL.
- OpenAPI: yes.

## Acceptance criteria
- [ ] `Select all N matching` selects the query result, and export/the workflow action unlock only after it.
- [ ] The export contains exactly the frozen id set with a manifest, and the job is visible in the tray with a download link.
- [ ] Empty, loading and error states above all render (nothing matches, starting, missing-rights list).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) and the download path is signed.
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
- [ ] No zip larger than the workspace storage quota is produced (refused with a 402-style message).

## Notes for the implementer
Freeze the ids at request time — do not re-run the query in the worker, or the export stops matching the sentence the user approved. Cap 20 000 ids and say so in the sheet.
