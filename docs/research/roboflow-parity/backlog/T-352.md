## User story
As a workspace owner with a data-residency requirement, I want a dedicated runtime to exist as a first-class option with a defined lifecycle, so that the day a provider is chosen it is configuration rather than a new feature.

## UX flow (LabelDesk words)
1. **Delivery options** (`/:ws/:project/deploy`) — the `Dedicated` row changes from "Not available in this deployment." to "Not configured yet." with one line: "A private box needs a provider to be chosen. Nothing is charged until one is." When `LD_DEDICATED_DRIVER` names a driver, the row becomes `available: true` and links to the panel. [empty: no deployments → "No private boxes. Create one to get a fixed endpoint."] [loading: the row shows its disabled state, never a spinner on the table] [error: a create that the driver refuses → "The provider refused this request: <reason>." with the raw reason in a details fold]
2. **The lifecycle** — `Create` takes a type (`dev` | `prod`), a size (`cpu` | `gpu`), an optional lifetime in hours and an optional startup script; the row then reads `pending` → `ready` with a domain, and offers Pause, Resume, Delete. `dev` states its consequences on the button's tooltip: "Deleted after 3 hours, pauses itself after 1 hour, may be evicted."
3. **Polling** — the panel polls every 30 s only while a row is `pending`, and stops when nothing is pending.
4. **The honest default** — with no driver configured every lifecycle route answers `501 "not available in this deployment"`, so a client built against the interface sees a reason rather than a 404.

## Backend changes
- Models/schema: new module `apps/backend/app/models/dedicated.py` — `DedicatedDeployment` (`id`, `workspace_id`, `project_id`, `kind` ∈ `dev|prod`, `size` ∈ `cpu|gpu`, `status` ∈ `pending|ready|paused|deleting|deleted|failed`, `domain`, `driver` (`mock` or empty), `external_id`, `lifetime_h`, `startup_script`, `last_error`, `created`, `updated`, `ready_at`), registered in `models/__init__.py`.
- Routers: `apps/backend/app/routers/runtimes.py` — `GET /api/ws/{ws}/projects/{project}/dedicated`, `POST …/dedicated` (create), `POST …/dedicated/{id}/pause`, `…/resume`, `DELETE …/dedicated/{id}`; every one returns 501 when `settings.dedicated_driver` is empty.
- Services/jobs: `apps/backend/app/services/dedicated.py` (new) — `PROTOCOL` documented as five methods (`create`, `pause`, `resume`, `delete`, `state`), `configured() -> str` reading `LD_DEDICATED_DRIVER`, `driver() -> DedicatedDriver` returning `MockDriver` in tests and raising `NotConfigured` in a deployment with no driver, `create/pause/resume/delete` writing the row before and after each driver call so a crash mid-call leaves a visible `failed` row, `sweep_expired(now)` deleting a `dev` box past its lifetime.
- Permissions + workspace isolation: create/delete need `workspace.billing` (a box costs money by existence) and `project.models`; reads need `project.models`; ids are project-scoped, so a foreign id is 404.
- Secrets/safefetch: no vendor credential exists yet; the startup script is stored as text and capped at 4 KB, and is never executed by this deployment.
- OpenAPI: yes — five routes.

## Acceptance criteria
- [ ] With no driver, the row says "Not configured yet." and all five routes answer 501 with a reason.
- [ ] With the mock driver, a box walks pending → ready → paused → ready → deleted, and a driver error leaves a `failed` row with its reason.
- [ ] A `dev` box past its lifetime is swept; a `prod` box is not.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ today's "not available" row and no routes.

## Notes for the implementer
The driver is configuration, not code: `LD_DEDICATED_DRIVER` names it, `MockDriver` is the only implementation in this card, and no vendor SDK, credential or price is invented. The row is written before the driver call and updated after, so an interrupted create is diagnosable instead of invisible.
