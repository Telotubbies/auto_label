## User story
As someone who has just labelled twenty images, I want a rough working model without choosing anything or spending credits, so that I can see whether the idea is even possible before committing to a real run.

## UX flow (LabelDesk words)
1. **Models → empty state** — a secondary action *Get a quick model* beside *Train a model*: "Runs a short fixed recipe on what you have approved. Free, detection only, usually ready in minutes."
2. **Confirm** — one dialog: what it is ("20 epochs, 640 px, YOLO26 Nano, no augmentation"), its limit ("up to 1,000 approved images"), and that it counts against GPU time but not credits. Primary *Start quick model*.
3. **Too little data** — the action is disabled with "Approve at least 20 images first — this project has 12." [empty: no images at all ⇒ the action is absent and the upload prompt shows]
4. **Too much data** — over 1,000 approved images the action is disabled with "Quick models are for small batches — use Train for this dataset." and a link to Train.
5. **Running** — the job tray shows "Quick model · 38 %"; the model appears in the list as *Quick model* with a badge, deployable like any other.
6. **Not a detector project** — the action is absent on classification projects, replaced by one line: "Quick models need a detection project."

- **States** — [loading: the dialog's primary shows a spinner from press to response] [error: a 400 renders its sentence in the dialog and the chosen version is kept].

## Backend changes
- Models/schema: `trained_models.engine VARCHAR(16) DEFAULT 'fine_tune'` (`fine_tune|search|instant`) so the list can badge it. Append to `TRAINED_MODELS` in `apps/backend/app/schema/training.py`.
- Routers: `POST {P}/train/quick` (no body beyond `version_id | mode=current`) → `201 model_out`; **400** cases: not a detection project ("quick models need a detection project"), under 20 approved images ("approve at least 20 images first"), over 1,000 training images ("quick models are for small batches"), a project already running (`T-262`'s guard). No new credit path: it reuses `POST /train`'s internals with a fixed `TrainIn`.
- Services/jobs: new `apps/backend/app/services/quick_model.py` — `RECIPE = {"epochs": 20, "imgsz": 640, "batch": 16, "training": {}}`, `VARIANT = "yolo26n"`, `LIMIT = 1000`, `MIN_IMAGES = 20`, `eligible(project, version) -> (bool, reason)`, `enqueue(db, c, version) -> TrainedModel` that reuses the train enqueue (one code path: the router's helper is factored, not copied). `config.CREDIT_COST["train_instant"] = 0` — the metering check still runs (`metering.check(..., "gpu_seconds", quote_seconds)`), so a workspace with no GPU allowance left is refused with the same 402.
- Permissions + workspace isolation: `c.need("admin")` (it starts a run); foreign project → 404.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate both files.
