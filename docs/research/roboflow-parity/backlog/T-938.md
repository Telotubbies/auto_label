## User story
As a member of a delivery team, I want a Dockerfile for the model I just trained, so that I can run it on our own machine without reverse-engineering your inference code.

## UX flow (LabelDesk words)
1. **Model detail → Container** — the user picks a target (CPU / NVIDIA GPU) and clicks "Prepare container files". [empty: a family with no supported target shows the reason and the supported list, and the button stays disabled] [loading: "Preparing…" then the file list appears] [error: "This model cannot be containerised: <reason>" where the reason names the missing export, e.g. "Build and download an ONNX export first"]
2. **Download** — a zip with `Dockerfile`, `serve.py`, `model.json`, the weights, `requirements.txt` and `README.txt`. The README's first command is `docker build -t <name> . && docker run -p 8080:8080 <name>`.
3. **Verify** — the README quotes the health path and one `curl` whose body is taken from the model's own input example, so the first run answers instead of erroring.
4. **Too big** — when the artefact is over 2 GB the page says the image will be large and offers the ONNX export first.

## Backend changes
- Models/schema: none.
- Routers: `GET {P}/models/{mid}/container?target=cpu|gpu` returns `application/zip`; 409 when the model is not ready or has no weights, 400 for an unknown target, 503 when the family has no generated server. `project_ctx`, `project.read`.
- Services/jobs: `apps/backend/app/services/container.py` (new) — `TARGETS = {"cpu": {...}, "gpu": {...}}`, `render(m, db, target) -> dict[str, bytes]` producing `Dockerfile` (base `python:3.12-slim` for cpu, `nvidia/cuda:12.4.1-python3.12` for gpu; `pip install -r requirements.txt`; `EXPOSE 8080`; `CMD ["python", "serve.py"]`), `serve.py` (a 60-line FastAPI app with `POST /invocations`, `GET /ping`, `GET /version` that loads the artefact through `services/artefacts.py`), `README.txt`. No templating dependency: three `str.replace` calls on fixed templates.
- Permissions + workspace isolation: `project_ctx`; weights path comes from the model row, never from the query.
- Secrets/safefetch: none — the generated files contain no LabelDesk URL, key or hostname.
- OpenAPI: yes — `python tools/export_openapi.py`, `npm run gen:api-types`.

## Acceptance criteria
- [ ] A ready model produces a zip whose README's two commands build and run it on port 8080.
- [ ] The generated server answers `GET /ping` and `POST /invocations` against the model's own input example.
- [ ] A model without weights, an unknown target and a flag-off request each return a distinct status with a readable message.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
