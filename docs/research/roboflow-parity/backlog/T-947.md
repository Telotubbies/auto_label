## User story
As an ML engineer, I want to choose which pinned set a model is scored against, so that a number on screen
always says which images produced it.

## UX flow (LabelDesk words)
1. **Models → a model → Evaluation** — the panel header gains the set: "Scored on *Gate line test* · pinned
   12 Nov · digest a91f2c3d". A secondary *Evaluate again* opens a menu. [empty: a model with no
   evaluation shows *Run evaluation* as the primary and no charts] [error: "Evaluation could not be
   started: <reason>" under the button, the old report left intact]
2. **Choose the data** — the menu lists the model's own version split first, then every set in the
   project; each entry shows images and the date it was pinned.
3. **Run** — the panel badge becomes *Queued*, then *Running* with "evaluating 820 images"; the old report
   stays dimmed until the new one lands. [loading: the button reads *Starting…* and cannot be pressed
   twice]
4. **The result carries its set** — after the run the header names the set, the digest and the time; the
   compare screen shows the same label so two numbers are never silently compared across sets. [empty: a
   set that was deleted after a run keeps the run's stored name and prints "(set deleted)"]
5. **Refusal** — a model whose status is not `ready` gets the menu entry dimmed with "not ready".

## Backend changes
- Models/schema: no new column — the set rides the existing report: `trained_models.metrics["eval"]` gains
  `set_id`, `set_name`, `set_digest`, `evaluated_at`.
- Routers: `POST {P}/models/evaluate` (T-283's route) gains `set_id: str | None`; when present the payload
  returns `set: {id, name, digest}` and the job is enqueued with `params.set_id`. `GET {P}/models/{mid}`
  (in `apps/backend/app/routers/training.py:304`) passes the three fields through `model_out`. 404 for a
  foreign or unknown set, 409 while the model is not `ready`.
- Services/jobs: `apps/backend/app/handlers/training.py` — `run_eval_model(job)` (created by T-283) reads
  `params.set_id`, resolves the set to `(version, split)` through
  `services.evaluation_sets.get`, and calls `w.evaluate(...)` with that version's directory and the set's
  split through a new keyword `split=` on `services.evaluate.evaluate`; the report gains the three set
  fields before it is stored.
- Permissions + workspace isolation: `c.need("admin")` on the run (it spends compute), `project.review`
  to read; a set id from another workspace is a 404.
- Secrets/safefetch: none. Dependency: none added (no `mlflow-skinny`), so no
  `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] A model can be scored against a set pinned on a different version, and the report names that set and digest.
- [ ] A report without a set keeps today's header and today's behaviour.
- [ ] A changed image on disk fails the run with the sentence above instead of producing a misleading number.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
