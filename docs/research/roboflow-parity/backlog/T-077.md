## User story
As a workspace admin, I want a **Test connection** button that tells me *why* a bucket fails — wrong key,
path-style, region, or a blocked endpoint — so that setup stops being an afternoon of guessing.

## UX flow (LabelDesk words)
1. **Settings · Datasources · Connection** — fields: name, provider, bucket, region, credential, and for
   S3-compatible hosts an **endpoint** plus a "Use path-style addressing" checkbox that starts ticked.
   [error: a bucket entered as `s3://my-bucket/path` is rejected inline: "Enter the bucket name only —
   no path"]
2. **Settings · Datasources · Connection** — **Test connection** lists the first object and shows
   "Connected · 1,204 objects visible · first: frames/0001.jpg". [empty: the bucket is reachable but holds
   nothing at the prefix → "Connected · no objects at this prefix"] [loading: button spinner, result area
   skeleton]
3. **Settings · Datasources · Connection** — a virtual-hosted host that only speaks path-style fails with
   "The host answered 403 for `my-bucket.host`. Try ticking **Use path-style addressing**." and the
   checkbox is highlighted. [error: blocked endpoint → "That endpoint is not reachable from LabelDesk"
   without echoing the resolved IP; bad key → "The key was rejected (403) — rotate the credential"]
4. **Settings · Datasources · Connection** — saving with an untested connection is allowed but the row
   shows "Untested"; the first sync writes the real verdict.

## Backend changes
- Models/schema: none — `Connector.config` JSON gains `path_style` (default `true`), `region`,
  `endpoint_url`, `bucket` (bare name). No column.
- Routers: `apps/backend/app/routers/connectors.py`
  - `POST /connectors/{cid}/test` → `200 {ok, objects, firstKey, elapsedMs}`; failure →
    `200 {ok: false, code, message, hint}` for *user-fixable* failures (403/404/addressing), `502` with
    the generic safe message for infrastructure failures.
  - `POST /connectors` / `PATCH /connectors/{cid}` (PATCH new) accept the new config keys; `PATCH` may
    change the credential and re-test.
- Services/jobs: `apps/backend/app/services/connectors.py`
  - `normalise_bucket(value)` — strips `s3://`, `gs://`, `https://<account>.blob.core.windows.net/`,
    rejects anything with a `/` after the bucket name.
  - `_s3_client` passes `config=botocore.config.Config(s3={"addressing_style": "path"|"virtual"},
    retries={"max_attempts": 1})`; `test(conn)` lists with `MaxKeys=1` plus a count via
    `list_objects_v2(MaxKeys=1000)` and maps `ClientError` codes (`403`, `NoSuchBucket`,
    `PermanentRedirect`, `InvalidAccessKeyId`) to `{code, message, hint}`.
  - `validate()` keeps the SSRF guard (`safefetch.check_url`) and the multi-tenant refusal of custom
    endpoints — this card does not widen egress.
- Permissions + workspace isolation: `c.need("admin")` on test and CRUD; the connector is fetched by
  `_connector(db, c.ws.id, cid)` so a foreign id is 404.
- Secrets/safefetch: `secretbox` for the credential; `safefetch.check_url` for the endpoint.
- OpenAPI: yes — one route + PATCH.

## Tests to write first
pytest — `apps/backend/tests/test_connector_setup.py`:
- `test_bucket_accepts_bare_and_scheme_forms` — `my-bucket`, `s3://my-bucket` → `my-bucket`;
  `s3://my-bucket/frames` → `ValueError` naming the path.
- `test_path_style_is_sent_to_the_client` — monkeypatched `boto3.client` asserts
  `config.s3["addressing_style"] == "path"` when the box is ticked and `"virtual"` when not.
- `test_test_connection_reports_addressing_hint` — a stubbed `PermanentRedirect` → `ok:false`,
  `hint` contains "path-style".
- `test_test_connection_reports_bad_key` — `InvalidAccessKeyId` → hint names the credential rotation.
- `test_private_endpoint_is_refused` — `http://10.0.0.5:9000` → 400 from `validate`, no client built.
- `test_multi_tenant_custom_endpoint_still_refused` — `MULTI_TENANT=1` → 400 with the existing message.
- `test_cross_workspace_connector_is_404` — workspace B's id under A → 404.
- `test_flag_off_404` — test/PATCH 404 when the connector family flag is off.
node — `apps/frontend/tests/<name>.test.mjs`:
- `test_connection_form_defaults_path_style_on` — pure default state: `pathStyle: true`, region `"auto"`.

## Acceptance criteria
- [ ] Test connection distinguishes wrong key, missing bucket, addressing mode and blocked endpoint with a
      fix in the message.
- [ ] Path-style is a stored per-connector setting, default on, and reaches the SDK client.
- [ ] A bucket value with a path is refused inline; a scheme prefix is tolerated.
- [ ] Multi-tenant custom endpoints stay refused; no egress widening.
- [ ] Empty/loading/error states above render (untested row, spinner, inline field error).
- [ ] Flag off ⇒ test/PATCH 404 and today's create/list/sync flow is unchanged.
- [ ] Workspace A cannot see or change workspace B's data (404 for a foreign connector id).

## Notes for the implementer
Map only codes you can act on; anything else is `502 "connector listing failed"` and stays in the log with
the connector id. Never echo a presigned URL, an access key or a resolved IP in the test response.
