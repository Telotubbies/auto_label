## User story
As the person maintaining the wire surface, I want a test that drives the real third-party client
against our app, so that "their client works" is a green suite instead of a claim in a card.

## UX flow (LabelDesk words)
1. **CI** — the API job installs the wire extras and runs one test that starts the app in-process, mint
   a workspace key, points the client at `/api/2.0/mlflow`, and logs a run. [empty: no run logged —
   the assertion fails with "the client reported success but no run exists"] [loading: n/a] [error: a
   breaking change in their client shows up as one failing test naming the method that broke].
2. **A developer without the extra** — the same test skips with `mlflow-skinny is not installed
   (pip install -r apps/backend/requirements-wire.txt)`; the rest of the suite stays green.
3. **Docs** — the Integrations card (T-983) links to this file as the worked example.
