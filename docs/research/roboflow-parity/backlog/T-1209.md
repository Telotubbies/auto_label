## User story
As a factory operations lead, I want to point a camera at the line, see the same frame the model sees,
and turn one event into training data, so that the stream earns its keep instead of being a demo.

## UX flow (LabelDesk words)
1. **Deploy → Streams** (`/:ws/p/:project/deploy?tab=streams`) — the list shows each camera with a state
   chip and the last error if any. [empty: "No cameras yet" plus the one create action].
2. **New stream** — name, source (uploaded video or RTSP), model (only tracking-capable families),
   sample fps. [error: an RTSP address without a scheme is refused in place].
3. **Start** — the state moves `connecting → live`; a frozen feed shows `reconnecting` with the attempt,
   never a silent still image.
4. **Live view** — the annotated frame is the same frame the event used; the fps readout is visible.
5. **Rule** — a count or zone rule; the form states what the rule ignores (for example frames below the
   sample rate).
6. **Event** — the timeline names the rule, the class count, the time and a snapshot.
7. **Send to dataset** — the snapshot lands in the project with the option to pre-label; the dataset
   count increases by one.
8. **Stop and restart** — stop is immediate; restart says what it will do to the running capture.

## Acceptance criteria
- [ ] A stream can be created from a video source and moved to `live`; the live view shows the fixture
      frame with the overlay.
- [ ] The event row names the rule, the count and the time; its snapshot matches the frame.
- [ ] "Send to dataset" adds exactly one image and the dataset count agrees.
- [ ] Steps ≤ 10 and time ≤ 240 s; numbers recorded.
- [ ] Empty, loading and error states: no cameras, connecting, a dead source, a refused RTSP address.
- [ ] Flag off ⇒ the surface says "not available in this workspace" with the reason and the way back.
- [ ] No console error; at 375 the list and the detail stack without clipped controls.
- [ ] Workspace isolation: a stream and its events in A are absent in B; B's detail URL 404s.
- [ ] The model picker offers only tracking-capable families and names why the others are absent.

## Notes for the implementer
Never wait for a real frame or a real clock tick. The fixture frame and the seeded event make the test
deterministic; the stream's state transitions are asserted from the status chip, not from the image
content.
