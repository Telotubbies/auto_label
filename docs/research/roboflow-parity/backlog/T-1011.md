## User story
As a workspace admin, I want a model download to resume after a drop, verify what arrived and stop
before it fills the disk, so that a 15 GB transfer is not a coin flip.

## UX flow (LabelDesk words)
The screen is T-1012; this card supplies the job.
1. **Queued** — waits for a worker that advertises `model_pull` and matches the host.
2. **Downloading** — phase `downloading <file> (3/7)`, progress by bytes, log line per file with size.
3. **Resumed** — after a worker restart the same job continues from the partial file; the log says
   `resuming at 6.2 GB`.
4. **Verifying** — phase `verifying`; each LFS file's sha256 is checked against the hub metadata.
5. **Checksum failed** — the partial file is deleted, the job fails with `checksum_failed`, and the UI
   offers `Retry`.
6. **Disk full** — before the first byte or mid-transfer, the job fails with `disk_full` naming the
   shortfall; nothing is left behind.
7. **Removed** — an admin removes an installed model; phase `removing`, disk after is reported.

## Backend changes
- Models/schema: none.
- Routers (`apps/backend/app/routers/inference.py`):
  - `POST /models/download` `{host, id, variant, confirm}` → `{job}`; 400 without confirm, 409 when a
    job runs on that host or the variant is already installed, 422 for an unknown id/variant.
  - `DELETE /models/{id}?host=&variant=&confirm=true` → `{job}` with `action: "remove"`; 404 when not
    installed.
- Services/jobs: `inference_jobs.enqueue_model(...)` and the `model_pull` branch of
  `inference_jobs.payload()` → `{host, action, repo, revision, files:[{path, bytes, sha256}], target,
  total_bytes}`. The API sends catalogue data only; no URL and no token.
- Worker:
  - `apps/worker/labeldesk_worker/hf.py` (new) — a thin wrapper over `huggingface_hub`:
    `metadata(repo, revision, token)`, `download(repo, revision, filename, local_dir, token,
    on_progress)`, `sha256(path)`. `token` comes from `os.environ["HF_TOKEN"]`, never an argument that
    is logged.
  - `apps/worker/labeldesk_worker/model_pull.py` (new) — `run_model_pull(srv, job, args)`:
    1. `Guard`: repo matches `owner/name`, revision is a commit hash, every `path` is relative and
       stays under the staging dir, and the target is `<LD_MODELS_DIR>/<id>/<variant>`.
    2. Disk: `shutil.disk_usage(models_dir).free × 0.8 ≥ total_bytes`, else `disk_full` before any
       write; re-check every 5% of progress and after each file.
    3. Download each file into `<target>.partial/` using the hub client's own resume (`.incomplete`),
       reporting bytes; `os.replace` the directory into place only when every file verified.
    4. Verify: LFS files against the metadata `lfs.oid` (sha256); non-LFS files are size-checked and
       recorded, not hashed against a git blob id. A mismatch deletes `.partial/` and fails.
    5. `remove`: path-guard, `shutil.rmtree(target)`, report freed bytes.
  - `apps/worker/pyproject.toml` gains an optional extra `inference = ["huggingface_hub>=…,<…"]`; the
    base worker install is unchanged, and a missing extra fails the job with `missing_extra` naming the
    pip command.
  - `apps/worker/labeldesk_worker/cli.py` — `handlers["model_pull"] = run_model_pull` and a
    `--models-dir` argument (shared with T-1001).
- Permissions + workspace isolation: admin only; the job is workspace-scoped; the target path is built
  from catalogue ids.
- Secrets/safefetch: `HF_TOKEN` stays in the worker env; it is never written to `result`, `error` or
  `log`; a redactor strips `hf_[A-Za-z0-9]{20,}` before every progress post.
- OpenAPI: yes.

## Acceptance criteria
- [ ] A job is claimed only by a `model_pull` worker on the named host.
- [ ] Resume continues from the partial file; a finished file is byte-identical to the fixture.
- [ ] A checksum mismatch deletes the partial data and fails with `checksum_failed`.
- [ ] Disk is checked before the first byte and during the transfer; failure leaves nothing behind.
- [ ] Paths are catalogue-derived and guarded; no request value becomes a path or a URL.
- [ ] The token never appears in a log, an error, a job row or an API response.
- [ ] Removing a model frees the directory and reports the bytes.

## Notes for the implementer
Do not reimplement HTTP Range; the hub client owns resume and its `.incomplete` file is the partial
state. Verify LFS files by `lfs.oid` (sha256) and be explicit in the log that non-LFS files are only
size-checked. `os.replace` the directory only after every file verifies, so a half-downloaded model is
never visible as installed.
