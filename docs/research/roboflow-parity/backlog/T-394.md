## User story
As an admin, I want a key that lacks a scope to see a missing route rather than a forbidden one, so that a leaked
key cannot map the API by trial.

## UX flow (LabelDesk words)
1. **API** — a call from an API key without the required scope answers `404 {"detail": "Not found"}`; the response
   body carries no scope name and no route hint. A signed-in user session keeps today's `403 requires <perm>`
   (their role is not a secret from them).
2. **Create / edit key** — `Key permissions` is a grouped checkbox grid (`Read`, `Upload`, `Train`, `Infer`),
   all but `Train` preselected, with `Deselect all`; `Publishable` forces and locks `Infer`.
3. **Change later** — `⋯ → Edit permissions` opens the same grid; the row's badge flips between `Full access`
   and `Scoped` after save.
4. `[error]` a scope list that is empty or unknown → `Choose at least one permission from the list.`
5. `[empty]` a key with every scope shows `Full access`; the grid is still readable.

## Backend changes
- Models/schema: none.
- Routers: `app/apikeys.py` `KeyCtx.need(scope)` raises `HTTPException(404, "Not found")` when the flag is on and
  keeps the 403 sentence when it is off; `routers/workspaces.py` gains
  `PATCH /api/ws/{ws}/keys/{kid}/scopes` `{scopes}` → 200 row, `400` for an empty/unknown list, `409` for a
  protected key or a publishable key (`Publishable keys always have infer only.`).
- Services/jobs: `apikeys.missing_scope_response(scope) -> HTTPException` in `apikeys.py` so the decision lives in
  one place; `services/keys.py` gains `set_scopes(db, key, scopes)`.
- Permissions + workspace isolation: `workspace.keys` for the route; the 404 rule applies to key authentication
  only, never to a member's session.
- Secrets/safefetch: none.
- OpenAPI: yes (the new route; the 404 semantics are described in the devapi tag description).

## Frontend changes
- Route: `/:ws/settings/api` (existing).

## Acceptance criteria
- [ ] A key without a scope sees a bare 404; a member without a permission still sees a 403 naming the permission.
- [ ] Scopes can be edited after creation and the row's `Scoped`/`Full access` badge follows.
- [ ] A publishable key cannot be re-permissioned, and an empty or unknown scope list is refused with a reason.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the 403 sentence and today's fixed scope list at creation only.

## Notes for the implementer
Return FastAPI's own `{"detail": "Not found"}` shape so a missing scope is indistinguishable from a typo'd path.
Do not log the missing scope at INFO — that would re-leak it through logs.
