## User story
As a first-time trainer, I want three promises — Fast, Balanced, Accurate — and a single ordered path, so that fifteen variants are a choice I can defer instead of a decision I must make.

## UX flow (LabelDesk words)
1. **Train** — one column, max 720 px: **1 Dataset** (select with a health chip), **2 Recipe** (Fast / Balanced / Accurate, one line each with epochs, image size, ETA and credits), **3 Output** (name, base weights, credit cap). [empty: no ready version ⇒ "A model needs a frozen dataset — make a version first." with one primary *Go to Versions* and no form] [loading: three card skeletons at final geometry, no spinner] [error: options failed ⇒ "The model catalogue could not be read" + Retry, form disabled]
2. **Preset control** — one segmented control, three segments; the selected segment prints its line: Fast "20 epochs · 640 px · ~18 min · 3 credits"; Balanced "50 epochs · 704 px · ~44 min · 2.5 credits"? No — see Notes for the exact table the card ships. Changing the preset rewrites epochs/imgsz and the summary follows.
3. **Advanced (details panel)** — expands into the family grid (T-250's sizes) plus the recipe fields (T-256). A chip on the collapsed header states the current family ("YOLO26 Nano") and the licence as one *Licences* link that opens a modal listing each family's licence — never a per-card badge wall.
4. **Start guard** — with a missing dataset the primary is disabled and names the reason; the submit path is T-254's.
5. **Advanced holds the risk** — *random init* and the other exotic options are only reachable inside Advanced, each with its warning line.
