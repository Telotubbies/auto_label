## User story
As a workspace admin, I want one panel that says which engines and models are on this host and how much
disk is left, with a confirmed way to remove a model, so that a full disk has a remedy inside the
product.

## UX flow (LabelDesk words)
1. **Models tab → `Installed on this host`** — a collapsible panel above the catalogue: a disk bar
   (`812 GB free of 1.8 TB`), then one row per installed model with variant, size, installed date (from
   the file mtime reported in inventory) and `Remove`. Engines are shown as a compact line
   (`vLLM <pin> · llama.cpp <pin>`).
2. **Remove** — confirm sheet: "Remove Qwen2.5-VL-7B (AWQ) from <host>? This frees 4.4 GB." →
   job `Removing` → the row disappears and the disk bar updates.
   [error: 404 when it vanished already → "That model is no longer on this host." + refresh].
3. **No inventory** — "This host has not reported what it has installed." [empty: nothing installed →
   "Nothing installed yet. Download a model from the catalogue."].
4. **Low disk** — under 10% free, the bar uses the warning tone and one line: "Under 10% free. Remove a
   model or raise `LD_MODELS_MAX_GB`." Not a modal, not a banner that blocks work.
5. **Busy host** — `Remove` is disabled while an engine/model job runs, with the job link.

## Acceptance criteria
- [ ] The panel shows disk free/total and a bar, installed models with size, and the engine line.
- [ ] Remove requires a confirm naming model, variant, host and bytes; the job runs and the panel
      refreshes.
- [ ] Under 10% free the bar is warning-toned with the one-line remedy.
- [ ] No inventory and nothing-installed are different empty states.
- [ ] Remove is disabled while a job runs on the host.
- [ ] 375 px: the panel stacks, the table scrolls, the confirm is full-height.
- [ ] No new token, hex or font size.

## Notes for the implementer
Do not add a "remove all" action: one confirmed removal is the whole safety story. The installed date
comes from the inventory's file mtime; if the host omits it, render "unknown" rather than inventing one.
