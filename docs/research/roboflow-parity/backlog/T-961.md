## User story
As a quality lead, I want to write my own pass/fail criteria in words and test them on real answers, so that a
domain rule — "must not guess a count above ten" — is checked on every run.

## UX flow (LabelDesk words)
1. **Project settings → Evaluation → Judges** — a table of custom judges: name, the tokens it uses, version,
   last agreement figure, and who wrote it. [empty: "No custom judges" with *New judge* and one worked example
   in the description]
2. **New judge** — name, a criteria box with the reserved tokens offered as chips (`{{ question }}`,
   `{{ answer }}`, `{{ reference }}`, `{{ image }}`), and *Verdict shape* (pass/fail, or a score 0–3).
   [error: "the criteria must reference at least one of question, answer, reference" — a criteria box without
   a token cannot be saved]
3. **Test on real rows** — *Try on 5 answers* runs the judge over the newest answered traces and shows each
   verdict beside the answer, with the general *Test on 5* primary disabled until at least one row returns.
4. **Save** — saving a judge freezes version 1; editing later creates version 2 and the table shows both, with
   the assessments that used each. [empty: no answered traces yet ⇒ "run a VLM in the Playground first" with
   the link]
5. **Use** — the custom judge joins the axes in T-960's drawer under a *Custom* heading.

## Backend changes
- Models/schema: `CustomJudge(id, workspace_id, project_id, name, criteria TEXT, shape, created, created_by)`
  and `CustomJudgeVersion(id, judge_id FK ondelete=CASCADE, version, criteria, shape, created, created_by)`
  in `apps/backend/app/models/evaluation.py`. Assessments extend T-960's `axis` to `judge:<id>:v<version>`,
  so the existing unique key keeps one verdict per trace per judge version.
- Routers: `GET/POST {P}/custom-judges`, `POST {P}/custom-judges/{id}/versions` (edit),
  `POST {P}/custom-judges/{id}/try` body `{limit: int = 5}` → `{rows: [{trace_id, question, answer, verdict,
  reason}]}`, `DELETE {P}/custom-judges/{id}`. 400 for criteria without a reserved token, a name that already
  exists, an unknown token, or a shape other than `pass_fail|score_0_3`; 404 for a foreign id.
- Services/jobs: `apps/backend/app/services/judges.py` gains `render(criteria, trace)` which substitutes only
  the four reserved tokens from the trace (no arbitrary find-and-replace), and `judge_custom(...)` reusing
  T-960's call and parser. `try` loops the newest N answered traces and discards the assessments (nothing is
  stored on a trial run).
- Permissions + workspace isolation: read `project.review`, write `c.need("admin")`; foreign ids 404.
- Secrets/safefetch: none. Dependency: none added (no `mlflow-skinny`), so no
  `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] A custom judge can be written, trialled on five real answers without storing anything, then saved.
- [ ] Editing creates an immutable new version, and assessments record which version judged them.
- [ ] Criteria with no reserved token, or with an unknown token, are refused.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: none. The docs' judge takes `{{ trace }}` and explores it with tools; LabelDesk's equivalent is the
four fields we already store, and offering a tool loop would be a different product.
Substitution is a fixed map, never `str.format`: criteria is customer text and `{0}` must not raise.
