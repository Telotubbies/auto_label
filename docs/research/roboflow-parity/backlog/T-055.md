## User story
As a reader of the app, I want one rounding rule per kind of number, so that 0.5 confidence reads the same
in the evaluation table as in a progress bar, and a duration never shows milliseconds as seconds.

## UX flow (LabelDesk words)
None: no new surface. The same numbers appear on the same screens; the card fixes three disagreements the
grep found:
1. **Evaluation / models tables** — a rate shows one decimal (`50.0%`).
2. **Progress bars and distribution legends** — a part/whole shows a rounded integer (`50%`), and an
   unknown value shows `—`.
3. **Stream detail vs. editor panels** — a duration has two units today: `StreamDetail.tsx:20` treats the
   argument as seconds, `Panels.tsx:38` as milliseconds. Both keep their current output, under two names.

## Notes for the implementer
Two percentage shapes are deliberate and must not be "unified": a *rate* (0…1) gets one decimal because
mAP at `50.0%` and `50.4%` are different; a *share of a whole* gets an integer because a bar legend with
one decimal is noise. `Models.tsx` exports `pct` today; after this card the export goes away — check
`Deploy.tsx` only imports `headline` (verified), so nothing else breaks.
