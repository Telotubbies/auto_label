## User story
As a control-room operator or a shift leader on a phone, I want one queue where the four copies of an alarm are one row I can take, acknowledge with a note and snooze, so that a twelve-hour shift is a list of decisions instead of a stream of notifications.

## UX flow (LabelDesk words)
1. **`แจ้งเตือน` in the project panel** (`/:ws/:project/alarms`) — a queue of `Card` rows: rule label, station, `4 กล้อง`, first and last time, and a state chip. Unacknowledged rows first. [empty: `ไม่มีรายการค้างรับทราบ` with `24 ชม. ที่ผ่านมา 0 รายการ`] [loading: `กำลังโหลดคิว`] [error: `โหลดคิวไม่สำเร็จ — ลองอีกครั้ง`]
2. **Open a group** — a `Modal` (`Glass strength="overlay"`) with the trigger frame, the member events (camera name, time, snapshot thumb) and the actions `รับทราบ`, `มอบให้ฉัน`, `เลื่อน 1 ชม.`.
3. **`รับทราบ`** — an optional note field, then the row updates in place; the note and the operator read under the row. [error: `มีคนอื่นรับทราบรายการนี้แล้ว` — the modal re-reads the group and both buttons disable]
4. **`เลื่อน 1 ชม.`** — asks for `เหตุผลที่เลื่อน` in a one-field sheet, then the row shows `เลื่อนไว้ถึง 14:20` and leaves the queue. [error: `ต้องระบุเหตุผลก่อนเลื่อนการแจ้งเตือน`]
5. **On a phone** — the queue is one column, each row ≥ 56 px tall, and the actions are reachable with a thumb; the member list scrolls, the buttons never do.

## Backend changes
- Models/schema: none — T-678 shipped the columns.
- Routers: none — the screen reads `GET …/alarms/queue` and writes `ack`/`assign`/`snooze`.
- Services/jobs: none.
- Permissions + workspace isolation: the route is `<PermGate perm="project.streams">`; the action buttons are disabled without `project.review` and the API refuses the same calls with 403; a group whose event ids belong to another workspace never appears on this page because the query is filtered server-side.
- Secrets/safefetch: none.
- OpenAPI: no — no route changes.

## Acceptance criteria
- [ ] `/ :ws/:project/alarms` lists groups unacknowledged first with rule, station, camera count and times, on a phone in one column.
- [ ] A group opens with its frame and members, and `รับทราบ` / `มอบให้ฉัน` / `เลื่อน 1 ชม.` each update the row in place.
- [ ] A 409 from a second operator shows `มีคนอื่นรับทราบรายการนี้แล้ว`, reloads the group and disables both buttons.
- [ ] Empty, loading and error states above all render, with the last-24-hour count in the empty state.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no `Alerts` nav entry, the route redirects and the project panel is today's.

## Notes for the implementer
The empty state must carry the 24-hour count, because "nothing to acknowledge" and "no camera has fired since yesterday" are different facts and an operator acts differently on each. Keep the ack note optional and short (280 chars, matching the API) and never let a snooze look like a delete: the row must be able to say `เลื่อนไว้ถึง 14:20`. Copy: `alarms.nav`=`แจ้งเตือน`, `alarms.title`=`คิวแจ้งเตือน`, `alarms.empty`=`ไม่มีรายการค้างรับทราบ`, `alarms.emptyHint`=`24 ชม. ที่ผ่านมา {n} รายการ`, `alarms.loading`=`กำลังโหลดคิว`, `alarms.error`=`โหลดคิวไม่สำเร็จ — ลองอีกครั้ง`, `alarms.ack`=`รับทราบ`, `alarms.assignMe`=`มอบให้ฉัน`, `alarms.snooze`=`เลื่อน 1 ชม.`, `alarms.snoozeReason`=`เหตุผลที่เลื่อน`, `alarms.snoozeNoReason`=`ต้องระบุเหตุผลก่อนเลื่อนการแจ้งเตือน`, `alarms.alreadyAcked`=`มีคนอื่นรับทราบรายการนี้แล้ว`, `alarms.snoozedUntil`=`เลื่อนไว้ถึง {time}`, `alarms.cameras`=`{n} กล้อง`, `alarms.members`=`รายการในกลุ่ม`.
