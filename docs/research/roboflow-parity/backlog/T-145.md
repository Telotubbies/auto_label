## User story
As a reviewer, I want the History tab to show everyone's saved changes and to roll one back, so that the panel stops being a list I lose on reload.

## UX flow (LabelDesk words)
1. **Editor → right inspector sheet → History** (the rail becomes Classes/Objects only in wave E; until then the left rail's History tab) — server revisions, newest first: author initial, name, kind chip, `4 labels`, relative time. [loading: three skeleton rows] [empty: "No saved changes yet — the first save appears here"] [error: the message plus a retry button]
2. **Three-dot row menu** — reveals **Restore this version** (the chevron is the only way to see it, as before) and, for the newest row, a disabled "Current" label.
3. **Confirm** — names the revision's author and time and the current label count; Cancel is the default focus. On confirm the image reloads from the revert response, the canvas repaints, local undo history resets, and a toast reads "Restored the 14:32 version".
4. **Stale image** — if the image changed since it was loaded, the confirm is blocked and the T-121 conflict bar takes over: restore only after Reload.
5. **Live update** — a save from this tab adds one row at the top without a full refetch; a save from another tab appears on the next open of the panel (no polling).
6. **Flag off** — the panel shows the existing session log exactly as today and the row menu is absent.

## Acceptance criteria
- [ ] The History panel lists server revisions newest first with author, kind and label count, and survives a reload.
- [ ] Restore asks for confirmation naming the author, time and current count, then repaints the canvas from the response.
- [ ] A restore is impossible while the image is conflicted or a save is in flight.
- [ ] With the flag off the old session log is unchanged and no history request is made.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the panel is the session log, exactly as today.
- [ ] Keyboard-only path: Tab to the panel → Tab to a row's menu → Enter → Enter on Restore → confirm.

## Notes for the implementer
After a revert, clear `history`/`future` (the local undo stack) — offering an undo that jumps back to a state two revisions old would be a lie. The revision list is per image; switching images refetches.
