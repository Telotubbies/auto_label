## User story
As a workspace admin, I want each engine row to say compatible, warning or blocked with the reason,
before I can select it, so that I never plan an install the host cannot run.

## UX flow (LabelDesk words)
1. **Engines tab loads for a host** — each row carries a badge: `Compatible` (success),
   `Warning` (warning tone, still selectable), `Blocked` (muted, not selectable) with one inline sentence.
2. **Blocked examples** — "Needs an NVIDIA GPU; this host reports CPU only." / "Needs CUDA 12.4 or
   newer; the host reports 12.1." / "Needs 6.4 GB free; the host has 2.1 GB." / "This host has not
   reported hardware yet." / "Docker is not available on this host."
3. **Warning examples** — "Untested driver 551.xx; the pin is verified on 550.xx." / "Linux only; the
   host reports Windows and WSL was not detected."
4. **Host changes** — badges recompute; a selected row that becomes blocked is deselected with a
   one-line notice. [loading: the table shows skeleton badges, not a full-page spinner].
5. **No host** — every row is blocked with "Pick a host first." [empty: no inventory].

## Backend changes
- Models/schema: none.
- Routers: `GET /api/ws/{ws}/inference/engines?host=<id>` → `{host, engines:[{...catalogue,
  installed, compatibility:{status, reasons: []}, disk_after_gb}]}`. `host` is required; an unknown or
  foreign host id is 404, never a default.
- Services/jobs: `apps/backend/app/services/inference_compat.py` (new) —
  `evaluate(host_inventory: dict | None, engine: dict, runtime: str | None, *, free_gb: float | None)
  -> {"status": "ok"|"warn"|"blocked", "reasons": list[str], "warnings": list[str]}`.
  Rules, in order: no inventory → blocked; no GPU and `engine.accelerator` excludes `cpu` → blocked;
  OS not in `engine.os` → blocked (Windows + WSL is a warn, not a block); driver below `min_driver` →
  blocked; CUDA outside `[cuda_min, cuda_max]` → blocked; free disk below `disk_mb × 1.2` → blocked;
  runtime `docker` when inventory says docker is absent → blocked; unknown/untested driver major →
  warn; engine already installed at the same version → `ok` with `installed: true`.
  Reasons are fixed sentences with the host's own numbers interpolated, never a raw exception.
- Permissions + workspace isolation: admin only; `host` must appear in `hosts(db)` for this deployment
  scope, else 404.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] Every engine answers `ok`, `warn` or `blocked`, with at least one reason for anything not `ok`.
- [ ] Reasons quote the host's own driver, CUDA and free-disk figures.
- [ ] A blocked engine cannot be selected by the UI (T-1007 relies on `status`).
- [ ] A stale host (offline) blocks installs but still renders its last inventory, marked stale.
- [ ] Admin-only; unknown/foreign host 404; flag off 404.

## Notes for the implementer
Keep the rules in this order and return on the first blocking rule, but collect every warning. Compare
versions numerically (`12.10 > 12.4`), not lexically. Never read `inventory` keys with `[]`; a host that
reports a partial payload must produce "reason unknown", not a 500.
