## User story
As an admin, I want to scan one table and see which credential is protected, disabled, default or overdue, so
that a leak has an obvious row to act on.

## UX flow (LabelDesk words)
1. **Settings → API keys** (`/:ws/settings/api`) — table: `Name`, `State` (badges), `Key`, `Permissions`,
   `Created`, `Last used`, `⋯`. [loading: six skeleton rows] [error: `Could not load API keys.` + `Try again`]
2. **Badges** — `Default`, `In use`, `Protected`, `Disabled` (hover: `Disabled 3 days ago`), `Full access` /
   `Scoped`, `Rotate by 12 Aug 2027`, and the rotation ladder `Due in 22 days` / `Due today` / `Overdue`
   (warning and danger tones), `New` for 24 h after creation.
3. **Key column** — `lkd_ab12…` with `Copy` and `Reveal`; `Reveal` is available only for a key this session
   created (the full value is never re-served), otherwise it is absent and the tooltip says
   `The value is shown once when the key is created.` Name advice sits in the create dialog:
   `Name it after the consumer — “ci-pipeline”, “line-3-gateway”.`
4. **Filter** — a `Only keys due for rotation` switch filters client-side and states
   `3 of 9 keys are due within 30 days.` [empty when filtered: `No keys are due for rotation.` + `Clear filter`]
5. **`[empty]`** no keys: `No API keys yet.` explanatory block plus `Generate new key` as the only filled control.
6. **A device key** (metadata marks it) replaces `⋯` with `View device`; the target is the device page, not a menu.
