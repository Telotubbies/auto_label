## User story
As a procurement officer finishing a review at 6pm, I want one page with the DPA, the security practices, the sub-processor list and an honest word on what is not certified, so that I do not have to book a call to obtain a PDF.

## UX flow (LabelDesk words)
1. **Public `/trust`** (no login) — sections `Certifications`, `Data protection`, `Security practices`, `Sub-processors`, `Accessibility`, `Reports`. Every row carries a status chip and a sentence: "Not certified — no certificate is held today", "In progress — no date is promised", "Audited <date>" only where an evidence link is present. [empty: a claim with no evidence reads "Not yet available." and keeps its row instead of hiding] [loading: each section renders two skeleton rows] [error: "Couldn't load the trust page." + `Try again`]
2. **`Download the DPA`** — signed in, returns this workspace's filled agreement; signed out, returns the template with the workspace fields blank and a line saying so.
3. **`Request a pen-test summary`** — a dialog: company, work email, NDA acceptance checkbox, optional note. `Send request` stays disabled until all three are present. On success: "Request received — reference TR-<id>. We reply to the address you gave." [error: "That address is not accepted — use a work email."]
4. **Footer → Trust** inside the app — the same page at `/:ws/legal/trust`, with the DPA link pointing at this workspace's agreement.
5. **The operator** (`/:ws/admin`, superadmin only) — a `Trust requests` section lists the requests with company, address, NDA flag and time, newest first. [empty: "No trust requests yet."]

## Backend changes
- Models/schema: `TrustRequest(id, company, email, nda_accepted, note, created, handled_at, handled_by)` appended to `app/models/trust.py`; no other column.
- Routers: `app/routers/trust.py` — `GET /api/public/trust` (no auth: sections, claims, status words, links; never workspace data), `POST /api/public/trust/requests` (201 with `reference`; 422 on a missing company, NDA or a malformed address), `GET /api/trust/requests` and `PATCH /api/trust/requests/{id}` behind `require_superadmin`.
- Services/jobs: `app/services/trust_content.py` (new) — `SECTIONS` as module constants: `{"id", "title", "rows": [{"label", "claim", "status", "evidence"}]}`, with `status` one of `not_certified | in_progress | audited | not_available` and no free text that asserts a certificate; `public_view()` returns it unchanged plus the DPA template link.
- Permissions + workspace isolation: the public read carries no tenant data by construction; the operator routes use `require_superadmin` (the same dependency `routers/admin.py` uses); the in-app page reads the workspace DPA through the existing `ws_ctx` route.
- Secrets/safefetch: none — the request stores three text fields and a boolean.
- OpenAPI: yes.

## Tests to write first
pytest — `apps/backend/tests/test_trust_centre.py`:
- `test_the_public_page_needs_no_session_and_names_no_tenant` — `GET /api/public/trust` without a token → 200, every section present, and the body contains no workspace slug or email.
- `test_no_claim_ships_a_certification_word` — every row whose `status` is `not_certified` has a claim sentence containing "not certified", and no row asserts a standard name it has no `evidence` for.
- `test_a_request_needs_company_email_and_nda` — `POST /requests` missing each field → 422 naming the field; a complete body → 201 with a `TR-` reference.
- `test_a_free_mail_address_is_refused` — `POST /requests` with `a@gmail.com` → 422 with the work-address sentence.
- `test_only_an_operator_reads_requests` — workspace admin `GET /api/trust/requests` → 403; a superadmin (`LD_SUPERADMINS` naming the user) → 200 with the row.
- `test_the_dpa_link_is_the_workspace_document_when_signed_in` — signed in, `GET /trust` payload carries `dpa: "workspace"`; signed out it carries `dpa: "template"`.
- `test_flag_off_hides_the_page_and_the_routes` — with the flag off → `GET /api/public/trust` 404 and `POST /requests` 404.

node — `apps/frontend/tests/trust-claims.test.mjs`:
- `test_a_claim_without_evidence_keeps_its_row` — `claimLine({status:'not_available', evidence:null})` returns the "Not yet available." sentence, never `null`.
- `test_the_word_is_always_beside_the_colour` — `claimChip('not_certified')` returns a tone and the label "Not certified"; no status maps to a tone alone.
- `test_a_reference_is_prefixed` — `referenceLabel('8f2')` is `TR-8f2`.

## Acceptance criteria
- [ ] A signed-out visitor reads all six sections and sees "Not certified" wherever a certificate would go.
- [ ] The DPA button returns the workspace's agreement when signed in and a visibly blank template when signed out.
- [ ] A pen-test request stores company, work email and NDA flag and appears once in the operator list.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ both routes and both public endpoints are absent and the footer is unchanged.

## Notes for the implementer
Owner-gated: the status word on every claim, and whether any certification, audit date or pen-test summary may be named at all (INDEX §4.3). Until the owner supplies evidence, every row ships `not_certified` or `not_available`; there is no placeholder logo, no badge graphic and no year that implies an audit. Claims live in `trust_content.py` as data so changing one is a reviewed diff, not an edit to a page.
