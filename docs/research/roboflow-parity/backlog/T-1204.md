## User story
As a labeler, I want to draw a box and a polygon, accept one model proposal, and know my work is saved
before I move on, so that a shift is drawing and reviewing, not repairing lost work.

## UX flow (LabelDesk words)
1. **Annotate board** (`/:ws/p/:project/annotate`) — "Start labelling" opens the first image of the batch.
2. **Editor** (`/:ws/p/:project/annotate/:imageId`) — the class list, the tool column and the canvas are
   visible without scrolling at 1440; the image fits.
3. **Box** — pick the class, pick the box tool, two clicks; the object appears in the list with its class
   and count. [error: a zero-area box is refused, not saved].
4. **Polygon** — pick the polygon tool, click vertices, close with the first vertex or Enter; each vertex
   drags. [empty: no shape selected, no handles shown].
5. **SAM assist** — open the assist picker, choose the fake model, draw or accept a proposal; the proposal
   is visibly a proposal until accepted (the shipped proposal-versus-committed rule).
6. **Save** — the status moves to saved without a modal; a forced save failure says what survived and
   retries.
7. **Next image** — the shortcut advances and the previous image keeps both shapes after reload.

## Acceptance criteria
- [ ] Both shapes exist after reload with the right class and geometry (the box's four numbers, the
      polygon's vertex count).
- [ ] Steps ≤ 11 and time ≤ 240 s; numbers recorded.
- [ ] A proposal is distinguishable from a committed label before acceptance; accepting commits it.
- [ ] A failed save never loses the drawn shapes and offers one retry.
- [ ] No console error; keyboard-only leg: class, box tool, two Enter-anchored points, save, next.
- [ ] Empty, loading and error states: the empty image, the assist spinner, the refused zero-area box.
- [ ] Workspace isolation: the saved annotation is absent from another workspace's image.
- [ ] Flag off ⇒ the review shortcut leg is skipped; the drawing and save legs still pass.

## Notes for the implementer
Canvas coordinates come from `getByTestId('canvas-area')` and its bounding box, as `core-loop.spec.ts`
already does. Never assert the fake model's confidence number; assert the proposal exists, then accept it.
The SAM path is the model dropdown plus a proposal, not a real SAM call.
