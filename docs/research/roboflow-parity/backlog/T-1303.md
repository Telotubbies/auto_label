# T-1303 — Security scanners in the gate: SAST, CVEs, secrets, licences

| Field | Value |
| --- | --- |
| Wave | O (security, monitoring, performance) |
| Area | Security |
| Size | 3 agent-hours |
| Role | R3 backend + R11 docs |
| Skills | ponytail, test-driven-development, verification-before-completion |
| R7 security review | yes — this card decides what blocks a merge |
| Depends on | none |
| Feature flag | none |

## Problem
CI lints `apps/backend` with `ruff.toml` `select = ["F"]` (pyflakes only): no security rules, no
dependency CVE scan, no secret scan, no licence inventory. The code audit measured 825 broader ruff
findings including `S110` (try/except/pass) and `BLE001`, but none of those classes can fail a merge
today.

## Design
One new `security` job in `.github/workflows/ci.yml`, added to the `gate` aggregator, target ≤ 3 min.
Block/warn split exactly as the security plan §4.1 states.

1. **SAST** — `ruff.toml`: `select = ["F", "S"]`; `per-file-ignores` for tests
   (`S101` assert, `S105`/`S106` hard-coded password in fixtures, `S311` random in fixtures) and
   inline `# noqa: S<code>  # reason` elsewhere, at most ~30 files. The RED step is the new select
   with no ignores: capture the finding count in the report, then triage.
2. **Python CVEs** — `pip-audit -r apps/backend/requirements.txt --strict --disable-pip-version-check`
   in the `api` job after install; failures for high/critical block, and an entry may be waived only
   through `security/audit-ignore.txt` (one line per id with a reason and an expiry date).
3. **Node CVEs** — `npm audit --omit=dev --audit-level=high` blocks in the `web` job;
   `npm audit --audit-level=high` (dev included) runs in the same step with `|| true` and prints.
4. **Secrets** — `gitleaks dir . --redact --no-banner -c .gitleaks.toml` in the `security` job
   (binary installed by a pinned release URL, no Docker). `.gitleaks.toml` allows only the known test
   fixtures (demo password, fake `ld_` keys) by path, each with a comment.
5. **Licences** — `tools/check_licenses.py` (new, ~90 lines): reads installed metadata via
   `importlib.metadata` for the backend requirements and `apps/frontend/package-lock.json` for the web
   side, prints a grouped table (licence → packages), exits 1 for *unknown/no licence* and for anything
   outside `security/licences-allow.txt`, and exits 0 with a warning row for AGPL-3.0 (annotated
   "Ultralytics — deliberate, badge kept").

## Tests to write first
`tools/tests/test_gate_security.py`:
- `test_the_security_job_is_in_the_gate` — parse `ci.yml`; `gate.needs` contains `security` and the job
  runs gitleaks, pip-audit and the licence script.
- `test_a_hardcoded_password_fails_ruff_s` — run ruff with the repo config over a temp file containing
  `password = "hunter2"`; non-zero and `S105` in the output.
- `test_ruff_still_passes_on_the_repo` — the real tree is clean at the pinned version.
- `test_gitleaks_config_is_valid_and_scoped` — the toml parses and every allowlist entry has a path.
- `test_audit_ignore_entries_have_a_reason_and_a_date` — every line matches the documented format.

`tools/tests/test_check_licenses.py`:
- `test_allowlisted_licence_passes`, `test_unknown_licence_blocks`, `test_agpl_warns_and_names_ultralytics`,
  `test_missing_licence_metadata_blocks`, `test_npm_lock_side_is_read` (fixture lockfile).
- `test_output_is_grouped_by_licence` (pure formatter, no install).

## Acceptance criteria
- [ ] `gate` fails when the `security` job fails; the job's wall time is under 3 minutes.
- [ ] A deliberately committed fake key and a hardcoded password each turn the gate red in the RED step
      of this card (evidence in the report), then are removed.
- [ ] `pip-audit` blocks on high/critical; a waiver needs an id, a reason and a date.
- [ ] `npm audit` blocks on high in production dependencies and only prints for dev.
- [ ] The licence report lists every backend and frontend package, names AGPL-3.0 explicitly as
      deliberate, and blocks an unknown licence.
- [ ] No suppression exists without a one-line reason in the file it suppresses.

## Notes for the implementer
Ponytail applies hard here: no Semgrep, no `bandit`, no `safety`, no `detect-secrets` — one scanner, one
CVE tool per ecosystem, one binary, one script. Do not add a rule family beyond `S`; the code audit's
other 800 findings are style, not security, and belong to no card. Pin the gitleaks version by release
URL, not `latest`.
