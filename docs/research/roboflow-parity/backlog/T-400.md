## User story
As a compliance lead, I want one table where I can name the actor, the action and the thing, and open a row to
see what changed, so that an auditor's question is answered without an export.

## UX flow (LabelDesk words)
1. **Settings → Audit log** (`/:ws/settings/audit`; the old `/:ws/audit` route redirects here) — header
   `Audit log` with `Export CSV` and a `Retained for 365 days` badge.
2. **Filter bar (four slots)** — `Actor` (a member picker plus `API key` and `System`), `Action` (a searchable
   list from the catalogue), `Resource` and `Folder` share **one** slot: choosing a folder clears the resource and
   `All resources` clears the folder back. `From`/`To` stay. `Apply filters` / `Reset`.
3. **Rows** — `When` (UTC clock under the date), `Actor` with a type chip (`Person` / `API key` / `System`),
   `Action` chip, `Resource`, and a chevron. Clicking expands the row in place: `Before` / `After` columns per
   field, or `No field detail recorded for this event.` `[loading]` skeleton rows matching the column widths.
4. **Endless scroll** — the next page loads when the sentinel enters view, with `Loading more…`; the footer states
   `Showing 100 of 412 · filters applied`.
5. **`[empty]`** no filters: `No audit entries yet. Uploads, exports, role changes and stream views appear here.`
   with filters: `No entries match these filters.` + `Clear filters`.
6. **`[error]`** `Could not load the audit log.` + `Try again`; a failed *next* page keeps the rows and shows a
   footer retry instead of clearing the table.

## Acceptance criteria
- [ ] The four slots are visible, combinable, and resource/folder never apply together.
- [ ] A row expands in place to before/after values, or says no detail was recorded.
- [ ] Scrolling loads the next page and appending never clears rows already on screen.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the old page at `/:ws/audit`, and the settings tab absent.

## Notes for the implementer
The single resource/folder slot is the whole trick: model it as one `{kind, value}` object, not two strings with a
sync effect. Keep `Export CSV` pointed at the current filter set so the export and the table never disagree.
