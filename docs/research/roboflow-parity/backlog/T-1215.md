## User story
As the design and quality leads, I want one audit of how images arrive, are found, filtered, fixed and
counted, so that the grid — the place labelers spend the most time — is judged on evidence, not taste.

## UX flow (LabelDesk words)
1. **Upload** (`/:ws/p/:project/upload`) — pre-flight counts, refusals, the result sheet, the next step.
2. **Dataset images** (`/:ws/p/:project/dataset`) — the filter bar and popover, saved views, the selection
   bar, the grid at 2/3/5 columns. [empty vs no-match].
3. **Health** (`/dataset?tab=health`) — the ring, the warnings, each chart as a filter, staleness named.
4. **Batches** — the batch rows, the bulk menu and the count-bearing confirms.
5. **Video timeline** (`/videos`, `task_22`) — the trim and frame selection; audited only with the flag on.

## Acceptance criteria
- [ ] The grid renders readable tiles at 375 (the A8 contract), with the caption and class legible.
- [ ] The header count distinguishes filtered from total (the A9 contract) on every filter state.
- [ ] axe: 0 critical/serious; every moderate/minor listed with element and rule.
- [ ] The 10 heuristics are scored per screen; no score < 3; the worst three are named with evidence.
- [ ] `uxui-law` checks: Fitts on tile actions, Hick on the filter bar, Miller on class chips, One primary
      per screen.
- [ ] Every state in J3's flow has a distinct screen: empty, no-match, loading skeleton, error, refusal.
- [ ] Findings are S1–S4 in the program's format with a proposed fix card title for each S1/S2.
- [ ] P1 and P2 walk the area; their SUS-8 scores and any dead end are recorded.
- [ ] No deep link to a flag-off surface lands on the grid without a sentence (the A10 contract).

## Notes for the implementer
Use the seeded 40-image project; do not create data just to fill a state. Capture the no-match state with a
filter the UI offers, not by editing URLs.
