## User story
As an ML engineer, I want one dialog that lists the formats my project type supports, downloads a ZIP and shows progress, so that export stops being a select box with a stray Python block under it.

## UX flow (LabelDesk words)
1. **Version detail → Export…** — a modal titled "Export v3". Format chips (one per supported format, ordered as the API returns), a note under the grid: "Formats are filtered to this project type." [empty: "No format fits this project type — tell us what you need from the export screen."] [loading: chip skeleton row] [error: "Could not load formats — retry"]
2. **Pick a format → Download ZIP** — a button that becomes "Exporting… 40%" with a progress bar, then "Download ZIP (12.4 MB)" when ready. [error: "This version is still generating — export works once it is ready." as an inline warning, not a toast]
3. **Unavailable format** — a format the project type does not support is not in the list at all; if a stale selection somehow arrives, the dialog shows "That format does not fit this project type."
4. **Already built** — the chip carries a small "built" tick and the button reads "Download ZIP" immediately; a second export of the same format reuses the artefact (the API returns the existing job).
5. **Footer** — *Use from code* and *Send to storage* are secondary links inside the dialog (each owned by T-225 and T-231); *Done* closes.

## Backend changes
- Models/schema: none.
- Routers: none — `POST /versions/{vid}/export` already returns the existing job for a repeated request and 409 for a not-ready version.
- Services/jobs: none.
- Permissions + workspace isolation: the dialog is only reachable behind `project.export`; the signed URL comes from the payload and is absent for roles without it; a foreign version id 404s.
- Secrets/safefetch: none.
- OpenAPI: no.

## Acceptance criteria
- [ ] The dialog lists exactly the formats the project type supports, exports with visible progress, and downloads when done.
- [ ] A generating version, a failed export and a role without export rights each render their own state instead of a toast.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the old inline download card renders unchanged.

## Notes for the implementer
The API is idempotent per (version, format) — never disable the button after a click "just in case"; a second click must feel safe because it is. Keep the ZIP size from `exp.result.bytes`, formatted with one decimal.
