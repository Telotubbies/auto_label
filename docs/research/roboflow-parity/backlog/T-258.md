## User story
As an ML engineer with three projects, I want to start a run from a model another project already trained, so that a good detector becomes a starting point instead of a reason to duplicate the dataset.

## UX flow (LabelDesk words)
1. **Workspace → Models → Shortlist** — a *Shared checkpoints* section lists every shared ready model with project, task, variant and headline metric. [empty: "No shared checkpoints yet — open a model and choose Share with this workspace."] [loading: three skeletons] [error: "Shared checkpoints could not be loaded" + Retry]
2. **Checkpoint card** — opening one shows a read-only summary (project, version, task, variant, mAP, licence) and one action *Start from this checkpoint*. The card states "This is a base model, not a deployable copy — the new project gets its own model."
3. **Start from this checkpoint** — navigates to that project's Train screen with `?checkpoint=<model_id>`; the new project's form preselects the same family and variant, the *Starting weights* row (T-259) reads "Shared checkpoint · <project> / <name>", and the summary shows the quote for **this** project's data. [error: an incompatible checkpoint (different task or family) renders "This checkpoint trains <task> models; this project is <task>" and the row is not selected]
4. **Reuse is explicit** — a banner: "Starting from another project's weights. The dataset stays yours; the weights are copied into this run." The new run's `resume_from` never points at a row the project cannot read.

## Backend changes
- Models/schema: none new (T-257's `shared` column is the only state).
- Routers: `GET /api/ws/{ws}/checkpoints` → `[{model_id, project, project_name, name, task, variant, family, license, ap, created}]` (`shared = true`, `status = "ready"`, lean metrics only). `POST {P}/train` `checkpoint.kind == "shared"` accepts a `model_id` from **any project in the same workspace**: validation = `m.workspace_id == c.ws.id`, `m.status == "ready"`, `m.task == task`, `m.variant == variant` (or a base-variant match), `m.shared`; each failure is a **400** with its own sentence ("that checkpoint trains detection models, this project is segmentation").
- Services/jobs: `handlers/training.py` already resolves `resume_from` into adapter start weights via `_start_weights`; the shared path sets `options.checkpoint_weights = m.weights` (a `DATA_DIR`-relative path the worker can read) and the adapter loads that file. Weights are copied once into `DATA_DIR/models/<new_id>/start.pt` at run start so deleting the source model cannot break a queued run.
- Permissions + workspace isolation: the catalogue is `c.perm("project.read")`-shaped at workspace level (`ws_ctx`) and only lists `shared` rows the caller can read; a `model_id` from another **workspace** is a 400 "unknown checkpoint" (never 404 with an id echo).
- Secrets/safefetch: none — a local file copy inside `DATA_DIR`.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] A shared ready model appears in the workspace catalogue with its metric and licence.
- [ ] Starting from it copies the weights into the new run before the job can be claimed, so a later delete cannot strand it.
- [ ] An incompatible task or an unshared model is a 400 with a sentence that names both sides.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no catalogue, no `shared` checkpoint kind, the train form shows the four original options.

## Notes for the implementer
Copy the file at enqueue time, not in the handler: a queued job of a deleted model must still be runnable. `start.pt` is `DATA_DIR`-relative and recorded in `job.params.options` only.
