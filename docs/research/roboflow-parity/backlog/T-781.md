## User story
As the ML engineer choosing what to ship, I want every run of the project in one table whose columns are its parameters and its metrics, so that "which of my nine runs is best at 640 px" is one sort instead of opening nine cards.

## UX flow (LabelDesk words)
1. **Insights → Runs** (`/:ws/:project/model-insights?tab=runs`) — a table: name, date, version, architecture, then `epochs`, `image size`, `batch`, then AP, mAP50, latency. [empty: "No finished run yet. Train one and its row appears here." with a link to Train] [loading: the table's skeleton rows]
2. **Columns** — a `Columns` control toggles parameters and metrics; the choice is remembered per user in the browser. [error: the ledger request fails ⇒ an inline "Runs could not be loaded" line with a retry, the rest of Insights keeps working]
3. **Sort** — clicking a header sorts ascending or descending; the best value in each numeric column carries a small marker, and runs scored on another dataset version are muted with "different version".
4. **Pin as baseline** — one row is pinned; every other row prints its delta to the baseline (`+0.03 AP`, `+12 s`) and the pinned row is labelled `Baseline: <name>`.
5. **Row click** — opens the existing five-curve overlay for the pinned set on the Training tab. [loading: the overlay keeps the table visible while it fetches]

## Backend changes
- Models/schema: none — the row is assembled from `TrainedModel` + its `config` (T-780) + stored metrics.
- Routers: `GET /api/ws/{ws}/projects/{project}/runs` in a new `routers/runs.py`, returning `[{id, name, created, version, arch, task, status, config, metrics:{AP, AP50, latency_ms}, scored}]`; `project.models` required.
- Services/jobs: `services/run_ledger.py` (new) — `rows(db, project) -> list[dict]`, one query for models plus one for version numbers; no N+1.
- Permissions + workspace isolation: `c.perm("project.models")`; a project id from another workspace answers 404 through the existing `project_ctx`.
- Secrets/safefetch: none.
- OpenAPI: yes — the new router is registered and the document regenerated.

## Tests to write first
pytest — `apps/backend/tests/test_run_ledger.py`:
- `test_rows_carry_config_and_metrics` — two trained models with different `epochs` → each row carries its own `config.epochs` and AP.
- `test_unscored_run_has_null_metrics` — a model whose eval note says "not evaluated" → `scored` false and AP `None`, never `0.0`.
- `test_other_workspace_project_is_404` — workspace B asks for A's project ledger → 404.
- `test_flag_off_is_404` — flag off → 404 on `/runs`.
node — `apps/frontend/tests/runs-ledger.test.mjs`:
- `test_sort_puts_unknowns_last` — `sortRows` on AP places `null` after every number in both directions.
- `test_best_value_marks_one_row_per_column` — `bestValue(rows,'AP')` returns the highest id; latency returns the lowest.
- `test_deltas_are_signed_and_rounded` — baseline AP .71, row .74 → `+0.03`; latency 110 vs 98 → `+12 s`.
- `test_hidden_column_is_not_rendered` — `visibleColumns({epochs:false})` omits `epochs` but keeps name and AP.

## Acceptance criteria
- [ ] One row per run, with version, architecture, epochs, image size and batch as columns beside AP, mAP50 and latency.
- [ ] Any header sorts; the best value in each numeric column is marked; a run on another version is muted and labelled.
- [ ] Pinning a baseline prints a signed delta on every other row and labels the pinned one.
- [ ] Empty, loading and error states above all render: no runs explains what to do first, and a failed ledger request leaves the other tabs usable.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no Runs tab; Training, Evaluation and Compare behave exactly as today.

## Notes for the implementer
Sort with `null` always last and stable ties by `created` descending. "Best" is highest for AP/mAP50, lowest for latency, and only among `scored` rows — a muted row must never win a column. The column preference is a browser preference (`localStorage`, the `theme.ts` pattern), not a workspace setting: a colleague's column set is not data.
