## User story
As an ML engineer, I want a stop that keeps my weights and a cancel that says it throws them away, so that ending a run is a decision with a stated cost instead of one ambiguous button.

## UX flow (LabelDesk words)
1. **A running row → *End run*** — opens *End this run?* with two named choices, not a checkbox: *Stop after this epoch* ("Keeps the best weights, bills the credits used so far.") and *Cancel and discard* ("Nothing is kept; credits are refunded only if the run has not started its first epoch.").
2. **Cancel late** — choosing discard on a run older than 30 minutes shows the warning "The refund window has passed. This refunds nothing." and the primary becomes *Cancel anyway* only after the sentence is acknowledged.
3. **Confirm** — the dialog closes, the row shows *Stopping…* / *Cancelling…* and the job tray follows. [loading: the button reads the pending verb] [error: "That did not go through" + the reason and a Retry; the run keeps running so nothing is lost]
4. **After a stop** — the row reads *Stopped early · weights kept*, the model is deployable, and the detail card states the epoch it stopped at.
5. **After a discard** — the row reads *Cancelled · nothing kept*, and the version can train again with one click.

- **States** — [empty: a finished run offers no ending, so the dialog never opens].

## Backend changes
- Models/schema: none — `job.result.stop_mode`, `job.result.refunded` and `TrainedModel.metrics.stop_reason` carry the outcome (T-265 writes the last one).
- Routers: `POST {P}/jobs/{jid}/cancel` gains body `{mode: "stop" | "discard" = "stop", confirm: bool = False}`. Rules: a `discard` on a job whose `started` is older than 30 min and `confirm is False` → **409** `{code: "confirm_no_refund", message: "the refund window has passed; this refunds nothing"}`; a job that is not `queued|running` → **409** "this run has already ended". Foreign job id → **404**. Response `job_out` plus `{mode, refunded: bool}`.
- Services/jobs: `handlers/training.py` — on `Cancelled` with `stop_mode == "discard"` delete `DATA_DIR/models/<id>/best.pt` and set status `cancelled`; with `stop` keep the checkpoint, set `metrics.stop_reason = "user_stop"` and status `ready`. Refund: new `deps.refund(db, ws, amount)` (mirror of `charge`, floored at zero) called from the cancel route when `mode == "discard"` and `started is None or now - started < 1800`, refunding `CREDIT_COST["train"]` and one `metering.record(..., "gpu_seconds", -used)` is **not** attempted — GPU seconds are history (see Notes).
- Permissions + workspace isolation: `c.need("reviewer")` (unchanged, per the existing `I10` test), foreign project/job → 404.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] Two named endings, each with its consequence in the dialog; nothing is a bare checkbox.
- [ ] A stop keeps deployable weights; a discard removes them.
- [ ] An early discard refunds the train credits; a late one needs a second confirming call and states no refund.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ one *Stop* button and today's cancel semantics.

## Notes for the implementer
Refund credits only — `gpu_seconds` is an append-only usage history and must not be adjusted (see `metering.adjust`: monthly meters are not adjustable). The 30-minute window starts at `job.started`, and a job that never started always refunds.
