## User story
As a packaging line engineer, I want the camera to find and decode the lot code in a region and tell me whether it matches the expected pattern, so that I can prove the right label went on the right box without a separate scanner.

## UX flow (LabelDesk words)
1. **Stream detail → Zones & rules → `เพิ่มกฎ` → `อ่านรหัส`** (`/:ws/:project/streams/:sid`) — the rule asks for a region (an existing zone), the symbologies (`QR`, `DataMatrix`, `Code128`, `EAN-13`, `Code39`) and the expected pattern with `*` wildcards. [empty: a new code rule reads `ยังไม่ได้ตั้งรูปแบบที่คาดหวัง` and only records what it reads]
2. **A read** — the timeline row reads `LOT-2481 · QR · ตรงตามรูปแบบ`; a mismatch reads `LOT-2481 · QR · ไม่ตรงรูปแบบ (คาด LOT-24*)` in the destructive tone. [loading: the first read lands on the next analysed frame, no spinner of its own]
3. **Undecodable** — one event per cooldown carries `อ่านรหัสไม่ได้ — ความต่างต่ำที่ 0.3 MP; ลองสตรีมย่อย` so a blurry read is a stated failure, not silence. [error: that sentence, in the warning tone]
4. **Filtering** — the events list gains a `รหัส` filter that matches the stored value, so a lot is searchable in one field; the export carries `code.value` and `code.match` with the event.
5. **No decoder installed** — the rule form disables the symbologies the worker cannot read and prints `ตัวอ่านรหัสนี้ยังไม่ติดตั้งบนเครื่องนี้`; QR always works because it ships with OpenCV.

## Backend changes
- Models/schema: `StreamEvent` gains `code_value VARCHAR(200) DEFAULT ''` and `code_match BOOLEAN` (null) as one `ADD COLUMN` block in `app/schema/streams.py` `STREAM_EVENTS`, so the filter and the export read columns; the full `{value, symbology, match}` object rides in the rule JSON.
- Routers: `app/routers/codes.py` (new), prefix `/api/ws/{ws}/projects/{project}`, `dependencies=[Depends(require_flag("task_symbol_decode"))]`; `GET /codes/capabilities` → `{decoders: [{id, label, available, reason}]}`; `POST /codes/read` `{image_id, zone_id, symbologies, pattern}` → `{reads: [{value, symbology, box}], match, error}` (422 for an unknown symbology, 404 for a foreign image). `check_rules` accepts `kind: "code"` with `zone_id`, `symbologies`, `pattern`, `every_s` (2–3600 s, default 10). `list_events` gains `code=` over `code_value`.
- Services/jobs: `app/services/codes.py` (new) — `SYMBOLOGIES`, `capabilities()` (`zxing-cpp` optional exactly like `asyncua`: without it only `qr` is available and the others report `ตัวอ่านรหัสนี้ยังไม่ติดตั้งบนเครื่องนี้`), `read(frame, region, symbologies) -> list[dict]` (QR through `cv2.QRCodeDetector`, the rest through `zxingcpp` when installed), `compile_pattern(pattern)` and `match(value, pattern)` (`*`/`?` wildcards, case-insensitive, full-string). `app/streams/manager.py` decodes every `every_s` for each code rule on the analysed frame, fires on a value change or a mismatch, and writes both columns.
- Permissions + workspace isolation: the read route needs `project.infer`; the rule is saved through the existing `PATCH /streams/{sid}` (`c.need("admin")`); the image and the stream are resolved through `workspace_id` + `project_id`, so a foreign id is 404.
- Secrets/safefetch: none — no URL is fetched; a pattern is compiled with a length cap (200) and no regex engine is exposed to the user.
- OpenAPI: yes — two routes, one new rule shape and two `event_out` keys.

## Tests to write first
pytest — `apps/backend/tests/test_symbol_decode.py`:
- `test_a_generated_qr_decodes_to_its_payload` — a QR generated with the shipped `segno` dependency decodes to `LOT-2481` with `symbology == "qr"`.
- `test_a_pattern_with_a_wildcard_matches_and_a_wrong_lot_does_not` — `LOT-24*` matches `LOT-2481` and not `LOT-1999`; `*` alone matches anything.
- `test_an_unreadable_region_reports_the_low_contrast_sentence` — a blurred 0.3 MP crop returns `reads: []` and `error: "อ่านรหัสไม่ได้ — ความต่างต่ำที่ 0.3 MP; ลองสตรีมย่อย"`.
- `test_a_code_rule_needs_a_known_zone_and_symbology` — `PATCH /streams/{sid}` with `kind: "code"` and an unknown `zone_id` is 400, and an unknown symbology is 400.
- `test_the_rule_kind_is_refused_while_the_flag_is_off` — with the flag off a `code` rule is 400 and the route is 404.
- `test_a_capability_reports_the_missing_1d_decoder` — without `zxingcpp` imported, `GET /codes/capabilities` marks `code128` unavailable with its sentence and `qr` available.
- `test_reading_an_image_from_another_workspace_is_404` — a foreign image id is 404.
node — `apps/frontend/tests/code-rule.test.mjs`:
- `test_pattern_validation_allows_wildcards_and_refuses_empty` — `LOT-24*` is valid, `''` is not, a 201-character pattern is not.
- `test_code_chip_reads_the_value_the_symbology_and_the_match` — a match renders `LOT-2481 · QR · ตรงตามรูปแบบ`; a mismatch names the expected pattern.
- `test_an_undecodable_event_reads_the_short_sentence` — `codeChip({code: null, code_error: 'low contrast'})` reads `อ่านรหัสไม่ได้`.
- `test_describe_read_never_prints_an_empty_value` — an empty value renders `—`, never a blank chip.

## Acceptance criteria
- [ ] A code rule names a region, the symbologies and an optional pattern, and the timeline shows the read value, the symbology and whether it matched.
- [ ] A QR generated in a test decodes to its payload, and a pattern with wildcards classifies match and mismatch.
- [ ] A read that fails states `อ่านรหัสไม่ได้` with the low-contrast sentence and keeps the rule running.
- [ ] Empty, loading and error states above all render, including the unavailable-decoder sentence per symbology.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no `code` rule kind, no code chip, no code route, and the timeline is today's.

## Notes for the implementer
QR works out of the box through `cv2.QRCodeDetector`; 1D and DataMatrix need `zxing-cpp`, treated exactly like the optional `asyncua` driver: one commented requirement line, a capability sentence, never an import error. Do not evaluate the code rule in `streams/rules.py` — the engine has no pixels; decode in the manager on the analysed frame at `every_s`, and fire on a change or a mismatch so a static box does not spam one event per frame.
