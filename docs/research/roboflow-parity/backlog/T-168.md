## User story
As a dataset owner, I want to add, order and remove prompt slots and download the answers as VQA training rows, so that the multimodal dataset is mechanical to produce.

## UX flow (LabelDesk words)
1. **Classes & tags → Prompts card** — a table of prompts in order: kind chip (Question / Prefix), the text (with `<SLOT>` emphasised), type, required, answered count, and row actions (move up/down, edit, delete). **Add prompt** opens a small form with those fields. [empty: "No prompts yet — add one to make this a multimodal project"] [loading: skeleton rows] [error: save failed → the form keeps its values with the reason]
2. **Validation in the form** — a prefix without exactly one `<SLOT>` is refused inline; a choice prompt with no options is refused; a duplicate key is refused with the existing key named.
3. **Delete** — the confirm states the answer count: "Delete "What is the total?" and its 42 answers?" — Cancel is the default.
4. **Answered count** — per prompt, "42 of 120 images answered", linking to the dataset filtered to `answered=no` for that prompt (a saved-view chip the dataset page already supports).
5. **Export** — **Export VQA** next to the card exports every answered prompt as `JSONL` (default) or `CSV`: `{"image": "IMG_0031.jpg", "prompt_key": "total", "question": "What is the total on this receipt?", "answer": "1250"}`; a prefix prompt exports its rendered sentence as `question` ("A receipt totalling 1250 baht") and the answer separately. The file downloads directly; only images with at least one answer are included, and the button states that count. [error: no answers → the button is disabled with "No answers to export yet"]
6. **Keyboard** — the table rows are navigable, the add form is a normal tab sequence, and the delete confirm focuses Cancel.

- Routers: in `routers/prompts.py` — `GET /prompts/export?format=jsonl|csv` returning `text/plain` with `Content-Disposition`; `GET /prompts/stats` → `[{prompt_id, answered, total}]` for the counts (a single grouped query).

- Permissions + workspace isolation: stats and export need `project.export`; every query filters `project_id` and workspace; a foreign project slug is 404.

## Acceptance criteria
- [ ] Prompts can be added, edited, reordered and deleted with the documented validation and count-bearing confirm.
- [ ] The answered count per prompt is accurate and links to the unanswered filter.
- [ ] Export produces JSONL or CSV with one row per answered prompt, the rendered sentence for a prefix, and no deleted images.
- [ ] Export requires `project.export` and refuses an empty set with a readable message.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the card is absent and both routes 404.
- [ ] Keyboard-only path: Classes & tags → Tab to Add prompt → fill → Enter to save.

## Notes for the implementer
`prompt_key` is the stable column name in the export; the human `question` is the prompt's text, so renaming a prompt's wording does not break a downstream training script that keys on `prompt_key`.
