## User story
As an ML engineer, I want `ci` to run 20 images on the small model and `full` to run everything,
from one file, so that the test run and the production run cannot drift apart.

## UX flow (LabelDesk words)
1. **Pipeline run panel → Profile** — a picker listing the profiles the file declared, each with the
   one-line summary of what it changes ("ci: model yolo26n, 20 images"). [empty: the file declares no
   profiles — the picker is absent and "default" is shown as text] [loading: profiles come with the
   workflow, so the picker renders as soon as the panel does] [error: a profile that changes the graph
   shape (adds/removes a step) is refused with "a profile may change values, not steps"].
2. **Diff preview** — choosing a profile lists each changed field with old → new, before Run.
3. **Run** — the run records the profile name; the job row and the run report both name it, so two
   runs of the same workflow are distinguishable. [empty: n/a] [loading: the run row appears queued]
   [error: a profile names a model the project does not have — "profile `full` references `yolo26x`,
   which is not in this project", nothing queued].

## Backend changes
- Models/schema: `workflows.profiles` JSON, nullable, default NULL — one `ADD COLUMN` block
  `WORKFLOWS` appended to `app/schema/dataset.py` and one line in `schema/__init__.py` `STEPS`.
  Backfill: none (NULL = no profiles).
- Routers: the import route (T-973) stores `profiles`; `POST /workflows/{id}/run` accepts
  `profile: str | None` and resolves overrides server-side before handing blocks to the runner.
- Services/jobs: `app/services/pipeline_file.py` gains `apply_profile(blocks, profiles, name) -> list`
  (per-block field overrides only; a change that alters `type` or the block count raises) and
  `profile_diff(blocks, profiles, name) -> [{index, field, from, to}]`.
- Permissions + workspace isolation: running needs `project.infer` (unchanged from the workflow run
  route); profiles are read with the workflow; foreign project → 404.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Frontend changes
- Route: none (inside the workflow run panel and the batch-inference launcher).

## Acceptance criteria
- [ ] A profile changes values only; a shape change is refused by the server and the picker.
- [ ] The chosen profile and its diff are visible before the run starts.
- [ ] The finished run names its profile on the job row and in the report.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
