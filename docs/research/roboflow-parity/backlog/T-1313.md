## Problem
A blank screen, a rejected promise or a slow page is invisible: there is no `window.onerror`, no
`unhandledrejection`, no error boundary and no LCP/INP/CLS capture anywhere in `apps/frontend`. The
monitoring plan's dashboard has no client-side row because there is no data.

## Design
**Backend** — `app/routers/telemetry.py` (new, ~70 lines), `POST /api/telemetry/web`:
- accepts `{kind: "error"|"rejection"|"vital", message, stack?, route, request_id?, metric?, value?, page?}`;
- caps: body 8 KB, `message` 500 chars, `stack` 2 000 chars, `route` must start with `/` and contain no
  query string, `metric ∈ {lcp, inp, cls, ttfb}`;
- increments `labeldesk_web_errors_total{kind, page}` or observes
  `labeldesk_web_vitals{metric, page}` (a summary/gauge pair), writes one `web.telemetry` log line with
  the request id;
- rate limit 60/min per session (anonymous allowed: a crash on the login page must be reportable);
- **no table, no migration**: raw samples live in the structured log, aggregates in `/metrics`.

**Frontend** — `src/lib/telemetry.ts` (new, ~90 lines):
- `initTelemetry()` wires `window.addEventListener("error")` and `"unhandledrejection"`, strips query
  strings and anything matching `ld_[a-z]+_[A-Za-z0-9]+`, and posts with `navigator.sendBeacon` when the
  page is hidden, `fetch(keepalive)` otherwise;
- the `web-vitals` package (2 KB) reports LCP, INP, CLS and TTFB once each on hidden/route change, with
  a page class derived from the route (`login`, `home`, `projects`, `dataset`, `editor`, `models`, …);
- a 30-second dedupe per message so a render loop cannot flood the API.

**Error boundary** — `App.tsx`: one class component that catches a render error and shows a `Card` with
"Something went wrong", the request id, a **Reload** button and a **Report** button (which posts the
same payload with a note), instead of today's white screen.

## Acceptance criteria
- [ ] A thrown render error shows the boundary card, not a white screen, and posts once.
- [ ] LCP, INP, CLS and TTFB appear as counters/summaries on `/api/metrics` after a page visit.
- [ ] No query string, token, email or image path leaves the browser.
- [ ] The route is rate-limited, caps every field, and is 404 with `LD_TELEMETRY=0`.
- [ ] No new database table and no migration.
- [ ] Works with the SPA's CSP (`connect-src 'self'` — the call is same-origin).

## Notes for the implementer
The ErrorBoundary must not swallow the router: put it *inside* `BrowserRouter`, around `App`, and log
the same payload the window handler would. Do not add Sentry or GlitchTip — one route and one log line
answer the question, and the plan names them as the upgrade path if the owner wants grouping. Keep the
`web-vitals` integration to four callbacks; no attribution build.
