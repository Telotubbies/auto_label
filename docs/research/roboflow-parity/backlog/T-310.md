## User story
As a workspace member, I want every way of running a model to be listed in one place with the reason it cannot be used, so that a delivery option is never silently missing from the product.

## UX flow (LabelDesk words)
1. **Deploy & test** (`/:ws/:project/deploy`) — the page asks `GET /api/ws/{ws}/runtimes` once and renders one row per runtime. [empty: a deployment with no runtime configured still renders six rows, five of them with a reason] [loading: the chooser shows six skeleton rows] [error: the call fails → one inline line, "Delivery options could not load — the hosted API still works", and the endpoint card keeps rendering]
2. **A disabled row** — the reason sits under the label, in the sentence the API returned, e.g. "Batch inference is not enabled in this workspace." The row is dimmed, keeps its label, gets `aria-disabled="true"`; it is never dropped from the list and never hidden behind a tooltip only.
3. **`GET /api/ws/{ws}/runtimes`** — the response is what the chooser and the snippet builder both read (`{runtimes: [...], envelope: 1}`), so the two screens cannot disagree.

## Backend changes
- Models/schema: none. Availability is derived per request from the plan, the workspace flags and the deployment topology.
- Routers: `apps/backend/app/routers/runtimes.py` (new) — `GET /api/ws/{ws}/runtimes`, `ws_ctx`, returns `{"runtimes": [...], "envelope": 1}`. One row per id in `RUNTIME_IDS`, in that fixed order, each `{id, label, kind, runs_on, accelerator, latency, billing, region, best_for, doc_anchor, available, reason}`. `kind` ∈ `realtime | bulk | device`.
- Services/jobs: `apps/backend/app/services/runtimes.py` (new) — `RUNTIME_IDS = ("hosted", "self_hosted", "batch", "stream", "dedicated", "edge")`, `catalogue(db, ws) -> list[dict]`, `envelope(pred, runtime, request_id) -> dict` adding `runtime`, `request_id`, `envelope: 1` to a prediction body without touching `predictions`, `image` or `time`, and `NOT_CONFIGURED = "Not available in this deployment."` Availability: `hosted` always true; `self_hosted` always true (it is a link, not a service call); `batch` true when `is_enabled("task_36", db, ws.id)`; `stream` true when `task_10b` is on and `PLANS[ws.plan]["streams"] > 0`; `dedicated` and `edge` false with `NOT_CONFIGURED` until T-352/T-358 land.
- Permissions + workspace isolation: `ws_ctx` only (`workspace.read`); the ids carry no project data, so a member of workspace B who calls workspace A's path gets the same 403/404 the shell already returns for a foreign slug.
- Secrets/safefetch: none — the catalogue holds no URLs, keys or hostnames.
- OpenAPI: yes — new route.

## Tests to write first
pytest — `apps/backend/tests/test_runtimes.py`:
- `test_catalogue_lists_every_runtime_in_a_fixed_order` — the response ids equal `RUNTIME_IDS`, so a later deployment cannot drop a row.
- `test_unconfigured_runtimes_are_disabled_with_a_reason` — `dedicated` and `edge` come back `available: false` with a non-empty `reason`, and are still present.
- `test_batch_follows_the_workspace_flag` — with `task_36` off, `batch.available` is false and its reason names the workspace; turning the flag on flips it.
- `test_stream_is_disabled_when_the_plan_allows_no_camera` — a plan whose `streams` cap is 0 returns `available: false`.
- `test_envelope_adds_fields_without_moving_the_predictions` — `envelope({"predictions": [...], "image": {...}, "time": 0.1}, "hosted", "req1")` keeps the three keys byte-identical and adds `runtime`, `request_id`, `envelope`.
- `test_runtimes_is_scoped_to_the_workspace` — the sibling-workspace client gets 403 (it is a ws route, not a project route), and no other workspace's plan leaks into the payload.
node — `none: no frontend surface`.

## Acceptance criteria
- [ ] `GET /api/ws/{ws}/runtimes` returns six rows in a fixed order for a free workspace.
- [ ] `dedicated` and `edge` are present with `available: false` and a readable reason, never omitted.
- [ ] `batch` and `stream` flip with their existing flags and the plan cap; the reason names which one blocked them.
- [ ] `envelope()` leaves `predictions`, `image` and `time` untouched so the hosted and self-hosted bodies stay interchangeable.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — enforced by `ws_ctx`; the test asserts the foreign call is refused.
- [ ] No flag: the payload is additive, and this card renders nothing on its own.

## Notes for the implementer
`self_hosted` is `available: true` on every plan and carries `billing: "no credits — your hardware"`; the card that explains it is T-312, and this catalogue must not imply LabelDesk operates a second server. Reuse `is_enabled` from `services/flags.py` and `PLANS` from `config.py`; do not copy their numbers into the catalogue.
