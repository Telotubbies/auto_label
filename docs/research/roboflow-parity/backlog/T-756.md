## User story
As a customer's accountant, I want one page carrying every element a Thai tax invoice needs, with the VAT as its own line and "draft" printed on it, so that I can tell at a glance whether it can be filed and what is missing if it cannot.

## UX flow (LabelDesk words)
1. **An invoice row → `Open document`** (`/:ws/billing/invoices/:id`) — a full-page sheet on white, no sidebar, no glass. Header block: seller name, tax id and address; `"Tax invoice"` / `"ใบกำกับภาษี"`; the number with its `(draft)` suffix; the issue date in the reader's calendar (Buddhist era when the preference is on); the buyer block with name, tax id and address. [loading: the sheet outline with three skeleton lines] [error: "Could not build this document." + **Try again**]
2. **The line table** — `Description`, `Quantity`, `Unit price`, `Amount`, then the three totals: `"Subtotal"`, `"VAT 7%"`, `"Total"` in baht with two decimals and the satang never rounded twice.
3. **An element missing** — the sheet prints `"Seller tax id: not set"` in place of the value and a footer strip: `"This is a draft. It is not a tax invoice yet — 2 elements are missing."` / `"นี่เป็นฉบับร่าง ยังไม่ใช่ใบกำกับภาษี — ยังขาด 2 รายการ"` with the list. The `Deliver` action in T-758 is disabled while `deliverable` is false.
4. **No price configured** — every amount cell reads `"Pricing not set"`, the totals read the same, and the document is not deliverable. A number is never invented to fill the sheet.
5. **`Print`** — the browser dialog; `@media print` drops the sidebar, the top bar, the job tray and every button, and keeps the sheet's borders. No PDF library, no second renderer.
6. **A foreign invoice** — the route renders the neutral "not available" page, never an empty sheet with our seller block.

## Backend changes
- Models/schema: none — T-755 owns the columns.
- Routers: `GET /api/ws/{ws}/billing/invoices/{id}/document` appended to `app/routers/billing.py` → `{seller: {name, tax_id, address, set: bool}, buyer: {...}, number, number_draft: true, issued, lines: [{description, quantity, unit_satang, amount_satang}], subtotal_satang, vat_rate, vat_satang, total_satang, currency, po_number, note, missing: [...], deliverable: bool}`; 404 foreign id, 409 for a credit note (a credit note renders its own document kind later, not this one).
- Services/jobs: `app/services/invoice_doc.py` (new) — `ELEMENTS = ("seller_name", "seller_tax_id", "seller_address", "buyer_name", "buyer_tax_id", "number", "issued", "lines", "vat")`, `document(db, ws, invoice) -> dict` (fills each element from the invoice row or `config` and lists what is missing), `deliverable(doc) -> bool` (every element present and `dry_run` recorded), `baht(satang) -> str` (`"12,345.60"`, integer math, never `float`). Seller identity comes from `config` defaults that are empty today, so a fresh install prints "not set" rather than a placeholder company.
- Permissions + workspace isolation: `workspace.billing` on the route; the invoice is resolved by `workspace_id`, so a foreign id is 404.
- Secrets/safefetch: none — no URL, no upload; the seller block reads configuration, not the database.
- OpenAPI: yes — one route and the document shape.

## Tests to write first
pytest — `apps/backend/tests/test_invoice_document.py`:
- `test_the_document_carries_every_required_element` — an invoice with buyer fields set and seller config filled returns all of `ELEMENTS`, `deliverable: true`, and `number` ending in `(draft)`.
- `test_missing_seller_and_buyer_fields_are_listed_not_blanked` — with empty seller tax id and empty buyer tax id the response lists both in `missing`, `deliverable` is false, and neither value is an empty string pretending to be set.
- `test_baht_never_uses_float` — `baht(12345600)` is `"123,456.00"` and `baht(1)` is `"0.01"`.
- `test_no_price_renders_pricing_not_set` — an invoice with no lines answers `missing` containing `lines` and each amount is `null`, so the sheet can print `Pricing not set`.
- `test_a_credit_note_has_no_invoice_document` — the route is 409 for a `credit_note` row.
- `test_foreign_invoice_and_flag_off` — 404 for another workspace's invoice; with the flag off the route is 404.
node — `apps/frontend/tests/invoice-document.test.mjs`:
- `test_amount_cell_prints_pricing_not_set_for_a_null` — `amountCell(null, 'THB')` reads `Pricing not set`, never `0.00` or `฿NaN`.
- `test_amount_cell_groups_baht_with_two_decimals` — `12345600` reads `฿123,456.00`; the currency symbol follows the invoice, not the reader.
- `test_missing_line_names_the_elements_and_the_count` — two missing elements read the count and both names.
- `test_issue_date_follows_the_reader_calendar` — a Buddhist-era reader gets 2569 and a Gregorian reader 2026 for the same instant.
- `test_the_sheet_has_no_glass_in_print` — the print block hides the shell and the sheet uses no `data-glass` attribute.

## Acceptance criteria
- [ ] The document carries every required element or names it as missing, and prints "draft" whenever `deliverable` is false.
- [ ] The VAT is a separate line and subtotal + VAT equals the total to the satang, with `"Pricing not set"` wherever no amount exists.
- [ ] `Print` produces a sheet with no sidebar, no top bar and no buttons.
- [ ] Empty, loading and error states above all render: the skeleton sheet, the load error with **Try again**, the missing-element strip, and the neutral page for a foreign invoice.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no document route and no sheet; the usage page is exactly today's.

## Notes for the implementer
Owner-gated: the seller's legal name, tax id, registered address and VAT registration, and whether this document may be issued at all — a person and an accountant sign that, not the implementation (INDEX §4.3). The element list is a *specification to be confirmed by an accountant*: the words "tax invoice", seller name/address/tax id, buyer name/address, a serial number, description/quantity/value per line, the VAT amount separately, and the issue date; numbering series, withholding tax and e-tax filing are unverified (BEYOND §5). Print, do not generate a PDF — no PDF library is a dependency, and a browser print of this sheet is the artefact an accountant accepts; adding a renderer here would be a second document that can disagree with the first.
