## User story
As someone automating dataset setup, I want `create_project` in the SDK and `project create` in the CLI with the same fields as the form, so that a script does not have to hand-roll an HTTP call.

## UX flow (LabelDesk words)
1. **CLI** — `labeldesk project create "Hardhat Detection" --type object-detection --group ppe --folder safety --license "CC BY 4.0" --classes person,helmet,vest [--json]`. Success prints `Created Hardhat Detection (/pe-hd)` and the project row; with `--json` it prints the API payload. [error: 402 → `The Free plan holds 3 projects.`; 400 → `type must be one of …` verbatim from the server, exit code 1]
2. **CLI list** — `labeldesk project list [--json]` prints one line per project (`slug · name · type · images`) so a script can pipe it. [empty: `No projects yet.` on stdout, exit 0]
3. **SDK** — `LabelDesk(...).create_project(name, type="object-detection", annotation_group="objects", license="CC BY 4.0", folder=None, classes=[], visibility="private") -> dict` returns the project payload the API returned; a 4xx raises `LabelDeskError(status, detail)` carrying the server detail unchanged.
4. **No surface for agents** — there is no MCP server in this repo, so nothing is invented; the assistant (T-014) is the agent path.

## Acceptance criteria

- [ ] SDK `create_project` returns the created project and raises `LabelDeskError` on 4xx with the server detail intact.
- [ ] Empty and error states above render (`No projects yet.`, 402 and 400 lines, exit codes).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag none: the web form and the CLI hit the same endpoint and produce identical rows.
- [ ] No MCP server or agent tool is invented.
