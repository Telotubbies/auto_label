## User story
As an integrator, I want to point an output at an MQTT topic and watch the attempts in one log, so that a factory pilot survives its security review without me writing a bridge service.

## UX flow (LabelDesk words)
1. **Project settings → `เอาต์พุตเหตุการณ์`** (`/:ws/:project/settings?tab=outputs`) — one card per output: name, transport (`เว็บฮุก` / `MQTT`), the address fields, the topic, the filter and an on/off switch. [empty: `ยังไม่มีเอาต์พุต — เหตุการณ์อยู่ในไทม์ไลน์ตามเดิม`] [loading: `กำลังโหลดเอาต์พุต`]
2. **`ตัวอย่างข้อมูล`** — a read-only JSON of the envelope with `schema_version` at the top and the mapping of extra fields (piece id from a code read, shift id) listed under it. [error: `หัวข้อต้องไม่มี wildcard` / `ที่อยู่ต้องอยู่ในเครือข่ายที่อนุญาต`]
3. **`ส่งเหตุการณ์ทดสอบ`** — publishes once and prints `ส่งแล้ว · 12 ms · 200` or the broker's answer. [loading: `กำลังส่ง`] [error: `ไคลเอนต์ MQTT ยังไม่ติดตั้งบนเครื่องนี้` when the build has no broker client compiled in — the sentence names the missing part, never a silent stop]
4. **`บันทึกการส่ง`** — the last twenty attempts: state, attempts, code, latency, next retry; the dead-letter tab lists what gave up and offers `ส่งซ้ำ` per row and `ส่งซ้ำทั้งหมด`.
5. **A broker that is down** — the card shows the last error and the next retry, and the events keep flowing into the timeline; an output failure never blocks a camera.

## Backend changes
- Models/schema: none — T-695 shipped `EventSink` and `SinkDelivery`.
- Routers: `app/routers/event_outputs.py` (T-695 created it) — `POST`/`PATCH` accept `transport: "mqtt"` with `config: {host, port, topic, username?, password?, tls?}`; `POST /{id}/test` dispatches through the same delivery path. 400 for a wildcard topic, a port outside 1–65535, or a host outside the operator allowlist.
- Services/jobs: `app/services/broker.py` (new) — a minimal MQTT 3.1.1 publisher on `socket`/`ssl` (CONNECT with optional user/pass, one PUBLISH at QoS 0, DISCONNECT) with a 3 s timeout and no retained flag; `publish(config, payload) -> (status_code, latency_ms)` raising `BrokerUnavailable` with a sentence. `app/services/event_sinks.py` gains one branch: `deliver()` sends webhook or broker through the same retry/dead-letter path, and `check_broker_target(host, port)` reuses `config.OT_ALLOW_CIDR` exactly like `services/ot.py::check_target`.
- Permissions + workspace isolation: writing an output needs `project.settings`; reading the log needs `project.read`; sinks and deliveries stay filtered by `workspace_id` + `project_id`, and a foreign output id is 404.
- Secrets/safefetch: the webhook path keeps `services/safefetch.py`; the broker path is guarded by `check_broker_target` against `LD_OT_ALLOW_CIDR` (empty by default ⇒ no broker reachable). A broker password is stored through `services/secretbox.encrypt` inside `config` and never returned — `_out` masks it to `"****"`.
- OpenAPI: yes — two changed request schemas and one test route contract.

## Tests to write first
pytest — `apps/backend/tests/test_broker_sink.py` (an in-process fake broker: a `socket` server that reads CONNECT and PUBLISH; never a real broker):
- `test_publish_sends_connect_publish_and_disconnect` — against the fake, `publish()` writes a CONNECT, one PUBLISH on the configured topic and a DISCONNECT, and returns `(0, ms)`.
- `test_the_broker_payload_is_the_envelope` — the PUBLISH payload parses as JSON with `schema_version` and the event id.
- `test_a_refused_broker_is_retried_then_dead_lettered` — a fake that closes the socket three times moves the delivery to `dead` with `attempts == 3`.
- `test_a_wildcard_topic_is_400` — `topic: "plant/+/events"` is refused at save time.
- `test_a_broker_outside_the_allowlist_is_refused` — a host outside `LD_OT_ALLOW_CIDR` is 400 with the allowlist sentence, and the fake broker records no connection.
- `test_the_broker_password_is_masked_in_every_response` — `GET /event-outputs` never contains the password, and the stored `config` is sealed.
- `test_a_missing_broker_client_is_named` — with `broker.publish` patched to raise `BrokerUnavailable`, the test route answers the `ไคลเอนต์ MQTT ยังไม่ติดตั้งบนเครื่องนี้` sentence rather than a 500.
- `test_the_routes_are_hidden_while_the_flag_is_off` — 404 with the flag off.
node — `apps/frontend/tests/event-outputs.test.mjs`:
- `test_transport_fields_switch_between_webhook_and_mqtt` — webhook shows `url`; mqtt shows host, port, topic, tls.
- `test_mask_config_hides_the_password` — `maskConfig({password: 'x'})` returns `"****"` and never the value.
- `test_preview_text_is_pretty_and_versioned` — `previewText({schema_version: '1.0'})` starts with `{`, is indented two spaces and contains `"schema_version": "1.0"`.
- `test_delivery_tone_maps_dead_to_the_destructive_chip` — `deliveryTone({state: 'dead'})` is the destructive `chipTone` class, `sent` is the success one.

## Acceptance criteria
- [ ] An output can be a webhook or an MQTT topic, with a filter, a read-only envelope preview and a masked password.
- [ ] `ส่งเหตุการณ์ทดสอบ` publishes through the real path and reports the status and the latency.
- [ ] The delivery log lists the last twenty attempts, the dead-letter lists what gave up, and `ส่งซ้ำ` resends one or a bounded range.
- [ ] Empty, loading and error states above all render, including the missing-client and outside-allowlist sentences.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no tab, no routes, and project settings is today's.

## Notes for the implementer
Write the publisher, do not add `paho-mqtt`: forty lines of CONNECT/PUBLISH/DISCONNECT over `socket` covers the plant case and keeps a dependency out of the API image — QoS 0, no retained messages, no subscriptions, and say so in the hint. A broker host is guarded by the same `LD_OT_ALLOW_CIDR` as a PLC: it is the plant network, not the internet.
