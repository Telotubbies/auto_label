## User story
As a workspace admin or a platform operator, I want to read who did what, see which workspaces exist, and
change a policy with the consequence stated, so that governance is a screen I can use under pressure, not
a database query.

## UX flow (LabelDesk words)
1. **Workspace → Audit** (`/:ws/audit`) — the table shows actor, action, target and time; four filter slots
   and a row that expands to the before/after.
2. **Filter and scroll** — filter by actor and action; the list pages or scrolls endlessly without losing
   the filter. [empty: "No events match these filters" plus clear].
3. **Expand a row** — the diff is readable and names the object; a denied action is visible as denied.
4. **Platform console** (`/admin`, superadmin only) — workspace list with seats, usage and state.
   [error: a non-superadmin sees the refusal page, never a blank console].
5. **Workspace detail** — quota, flags and the last admin action; a feature flag toggle is audited.
6. **Project settings → Policy** (`/:ws/p/:project/settings`) — the private-data opt-out is stated with its
   consequence before it changes.
7. **Audit again** — the policy change is the newest row with the right actor and target.

## Acceptance criteria
- [ ] The audit row names actor, action, target and time; the expanded diff is readable.
- [ ] Filters survive scrolling/paging and the empty-filter state is distinct from an empty log.
- [ ] A flag toggle and a policy change each appear as the newest audit row with the right actor.
- [ ] A non-superadmin cannot reach the console; the refusal is explicit, not a blank page.
- [ ] Steps ≤ 9 and time ≤ 180 s; numbers recorded.
- [ ] Empty, loading and error states: no events, a busy toggle, a failed audit fetch with a retry.
- [ ] Keyboard only: filters, row expand and the console's primary actions.
- [ ] No console error; no absolute path, email list or secret in the audit payload.
- [ ] Workspace isolation: A's audit lists only A's events; B's rows never appear, and a project policy in
      A leaves B unchanged.
- [ ] Flag off ⇒ not applicable; this card adds no flag.
