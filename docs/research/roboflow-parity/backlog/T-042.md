## User story
As a workspace admin, I want to see which capabilities my plan includes, so that an invite, a review column or an analytics page either works or tells me what it needs.

## UX flow (LabelDesk words)
1. **Read entitlements** — `GET /api/ws/{ws}/entitlements` → `{plan, planLabel, features: {review_mode, labeling_analytics, label_history, public_projects, scim, custom_roles, folder_permissions}, seats: {used, limit, non_admin_used, non_admin_limit}}`.
2. **Refusal** — any gated endpoint answers 402 `This capability is not in the Free plan.` with `{feature, plan, upgrade: "settings/usage"}` in the body, never a 403 that reads like a permission bug.
3. **No prices** — the payload carries plan labels and limits only; no price, no provider, no charge.
4. **Settings → Plan & Usage** — the existing page lists the same features as `Included` / `Not in this plan`, read from this endpoint (no second table).

## Backend changes
- Models/schema: none — `workspaces.plan` and `config.PLANS` exist.
- Routers: `GET /api/ws/{ws}/entitlements` in `routers/workspaces.py`; a `require_feature(key)` dependency in `app/entitlements.py` that raises 402 with the body above.
- Services/jobs: `app/entitlements.py` (new) — `FEATURES: dict[str, frozenset[str]]` mapping each capability to the plans that include it (`free`, `pro`, `enterprise`); `for_workspace(db, ws) -> dict`; `require_feature(key) -> Callable` (satisfies `Depends`, mirrors `services/flags.require_flag`); `non_admin_limit(plan, seats)`. Defaults: review/analytics/history = `pro`+`enterprise`; scim/custom_roles/folder_permissions = `enterprise`; public_projects = all three, and a workspace policy can still forbid it.
- Permissions + workspace isolation: `ws_ctx` on the read; the dependency resolves the workspace from the request context, so a plan lookup can never read another workspace's row.
- Secrets/safefetch: none. No billing provider, no price table, no charge — wave D order.
- OpenAPI: yes.

## Acceptance criteria
- [ ] One map decides every plan-gated capability, and the API answers 402 with the feature key when a plan lacks it.
- [ ] The payload has no price, currency or provider field and changes nothing about billing.
- [ ] Empty and error states above all render (unknown plan → treated as free; flag off → 404).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged (no route, no guard, every surface open as today).
- [ ] `PLANS` remains the single source of project/image/seat/credit limits; this map only adds capability names.
