## Problem
There is no reproducible dataset and no scenario. A measurement on demo data measures the demo.

## Design
Two files, both under `tools/perf/`, both runnable by hand with one command each.

**`seed.py` (~110 lines)** builds a throwaway SQLite database under
`B:/02_Projects/ld-tmp/perf/` (never the dev database, never `apps/backend/data`):
1 workspace, 1 owner (`perf@labeldesk.dev` / `perf1234`), 1 API key with all scopes, 4 projects,
30 classes, **10 000 images** across the four projects, 40 000 annotations, 20 versions, 5 trained
models with metrics, 200 terminal jobs, 20 queued jobs, 3 alert channels' worth of rows and 1 webhook.
200 real 12 KB JPEGs are generated once with Pillow and shared by sha across the 10 000 rows, so the
whole fixture is under 3 MB. Deterministic (`random.Random(1337)`), idempotent (`--reset`), writes
`perf-seed.json` (credentials, project slugs, image ids, job ids) and prints the counts. Under 20 s.

**`locustfile.py` (~190 lines)** — four named scenarios, weights 6/3/1/1, 20 users, spawn 2/s:

| Scenario | Steps |
| --- | --- |
| `browse_10k` | login once per user → `GET /projects` → `GET …/images?limit=25` at offsets 0, 500 and 5 000 → one filtered query (`status`, `class_id`) → 6 thumbnails through signed URLs |
| `annotate_save` | open a random image → `PUT …/annotations` with 20 boxes → re-save with `review.status` |
| `export` | `POST …/versions/{id}/export` → poll `GET /jobs/{id}` every 1 s to a terminal state (bounded 60 s) |
| `mcp_list_images` | JSON-RPC `tools/call list_images` over the MCP HTTP transport with the seeded `ld_` key |

- Every request carries `name=` so Locust's CSV is per class, not one blob.
- Auth is a `@task`-level `on_start` login (not per request), so the run measures the product, not PBKDF2.
- Route paths are resolved from `apps/backend/openapi.json` at start; a renamed route fails loudly
  instead of 404-ing quietly for five minutes.
- `--csv` output lands in `docs/ops/perf/runs/<date>/`.

## Tests to write first
`tools/tests/test_perf_seed.py`:
- `test_seed_counts_match_the_contract` — 10k images, 40k annotations, 4 projects, 20 versions.
- `test_seed_is_deterministic` — two runs produce the same ids and the same sha list.
- `test_seed_reset_is_clean` — `--reset` then seed twice leaves one workspace.
- `test_fixture_disk_stays_under_3_mb`.
- `test_seed_never_touches_the_dev_database` — refuses a `DATABASE_URL` or `LD_DATA_DIR` under
  `apps/backend`; exits 2.

`tools/tests/test_perf_routes.py`:
- `test_every_scenario_path_exists_in_openapi` — the four scenarios' paths, with `{…}` placeholders,
  all appear in `apps/backend/openapi.json`.
- `test_mcp_scenario_uses_the_tools_call_shape`.

## Acceptance criteria
- [ ] `python tools/perf/seed.py --reset` builds the fixture in under 20 s and under 3 MB.
- [ ] `locust -f tools/perf/locustfile.py --headless -u 20 -r 2 -t 5m --csv …` completes with all four
      scenarios represented in the CSV.
- [ ] No scenario hard-codes a route string that is absent from `openapi.json`.
- [ ] The seed cannot write to the development database or to `apps/backend/data`.
- [ ] The README is two copy-paste commands.

## Notes for the implementer
Do not add k6. Do not reuse `seed_v2.py` (it is the demo seed and its data is intentionally small). The
annotation payload shape must come from the real route's Pydantic model — read it, do not guess. If
`locust` needs a pin, pin it in `tools/perf/requirements-perf.txt` and say so in the README; the API's
`requirements.txt` must not grow.
