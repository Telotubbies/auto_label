## User story
As a line operator on a touch screen, I want the frame in front of me with two buttons and the plant's reason list, so that I decide one piece with one gesture and never re-watch the video later to remember why.

## UX flow (LabelDesk words)
1. **`โหมดผู้ปฏิบัติงาน`** (`/:ws/:project/streams/:sid/operator`) — reached from a button in the stream header; a full-width layout: large frame, `ผ่าน` / `ไม่ผ่าน` buttons, the piece-id field and the running counters. [loading: `กำลังโหลดภาพ`] [error: `โหลดไม่สำเร็จ — ลองอีกครั้ง` with a retry that re-runs the same query]
2. **`ไม่ผ่าน`** — a reason sheet opens over the frame with the station's reasons as large rows (`รอยขีดข่วน`, `บุบ`, `ปนเปื้อน`, `ชิ้นส่วนผิด`, `อื่น ๆ`) and a `ยืนยัน` button; cancelling returns without a write. [error: `เหตุผลนี้ไม่ได้อยู่ในรายการของสถานี` if the list changed under the sheet, and the sheet reloads]
3. **Saving** — `กำลังบันทึก` under a second, then the next frame replaces the current one and the counters move. A queued verdict (spool non-empty) still counts locally and `คำตัดสินถูกเก็บในเครื่องก่อน` stays visible. [empty: `ยังไม่มีเหตุการณ์ — กล้องกำลังทำงาน`, never an empty black frame]
4. **A read-only account** — the two buttons are dimmed and the line under them reads `บัญชีนี้ดูได้อย่างเดียว — ต้องมีสิทธิ์ตรวจสอบเพื่อตัดสิน` (permission = dimmed + lock, per the v3 state rules). [error: a 403 from the API re-renders that same line instead of a toast]
5. **Piece id** — optional, typed or scanned into a `รหัสชิ้นงาน / ล็อต` field with the hint `สแกนหรือพิมพ์ แล้วกดยืนยัน`; a barcode scanner behaves as a keyboard and ends with Enter, which submits the verdict.

## Backend changes
- Models/schema: none — T-675 shipped the columns.
- Routers: none — the screen reads `GET /streams/{sid}/events?limit=1` (with the `verdict` keys T-675 added) and `GET /verdict-reasons?stream=`, and writes `POST /streams/{sid}/events/{eid}/verdict`.
- Services/jobs: none.
- Permissions + workspace isolation: the route is `<PermGate perm="project.streams">`; the decide buttons are disabled unless `can('project.review')`, and the API enforces the same rule, so a crafted request from a viewer is still 403. A stream id from another workspace is 404 through T-675's resolution.
- Secrets/safefetch: none.
- OpenAPI: no — no route changes.

## Frontend changes
- Route: `apps/frontend/src/routes/project/deploy.routes.tsx` — `<Route path="streams/:sid/operator" element={<FlagGate flag="task_operator_verdict"><FlagGate flag="task_10b"><PermGate perm="project.streams"><OperatorView /></PermGate></FlagGate></FlagGate>} />`.
- Nav entry: none — the screen is entered from the stream header, so an operator never loses the camera they are watching.
- Components:
  - `apps/frontend/src/features/streams/OperatorView.tsx` (new) — frame, verdict buttons, reason sheet, piece field, counters, keyboard map (`a` accept, `r` reject, `Esc` close).
  - `apps/frontend/src/features/streams/verdictView.ts` (new, pure) — `counters(events)`, `reasonOrder(reasons)`, `canDecide(perms)`, `verdictLine(event)`.
  - `apps/frontend/src/features/streams/StreamDetail.tsx` — one `โหมดผู้ปฏิบัติงาน` button in the header.
- API client: `apps/frontend/src/lib/api/verdicts.ts` (new) — `verdictReasons(ws, p, stream)`, `recordVerdict(ws, p, sid, eid, body)`, `verdictSummary(ws, p, sid, range)`.
- Glass: the frame sits on `.canvas-well` (solid), the verdict buttons are the shipped `Button` at `h-14` with `text-sm`, the reason sheet is the shipped `Modal` (`Glass strength="overlay"`), and only the thin top strip is `Glass strength="chrome"`; counters are `Stat` on `Card`; verdict chips go through `chipTone('status', …)`. No new token, no hex, no arbitrary font size, `lucide-react` only.
- Feature flag: `task_operator_verdict`; off ⇒ the header button is absent and the route redirects to the stream page.

## Acceptance criteria
- [ ] The operator screen shows the current frame, two verdict buttons, the reason sheet, the piece field and the counters, and fits a 1024×768 touch screen without scrolling the buttons.
- [ ] A reject requires a reason from the station's list and a verdict saves in under a second, then the next frame loads on its own.
- [ ] A viewer sees dimmed buttons with the lock line, and the API refuses the same request with 403.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no header button, the route redirects, and the stream page is exactly today's.

## Notes for the implementer
One screen, two gestures: `ผ่าน` and `ไม่ผ่าน` each ≥ 56 px tall and reachable with a thumb, and the reason sheet is the only modal in the flow. Bind `a`/`r`/`Esc` but never make the keyboard the only path — a glove first. Copy: `operator.title`=`โหมดผู้ปฏิบัติงาน`, `operator.accept`=`ผ่าน`, `operator.reject`=`ไม่ผ่าน`, `operator.reason.title`=`เลือกเหตุผล`, `operator.reason.unknown`=`เหตุผลนี้ไม่ได้อยู่ในรายการของสถานี`, `operator.piece`=`รหัสชิ้นงาน / ล็อต`, `operator.piece.hint`=`สแกนหรือพิมพ์ แล้วกดยืนยัน`, `operator.counters`=`ผ่าน {accept} · ไม่ผ่าน {reject}`, `operator.empty`=`ยังไม่มีเหตุการณ์ — กล้องกำลังทำงาน`, `operator.loading`=`กำลังโหลดภาพ`, `operator.error`=`โหลดไม่สำเร็จ — ลองอีกครั้ง`, `operator.saving`=`กำลังบันทึก`, `operator.undecided`=`ยังไม่ตัดสิน`, `operator.readOnly`=`บัญชีนี้ดูได้อย่างเดียว — ต้องมีสิทธิ์ตรวจสอบเพื่อตัดสิน`.
