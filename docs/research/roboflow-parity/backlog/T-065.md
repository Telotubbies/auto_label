## User story
As a data engineer, I want to drop the folder my previous tool exported — CreateML JSON, a Darknet
`obj/` tree or Pascal-Seg mask PNGs — so that a migration does not need a conversion script first.

## UX flow (LabelDesk words)
1. **Upload** — dropping a CreateML `annotations.json` next to its images produces the same result sheet
   as a COCO drop: "Recognised: CreateML JSON · 40 images with labels".
2. **Upload** — a Darknet tree (`obj/`, `train.txt`, `classes.names`) is recognised from its folder
   names and listed as "Recognised: Darknet folder · 40 images".
3. **Upload** — a Pascal-Seg set (`SegmentationClass/*.png` masks beside `JPEGImages/*.jpg`) imports one
   polygon per mask region: "Recognised: Pascal-Seg masks · 40 images" and each image shows its polygon
   in the editor. [error: a mask whose filename has no matching image is reported per file in the reason
   list, and the batch continues]
4. **Upload** — a format nobody supports is refused with one readable line: "No supported annotation
   file found — images will be added without labels", and the images still upload.
   [empty: a folder with no label files at all → the result sheet says "Images only — nothing to import"]
   [loading: each mask decodes in turn and the file list resolves in place]

## Backend changes
- Models/schema: none.
- Routers: none (the existing upload route reaches the new readers through `ingest`).
- Services/jobs:
  - `apps/backend/app/services/import_extra.py` (new) — three readers with the same
    `(Bundle, path, bytes) -> bool` shape the current parsers use:
    - `createml(bundle, name, data)` — `[{"image": str, "annotations": [{"label", "coordinates": {x,y,width,height}}]}]`,
      absolute pixels → normalised at ingest; supports classification form (`"label": str`).
    - `darknet(bundle, files)` — `obj/*.txt` + `*.names` + `train.txt|valid.txt|test.txt` sets the split
      from the list file; `data.data`/`obj.data` gives class names.
    - `pascal_seg(bundle, name, data)` — mask PNG decoded with `PIL`, connected regions via
      `PIL.Image.point`/`numpy` flood label per colour, simplified with the existing
      `imaging` polygon contract (points normalised, ≤ 20 000 values, region < 3 px² skipped).
  - `Bundle` gains `masks: dict[str, bytes]`; `importers.collect` dispatches `.png` under
    `SegmentationClass/` or `*_mask.png` to `pascal_seg` (one dispatch line, Shared).
  - Caps reuse `MAX_ZIP_TOTAL`, `MAX_ZIP_FILES`, `MAX_XML_BYTES`; a mask larger than 8 MB is skipped
    with a reason, never decoded.
- Permissions + workspace isolation: unchanged; all readers are pure functions called inside `ingest`.
- Secrets/safefetch: none.
- OpenAPI: no (response shape unchanged; `format` values are strings).

## Tests to write first

- `test_createml_boxes_become_normalised` — a 2-box CreateML file for a 200×100 image yields two bboxes
  with `x=0.1, w=0.25` and `format == "createml"`.
- `test_createml_classification_label` — `{"image": "a.jpg", "label": "cat"}` yields a `class` shape.
- `test_darknet_split_lists_and_names` — `train.txt` naming 3 images sets `split_of`-equivalent splits and
  the `.names` file supplies class names.
- `test_pascal_seg_two_regions` — a 4×4 mask with two colours yields two polygons and skips a 1-pixel
  speck.
- `test_mask_without_image_is_an_orphan` — mask `ghost.png`, no `ghost.jpg` → orphan reported, batch ok.
- `test_oversize_mask_is_skipped_not_decoded` — 9 MB mask → skipped with a reason.
- `test_unknown_format_still_uploads_images` — no annotation file → images land, `format == "none"`.

## Acceptance criteria
- [ ] Each of the three formats imports with correct normalised shapes and a recognisable format label.
- [ ] One bad file (orphan mask, oversize mask, unreadable JSON) never fails the rest of the batch.
- [ ] Caps (files, total bytes, per-file size) are the existing constants, not new numbers.
- [ ] A format nobody supports still uploads the images with an explicit "no labels" line.
- [ ] Empty/loading/error states above render (per-file reason rows).
- [ ] Flag off ⇒ these uploads behave exactly as today (images only, labels ignored).
- [ ] Workspace A cannot see or change workspace B's data (404 for cross-workspace project ids).

## Notes for the implementer
Do not add TFRecord/COCO-Camera-Trap readers: they need `protobuf`/`av` and the area forbids a new
dependency. If a buyer asks, the answer is "export COCO from that tool". Mask decoding must reuse
`imaging`'s normalisation contract, not invent a pixel shape kind.
