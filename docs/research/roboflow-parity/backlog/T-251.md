## User story
As a labeler-turned-trainer, I want to ask for a family my workspace cannot use yet, so that "SAM 3 fine-tune" is a request with a record instead of a dead card.

## UX flow (LabelDesk words)
1. **Train → Advanced → a gated family** — the card is dimmed and prints its reason ("Fine-tuning this family needs an access grant"), with one secondary button *Request access* where a start path would be.
2. **Request dialog** — a textarea ("What will you use it for?") plus the family name and licence; primary *Send request*. [loading: the button reads "Sending…"] [error: "The request was not saved" with the reason and a retry; the dialog keeps the text]
3. **Already requested** — after success the card's button becomes a status line: "Requested 12 Nov — your workspace admin can see it in Activity." and the dialog closes. [empty: the textarea is optional; an empty note sends "no note"]
4. **Admin read** — the request also writes one audit row (`train.access_request`) so it appears in the workspace Activity log without a new admin screen.

## Backend changes
- Models/schema: new table `model_access_requests` in `apps/backend/app/models/training.py` — `id` (pk), `workspace_id` (FK cascade), `project_id` (FK cascade), `family` `VARCHAR(32)`, `note` `TEXT DEFAULT ''`, `status` `VARCHAR(16) DEFAULT 'requested'`, `created_by` `VARCHAR(32) NULL`, `created` `FLOAT`. Register the class in `models/__init__.py` (`training` import list + re-export). No `ADD COLUMN` block is needed for a new table; `DOMAIN_MODULES` already contains `training`.
- Routers: `POST {P}/train/access-requests` body `{family: str, note: str = ""}` → `201 {id, family, status, created}`; **400** when `family` is not a catalogue family that is `request_access`-gated ("that family needs no access grant"), **409** when a `requested` row already exists for this project + family ("already requested — your admin has it"). Add `GET {P}/train/access-requests` → the project's rows (manager only) so the Models page can dim/annotate the card.
- Services/jobs: none. `train_catalog.families` marks `request_access: True` for the SAM 3 fine-tune entry (T-250 adds the entry: `family="sam3-ft"`, `adapter="sam3"`, `available=False`, `reason="fine-tuning this family needs an access grant"`) and for any family whose adapter probe reports `vram_mb` above the worker budget.
- Permissions + workspace isolation: request = `c.need("reviewer")`; list = `c.need("admin")`. A foreign project slug is 404; the `family` value is validated against the catalogue, never echoed into a path.
- Secrets/safefetch: none (the note is user text, stored and length-capped at 500 characters).
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] A gated family offers exactly one action (Request access) and never a start path.
- [ ] The request stores one row, writes one audit line, and a repeat is a 409 with copy that says it is already in.
- [ ] The requested state is visible on the next render of the card without a page reload.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no button, no dialog, both routes 404.

## Notes for the implementer
The note is capped at 500 characters in the pydantic model (`Field(max_length=500)`); never render it as HTML. One request per project + family is the uniqueness rule — do not add a per-user variant, the admin wants one queue.
