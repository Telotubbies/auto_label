## User story
As a workspace admin, I want each GPU worker to report its OS, GPU, driver, CUDA, free disk and what is
already installed, so that I choose a host that can actually run the engine instead of guessing.

## UX flow (LabelDesk words)
This card is the data behind the hub header; the visible screen is T-1007's host picker.
1. **Host selected** — the picker lists name, GPU, VRAM, `driver 550.54 · CUDA 12.4`, free disk and
   `seen 3 s ago`. [loading: three skeleton rows].
2. **No inventory yet** — a worker running an older build reads "This worker has not reported hardware
   yet." with the worker command to copy. [empty: no workers at all → one line naming
   `labeldesk-worker --kinds train,autolabel,engine_apply,model_pull`].
3. **Offline host** — greyed, `offline 12 min`, actions disabled with that reason. [error: the endpoint
   failed → "Hosts did not load." + Retry].
4. **CPU-only host** — `CPU only` badge; GPU engines are blocked later with this reason.

## Backend changes
- Models/schema: `Worker.inventory` — `JSON`, nullable, no backfill, in `models/insights.py`. New
  `apps/backend/app/schema/insights.py` with `WORKERS = {"inventory": "JSON"}` registered as
  `("workers", insights.WORKERS)` in `schema/STEPS`; existing databases get `ADD COLUMN`, empty ones get
  it at create time.
- Routers: `apps/backend/app/routers/inference.py` (new), prefix `/api/ws/{ws}/inference`,
  `dependencies=[Depends(require_flag("task_inference"))]` — `GET /hosts` → `{hosts: [...]}` where each
  row is `{id, host, online, kinds, current_job, last_seen, inventory}`; admin-only; sorted
  online-first then `host`.
- Services/jobs: `apps/backend/app/services/host_inventory.py` (new) —
  `record(db, worker_id: str, host: str, inventory: dict | None) -> None` validates and sanitises
  (≤ 8 GPUs, ≤ 8 engines, ≤ 200 models, strings truncated to 120 chars, numbers finite, unknown keys
  dropped) and upserts the `Worker` row; `hosts(db, stale_after) -> list[dict]` reuses
  `services.heartbeat.workers` and adds `inventory`. No new job kind.
- Worker: `apps/worker/labeldesk_worker/inventory.py` (new) — `collect(models_dir) -> dict` reads OS/arch
  (`platform`), Python, GPUs (`nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv,
  noheader`, falling back to `torch.cuda` then to `[]`), CUDA (the `nvidia-smi` header, else
  `torch.version.cuda`), `shutil.disk_usage(models_dir)`, `HF_TOKEN` presence as a boolean, the
  `LD_ALLOW_ENGINE_INSTALL` flag, installed engines from the engine directory, and model files from the
  models directory. Any probe that fails becomes a `null` plus a `reason`, never an exception.
- `apps/backend/app/routers/remote.py` — `ClaimIn` gains `inventory: dict | None`; `claim()` calls
  `host_inventory.record(db, body.name, body.name, body.inventory)` before selecting a job. An existing
  worker that sends nothing keeps working.
- `apps/worker/labeldesk_worker/cli.py` — the claim body gains `inventory=collect(args.models_dir)`;
  one argument `--models-dir` defaulting to `LD_MODELS_DIR` (default `~/.labeldesk/models`).
- Permissions + workspace isolation: `owner`/`admin` only (403 for anyone else); the deployment scope
  check is `services/inference_access.workspace_allowed(db, ws_id)` (created here, extended by T-1017) —
  when `LD_INFERENCE_WORKSPACE` is set and names another workspace, every inference route 404s.
- Secrets/safefetch: inventory carries `hf_token: true|false` and never the token; no paths leave the
  worker except the engine/model **ids** and byte sizes.
- OpenAPI: yes.

## Acceptance criteria
- [ ] A remote worker that sends inventory appears in `GET /hosts` with OS, GPU, VRAM, driver, CUDA,
      disk, `hf_token` presence and `allow_install`.
- [ ] A worker that sends no inventory (older build) still claims `train`/`autolabel` and reads as
      "has not reported hardware".
- [ ] Malformed inventory is sanitised, never 500 and never unbounded.
- [ ] The HF token value never appears in an API response or in the database.
- [ ] Member 403, flag off 404, out-of-scope workspace 404.
- [ ] `ADD COLUMN` applies cleanly to an existing database and to an empty one.

## Notes for the implementer
`Worker.id` stays `host:pid` for the embedded worker; a remote worker uses its `--name` so a restart
does not create a second host row. Cap every list and string in `record()` — this payload is supplied by
a host, so it is an input boundary, not trusted config.
