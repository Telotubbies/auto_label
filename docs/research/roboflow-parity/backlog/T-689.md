## User story
As an automation engineer, I want to set the model-down mode, test the stop signal and see a permanent banner while the line is not receiving verdicts, so that nobody walks past a cell that has quietly stopped rejecting.

## UX flow (LabelDesk words)
1. **Project settings → `OT output` → `โหมดเมื่อโมเดลหยุด`** (the shipped OT tab) — three radio rows: `หยุดไลน์` (marked `ค่าเริ่มต้น — ปลอดภัยกว่า`), `ยิงรีเจกต์ค้างไว้`, `ไม่ทำอะไร (บันทึกไว้)`; two number fields for the timings; a `บันทึก` button. [error: `โหมดนี้ไม่ปลอดภัย — ต้องยืนยันจากเจ้าของไลน์` shown as a checkbox the user must tick before `ไม่ทำอะไร` saves]
2. **`ทดสอบสัญญาณหยุด`** — sends the configured mode through the real driver and prints the round trip and what was asserted, e.g. `หยุดไลน์ · 18 ms · ปล่อยสัญญาณแล้ว`. [loading: `กำลังทดสอบสัญญาณหยุด`] [error: `ตั้งค่าอุปกรณ์ไม่สำเร็จ` with the address named]
3. **No outputs** — the whole card reads `ยังไม่มีเอาต์พุต — คำตัดสินอยู่ใน LabelDesk เท่านั้น` in a warning tone, and the policy form is hidden: a policy with nothing to actuate is a comfort, not a control. [empty: that sentence, not an empty form]
4. **A live fault** — the streams wall and the station page carry a permanent banner `โมเดลหยุดทำงาน — สายการผลิตไม่ได้รับสัญญาณ`; under the `hold` mode it reads `โหมดปัจจุบันไม่หยุดไลน์ — ตรวจสอบทันที`. The banner clears only when the API reports recovery, never on a timeout. [error: the banner cannot be dismissed while the fault stands]
5. **A phone** — the banner is one line at the top of the wall and the policy rows are full-width; the test button is at least 44 px tall.

## Backend changes
- Models/schema: none — T-688 shipped the columns and the policy settings key.
- Routers: none — the screen reads and writes `GET/PUT …/ot-outputs/fault-policy` and `POST …/fault-policy/test`, and reads `last_status`/`last_error` from the existing output list.
- Services/jobs: none.
- Permissions + workspace isolation: the OT tab is manager-only (the shipped `ProjectSettings` gate); the policy routes need `project.settings` and the banner is read through `project.streams`, so a viewer sees the fault but cannot change the mode, and a foreign project is 404.
- Secrets/safefetch: the test button goes through `services/ot.py::check_target` on the server before any packet leaves — the guard, not the browser, decides whether an address is reachable.
- OpenAPI: no — no route changes.

## Tests to write first
pytest — `apps/backend/tests/test_ot_fault_policy_screen.py`:
- `test_the_policy_payload_has_a_default_and_both_timings` — `GET /fault-policy` on a project that never chose returns `model_down: "stop"`, `degraded_after_s: 30`, `watchdog_ms: 2000`.
- `test_the_test_route_reports_what_it_asserted` — `POST /fault-policy/test` with a recorder driver returns `{mode, status, latency_ms, asserted}`.
- `test_the_policy_routes_are_404_without_both_flags` — off for `task_ot_fault_policy` and, separately, for `task_40`.
- `test_a_foreign_project_policy_is_404` — read and write in another workspace are 404.
node — `apps/frontend/tests/ot-fault-policy-ui.test.mjs`:
- `test_banner_never_renders_for_a_healthy_project` — `bannerFor([{last_status: 'ok'}], [{status: 'live'}])` is null.
- `test_banner_reads_the_fault_sentence_under_stop` — a `fault` output and a stopped stream → `โมเดลหยุดทำงาน — สายการผลิตไม่ได้รับสัญญาณ`.
- `test_banner_names_the_unsafe_hold_mode` — the same state with `model_down: 'hold'` reads `โหมดปัจจุบันไม่หยุดไลน์ — ตรวจสอบทันที`.
- `test_every_mode_has_thai_copy_and_a_default_marker` — `MODES` has three entries, exactly one marked default, and no English label.
- `test_test_result_sentence_names_the_mode_and_the_round_trip` — `{mode: 'stop', latency_ms: 18, status: 'ok'}` reads `หยุดไลน์ · 18 ms · ปล่อยสัญญาณแล้ว`.

## Acceptance criteria
- [ ] The OT tab shows the three modes with `หยุดไลน์` marked as the default and saves the two timings inside their bands.
- [ ] `ไม่ทำอะไร` cannot be saved without the owner acknowledgement, and the test button reports the mode, the round trip and what was asserted.
- [ ] A live fault shows an undismissable banner on the wall and the station page, with the stronger sentence under the unsafe mode.
- [ ] Empty, loading and error states above all render, including the no-outputs warning instead of a form.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off (either key) ⇒ no policy card, no banner, and the OT tab is today's.

## Notes for the implementer
The banner is not a toast and not dismissable: a cell that has stopped rejecting must be visible to whoever walks past the screen. Show the mode word inside the banner, because "we chose to hold" and "we could not reach the PLC" look identical otherwise. Copy: `ot.policy.title`=`โหมดเมื่อโมเดลหยุด`, `ot.policy.stop`=`หยุดไลน์`, `ot.policy.reject`=`ยิงรีเจกต์ค้างไว้`, `ot.policy.hold`=`ไม่ทำอะไร (บันทึกไว้)`, `ot.policy.defaultNote`=`ค่าเริ่มต้นคือหยุดไลน์ — ปลอดภัยกว่า`, `ot.policy.holdNeedsOwner`=`โหมดนี้ไม่ปลอดภัย — ต้องยืนยันจากเจ้าของไลน์`, `ot.policy.test`=`ทดสอบสัญญาณหยุด`, `ot.policy.testing`=`กำลังทดสอบสัญญาณหยุด`, `ot.policy.testFailed`=`ตั้งค่าอุปกรณ์ไม่สำเร็จ`, `ot.degraded`=`โมเดลหยุดทำงาน — สายการผลิตไม่ได้รับสัญญาณ`, `ot.degradedHold`=`โหมดปัจจุบันไม่หยุดไลน์ — ตรวจสอบทันที`, `ot.outputsEmpty`=`ยังไม่มีเอาต์พุต — คำตัดสินอยู่ใน LabelDesk เท่านั้น`.
