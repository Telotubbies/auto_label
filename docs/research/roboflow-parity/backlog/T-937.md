## User story
As an integrator, I want a health check and a version for the model I call, so that my monitor can tell "not deployed" from "broken" without spending a credit.

## UX flow (LabelDesk words)
1. **Deploy & test** — the endpoint card shows a status pill (Ready / Warm-up / Failed) and the served model's name and trained date, plus the two probe URLs. [empty: nothing deployed → the card reads "Nothing deployed" with a link to Models] [loading: the pill pulses "Checking…"] [error: the probe fails → "Endpoint did not answer — the deployed model may have been deleted" with a retry]
2. **Check now** — the button calls the probe and shows the round trip in ms.
3. **A monitor** — `GET /api/v1/models/{ref}/health` answers 200 `{"status": "ready"}` or 503 `{"status": "degraded", "reason": "..."}`; `GET /api/v1/models/{ref}/version` answers `{"model": "<name>", "trained": "<ISO 8601>", "family": "<family>", "contract": 1|0}` and no workspace name, project name or path.

## Backend changes
- Models/schema: none.
- Routers: `apps/backend/app/routers/model_health.py` (new) — `GET /api/v1/models/{ref}/health` and `GET /api/v1/models/{ref}/version`, both resolving `ref` through `_hosted_model` (`apps/backend/app/routers/training.py:592`) so an id and an alias behave the same. Auth: the same `key_ws(db, api_key, request, "infer")` dependency the predict route uses (`apps/backend/app/routers/training.py:668`); no new scope.
- Services/jobs: `apps/backend/app/routers/model_health.py` also holds `probe(m: TrainedModel) -> dict` returning `{"status", "reason", "trained", "family", "contract"}` from the artefact on disk (weights present plus the adapter's `probe()`), reused by T-940. No credit, no metering, and no audit row per successful probe — one audit row per failed probe only.
- Permissions + workspace isolation: `key_ws` already binds the key to a workspace; a model id from another workspace is 404 and another workspace's alias cannot resolve, because `_hosted_model` filters on `ws.id`.
- Secrets/safefetch: none — the probe reads a path, it does not call out.
- OpenAPI: yes — `python tools/export_openapi.py`, `npm run gen:api-types`.

## Tests to write first
pytest — `apps/backend/tests/test_model_health.py`:
- `test_health_is_200_for_a_ready_model` — the body has `status: ready` and carries no project or workspace name.
- `test_health_is_503_when_the_weights_are_gone` — delete the weights file; the probe returns 503 with a reason, never a 500.
- `test_health_accepts_the_alias` — `production` and `production@project-slug` resolve to the same model as the id.
- `test_probe_costs_nothing` — metering for `ai_calls` is unchanged after ten probes.
- `test_version_names_the_model_and_the_family` — the body carries family, the trained date and `contract: 0|1`.
- `test_health_is_404_for_another_workspace` — a key from workspace B gets 404 for A's model id.
- `test_an_unknown_ref_is_404_not_500` — `ref=does-not-exist` returns 404.

## Acceptance criteria
- [ ] `GET /api/v1/models/{ref}/health` answers 200 with `status: ready` for a ready deployed model, and 503 with a reason when it cannot run.
- [ ] `GET /api/v1/models/{ref}/version` names the model, its trained date, its family and whether a contract exists.
- [ ] Neither route charges a credit or writes an audit row on success.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged — no flag here: the routes are additive and `Deploy.tsx` keeps working when they 404.
