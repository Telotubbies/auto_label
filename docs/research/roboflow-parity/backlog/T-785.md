## User story
As the person deciding what to collect or relabel next, I want a slice of the score to hand me the exact images behind it, worst first, so that "dark images score 0.41" becomes a labelling batch instead of a chart.

## UX flow (LabelDesk words)
1. **Evaluation → Slices** (`/:ws/:project/model-insights?tab=evaluation`) — the existing bars now carry `See the images`; the route behind it returns the slice's own files. [empty: a slice with no failures returns an empty list and the UI says so] [loading: the gallery fetches by slice, not a second full evaluation]
2. **Save this slice** — names the definition (dimension, value, model) so `did the night shift improve` is one click after the next training. [error: the same name twice ⇒ 409 "A slice with that name already exists."]
3. **Saved slices** — `GET …/slices` lists them per model, each with its stored AP and image count from the run that saved it.
4. **Send to labelling** — the gallery's action asks the API to create a batch from the selection and returns the batch id and name; the batch description is `<dimension>: <value>`. [error: an image deleted since the evaluation ⇒ the batch is created from the surviving ids and the response names how many were dropped]
5. **A model without stored detections** — the slice route answers 409 "This run stored no per-image detections." and the UI keeps the existing "No per-image detections stored for this run." line.

## Backend changes
- Models/schema: `SavedSlice` (`id, workspace_id, project_id, model_id, name, dimension, value, ap, ap50, images, created_by, created`) in `app/models/project.py`; a new table needs no `ADD COLUMN`. `Batch` already exists and is reused unchanged.
- Routers: new `app/routers/slices.py` — `GET …/insights/models/{mid}/slice?dimension=&value=&limit=` (worst first, signed `url` per file, `gt`/`pred` counts), `GET/POST/DELETE …/slices`; `POST …/batches` `{name, image_ids}` in `routers/images.py` creating one `Batch` and pointing the images at it.
- Services/jobs: `services/insights_eval.py` `slices()` keeps `files` (eval file names) and resolves them to image ids via the existing `image_meta()`; `services/slices.py` (new) — `worst_files(model, dimension, value)`, `save(db, project, model, body, user)`, `batch_from_slice(db, project, image_ids, name)`.
- Permissions + workspace isolation: `project.models` to read a slice, `project.review` to save one and to create a batch; a model, slice or image from another workspace answers 404.
- Secrets/safefetch: signed URLs through the existing `security.sign_path`, exactly as `_eval_images()` does; no new signing path.
- OpenAPI: yes — regenerate both generated files.

## Tests to write first
pytest — `apps/backend/tests/test_slice_drilldown.py`:
- `test_slice_keeps_its_files` — a model evaluated over four images → the `brightness` slice for the dark bucket lists exactly the dark files, worst AP first.
- `test_slice_files_are_signed_and_workspace_scoped` — each row has a signed `url`; workspace B asks for A's model → 404.
- `test_saved_slice_round_trips` — save `{dimension:'brightness', value:'dark'}` → `GET …/slices` returns it with its AP and image count.
- `test_saved_slice_name_is_unique_per_model` — the same name twice → 409.
- `test_batch_from_selection_names_the_slice` — `POST …/batches` with three ids → a `Batch` named `brightness: dark` holding them; a deleted id is reported as dropped.
- `test_slice_route_is_409_without_detections` — a run with no stored detections → 409 with the stated sentence.
- `test_flag_off_is_404` — flag off → 404 on the slice and batch routes.

## Acceptance criteria
- [ ] A slice value resolves to its own image files, worst first, each with a signed preview URL.
- [ ] A slice definition can be saved and read back with the AP and count of the run that saved it.
- [ ] A selection from a slice becomes one batch whose name is the slice, and the response reports any dropped images.
- [ ] A run without per-image detections answers a stated conflict, never an empty 200.
- [ ] Empty, loading and error states above all render as API states: a clean slice returns an empty list with its reasons on the row.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ slice metrics are today's, with no file list and no new routes.

## Notes for the implementer
"Worst first" means the lowest per-image AP (or the highest loss when AP is undefined), ties broken by file name so two runs of the same slice list the same order. A slice's `value` is the exact string the chart shows (`dark`, `1–4 MP`, a tag name) — never a re-derived bucket on read, or the saved slice and the bar would disagree.
