## User story
As the reviewer of any area-1 PR, I want the seven shipped workspace/project flows pinned by cheap
tests so that a later card cannot silently change a key's one-time reveal, the project-create
landing page, the four board columns, the home counters or the empty state.

## UX flow (LabelDesk words)
1. **Signup → workspace** — a new account owns one workspace and lands on `/:ws`; `GET /api/ws/{ws}/home`
   answers zeros, not a 404. [empty: zeroed stats and an empty `waiting` list]
2. **Home** — folders render above the project grid; each project card shows `N Images · N Models`;
   the grid ends in an `EmptyState` (`No projects yet.` / `No projects match.`). [empty: the empty state,
   not a blank grid] [loading: the checklist and grid keep their height]
3. **New project** — name, type, annotation group, licence, folder and initial classes in one modal;
   Create navigates straight to `/:ws/:slug/upload`.
4. **Project** — the sidebar walks DATA → LABEL → MODELS → (STUDIO) → DEPLOY → SETTINGS; the editor
   opens at `/:ws/:project/images/:imageId`.
5. **Annotate** — four columns (Unassigned / Annotating / Review / Dataset); moving a card to Dataset
   marks its images approved.
6. **Settings → API keys** — Create key returns the secret once; the list afterward shows prefix,
   scopes, created and last-used, never the secret.

## Notes for the implementer
The guard pins today's six nav groups on purpose. `nav.test.mjs:104-106` already asserts STUDIO in that
position; the wave-E IA pass (band T-470–T-519, no card written yet) moves STUDIO into Insights and
must update both tests in the same PR — say so in that card, not here. Vice versa, do not "fix" the
order in this guard.
`POST /board/move` sets `review = "approved"` for `to_status == "done"` (`app/routers/images.py:414-415`);
that is the HAVE fact, not an implementation detail to abstract.
Migration-sensitive HAVE facts: a key's plaintext is returned only from `POST /keys` and the row stores
`hash` + `prefix`; `scopes = None` means full access; `Project.slug` reserves workspace page names
(`app/routers/projects.py:90`); `STATUSES` order is the board order (`app/models/common.py:13`).
Build the guard's own workspace + admin user with `issue_access` (the `test_home.py:37-108` fixture
pattern). The demo workspace is on the Free plan, where several existing modules already create
projects; depending on it would make this guard fail on the 20-project cap for reasons unrelated to
area 1.
