## User story
As an ML engineer, I want the price, the time and the graphics card in one card that never scrolls away, and a stop before a run that will take more than a day, so that the commitment is visible at the moment I press Start.

## UX flow (LabelDesk words)
1. **Train → summary card (sticky, right)** — "~18 min · 3 credits · RTX 4090", the *Start training* primary, and a secondary *Details* that expands the basis line ("2,400 train images × 20 epochs at 640 px, 600 images/min"). [empty: nothing selected ⇒ the card shows "Pick a dataset to see the estimate" and the primary is disabled with that reason] [loading: numbers shimmer in place; the primary stays clickable only after the first quote returns] [error: "The estimate is unavailable" + the reason code, with a *Retry*; the primary stays disabled and says why]
2. **Cap field** — under the estimate, as in T-253's flow; below the floor the card shows the error and disables the primary; a cap under the estimate adds "probably stops early, keeps its best weights".
3. **Long-run confirmation** — pressing Start on a quote above 24 h (86,400 s) opens *This run is long*: the expected hours, the credits at the standard rate, the cap (if set) and the sentence "You can stop it early; weights are kept." Primary *Start the 26-hour run*, secondary *Back*. Below a day there is no dialog.
4. **After submit** — the button enters a busy state ("Queuing…"), then the page becomes the run view with a job-tray entry (T-261 renders it). [error: a 402 shows the plan name and the remedy from the API; the form state is kept so the user does not retype]

## Acceptance criteria
- [ ] The summary keeps minutes, credits and the GPU in one line that tracks every form change.
- [ ] A cap under the floor disables Start with the floor named in the message.
- [ ] Start above 24 h always opens the confirmation; below it, never.

## Notes for the implementer
Threshold for the dialog is exactly 24 h of quoted training time, not wall-clock or credits. Reuse the existing `api.post` start call — do not add a second submit path; the cap and the long-run acknowledgement ride in the same body.
