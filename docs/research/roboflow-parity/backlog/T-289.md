## User story
As an ML engineer bringing a checkpoint in, I want the dialog to ask only for what the server needs and to show the check honestly, so that a rejection reads as a reason rather than a mystery.

## UX flow (LabelDesk words)
1. **Models → *Add external weights*** — a dialog: drop zone (click, drag or paste a path), then *Family* (only installed families), *Size* (that family's sizes), *Name*, *Dataset version* (defaults to the newest ready version), and the fixed note "Weights stay in this workspace; *Share* afterwards to reuse them elsewhere."
2. **Before upload** — the primary is disabled until a file, a family, a size, a name and a version are present; each missing field's reason is one line. A file over the limit is refused locally with "Larger than 1,024 MB — upload a smaller checkpoint." [loading: the primary reads "Uploading… 42 %"]
3. **After upload** — the dialog closes into a row state *Checking* (spinner, polled every 2 s); *Checking → Ready* shows the licence and *Run evaluation*; *Checking → Rejected* shows the check's sentence with *Choose another file*. [error: the poll failing twice shows "The check did not report back" + *Check again*]
4. **A rejected file** — the reason renders verbatim ("This file is not a weights archive") and the original file name, no stack trace, no path.
5. **The badge and the artefact case** — an accepted row carries *External weights*; an ONNX row carries *Artefact only* and its row says "This file can be stored and exported, not served." with Deploy absent.

- **States** — [empty: no installed family for this project type shows the dialog's list empty with the reason].

## Acceptance criteria
- [ ] The dialog asks for exactly the fields the server validates and disables the primary with a reason per missing field.
- [ ] Upload progress, checking, ready, rejected and artefact-only each render distinctly, and the rejection text is the server's own sentence.
- [ ] Only a manager sees the entry; a rejected file leaves nothing deployable.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no entry, no badge, no artefact copy.
