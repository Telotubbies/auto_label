## Problem
`versioning.phash_groups` (`versioning.py:59-92`) is called unconditionally by every version build and by
the duplicate pass in `insights_jobs.py:123-138`. It compares every hash with every other hash in Python:
300 images cost 70 ms for 44 850 pairs (measured 2026-11-17, 1.56 µs/pair), which extrapolates to **78 s
at 10 000 images and ~21 minutes at 40 000**. Today that 78 s hides inside a ~21-minute job that is
dominated by full-resolution decoding, so it is only ~6 % of the wall clock — **and that is exactly why
this card is conditional**: it only pays once the decode is fixed, which is a different (Python) card.

## Design
Split the work where the language boundary already is:

- Python keeps reading pixels and computing the hash (`cv2` decode + `imagehash.phash`, both already
  native) and passes the hashes down as `u64`;
- Rust does the pairing and the disjoint set in one call:
  ```rust
  // bit-for-bit the grouping today's union-find produces: union to the smaller root, path compression
  fn group_hashes(hashes: Vec<u64>, max_dist: u32) -> Vec<u64>;   // root hash per input index
  ```
  `(a ^ b).count_ones() <= max_dist`, `u64` XOR and a popcount per pair instead of two `imagehash`
  objects and a Python-level `-` operator.

`phash_groups` becomes: collect `(id, hash)` (same decode and error handling, unreadable files stay in
their own group), one `group_hashes` call, then the same `out` dict it returns today.
`insights_jobs` reuses it unchanged.

Known ceiling, written as a code comment: `shortcut: O(n²) pairs, fine to ~50k images; switch to a BK-tree
or LSH when a customer passes that` — the native version makes the O(n²) cheap, not correct forever.

## Notes for the implementer
**Do not fix the decode in this card.** `phash_groups` decodes every image at full resolution
(measured: 118 ms for a 12 MP JPEG, plus 9 ms for the hash), which is 8–64x cheaper at reduced scale —
that is a Python change with its own tests and its own parity question (the hashes change when the decode
scale changes), and mixing it in here would hide which change moved the number.

The fixture's 200 shared-sha JPEGs make this job look free. Measure with the fixture **and** with 10 000
distinct images, or the report will state a number the owner's real data will never reproduce.
