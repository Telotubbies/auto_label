## User story
As a labeler, I want the look-alikes of this image beside the canvas instead of in a grid that loses my place, so that the cheapest next label is one click.

## UX flow (LabelDesk words)
1. **Editor header → ⋯ menu → Find similar · not labelled yet / in the dataset** — the menu and the request are T-087/T-088's. This card changes where the result appears: the right thumbnail strip switches from the queue to the **Similar** results instead of navigating to the dataset grid. [loading: "Looking for look-alikes…" over the strip] [empty: "No similar images in this view" with a **Back to queue** button] [error: the ranking's error (unreadable image, missing model) renders in the strip with a retry, and the queue is one click away]
2. **Result rows** — up to 12 thumbnails in score order, each with its status chip and annotation count, and the score as a small percentage. Clicking one opens it in the editor with the same query state, so `→` continues the job afterwards.
3. **Ranked, not de-duplicated** — the strip header states "24 close matches · ranked" so nobody assumes the list is unique.
4. **Two scopes** — the two menu items map to the route's `scope` values; the dataset scope is disabled with a reason when the project has no approved images.
5. **Dismiss** — **Back to queue** restores today's strip; changing image or submitting for review also returns to the queue.
6. **No new inference** — the strip never calls an embedding model itself: it renders what T-088 returns, so the editor cannot become a second, divergent ranking.
