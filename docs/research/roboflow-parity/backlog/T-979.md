## User story
As a reviewer, I want to tag and annotate an experiment and undo an archive, so that finding "the q3
retrain" is a search, not an archaeology session.

## UX flow (LabelDesk words)
1. **Experiment page → Tags** — add/remove tags inline (`q3`, `retrain`, `customer-a`), each a chip with
   a remove cross; typing shows the tags already used in this project. [empty: "no tags yet" with the
   input focused] [loading: optimistic chip, one PATCH] [error: a tag over 64 chars or containing a
   comma is refused inline; a failed PATCH rolls the chip back with "could not save that tag"].
2. **Note** — a free-text note (≤ 4 000 chars) under the header, saved on blur; the run list shows the
   first line as a hint. [empty: "add a note — what is this experiment for?"] [loading: "saving …" in
   the corner] [error: over the limit — the counter turns red before submit].
3. **Archived** — for an archived experiment the page shows a banner "archived on 12 nov" and a Restore
   button; the list hides it behind a "show archived" toggle. [error: restoring one whose name was
   reused is a 409 — "an active experiment already uses this name; rename one first"].
4. **Search** — the list filters by tag and by name substring.

## Backend changes
- Models/schema: none new beyond T-978 — `tags` (JSON list) and `note` (Text) already exist.
- Routers: `routers/experiments.py` — `GET ""` gains `?tag=` and `?q=`; `PATCH /{id}` accepts `tags`
  (list of ≤ 20 trimmed strings, each 1–64 chars, no commas) and `note` (≤ 4 000); `POST /{id}/restore`
  returns 409 when an active experiment holds the name.
- Services/jobs: `app/services/experiments.py` — `normalise_tags(raw) -> list[str]` (trim, dedupe,
  reject), `used_tags(db, project) -> list[str]` for the suggestions, `restore(db, project, id)`.
- Permissions + workspace isolation: edits `project.train`; read `project.read`; project from
  `project_ctx` so a foreign id is 404.
- Secrets/safefetch: none.
- OpenAPI: yes.
