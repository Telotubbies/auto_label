## User story
As a new user who typed a brief, I want the assistant to turn it into a concrete next step, so that my first screen produces a project instead of a blinking cursor.

## UX flow (LabelDesk words)
1. **Assistant home** — the first message is the stored brief: `You said: “count hard hats on site”. Here is where I would start.` followed by one proposal row.
2. **Proposal row** — a `TaskRow`-shaped line: `Create the project “PPE Detection” · object detection · classes person, helmet, vest` with one primary `Create project` and one ghost `Change details`.
3. **No brief (all three questions skipped)** — the same screen shows `Nothing to go on yet — describe what you want to count, or pick a starting point below.` plus three starter rows: `Object detection on my photos`, `Sort images by label`, `Find defects against a good sample`. [empty: exactly this state]
4. **Unclear brief** — the planner asks one clarifying question instead of guessing: `Do you want boxes around each object, or one label for the whole image?`. [error: never a failure state — the planner always returns text]

## Backend changes
- Models/schema: none — this card is a pure module.
- Routers: none.
- Services/jobs: `services/assistant_planner.py` (new). `seed(setup: dict) -> str` renders the first message from `onboarding.QUESTIONS` keys; `reply(text: str, *, setup: dict | None, project_types: tuple[str, ...]) -> dict` returns `{"text": str, "actions": [{"kind": "create_project", "label": str, "args": {"name", "type", "annotation_group", "classes", "visibility", "license"}} | {"kind": "open_page", "label": str, "route": str}], "question": str | None}`. Keyword table maps briefs to a type: hat/helmet/vehicle/box/defect → `object-detection`; mask/outline/area → `instance-segmentation`; good/bad/whole image → `classification`; pose/joint/keypoint → `keypoint-detection`; nothing usable → no action plus a question.
- Permissions + workspace isolation: none — no DB access; project types come from `models.PROJECT_TYPES` so a new type cannot be suggested before the API accepts it.
- Secrets/safefetch: none. No model call, no API key: the planner is templates until an LLM provider is chosen (see INDEX owner decisions).
- OpenAPI: no.
