## User story
As an ML engineer, I want a deleted version to leave a gap in the numbering and a record of what it was, so that "v2" in a chat message never becomes a different model after someone cleans up.

## UX flow (LabelDesk words)
1. **Delete a version** — the row menu's *Delete model* removes the entry from the rail and the detail pane falls back to the newest remaining version. [empty: deleting the only version shows "No models yet — train a version to register the first one."] [loading: the row stays with a spinner until the delete returns] [error: "Some files could not be deleted; retry" keeps the row visible and unchanged, exactly as today]
2. **Numbering after a delete** — the group that had `v1 v2 v3` shows `v1 v3` and the next registration is `v4`; no screen ever offers `v2` again. [error: a refresh after the delete still hides the tombstone, even if the browser had the old list cached]
3. **Deployment history** — the alias that pointed at the deleted version is cleared and the history records `deleted` with who and when, so a caller of `GET …/deployments` sees an empty alias instead of a stale name. [empty: a project that never deployed has no history rows]
4. **Read-only caller** — a non-manager sees no delete action; a direct API call is the same 403 it is today.

## Backend changes
- Models/schema: append `"deleted": "FLOAT DEFAULT 0"` and `"deleted_by": "VARCHAR(32) DEFAULT ''"` to `TRAINED_MODELS` in `apps/backend/app/schema/training.py`; add both `Mapped` columns to `TrainedModel`.
- Routers: `DELETE {P}/models/{mid}` keeps its contract (`admin`, 409 on unerasable files) but writes the tombstone instead of `db.delete`: status `deleted`, `weights = ""`, `runtime_refs = {}`, `deleted = now()`, `deleted_by = c.uid`, and one `DeploymentEvent(action="deleted")` per alias that pointed at it before clearing `model_id`. `GET {P}/models` and `GET {P}/leaderboard` add `.where(TrainedModel.deleted == 0)`. `GET {P}/models/{mid}` on a tombstone is a 404.
- Services/jobs: `apps/backend/app/services/model_registry.py` gains `tombstone(db, model, user_id) -> None` and `events_for_delete(db, model, user_id) -> list[DeploymentEvent]`; it already owns `next_version`, which counts tombstones by construction.
- Permissions + workspace isolation: unchanged — `c.need("admin")`, `_model` resolution, and the 404 for another project's id.
- Secrets/safefetch: none.
- OpenAPI: yes — `python tools/export_openapi.py`, `npm run gen:api-types` (no new route, one changed response for a tombstone id).

## Acceptance criteria
- [ ] A deleted version disappears from the list and the detail route, and its number is never handed out again.
- [ ] The weights file is erased before the row is tombstoned; a failed erase leaves the row untouched and returns 409.
- [ ] Every alias that pointed at the deleted version is cleared and recorded as a `deleted` event with the actor.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
