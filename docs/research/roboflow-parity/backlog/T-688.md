## User story
As an automation engineer, I want to choose what the cell does when inference stops — hold, fire the reject output, or stop the line — and I want that choice to be configuration with the safe option on, so that a missed NG part is a stated policy and never a silent pass.

## UX flow (LabelDesk words)
1. **The policy is read with the outputs** — `GET …/ot-outputs/fault-policy` returns the project's mode and its timings, and a project that has never chosen reads the default `หยุดไลน์` with the sentence `ค่าเริ่มต้นคือหยุดไลน์ — ปลอดภัยกว่า` beside it. [empty: no outputs configured reads `ยังไม่มีเอาต์พุต — คำตัดสินอยู่ใน LabelDesk เท่านั้น`, and that sentence is a warning, not a comfort]
2. **`โหมดเมื่อโมเดลหยุด`** — one of `หยุดไลน์` (default), `ยิงรีเจกต์ค้างไว้`, `ไม่ทำอะไร (บันทึกไว้)`; `degraded_after_s` 5–300 (default 30) and `watchdog_ms` 500–10000 (default 2000) are editable. [error: `โหมดนี้ไม่ปลอดภัย — ต้องยืนยันจากเจ้าของไลน์` when `ไม่ทำอะไร` is saved without the acknowledgement flag]
3. **A fault** — when no stream on the project has been live for `degraded_after_s`, the actuator applies the mode: stop asserts the stop output and stops the heartbeat; reject holds the reject output asserted; hold writes the fault and does nothing to the wire. Every mode writes one `OtDelivery` row with `status: "fault"` and an audit entry, so a fault is never invisible. [error: `ตั้งค่าอุปกรณ์ไม่สำเร็จ` when the stop output itself is unreachable — the row says so and the banner in T-689 stays up]
4. **Recovery** — the outputs are released, the heartbeat resumes and one `ot.recovered` audit row closes the incident with its duration.
5. **A dry run** — `POST …/fault-policy/test` exercises the configured mode through the real driver without a line attached, and reports the round-trip and what it would have asserted. [loading: `กำลังทดสอบสัญญาณหยุด`]

## Backend changes
- Models/schema: `OtOutput` gains `role VARCHAR(12) DEFAULT 'reject'` (`reject|stop|heartbeat`) and `watchdog_ms INTEGER DEFAULT 2000` in a new `OT_OUTPUTS` block in `app/schema/streams.py`, registered in `schema.__init__.STEPS` after `stream_events`. The policy itself lives in `Project.settings["ot_fault_policy"]` (`{"model_down": "stop"|"reject"|"hold", "degraded_after_s": 30, "watchdog_ms": 2000, "acknowledged_unsafe": false}`).
- Routers: `app/routers/ot.py` (existing) gains `GET /fault-policy`, `PUT /fault-policy`, `POST /fault-policy/test`; `OutputIn`/`OutputPatch` gain `role` and `watchdog_ms`; `_out` returns them. 422 for an unknown mode or an out-of-band timing, 409 when `hold` is saved without `acknowledged_unsafe`, 404 while either flag is off.
- Services/jobs: `app/services/ot.py` gains `policy(db, project)`, `set_policy`, `degraded(db, project, now) -> bool` (true when every stream on the project has been non-`live` for `degraded_after_s`), `apply_fault(db, project, reason)` and `recover(db, project)`; `AsyncDispatcher` gains a supervisor tick every second that (a) pulses every `heartbeat` output at its `watchdog_ms`, (b) evaluates `degraded` once per `degraded_after_s`, (c) applies the mode once per incident, and (d) on `queue.Full` records `status: "fault"` with `detail: "actuator queue full"` before applying the mode — the drop today is silent and that is the defect this card closes.
- Permissions + workspace isolation: read `project.read`, write `project.settings`; every output, delivery and policy row is filtered by `workspace_id` **and** `project_id`, and a foreign output id is 404. Fault, recovery and every policy change write an `audit()` row.
- Secrets/safefetch: `services/ot.py::check_target` is the guard — an output host must resolve inside `config.OT_ALLOW_CIDR` (empty by default), the OT twin of `streams/allowlist.py`; the stop output is validated by the same check at save time and re-checked on every connection attempt.
- OpenAPI: yes — three routes and two output fields.

## Acceptance criteria
- [ ] A project carries a fault policy whose default is `หยุดไลน์`, with `degraded_after_s` and `watchdog_ms` inside their bands.
- [ ] When every stream has been down for `degraded_after_s`, the configured mode is applied once, a `fault` delivery row is written and an audit entry names the reason.
- [ ] A full actuator queue is a fault, never a silent drop, and recovery releases the outputs and resumes the heartbeat.
- [ ] Empty, loading and error states above all render — a project with no outputs says the verdicts stay in LabelDesk, in a warning tone.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the policy routes 404, the supervisor does not tick, and dispatch behaves exactly as today.

## Notes for the implementer
**Owner decision, not an engineer's:** the default is `stop` and it ships on. `reject` is available because some cells have no stop input, and `hold` exists only so a plant that knowingly accepts the risk can say so in writing — it requires `acknowledged_unsafe` and must never be the default. The heartbeat is the mechanism that makes "stop" work when the network itself dies: the PLC stops the line when our pulse disappears, so we do not need a working socket to stop a line that has lost us. Never ship a path where a firing is dropped without a `fault` row.
