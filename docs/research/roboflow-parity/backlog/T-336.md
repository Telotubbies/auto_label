## User story
As an ML engineer, I want request volume, latency and confidence by model with a drill-down to single requests, so that a regression shows up as a number and leads to the images behind it.

## UX flow (LabelDesk words)
1. **Deployments → a project → "Requests"** (`/:ws/deployments`, a tab on the existing project card) — a range picker defaulting to the last seven days, three totals with their change against the previous equal period (`requests`, `p95 latency`, `mean confidence`), then a per-model table. [empty: no traffic → "No requests in the last seven days. Requests appear here once a client calls the endpoint." with a link to the endpoint card] [loading: three skeleton tiles and five skeleton rows, same geometry] [error: "Requests could not load." with "Try again"]
2. **Per-model row** — model name, requests, mean confidence, p95 latency, detection count, and the share of refusals. Clicking a row filters the table below; a model with zero requests is absent rather than a row of dashes.
3. **Requests table** — one row per request: time, model, status chip, latency, predictions, billed, and a thumbnail only when the image was saved. Clicking opens the request detail (T-335's `GET /requests/{rid}`): the image when it exists, the meta, and "Image not saved for this request" otherwise.
4. **The privacy line** — one sentence above the table: "Request images are not saved unless this project opts in. Turning it on stores the frame beside each request and counts against storage." with a switch for `project.settings.request_images` (manager only; others see the setting's state).
5. **Range and export** — the range picker offers 24 h / 7 d / 30 d, and "Export CSV" downloads the filtered rows. `[error]` a range longer than the retention window says "This project keeps 14 days, so the range starts 14 days ago."

## Tests to write first
pytest — `apps/backend/tests/test_request_stats.py`:
- `test_totals_compare_against_the_previous_equal_period` — seven days of data against seven days before returns both changes, and the first period's counts are correct.
- `test_p95_is_nearest_rank_not_a_mean` — ten latencies 1..10 give p95 = 10 (nearest rank), proving the mean was not used.
- `test_a_model_with_no_traffic_is_absent` — only models with rows appear.
- `test_the_range_is_clamped_to_the_retention_window` — asking for 30 days on a 14-day project returns `lookback_days: 14` and rows from 14 days only.
- `test_the_csv_escapes_formula_prefixes` — a model name starting with `=` is written as text through `csvsafe`.
- `test_a_foreign_project_slug_is_404` — another workspace's slug is not readable.
node — `apps/frontend/tests/monitor-view.test.mjs`:
- `test_change_tone_reads_the_direction` — a latency rise is warning, a rise in requests is neutral, a confidence drop is danger.
- `test_the_range_label_names_the_clamp` — `rangeLabel(30, 14)` returns the sentence naming 14 days.
- `test_every_status_has_a_tone` — 200/402/404/413/422/429/503 each map to a chip tone and no status is untoned.

## Acceptance criteria
- [ ] Three totals with period-over-period change, a per-model table and a request table render for the selected range.
- [ ] A model with no traffic is absent; a request opens a detail that states when no image was saved.
- [ ] The privacy line and the opt-in switch match the server's setting, and a clamped range says so.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: with `task_335` off the tab is absent.

## Notes for the implementer
p95 is nearest-rank over the returned rows; do not add a percentile extension to SQLite. One chart-free screen is deliberate: three numbers and two tables answer "is it healthy" faster than a chart nobody reads.
