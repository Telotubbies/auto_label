## User story
As the design and quality leads, I want one audit of the train screen, the run view, the metric tiles and
Compare, so that the place where trust is won or lost is measured for comprehension, contrast and a clear
next step.

## UX flow (LabelDesk words)
1. **Train** (`/:ws/p/:project/train`) — three blocks, three presets, the sticky summary with time, credits
   and device, the one primary.
2. **Run view** — live loss, the stage stepper, the spend meter, the stop/cancel consequences.
3. **Models → Compare** (`/models`) — the chart as picker, the metric tiles, the matrix, "what to fix next".
4. **Runs** — the run list, states, median latency, the remedy for a failure.
5. **Not comparable** — a run trained on another version is marked, and the caveat is readable.

## Acceptance criteria
- [ ] Time, credits and device are visible before the start button; the estimate is never zero.
- [ ] The run view names the stages and what stopping does before the action.
- [ ] Compare's chart selects a run, and the tiles and matrix follow it without stale numbers.
- [ ] The matrix prints a value in every cell; colour is a second signal, never the only one.
- [ ] axe: 0 critical/serious; chart legends and axis labels meet 4.5:1; a table view exists.
- [ ] The 10 heuristics are scored per screen; no score < 3; the two worst are named.
- [ ] Findings are S1–S4 with evidence; each S1/S2 has a proposed fix card title.
- [ ] P2 walks the area; SUS-8 and any dead end are recorded.
- [ ] Empty, loading and error states: no version, no runs, a busy start, a failed run with a remedy,
      a metric with no test result.

## Notes for the implementer
The harness's fixed metrics are a fixture, not a product claim. Do not score the numbers; score whether a
person can tell what they mean and what to do next.
