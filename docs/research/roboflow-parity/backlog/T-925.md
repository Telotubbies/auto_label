## User story
As an ML engineer, I want the model page to say exactly which dataset version and which run produced this version, with its hyper-parameters, so that I can reproduce a good result without hunting through the lineage graph.

## UX flow (LabelDesk words)
1. **Model detail → Produced by** — a block above the metrics reads `dataset v4 · 1,284 images · 812 / 236 / 236`, `run #12 · started 14:02 · 38 min`, `yolo26n · detect`, and the frozen version's hash in monospace. [empty: a model imported outside the queue (T-288) shows "source run unknown" and keeps the dataset line] [loading: the dataset line renders from the model row, the split counts fill when the version resolves] [error: a deleted dataset version shows "dataset version deleted — the snapshot is gone" and no counts]
2. **Parameters** — a disclosure lists the params the job actually ran with (epochs, imgsz, batch, patience, seed) as read-only key/value rows; a copy button copies them as JSON. [empty: "This run recorded no parameters."]
3. **Open the chain** — *Show in lineage* navigates to Lineage with this model focused; *Open dataset version* goes to the frozen version page. [error: lineage unavailable ⇒ the link is disabled with "Lineage is unavailable right now" rather than a dead navigation]
4. **Reader without `project.models`** — the panel is absent from the masked payload, like weights and the evaluation today.

## Backend changes
- Models/schema: none — `TrainedModel.version_id`, `job_id`, `family`, `variant` (`apps/backend/app/models/training.py:39-50`), `Version.number`, `name`, `stats` (`apps/backend/app/models/project.py:194-203`) and `Job.params` (`apps/backend/app/models/training.py:25`) already carry everything.
- Routers: `GET {P}/models/{mid}/provenance` → `{dataset: {versionId, number, name, counts, hash}, run: {jobId, started, finished, minutes}, variant, family, task, params}`; **404** for a foreign or deleted model; the route is behind the same `project.models` gate as the detail route.
- Services/jobs: `apps/backend/app/services/model_provenance.py` (new) — `provenance(db, model) -> dict` reading `Version.stats`, `insights.version_manifest(version)` for the hash and `Job.params` for the hyper-parameters; `split_counts(stats) -> dict` tolerating an empty or partial `stats`.
- Permissions + workspace isolation: `c.perm("project.models")`; `_model` already 404s another project's id.
- Secrets/safefetch: none.
- OpenAPI: yes — one route; regenerate both files.

## Acceptance criteria
- [ ] The panel names the dataset version with split counts, the run with its duration, and the variant that ran.
- [ ] Parameters shown are the ones the job ran with, not the request's defaults.
- [ ] Both links work, and a deleted version or unavailable lineage degrades with a sentence rather than a blank panel.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
