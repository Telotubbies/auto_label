## User story
As the deployment operator and as a workspace admin, I want one runbook and one user page that explain
the flags, the token, the disk, the three common failures and how to undo the whole hub, so that the
feature can be handed over without a call.

## UX flow (LabelDesk words)
1. **Operator runbook** (`docs/INFERENCE-HUB.md`) — what the hub does, the four surfaces, the three
   locks (`task_inference`, `LD_INFERENCE_WORKSPACE`, `LD_ALLOW_ENGINE_INSTALL`), the worker flags
   (`--kinds`, `--engines-dir`, `--models-dir`), `HF_TOKEN`, `LD_MODELS_MAX_GB`, the disk layout, and a
   step-by-step first install with the exact commands.
2. **User page** (`docs/inference-hub.md`) — what each tab answers, what "estimate" means, how to read
   the fit verdict and the tok/s range, what a gated licence is, what the provisioned state means for
   auto-label.
3. **Troubleshooting** — driver mismatch, disk full, gated repo, host offline, checksum failed, stale
   plan; each with the symptom, the cause, the fix and the job id to quote.
4. **Rollback** — turn the flag off (routes 404, rail gone, no new job), unset
   `LD_ALLOW_ENGINE_INSTALL` (running jobs finish or cancel), and remove an installed asset with the
   product's own uninstall; the schema column stays.
5. **Release note** — one paragraph in the ledger: what shipped behind the flag, what was verified
   mocked, what still needs the real GPU.
