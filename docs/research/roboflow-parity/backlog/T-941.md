## User story
As a workspace admin, I want to point LabelDesk at an inference service we already run, so that the delivery screen tells the truth about where predictions come from instead of implying every model runs here.

## UX flow (LabelDesk words)
1. **Deploy & test → External targets** — "Add a target" asks for a name, a base URL, an auth header name and its secret, and a health path. [empty: "No external targets yet — models run on this server."] [loading: "Verifying the target…" with the save button held] [error: "The target did not answer: 403 from https://…" and the target saves as Unverified, never as active]
2. **Verify** — "Check now" probes `GET <base><health path>` from the worker with the stored secret and shows the status and round trip.
3. **Use it** — an alias can be bound to a target; the endpoint card then shows the external host, and the alias row says "Runs on <target>".
4. **Delete** — removing a target that an alias uses is refused with the alias names.

## Backend changes
- Models/schema: new table in `apps/backend/app/models/targets.py` (new), registered in `apps/backend/app/models/__init__.py` — `DeployTarget(id, workspace_id, name, base_url, auth_header, secret_id, health_path, state, checked, reason, created, updated)`; `CHECK` on `name` unique per workspace. One `CREATE TABLE` block appended to `apps/backend/app/schema/training.py`. One `ADD COLUMN` block, `deployment_aliases.target_id`.
- Routers: `apps/backend/app/routers/targets.py` (new) — `GET /api/ws/{ws}/targets`, `POST /api/ws/{ws}/targets` (201), `PATCH .../{id}`, `DELETE .../{id}` (409 while an alias uses it), `POST .../{id}/check`. All `ws_ctx` with `c.perm("workspace.update")` (the permission `apps/backend/app/routers/privacy.py:100` already uses for workspace-level mutations); the secret is write-only and never returned.
- Services/jobs: `apps/backend/app/services/targets.py` (new) — `add(db, ws, body) -> DeployTarget` (rejects a non-`https` URL unless `LD_ALLOW_HTTP_TARGETS=1`), `check(t, db) -> dict` (calls the stored URL through `services.safefetch.py` so private ranges and redirect-to-private are refused), `public(t) -> dict` (drops the secret). The secret is encrypted with `services/secretbox.py` and stored in `secret_id`, never in this table's plaintext.
- Permissions + workspace isolation: `ws_ctx`; every query filters `workspace_id`, so a foreign target id is 404, not 403.
- Secrets/safefetch: `services/secretbox.py` for the header value, `services/safefetch.py` for every outbound call, including the redirect chain.
- OpenAPI: yes — `python tools/export_openapi.py`, `npm run gen:api-types`.

## Tests to write first
pytest — `apps/backend/tests/test_targets.py`:
- `test_a_target_never_returns_its_secret` — `GET` and `POST` responses contain no secret value and no `secret_id`.
- `test_a_private_address_is_refused` — `http://127.0.0.1:8000` and `http://10.0.0.5` are rejected even with `LD_ALLOW_HTTP_TARGETS=1`.
- `test_a_redirect_to_a_private_address_is_refused` — the stub answers 302 to `169.254.169.254` and the check fails with a reason.
- `test_a_failed_check_saves_as_unverified` — a 403 leaves `state: "unverified"` and a reason naming the status.
- `test_delete_is_409_while_an_alias_uses_it` — the message names the alias.
- `test_a_foreign_target_is_404` — a target id from workspace B is not reachable from A.
- `test_flag_off_hides_every_route` — all five routes 404.

- `test_unverified_target_renders_its_reason` — `state: 'unverified'` renders the reason and keeps the row.
- `test_the_secret_field_is_write_only` — the form never pre-fills the secret from a loaded target.

## Acceptance criteria
- [ ] An admin can add, check and remove an external target; the secret is never readable back.
- [ ] A target on a private or link-local address, or redirecting to one, is refused with a reason.
- [ ] A failed check saves the target as Unverified, and an alias can be bound only to a verified one.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
