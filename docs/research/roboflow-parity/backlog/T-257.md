## User story
As a team lead, I want to shortlist the models worth keeping and share one across projects, so that a 40-candidate search ends in three names and a checkpoint my other project can start from.

## UX flow (LabelDesk words)
1. **Workspace → Models** — two tabs: *Project models* (every model of every project, as today) and *Shortlist* (starred only). A third filter chip row narrows by task and by project. [empty: *Shortlist* with nothing starred shows "Nothing starred yet — star a model to keep it one click away." and one link back to a project's Models page] [empty: *Project models* with no model at all keeps today's "No models trained yet."] [loading: five row skeletons] [error: "Models could not be loaded" + Retry]
2. **Star a row** — the star sits in the first column of every row; clicking it fills the star immediately (optimistic) and a failure reverts it with a toast naming the model.
3. **Share a model** — the row menu has *Share with this workspace*; the dialog states the consequence: "Other projects in this workspace can start a run from this checkpoint. The weights never leave the workspace." [loading: the item shows a spinner] [error: "Sharing failed" + reason, the row unchanged]
4. **Shared badge** — a shared row carries one small badge and sorts above unshared ones inside the same project.
5. **Project → Models** — the same star appears on the project run list (T-263 mounts it); starring there changes the workspace tab without a reload.

## Backend changes
- Models/schema: `trained_models.starred BOOLEAN DEFAULT FALSE`, `trained_models.shared BOOLEAN DEFAULT FALSE`. Append both keys to `TRAINED_MODELS` in `apps/backend/app/schema/training.py`.
- Routers: `POST {P}/models/{mid}/star` body `{starred: bool}` → `{id, starred}`; `POST {P}/models/{mid}/share` body `{shared: bool}` → `{id, shared}`. Both **404** for another workspace or project, **409** when the model is not `ready` ("only a finished model can be starred or shared"). `GET /api/ws/{ws}/models` gains query `starred=0|1`, `shared=0|1`, `task=`, `project=`, and returns `starred`, `shared`, `task`, `version`, `license`, `metrics` (lean) per row.
- Services/jobs: none. `routers/workspaces.py::ws_models` gains the four filters as SQL predicates.
- Permissions + workspace isolation: star/share = `c.perm("project.models")` on the owning project (the same grant the Models page needs); the workspace list keeps its per-project `visible_model` masking (`I1`) so a labeler still gets no weights and no eval payload. Cross-workspace star/share is 404.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] A model can be starred and unstarred from the workspace list without a reload, and the Shortlist tab reflects it.
- [ ] Sharing states its consequence and never moves weights outside the workspace.
- [ ] The workspace list keeps per-project permission masking for labelers.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ today's single table, no star column, both routes 404.

## Notes for the implementer
`shared` means "reusable inside this workspace", not "published to the internet" — the internet-public model page needs a licence/IP decision the owner has not made (see the part index). Do not add a `public` column now.
