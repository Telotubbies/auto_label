## User story
As a workspace member, I want the deployment row to say whether what it points at actually answers, so that "deployed" and "working" stop being the same word.

## UX flow (LabelDesk words)
1. **Deploy & test** — each alias row shows a state (Ready / Warm-up / Failed / Unknown), the last probe time and, when Failed, the reason. [empty: "Nothing deployed — pick a model to go live"] [loading: the state shows "Checking…" and keeps the last known value] [error: the state cell reads "Unknown — check failed" with a retry, and the rest of the row still renders]
2. **Switch** — after a switch the row shows Warm-up until one probe passes, then Ready; a failed switch keeps the previous model live and says so: "Switch failed — production still serves <model>".
3. **History** — the event list gains a "Checked" event only when a probe changes the state, so the log is not one row per minute.

## Acceptance criteria
- [ ] Each alias row shows Ready / Warm-up / Failed / Unknown with the time it was checked.
- [ ] A probe that changes the state appends exactly one event; repeated probes append none.
- [ ] After a failing probe the row still names the model that is live.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged — no flag here: with no probe the state renders "Unknown" and every existing row behaves as today.
