## User story
As a workspace owner, I want a billing surface that works the same whichever payment provider we sign with, so that
the product is not blocked while that decision is open.

## UX flow (LabelDesk words)
1. No screen in this card. It defines the four calls every later billing card uses and the one place a price may
   live. Nothing here charges anything: the default provider is a mock that answers deterministically.
2. `pack_ladder()` returns the configured pack rows, each with `add_credits`, `price_usd` and `price_per_credit`.
   Every money value today is `TBD`; a caller that needs a number gets `None` and renders `Not set`, never a guess.
3. `[empty]` an unconfigured ladder returns rows with `price_usd: None` — the screen says pricing is not set.
4. `[error]` a provider that raises is a `BillingError` with a stable `code` (`provider_unavailable`,
   `not_configured`, `declined`), so a screen never parses a provider string.

## Backend changes
- Models/schema: `app/models/billing.py` (new) — `BillingAccount(workspace_id PK FK CASCADE, provider VARCHAR(24)
  default "mock", external_customer_id VARCHAR(120) null, plan_code VARCHAR(32) null, cycle VARCHAR(8) default
  "monthly", cancels_at FLOAT null, flex_enabled BOOLEAN default false, spend_cap_usd FLOAT null,
  prepaid_credits FLOAT default 0, updated FLOAT)`; `BillingInvoice(id, workspace_id FK, number VARCHAR(64),
  amount_usd FLOAT, status VARCHAR(16), period_start FLOAT, period_end FLOAT, issued FLOAT, hosted_url VARCHAR(1024))`;
  `BillingEvent(id, workspace_id FK, provider_event_id VARCHAR(120) UNIQUE, kind VARCHAR(32), payload JSON, created)`.
  Registered in `models/__init__.py` (`DOMAIN_MODULES` + re-exports); tables are created by metadata on a fresh
  database and are absent-but-unused on an old one until the flag is on.
- Routers: none in this card.
- Services/jobs: `app/services/billing.py` (new) — 
  `class BillingProvider(Protocol)` with `create_checkout(account, pack_code, success_url, cancel_url) -> Checkout`,
  `cancel(account, at_period_end: bool) -> dict`, `webhook_verify(body: bytes, headers: Mapping[str,str]) -> Event`,
  `invoice_list(account, limit: int) -> list[Invoice]`;
  `class MockProvider` implementing all four with no network call, a deterministic `checkout_id`
  (`mock_<sha1(ws_id+pack_code)[:12]>`), `webhook_verify` checking a fixed test header, and `invoice_list` reading
  `BillingInvoice` rows;
  `provider() -> BillingProvider` (returns `MockProvider`), `account(db, ws) -> BillingAccount` (get-or-create),
  `class BillingError(Exception)` with `code`.
- Services/jobs (pricing): `app/pricing.py` (new) — `PRICE_TBD: None`, `@dataclass Pack(code, add_credits, price_usd,
  price_per_credit)`, `PACK_LADDER: tuple[Pack, ...]` with **every** money field `None` and a comment naming the owner
  decision; `ADDONS = {"teams": Addon(code="teams", price_usd=None, non_admin_seat_cap=None)}`;
  `pack_ladder()`, `addon(code)`, `catalogue() -> dict` (the one payload the screen reads).
- Permissions + workspace isolation: every function takes the workspace and never queries another; the provider is a
  process-level singleton with no workspace state.
- Secrets/safefetch: no provider secret is stored — `webhook_verify` reads a header against a value from
  `config` if one is ever configured; today the mock ignores it. No network call in any path.
- OpenAPI: no (no route).

## Tests to write first
pytest — `apps/backend/tests/test_billing_provider.py`:
- `test_mock_checkout_is_deterministic_and_offline` — same workspace + pack → the same `checkout_id` twice, and no socket call (monkeypatch `socket.socket` to raise).
- `test_mock_webhook_verify_rejects_a_bad_signature` — wrong header → `BillingError(code="declined")`.
- `test_ladder_has_no_invented_price` — every pack's `price_usd` and `price_per_credit` is `None`; `catalogue()` has no number.
- `test_account_is_created_once` — two calls → one `BillingAccount` row with `provider="mock"`.
- `test_billing_error_codes_are_stable` — the three codes exist and nothing raises a provider-specific type.
- `test_flag_off_means_no_account_row` — every service entry point raises/returns without writing.
- `test_foreign_workspace_account_is_never_returned` — account lookup is by workspace id only.

## Acceptance criteria
- [ ] One protocol with four calls is the only way the app talks to a payment provider.
- [ ] The default provider is a mock: no network, no charge, deterministic ids, offline tests.
- [ ] Every price and ladder value is configuration with an explicit `None`/`TBD`, defined in one module.
- [ ] Flag off ⇒ no billing account is created and no provider is constructed.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] A provider failure surfaces as a `BillingError` code, never a raw provider payload.

## Notes for the implementer
**Three owner decisions are open and must not be invented:** (1) the payment provider, (2) the plan ladder and prices,
(3) the self-host licence terms. Carry all three into `INDEX.md`; this card keeps them as `None`. The protocol is four
methods, not a class hierarchy — a second provider implements the same four and changes nothing else.
