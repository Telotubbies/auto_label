## User story
As an admin, I want to set a folder's grants and manage named auth groups over the API, so that the two screens
in T-387 have one contract each.

## UX flow (LabelDesk words)

*Screen this contract serves:* the folder **Access** dialog on the workspace Home tree (T-096) and the
**Auth groups** tab in Settings (T-387). States the screens must show: a folder with no grants → "Everyone in the
workspace can see this folder" and one `Restrict` action; a restricted folder with no rows → "Only the people
listed can see it" plus the first-grant form; a duplicate subject → inline error on that row, the rest of the
form keeps its values; a group with a duplicate name → the 409 sentence under the name field.

1. `GET /api/ws/{ws}/folders/{fid}/permissions` → `{folder, grants: [{subject_type, subject_id, subject_label, access}], subjects: {roles: [...], groups: [...], members: [...]}, restricted: bool}`.
   A folder with no rows answers `grants: []` and `restricted: false`.
2. `PUT /api/ws/{ws}/folders/{fid}/permissions` `{grants: [{subject_type, subject_id, access}]}` replaces the set
   and answers the same shape; `400` names the offending subject; `409` when the same subject appears twice.
3. `GET/POST /api/ws/{ws}/auth-groups`, `PATCH/DELETE /api/ws/{ws}/auth-groups/{gid}` — name, `idp_groups: [str]`,
   and `members: [{user_id, name, email, source}]`; `409` for a duplicate name; `400` for a name outside 2–80 chars.
4. `POST /api/ws/{ws}/auth-groups/{gid}/members` `{user_id}` adds a `manual` membership; `DELETE` removes it;
   `sso` rows are read-only here (`409 Managed by your identity provider.`).
5. `[empty]` no groups → `{groups: []}`; `[error]` every write is audited as `folder.permissions` or
   `authgroup.create|update|delete`.

## Backend changes
- Models/schema: none (T-384).
- Routers: new module `app/routers/folder_access.py` — `router = APIRouter(prefix="/api/ws/{ws}", tags=["folder access"])`
  with the seven routes above; register it in `routers/__init__.py` after `rbac.router`.
- Services/jobs: `folder_access.set_grants` and `validate_grant` (T-384) plus
  `resolve_subject_labels(db, ws, grants) -> list[dict]` so the UI never needs a second lookup.
- Permissions + workspace isolation: reads `workspace.read`; every write `workspace.update` (owner/admin) —
  folder grants are a workspace-level decision; a folder or group id from another workspace is a 404, never a
  403 that confirms it exists.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] Grants can be read and replaced for one folder, with labels resolved in the same response.
- [ ] Auth groups can be created, renamed, deleted and have manual members added or removed.
- [ ] Identity-provider memberships are visible and cannot be edited by hand.
- [ ] Empty, loading and error states above all render (empty grant set, empty group list, named 400/409).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no route exists and no grant is enforced.

## Notes for the implementer
`PUT` replaces the whole set: the UI sends what it wants to keep, so there is no per-row delete route. Audit
target is the folder name (or group name), never the folder id.
