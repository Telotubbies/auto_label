## User story
As a quality lead, I want to see how often a judge agrees with the people who reviewed the same answers, so
that I know whether an automatic verdict is worth acting on.

## UX flow (LabelDesk words)
1. **Evaluation → Judges → a judge → Agreement** — the headline figure and its sample: "Agrees with reviewers
   on 84% of 120 reviewed answers", with a two-by-two count (judge pass / reviewer pass). [empty: "No reviewed
   answers yet — review 20 to see agreement" and a link to the review queue]
2. **Read the disagreements** — a list of rows where the two differ, each with the answer, the judge's reason
   and the reviewer's reason, and *Which was right?* with two buttons.
3. **Verdicting a disagreement** — the choice is stored as a second reviewer verdict and the figure recomputes;
   the row states "3 of 5 disagreements were the judge's mistake". [error: "the verdict was not saved" with the
   row unchanged]
4. **Below the bar** — under 70% the judge is badged *Not calibrated* everywhere it is listed, and a sentence
   explains: "this judge is not a substitute for review yet".
5. **After a new judge version** — the table shows one row per version, so a criteria change can be judged.

## Backend changes
- Models/schema: none new — reads T-960's `Assessment` and the existing `SuspectFeedback`
  (`apps/backend/app/models/project.py`) joined on `image_id`; a disagreement verdict writes one more
  `SuspectFeedback` row with the existing schema.
- Routers: `GET {P}/insights/judge-agreement?judge=&days=` → `{rows: [{judge, version, reviewed, agreed,
  rate, matrix: {judge_pass_reviewer_pass, judge_pass_reviewer_fail, judge_fail_reviewer_pass,
  judge_fail_reviewer_fail}, disagreements: [{trace_id, image_id, judge_reason, reviewer_reason}]}]}`;
  `POST {P}/insights/judge-agreement/{trace_id}/verdict` body `{side: "judge"|"reviewer"}` → the recomputed
  row. 400 for an unknown side or a trace with no disagreement; 404 for a foreign trace.
- Services/jobs: `apps/backend/app/services/judge_agreement.py` (new) — `agreement(db, project, judge, days)`
  pairing only rows where both an assessment and a reviewer verdict exist for the same image (never inferring
  a reviewer verdict from a missing row), and `resolve(db, trace, side, user)` writing the extra verdict
  through `services/suspects.py`'s existing write path. Read-only otherwise.
- Permissions + workspace isolation: `project.review` throughout; a foreign project or trace is a 404.
- Secrets/safefetch: none. Dependency: none added (no `mlflow-skinny`), so no
  `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] Agreement is computed only over rows that have both a judge verdict and a reviewer verdict.
- [ ] A disagreement can be resolved by a reviewer, and the figure recomputes from the stored verdicts.
- [ ] Under 20 reviews the surface says "too few reviews" instead of showing a misleading rate.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: none. The docs' alignment *re-optimises* the judge prompt against human feedback; this card measures
agreement and records which side was right, which is what a reviewer can act on. Automated re-alignment is out
of scope and the card says so.
Pair on image id, not trace id: a re-run creates a new trace for the same image, and the reviewer's verdict
belongs to the image.
