## User story
As a workspace admin, I want to see how large each model and export is, so that I know what a disk limit will hit before it hits.

## UX flow (LabelDesk words)
1. **Model detail → Size** — weights size, the size of each built export, and the total for this model. [empty: "Not measured yet" while the model is still training] [loading: one skeleton line] [error: "Weights file is missing on disk" plus the storage path the operator must restore]
2. **Models list** — the card's meta line gains the weights size, so the biggest model is visible without opening it.
3. **Warning** — a single artefact over 2 GB renders an inline warning row: "This export is over 2 GB. Some targets cannot load a single file this large — see the export notes."
4. **Delete** — the confirmation says how much will be freed.

## Backend changes
- Models/schema: none. Size is measured on read.
- Routers: `GET {P}/models/{mid}` gains `size: {"weights", "exports": [{"preset", "bytes", "parts", "url"}], "total", "missing": bool}` on the dict built by `model_out` (`apps/backend/app/routers/training.py:90`). `project_ctx`, `project.read`.
- Services/jobs: `apps/backend/app/services/model_size.py` (new) — `measure(m: TrainedModel) -> dict` (one `stat` per file, `parts` counts sibling files sharing a stem so a split ONNX graph counts as one artefact), `human(n: int) -> str`, `LARGE = 2 * 1024**3`.
- Permissions + workspace isolation: `project_ctx`; `measure` only stats paths derived from the model row, never from the request.
- Secrets/safefetch: none.
- OpenAPI: yes — `python tools/export_openapi.py`, `npm run gen:api-types`.

## Tests to write first
pytest — `apps/backend/tests/test_model_size.py`:
- `test_measure_sums_the_exports` — two export files of 10 and 20 bytes report `total` 30.
- `test_a_split_onnx_graph_counts_as_one_artefact` — `model.onnx` plus `model.onnx.data` report one export with two parts and the summed bytes.

## Acceptance criteria
- [ ] Model detail shows weights bytes, per-export bytes and the total, human readable.
- [ ] A missing weights file reports the path instead of a 500.
- [ ] A single artefact over 2 GB renders one warning row naming the limit.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged — no flag here: the fields are additive and the panel renders nothing on its own.

## Notes for the implementer
Overlap: 5-F5.31 → T-288, T-289. Those validate an upload's format and magic; this only measures. Do not add a size limit to any existing route — the warning is informational, and T-288 owns rejection.
`parts` must use `Path.stem` grouping, not a glob by extension: an ONNX graph with external data is two files with different suffixes.
