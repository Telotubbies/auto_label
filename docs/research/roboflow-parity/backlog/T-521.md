## User story
As a reviewer who followed a link to Streams or Review & Quality, I want to be told that the surface is
not enabled in this workspace, so that I stop looking for a button that will never appear.

## UX flow (LabelDesk words)
1. **Any flag-gated project route** (`/:ws/:project/streams`, `/qa`, `/videos`, `/search`, `/events`,
   `/workflows`, `/suspects`, `/lineage`, `/dashboards`, `/stream-analytics`, `/anomaly`) with the flag
   off — the page renders in place of the surface, not a redirect. Heading: the surface's own nav label.
   Body: `Streams is not enabled in this workspace.` Then `An administrator turns it on in Workspace
   settings.` Two actions: `Back to Dataset` and, for an admin, `Open workspace settings`.
2. **Workspace route** (`/:ws/audit`, `/:ws/admin`) with the role missing — unchanged: a redirect is right
   when the surface is not the caller's, wrong when it simply is not switched on.
3. **Flag on** — the surface renders exactly as today. [empty/loading/error: the surface's own states]

## Notes for the implementer
Options considered:
1. **A notice in place of the redirect (recommended).** One component, one pure decision. The URL keeps the
   user's intent, so the same link works once the flag is on.
2. **Keep the redirect, add a toast on arrival.** Rejected: a toast on a page the user did not ask for
   reads as a glitch, and it disappears before it is read.
3. **Hide the deep link entirely (404 page).** Rejected: the user did arrive from a real link, often from a
   teammate, so the answer is "not switched on here", not "not found".

The label comes from the same nav registry the sidebar uses, so the notice and the rail cannot disagree.
