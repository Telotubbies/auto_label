## User story
As a solo project manager, I want to switch the review step off, so that finished images land in the dataset without an approval I would give myself.

## UX flow (LabelDesk words)
1. **Project settings → General → Workflow card** — a **Review step** switch, on by default, with the line "Reviewers approve each image before it enters the dataset. Turn this off for solo work." Only a project manager sees it; everyone else sees the switch disabled with "Ask a project manager". [loading: the project is loading → the card is a skeleton]
2. **Turning it off with work in review** — a confirm names the count: "12 images are waiting for review. Turn review off and send them back to Annotating?" with Cancel / Turn off. Confirm disables review, moves those images to `annotating`, and the board's In review lane disappears. [error: the move fails → review stays on and the switch snaps back with the reason]
3. **Turning it off on an empty review lane** — no confirm; the lane disappears immediately.
4. **With review off** — the Annotate board has three lanes (To label, In progress, Approved); the editor's **Submit for review** becomes **Add to dataset** for the image's assignee (a labeler may now finish their own assigned image), and a rejected image can no longer exist. The review keys `a`/`r` are hidden from the cheat sheet with a note.
5. **Turning it back on** — the Review lane returns, empty; nothing moves retroactively. Review permission holders see the lane and the approve/reject controls again.
6. **Server enforcement** — with review off, setting an image to `review` is refused (400), and a labeler setting `done` on their own assigned image is allowed; a labeler setting `done` on someone else's image is still 403.

## Backend changes
- Models/schema: none — `Project.settings` JSON (`models/project.py:32`).
- Routers: `POST /api/ws/{ws}/projects/{project}/review-mode` `{enabled: bool, move_review_back: bool = false}` → `{review_mode, moved}`; requires `c.perm("project.settings")`; `409` when disabling with review images and `move_review_back` false, carrying the count; `PATCH /api/images/{image_id}` refuses `status: "review"` when review is off (400), and `status: "done"` from a labeler is allowed only on their own assigned image while review is off.
- Services/jobs: `services/review_mode.py` (new) — `is_on(project)`, `set_mode(db, project, enabled, move_back)` moving review images to `annotating` and writing one audit row `project.review_mode`.
- Permissions + workspace isolation: `project.settings` (manager) rather than the workspace-admin gate on `patch_project`; image routes keep `image_ctx`, so cross-workspace ids are 404.
- Secrets/safefetch: none.
- OpenAPI: yes — one route.

## Acceptance criteria
- [ ] A project manager can switch the review step off; with images in review the confirm names the count and moves them back to Annotating.
- [ ] With review off the board shows three lanes, the editor offers Add to dataset, and the server refuses new `review` statuses.
- [ ] A labeler can finish only their own assigned image while review is off, and nothing else.
- [ ] Turning it back on restores the lane empty and moves nothing retroactively.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the card is absent, the board keeps four lanes, and every review rule is as today.
- [ ] Keyboard-only path: Project settings → Tab to the switch → Space → confirm → Enter.

## Notes for the implementer
`review_mode` is stored in `Project.settings` and read through one helper — do not scatter `settings.get("review_mode", True)` across routers, or one endpoint will forget the default. The move-back is `status` only; annotations and assignees are untouched.
