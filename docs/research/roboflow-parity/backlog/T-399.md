## User story
As a compliance lead, I want to filter by who did it, what they did and which resource, and to see the before and
after values, so that "who deleted that version" needs no engineer.

## UX flow (LabelDesk words)
1. `GET /api/ws/{ws}/audit` gains `actor_type` (`user|api|system`), `resource` (a target slug/name match, exact
   prefix or free text), `action` (a list, comma-separated), `folder` (projects inside a folder) and `cursor`
   (opaque, replaces `offset` for the screen).
2. Each row gains `actor: {type, id, name}`, `resource_type` (derived from the action's first token, e.g.
   `version`, `member`, `apikey`) and `changes: [{field, before, after}]` built from `Audit.meta` when the writer
   recorded both sides, else `[]`.
3. `[empty]` `{rows: [], next: null}` — the screen renders "no entries match".
4. `[error]` a malformed cursor is a `400` with `Bad cursor.` — never a silent first page.
5. The route keeps its current behaviour when the flag is off (offset paging, no new fields).

## Backend changes
- Models/schema: none — `Audit(workspace_id, user_id, action, target, meta, created)` covers it. `resource_type`
  and `changes` are derived on read; no new column, no backfill.
- Routers: `routers/workspaces.py` `audit_log()` gains the four filters and cursor paging. The cursor is
  `created|id` base64 and pages on `(< created) OR (< created AND id < id)` so a busy second cannot repeat a row.
  `routers/audit.py` export query mirrors the same filters (one shared helper).
- Services/jobs: `app/services/audit_query.py` (new) — `filters()` (SQL builders), `encode_cursor/decode_cursor`,
  `resource_type(action)`, `changes(meta)` (`{"from": x, "to": y}` or `{"before": …, "after": …}` → pairs).
- Permissions + workspace isolation: `workspace.audit`; every statement is rooted at `Audit.workspace_id == c.ws.id`.
- Secrets/safefetch: none — but the detail payload must never echo a stored secret; `changes()` drops any value
  whose key matches `password|secret|token|key_hash`.
- OpenAPI: yes.

## Frontend changes

## Acceptance criteria
- [ ] Actor type, action list, resource and folder filters are additive and combinable.
- [ ] A row carries actor, derived resource type and before/after pairs when the writer recorded them.
- [ ] Cursor paging never repeats or skips a row on a busy second.
- [ ] Empty, loading and error states above all render (no match, bad cursor).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the previous response shape and offset paging.

## Notes for the implementer
Derive `resource_type` from the action prefix (`apikey.create` → `apikey`); do not add a column that every future
writer must remember. The secret-key denylist lives in `changes()` only.
