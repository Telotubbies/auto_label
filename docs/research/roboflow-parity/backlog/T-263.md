## User story
As an ML engineer, I want the run list to tell "stopped early, weights kept" apart from "failed", show one latency number beside the score, and name the fix for a failure, so that I know whether to deploy, retry or change a setting.

## UX flow (LabelDesk words)
1. **Models → run list (left column)** — each row: name, version, headline metric, median latency, state pill, age. [empty: no model at all ⇒ today's "No models yet." with *Train your first model*] [empty filtered: "No runs match these filters" + *Clear filters*] [loading: six row skeletons at final height] [error: "Runs could not be loaded" + Retry]
2. **State pills** — *Queued*, *Training* (with epoch progress), *Ready*, *Stopped early* (amber, tooltip "the credit cap or a stop ended this run; the best weights were kept"), *Failed* (red), *Cancelled* (grey, "nothing was kept"). A stopped-early row is selectable and deployable exactly like a ready one.
3. **Filter and sort** — one filter chip row: status, version, task; one sort control: newest / best metric / fastest. The choice lives in the URL (`?sort=metric&status=ready`) so a refresh keeps it.
4. **A failed run** — the detail card reads "Training failed — <what>", then the remedy line: "Reduce the batch or the image size and start again." plus *Why* opening the stage that failed. [error: a failure with no known cause prints the generic sentence and the job id for support, never raw worker text]
5. **Latency** — the row and the metric header both read "18.4 ms median per image" with the definition in a tooltip; when the test images are at least twice the model's input in pixels, one line is added: "Test images are 1280 px; the model sees 640 px — capture at 640 for comparable speed."

## Backend changes
- Models/schema: none — `TrainedModel.metrics.stop_reason` (T-265) and `metrics.eval.latency_ms` already exist.
- Routers: `GET {P}/models` rows gain `state` (`ready|stopped|failed|cancelled|queued|training`), `remedy: {code, message, remedy} | null`, `latency_ms` (median), `recommend_capture_resolution: bool`. `GET {P}/leaderboard` sorts by the same state and reports `latency_ms` as the median.
- Services/jobs: new `apps/backend/app/services/train_failure.py` — `remedy_for(error_text, *, oom=False, stalled=False, quota=False) -> dict` with the table: out-of-memory ("Reduce the batch or the image size and start again."), stalled worker ("The GPU worker stopped reporting. Start the run again; if it repeats, check the worker."), quota ("The workspace ran out of GPU time. Raise the plan or wait for the monthly reset."), dataset ("The dataset could not be read. Regenerate the version."), unknown (generic + job id). `handlers/training.py` writes `job.result.remedy` in its `except` branch (one line next to `safe_error`). `services/evaluate.py` records `latency_ms` as the **median** and adds `latency_p95_ms`; `_capture_hint` compares `test image pixels ≥ 2 × imgsz²`.
- Permissions + workspace isolation: unchanged (`c.perm("project.infer")` list masking stays: a labeler still gets `metrics == {}` and therefore no latency).
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate both files.

## Tests to write first
pytest — `apps/backend/tests/test_train_run_states.py`:
- `test_stop_reason_renders_as_stopped_early` — a ready model with `metrics.stop_reason == "cap"` → `state == "stopped"`, not `ready`.
- `test_cancelled_and_failed_stay_distinct` — a `cancelled` row → `state == "cancelled"`; a `failed` row → `"failed"`; neither reads as stopped.
- `test_oom_failure_gets_the_batch_remedy` — a job whose error names `OutOfMemoryError` → `remedy.code == "oom"` and the sentence names batch and image size.
- `test_unknown_failure_gets_the_generic_remedy_and_no_internal_text` — error "CUDA error at /home/worker/x.py" → generic message, no path in the payload.
- `test_latency_is_the_median_not_the_mean` — stored latencies `[10, 10, 10, 100]` → `latency_ms == 10.0`, `latency_p95_ms` present.
- `test_capture_hint_appears_only_at_twice_the_input` — 1280 px test images at imgsz 640 → hint true; 800 px → false.
- `test_labeler_list_has_no_latency_or_remedy` — a labeler's row → `latency_ms is None`, `remedy is None`.
- `test_flag_off_keeps_todays_payload` — with `task_250` off, `state` is present but the list renders the old shape (the added keys do not break the old client).
node — `apps/frontend/tests/run-states.test.mjs`:
- `test_five_states_and_their_tones` — `runState` returns the five labels with distinct tones; a stopped row carries the "weights kept" note.
- `test_sort_by_metric_and_speed` — nulls sort last in both directions.
- `test_filter_status_and_version_compose` — two filters → intersection; an empty result is the no-match copy, not the empty copy.
- `test_failure_copy_never_shows_raw_text` — `failureCopy({code:'unknown'})` returns the generic sentence.

## Acceptance criteria
- [ ] A stopped-early run is visibly different from a failed one and is still deployable.
- [ ] Every failure card names a remedy; no raw worker path or URL reaches the UI.
- [ ] One median latency figure appears on the row and in the metric header, with its definition.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ today's left column and status pill, no filters, no latency, no remedy card.

## Notes for the implementer
`state` is derived, never stored: `metrics.stop_reason == "cap"` (or `"user_stop"` with weights) → `stopped`; a `ready` row without it → `ready`. Keep `latency_ms` as the median for back-compat and add `latency_p95_ms` beside it.
