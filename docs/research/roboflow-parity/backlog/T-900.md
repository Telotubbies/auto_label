## User story
As the reviewer of any tracking PR, I want the shipped run record — per-epoch history, metric grouping, the
best-epoch headline, the run list order and the six-run overlay cap — pinned by cheap tests so that a later card
cannot change what a run means without saying so.

## UX flow (LabelDesk words)
1. **Models** — the run list renders newest first with status, task, version and metric columns.
   [empty: `No models yet.` with a *Train your first model* action] [loading: skeleton rows keep the table
   height] [error: retry card, never an empty table]
2. **Insights → Training** (`/:ws/:project/model-insights?tab=training`) — run chips for every run that has a
   history; pick 1–6; three chart groups appear in the fixed order Quality metrics, Loss, Other metrics.
   [empty: `No training history yet`] [loading: two chart skeletons] [error: `Training curves could not be
   loaded` + retry]
3. **A run with epochs but no numeric metric** — the tab renders `No metrics logged` instead of an empty chart.
4. **Insights → Compare** — a mix of dataset versions or tasks is refused with the reason, not a broken chart.

pytest — `apps/backend/tests/test_mlruns_guard.py` (new):
- `test_history_is_rewritten_per_epoch_and_never_duplicated` — seed a model, run the handler's epoch callback
  twice for epoch 3 (`handlers/training.py:90-96`) → `TrainedModel.history` holds one row for epoch 3, in epoch
  order, and the job's `progress` equals `ep / total * 100`. (`1.1`, `1.3`)
- `test_training_payload_returns_every_run_with_a_history_newest_first` — three models, one with `history=[]` →
  the payload lists two, newest first, each with `epochs == len(history)`. (`1.1`)
- `test_metric_keys_group_quality_loss_then_other` — a history with `metrics/mAP50(B)`, `train/loss`,
  `lr/pg0` → groups are exactly `quality, loss, other` in that order and the labels drop `(B)`/`(M)`
  (`services/insights.py:672-690`). (`1.3`)
- `test_headline_metrics_come_from_the_best_epoch` — history where epoch 4 has the top `mAP50-95` → `map50`,
  `map5095`, `precision`, `recall` are epoch 4's values (`services/ml.py:14-26`). (`1.3`)
- `test_the_caps_are_eight_selected_fifty_listed_and_four_compared` — request 9 run ids →
  `len(runs) == 8` (`MAX_SELECTED_RUNS`), a 51-run project lists 50 (`MAX_TRAINING_RUNS`), and comparing five
  raises `compare at most 4 models at a time` (`services/insights.py:470-474`, `:698-699`). (`1.1`, `1.16`)
- `test_a_run_without_history_is_absent_from_training_but_present_in_models` — one finished model, one queued →
  `GET /models` returns both, `GET /insights/training` returns the finished one only. (`1.1`)

node — `apps/frontend/tests/mlruns-guard.test.mjs` (new):
- `test_training_groups_keep_their_order_and_copy` — read `features/insights/TrainingTab.tsx` and assert the
  `GROUPS` ids are `['quality','loss','other']` and the three titles ship unchanged. (`1.3`)
- `test_the_overlay_cap_is_six` — `MAX_RUNS = 6` and the disabled-at-limit title names the cap. (`1.1`)
- `test_the_three_insight_tabs_are_training_evaluation_compare` — read `features/insights/Insights.tsx` and
  assert the tab ids and that `?tab=` selects them. (`1.1`)

## Notes for the implementer
Overlap: `5-F5.16` → T-005 (that guard pins the training UI; this one pins the *record* the UI reads), `5-F5.1` → T-263.
The handler callback is a closure inside `run_train` — extract nothing; call it through a small
`_epoch_callback(model_id, job_id)` seam only if the test cannot reach it, and say so in the PR.
`MAX_TRAINING_RUNS`/`MAX_SELECTED_RUNS` values are the shipped contract; if a later card needs a different cap it
changes the guard in the same PR.
