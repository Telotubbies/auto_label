## User story
As a buyer with PII in my footage, I want to stop private-project data feeding vendor models, with the limits of
that promise stated, so that I can answer a procurement questionnaire honestly.

## UX flow (LabelDesk words)
1. **Settings → Workspace → `Allow vendor training` → off** — a confirm dialog: `Turn off vendor training?` with
   three sentences, one per question a buyer asks:
   `It applies to private projects only.` / `It does not publish anything and does not change who can see a
   project.` / `Data already collected is not deleted by this switch — ask support for an erasure request.`
   Buttons `Keep it on` / `Turn off`.
2. **After the change** the row reads `Off — private-project data is excluded from vendor model training.` and the
   card links `What this covers →` to the trust page (T-446).
3. **Locked** — plan/policy/region lock renders exactly as T-403: dimmed, lock, reason, `Request access` for a
   member without `workspace.update`.
4. `[error]` the switch returns to its previous value and the toast quotes the server (`This setting is locked by
   your plan or region.`).
5. **Existing public projects** — the note under the row states `Public projects are already public; this switch is
   about training, not visibility.`

## Backend changes
- Models/schema: none — `Workspace.allow_vendor_training` ships in T-402.
- Routers: `PATCH /api/ws/{ws}/policies` already accepts the field; this card adds `GET /api/ws/{ws}/policies/effects`
  → `{vendor_training: bool, public_projects: bool, private_projects: int, public_projects_count: int}` so the
  dialog can state how much data the change covers.
- Services/jobs: `services/workspace_policy.py` — `effects(db, ws) -> dict` (two counts, workspace-scoped); the
  training path reads `allows(db, ws, "allow_vendor_training")` and skips vendor-model use when false — one line in
  `services/ml.py` where a vendor model is selected.
- Permissions + workspace isolation: `workspace.update` for the read of effects; the training check uses `c.ws`.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria

- [ ] The training path honours the switch; visibility and stored data are untouched.
- [ ] The settled row states the current value and links to the trust page.
- [ ] Empty, loading and error states above all render.

## Notes for the implementer
The three sentences are the deliverable: future collection, already-collected data, visibility. Do not promise
deletion on this switch — that is the erasure path in area 7's deletion cards.
