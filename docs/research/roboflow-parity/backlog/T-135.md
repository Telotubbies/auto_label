## User story
As a labeler, I want to paint a region with a brush and rub parts of it out, so that a hairy or transparent object gets an exact mask instead of a fifty-vertex polygon.

## UX flow (LabelDesk words)
1. **Editor tool rail** — a brush icon after polygon, `aria-label="Brush (U)"`, shown only when `task_mask` is on and the project type is `instance-segmentation`. Selecting it (`u`, remappable) shows the brush controls over the canvas: a size stepper in source pixels (`1–200`, `[` and `]` step it), and an **Add / Subtract** segmented pair (`x` toggles).
2. **Paint** — press-drag paints in the active class colour; the pending mask grows as a translucent overlay with a hard edge. Releasing commits one annotation with `source: "human"` and the active class, one undo step. [empty: no class selected → the hint says "Pick a class first" and painting is disabled] [error: the server rejects the mask (T-133) → the overlay stays, the toast carries the reason, nothing is saved]
3. **Subtract** — the same gesture with Subtract erases; a subtract stroke that leaves nothing discards the pending mask and the hint returns.
4. **Mask boxes switch** — in the Display popover (T-138) a new **Mask boxes** switch draws a thin box around every mask; the default is on, so a bare mask is still selectable by its box. Turning it off shows fill only.
5. **Objects tab** — a mask row reads its class, a `mask` chip, and its coverage (`12.4% of the image`).
6. **Review mode precedence** — `u` means "undo the last review decision" in review mode (T-128) and "brush" everywhere else; the cheat sheet lists both with their condition.
7. **Large images** — the brush works on a working bitmap capped at 1024 px on the long side and is upscaled to the image's own resolution before RLE encoding, so a 6000 px photo does not freeze the tab.

## Acceptance criteria
- [ ] The brush paints and subtracts with a visible overlay, commits one annotation per stroke and undoes in one step.
- [ ] Brush size and add/subtract work from the controls and from `[`, `]`, `x`; the tool is absent when the flag is off or the project is not a segmentation project.
- [ ] A mask renders as a filled region with an optional box; the Objects list shows its class and coverage.
- [ ] `u` keeps its review meaning in review mode and selects the brush elsewhere.
- [ ] Empty, loading and error states above all render, including "Pick a class first" and a rejected save that keeps the overlay.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — unchanged save path.
- [ ] Flag off ⇒ the brush tool, its keys and the mask overlay are absent; every other tool is unchanged.
- [ ] Keyboard-only path: `u` → `[` `]` size → arrow the pointer? — the pointer is required to paint; the keyboard path is `u` + `Ctrl+Z` + `Ctrl+S` after a mouse stroke, plus the Objects row delete.

## Notes for the implementer
Paint into an offscreen `Uint8Array`/canvas during the gesture and only lift it into React state on pointer-up: a per-mousemove `setState` on a 1024² bitmap is what makes brush tools feel broken. Cap the bitmap at 1024 px and upscale once at commit.
