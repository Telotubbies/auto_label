# T-1316 — Prometheus and Grafana in an off-by-default Compose profile

| Field | Value |
| --- | --- |
| Wave | O (security, monitoring, performance) |
| Area | Monitoring / operations |
| Size | 2 agent-hours |
| Role | R12 SRE |
| Skills | ponytail, verification-before-completion |
| R7 security review | yes — two new services and an admin password |
| Depends on | T-1302, T-1311 (`/api/metrics` with the series the dashboard reads) |
| Feature flag | Compose `profiles: ["monitoring"]`; no application flag |

## Problem
Metrics exist but nothing visualises them, and every operator would otherwise write PromQL during an
incident.

## Design
`docker compose --profile monitoring up -d` adds exactly two services, pinned and internal-only:

| Service | Image | Config |
| --- | --- | --- |
| `prometheus` | `prom/prometheus:v2.55.1` | `deploy/prometheus/prometheus.yml`: one scrape job `labeldesk` → `api:8000/api/metrics` every 15 s with `authorization: {credentials_file: /etc/prometheus/metrics_token}`; retention 15 d on volume `promdata`; `--web.enable-lifecycle` **off** |
| `grafana` | `grafana/grafana:11.2.0` | provisioning: one datasource (`Prometheus`, internal URL) and one dashboard provider; `GF_AUTH_ANONYMOUS_ENABLED=false`, `GF_SECURITY_ADMIN_PASSWORD=${LD_GRAFANA_PASSWORD}`, `GF_USERS_ALLOW_SIGN_UP=false` |

- Neither service publishes a port by default. Grafana is reached through
  `LD_GRAFANA_PORT` when set (documented as "bind to 127.0.0.1 or tunnel"), otherwise SSH tunnel only.
- Caddy is **not** changed: no route to Grafana or Prometheus, ever.
- `deploy/.env.example`: `LD_METRICS_TOKEN`, `LD_GRAFANA_PASSWORD`, optional `LD_GRAFANA_PORT`.
- `api` gains `LD_METRICS_TOKEN: ${LD_METRICS_TOKEN:-}` so the token exists in both processes.

**One dashboard** (`deploy/grafana/dashboards/labeldesk.json`), seven rows, each a panel:

1. Request rate by status class (5 min).
2. Error ratio with a 2 % threshold line (the alert's line).
3. Latency p50/p95/p99 from the histogram, one line each.
4. Queue depth by status + oldest-queued seconds.
5. Job duration p95 by kind.
6. Worker heartbeat age (table, red past 45 s).
7. Disk free (with a 5 GB line) and GPU VRAM used/budget.

Dashboard variables: `$route` (top 12 routes by volume), `$kind`. No panel queries a tenant label
because none exists.

## Tests to write first
`tools/tests/test_deploy_config.py` (no container is started):
- `test_monitoring_profile_is_off_by_default` — both services declare `profiles: ["monitoring"]`.
- `test_images_are_pinned` — no `:latest`, version tags present.
- `test_no_service_publishes_a_port_by_default` — `ports` absent or bound to `127.0.0.1`.
- `test_prometheus_scrapes_the_metrics_route_with_the_token` — parse the yml.
- `test_dashboard_json_is_valid_and_has_seven_panels` — every panel has a title, a datasource and a
  non-empty `expr`; every `labeldesk_` series it queries exists in `app/metrics.py` (grep the source).
- `test_caddyfile_has_no_grafana_or_metrics_route`.
- `test_env_example_lists_the_three_variables`.

## Acceptance criteria
- [ ] Default `docker compose up -d` starts exactly the current services (profile off).
- [ ] `--profile monitoring` yields a Grafana login with the provisioned dashboard, no manual import.
- [ ] Prometheus scrapes successfully with `LD_METRICS_TOKEN` set and fails visibly without it.
- [ ] No port is public by default and Caddy has no new route.
- [ ] Every dashboard query names a series that `app/metrics.py` actually defines.
- [ ] `docs/DEPLOY.md` explains start, access and the RAM cost (~300 MB total).

## Notes for the implementer
Keep it to one dashboard and seven panels: a wall of panels is a second product. Do not add Alertmanager
here — alerts are T-1317 and must work without this profile. Do not template the dashboard with a build
step; a committed JSON file is what Grafana's provisioning reads.
