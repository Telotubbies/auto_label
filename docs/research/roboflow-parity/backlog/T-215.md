## User story
As an ML engineer, I want to open a catalogue, add one augmentation, configure it and return to my list, so that I never face sixteen toggles at once and never over-augment by accident.

## UX flow (LabelDesk words)
1. **Wizard → step 4 → Add augmentation** — a dialog with two groups, *Appearance* and *Geometry*, and *Enhanced* last; every entry is one row: name, one-line effect ("changes the object's appearance", "moves the frame"), and a tier chip. [empty: n/a] [loading: n/a] [error: a premium row on a free plan is dimmed with "Available on Pro and Enterprise." and is not clickable]
2. **Pick a row → configure** — the dialog swaps to that op's form: only bounded sliders/checkbox groups from the table, plus the scope segmented control (T-211) where a box twin exists. Footer: *Back · Add augmentation*. [error: bound messages inline; *Add* stays disabled while invalid]
3. **Add** — the dialog closes and the op lands in the ordered list (T-216) at the end.
4. **Warnings inside the dialog** — cutout and mosaic carry the doubling warning; mosaic additionally shows the pool-size warning when the train pool is under 3.
5. **No preview inside the dialog** — the step-3 preview panel stays visible behind it when the modal is non-blocking on wide screens; the step-4 preview is T-216's.

## Acceptance criteria
- [ ] One augmentation is added per dialog session; the form shows only its own bounded controls; the ordered list receives it once.
- [ ] Tier gating dims premium rows with a reason and never hides the catalogue entry.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the flat ten-toggle grid renders and the catalogue is unreachable.

## Notes for the implementer
Do not build a search box for sixteen entries. Grouping plus one-line effects is the whole navigation budget; *Enhanced* sits last so the default path never starts with a premium op.
