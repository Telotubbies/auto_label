## User story
As a reviewer, I want to say "this is the wrong class" or "you missed one here" and get a revised preview, so that a bad prompt becomes a fixable request instead of a guessing game.

## UX flow (LabelDesk words)
1. **Auto-label preview → a label → "Wrong class" / "Should not detect this" / "Keep this"** — the client posts one feedback record with the preview image, the label's class and optionally the replacement class. [error: 404 if the preview's batch is gone; the UI shows the record but says it is unsaved]
2. **"Flag missing object" → click the object → optional note** — posts a record with a normalised point and the class the user expects; the preview draws a hollow marker where they clicked.
3. **"Update preview"** — posts the current job params plus the batch id; the agent returns revised params (prompt text and per-class descriptions), one line of explanation, and the records it considered. [loading: "Rewriting the prompt…"] [error: 503 when the vision-language model is not available — "The prompt assistant needs a vision model on this worker"; the current params stay untouched]
4. **What the revision may change** — the free-text prompt, each class's description, and the per-class thresholds; never the class set, model, batch or policy. A response that tries is rejected by the server before it reaches the client.
5. **Thread per batch** — records are stored per batch and replayed with it: leaving and returning to the batch shows the same feedback and the last revision, and **Start a new chat** archives the old records to a new thread id.
6. **Cost** — recording is free; a revision is one metered AI call and is refused with 402 at the allowance.
7. **Permission and gate** — the routes need `project.review` and the workspace flag; a labeler gets 403, never a silent no-op.

## Backend changes
- Models/schema: new table `preview_feedback` (`models/preview.py`, new) — `id`, `workspace_id`, `project_id`, `batch_id` (nullable), `image_id`, `user_id`, `kind`, `annotation_class_id` (nullable), `expect_class_id` (nullable), `note`, `point_x`, `point_y` (nullable floats), `thread` (string, default `"main"`), `created`; index `(batch_id, created)`; registered in `models/__init__.py`.
- Routers: `POST /autolabel/feedback` `{batch_id?, image_id, kind, expect_class_id?, note?, point?}` → the record; `GET /autolabel/feedback?batch_id=&thread=` → records plus the last revision; `POST /autolabel/feedback/revise` `{batch_id, params, thread?}` → `{params, explanation, considered}`; `400` for an unknown kind or a revision that changes model/batch/class set.
- Services/jobs: `services/preview_feedback.py` (new) — `record`, `history`, `revise(params, records)` calling the VLM adapter (`resolve("vlm:…")`) with a strict JSON contract, validating the returned params against the allowed keys, and `archive_thread(batch_id, thread)`.
- Permissions + workspace isolation: `project.review` on all three; batch and image ids are filtered by project, so a foreign batch is 404; class ids validated against the project.
- Secrets/safefetch: none.
- OpenAPI: yes — three routes.

## Acceptance criteria
- [ ] Three feedback kinds record against a batch and replay with the batch, in order, with their click point where applicable.
- [ ] Revising returns new prompt text and descriptions, one explanation line, and never changes model, batch, class set or policy.
- [ ] A revision costs one metered call; 402 and a missing vision model are distinct, readable failures that leave the params untouched.
- [ ] Feedback is per batch thread and "new chat" hides without deleting.
- [ ] Empty, loading and error states above all render (client states are T-157's).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ all three routes 404; the preview screen is unchanged.
- [ ] Keyboard-only path: not applicable in this card.

## Notes for the implementer
The VLM returns JSON; validate it against the allowed keys (prompt, class_prompts, class_confidence) and reject anything else, or a prompt-injected response could rewrite the job. Keep the user's note as data, never as an instruction concatenated into the system prompt.
