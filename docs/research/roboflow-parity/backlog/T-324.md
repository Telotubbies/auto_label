## User story
As a builder, I want to run a draft against a still, a trimmed clip and a live camera, so that "it worked on my image" is caught before the endpoint ships.

## UX flow (LabelDesk words)
1. **Run panel, media tab** — three sources in one control: `File` (JPG/PNG/WEBP), `Video` (an uploaded clip with a `Start ms` / `End ms` pair under a gear), `Camera` (one frame from the device camera, the same permission path the Playground uses). [empty: no project image and no file → "Add an image, or point the camera at the scene."] [loading: "Starting…" while the model loads, then per-frame progress for a clip] [error: a camera that cannot start shows the Playground's own sentence; a clip on a JSON-only workflow says "This workflow returns JSON only, so there is no annotated video."]
2. **Run a clip** — the panel steps the window at the workflow's sample rate, draws each frame's boxes over the video element, and stops at the last frame or the first error. Frame count and elapsed time print under the player: "48 frames · 6 skipped · 2.4 s".
3. **Run against a camera** — one captured frame, labelled "Camera frame · <time>", because a draft is tested on a frame and a stream is a separate destination (T-319).
4. **Outputs** — JSON as a collapsible tree plus the rendered image thumbnail when the workflow declares an image output; clicking it opens the full frame.
5. **Multi-input** — when the contract (T-315) declares more than one image input, each gets its own source selector and the run stops at the shortest clip; the panel says "Equal frame rates are required" once, in the gear.

## Backend changes
- Models/schema: none.
- Routers: `apps/backend/app/routers/workflows.py` — `POST /{workflow_id}/run` accepts `{image_id?, frame_index?}` for a project image and keeps `{image_id}` as today's shape; a video window is driven frame by frame from the client over the existing image rows, so no new video endpoint is added.
- Services/jobs: none — every frame is one `workflow_runner.run` through the existing metered path.
- Permissions + workspace isolation: `project.infer` as today; a foreign image id stays 404.
- Secrets/safefetch: none.
- OpenAPI: yes — the run body gains an optional `frame_index`.

## Tests to write first
pytest — `apps/backend/tests/test_workflow_run_frames.py`:
- `test_a_frame_index_selects_the_project_frame` — `{image_id, frame_index: 12}` runs the image whose `frame_index` is 12 in the same video and refuses 13 when the clip has 12 frames.
- `test_a_frame_index_without_a_video_is_400` — a still image with `frame_index` set is refused, so the client cannot silently ignore it.
- `test_a_foreign_frame_is_404` — another project's image id is not readable.
- `test_flag_off_keeps_the_single_image_body` — with `task_324` off, `frame_index` is rejected and today's body still runs.
node — `apps/frontend/tests/workflow-media.test.mjs`:
- `test_a_window_is_clamped_to_the_clip` — `windowFrames({startMs: -50, endMs: 9_999_999, fps: 5})` starts at 0 and never exceeds the clip length.
- `test_the_stepper_stops_at_the_last_frame` — `nextFrame` returns `done: true` once, then nothing.
- `test_multi_input_uses_the_shortest_clip` — two clips of 48 and 30 frames produce a 30-frame plan and the reason names the shorter one.
- `test_a_json_only_workflow_has_no_video` — `multiInputPlan` reports `video: false` when no output is an image, so the panel shows the JSON-only sentence.

## Acceptance criteria
- [ ] A still, a trimmed clip and one camera frame all run from the same panel and print their own result.
- [ ] A clip window is clamped to the clip, progress is visible per frame, and JSON-only workflows say why there is no video.
- [ ] Two image inputs stop at the shorter clip and the gear states the equal-frame-rate rule once.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ today's single-image run panel, unchanged.

## Notes for the implementer
A draft is tested on frames, never on a live connection: the camera path captures one frame with the Playground's `useCamera` and nothing stays on. Per-frame runs are billed per model call, so the panel prints "N calls" before the run starts and the quota-clamped badge from the runner still appears.
