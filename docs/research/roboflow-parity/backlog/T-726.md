## User story
As an exporter's QC lead answering a buyer six weeks later, I want one Thai sheet with the lot number, the orchard, the grade mix, the defect photographs and my signature, so that the claim is settled by the record instead of by memory.

## UX flow (LabelDesk words)
1. **`รายงานล็อต`** (`/:ws/:project/ops/lots/:lotId/report`) — reached from the lot bar; the page previews the exact page and offers the options that change it. [loading: `กำลังสร้างรายงาน`] [error: `สร้างรายงานไม่สำเร็จ — ลองอีกครั้ง`]
2. **Options** — which grade columns to print and how many photographs per defect class (0–4, default 3); both regenerate the preview. [empty: `ล็อตนี้ยังไม่มีชิ้นที่จัดเกรด` and the grade columns collapse to the disposition counts]
3. **A lot that is not closed** — issuing is refused with `ล็อตนี้ยังไม่ปิด — ออกรายงานไม่ได้`, because a partial report is worse than none. [error: that sentence and the close action]
4. **The sheet** — lot number, orchard and work order, fruit count per grade, defect photographs with their class names, the inspector, a signature block and a QR that opens this lot in LabelDesk. [error: a lot with no photo for a class prints the class name with `ไม่มีภาพ` rather than a gap]
5. **Print** — `พิมพ์ / บันทึกเป็น PDF` opens the sheet in a new tab; the browser produces the file. [error: a blocked popup offers the direct link]

## Backend changes
- Models/schema: none — `Lot`, `LotUnit.grade`, `LotUnit.size_mm` and `Lot.origin` carry the whole record; `project.settings["report_photos"]` holds the default photo count.
- Routers: one route appended to `app/routers/documents.py` (T-721's router): `GET "/lots/{id}/report.html?photos&grades&sign"` → `HTMLResponse`; 404 for a foreign lot, 409 for an open lot, 400 for `photos` outside 0–4 or an unknown grade name, 422 for a malformed `grades` list.
- Services/jobs: `app/services/lot_report.py` (new) — `grade_mix(units) -> [{grade, n, share}]` (a unit without a grade is counted under `ยังไม่จัดเกรด`), `photos(db, lot, per_class) -> [{class, path}]` (one cropped still per defect class, up to the cap, only paths under `DATA_DIR`), `build(db, project, lot, options) -> documents.Document` using `documents.render_html`, with a QR built by `segno` as a data URI. No job.
- Permissions + workspace isolation: `project.export` to issue a report (a manager or reviewer hands documents to a buyer); the lot is resolved through `workspace_id` + `project_id`, so another tenant's lot is 404 and no image is signed.
- Secrets/safefetch: none — no URL is fetched; the QR encodes the workspace slug, the project slug and the lot id, nothing else, and every text value is escaped by T-721's renderer.
- OpenAPI: yes — one route on the documents router.

- Nav entry: none.

  - `apps/frontend/src/features/ops/lotReportView.ts` (new, pure) — `reportQuery(options)`, `gradeColumns(mix)`, `canIssue(lot)`, `mixLine(row)`.
  - `apps/frontend/src/lib/i18n.ts` — the keys below.
- API client: `apps/frontend/src/lib/api/documents.ts` — one function `lotReportUrl(ws, p, lotId, query)` (T-722 created the file; this card appends, merge after T-722).
- Glass: the preview frame is a solid `Card` around an `<iframe>`; the options panel is `Card` content and the print bar is `Glass strength="chrome"`; the grade mix uses `chipTone('status', 'ok'|'warning')`. No new token, no hex, `text-sm`/`text-xs` only, `lucide-react` only.
- Feature flag: `task_lot_report`; off ⇒ the route 404s, no report is built and the lot screen is unchanged.

## Acceptance criteria
- [ ] A closed lot produces one sheet with its number, orchard, grade mix, defect photographs, inspector and a QR back to the lot.
- [ ] An open lot is refused with a sentence, and a lot with no grades falls back to disposition counts rather than an empty table.
- [ ] The photo cap and the grade columns are the user's choice, and the sheet is the same engine as the safety sheet.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see workspace B's lot or its images (404, not 403).
- [ ] Flag off ⇒ no route, no document, and the lot screen is unchanged.

## Notes for the implementer
One engine, two templates: this card adds `lot_report.build` and never a second renderer or a second PDF path. The signature block is a printed name and a date line, not a captured signature image, and the QR points at `/:ws/:project/ops/lots/{id}/report` so a buyer's scan lands on the same record. Copy: `lotReport.title`=`รายงานล็อต`, `lotReport.photos`=`จำนวนภาพต่อประเภท`, `lotReport.grades`=`เกรดที่แสดง`, `lotReport.issue`=`ออกรายงาน`, `lotReport.print`=`พิมพ์ / บันทึกเป็น PDF`, `lotReport.openLot`=`ล็อตนี้ยังไม่ปิด — ออกรายงานไม่ได้`, `lotReport.empty`=`ล็อตนี้ยังไม่มีชิ้นที่จัดเกรด`, `lotReport.ungraded`=`ยังไม่จัดเกรด`, `lotReport.noImage`=`ไม่มีภาพ`, `lotReport.mixLine`=`{grade} {n} ชิ้น · {share} %`, `lotReport.loading`=`กำลังสร้างรายงาน`, `lotReport.error`=`สร้างรายงานไม่สำเร็จ — ลองอีกครั้ง`, `lotReport.popupBlocked`=`เบราว์เซอร์บล็อกหน้าต่างใหม่ — เปิดลิงก์เอกสารแทน`.
