## User story
As a labeler isolating an object, I want to see what will be selected before I commit it and to choose the
smoothing that fits the object, so that a wrong seed click costs one glance instead of an undo.

## UX flow (LabelDesk words)
1. **Editor · isolate tool armed** — moving the pointer over the image shows a translucent proposal outline
   (dashed, 40 % opacity) that follows the cursor at most one request behind. [loading: a small ring follows the
   pointer while the proposal is in flight; no layout shift] [error: "Preview unavailable — click to try once";
   the tool stays armed and the click still works]
2. **Hover pauses 250 ms** — the proposal is requested for that point; moving on cancels the pending request
   (one in flight at a time).
3. **Click** — commits the shown proposal as a normal proposal object (source chip "Assist", confidence), not a
   committed label.
4. **Tool options (floating toolbar)** — `Smoothing: Tight · Balanced · Loose` and `Engine: Auto · Fast · Precise`.
   The chosen values persist for the session and are shown in the tool's tooltip. [empty: a project with no
   segmentation-capable model → Engine shows `Auto` only with "No isolation model ready" and a link to Train]
5. **Second click outside the object** — grows; inside — shrinks, exactly as today; each variant is previewed
   the same way before commit.
6. **Escape** — clears the pending preview and leaves the tool armed; a second `Esc` disarms.

## Backend changes
- Models/schema: none.
- Routers: `POST /api/images/{id}/segment` (existing isolate path, `images.py:712-725`) accepts
  `mode: "preview" | "commit"` (default `commit`) and `smoothing: "tight" | "balanced" | "loose"` and
  `engine: "auto" | "fast" | "precise"`; preview returns the polygon without writing the row and without
  metering; commit keeps today's write and metering.
- Services/jobs: `services/segment.py` gains `smooth(points, level)` (Douglas–Peucker epsilon per level) and
  passes the engine hint to the adapter; the adapter may ignore the hint and says so in the response
  (`engine_used`).
- Permissions + workspace isolation: unchanged `image_ctx` path; preview is read-only but still requires
  `project.annotate`, so a viewer gets 403 before any model work.
- Secrets/safefetch: none.
- OpenAPI: yes — request/response fields; regenerate.

## Acceptance criteria
- [ ] A hover never commits; only a click commits, and what commits is what was shown.
- [ ] One preview request in flight at a time; a fast pointer sweep sends at most one extra request.
- [ ] Preview costs no credit and writes nothing (asserted).
- [ ] Empty, loading and error states above all render; Esc clears the preview.
- [ ] Workspace A cannot see or change workspace B's data (404).
- [ ] Flag off ⇒ no hover request, click-to-commit unchanged, existing assist tests pass unmodified.

## Notes for the implementer
Do not add a second segmentation implementation: preview and commit must call the same adapter path, with the
only difference being the write and the charge. Reuse the existing proposal source chip.
