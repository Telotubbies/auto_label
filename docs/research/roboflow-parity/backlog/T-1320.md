## Problem
A green perf run tells nobody whether it got worse. Without a committed baseline there is no
regression, only a number.

## Design
**`docs/ops/perf/baseline.json`** — one measured run, committed, with the machine it came from:

```json
{"schema": 1, "measured": "2026-11-DD", "commit": "…", "machine": {"os": "…", "cpu": "…", "ram_gb": 32,
 "db": "sqlite", "api_processes": 1, "users": 20, "duration_s": 300},
 "api": {"list_page": {"p50_ms": 41, "p95_ms": 96, "p99_ms": 140, "rps": 61}, …},
 "jobs": {"claim_p95_s": 1.7, "export_1k_s": 18.4},
 "db": {"queries_list": 9, "queries_editor": 41},
 "bundle": {"entry_kb": 268, "largest_route_kb": 212}}
```

**`tools/perf/compare.py` (~90 lines)** — reads the baseline and a run JSON (the same shape), prints one
row per metric (`class, budget, baseline, run, delta%, verdict`) and exits 1 when any metric is worse by
more than `regression.pct` from `budgets.json` (10). Modes:
- `--strict` → 10 % on every metric (the owner's box);
- default → `shared_runner_pct` (25 %) and a header line saying "shared runner: threshold 25 %";
- `--update` refuses without `--base`/`--head` context (so nobody overwrites the baseline by accident in
  CI; the owner runs it locally).
Missing metric in the run = failure; a new metric not in the baseline = warning only (first run of a new
scenario). Zero-variance metrics (query counts, bundle sizes) use a 0 tolerance — they are exact.

**How the first baseline is produced** (recorded in the report, not automated in this card): run the
seed + locust + Playwright perf spec on the owner's machine, `compare.py --update --strict`, commit the
JSON with the machine block filled in. If the card runs on a shared machine, the baseline is marked
`"provisional": true` and the owner re-runs it on the real box (T-1324's report prints that flag).

## Acceptance criteria
- [ ] `python tools/perf/compare.py --run <run.json>` prints the table and exits 0 on a clean run.
- [ ] `--strict` fails at 11 % worse; the default fails at 26 % (shared runner) and says so.
- [ ] A missing class fails, a new class warns.
- [ ] `baseline.json` records machine, commit, date and the 20-user/300 s profile.
- [ ] The baseline is produced by a real run; the report carries the command and the numbers.

## Notes for the implementer
Do not average the run: use p95 (and p50 for context) from Locust's CSV, exactly as the tool wrote it —
no re-computation that could hide a tail. Keep the table stable and diffable: one row per class, sorted
by class name. Do not write a second comparison in the nightly workflow; the workflow calls this script.
