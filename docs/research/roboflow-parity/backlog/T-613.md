## User story
As a QA lead, I want to set the share of a batch that becomes the answer key and see every attempt a person made, so that accuracy reads as a trend and the queue keeps a steady trickle of scored images.

## UX flow (LabelDesk words)
1. **QA → Honeypots → `Answer-key pool`** — a `Card` with `Share of each batch` (1–50 %), `Seed` with a `Regenerate` button, a batch `Select`, and the live hint "≈ 4 of 30 approved images". [empty: "No approved images in this batch yet."] [loading: the hint reads "Counting approved images…"] [error: "The pool is limited to 50 % of a batch."]
2. **`Preview`** — lists the image names that would be promoted, without writing anything. [loading: a three-row skeleton] [error: "This batch is not part of this project."]
3. **`Add to the pool`** — toast "4 images joined the answer key · 26 skipped", the table below refreshes, and the promotion is recorded in the audit log by the API.
4. **Table → an answer-key image** — expands to "Last 5 attempts" with score, attempt number and date, newest first; a person's row in `Labeler accuracy` shows `Attempts` beside `Accuracy`. [empty: "Nobody has opened this image yet."]
5. **A labeler opens a pooled image** — nothing on this screen changes for them; the header, counts and ordering stay identical to an ordinary queue image.

## Acceptance criteria
- [ ] The pool card previews and then promotes a share of an approved batch, and the table shows the new answer-key images.
- [ ] Expanding an answer-key image lists its last five attempts with score, attempt number and date.
- [ ] A rate outside 1–50 % is refused inline with the same sentence the API 422 carries, and nothing is written.
- [ ] Empty, loading and error states above all render: no approved images, the counting hint, the skeleton and the 404/422 messages.
- [ ] Workspace A cannot see workspace B's pool: the screen only ever calls this project's routes, and a foreign batch id renders the 404 message.
- [ ] Flag off ⇒ no Honeypots tab and no pool card.

## Notes for the implementer
Copy the R7 line of the API, not the wording of it: the labeler-facing strings must never say "honeypot" or "benchmark" — the queue must stay indistinguishable from ordinary work. Score bands are 0.8 and 0.5; a missing score is `—`, never `0 %`.
