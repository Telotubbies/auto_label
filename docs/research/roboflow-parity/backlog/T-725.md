## User story
As a packing-house QC lead, I want the tray camera to measure the fruit against a reference object and apply my own grade table, so that the grade on the crate is my standard and not a guess from a box width.

## UX flow (LabelDesk words)
1. **`จัดเกรด`** (`/:ws/:project/ops/grade`) — the station screen shows the tray still, an empty instruction and the grade table beside it. [empty: `วางผลไม้บนถาด` until a detection exists] [loading: `กำลังวัดขนาด`] [error: `วัดขนาดไม่สำเร็จ — ลองอีกครั้ง`]
2. **Two taps measure one fruit** — the operator taps the reference object (a 100 mm marker) and then the fruit; the screen prints `ขนาด 84 มม. · เกรด A`. Without the reference the answer is `ไม่พบวัตถุอ้างอิงขนาด — วางวัตถุอ้างอิงในภาพ`, never a size band. [error: that sentence]
3. **The grade table** — the QC lead edits rows of `เกรด / ขนาดต่ำสุด / ขนาดสูงสุด / จำนวนตำหนิสูงสุด`; the first matching row wins and the order is theirs. [error: `ช่วงขนาดซ้อนกันที่เกรด {g} — แก้ก่อนบันทึก`]
4. **Confirm** — `ยืนยัน` writes the grade and the size onto the current lot's unit and shows the label with a QR back to the lot. [error: `ยังไม่มีล็อตที่เปิดอยู่ — เปิดล็อตก่อน`]
5. **A defect above the row's limit** — the grade falls to the next row that allows it and the screen names why: `ลดเกรดเพราะตำหนิ 3 จุด`. [empty: a fruit that matches no row reads `ไม่ตรงเกรดใดในตาราง — ตรวจด้วยคน`]

## Backend changes
- Models/schema: `LotUnit` gains `grade VARCHAR(16) DEFAULT ''` and `size_mm FLOAT` — one `LOT_UNITS` block at the end of `app/schema/dataset.py` plus one `("lot_units", dataset.LOT_UNITS)` line in `app/schema/__init__.py` (the table is created by T-710, so an upgraded database needs the `ADD COLUMN`). The grade table and the reference size live in `project.settings["grade_rules"]` and `["grade_calibration"]`, so no second table.
- Routers: `app/routers/grading.py` (new), prefix `/api/ws/{ws}/projects/{project}/grading`, `dependencies=[Depends(require_flag("task_fruit_grading"))]`; `GET/PUT "/rules"` (≤ 8 rows, ordered), `PUT "/calibration"` `{marker_mm}` (10–500), `POST "/measure"` `{image_id, marker_box, fruit_box, defect_count}` → `{size_mm, grade, rule, reason}`, `POST "/confirm"` `{image_id, size_mm, grade, lot_id?}` → the `LotUnit`, `GET "/label.png?lot=&grade=&size="` → a PNG label with a QR through the shipped `segno`. 400 for overlapping bands, a missing marker box or a reference size outside its range, 404 for a foreign image, 409 for a confirm with no open lot.
- Services/jobs: `app/services/grading.py` (new) — `size_mm(fruit_px, marker_px, marker_mm)` (longest edge ratio, rounded to 1 mm), `grade_of(size_mm, defects, rules) -> (grade, rule, reason)` pure and deterministic, `validate_rules(rules)` (ordered, no overlap, bands ascending), `label_png(grade, size, lot)` with `segno.make(...)` and `PIL`. No job.
- Permissions + workspace isolation: `project.read` to measure, `project.review` to confirm a grade, `project.settings` to edit the table; the image and the lot are resolved through `workspace_id` + `project_id`, so a foreign id is 404.
- Secrets/safefetch: none — no URL is fetched; the QR encodes the lot id and the workspace slug only.
- OpenAPI: yes — six routes and their schemas.

## Tests to write first
pytest — `apps/backend/tests/test_fruit_grading.py`:
- `test_size_is_the_longest_edge_over_the_reference` — a 260 px fruit and a 100 px marker at 100 mm → `size_mm == 260.0`, rounded to 1 mm.
- `test_the_first_matching_rule_wins_in_the_editors_order` — rules `A 80–95`, `B 60–80` and a 90 mm fruit with no defects → grade `A`; a 90 mm fruit with three defects and `A max_defects 1` → grade `B`.
- `test_a_fruit_that_matches_no_rule_is_not_guessed` — 40 mm against those rules → `grade: null` with `reason` naming the manual check.
- `test_overlapping_bands_are_400` — two rules sharing 70–75 mm → 400 naming the grade, and nothing is saved.
- `test_a_missing_marker_box_is_400_with_the_sentence` — no `marker_box` → 400 `ไม่พบวัตถุอ้างอิงขนาด — วางวัตถุอ้างอิงในภาพ`.
- `test_confirming_without_an_open_lot_is_409` — no open lot → 409, and the unit is not written.
- `test_confirm_writes_the_grade_and_the_size_on_the_unit` — with an open lot the unit carries `grade` and `size_mm` and the lot report can read them.
- `test_the_label_png_carries_a_decodable_qr` — the PNG opens with `PIL` and its QR decodes back to the lot id.
- `test_the_routes_are_hidden_while_the_flag_is_off` — 404 for all six.
- `test_an_image_from_another_workspace_is_404` — 404.
node — `apps/frontend/tests/grade-view.test.mjs`:
- `test_measurement_line_names_the_size_and_the_grade` — `measurementLine({size_mm: 84, grade: 'A'})` is `ขนาด 84 มม. · เกรด A`.
- `test_a_downgrade_names_the_defects` — `measurementLine({size_mm: 84, grade: 'B', reason: 'defects', defect_count: 3})` ends with `ลดเกรดเพราะตำหนิ 3 จุด`.
- `test_overlapping_bands_are_invalid_before_saving` — `rulesValid([{min:80,max:95},{min:70,max:85}])` is false with the grade named.
- `test_the_tray_empty_state_is_an_instruction` — `emptySentence({state:'idle'})` is `วางผลไม้บนถาด`.

## Acceptance criteria
- [ ] A fruit's size is measured against the reference object and the editor's own rule table decides the grade, first match wins.
- [ ] A missing reference, an overlap or an unmatched fruit is a stated refusal rather than a wrong band.
- [ ] Confirming writes the grade and the size onto the open lot's unit and renders a label whose QR points back to the lot.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's rules, image or lot (404, not 403).
- [ ] Flag off ⇒ no route, no nav item, no grade column written, and the lot screen is unchanged.
