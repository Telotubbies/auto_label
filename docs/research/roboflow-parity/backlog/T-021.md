## User story
As a workspace admin creating the second project over the same imagery, I want to reuse the existing annotation group from a list, so that I keep one vocabulary without remembering its spelling.

## UX flow (LabelDesk words)
1. **New project** — the *Annotation group* field becomes a combobox: existing groups listed with `PPE · 3 projects · 8 classes`, plus `Create a new group` as the last option. Typing filters; a new name shows `New group: “ppe” — its classes will start from the list below.` [empty: no groups yet → the field is a plain input with the hint `Groups keep one class list across projects.`] [loading: the combobox opens with one skeleton row] [error: `Could not load groups — the project still works with its own vocabulary.` and the field falls back to an input].
2. **Classes field** — when an existing group is chosen, the comma field is prepopulated and editable; the hint changes to `These come from PPE. New names are added to all 3 projects.` A `Preview shared classes` link opens a read-only chip list.
3. **Project → Classes & tags** — a panel above the table: `Shared vocabulary · PPE · 3 projects` with the sibling project links and one ghost action `Use its own vocabulary` (confirm sheet: `Your classes stay. The other 2 projects keep theirs.`). [empty: a project with no group shows `This project has its own vocabulary.` and one action `Share with another project`]
4. **Conflict** — a rename or delete refused by the server (T-020's 409) shows the message with a `Merge instead` shortcut when the conflict is a duplicate name.

## Acceptance criteria
- [ ] The create form lists existing groups with project and class counts, and reusing one prefills its classes.
- [ ] A new group name is still accepted and creates the group on submit.
- [ ] Empty, loading and error states above all render (no groups, loading row, load failure fallback).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — the picker lists only the current workspace's groups.
- [ ] Flag none: the field posts the same `annotation_group` value the server already accepted.
- [ ] The unlink confirm names what stays and what does not.
