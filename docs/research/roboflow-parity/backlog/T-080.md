## User story
As a workspace admin, I want one Settings page where I add a credential, point it at a bucket and press
**Test connection**, so that setup is a form with answers instead of a curl command.

## UX flow (LabelDesk words)
1. **Settings · Connectors** — two sections: **Credentials** (list + **Add credential**) and
   **Datasources** (list + **New datasource**, rendered by T-081). [empty: "No credentials yet — add one,
   or create it while adding a datasource."]
2. **Settings · Connectors · Add credential** — name, provider chips, then only the fields that provider
   needs; the primary is disabled until required fields are filled. [error: a rejected save shows the
   server line under the field that caused it]
3. **Settings · Connectors · Datasource form** — name, provider, bucket, region, credential dropdown with
   an inline `+`, endpoint and **Use path-style addressing** (on) for S3-compatible hosts.
   [error: a bucket with a path is refused inline: "Enter the bucket name only — no path"]
4. **Settings · Connectors** — **Test connection** shows "Connected · 1,204 objects visible · first:
   frames/0001.jpg" or the actionable failure, with the path-style checkbox highlighted when that is the
   fix. [loading: spinner in the button, result area skeleton] [empty: nothing tested yet → "Untested"]
5. **Settings · Connectors** — saving with a failed test asks once: "Save anyway? The first sync will
   retry."

## Backend changes
- Models/schema: none in this card.
- Routers: none in this card — consumes the T-076/T-077 routes.
- Services/jobs: none.
- Permissions + workspace isolation: the page is owner/admin only (`workspace.connectors`); a foreign id
  can only be reached by typing it, and the API answers 404.

## Tests to write first
node — `apps/frontend/tests/connector-form.test.mjs`:
- `test_required_fields_per_kind` — S3 needs bucket + access key + secret; GCS needs bucket +
  credentials JSON; Azure needs container + account + key or SAS.
- `test_bucket_input_tolerates_scheme_and_refuses_path` — `s3://b` → ok; `s3://b/frames` → error copy.
- `test_path_style_defaults_on_for_custom_endpoint` — a filled endpoint yields `pathStyle: true` unless
  the user unticked it.
- `test_test_result_line_covers_each_outcome` — ok → "Connected · 1,204 objects visible"; addressing →
  the path-style hint; blocked → the unreachable sentence.
- `test_save_anyway_confirm_only_after_a_failed_test` — failed test + save → confirm; untested → no confirm.
pytest — `apps/backend/tests/test_<name>.py`:
- none: no backend surface.

## Acceptance criteria
- [ ] Credentials are created, rotated and deleted from this page; the secret is never displayed again after
      save.
- [ ] A datasource form picks an existing credential or creates one inline without losing typed values.
- [ ] Test connection renders success, key failure, addressing failure and blocked endpoint differently.
- [ ] The page is reachable only by owner/admin; a labeler sees no tab (and the API would 403).
- [ ] Empty, loading and error states above render.
- [ ] Flag off ⇒ no Connectors tab and no route.
- [ ] Workspace A cannot see or change workspace B's data (404 for a foreign credential/connector id).

## Notes for the implementer
Reuse `Table`, `Field`, `Sheet`/`Modal` and `Button` from `components/ui.tsx`; do not build a new table.
The endpoint field is hidden for GCS and Azure standard hosts — only S3-compatible storage needs it.
