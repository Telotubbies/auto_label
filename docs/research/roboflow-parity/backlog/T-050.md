## User story
As the repo owner, I want app code under one cheap, honest lint gate, so that a typo like an undefined
name or a dead import fails CI instead of shipping, and the six-month-old "lint chore" stops being a
documented exception.

## UX flow (LabelDesk words)
1. **Contributor's terminal** — `pre-commit` runs `ruff check` on a backend file and reports a real
   problem (unused import, undefined name, f-string with no placeholder). [empty: no findings → the
   hook is silent] [error: a finding → the hook exits non-zero and names file, line and rule].
2. **CI on a pull request** — the `api tests` job gains a lint step before pytest. [loading: the job
   shows `Lint API (pyflakes)`] [error: a red step with the ruff output, no test run wasted].
3. **Owner reads the rule set** — `ruff.toml` states three lines: line length 120, target py311,
   `select = ["F"]`. No style rules, no import sorting, no format hook on `apps/backend` (a format hook
   would rewrite 271 files in one commit and bury every review).

## Notes for the implementer
`# noqa: F401` is the correct answer for the two registry modules, not deletion: `models/__init__.py` is
imported for its side effect (table registration) and `worker.py`'s imports are the handler dispatch seam.
Keep the `noqa` on the same line as the import, no blanket file-level `# ruff: noqa`, so a genuinely dead
import added later still fails. If you are tempted to also enable `I001`, `E702` or `BLE001`: don't —
`E702` alone is 169 findings and is this codebase's house style (`a = b; db.commit()`).
