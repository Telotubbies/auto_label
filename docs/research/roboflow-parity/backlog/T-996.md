## User story
As a hosted agent that cannot spawn a local process, I want to reach the same tools over one authenticated
HTTP endpoint on my LabelDesk origin, so that a cloud runner connects with the key it already has instead of
installing anything.

## UX flow (LabelDesk words)
1. **`POST https://<LD_DOMAIN>/mcp` with `Authorization: Bearer ld_…`** — the request is handled with that
   key; `tools/list` reflects that key's scopes. Every POST is self-contained: no session cookie, no
   `Mcp-Session-Id` to keep, nothing to make sticky behind a load balancer.
2. **No key** — 401 with `WWW-Authenticate: Bearer` and a one-line body. [error: the client shows its own
   "authentication required"; nothing about the workspace leaks].
3. **A publishable key (`ld_pub_`)** — 403: a browser-embedded key cannot drive an agent loop.
4. **A workspace with MCP off** — 404, the same answer an unknown path gets, so "off" looks missing rather
   than forbidden. [empty: n/a].
5. **A foreign `Origin` or `Host`** — 403/421 before any tool runs (DNS-rebinding defence).
6. **A body over 4 MiB** — 413 before parsing. [error: the client reports a transport failure; the server
   log names the size cap].

## Backend changes
- Models/schema: none.
- Routers: none.
- Services/jobs: `apps/mcp/labeldesk_mcp/http.py` (new):
  - `build_app(server, api, *, allowed_hosts=(), allowed_origins=(), path="/mcp")` returns the SDK's
    `server.streamable_http_app(streamable_http_path=path, stateless_http=True,
    transport_security=TransportSecuritySettings(...))` wrapped in a raw ASGI `KeyMiddleware`.
  - `KeyMiddleware` forwards `lifespan` scopes untouched (so the SDK's own session manager starts — this is
    why the app is wrapped rather than mounted: a `Mount()` never runs the sub-app's lifespan), and on
    `http` scopes resolves `Authorization: Bearer` (or `x-api-key`), then: missing → 401 +
    `WWW-Authenticate: Bearer`; `ld_pub_` prefix → 403; `api.enabled()` false (the workspace flag T-990
    added to `whoami`) → 404; otherwise `api.use(key)` for the duration of the call and a reset afterwards.
  - No session state, no cache, no registry: two instances behind a proxy behave identically.
- `labeldesk_mcp/__main__.py` gains `--http`, `--host` (default `127.0.0.1`), `--port` (default `8020`) and
  reads `LD_MCP_ALLOWED_HOSTS` / `LD_MCP_ALLOWED_ORIGINS` (comma lists) into the transport settings. Empty
  means the SDK's localhost-only default, which is the safe default for a laptop.
- Permissions + workspace isolation: the key in the header is the only identity; the workspace gate is a
  per-request `whoami` (cached for that request only); `Origin`/`Host` are checked by the SDK transport
  settings, with the allowlist coming from the environment, never from the request.
- Secrets/safefetch: the key is never logged; a 401/403 body never names the workspace.
- OpenAPI: no (the MCP endpoint is not part of the REST document).

`starlette.testclient.TestClient(build_app(...))`; the round-trip starts `uvicorn.Server` in a thread on a
free port and talks to it with the SDK's own client.
- `test_a_request_without_a_key_is_401_with_a_bearer_challenge` — POST `/mcp` with an `initialize` body →
  401, `WWW-Authenticate` starts with `Bearer`, body carries no workspace name.
- `test_a_publishable_key_is_refused` — `ld_pub_…` → 403.
- `test_a_workspace_with_mcp_off_is_404` — the mock `whoami` answers `mcp: false` → 404 for every method.
- `test_an_unknown_origin_is_403` — `Origin: https://evil.example` with a good key → 403.
- `test_an_unknown_host_is_421_or_403` — `Host: evil.example` → 421 or 403 (the SDK's transport answers one
  of the two; assert it is not 200).
- `test_the_body_cap_is_four_mib` — a 5 MiB body → 413.
- `test_a_real_client_round_trips_over_http` — uvicorn on `127.0.0.1:0` with the test host allow-listed;
  `from mcp.client import Client` (or `streamable_http_client` with an `httpx2.AsyncClient` carrying
  `Authorization`) → `list_tools` names `whoami`, and `call_tool("whoami")` returns the mock workspace.
- `test_two_keys_in_one_process_see_their_own_scopes` — two sequential requests with different keys; the
  second list does not inherit the first key's scopes (the context variable is reset, not leaked).

## Acceptance criteria
- [ ] One authenticated POST per request; no session id, no server-side state between requests.
- [ ] 401 without a key, 403 for a publishable key, 404 when the workspace flag is off, 403/421 for a
      foreign `Origin`/`Host`, 413 over 4 MiB — all before a tool runs.
- [ ] A real MCP client completes `list_tools` and one `call_tool` over HTTP.
- [ ] Two keys in one process never share scopes or a credential.
- [ ] Empty, loading and error states above all render as described.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the endpoint answers 404; the stdio transport is untouched by this card.
- [ ] `ruff check apps/backend` clean; the full serial API suite passes.

## Notes for the implementer
Wrap, do not mount: `Mount("/", app=server.streamable_http_app())` inside a Starlette would need the host's
lifespan to enter `server.session_manager.run()`, or the first request fails with
`Task group is not initialized`. A raw ASGI wrapper that forwards `lifespan` scopes gets the same result
with no second app to maintain.
`stateless_http=True` is deliberate: the 2026-07-28 revision has no protocol sessions, and stateless also
means the endpoint survives a restart and does not need sticky routing.
