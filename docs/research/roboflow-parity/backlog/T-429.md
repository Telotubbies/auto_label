## User story
As a member, I want to see exactly what an app is asking for and to revoke it later, so that a connected tool never
holds more access than I agreed to.

## UX flow (LabelDesk words)
1. **`/oauth/authorize` consent screen** — `“Camera Health” wants to access your account in “Site A”.` Then a list, one
   line per requested scope with the real consequence (`Read data` / `Upload images` / `Run inference` / `Train models`
   / `Watch streams (read only)`). Actions: `Allow` (primary) and `Deny`.
2. **Unregistered app** — the screen never redirects: `This application is not registered with LabelDesk.` with
   `Close this tab` only; the requested redirect is shown as plain text so the user can see where it pointed.
3. **`Deny`** — returns to the app with `error=access_denied`; the page shows `Nothing was shared.`
4. **Settings → Account → `Authorized apps`** (`/:ws/settings/security` section) — rows of app name, `Connected 4 Mar
   2026`, scopes, `Revoke`. [loading: two skeleton rows] [error: `Could not load connected apps.` + retry]
   [empty: `No apps are connected to your account.`]
5. **Revoke** — confirm `Revoke “Camera Health”? Its token stops working immediately.`; the row disappears and a toast
   confirms.
6. **`[error]`** a token call that fails after revocation is not shown here — this screen only lists live grants.

## Backend changes
- Models/schema: none (T-427/T-428).
- Routers: `GET /api/me/oauth-grants` → `[{client_id, name, scopes, created}]`; `DELETE /api/me/oauth-grants/{client_id}`;
  `GET /api/oauth/consent?client_id&scope&redirect_uri` → the screen's payload (`app_name, workspace, scopes,
  redirect_host`) — no redirect_uri echo in the HTML, only the host.
- Services/jobs: `services/oauth.py` — `grants_for_user(db, user)`, `revoke_user_grant(db, user, client_id)`,
  `consent_payload(...)`.
- Permissions + workspace isolation: grants are per user, not per workspace role — a member can revoke only their own;
  the list filters by `user_id` and never by workspace, so a cross-workspace token appears in the same list with its
  workspace name.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] The consent screen names the app, the workspace and one consequence per requested scope.
- [ ] An unregistered app is shown on our page and never redirected.
- [ ] A member can list and revoke their own connected apps, and revocation takes effect immediately.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no consent route and no connected-apps section.

## Notes for the implementer
The scope list is the consent contract: never show a raw scope string without its sentence, and never show a sentence
for a scope the API would not grant.
