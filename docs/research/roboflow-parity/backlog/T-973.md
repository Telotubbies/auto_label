## User story
As an ML engineer, I want to keep a detection pipeline in version control as a file and import it,
so that the graph reviewers approve is the graph that runs, not the one someone drew on a canvas.

## UX flow (LabelDesk words)
1. **Project → Studio → Pipelines → "Import from repo"** — paste or pick `pipelines/*.yaml`. [empty: an
   empty file — "this pipeline has no steps" with the smallest valid example] [loading: "reading the
   pipeline" while the compile runs] [error: a line-numbered message — "step 3: unknown block type
   `dedupe`" or "step 4: input `masks` is not produced by any earlier step"].
2. **Preview** — the compiled graph renders as a read-only step list (index, type, its inputs and
   outputs) with a diff against the workflow of the same name if one exists. [empty: new name — the
   diff panel says "this will create a new workflow"] [loading: n/a] [error: the diff cannot be
   computed because the existing workflow is on a newer version — "reload"]. 
3. **Import** — creates a workflow, or appends a version when the name matches; both paths go through
   `services/workflows.create/update`, so validation, snapshots and the `(project_id, name)` unique
   constraint behave as they do for the canvas.
4. **Re-import** — importing again from the same file produces no diff and no new version.

## Backend changes
- Models/schema: none — `workflows.blocks` JSON (`models/project.py:216`) already holds a block list.
- Routers: `routers/workflows.py` gains `POST /import` (body `{text: str, name?: str}` ≤ 64 KB):
  200 `{workflow, created: bool, diff: [{index, op}]}` or 400 `{line, step, message}`.
- Services/jobs: `app/services/pipeline_file.py` (new) — `compile_spec(text) -> dict` producing the
  same block dicts `services/workflows.validate_blocks` (`services/workflows.py:115`) accepts, plus
  `diff_blocks(old, new) -> list` (op = `added|removed|changed|same`). Block types are exactly
  `BLOCK_TYPES` (`services/workflows.py:18`); step order is the file order; the sink must be last.
- Permissions + workspace isolation: import needs `project.settings`; the router already sits on
  `project_ctx` (`routers/workflows.py:15-18`) so a foreign project slug is 404.
- Secrets/safefetch: none — nothing is fetched; a step naming a remote URL is rejected (models are
  referenced by id/alias through `parse_ref`, as the canvas already does).
- OpenAPI: yes.

## Acceptance criteria
- [ ] A valid file compiles to the same block shape the canvas saves, and runs.
- [ ] Every rejection names the step and the reason, with no stack trace.
- [ ] Re-importing an unchanged file creates no new version.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
