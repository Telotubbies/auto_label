## User story
As an ML engineer, I want a missing score explained and a stuck evaluation to stop instead of hanging, so that a usable model is never held hostage by its evaluation.

## UX flow (LabelDesk words)
1. **Model with a failed evaluation** — the detail card keeps today's warning and adds the remedy: "Evaluation failed — the model is still usable." then "Re-run on the test split" (primary) and *Why* expanding the reason. [error: an unknown failure prints the generic sentence and the job id]
2. **A large split** — evaluations over 2,000 images run on the first 2,000 and the card states it: "Scored 2,000 of 4,120 test images — the split is large; numbers are a sample." with the sample size in the tooltip of every metric.
3. **A timed-out evaluation** — "Evaluation stopped after 60 min on 4,120 images. The model is usable; re-run on a smaller version." The model stays deployable and the run list pill stays *Ready*, not *Failed*.
4. **A model never evaluated** — "This model has no evaluation yet" with *Run evaluation* (T-283's route); no zero metrics are drawn. [empty: a classification model keeps today's "not evaluated with COCO metrics" sentence]
5. **Compare tab** — a model with no evaluation is dimmed in the picker with "no evaluation", never a zero dot (T-284's copy is the one that ships).

- **States** — [empty: a model with neither an evaluation nor an error renders the "no evaluation yet" state]. [loading: the state line shows the job's progress until the evaluation writes its outcome].

## Backend changes
- Models/schema: none — the outcome rides `metrics.eval` (`sampled`, `scored_images`) and `metrics.eval_error`.
- Routers: none (re-run is T-283's `POST /models/evaluate`).
- Services/jobs: `services/evaluate.py` — `EVAL_MAX_IMAGES = 2000`, `EVAL_TIMEOUT_S` from `config` (default `3600`): the per-image loop checks elapsed time each image and raises `EvaluationTimeout`; when `len(images) > EVAL_MAX_IMAGES` it evaluates the first 2,000 deterministically (sorted by file name) and records `sampled: True, scored_images: 2000, split_images: 4120`. `handlers/training.py` and `finalize.evaluate_and_announce` catch `EvaluationTimeout` separately and store `eval_error = "evaluation stopped after 60 min on 4,120 images — the model is usable; re-run on a smaller version"` with `eval_timeout: True`.
- Permissions + workspace isolation: unchanged.
- Secrets/safefetch: none.
- OpenAPI: yes — `eval.sampled`/`scored_images` in the payload (regenerate both files).

## Acceptance criteria
- [ ] A failed, timed-out, sampled or absent evaluation each has its own sentence, its own numbers and the right action.
- [ ] A timed-out evaluation leaves the model deployable and never writes zero metrics.
- [ ] Large splits are sampled with the sample size stated wherever a metric is shown.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ today's warning card, today's full-split evaluation, no re-run button.

## Notes for the implementer
The deadline is checked inside the image loop — do not start a thread or a second process. Sampling is deterministic (sorted file names) so two people comparing the same model see the same numbers.
