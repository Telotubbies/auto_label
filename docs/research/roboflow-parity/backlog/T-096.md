## User story
As a workspace admin, I want a tree I can drag projects into and a permissions dialog per folder, so that
grouping client work and hiding one client from the rest is the same screen.

## UX flow (LabelDesk words)
1. **Home** — a left column tree: folders with an indent per level, a count (`12`), a lock when restricted,
   and a ⋯ menu (**New subfolder**, **Rename**, **Move**, **Set permissions**, **Delete**).
   [empty: "No folders — group projects by client or line."] [loading: 4 skeleton rows]
2. **Home** — dragging a project card (or a folder) onto a folder highlights the target and moves it on
   drop; with several projects ticked, all move. [error: a drop into the folder's own child shows
   "A folder cannot move inside itself" and nothing moves]
3. **Home · Set permissions** — **Anyone** (default) or **Restricted**, then member rows with a role
   select; saving lists "3 people can see this folder; everyone else does not see its projects".
   [empty: restricted with no members → "Nobody can see this folder — add at least one manager", save
   disabled] [error: the last manager removal → the server sentence, inline]
4. **Home** — a member with a deep grant sees that subfolder as a top-level row, without ancestor names.
   Opening a hidden project by URL shows the ordinary "Project not found" page. [error: the move refusal
   names both folders]

## Acceptance criteria
- [ ] The tree nests to five levels, shows counts including subfolders, and marks restricted folders.
- [ ] Drag-move and multi-project move work; an invalid drop is refused with the sentence.
- [ ] The permissions dialog switches between Anyone and Restricted, edits member roles, and blocks the
      last-manager removal.
- [ ] A deep-grant member sees their folder as a root with no ancestor names.
- [ ] Empty, loading and error states above render.
- [ ] Flag off ⇒ no tree, no permissions dialog.
- [ ] Workspace A cannot see or change workspace B's data: only `/folders` rows render; a foreign folder
      id is a 404 toast.

## Notes for the implementer
Keyboard alternative to drag: the ⋯ → **Move** dialog must offer the same targets (WCAG 2.5.7). Use the
existing `Modal`, `Select` and `Button`; a nested tree is `role="tree"` with arrow-key movement, not a
stack of divs.
