## User story
As an operations engineer, I want to say "take `raw/**/cam-*.jpg` from this bucket, name files by their
key, and delete images whose object disappeared" so that a nightly mirror keeps my dataset honest without
a script.

## UX flow (LabelDesk words)
1. **Settings · Datasources · Mirror** — destination radio (**A project** — picker; the workspace library
   option is disabled with "Available after the asset library ships"), include globs, an
   exclude list, naming strategy, and a "Remove images whose object was deleted" switch that is **off** by
   default and reads in amber when on. [empty: no datasource yet → the form is the create form]
2. **Settings · Datasources · Mirror** — typing `raw/**/cam-*.jpg` shows a helper line: "`*` matches one
   folder level, `**` any depth, quotes escape a literal `*`". [error: an invalid pattern (unbalanced
   quote) → "Check the pattern: unbalanced quote", nothing saved]
3. **Settings · Datasources** — the first sync imports 412 objects and reports
   "412 listed · 398 new · 14 duplicates · 0 failed · 3 skipped by filters".
   [loading: the row's progress follows the job; the rest of the page stays usable]
4. **Settings · Datasources** — enabling orphan removal and saving shows a confirm: "Up to 3 images whose
   bucket objects are gone will be removed from this project. Files shared with another project are kept."
   [error: a destructive delete that fails on a locked file → the run reports "2 removed · 1 kept, retry"]

## Backend changes
- Models/schema: `Image.source_ref VARCHAR(1024) DEFAULT ''` in `models/project.py` + one `IMAGES` entry in
  `schema/dataset.py`; `ingest` sets `source_ref = path` for `source == "connector"` (one line).
- Routers: `apps/backend/app/routers/connectors.py` — create/PATCH accept `mirror` inside `config` and
  validate it through `services.mirror.validate`; `POST /projects/{project}/connectors/{cid}/sync` reads
  the mirror block instead of a bare prefix (the old `prefix` body still works when `mirror` is absent).
- Services/jobs:
  - `apps/backend/app/services/mirror.py` (new) —
    - `validate(cfg)` — destination `"project"` only (`"library"` → `ValueError("the workspace library is
      not available yet")`), ≤ 32 globs, each ≤ 200 chars, naming in
      `fullPath|fileName|eTag|metadata:<key>`, `metadata:` key charset checked.
    - `match(patterns, key) -> bool` — case-sensitive glob→regex translation (`*` = `[^/]*`,
      `**` = `.*`, `?`, quoted `\*` literal); a key must match an include and no exclude.
    - `destination_name(key, cfg, etag) -> str` — `fullPath` → the key's basename path flattening
      (`raw/a/b.jpg` → `raw_a_b.jpg`), `fileName` → `b.jpg` with a `-<6-char sha>` suffix on collision,
      `eTag`/`metadata:<key>` from the object.
    - `plan(objects, cfg) -> {keep: [...], skipped: [...]}` and
      `orphans(db, project, conn, prefix, present_keys) -> list[Image]` (rows whose `source_ref` is under
      the prefix and no longer listed).
  - `apps/backend/app/services/connectors.py` — `sync_job` rewritten: paginate `list_objects` up to the
    configured `limit` (cap 500/run, unchanged), keep only image objects that `mirror.match`, name each
    through `mirror.destination_name`, ingest in `SYNC_CHUNK` batches, then apply orphan removal when
    enabled (bytes first via `erasure.delete_image_files`, meter refund, shared-file guard: skip a row when
    another project has an identical `sha256` live row). Result gains
    `{listed, skipped_filter, uploaded, duplicates, failed, orphans_removed, orphans_kept}`.
    `list_objects` must also return the object `etag` (S3/GCS/Azure all expose it) so the `eTag` naming
    strategy has something to name with; add it to the three branches (one field each).
- Permissions + workspace isolation: `c.perm("workspace.connectors")` on sync; the job re-reads the
  connector and project and refuses a workspace mismatch (already the pattern in `sync_job`).
- Secrets/safefetch: objects are fetched through `safefetch.fetch_bytes` on presigned URLs (unchanged).
- OpenAPI: yes — the connector body schema gains `mirror`.

## Acceptance criteria
- [ ] Include/exclude globs are case-sensitive, `*` is one level and `**` recursive, quoted `*` literal.
- [ ] Naming strategies produce stable, collision-free names; a re-run is a duplicate skip, not a rename.
- [ ] Orphan removal is off by default, requires the confirm, and never deletes an image shared with
      another project.
- [ ] Every refusal and every fetch goes through the existing `ingest`/`safefetch` paths — no second rule
      set and no direct `requests` call.
- [ ] Empty, loading and error states above render (helper line, pattern error, run summary).
- [ ] Flag off ⇒ the old single-prefix sync behaves exactly as today.
- [ ] Workspace A cannot see or change workspace B's data (a connector or project from B is 404/refused).

## Notes for the implementer
`source_ref` is the only bookkeeping needed for orphans: it holds the object key of the image that came from
this connector. Do not use `Image.name`, because the naming strategy can change it. A run is capped at 500
objects (the existing `MAX_SYNC_LIMIT`); the schedule in T-079 calls it repeatedly, it does not raise the cap.
Non-image objects (PDF, JSON, video) are counted under `skipped_filter` and never fetched; videos stay a
library-only feature, and the library destination is refused until area 1 ships it, so the mirror cannot
silently import a video into a project.
