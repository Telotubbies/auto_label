## Findings to fix (read `.superpowers/sdd/2026-10-31-labeldesk-v2/task-T-1202.md` §V1, §V2, §O1)
- **V1 (S3):** while the user types, the dialog shows the address the project will get, `/<ws>/p/<slug>`, using the same slug rule the API uses.
- **V2 (S2):** a name whose slug is already taken in the workspace is refused **in the dialog**. An inline alert names the taken address and suggests a free one; the dialog stays open and keeps what the user typed. The server never silently stores `<slug>-2`. The create route returns 409 with `{taken, suggestion}`, and the dialog shows it. A live pre-check while typing is optional: use it only if it is smaller.
- **O1 (S2):** the first-run tour must never sit above an open modal or capture its clicks. When a modal opens, the tour hides or drops below it (use the z-index tokens, not new arbitrary values). It must still be possible to tab to the primary button at 375 px.

## Tests (first)
- Unit/node test for the slug preview, which must match the backend slug rule on 5 sample names, including Thai text and punctuation.
- API test: a duplicate name returns 409 with `taken` and `suggestion`, and no second project is created.
- The T-1202 spec `apps/frontend/e2e/journey-project.spec.ts` (cherry-pick it from `t/1202` into this branch) passes in full. Do not weaken any of its assertions.
- At 375 px with a fresh visit (tour on), the dialog's primary button receives the click.
