## User story
As a developer, I want to sign the CLI in once and pin a workspace, so that every later command stops repeating the key
and the slug.

## UX flow (LabelDesk words)
1. `labeldesk login` — prompts for the API key (input hidden), validates it with `GET /api/v1/whoami`, then asks
   `Default workspace [<slug>]:` when the key names one, and writes `~/.labeldesk/config.json` with mode `0600`.
2. `labeldesk login --key <key>` — non-interactive for CI; never echoes the key back.
3. `labeldesk auth status` — `Signed in to site-a as ci-pipeline (read, upload, infer).`
4. `labeldesk workspace usage` / `labeldesk workspace plan` — read the workspace's usage and plan label, no flags needed
   once the default is set.
5. `[error]` a bad key → `That key was rejected. Check it was copied in full.` and exit code 2, nothing written.
6. `[error]` a missing scope on a command → the 404 the API returns becomes `This command needs the "read" scope.
   Add it in Settings → API keys.` (the API's silent 404 is translated once, in the CLI).

## Acceptance criteria
- [ ] `login` validates the key before writing anything and stores it with owner-only permissions.
- [ ] The default workspace removes the repeated flag from later commands.
- [ ] A rejected key and a missing scope each print one actionable sentence and a non-zero exit code.
- [ ] Empty, loading and error states above all render (no config, bad key, missing scope).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the three subcommands are not registered.

## Notes for the implementer
One config file, one reader: environment variables (`LABELDESK_API_KEY`, `LABELDESK_WORKSPACE`) win over the file so CI
needs no login step. Translate the API's deliberate 404 once, in the client.
