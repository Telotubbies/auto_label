## User story
As a quality lead, I want to define a business number over an evaluation — "cost = 1.5 × false positives +
0.2 × misses" — without forking the evaluator, so that the number my plant cares about sits beside mAP.

## UX flow, click by click.
1. **Project settings → Evaluation → Custom metrics** — a table: name, expression in words, task, who added
   it, and its value on the newest evaluation. [empty: "No custom metrics yet" with one worked example
   pre-filled in the form] [error: "Custom metrics could not be loaded" with *Try again*]
2. **Add a metric** — three controls: a *condition* (a prediction whose class is X / a ground truth with no
   matching prediction / a class confused with Y / a box smaller than N px), an *aggregation* (count, mean
   confidence, sum of area), and a *weight* with a `+`/`−`. A second line can be added, and a preview shows
   the number on the newest evaluation before saving. [error: "no rows match this condition on the latest
   evaluation" and the save stays disabled]
3. **Saved** — the metric appears in the model's Evaluation strip beside the built-ins, tagged *Custom*, and
   in the CSV/JSON export of the panel.
4. **Rename hazard** — a metric whose class was renamed shows "class no longer exists" on that model instead
   of a number, and the settings row offers *Fix class*.
5. **Delete** — deleting removes it from future reports; stored reports keep the value they computed.

## Backend changes
- Models/schema: new table in `apps/backend/app/models/evaluation.py` — `CustomMetric(id, workspace_id,
  project_id, name, task, terms JSON, created, created_by)`, unique `(project_id, name)`. `terms` is a list
  of `{condition, cls, threshold_px, aggregation, weight}`, validated at write time — no free text, no code.
- Routers: new `apps/backend/app/routers/custom_metrics.py` (new), `P = "/api/ws/{ws}/projects/{project}"`:
  `GET {P}/custom-metrics` → `{metrics: [...], preview: {metric_name: value}}` computed on the newest
  evaluation; `POST {P}/custom-metrics` body `{name, terms}` → 201 with the preview value; `PATCH
  {P}/custom-metrics/{id}` body `{cls}` for the rename fix; `DELETE {P}/custom-metrics/{id}` → 204. 400 for
  an unknown condition or aggregation, a class not in the project, more than four terms, or an empty
  expression; 404 for a foreign id.
- Services/jobs: `apps/backend/app/services/custom_metrics.py` (new) — `evaluate_terms(ev, terms) -> float`
  walking `ev["detections"]` through `insights_eval.match`, and `attach(ev, metrics)` which appends
  `{"name", "value"}` to `ev["custom"]` at report time. Called from the read path (`GET {P}/models/{mid}`)
  rather than at write time, so editing a metric re-scores old reports without a migration.
- Permissions + workspace isolation: read `project.review`, write `c.need("admin")`; foreign id → 404.
- Secrets/safefetch: none — the declared form has no code path that can execute customer input.
  Dependency: none added (no `mlflow-skinny`), so no `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] A declared metric's value matches hand arithmetic on a known evaluation and appears in the panel and the export.
- [ ] No customer-authored string is ever executed; every term is matched against a fixed vocabulary.
- [ ] A metric referencing a renamed class reports the sentence instead of a number.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
