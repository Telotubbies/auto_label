## User story
As a customer with a GPU box already bought and a residency rule against our cloud, I want one command that runs this exact training on my own hardware, so that the run appears in the project like any other and nothing leaves my building except the metrics.

## UX flow (LabelDesk words)
1. **Train** (`/:ws/:project/train`) — `Run on my hardware` returns a copyable command carrying a one-run claim token, the version and the chosen configuration. [loading: the dialog shows the command skeleton while it is minted] [error: the workspace's topology has no remote runner configured ⇒ "This workspace trains on its own worker only." and no command]
2. **Paste and run** — within a minute the run appears in the project with a `Remote` badge and a heartbeat. [error: no heartbeat for four minutes ⇒ `stale` with the last seen time, never `failed`]
3. **Progress** — curves, console tail and checkpoints arrive through the existing worker endpoints, so the run page is the same page.
4. **Interrupt and resume** — interrupting returns the run to `queued`; the next claim with the same token continues the same model record instead of creating a duplicate.
5. **Options** — the command accepts the epochs, image size, batch and max-minutes the form shows; an option the runner cannot execute is refused at submission with its name, not silently dropped. [error: an expired token answers 401 "This run command has expired." and the job stays queued for the workspace worker]

## Backend changes
- Models/schema: none — the token hash, expiry and pool travel on `Job.params`.
- Routers: `POST …/train/remote` `{version_id, variant, epochs, imgsz, batch, max_minutes, resume_from, pool_id}` in `routers/training.py` → `{command, token_expires, job}`; `GET …/models/{mid}/remote` → `{executor, last_seen, stale, pool}`; `remote.claim` accepts `X-Run-Token` beside `X-Worker-Token`.
- Services/jobs: `app/services/remote_run.py` (new) — `mint(db, ws, body, user)` writes the job with `params.runner_hash` (HMAC-SHA256 of the job id and expiry, keyed by `WORKER_TOKEN`, stored through `services/secretbox`), `command_for(ws, project, token)` renders the `labeldesk-worker run --token … --version …` line, `verify(db, token)` resolves the job; widen `_REMOTE_UNSUPPORTED` to the option allow-list `{variant, epochs, imgsz, batch, max_minutes, resume_from, pool_id}`.
- Permissions + workspace isolation: `admin` to mint; the run token resolves to exactly one job and cannot claim another; a job from another workspace is not claimable and its state route answers 404.
- Secrets/safefetch: the token is never stored in clear — only its HMAC through `services/secretbox.py`; it expires after 24 h and dies with the job's terminal status.
- OpenAPI: yes — regenerate both generated files.

## Tests to write first

- `test_mint_returns_a_command_and_a_hashed_token` — mint → response has `command` containing `--token`, and the job row stores a hash, never the token.
- `test_claim_with_the_run_token_claims_only_that_job` — two minted jobs → token A claims job A and never job B.
- `test_expired_token_is_401` — expiry in the past → 401 with the stated sentence and the job stays `queued`.
- `test_terminal_job_token_is_401` — complete the job, retry the claim → 401.
- `test_option_allow_list_refuses_an_unknown_option` — `{tiling: 512}` → 422 naming `tiling`.
- `test_state_route_reports_stale_after_the_timeout` — a heartbeat older than the configured timeout → `stale` true and not `failed`.
- `test_cross_workspace_job_state_is_404` — workspace B asks for A's model state → 404.
- `test_flag_off_is_404` — flag off → 404 on the mint route and the shared token still works.

## Acceptance criteria
- [ ] One action mints a command with a token that claims exactly one run and expires in 24 hours.
- [ ] A claimed run appears in the project with its executor and heartbeat, and goes stale rather than failed when the worker stops reporting.
- [ ] An option the runner cannot execute is refused by name at mint time.
- [ ] Empty, loading and error states above all render as API states: no remote topology refuses the mint, an expired token is a stated 401.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no mint route and the shared worker token path is unchanged.

## Notes for the implementer
The token is a capability, so it must never appear in the audit log, the job payload or an error message — log the job id instead. A run token is bound to one job id and one expiry; do not accept it for `autolabel`, which would turn a training credential into a dataset reader.
