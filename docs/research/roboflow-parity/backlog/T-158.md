## User story
As a pipeline author, I want to run a saved workflow over a batch and map its output classes onto mine, so that the builder stops at inference instead of ending at a JSON sink.

## UX flow (LabelDesk words)
1. **Auto Label → Model** — with `task_31` on, the grouped list gains a **Workflows** group listing this project's workflows, each with its block count. A workflow whose blocks do not end in an annotations sink is listed but disabled with "This workflow has no annotation output". [empty: no workflows → the group says "No saved workflows — build one in Workflows"]
2. **Pick a workflow → Class map step** — a table of the workflow's output class names (from the last preview) with a select per row onto a project class, plus a per-row threshold. Rows default to a same-name match where one exists. **Map every row you want to keep** is the header hint, and unmapped rows show "dropped".
3. **Preview** — runs the workflow on 3–5 samples through the existing preview route (preview rows now carry `dropped_classes`), and the strip shows the mapped classes with counts. An unmapped class that actually produced output is called out once: "hardhat produced 12 labels and is not mapped — they were dropped."
4. **Use this workflow** — stores `settings.autolabel_workflow = workflow_id` and the mapping in the job params; the summary sheet (T-132) echoes "Workflow: PPE chain · 2 classes mapped".
5. **Chat half** — building a workflow by talking to an assistant, iterating on the preview and resuming the conversation per batch, is the preview feedback thread (T-156/T-157) with `workflow_id` in place of a model ref: records and revisions are stored per batch, so leaving and returning resumes. This card does not add a second chat.
6. **Metering** — the preview and the job bill exactly as a workflow run does today (`workflow_runner` records `ai_calls` per model/OCR block); the dialog's estimate line names it as a workflow, not a model.

## Backend changes
- Models/schema: none — workflows already exist (`models/project.py:184`), and the chosen workflow lives in `Project.settings`.
- Routers: `AutoLabelIn` (`training.py:384`) gains `workflow_id: str | None` and `class_map: dict[str, str] = {}`; `_autolabel_target` refuses a workflow from another project (404), a workflow without an `annotations` block (400), and `task_31` off (400); `AutoLabelPreviewIn` responses gain `dropped_classes: [str]`; the job start persists `settings.autolabel_workflow`.
- Services/jobs: `adapters/refine.label_image` gains a workflow branch: load the workflow's blocks (`validate_blocks`), run `workflow_runner.run(...)`, then map each produced class name through `class_map` and drop the rest, counting them into `dropped_classes`; `handlers/training.run_autolabel` reuses the same params, so no second code path.
- Permissions + workspace isolation: `project.review` as today for auto-label; the workflow lookup filters `project_id` and `workspace_id`; `task_31` is checked with `is_enabled`.
- Secrets/safefetch: none beyond what `workflow_runner` already does.
- OpenAPI: yes — two fields and one response key.

## Acceptance criteria
- [ ] A workflow can be chosen as the labeller, with one mapping row per output class and a per-row threshold.
- [ ] Unmapped outputs are dropped and named, before the job when the preview knows them and after it in the summary otherwise.
- [ ] A workflow from another project, a workflow without an annotation sink, and `task_31` off are each refused with their own message.
- [ ] The chosen workflow is remembered on the project and echoed in the summary sheet.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no flag of its own: the surface appears only when `task_31` is on, and with it off the Workflows group is absent.
- [ ] Keyboard-only path: Auto Label → Tab to Workflows group → Enter → Tab the map rows → selects → Tab Preview.

## Notes for the implementer
The workflow branch belongs in `label_image` so the preview, the job and any future caller share one path. Never write a second mapping table on the client and send raw workflow names: the server maps, the client displays.
