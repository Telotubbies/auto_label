## User story
As the engineer who trained a model six weeks ago, I want the finished run to carry the exact arguments it used, so that "what produced this model" is one card I can copy, download and paste into a new run instead of a support thread.

## UX flow (LabelDesk words)
1. **Model page** (`/:ws/:project/models?model=<id>`) — a `Configuration` card lists every argument; values that differ from the defaults are marked, defaults are muted. [empty: a run trained before this shipped says "This run predates stored configurations." and links to the job's options instead of showing `{}`] [loading: the card renders its skeleton rows, never a half-filled list]
2. **Copy / Download** — `Copy` puts the JSON on the clipboard with a toast; `Download` gives `.json` or `.yaml`.
3. **Train screen** (`/:ws/:project/train`) — a `Paste a configuration` drop zone accepts a `.json`/`.yaml` file or pasted text; fields fill in place, out-of-range values are clamped with a warning beside the field, and unknown keys are named in the dialog rather than dropped silently. [error: unreadable file ⇒ "That file is not a configuration LabelDesk wrote." and the form keeps its current values]
4. **A configuration from another version** — pasting one whose `version_id` names a different dataset version shows "This configuration trained on v{n}" beside the dataset picker. [loading: nothing — the paste is local]
5. **Deep link** — `/train?fromModel=<id>` opens with the form already filled from that run and a line naming the source run.

## Backend changes
- Models/schema: `TrainedModel.config` (JSON, default `{}`) in `app/models/training.py`; `app/schema/training.py` `TRAINED_MODELS` gains `"config": "JSON"`; `app/bootstrap.py` backfills `Job.params["options"]` into `config` for existing models where it is empty.
- Routers: `GET /api/ws/{ws}/projects/{project}/models/{mid}/config` returns `{config, defaults, differs}`; `?format=json|yaml` returns the same document as a download; `model_out` gains `config` for a reader with `project.models`.
- Services/jobs: `app/services/run_config.py` (new) — `snapshot(options) -> dict`, `yaml_text(config) -> str` (flat `key: value`, no PyYAML), `differs(config, defaults) -> list[str]`; `services/finalize.py` writes the snapshot at registration.
- Permissions + workspace isolation: `project.models` for the payload; a model id from another workspace or project answers 404 through the existing `_model()` lookup.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate `openapi.json` and `api-types.gen.ts`.

## Tests to write first
pytest — `apps/backend/tests/test_run_config.py`:
- `test_config_snapshots_the_job_options` — submit a train with `epochs=7, imgsz=512, batch=4` → the model's `config` holds those three values plus `variant` and `version_id`.
- `test_config_export_json_and_yaml` — `GET .../config` returns `epochs`; `?format=yaml` returns a line `epochs: 7` and no JSON braces.
- `test_config_route_is_404_for_another_workspace` — workspace B's session asks for A's model id → 404, not 403.
- `test_config_route_is_404_when_flag_off` — flag off → 404 on the config route and `config` absent from `model_out`.
- `test_backfill_fills_an_old_model` — a model with an empty `config` and a job carrying `options` gains the options after the bootstrap backfill.
node — `apps/frontend/tests/run-config.test.mjs`:
- `test_parse_clamps_out_of_range` — `parseRunConfig('{"epochs":900}')` → `epochs` 500 and `clamped` names `epochs`.
- `test_unknown_key_is_reported_not_dropped` — `parseRunConfig('{"foo":1}')` → `unknown` contains `foo`, `config` unchanged, no throw.
- `test_yaml_round_trip` — `configToYaml({epochs:7,batch:4})` parses back to the same values through `parseRunConfig`.
- `test_diff_names_only_non_defaults` — `configDiff({epochs:30,imgsz:512},{epochs:30,imgsz:640})` returns `['imgsz']`.

## Acceptance criteria
- [ ] A finished run shows every argument it used, with non-default values marked and defaults muted.
- [ ] Copy, `.json` download and `.yaml` download all return the same document the run used.
- [ ] A pasted configuration fills the Train form, clamps out-of-range values with a named warning, and names an unknown key instead of dropping it.
- [ ] Empty, loading and error states above all render: an old run explains itself instead of showing an empty card, and an unreadable paste keeps the form.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no Configuration card, no paste zone, no `?fromModel=` seeding, and the old pages are unchanged.

## Notes for the implementer
`config` is the argument set only — never metrics, weights or paths. Defaults are read from `TrainIn` (`routers/training.py:218-228`), not duplicated in the frontend: send them in the payload so the "differs" marker cannot drift. The import path never writes to the server; it only fills the form, so an invalid paste cannot create a job.
