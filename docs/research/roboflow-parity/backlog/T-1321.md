## Problem
Page timing is unmeasured. The monitoring plan observes real users (T-1313), but a nightly lab number is
what fails a regression before users see it.

## Design
`apps/frontend/e2e/perf.spec.ts` (new, ~110 lines), Playwright, Chromium, production build
(`vite build` + `vite preview`) against the seeded API from T-1319.

- Four pages, five runs each, median reported, CPU throttling ×4 and a 4 Mbps network profile (CDP
  `Network.emulateNetworkConditions` + `Emulation.setCPUThrottlingRate`) so a laptop number is comparable
  to a phone.
- Metrics come from the same `web-vitals` library the app ships, read inside the page:
  `page.evaluate` waits for `onLCP`/`onINP`/`onCLS` to fire (INP needs an interaction — the spec clicks
  the first image thumbnail), a 10 s cap per metric with `null` recorded rather than a hang.
- Pages: `login → home`, `projects list`, `dataset grid (10k)`, `editor open`.
- Assertions read `docs/ops/perf/budgets.json` (`pages.<class>`), never a literal.
- `playwright.config.ts` gains a `perf` project (`testMatch: ["e2e/perf.spec.ts"]`,
  `workers: 1`, `retries: 0`) so `npm run e2e` stays fast and the perf project is opt-in
  (`npx playwright test --project=perf`).
- Output: `docs/ops/perf/runs/<date>/vitals.json` for the report and `compare.py`.

## Files
Exclusive:
- `apps/frontend/e2e/perf.spec.ts` (new)
- `apps/frontend/e2e/perf-helpers.ts` (new, ~40 lines: throttling, metric collection, budget lookup)
Shared (one block each):
- `apps/frontend/playwright.config.ts` — the `perf` project
- `apps/frontend/package.json` — `"perf": "playwright test --project=perf"`
- `apps/frontend/playwright.config.ts` also needs `webServer` for preview + API when `PERF=1` (use the
  existing config shape; do not add a second config file)

## Tests to write first
The spec is the test:
- `test_home_meets_lcp_inp_cls_budgets`.
- `test_projects_list_meets_budgets`.
- `test_dataset_grid_10k_meets_budgets`.
- `test_editor_open_meets_budgets`.
- `test_a_deliberately_slow_page_fails_the_gate` — a control run with CPU throttling ×20 on one page
  must fail, proving the assertion is not vacuous (marked `test.skip(!process.env.PERF_CONTROL)` so it
  does not slow the nightly).
- `test_each_metric_is_recorded_even_when_null` — the JSON shape, so a missing INP is visible.

## Acceptance criteria
- [ ] Four pages measured, median of five, with CPU and network profiles documented.
- [ ] Every threshold read from `budgets.json`; no literal in the spec.
- [ ] A run writes `vitals.json` with the page, metric, value, throttling profile and commit.
- [ ] The `perf` project is opt-in; `npm run e2e` time is unchanged.
- [ ] The control run proves the gate can fail.
- [ ] No new npm dependency beyond what T-1313 added (`web-vitals`) and Playwright.

## Notes for the implementer
Do not add Lighthouse CI: it brings a second Chromium and a second budget format for pages Playwright
already opens. INP needs a real interaction — click a thumbnail, not a synthetic event. Record `null`
rather than inventing a value when a metric does not fire; a missing INP is a finding, not a pass.
