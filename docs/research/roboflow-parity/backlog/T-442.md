## User story
As an admin, I want to fix a typo in the workspace address and be told exactly what stops working, so that no one
discovers it from a broken script.

## UX flow (LabelDesk words)
1. **Settings → Workspace → `Address`** — the current slug with `Change address`; the dialog shows the new name field,
   a live preview `/:ws` and the slug rule (`lower-case letters, digits and dashes`).
2. **The warning** — before the confirm: `Your workspace address changes. Every workflow endpoint, API base URL and
   inference URL that uses the old address stops working — including scripts, camera gateways and notebooks. There is
   no redirect.` plus a checkbox `I have updated every integration that uses this address`.
3. **Confirm** — `Change address` stays disabled until the checkbox is ticked and the slug differs.
4. **After** — a success line `This workspace is now at /site-a. Update your integrations.` and the app redirects to the
   new path.
5. **`[error]`** a taken slug → `That address is already in use.` inline; an invalid slug → `Use lower-case letters,
   digits and dashes (2–40).`
6. **`[empty]`** a slug that has never been customised shows `Default address` as a chip and no redirect promise.

## Backend changes
- Models/schema: none — `Workspace.slug` is unique and indexed.
- Routers: `PATCH /api/ws/{ws}` (`routers/workspaces.py`) already accepts `name`; this card adds `slug`
  (validated `^[a-z0-9][a-z0-9-]{1,38}[a-z0-9]$`, not reserved by `RESERVED_WORKSPACE_SEGMENTS`, unique → `409`).
  The response carries the new slug so the client can navigate.
- Services/jobs: one helper `unique_slug(db, candidate, exclude_ws)` in `routers/auth.py` reused (it already exists for
  creation); audit `workspace.rename` with `{from, to}`.
- Permissions + workspace isolation: `workspace.update`; a slug owned by another workspace is a `409` and never a 404 that
  would confirm or deny which tenant owns it (the name is public by design).
- Secrets/safefetch: none.
- OpenAPI: yes.

## Frontend changes

## Acceptance criteria
- [ ] The address can be changed once, with a warning that names endpoints, API URLs and scripts.
- [ ] The confirm requires the acknowledgement checkbox and a valid, unique slug.
- [ ] The app lands on the new address after the change and the old one stops routing.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404/409, never a silent cross-tenant write).
- [ ] Flag off ⇒ the slug is read-only and the API ignores the field.

## Notes for the implementer
No redirect from the old slug — the warning says so, and a redirect would quietly keep old scripts alive. Reuse the
creation-time `unique_slug` helper so there is one slug rule.
