## User story
As a production manager, I want first-pass yield per lot, line and shift with the top defect classes beside it, so that Monday's meeting starts from a number instead of an export someone rebuilt in a spreadsheet.

## UX flow (LabelDesk words)
1. **A query names its grouping** — `GET /yield?start&end&group_by=lot|line|shift` returns rows, the Pareto and the totals the board T-713 draws. [empty: `ยังไม่มีคำตัดสินในช่วงนี้` with a link to the station] [loading: `กำลังคำนวณอัตราผ่าน`] [error: `คำนวณไม่สำเร็จ — ลองอีกครั้ง`]
2. **A lot row carries its own units** — `GET /yield/lots/{lot_id}/units?disposition=ng` returns the units behind the number, so a click on a lot always lands on evidence.
3. **A shift row uses the station's own windows** — the same `window_for` T-693 shipped, so 05:59 is the night shift here exactly as it is on the shift tile. [empty: a station with no windows is grouped under `ทั้งวัน`, never dropped]
4. **A range past retention** — 400 with `ช่วงวันที่เกินระยะเก็บข้อมูลของโปรเจกต์ (30 วัน)` rather than silently returning a shorter window. [error: that sentence, naming the project's own number]

## Acceptance criteria
- [ ] One query returns FPY per lot, line or shift with the top-five defect Pareto and the totals behind it.
- [ ] First-pass yield counts a reworked unit as not-first-pass, and a lot with no decisions reports `null`, never 0 % or 100 %.
- [ ] Every row links to the units behind it, and a range past the project's retention policy is refused with the number in the message.
- [ ] Empty, loading and error states above all render — an empty window is a row-less answer with `fpy: null`, not an error.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ both routes 404 and the shift tile still reports exactly what it reports today.

## Notes for the implementer
FPY = `ok with reworks == 0` ÷ every decided unit; NG and rework are both failures for this number, and an undecided unit is in the denominator of nothing. `previous_fpy` compares the same key in the previous window (previous lot, previous shift, previous period for a line) and is `null` for the first one. Do not recompute shift yield here: import `window_for` from `services/shift.py` so the two boards cannot disagree about where a shift starts.
