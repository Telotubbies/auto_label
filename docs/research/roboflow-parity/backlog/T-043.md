## User story
As a workspace owner, I want the paid surfaces to say they need a plan instead of quietly working, so that the tiers mean something and nobody is surprised by a limit.

## UX flow (LabelDesk words)
1. **Review column** — on a free plan the Annotate board's `In review` lane renders dimmed with a lock and `Review needs a plan with reviewers. See plans.` Clicking the lock opens a sheet naming the capability; the lane cannot be entered. [empty: flag off → today's board]
2. **Labeling analytics** — `Insights → Labeling` tab and `Reviews → dashboard` render the lock state instead of data; the API returns 402 for a direct call.
3. **Non-admin seats** — the Members page seat line reads `3 of 3 seats used · 0 of 0 labeler seats on Free`; inviting or accepting a non-admin role on free → 402 `Labeler and reviewer seats are not in the Free plan.` Admin seats stay unlimited on every plan.
4. **Request access** — the dimmed rail item keeps the v3 permission pattern: lock + `Request access` tooltip that opens a mailto to the workspace owner with the feature name prefilled. Never a silent redirect.
5. **After an upgrade (operator action)** — the same screens render normally with no reload-time flag change; the entitlements query is refetched on focus.

## Backend changes
- Models/schema: none.
- Routers: guard with `require_feature` from T-042: `GET /api/ws/{ws}/projects/{p}/labeling/dashboard`, `GET …/labeling/review-queue`, `POST /api/ws/{ws}/invites` and `POST /api/join/{token}/accept` when the role is non-admin (`labeler`, `reviewer`, `member`, `annotator`), and the Annotate board's review column data (the existing board route returns `review` counts only when the feature is on).
- Services/jobs: `entitlements.non_admin_limit(plan, seats)` consulted by invites/accept; no new service.
- Permissions + workspace isolation: every guard runs after `project_ctx`/`ws_ctx`, so a foreign workspace 404s before the plan check.
- Secrets/safefetch: none. No price, no provider, no charge.
- OpenAPI: yes (402 responses documented on the guarded routes).

## Acceptance criteria
- [ ] On a free plan, review column, labeling analytics and non-admin seats are refused by the API (402) and shown as locked in the UI.
- [ ] Admin seats stay unlimited on every plan; an admin invite is never blocked.
- [ ] Empty, loading and error states above all render (locked-panel copy, seat line, tooltip).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) before any plan check.
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged (nothing locked, no 402).
- [ ] No locked state ever names a price, a currency or a provider.

## Notes for the implementer
Locked means *dimmed + lock + `Request access`*, the v3 permission pattern — not a redirect and not an upsell modal. The server is the gate; the UI mirrors it from `/entitlements`.
