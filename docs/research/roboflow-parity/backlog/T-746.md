## User story
As a security lead during an incident, I want to verify that a date range of audit rows has not been edited, so that "could our own team have changed this row" has an answer that does not depend on trusting us.

## UX flow (LabelDesk words)
No screen in this card (T-747 owns the Integrity tab):
1. **A verification over a quarter** — `GET /api/ws/{ws}/audit/integrity?since=…&until=…` answers `{events: 12430, intact: true, first_hashed: 118422, last_hash: "9f3c…", gaps: [{from: 8800000000, to: 8800004320, reason: "no rows written"}], digest: "sha256:…"}`.
2. **A tampered row** — `{intact: false, break_at: "a1b2…", reason: "hash mismatch"}` and the range stops being presented as proof. [error: the screen prints `"Chain break at event a1b2… — stop deleting logs and open a ticket."` / `"พบจุดที่สายโซ่ขาดที่เหตุการณ์ a1b2… — หยุดลบบันทึกและแจ้งทีม"`]
3. **Rows written before the chain existed** — `gaps` reports `{reason: "before integrity started", from: <oldest hashed>, to: <now>}` and the copy says the range is hashed "from 17 Nov 2026", never "intact since 2024".
4. **Downloading the proof** — `?download=digest` returns a `text/plain` file named `audit-chain-<ws>-<date>.txt` carrying the range, the count, the last hash and the digest, so it travels beside the CSV export.
5. **Every verification is logged** — the call itself writes an `audit.verify` row, which joins the chain.

## Backend changes
- Models/schema: `Audit` gains `hash VARCHAR(64)` and `prev_hash VARCHAR(64)` (both nullable: rows written before the flag stay null and are reported as the boundary, never silently re-hashed). One block in `app/schema/insights.py` (new) registered as `("audit", insights.AUDIT)` in `schema.STEPS` plus `DOMAIN_MODULES`.
- Routers: `GET /api/ws/{ws}/audit/integrity` in `app/routers/audit.py` — `since`, `until` (epoch seconds), `download` (`digest` only), permission `workspace.audit` (`_can_audit`), 400 for `until < since`, 404 while the flag is off.
- Services/jobs: `app/services/audit_chain.py` (new) — `GENESIS = "0" * 64`, `payload(row) -> bytes` (canonical JSON: id, created, user_id, action, target, meta with sorted keys, `ensure_ascii=False`), `link(db, row) -> None` (sets `prev_hash` from the workspace's newest hashed row and `hash = sha256(prev_hash + payload)`), `verify(db, ws_id, since, until) -> dict` (ascending walk, recompute each hash, collect `gaps` and `break_at`), `digest_of(hashes) -> str`, `digest_text(result, ws_slug) -> str`. `app/deps.py::audit()` mints the id explicitly (`Audit(id=new_id(), …)`) and calls `link()` so every existing call site is covered by one line.
- Permissions + workspace isolation: the route is `workspace.audit` (owner/admin); the walk is `Audit.workspace_id == c.ws.id`, so a chain is never compared across tenants and a foreign workspace id is 404 at the slug.
- Secrets/safefetch: none — SHA-256 over row fields; no key material, no signing key to rotate. The digest proves consistency, not authorship; the copy says so.
- OpenAPI: yes — one route, one query set, one response shape.

## Tests to write first
pytest — `apps/backend/tests/test_audit_chain.py`:
- `test_every_new_row_carries_a_chain_link` — three audited actions leave three rows whose `prev_hash`/`hash` form a chain ending at the newest, and the second row's `prev_hash` equals the first row's `hash`.
- `test_verify_reports_intact_for_an_untouched_range` — `GET …/integrity` over the range answers `intact: true`, `events >= 3`, and a digest of 64 hex characters.
- `test_editing_a_row_breaks_the_chain_at_that_row` — update a middle row's `target` directly in the database, then verify answers `intact: false` with `break_at` equal to that row's id.
- `test_deleting_a_middle_row_is_reported_as_a_break` — delete a row, verify answers `intact: false` naming the following row.
- `test_rows_before_the_chain_are_a_gap_not_a_claim` — a row inserted with `hash = NULL` inside the range produces a `before integrity started` gap and does not fail the run.
- `test_the_verification_itself_is_audited` — after one verify call an `audit.verify` row exists with the range in its meta.
- `test_foreign_workspace_and_flag_off` — with the flag off the route is 404 and no hash is written; a workspace the caller does not belong to is 403 at the slug boundary and a foreign id is never walked.

## Acceptance criteria
- [ ] Every audit row written while the flag is on carries a hash and the previous row's hash, and the newest row closes the chain.
- [ ] Verification answers intact, break-at-id or gap, and never calls a range intact when a hash is missing or mismatched.
- [ ] The digest downloads as a text file that names the workspace, the range, the count and the last hash.
- [ ] Empty, loading and error states above all render: an empty range answers `events: 0` with an explicit "no rows in this range" reason, `until < since` is 400.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — a chain never spans two workspaces.
- [ ] Flag off ⇒ no hashes are written, the route is 404, and the audit table behaves exactly as today.

## Notes for the implementer
The chain proves consistency, not authorship: say that in the copy, and do not sign the digest with a key we do not have an HSM for. Do not backfill hashes onto old rows — a hash computed today over a row that could have been edited yesterday proves nothing, and the honest gap sentence is worth more than a green tick. `shortcut: the last-hash read is not locked against a concurrent writer, so two simultaneous writes can fork the chain; the verifier reports the fork as a break, never as intact — add a per-workspace row lock when the API runs on more than one process`.
