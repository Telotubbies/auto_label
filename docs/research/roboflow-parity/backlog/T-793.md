## User story
As a reviewer clearing a dataset before a retrain, I want to select twenty rows and settle them in one action, so that a queue of three hundred disagreements is an hour of work instead of an afternoon of clicking.

## UX flow (LabelDesk words)
1. **Suspect labels** (`/:ws/:project/suspects`) — each row gains a checkbox; a selection bar reads `{n} selected` with `Mark all as real errors` and `Dismiss all`. [empty: the page keeps today's states; a scan with no model still says "Train a model first" and its button lands on Train]
2. **Select all in view** — selects the currently filtered rows only, never the hidden ones behind a filter. [loading: the bulk action disables the bar and shows a spinner on it]
3. **Bulk verdict** — one request settles every selected id; the rows update in place and the precision statistic refreshes. [error: one id was rescanned away ⇒ the response reports how many settled and the toast names the rest, never a silent partial success]
4. **Header link** — when no model exists the page header carries `Train a model`, so the empty state and the header agree. [error: the queue request fails ⇒ today's alert with `Try again`]
5. **Queue precision** — unchanged; the card does not alter ranking, kinds, scores or the method note.

## Tests to write first
pytest — `apps/backend/tests/test_suspect_bulk.py`:
- `test_bulk_verdict_settles_every_selected_id` — three queued ids, verdict `confirmed` → `settled` 3 and the precision statistic counts three confirmed.
- `test_unknown_id_is_reported_not_raised` — one id that is no longer queued → `settled` 2, `missing` 1, HTTP 200.
- `test_bulk_is_capped_at_500` — 501 ids → 422 and nothing written.
- `test_bulk_needs_reviewer` — a labeler's token → 403 on the bulk route while the read route still works.
- `test_cross_workspace_ids_are_missing_not_settled` — ids from workspace A used in workspace B → all reported missing, no row changes.
- `test_ranking_is_untouched` — the same queue read before and after a bulk verdict returns the same scores and order minus the settled rows.
node — `apps/frontend/tests/suspect-bulk.test.mjs`:
- `test_select_all_in_view_ignores_filtered_out_rows` — five visible of nine → five selected.
- `test_toggle_clears_on_second_click` — select then deselect returns an empty set.
- `test_bulk_outcome_is_plural_safe` — 50 settled, 1 missing reads "50 settled, 1 no longer in the queue".
- `test_selected_count_reads_zero_without_selection` — empty set → the bar is hidden and the count is 0.

## Acceptance criteria
- [ ] Rows can be selected individually or all in view, and the count is shown.
- [ ] One action settles every selected row with one verdict and refreshes the precision statistic.
- [ ] A row that left the queue is reported as missing while the rest settle; nothing fails silently.
- [ ] Empty, loading and error states above all render: no model still links to Train from the header, the bulk bar shows pending, a failure keeps the rows.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the page, nav entry and routes are absent exactly as today.

## Notes for the implementer
This is a HAVE row: do not touch `services/suspects.py`, the score, the kind taxonomy or the scan. Selection lives in component state and resets after a bulk action and on a filter change. "Select all in view" means the filtered array the user can actually see, never `items`.
