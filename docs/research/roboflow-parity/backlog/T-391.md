## User story
As an admin, I want the least destructive action next to the irreversible one, so that a mistake is a click away
from undo.

## UX flow (LabelDesk words)
1. **`⋯` on a key row** — `Edit name`, `Protect` (or `Unprotect`), `Disable` (or `Enable`), `Roll`, `Revoke`,
   in that order; the destructive item is separated by a rule and coloured danger.
2. **Edit name** — a dialog with one field and `Save`; hint `The key itself does not change.`
3. **Protect** — confirm `Protect “ci-pipeline”? A protected key cannot be disabled, rolled or revoked from the app
   or the API until you unprotect it here.` `Unprotect` is offered only in the app and says so.
4. **Disable** — confirm `Pause “ci-pipeline”? Every call with this key starts failing immediately. The value stays
   the same, so enabling it again restores service.`
5. **Revoke** — a typed confirm: type the key name, then `Revoke key`. On the last key the dialog is replaced by
   `This is the workspace's last key — create a replacement first.` with `Generate new key`.
6. **Every action** disables the row's controls until the answer arrives (`Working…`), then the row updates in
   place; a 409 shows the server sentence inside the dialog, not a toast.

## Acceptance criteria
- [ ] The row menu offers rename, protect, disable, roll and revoke in one ladder, with revoke separated.
- [ ] Revoke requires typing the exact key name; the last key cannot be revoked from the UI.
- [ ] Every refusal renders inside the dialog and the row is unchanged.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the trash icon and the browser `confirm()` are unchanged.
