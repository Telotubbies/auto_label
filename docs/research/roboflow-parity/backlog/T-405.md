## User story
As an admin, I want every deleted thing to keep who deleted it and when, so that the trash can answer "who removed
this and how long have I got".

## UX flow (LabelDesk words)
1. This card ships the rows, not the screen. A project, dataset version, training run and workflow each gain a
   soft-delete stamp and a deleter; an image keeps the stamp it already has.
2. A soft-deleted item disappears from every list and API read exactly as a deleted project does today (the
   `deleted_at IS NULL` filter), and a hard purge is still a separate action (T-406).
3. `[empty]` an item deleted before this card has `deleted_by = NULL` and renders `Deleted by a member who has since
   left.` — the UI's problem, not a backfill.
4. `[error]` the retention sweep never touches a row it did not stamp (no `deleted_at`, no deletion).

## Backend changes
- Models/schema: `Project` gains `deleted_by: str | None`; `Version`, `TrainedModel`, `Workflow` each gain
  `deleted_at: float | None` and `deleted_by: str | None`.
  `ADD COLUMN` blocks: `PROJECTS` in `app/schema/dataset.py` gains `"deleted_by": "VARCHAR(32)"`; new
  `VERSIONS`/`WORKFLOWS` blocks appended in `app/schema/dataset.py`; `TRAINED_MODELS` in `app/schema/training.py`
  gains both columns. Add the three `STEPS` rows in `app/schema/__init__.py` at the end, in table order.
- Routers: no new routes. The existing delete paths set the stamp + deleter: `routers/projects.py` (project),
  `routers/versions.py`, `routers/training.py` (run delete), `routers/workflows.py`.
- Services/jobs: `app/services/trash.py` (new) — `soft_delete(db, obj, actor)` (one helper for the four types),
  `TRASH_TYPES = ("project", "version", "run", "workflow")`, `type_of(obj) -> str`, `label_of(obj) -> str`.
- Permissions + workspace isolation: the stamp is written only by a route already holding the type's delete
  permission; `trash.type_of` resolves through `workspace_id`/project's workspace.
- Secrets/safefetch: none.
- OpenAPI: no (no route change).

## Acceptance criteria
- [ ] Projects, versions, runs and workflows carry a deletion stamp and a deleter.
- [ ] A soft-deleted item is invisible to every list and API read, as a deleted project is today.
- [ ] Rows deleted before this card are readable without a backfill.
- [ ] Empty, loading and error states above all render (no trash rows, pre-existing rows).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ deletes are hard deletes exactly as today.

## Notes for the implementer
One `soft_delete` helper, four call sites. Do not add a trash table: the stamp on the row is the trash entry, which
keeps restore a one-line update and purge an existing cascade.
