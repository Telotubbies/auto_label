## User story
As an ML engineer, I want to tune training-time augmentation and a few hyperparameters, and to see the dataset's frozen preprocessing beside them, so that I know which knobs still move and which were baked into the pixels.

## UX flow (LabelDesk words)
1. **Train → Advanced → Recipe** — two stacked groups. *From the dataset (locked)*: one line per step the version baked ("Resize 640 · stretch", "Horizontal flip ×2", "Contrast stretch") with a lock icon and the sentence "Baked when the version was generated — changing this here would be a silent lie." *At train time (this run)*: editable rows.
2. **Train-time rows** — grouped: *Augmentation* (flip horizontal/vertical, rotate 90°, scale, translate, HSV, mosaic, mix-up) as switches with a number each; *Hyperparameters* (learning rate, patience, weight decay, freeze layers) under a *Show hyperparameters* disclosure. [empty: a family that accepts none of these shows "This family takes its recipe from the adapter — no train-time knobs."] [loading: the panel renders from the cached options payload; no second request]
3. **Out-of-range value** — the field goes red with the accepted range ("Scale must be between 0 and 1") before submit.
4. **Server disagrees** — a 400 names the field and the range; the message is rendered on the row, not only as a toast.
5. **Random init and mosaic** — the two riskiest knobs carry a one-line warning ("Mosaic rarely helps under 200 images").

- **States** — [error: a server 400 renders on its own row with the accepted range, not only as a toast].

## Backend changes
- Models/schema: none — the chosen recipe lands in `Job.params.options.training` (JSON on the existing `jobs` row) and is echoed into `TrainedModel.metrics.recipe` at register time so the run page can re-read it.
- Routers: `POST {P}/train` body gains `training: dict = {}`. New `apps/backend/app/services/train_recipe.py`: `ALLOWED = {"flip_h": bool, "flip_v": bool, "rotate90": bool, "scale": (0, 1), "translate": (0, 0.5), "hsv": (0, 1), "mosaic": (0, 1), "mixup": (0, 1), "lr0": (1e-6, 1), "patience": (0, 500), "weight_decay": (0, 0.1), "freeze": (0, 24)}`; `validate(training, family) -> dict` raises `ValueError("scale must be between 0 and 1")`; families that accept none (`rfdetr`, `hf`, `sam3`) raise `ValueError("<family> takes its recipe from the adapter — remove the train-time options")`. Unknown keys are a 400, never dropped.
- Services/jobs: `handlers/training.py` passes `opts["training"]` through; `adapters/ultralytics_ad.py::train` maps it onto the `model.train()` kwargs it already passes (`fliplr`, `flipud`, `degrees`→rotate90, `scale`, `translate`, `hsv_h/s/v`, `mosaic`, `mixup`, `lr0`, `patience`, `weight_decay`, `freeze`) — one `kw.update(...)` line, values already validated.
- Permissions + workspace isolation: unchanged (`c.need("admin")`).
- Secrets/safefetch: none.
- OpenAPI: yes — `TrainIn.training` (regenerate both files).

## Acceptance criteria
- [ ] Train-time augmentation and hyperparameters are editable, validated client-side, and validated again by the API with a field-naming 400.
- [ ] The dataset's frozen preprocessing and augmentation render read-only with the reason they cannot change here.
- [ ] A family that owns its recipe refuses train-time options instead of ignoring them.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ today's three-field Advanced panel and no training-time augmentation.

## Notes for the implementer
The version's preprocessing is never re-applied at train time — `Version.settings` is read for display only. `rotate90` maps to ultralytics `degrees: 90`; do not invent a new adapter parameter.
