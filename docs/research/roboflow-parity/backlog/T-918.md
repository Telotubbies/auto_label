## User story
As an ML engineer, I want every finished run filed under a named model with its own version number, so that "ppe-detection v3" means one exact artifact instead of "the third run from Tuesday".

## UX flow (LabelDesk words)
1. **Project → Models** (`/:ws/p/:project/models`) — the rail stops being a pile of runs: each row carries `ppe-detection · v2` under its name, and the run's arch and score stay on the second line. [empty: the first version of a new name reads `v1`] [loading: the rail shows four name skeletons until the list resolves] [error: "Models could not be loaded" + Retry, the rail never shows a half-numbered row]
2. **Train → Run** — the run form gains an optional *Model name* field, prefilled with the project name; the run inherits it, so a finished run needs no second step to appear in the registry. [empty: clearing the field falls back to the project name] [error: a name over 160 characters is refused inline before the run starts]
3. **Model detail** — the header prints `ppe-detection v2` and the dataset version separately ("dataset v4"), because the two numbers are no longer the same thing. [error: a pre-backfill row shows its old name and `v1` rather than a blank chip]
4. **Register an existing run** — the run menu's *Register as model…* accepts a name and returns the row with a number; a name that already exists adds the next version and never overwrites the old one. [loading: the action reads "Registering…" while the row number is assigned] [error: a concurrent registration of the same name gets the next number, never a duplicate]

## Backend changes
- Models/schema: append `"registered_name": "VARCHAR(160) DEFAULT ''"` and `"model_version": "INTEGER DEFAULT 0"` to `TRAINED_MODELS` in `apps/backend/app/schema/training.py` (the `trained_models` step is already in `schema.STEPS`, so nothing else registers). Add the two `Mapped` columns to `TrainedModel` in `apps/backend/app/models/training.py`.
- Backfill: in `bootstrap.py`, next to the existing one-time blocks, set `registered_name = project.slug` for rows where it is empty (join `projects`) and `model_version` by `ROW_NUMBER()` over `(project_id, registered_name)` ordered by `created`. Idempotent: only rows with `model_version = 0` are touched.
- Routers: `GET {P}/models` and `GET {P}/models/{mid}` responses gain `registeredName`, `modelVersion` (`apps/backend/app/routers/training.py` `model_out`). `TrainIn` gains `registered_name: str = ""`; `POST {P}/train` resolves it to `project.name` when empty and stores it on the row at enqueue. New `POST {P}/models/{mid}/register` body `{name: str}` → moves a finished row under `name` and returns `{id, registeredName, modelVersion}`; **409** when the model is not `ready`, **422** on a name that is empty after trimming or longer than 160.
- Services/jobs: `apps/backend/app/services/model_registry.py` (new) — `clean_name(raw, fallback) -> str`, `next_version(db, project_id, name) -> int` (`SELECT MAX(model_version)` over all rows with that name, tombstones included) and `register(db, model, name) -> TrainedModel` raising `ValueError("not ready")`.
- Permissions + workspace isolation: read follows today's `c.perm("project.infer")` / `project.models` split; `register` needs `project.models`; a model id from another project or workspace stays a 404 from `_model` and the endpoint never echoes the id.
- Secrets/safefetch: none.
- OpenAPI: yes — `python tools/export_openapi.py`, `npm run gen:api-types`.

- `test_register_assigns_v1_then_v2` — two ready models registered under `ppe-detection` → `modelVersion` 1 then 2, both rows kept.

## Acceptance criteria
- [ ] Every finished model row has a registered name and a per-name version number from the moment it is registered, and numbers are never reused.
- [ ] A second registration under an existing name adds a version and leaves the first row untouched.
- [ ] Rows created before the upgrade are backfilled once and render their version without a migration run.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
