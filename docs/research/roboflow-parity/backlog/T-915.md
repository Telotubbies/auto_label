## User story
As a data scientist, I want the client I already use to list my runs, pull one metric's full history, list a run's
artifacts and undo a delete, so the notebook workflow is complete rather than write-only.

## UX flow (LabelDesk words)
1. **Notebook** — `POST /api/2.0/mlflow/runs/search` with
   `filter: "metrics.accuracy > 0.9 and tags.team = 'vision'"`, `order_by: ["metrics.accuracy DESC"]`,
   `max_results: 20`, `run_view_type: "ACTIVE_ONLY"`; response is
   `{runs: [{info, data, inputs}], next_page_token}`. [empty: a filter that matches nothing returns `runs: []`, not
   a 404] [error: an unsupported clause returns 400 naming the token and the supported prefixes]
2. **Notebook** — `GET /api/2.0/mlflow/metrics/get-history?run_id=…&metric_key=accuracy` → every point with step and
   timestamp, for a notebook run and for a worker-trained run alike (a trained run's epoch curve is the same series).
3. **Notebook** — `POST /api/2.0/mlflow/runs/delete` then `POST /api/2.0/mlflow/runs/restore` on a notebook run →
   it leaves and re-enters the list, with its params and history intact.
4. **Models** — a notebook run deleted from the notebook disappears from the LabelDesk list too; a restored one comes
   back. A worker-trained run cannot be deleted this way (409, with a pointer to the trash).

## Backend changes
- Models/schema: none new — `ExternalRun` already carries `deleted` (T-914) and `datasets`.
- Routers: `apps/backend/app/routers/mlrun_api.py` — five more routes:
  - `POST /runs/search` (filter, order_by, max_results ≤ 1 000, page_token, run_view_type
    `ACTIVE_ONLY|DELETED_ONLY|ALL`);
  - `GET /metrics/get-history` (`run_id`, `metric_key`, optional `max_results`, `page_token`);
  - `GET /metrics/get-history-bulk-interval` (the sampling summary MLflow clients call for chart ranges — one
    min/max/last per key);
  - `POST /runs/delete`, `POST /runs/restore`;
  - `POST /runs/log-inputs` (`{run_id, datasets: [{name, digest, context, source}]}`);
  - `GET /artifacts/list` (`run_id`, `path`) — delegated to `services/run_artifacts.list_artifacts` (T-911).
- Services/jobs: `apps/backend/app/services/mlrun_wire.py` — `search_runs`, `metric_history`, `history_bulk`,
  `delete_run`, `restore_run`, `log_inputs`, `list_artifacts`; a `translate_filter(text) -> str` that rewrites the
  wire prefixes onto the native grammar T-907 parses (`metrics.` → `metric:`, `tags.` → `tag:`,
  `attributes.status` → `status:`, `attributes.run_name` → a name clause) and raises a 400 with
  `param filters are not supported yet` for `params.`.
  Search unions `ExternalRun` rows and `TrainedModel` rows of the key's project (`deleted` decides the view), so a
  notebook's result list includes the production runs.
- Permissions + workspace isolation: `read` scope for every route except delete/restore, which need `train`;
  every id is resolved inside the key's project; a cross-workspace id is 404.
- Secrets/safefetch: none; `artifacts/list` reuses the signed-URL service and its `DATA_DIR` guard.
- OpenAPI: yes — `python tools/export_openapi.py`, then `npm run gen:api-types`.

## Acceptance criteria
- [ ] Search, history, delete, restore, log-inputs and artifacts/list all answer in the wire shapes a client expects.
- [ ] A notebook result list and the LabelDesk run list show the same runs, in the same order, for the same filter.
- [ ] A cross-workspace id is 404 on every route; a missing scope is 403; no route can widen the key's project.
- [ ] Empty, loading and error states above all render.
  (An empty search is `runs: []`, never an error.)
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: `ML1-T1.15` delete/restore for *trained* runs is T-267 + T-405…T-407 — this route refuses those ids on
purpose rather than growing a second delete path.
`params.` filters are refused, not silently ignored: MLflow's own clients send them, and a filter that quietly
matches everything is worse than a 400. Convert `order_by` entries of the form `"metrics.accuracy DESC"` before
handing them to `run_filter`, which expects `sort:-metric:accuracy`.
