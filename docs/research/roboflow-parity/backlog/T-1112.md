## Problem
`apps/backend/tests/test_streams.py` fails only when the full serial suite runs while other lanes load the machine. The failures seen so far, each of which passes alone:
- `test_vlm_rule_fires_on_yes_and_skips_while_sleeping`
- `test_start_enforces_the_plan_stream_cap`
- `test_stop_returns_when_source_never_opens`

`B:/02_Projects/ld-tmp/lanes/flaky.log` lists each run.

## Steps
1. Find every wall-clock dependency in these tests and the code they exercise: `time.sleep`, fixed timeouts, thread joins with a deadline, and sampling intervals.
2. Replace each one with an injected clock or event, or a poll with a generous upper bound. Keep the timeout at the edge of a test, never in the test's inner logic.
3. Prove it: run the three tests 20 times in a row while a CPU burner runs (`python -c "while True: pass"` × 4). Paste the numbers into the report. Never use xdist. Never skip a test or loosen an assertion.

## Files
Only `apps/backend/tests/test_streams.py`, plus `services/streams*.py` if a clock seam is needed there. The report must justify any production change.
