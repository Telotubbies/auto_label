## User story
As an integrator wiring LabelDesk into an MES, I want a fixed JSON envelope with a version, a preview I can code against, a delivery log and a dead-letter I can replay, so that I am not reverse-engineering a timeline row and a summary string.

## UX flow (LabelDesk words)
1. **An output is configured per station** — transport `webhook` in this card, a URL, and a filter (kinds, classes, verdicts); `GET …/event-outputs/envelope/preview` returns the exact JSON with a sample event, read-only. [empty: no output configured keeps events in the timeline, and the T-696 screen says so]
2. **`ส่งเหตุการณ์ทดสอบ`** — posts the preview envelope and reports the status and the latency. [error: `ส่งไม่สำเร็จ — ตรวจ URL และการอนุญาตเครือข่าย`] [loading: `กำลังส่ง`]
3. **The delivery log** — the last twenty attempts per output with state, attempt count, status code and the next retry; a failed attempt retries three times with a backoff and then moves to the dead-letter. [error: `เข้า dead-letter แล้ว — ตรวจสอบปลายทาง`]
4. **Replay** — `POST /deliveries/{id}/replay` resends one dead-lettered envelope; `POST /…/replay?since=` resends the last N events to a new subscriber, bounded to 500.
5. **A new subscriber** — the replay is the onboarding path: a data-lake team gets the last day without asking us to re-run anything.

## Backend changes
- Models/schema: `app/models/event_sink.py` (new) — `EventSink(id, workspace_id, project_id, station_id nullable, name, transport ('webhook'|'mqtt'), config JSON, filter JSON, schema_version, enabled, created, updated)` with `UniqueConstraint(project_id, name)`; `SinkDelivery(id, sink_id, workspace_id, project_id, event_id, state ('sent'|'failed'|'dead'), attempts, status_code, last_error, next_try, created)` with `Index(sink_id, created)`. Register in `models/__init__.py`; `create_all` creates both, no `ADD COLUMN`.
- Routers: `app/routers/event_outputs.py` (new), prefix `/api/ws/{ws}/projects/{project}/event-outputs`, `dependencies=[Depends(require_flag("task_event_envelope"))]`; `GET ""`, `POST ""` (201), `PATCH /{id}`, `DELETE /{id}`, `GET /envelope/preview?event_id=`, `POST /{id}/test`, `GET /{id}/deliveries`, `GET /{id}/dead-letter`, `POST /deliveries/{did}/replay`, `POST /{id}/replay?since_hours=` (≤ 500 events). 400 for a bad URL or filter, 409 duplicate name.
- Services/jobs: `app/services/event_sinks.py` (new) — `SCHEMA_VERSION = "1.0"`, `envelope(event, station, stream, model) -> dict` with the fixed keys `schema_version, site, line, station, camera{id, name}, event{id, ts, kind, rule, summary}, objects[{class, class_id, confidence, track_id, box}], verdict{value, reason, piece_id, operator}, model{ref, name}, timestamps{device, server}`; `validate_envelope(d)` (the test asserts the key set never drifts); `matches(sink, event)`; `dispatch(db, project, event)`; `deliver(db, delivery)` through `services/safefetch.post` (three attempts, 2/8/30 s backoff, then `dead`); `replay(db, sink, since_hours)`. The stream worker calls `dispatch` beside the existing `alert_bridge`/`ot_bridge` calls, so a slow broker never delays capture.
- Permissions + workspace isolation: read `project.read`, write `project.settings`; sinks, deliveries and replays are filtered by `workspace_id` **and** `project_id`; a foreign sink or delivery id is 404, and an envelope never carries another project's station or camera names.
- Secrets/safefetch: `services/safefetch.post` is the guard — a webhook URL is resolved and pinned per hop, private addresses are refused, and a redirect to a private address is blocked. A sink URL that fails the check is 400 at save time and `dead` at send time, never a raw socket write.
- OpenAPI: yes — nine routes and their schemas.

## Acceptance criteria
- [ ] An output names a transport, a URL and a filter, and the envelope preview shows the exact JSON the subscriber receives with its schema version.
- [ ] A matching event writes one delivery per output; a non-matching event writes none.
- [ ] Three failed attempts move a delivery to the dead-letter, and one delivery or a bounded range can be replayed.
- [ ] Empty, loading and error states above all render — no output configured leaves events in the timeline and a private URL is refused with a sentence.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the routes 404, nothing is dispatched, and the event payload is today's.

## Notes for the implementer
The envelope is a contract: `validate_envelope` runs in a test so a key can never be renamed quietly, and the version increments only with a card that changes it. Two rules for the dead-letter: never retry forever (three attempts then `dead`) and never drop the payload (it is small JSON beside the event id, so a replay months later still carries the original numbers). Copy: `events.output.test`=`ส่งเหตุการณ์ทดสอบ`, `events.output.sending`=`กำลังส่ง`, `events.output.sendFailed`=`ส่งไม่สำเร็จ — ตรวจ URL และการอนุญาตเครือข่าย`, `events.output.dead`=`เข้า dead-letter แล้ว — ตรวจสอบปลายทาง`, `events.output.empty`=`ยังไม่มีเอาต์พุต — เหตุการณ์อยู่ในไทม์ไลน์ตามเดิม`.
