## User story
As the QA engineer, I want fake `uv`/`python`/`docker` executables and a fake hub behind every
install/download test, plus a guard that fails on a real network call, so that CI is fast, hermetic and
incapable of downloading 15 GB.

## UX flow (LabelDesk words)
No new screen. What the harness lets a reviewer see in the report:
1. An install job that runs a fake engine to completion and reports two engines installed.
2. A download job against a 1 MiB local file that resumes, verifies and finishes.
3. A deliberate checksum mismatch that deletes the partial data and fails.
4. A test run that fails immediately if anything opens `huggingface.co`, `pypi.org` or a registry.

## Tests to write first
pytest — `apps/backend/tests/test_inference_no_network.py`:
- `test_no_test_opens_a_real_host` — install a `socket.socket` wrapper in a session fixture that raises
  on `connect` to any host except `127.0.0.1`; the whole inference test package runs under it.
- `test_the_guard_itself_fails_closed` — a deliberate connect to `huggingface.co:443` inside a
  `pytest.raises(SocketBlocked)` proves the guard is armed (skipped when the fixture is disabled).
- `test_the_models_directory_is_a_temp_path` — `LD_MODELS_DIR` points under `B:\02_Projects\ld-tmp` in
  the test env and the repo tree contains no `.gguf`, `.safetensors` or `.bin` above 1 MiB.
pytest — `apps/worker/tests/conftest.py` behaviours (exercised by T-1008/T-1011 tests):
- `test_fake_uv_records_its_argv` — running the fake writes each argv to `$FAKE_LOG`; a test can assert
  exactness without trusting the code under test.
- `test_fake_hub_serves_a_1_mib_file_with_range_support` — `GET /file` and `Range: bytes=409600-` return
  206 with the right bytes and an `ETag` matching the fixture sha256.
- `test_fake_hub_metadata_reports_lfs_oid` — `GET /api/models/{repo}/revision/{rev}` returns file entries
  with `lfs.oid` equal to the fixture digest.
- `test_paths_are_created_under_tmp_and_removed` — the session fixture leaves nothing outside
  `B:\02_Projects\ld-tmp\pytest`.

## Acceptance criteria
- [ ] Every install/download test runs against fake executables and a local HTTP fixture.
- [ ] A real outbound connection fails the test session, proved by a self-test.
- [ ] The fake hub supports `Range`, `ETag` and `lfs.oid`, so resume and checksum paths are real tests.
- [ ] No weight file is added to the repository, the image or the cache by the suite.
- [ ] The suite passes with `HF_TOKEN` unset and with a dummy value set.
- [ ] Windows and POSIX both have an executable fake for each engine runtime used by the cards.

## Notes for the implementer
Prefer one `conftest.py` with small fixtures over a mock library. The fakes are scripts, not Python
mocks, because the worker calls `subprocess` — mocking `subprocess` would test the mock, not the argv.
Keep the fake hub to the four endpoints the worker uses; a full HF emulator is out of scope.
