## User story
As a workspace admin, I want the four sign-in questions on one page with the consequence of each written underneath, so that I can tighten the workspace without locking out the night shift to find out.

## UX flow (LabelDesk words)
1. **Settings → Workspace → `Sign-in security`** (`/:ws/settings/workspace`) — the shipped card keeps its MFA row and gains three: `Idle sign-out`, `Maximum session`, `Allowed networks`. Every control carries a live consequence line in plain words: `"A shared tablet will be signed out after 30 minutes without a request."` / `"แท็บเล็ตที่ใช้ร่วมกันจะถูกออกจากระบบเมื่อไม่มีการใช้งาน 30 นาที"`. [loading: the card's shipped "Loading security settings…" line] [error: "Could not load this workspace's security setting." + **Try again**]
2. **Changing a value** — the control is a `Select` with the shipped values (idle: 15 / 30 / 60 minutes, 2 / 8 hours; session: 8 hours / 24 hours / 7 days / 30 days) plus the step-up switch; the consequence line rewrites before the save, as the user picks. Saving asks for the step-up sheet (T-741) and only then writes.
3. **Allowed networks** — a monospace textarea, one CIDR per line, with `"Empty means every address can sign in."` and, on save, the lockout refusal from T-742 printed inline under the field. [empty: the textarea reads empty and the consequence line says every address is allowed]
4. **Members → a member's row → `Sessions`** (`/:ws/settings/members`) — a sheet lists that member's devices: device label from the shipped `describeDevice()`, IP, last seen, "signed out at 14:20". One `Revoke` per row with `"Revoke the session from Chrome on Windows? That device will be signed out."` [empty: "This member has no sessions on this server."] [loading: three skeleton rows]
5. **A member's own view** — `Settings → Security` already lists the caller's sessions; with none it reads `"No other sessions."` (never an empty table).
6. **Locked out by an address rule** — the workspace pages render the blocked view instead of the shell: the sentence from T-742, the CIDR list, the caller's address in monospace, and **Copy my address** plus **Email the owner** (a `mailto:` built from the 403 body's `contact`). No form posts anywhere.

## Backend changes
- Models/schema: none — every column and route was created by T-740 and T-742.
- Routers: none — the screen reads `GET /api/ws/{ws}` (policy, ranges, caller ip), writes `PATCH /api/ws/{ws}`, and uses `GET/DELETE /api/ws/{ws}/members/{uid}/sessions`.
- Services/jobs: none.
- Permissions + workspace isolation: the screen is hidden for non-admins (the tab already is), and every write is refused server-side; a member id from another workspace is 404 by T-740.
- Secrets/safefetch: none.
- OpenAPI: no (no route in this card).

## Acceptance criteria
- [ ] The page shows the four controls with a consequence line each, and the line rewrites as the value changes.
- [ ] Saving any control goes through the step-up sheet, and a cancelled sheet writes nothing.
- [ ] A range list that excludes the admin is refused inline with the lockout sentence; a malformed entry names the entry.
- [ ] An admin opens a member's sessions, revokes one, and the row disappears; with none, the sheet shows "This member has no sessions on this server."
- [ ] Empty, loading and error states above all render: the empty textarea sentence, the skeleton rows, the load error with **Try again**, and the blocked view.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — a foreign member id surfaces the generic "not found" sentence.
- [ ] Flag off ⇒ no policy card, no Sessions action, no blocked view; the workspace looks and behaves exactly as today.

## Notes for the implementer
The consequence line is the whole feature: "signed out after 30 minutes" is what stops an admin typing 15 into a factory tablet policy. Keep the numbers in one list (`IDLE_CHOICES`, `SESSION_CHOICES`) so the API range in T-740 and the `Select` cannot drift. Do not add a per-member override — the group file asks for one workspace policy, and a per-member exception is the thing that makes an auditor ask which policy was in force.
