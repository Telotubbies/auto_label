## User story
As a privacy officer, I want to erase one person's appearances through the store that already knows every byte we hold, and download a certificate naming the operator, the time and the hash, so that an erasure is a record rather than a support ticket.

## UX flow (LabelDesk words)
1. **Workspace sidebar → `Compliance`** (`/:ws/compliance`) — a new GOVERN item opening a page with two tabs, `Requests` and (after T-754) `Processing register`. [empty: "No requests yet — nothing is due." / "ยังไม่มีคำขอ — ไม่มีกำหนดที่ต้องดำเนินการ"] [loading: three skeleton rows] [error: "Could not load requests." + **Try again**]
2. **`New request`** — a dialog: kind (`Access`, `Erasure`, `Objection`), a subject label, and up to ten identifiers, one per line, with the hint `"A name, a staff id, an email or one reference frame id."` The row then carries a countdown chip: `"in 12 days"`, `"due today"`, `"4 days overdue"` (destructive tone).
3. **A case row → the case panel** — the countdown, the identifiers, the three actions `Find`, `Export`, `Erase`, and the store counts after a find. [error: the 404 sentence when another browser deleted it]
4. **`Erase`** — a confirm listing what will go: `"12 frames and their thumbnails, 3 alert deliveries' snapshots. Audit rows are kept. This cannot be undone."` then a job with a progress line per store (`frames 12/12`, `thumbnails 12/12`, `snapshots 3/3`).
5. **Partial failure** — `"4 frames could not be deleted — locked, retry scheduled."` in the warning tone, the certificate says so, and the case stays `open`. [error: that sentence, never a green tick]
6. **`Download certificate`** — a `.txt` naming the case, the operator, the time, every store touched, every failure and a SHA-256 over the manifest.

## Backend changes
- Models/schema: none — the case row carries the status, and the certificate is generated from the case plus its audit rows, so there is nothing else to erase later.
- Routers: in `app/routers/compliance.py` — `POST /compliance/requests/{id}/erase` → `{job_id}`; `GET /compliance/requests/{id}/certificate` → `text/plain` attachment `dsar-<case>-certificate.txt` (409 until the case is `erased` or has recorded failures).
- Services/jobs: `app/services/dsar.py` gains `erase(db, ws, request) -> dict` (re-runs the T-751 search, then for every image hit calls the one shipped byte path `erasure.delete_image_files` and the row cleanup, collects `{store, ref, result}` and `failures`, sets `erased` only when `failures` is empty) and `certificate(db, ws, request) -> tuple[bytes, str]` (text plus its SHA-256). `app/services/erasure.py` gains `delete_image(db, img) -> tuple[int, bool]` — the three statements `retention._clean_project` and `routers/images.delete_image` already spell out — so the DSAR path shares the byte deletion instead of inventing a second one. `app/handlers/ops.py` gains `run_dsar_erase(job)`; `dsar_erase` joins the `LD_LOCAL_JOBS` default string.
- Permissions + workspace isolation: `workspace.update`; the case, the hits and every file path resolve inside `c.ws.id`, and each path is checked with `erasure.inside()` before removal, so a foreign id is 404 and a tampered path removes nothing.
- Secrets/safefetch: none — no download, no URL; the certificate is a local text file built from rows the API already returns.
- OpenAPI: yes — two routes and the erase result shape.

## Acceptance criteria
- [ ] A case shows its countdown, identifiers and store counts, and the three actions run against the routes above.
- [ ] Erase deletes the matched bytes through the shipped erasure service, keeps audit rows, and leaves the case `open` when any file survives.
- [ ] The certificate is a text file naming the operator, the time, every store, every failure and a SHA-256 over the manifest.
- [ ] Empty, loading and error states above all render: the empty request list, the per-store progress line, the locked-file sentence and the 409 before erasure.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no Compliance item, no route, no erase job and no certificate.

## Notes for the implementer
