## User story
As a bank's security lead, I want to know exactly where our images would be written and what happens when this deployment cannot write to our bucket, so that "we will support it" is not the answer I take back to the committee.

## UX flow (LabelDesk words)
1. **Settings → Storage** (`/:ws/settings/storage`) — one `Card` reads the current mode: "LabelDesk storage" with the sentence "Images, models and exports are written to this deployment's own data directory." [loading: the card renders a skeleton row] [error: "Couldn't read this workspace's storage settings." + `Try again`]
2. **`Customer bucket` selector** — the option is present and disabled, with the line "Not available in this deployment." and a `What this needs` link that opens a short explanation sheet (write access, a prefix, a key reference, and that existing data would have to migrate).
3. **A deployment that does configure a driver** — the card reads "Customer bucket — <endpoint>/<bucket>/<prefix>" with the chip "Configured" and `Test write` (T-769). [empty: no bucket configured ⇒ "No bucket configured." with the same disabled selector]
4. **Key reference** — a read-only row "Key reference — not configured" until T-769 stores one; never a blank value.
5. **Flag off** — no Storage tab and every route 404s.

## Backend changes
- Models/schema: `workspaces` gains `storage_mode VARCHAR(16) DEFAULT 'local'`, `bucket_config JSON`, `kms_ref JSON` in `app/schema/identity.py` (`WORKSPACES`); existing rows read `local`, no backfill.
- Routers: `app/routers/storage.py` (new) — `GET /api/ws/{ws}/storage` returns `{mode, available, reason, bucket: {endpoint, bucket, region, prefix} | null, key: {state, arn_tail, region} | null}` with the credential never echoed; `PUT /api/ws/{ws}/storage/mode` accepts `local` only in this card (422 for `bucket` with the not-available sentence).
- Services/jobs: `app/services/storage_driver.py` (new) — `StorageDriver` protocol (`put(rel, data) -> str`, `open(rel) -> bytes`, `delete(rel) -> bool`, `probe() -> dict`), `LocalDriver` (wraps `config.DATA_DIR`), `MockBucketDriver` (in-memory dict, used by the suite and the demo), `UnavailableDriver` (every method raises `StorageNotAvailable`), `driver_for(db, ws) -> StorageDriver`, `mode_of(ws) -> str`, `describe(ws) -> dict`. No import of boto3, a GCS client or an Azure SDK anywhere in the module.
- Permissions + workspace isolation: `workspace.update` to change the mode, `workspace.read` to read it; the driver is built from the calling workspace only, so a bucket config from workspace B is never addressable.
- Secrets/safefetch: `services/secretbox.encrypt_config` is the only writer of `bucket_config` (this card writes nothing; it defines the contract T-769 uses).
- OpenAPI: yes.

## Tests to write first
pytest — `apps/backend/tests/test_storage_driver.py`:
- `test_a_workspace_starts_on_local_storage` — `GET /storage` → `mode == "local"`, `available is True`, `bucket is None`, `key is None`.
- `test_choosing_a_customer_bucket_is_422_in_this_deployment` — `PUT …/storage/mode {"mode": "bucket"}` → 422 with "Not available in this deployment." in the detail, and the row stays `local`.
- `test_the_mock_driver_round_trips_a_file` — `driver_for` with the mock selected → `put("a/b.txt", b"x")`, `open` returns `b"x"`, `delete` returns True, `probe()["ok"]` is True.
- `test_the_unavailable_driver_refuses_every_method` — the unavailable driver → `put`, `open` and `probe` each raise `StorageNotAvailable` and never touch `DATA_DIR`.
- `test_no_vendor_sdk_is_imported` — importing `app.services.storage_driver` leaves `boto3`, `google.cloud.storage` and `azure.storage.blob` out of `sys.modules`, and the module source holds no `import boto3`.
- `test_a_labeler_cannot_change_the_mode` — labeler `PUT` → 403, `GET` → 200.
- `test_flag_off_hides_both_routes` — with `task_customer_storage` off → `GET` and `PUT` 404.

node — `apps/frontend/tests/storage-mode.test.mjs`:
- `test_unavailable_reads_as_one_sentence` — `availability({available: false, reason: 'not_available'})` is "Not available in this deployment." and has no trailing detail code.
- `test_a_bucket_line_never_shows_a_credential` — `bucketLine({endpoint:'https://s3.example', bucket:'acme', prefix:'acme/'})` contains the three parts and no `key`, `secret` or token field.
- `test_an_unset_key_reads_not_configured` — `keyLine(null)` is "Key reference — not configured", never an empty string.

## Acceptance criteria
- [ ] The Storage tab reads the current mode and states in one sentence where bytes are written.
- [ ] Selecting a customer bucket in this deployment is refused with 422 and the sentence "Not available in this deployment."
- [ ] The driver seam round-trips a file through the mock driver and refuses through the unavailable driver without touching disk.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no tab, no route, both endpoints 404, and every write still lands in `DATA_DIR`.

## Notes for the implementer
Owner-gated: whether LabelDesk may offer customer-owned storage at all, and which storage targets the first real driver must support (INDEX §4.3). Interface-first by owner rule: the protocol, the mock and the explicit refusal are the deliverable; a real bucket driver is a later card with its own review. Keep the reason string in one place (`storage_driver.REASON`) so the UI, the 422 and the tests cannot drift into three different sentences, and never let a credential enter `describe()`.
