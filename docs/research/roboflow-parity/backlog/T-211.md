## User story
As an engineer with 200 images, I want to vary each object's appearance inside its own box, so that augmentation stops teaching the model a new background.

## Backend changes
- Models/schema: none.
- Routers: none.
- Services/jobs: `app/services/imaging.py` — `augment_in_boxes(im, anns, op, params, rng)` shares one mechanism: build a mask from all annotation shapes (`ImageDraw.polygon` for polygons, rectangle for boxes, filled ellipse-capable for keypoints skippable), crop each object's bbox, apply the op to the crop (photometric ops from T-210, flip/rotate from T-209), paste back through the mask. Geometry ops inside a box **do not move the box** — the object is re-composited inside the same frame region, and the annotation geometry is kept (documented rule).
- Permissions + workspace isolation: unchanged.
- Secrets/safefetch: none.
- OpenAPI: no.
- Flag: `task_190` off ⇒ `scope: "box"` is a 400 `aug_scope_unavailable`; `scope: "box"` with a premium-gated plan is `aug_tier_unavailable`.

## Acceptance criteria
- [ ] Box-scoped ops change only the object's pixels; the background is byte-identical.
- [ ] Box geometry is preserved for photometric ops and documented for geometric ones.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the scope control is absent and the API rejects `scope: "box"`.

## Notes for the implementer
One mask for all objects, one paste per object: build `PImage.new("L")` at full size, draw every shape white, and `Image.composite(augmented, base, mask)`. The rule to print in the UI: *"Inside each box moves the object's pixels, not the box."*
