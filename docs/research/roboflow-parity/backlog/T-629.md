## User story
As a customer with a compliance rule, I want a small script of my own to run when a label is saved, so that a mandatory ID format or attribute is enforced by the platform rather than by a polling listener I have to host.

## UX flow (LabelDesk words)
The screen is T-630; this card owns installing and running the package.
1. **`POST /extensions`** — a single `.py` entry file of at most 64 KiB, a name and a set of events (`label.submitted`, `label.reviewed`, `label.skipped`); stored as source, never executed at install. [error: "Package over the size limit." (413)] [error: "Only a single .py entry file is accepted." (422)]
2. **`POST /extensions/{id}/test {image_id}`** — queues one run and returns the run id, so the screen can poll. [loading: the run row shows `running`]
3. **A save on a project with an enabled extension** — one `extension_run` job is queued with the image payload; the save is never blocked by the extension. [error: "No runner available — start a worker and try again." (409) when no worker claims the job within the queue timeout, surfaced in the run row]
4. **Run history** — `GET /extensions/{id}/runs` returns status, output (stdout JSON, capped at 4 KiB) and the error tail for a failure.
5. **A disabled extension** — a save queues nothing and the history shows no new rows.

## Backend changes
- Models/schema: new `app/models/extensions.py` with `Extension` (`id`, `workspace_id`, `project_id` nullable, `name`, `entry` Text, `events` JSON, `enabled` Boolean default False, `size` Integer, `created_by`, `created`, `updated`) and `ExtensionRun` (`id`, `extension_id` FK CASCADE, `workspace_id`, `project_id`, `image_id`, `event` String(32), `status` in `queued|running|done|failed`, `output` Text default `''`, `error` Text default `''`, `created`, `finished`), registered in `app/models/__init__.py`. Tables via `create_all`.
- Routers: `routers/extensions.py` (new), prefix `/api/ws/{ws}/projects/{project}/extensions` — `GET ""`, `POST ""` (multipart: file ≤ 65536 bytes, name, events), `PATCH "/{id}"` `{enabled?, events?}`, `DELETE "/{id}"`, `POST "/{id}/test"` `{image_id}`, `GET "/{id}/runs"`. 413 over the size limit, 422 for a non-`.py` file or an unknown event, 409 when the job is not claimed by a worker, 404 for a foreign extension or image.
- Services/jobs: `app/services/extensions.py` (new) — `install`, `enabled_for(db, project_id, event)`, `queue_run(db, extension, event, image)` (writes a `Job(kind="extension_run")` and one `ExtensionRun`), `payload(db, image)` (class names, annotation counts, image id — never file paths or secrets); `app/handlers/extensions.py` (new) — `run_extension(job)` writes the entry to a temp file and runs it in a child interpreter (`sys.executable -I`) with a 5 s wall clock, JSON on stdin and capped stdout, then records status and output. `HANDLERS` entry in `handlers/extensions.py`, module added to `app/handlers/__init__.py::MODULES`, `app/worker.py` import, and `extension_run` appended to `config.LOCAL_JOB_KINDS`.
- Permissions + workspace isolation: `c.need("manager")` on every route; the extension and its runs are filtered by `c.project.id`, so a foreign id is a 404; the payload carries only project data of the owning workspace.
- Secrets/safefetch: none for delivery; the child gets no environment variables beyond `PATH`, no network interface is granted and `services/safefetch.py` is not used — the runner is a subprocess, not a fetcher.
- OpenAPI: yes.

## Acceptance criteria
- [ ] A manager installs one `.py` entry with events, and a save on an enabled extension queues exactly one run.
- [ ] A run records its stdout as output, a failure as status plus an error tail, and never touches the annotation.
- [ ] An entry that loops is killed inside the limit and cannot stop the worker from taking the next job.
- [ ] Empty, loading and error states above all render where the surface exists: 413 size, 422 file or event, 409 no runner, 404 foreign id.
- [ ] Workspace A cannot install, list or run workspace B's extension (404, not 403).
- [ ] Flag off ⇒ no routes, no queued runs, and the worker does not register the handler.

## Notes for the implementer
Owner-hold: BEYOND §4 names this as a non-goal; do not schedule until the owner overrules it.
The scope here is deliberately one entry file, three events and a run log — no marketplace, no organisation-level apps, no dependency install. Say plainly in the R7 note that the subprocess is a resource boundary, not a security boundary (no seccomp on Windows), and that the flag being off by default is the actual control.
