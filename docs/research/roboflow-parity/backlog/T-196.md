## User story
As a reviewer, I want to assign each tag to *Required*, *Excluded* or *Allowed* and immediately read how many images survive, so that I can freeze a slice of the dataset without guessing.

## UX flow (LabelDesk words)
1. **Wizard → step 1 — What enters this version** — a table of tags with three radio columns; the header of each column is a button that sets the whole list to that role. Above it: "**84 of 96 approved images** will be frozen" and the rule sentence from today's copy. [empty: "No tags on this project yet." with a link to the Annotate board] [loading: three skeleton rows, the count reads "…"] [error: "Could not load tags — retry"]
2. **Click a radio** — the count line updates from the preview response within the same render pass; a tag set to *Required* while another is *Excluded* shows both as chips under the count.
3. **Reset** — "Reset rules" clears every role back to *Allowed* in one click; the button is disabled when nothing is set.
4. **Zero match** — the count line turns warning-coloured: "No images match these rules — adjust or reset." and *Continue* stays enabled (the server refuses at Create with the same words).
5. **Static crop / preprocessing** stays in step 3; this step owns selection only.

## Tests to write first
node — `apps/frontend/tests/tag-rule-matrix.test.mjs`:
- `test_set_all_column_sets_every_role` — `setAll(rules, 'exclude')` returns one rule per tag, all `exclude`.
- `test_decision_matrix_orders_exclude_first` — `tagDecision([{tag:'a',role:'require'},{tag:'a',role:'exclude'}], ['a'])` → `'drop'` (exclude wins over require).
- `test_allow_passes_untagged_images` — a rule `allow` on `a` leaves an image tagged `b` in the pool.
- `test_toggling_a_role_keeps_the_other_tags` — switching `site-a` from allow to require leaves `site-b` untouched.
- `test_reset_clears_every_rule` — `reset(rules)` → `[]`, and `isDirty([])` is false.
- `test_zero_match_copy` — `countLine({matched: 0, total: 96})` → `"No images match these rules — adjust or reset."`.
- `test_count_line_reads_matched_of_total` — `countLine({matched: 84, total: 96})` → `"84 of 96 approved images will be frozen"`.
pytest — `apps/backend/tests/test_version_tags.py`:
- `test_preview_pool_matches_the_generation_pool` — the same rules produce an equal `pool.total` on preview and `stats.source_images` after generation (guards the two code paths from drifting).
