## User story
As the engineer calling the API, I want a real image and a real response for this exact version, so that I can tell a correct call from a malformed one without producing a test image.

## UX flow (LabelDesk words)
1. **Model detail → Example** — beside the contract, the first correctly detected evaluation image is shown as a small thumbnail with the response it produced, copyable as JSON. [empty: a model with no evaluation shows "No example yet — run an evaluation to create one." and hides the copy button] [loading: the thumbnail box holds a 4:3 frame while the signed URL resolves] [error: an image that has since been deleted shows "Example unavailable" and a *Regenerate* link that explains it needs a new evaluation]
2. **Open it in the tester** — *Try this image* on the example (and on the Deploy page's example card) loads it into the existing tester at the current confidence. [loading: the tester shows "Running inference…" as today] [error: a failed inference keeps the image and reports the API message]
3. **Which image** — the example is the detection with the highest confidence among the evaluation's correct rows, so it is stable across reloads; a segmentation model shows its polygon overlay, a classifier shows the true label. [empty: an evaluation whose rows are all wrong ⇒ "No correct detection to show"; the image is not picked]
4. **Reader** — a role without `project.models` gets no example, because it already gets no evaluation.

## Backend changes
- Models/schema: none — the evaluation report already stores per-image detections (`TrainedModel.metrics.eval.detections`, read by `apps/backend/app/routers/training.py:131-143`).
- Routers: `GET {P}/models/{mid}/example` → `{file, url, body, source: "eval", note}` where `url` is a signed path via the existing `sign_path`; **404** for a foreign or deleted model; **200** with `file: null` and a `note` when there is no usable detection.
- Services/jobs: `apps/backend/app/services/model_example.py` (new) — `pick_example(model) -> dict | None` (highest-confidence correct detection, deterministic tie-break on file name), `example_body(model, detection) -> dict` matching the contract's output shape, `example_note(model) -> str`.
- Permissions + workspace isolation: `c.perm("project.models")`; the signed URL path is the same `versions/{version_id}/{split}/{file}` the evaluation already serves.
- Secrets/safefetch: none.
- OpenAPI: yes — one route; regenerate both files.

## Acceptance criteria
- [ ] A model with a successful evaluation shows one real input image and the response it produced.
- [ ] The example is deterministic across reloads and matches the version's contract.
- [ ] A model without an evaluation, or with a deleted image file, degrades to a sentence and never to a broken image.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: none — `5-F5.16` is training curves; this is a stored-in-place example read from the evaluation, so add no column. Deterministic selection matters more than "the best": tie-break on file name and document it, or two reviewers will disagree about which image the page is showing.
