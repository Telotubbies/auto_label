## User story
As the engineer wiring a model into a camera pipeline, I want one screen that states the request, the response and the parameters with their defaults, so that I stop reverse-engineering the sample snippet.

## UX flow (LabelDesk words)
1. **Model detail → Contract** — three small tables, generated from the model's task: *Input* (`image` — multipart file or `image=` URL, JPEG/PNG/WebP, ≤ 20 MB, long edge ≤ 8 192 px), *Output* (`predictions[]` with `class`, `class_id`, `confidence`, centre-based `x`, `y`, `width`, `height`, and `points` for segmentation; `image`; `time`), *Parameters* (`confidence` 0–1 default 0.40, `overlap` 0–1 default 0.50, `tile_size` px default 0 — 0 means off). [empty: a model whose task is not one of detect/segment/classify shows "Contract unavailable for this task" and the call still works] [loading: the panel renders immediately from the model's task, no request needed] [error: a failed fetch shows "Contract could not be loaded" + Retry, the rest of the page unaffected]
2. **Copy a request** — each parameter row states whether it is honoured by the hosted route or only by the in-browser tester, and one button copies a `curl` for this exact version built from the contract. [error: copy blocked by the browser falls back to selecting the text]
3. **Class names are data** — the output example names the model's first class, never a hard-coded `object`, and a segmentation model's example carries `points`.
4. **API** — `GET {P}/models/{mid}/contract` returns the same JSON; a foreign id is a 404. [error: an unknown model is a 404 with a sentence, not a stack]
5. **Reader without `project.models`** — the panel is absent from the masked payload.

## Backend changes
- Models/schema: none — the task is on the row (`apps/backend/app/models/training.py:43`) and the accepted parameters are in the handler (`apps/backend/app/routers/training.py:340-343`).
- Routers: `GET {P}/models/{mid}/contract` → `{input: [...], output: [...], params: [...], example: {curl}, task, version}`; **404** for a foreign or deleted model.
- Services/jobs: `apps/backend/app/services/model_contract.py` (new) — `contract(model, base_url) -> dict` switching on `model.task` (`detect` / `segment` / `classify`), `param_specs() -> list[dict]` (name, type, default, min, max, honoured_by), `curl_for(model, base_url) -> str`. No schema language, no validator: the route documents the shape, the predict handler stays the enforcement point.
- Permissions + workspace isolation: `c.perm("project.models")`; `_model` 404s another project's id.
- Secrets/safefetch: none — `base_url` comes from the request origin, never from stored state.
- OpenAPI: yes — one route; regenerate both files.

## Acceptance criteria
- [ ] Every version shows its input, output and parameter contract, generated from its task, with defaults and ranges.
- [ ] The contract distinguishes detect, segment and classify, and never hard-codes a class name.
- [ ] A copyable request is built from the contract, and an unknown task degrades to a note rather than an error.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: none — `6-F6.10` declares a workflow's inputs for an external caller; this declares one model version's HTTP shape. Do not invent a type system: the contract is data, and the handler remains the only validator. `tile_size` is honoured only when the tiling flag is on for the workspace, so mark it "off for this workspace" instead of hiding it.
