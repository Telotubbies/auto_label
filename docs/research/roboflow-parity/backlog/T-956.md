## User story
As an engineer, I want the tracing of a library call switched on once for a project, so that no adapter file
and no customer script has to be decorated by hand.

## UX flow, click by click.
1. **Project settings → Tracing** — a table of the components LabelDesk can trace on its own: *Ultralytics*,
   *RF-DETR*, *HF transformers*, *SAM 3*, *Qwen-VL over the OpenAI-compatible endpoint*, *CLIP embeddings*,
   each with a switch, the installed version and "records: tokenizer, forward, postprocess". [empty: an
   install with no adapter available reads "not available in this install" with the reason, switch hidden]
2. **Turn one on** — the row shows *Tracing since 12 Nov* and the last captured trace as a link. [error: an
   integration that fails to import is reported per component and never fails a request]
3. **Run the model** — the trace of a playground call now contains the framework's own spans under the
   adapter span, with the library's names kept, so a tokenizer cost is separable from a forward pass.
4. **Turn it off** — the switch stops new spans; existing traces stay until retention drops them, and the row
   says when tracing stopped.

## Backend changes
- Models/schema: `TracingSetting(project_id PK, component, enabled, since, updated_by)` in
  `apps/backend/app/models/evaluation.py` (one row per component that was ever toggled).
- Routers: `GET {P}/tracing/settings` → `{components: [{key, label, available, reason, enabled, since}],
  }`; `PUT {P}/tracing/settings/{component}` body `{enabled: bool}` → the updated row. 400 for an unknown
  component; 409 when `available` is false.
- Services/jobs: `apps/backend/app/services/tracing.py` gains `instrumented(component)` — a context manager
  that opens a span around the adapter call and, when the component is enabled, also records the library's
  own sub-steps from the metadata the adapter already gets back (Ultralytics `results.speed`, RF-DETR's
  `postprocess` timing, tokenizer ids from the VLM response's `usage`). Wrapping happens in
  `apps/backend/app/adapters/catalog.py` where `Resolved.predict` dispatches, so no adapter file is edited.
  The metadata is optional everywhere: a missing key means "no sub-step", never an error.
- Permissions + workspace isolation: read `project.review`, write `c.need("admin")`; a foreign project is a 404.
- Secrets/safefetch: none. Dependency: none added (no `mlflow-skinny`), so no
  `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: yes — regenerate both files.

## Acceptance criteria
- [ ] An enabled component's library sub-steps appear as spans inside the adapter span, with no adapter file edited.
- [ ] A disabled or unavailable component changes nothing about the prediction.
- [ ] Unavailable (409) and unknown (400) components are refused with distinct statuses.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: none. The docs' "one-line autolog" writes to their store; LabelDesk's equivalent is one context
manager at our dispatch point, because the store is ours.
Sub-span timings come only from metadata the adapter already returns — never time the library by monkeypatching
it, or a library upgrade becomes a tracing outage.
