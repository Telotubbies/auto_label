## User story
As a reviewer, I want to add preprocessing steps as an ordered list, each with only the controls it needs, so that I can see the whole pipeline at once instead of hunting fifteen toggles.

## UX flow (LabelDesk words)
1. **Wizard → step 3 — Preprocessing** — a stack of step cards in the fixed pipeline order (`Tiling → Crop → Resize → Isolate objects → Grayscale → Contrast`), each with a drag-free *Move up / Move down* pair that only reorders within the allowed order (the order is fixed, so the pair is shown disabled with the reason "Tiling always runs before resize"). [empty: "No preprocessing — the version keeps the source pixels."] [loading: n/a] [error: an incompatible pair shows on both cards: "Tiling cannot be combined with crop."]
2. **Add step** — a menu of the six steps, each disabled with a reason when its prerequisite is missing ("Crop needs a detection or segmentation project"). [empty: every step already added ⇒ the button reads "All steps added"] [error: n/a]
3. **Remove** — the card's overflow menu removes it; the preview refreshes.
4. **Each step's own controls** live in the card body: Tiling (T-205), Crop (T-201), Resize (six-mode select + width/height + "Never enlarge"), Isolate objects (T-202), Grayscale (switch), Contrast (three-algorithm select, T-200). A card whose implementation card has not landed yet renders `null` — the registry is data, not dead code.
5. **Scope note** — one line above the stack: "These steps apply to train, valid and test." [empty: n/a]

## Notes for the implementer
The order is the product: do not build a drag-and-drop reorder. `Move up/down` exists only to explain *why* the order is fixed, and its disabled state is the explanation. Each op's UI component receives `{recipe, onChange, ctx}` and nothing else.
