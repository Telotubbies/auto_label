## User story
As a reviewer, I want to type `split:test -class:helmet class:person>=2 date:>=2026-10-01` in the dataset
search box so that I can describe the slice I need once and paste it to a colleague.

## UX flow (LabelDesk words)
1. **Dataset · Images** — the user types in the query box (rendered by T-062). [loading: the grid keeps
   the previous rows under a 40%-opacity skeleton until the new result arrives] [empty: results are
   empty only after a valid query runs — the empty state is T-062's job]
2. **Dataset · Images** — malformed input never reaches the API: the box shows the caret position and
   "Check the query near `class:`" under the field; the last valid result stays on screen. [error]
3. **Dataset · Images** — valid input narrows the grid and the header line changes to
   "12 uploaded · 9 approved" once T-062 lands; the query lives in the URL (`?q=`).

## Backend changes
- Models/schema: none.
- Routers: none in this card (T-061 exposes it).
- Services/jobs: `apps/backend/app/services/query.py` (new)
  - `parse(text: str) -> Node` — selectors `tag`, `split`, `status`, `class`, `file`, `batch`, `assignee`,
    `date`, `width`, `height`, `annotations`, `metadata`, `is` (`is:null`, `is:annotated`); operators
    `:`, `=`, `>=`, `<=`, `>`, `<`, `!=`; free text = filename contains; `AND`/`OR`/`NOT`, parentheses,
    leading `-` = NOT, adjacent terms = AND.
  - `compile(node, project_id) -> ColumnElement` — returns SQLAlchemy conditions over `Image` and
    `ImageClass` (`Image` is imported from `models`, `ImageClass` for `class:` counts).
  - `QueryError(ValueError)` with `.position` and `.token` for the UI caret; limits: input ≤ 2000
    chars, ≤ 64 terms, nesting depth ≤ 8, `class:` count 0–10000, `date:` ISO-8601 only.
  - `metadata:` compiles to a stub that raises `QueryError("metadata filters are not available yet")`
    until T-082 registers its branch (one `case` arm added there).
- Permissions + workspace isolation: no route; callers pass `project_id` so a compiled condition can
  never span projects. Wrong-workspace behaviour is decided by the route (T-061, 404).
- Secrets/safefetch: none.
- OpenAPI: no.

## Acceptance criteria
- [ ] Every selector and operator listed above parses and compiles; a mixed query with parens, OR and
      `-` returns exactly the rows the equivalent legacy parameters return.
- [ ] A syntax error carries a caret position and never raises a 500.
- [ ] A compiled condition is scoped by the `project_id` the caller passes; no compiled fragment
      references another project's rows.
- [ ] Query text over 2000 chars, over 64 terms or deeper than 8 levels is rejected with a readable
      message, not a timeout.
- [ ] Empty/loading/error states above render (error is the inline caret message).
- [ ] Flag off ⇒ `services/query.py` is unreachable: the route that imports it answers 404 (T-061).
- [ ] Workspace A cannot see workspace B's data: the compiler takes `project_id` and has no lookup that
      could cross a workspace.

## Notes for the implementer
Selector aliases: `file` = `filename`, `annotations` = `count`, `width`/`height` in pixels (range
operators only). `date:` compares `Image.created` (immutable upload date), never `updated`. A bare
`class:x` means "at least one", `class:x=0` means "none" and compiles with `NOT EXISTS`, not `!=`.
