## User story
As a reviewer, I want Versions and Health to open *inside* Dataset, so that the rail stops pretending four screens are four different parts of the pipeline.

## UX flow (LabelDesk words)
1. **Project → ③ Dataset** — the page opens on `?tab=images` with a tab row `Images · Versions · Health`; the URL holds the tab, so a refresh and a pasted link land on the same one. [loading: the tab row renders immediately with the child's skeleton below it]
2. **A saved link to `…/versions`** — redirects to `…/dataset?tab=versions`. [error: an unknown `?tab=report` falls back to the first tab and says nothing — no blank page]
3. **④ Train and Models are two destinations, not a tab pair** — Train starts a run (T-255's three-block screen); the run list and its evaluation live at `/models`, which the rail's `Models` row opens (the v3e rail, REDESIGN §13.1, lists it under Models beside Train). `…/model-insights` redirects to `/models`, so the old link still lands on the same screen. Train therefore renders **no tab row**; a one-item tablist is noise.
4. **⑤ Deploy** — tabs `Test · Streams`; the endpoint card lives inside *Test* (S10 draws test-first, API second on one screen), and `…/streams` lands on the Streams tab. `/w/playground` stays a workspace URL that renders the same test pane.
5. **A labeler** — Dataset shows `Images · Versions` only when `project.export` is granted, Deploy only when `project.models` is; an unavailable tab is absent, not disabled, because the child route is gated the same way.
6. **No tab is also a rail row.** Versions, Health, Streams and Test have no row of their own in the project rail; the stage row is the only entry, so the rail never lists the same destination twice.

## Frontend changes

  - `dataset` → `DatasetStage` (`?tab=images|versions|health`, default `images`).
  - `train` → `Train` mounted directly — no tab row, no `TrainStage` host.
  - `models` → `Models` mounted directly; it is the rail's `Models` row (REDESIGN §13.1) and `model-insights` becomes `<Navigate replace to="models">`.
  - `deploy` → `DeployStage` (`?tab=test|streams`, default `test`).
  - `versions` and `streams` stay as `<Navigate replace>` into the tab URLs.
- Nav entry: `apps/frontend/src/lib/nav/project/stages.ts` gains `tabs: [{id, label, perm, flag?}]` for `dataset` and `deploy` only; the rail renders one row per stage (T-478).
- Components:
  - `apps/frontend/src/components/shell/StageTabs.tsx` (new) — accessible tablist (`role="tablist"`, arrow keys, `aria-selected`), reads and writes the `tab` search param with `replace`.
  - `apps/frontend/src/features/project/DatasetStage.tsx`, `DeployStage.tsx` (new) — each renders `<StageTabs>` plus the existing child component; no child file is edited.
- Glass: the tab row is content, so it stays solid on `Card` — active tab `bg-accent text-accent-foreground` with a 2 px primary underline, inactive `text-muted-foreground`; no glass on content and no new token.
- API client: none.
- Feature flag: `task_470`; off ⇒ the old sibling routes render their pages un-nested.
