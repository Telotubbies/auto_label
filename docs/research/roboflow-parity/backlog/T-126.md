## User story
As a project manager, I want to choose single- or multi-label classification when I create or edit a project, so that one image can carry several classes without a database edit.

## UX flow (LabelDesk words)
1. **Workspace home → New project** (`features/workspace/Home.tsx:24`, extracted to a form component) — choosing the "Classification" project type reveals one radio row under the type grid: **One label per image** (default) and **Several labels per image**, with the hint "Several labels let a single image be both "helmet" and "no vest"." [empty: name blank → Create disabled]
2. **Save** — Create sends `multilabel` with the project; a failure keeps the dialog open with the reason. [loading: Create shows a spinner and is disabled]
3. **Project settings → General** (classification projects only) — a new **Image labels** card repeats the same two radios; switching to single-label warns before saving: "Images with more than one label keep only the first; the others are removed from X images." with Cancel / Switch. [error: the patch fails → the switch reverts and the toast carries the reason]
4. **Editor (classification)** — the class chips already toggle per class; with single-label on, picking a chip replaces the previous label instead of adding, and the canvas hint names the single label. With multi-label on, chips toggle independently and the hint lists them comma-separated.
5. **Dataset grid** — a thumbnail's `title` lists the applied class names on hover, in the project's class colours, for both modes.

## Acceptance criteria
- [ ] Creating a classification project offers the label mode and stores it; the editor's chips add or replace accordingly.
- [ ] A detection or segmentation project never shows the control, and the API refuses the field with 400.
- [ ] Switching to single-label warns with the affected image count and keeps the first label per image on confirm.
- [ ] The dataset grid shows the applied class names on thumbnail hover in both modes.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] No flag: an option on existing forms; there is no separate surface to hide.
- [ ] Keyboard-only path: New project → type → Tab to the mode radios → arrow to "Several" → Create.

## Notes for the implementer
The `relabelled` count is images, not annotations. Keep "keep the first label" deterministic by annotation array order, which is the paint order, so the surviving label is the one the user drew first — not the alphabetically first class.
