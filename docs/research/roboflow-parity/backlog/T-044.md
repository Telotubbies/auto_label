## User story
As a visitor, I want to drop a photo of my own scene and see the closest public datasets first, so that I find relevant data without describing it in words.

## UX flow (LabelDesk words)
1. **Gallery dropzone** — a bordered strip above the results: `Find datasets like your photo` + `Choose a photo` (drag, paste or browse). Accepted JPEG, PNG, WebP, GIF (first frame), ≤20 MB. [empty: no photo → the strip is a single line]
2. **Searching** — the strip shows a 48 px thumbnail and `Comparing 940 images…`; results reorder by similarity with a `Similar to your photo` chip and a `Clear` action. [error: over 20 MB → `That file is too large — up to 20 MB.`; HEIC → `HEIC is not supported yet. Export as JPEG and try again.`; unreadable → `That image could not be read — try a JPEG or PNG.`; rate limit → `Try again in a minute.`]
3. **Combined with filters** — similarity ranks only the datasets that already match the text and filters; changing a filter re-runs the comparison with the same photo (kept in memory, never uploaded twice).
4. **Signed out** — this works anonymously; nothing is stored server-side after the request.

## Backend changes
- Models/schema: none.
- Routers: `routers/discovery.py` gains `POST /api/public/datasets/similar` (multipart `image`) → `{items: [{slug, workspace, score}]}` ordered by score desc, ≤48; 413 over 20 MB, 415 for an unsupported type, 422 for an undecodable file, 429 rate-limited at 10 requests/minute per IP. `GET /assets` listing accepts no probe; the client joins scores to the current page by slug.
- Services/jobs: `services/similarity.py` (new) — `probe_vector(data) -> np.ndarray` via `insights_embedding`'s backend (CLIP when available, cheap CV features otherwise), `scores(db, probe, public_projects, per_project=20) -> list[tuple[slug, score]]` reusing the on-disk feature cache (`_load_feature`/`_store_feature`) keyed by image sha; scoped to `visibility == "public"`, `deleted_at IS NULL`, ≤50 datasets per call.
- Permissions + workspace isolation: anonymous, and the only projects read are public ones; the probe image is decoded in memory and never written to disk (assert: no file with the probe's sha appears under `DATA_DIR`); scores never reveal private projects or file names.
- Secrets/safefetch: none — bytes arrive in the request body, nothing is fetched.
- OpenAPI: yes.

## Tests to write first
pytest — `apps/backend/tests/test_similarity.py`:
- `test_similar_returns_public_datasets_ranked` — two public datasets with deterministic feature vectors → the nearer one scores higher; private datasets absent.
- `test_probe_is_never_written_to_disk` — snapshot `DATA_DIR` before/after → no new file.
- `test_oversize_is_413_and_wrong_type_is_415` — 20 MB + 1 byte; a `.txt` upload.
- `test_undecodable_bytes_are_422` — truncated JPEG.
- `test_rate_limit_is_429` — 11 requests in a minute from one IP.
- `test_flag_off_has_no_route` — 404.
- `test_scores_are_bounded` — every score in `[0, 1]` and the list is sorted descending.

node — `apps/frontend/tests/similarity.test.mjs`:
- `test_score_merge_preserves_filtered_order` — merging scores reorders only the current page and never drops a filtered-out dataset back in.
- `test_error_copy_per_status` — 413/415/422/429 map to the four sentences above; HEIC maps to the HEIC sentence client-side before upload.
- `test_clear_restores_the_plain_order` — clearing the probe returns the previous ordering.

## Acceptance criteria
- [ ] Dropping a JPEG reorders the current, filtered public results by similarity and shows the `Similar to your photo` chip.
- [ ] HEIC is refused with its own remedy sentence; nothing is silently misread.
- [ ] Empty, loading and error states above all render (no photo, comparing, four error copies).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids); the probe reaches no private project and is never persisted.
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.
- [ ] The endpoint is rate-limited and reads at most 50 datasets × 20 images per request.

## Notes for the implementer
No new dependency: this repo has Pillow + OpenCV, not a HEIC decoder, so HEIC gets a precise refusal rather than a silent failure. Reuse `insights_embedding`'s cache paths — a second embedding store would double GPU work.
