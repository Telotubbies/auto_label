## User story
As a brand-new account, I want the first screen to be the assistant that produces something, and to see long jobs there while I keep reading, so that I am never dropped into an empty project grid.

## UX flow (LabelDesk words)
1. **After signup** — a user whose workspace has no projects and whose setup is answered lands on `/:ws/assistant` once. A ghost `Skip to projects` sits under the first reply. The workspace home stays the Projects page with the Needs-you queue for every later visit (v3 S1), so no second home is invented.
2. **Background tasks** — a counter above the composer: `2 running`. Expanding it (or the panel under the thread on ≥1024) lists up to five workspace jobs: name, project, progress bar, ETA; a finished row is a link to the page it produced (version → Dataset › Versions, train → Train › Runs, export → Versions, autolabel/health → Annotate). [empty: no jobs → the counter is absent, and the panel is not rendered at all] [loading: panel shows two 16 px skeleton rows, counter absent] [error: `Could not read background tasks` with `Retry`, thread untouched].
3. **A job finishes while reading** — the row flips to `done` and gains its link; the counter drops by one. No toast.
4. **Route away and back** — the assistant restores the thread and the same tasks (server state), never a modal.

## Backend changes
- Models/schema: none.
- Routers: none new. Reads the existing `GET /api/ws/{ws}/jobs` (`routers/workspaces.py:314`); the job `kind` → destination mapping lives in the frontend.

- Secrets/safefetch: none.

## Frontend changes
- Route: `/:ws/assistant` (exists from T-015); the redirect logic sits in `WorkspaceHome` (`routes/guards.tsx`) and must not loop: only when `projects.length === 0`, `setup.asked`, flag on, and the visitor has not already skipped (`sessionStorage` key `ld:assistant-skipped:<ws>`).
- Nav entry: none.
- Components: `features/assistant/TaskPanel.tsx` (new) — counter, panel, per-kind destination map; mounted by `Assistant.tsx` (one import line).
- API client: reuses `get<Job[]>` with `/ws/${ws}/jobs`; no new client function.
- Feature flag: `task_a1_assistant`; off ⇒ no redirect, no panel, workspace home unchanged.

## Acceptance criteria
- [ ] A new account with zero projects lands on the assistant exactly once; `Skip to projects` and any second visit land on Projects.
- [ ] Background tasks render running and finished jobs with a working destination link per kind.
- [ ] Empty, loading and error states above all render; the panel error never replaces the thread.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — the panel asks only for the current workspace's jobs.
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged (home is Projects, no redirect, no panel).

## Notes for the implementer
The counter is one chip, not a card: `2 running`. The finished-row destination map is a `Record<kind, (project, job) => string>` with a `null` fallback that renders the row as text.
