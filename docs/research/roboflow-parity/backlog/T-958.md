## User story
As a customer running my own inference service, I want to send its traces to LabelDesk with the standard
OpenTelemetry exporter, so that my pipeline and my models are debugged in one place.

## UX flow, click by click.
1. **Project settings → Tracing → OpenTelemetry** — an endpoint URL with a copy button
   (`/api/otel/{project}/v1/traces`), the header it expects (`X-LD-Trace-Key`), and a one-line example for the
   Python exporter. [empty: tracing not enabled yet shows the two steps, with the first link]
2. **Create the key** — *Create trace key* shows the secret once, with its scope (`traces:write`) and a
   revoke button; the settings page lists keys by prefix and last use. [error: a revoked key is refused with
   401 and the refusal names the key prefix, never the secret]
3. **Send a trace** — a customer's service posts OTLP/JSON; the trace appears under Traces with the service
   name as its source and its spans in ordinal order.
4. **A malformed payload** — 400 with the OTLP status object, the offending span index, and the request is not
   partially stored. [empty: a post with zero spans is a 400, not a silent success]
5. **Rate limit** — over the project's trace budget the ingest returns 429 with `Retry-After`, and the settings
   page shows "traces dropped by budget in the last hour".

## Backend changes
- Models/schema: reuse `ApiKey` with a new scope `traces:write` in `apps/backend/app/models/common.py`
  `API_SCOPES` (one tuple entry). No new table.
- Routers: `apps/backend/app/routers/otel.py` (new) — `POST /api/otel/{project}/v1/traces`, authenticated by
  `X-LD-Trace-Key` (never a query string), body `application/json` OTLP `resourceSpans`; returns
  `{"partialSuccess": {}}` on success and the OTLP-shaped error body on 400. 401 for a bad key, 404 for a
  project the key does not belong to, 413 above 5 MB, 429 over budget.
- Services/jobs: `apps/backend/app/services/otel.py` (new) — `to_trace(payload, project, workspace_id)` maps
  `resourceSpans[].scopeSpans[].spans[]` to T-954's `Trace`/`Span` (span id as our id, parent from
  `parentSpanId`, `startTimeUnixNano`/`endTimeUnixNano` to our floats, status code to `state`,
  `service.name` to our `kind`/source label); attributes are stored through T-954's `_trim`. Unknown attribute
  types are stringified, never rejected. Proto encoding is out of scope: 415 with "send OTLP/JSON".
- Permissions + workspace isolation: the key's workspace and the path's project must match, else 404 — a trace
  key from workspace A cannot write into workspace B.
- Secrets/safefetch: the key is a credential — hash it like the existing API keys (`apps/backend/app/models/
  identity.py` `ApiKey`), show it once, store only its prefix. Dependency: none added (no `mlflow-skinny`), so
  no `THIRD_PARTY_LICENSES.md` change.
- OpenAPI: yes — regenerate both files.

## Tests to write first
pytest — `apps/backend/tests/test_otel_ingest.py`:
- `test_an_otlp_payload_becomes_one_trace_with_ordered_spans` — a fixed payload with three spans → one trace,
  spans ordered by start time, the root's parent empty, `source` equal to `service.name`.
- `test_the_key_scope_and_project_must_match` — a key without `traces:write` → 401; a key for workspace A on a
  project of B → 404.
- `test_a_malformed_payload_is_400_and_stores_nothing`.
- `test_an_empty_payload_is_400` and `test_a_6mb_payload_is_413` and `test_over_budget_is_429_with_retry_after`.
- `test_the_key_secret_is_never_in_a_read_response`.
- `test_flag_off_returns_404`.

- `test_endpoint_is_built_from_workspace_and_project` and `test_key_shown_once_then_only_its_prefix`.

## Acceptance criteria
- [ ] An OTLP/JSON payload from a customer's service becomes a trace with ordered spans and a source label.
- [ ] Trace keys are scoped, hashed, shown once, and a key from another workspace writes nothing.
- [ ] Malformed, oversized, over-budget and wrong-encoding requests each fail with the documented status.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged.

## Notes for the implementer
Overlap: none. Ingest is the half that helps a CV customer (their pipeline's traces land where their models
are); exporting our traces to a third-party collector is a later card and is deliberately not in scope here.
The docs also expose OTLP over gRPC; JSON over HTTP is the only encoding this card accepts, and it says so at
415 rather than half-supporting both.
