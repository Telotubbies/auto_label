## User story
As a team with its own training pipeline, I want the frozen dataset in a format my tool expects plus a note on how to bring the result back, so that leaving the platform with my data is one download.

## UX flow (LabelDesk words)
1. **Models → *Train elsewhere*** — a dialog: pick a version (default the newest ready), a format (COCO or YOLO), and read the two-line explanation: "Download the frozen dataset with its manifest. Train anywhere. Upload the checkpoint here to evaluate and deploy it."
2. **Download** — a progress state and then a `.zip` named `<project>-v<n>-<format>.zip`. [empty: no ready version ⇒ "Generate a version first — training needs frozen data." and the primary is disabled] [loading: "Building the bundle…" with a spinner, the download starts automatically] [error: "The bundle could not be built" + the reason and a Retry]
3. **What is inside** — the dialog lists it before download: the split folders, `manifest.json` (file names, splits, class names, annotation counts, sha256 of the version), `data.yaml` for YOLO, and `README.txt` with the three import steps.
4. **The way back** — the README's last section and the dialog's footer link to *Add external weights* (T-288) so the return path is one click from the same screen.
5. **A huge version** — over 2 GB the dialog warns first ("2.4 GB — the download may take a while") and still proceeds on confirmation.

## Backend changes
- Models/schema: none.
- Routers: `GET {P}/train-kit?version_id=&format=coco|yolo` → `StreamingResponse` of a zip with `Content-Disposition: attachment; filename="<slug>-v<n>-<format>.zip"`; **400** for an unknown format ("choose coco or yolo") or a version that is not `ready`/not this project; **409** while the version is generating.
- Services/jobs: new `apps/backend/app/services/train_kit.py` — `build(version, fmt) -> Path` writes into `DATA_DIR/train_kit/<version_id>/<fmt>.zip` from `exporters.cached_export(version_dir, fmt)` (copy, never move), adds `manifest.json` (from the version's manifest plus class names and counts), `data.yaml` for YOLO, and `README.txt` with the exact steps ("1. unzip, 2. train with your tool, 3. upload the checkpoint under Models → Add external weights"). Cached by `(version_id, fmt, manifest mtime)`; a rebuild replaces atomically.
- Permissions + workspace isolation: `c.perm("project.export")` (the same grant that already gates a version export); a foreign project slug or version id → 404/400 per the version rules.
- Secrets/safefetch: **none outbound** — the route only reads local files it just built; no URL is fetched, so `safefetch` is not involved.
- OpenAPI: yes — one route (regenerate both files).

## Tests to write first
pytest — `apps/backend/tests/test_train_kit.py`:
- `test_coco_bundle_contains_manifest_and_splits` — zip entries include `manifest.json`, `train/`, `valid/` (when present) and `README.txt`.
- `test_yolo_bundle_adds_data_yaml` — `format=yolo` → `data.yaml` present and lists every class name.
- `test_manifest_carries_the_class_names_and_counts` — `manifest.json` has `classes`, `splits`, `annotation_count`, and a `version_sha256`.
- `test_the_same_version_and_format_builds_once` — two calls → one file on disk, identical bytes.
- `test_a_generating_version_is_a_409` and `test_an_unknown_format_is_a_400`.
- `test_a_version_of_another_project_is_a_400_or_404` — never a zip of someone else's data.
- `test_a_labeler_cannot_download_the_kit` — 403 (needs `project.export`).
- `test_flag_off_is_a_404` — `task_291` off → 404.
node — `apps/frontend/tests/train-kit.test.mjs`:
- `test_coco_and_yolo_contents_differ_by_data_yaml` — the YOLO list contains `data.yaml`, COCO's does not.
- `test_file_name_is_slug_version_format` — `kitFileName('ppe-detection', 3, 'coco')` → `ppe-detection-v3-coco.zip`.
- `test_size_warning_only_above_two_gigabytes` — 2 GB → null; 2.4 GB → a sentence containing both figures.

## Acceptance criteria
- [ ] One download yields a frozen dataset bundle with a manifest, the split folders and format-appropriate metadata.
- [ ] The bundle is built once per version and format and never moves the cached export.
- [ ] The dialog names the return path (upload) on the same screen.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no entry, no route.

## Notes for the implementer
Copy from `cached_export`, never `shutil.move` — a concurrent evaluation reads the same directory. The README is five lines, no marketing: zip, train, upload, evaluate, deploy.
