## User story
As an agency owner, I want one call that compares my client workspaces' spend and activity, so that a monthly review does
not mean opening each workspace.

## UX flow (LabelDesk words)

*Screen this contract serves:* the **Organisation rollup** page (T-449's card owns the screen). States: one
workspace → the page explains it is for agencies and links to Projects; a long range → the chart shows the chosen
window and a caption; a failed workspace → a row-level "Could not read this workspace" with Retry, other rows still
render.

1. `GET /api/orgs/{org}/rollup?since&until` → `{org: {id, name}, range: {since, until},
   workspaces: [{id, slug, name, plan, members, projects, images, deployments, credits, storage_bytes, last_activity}],
   totals: {workspaces, credits, projects, members}, excluded: n}`.
2. `excluded` counts linked workspaces the caller is not a member of — the number is visible, the names are not.
3. `GET /api/orgs/{org}` → `{id, name, workspaces: [{id, slug, name}]}` for the switcher, same membership rule.
4. `[empty]` no activity in the range → zeroed rows, `totals.credits = 0`, no error.
5. `[error]` a range longer than 366 days is `400`; a non-member is `404` (not 403 — the org's existence is not public).

## Backend changes
- Models/schema: none (T-447).
- Routers: `app/routers/orgs.py` (new) — `GET /api/orgs/{org}` and `GET /api/orgs/{org}/rollup`; prefix `/api/orgs`,
  **no** workspace in the path, so the membership check is explicit rather than structural.
- Services/jobs: `services/organization.py` — `rollup(db, org, user, since, until) -> dict` (one query per metric over
  the member-visible workspace ids: `Member`, `Project`, `Image`, `TrainedModel`, `CreditEvent`, `UsageEvent` storage;
  `last_activity` from the newest `Audit.created`), `visible_workspaces(db, org, user) -> list[Workspace]`.
- Permissions + workspace isolation: `can_read(org, user)` from T-447; every aggregate is restricted to the workspace ids
  that passed that check, so a workspace the caller left disappears from the numbers on the next call.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Frontend changes

## Acceptance criteria
- [ ] One call returns per-workspace rows and totals for the workspaces the caller may see.
- [ ] A workspace the caller is not a member of is counted in `excluded` but named nowhere.
- [ ] A non-member gets a 404, and a range longer than a year is refused.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no org routes.

## Notes for the implementer
No workspace in the path means the membership check cannot be forgotten by a dependency: do it once at the top of each
route. `excluded` exists so the numbers are honest without leaking names.
