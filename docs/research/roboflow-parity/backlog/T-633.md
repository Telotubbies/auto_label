## User story
As an ops manager, I want hours per stage, objects per hour and how much of the work was derived, so that the next batch is quoted from this batch's own numbers instead of arithmetic on a notepad.

## UX flow (LabelDesk words)
1. **QA → Workforce → `Time and speed`** — a stage `Select` (`All stages` plus the project's stages) and a window (`7 / 30 / 90 days`); a table of members: hours, images, objects, objects/hour, derived share. [empty: "No activity in this range."] [loading: four skeleton rows] [error: "These numbers did not load." + `Retry`]
2. **A member row** — expands to a daily bars chart of hours and objects, drawn with the `recharts` dependency `Workforce.tsx` already imports, plus an `sr-only` list for screen readers.
3. **Stage filter** — choosing `Review` recomputes hours and objects from moves and saves attributed to that stage; objects/hour stays blank (`—`) rather than `0` when hours are zero.
4. **Derived share** — the percentage of the objects now on those images that carry an `interpolated`, `sam3` or `vlm+sam3` source.
5. **A window with no saves** — the totals are `0` and the empty line shows; the window switch stays usable.

## Backend changes
- Models/schema: `LabelEvent.stage` String(20) default `''` in `app/models/insights.py` plus one `LABEL_EVENTS` line in `app/schema/dataset.py`; `labeling_ops.record_save` writes `image.stage or image.status` into it. Existing rows read as `''` and are attributed to `—`; no backfill.
- Routers: `routers/labeling.py` — `GET "/time"` (`days: int = 30`, `stage: str = ""`) → `{window_days, stage, totals, members: [{user_id, name, hours, images, objects, objects_per_hour, derived_share, daily}], stages: [...]}`; 422 for `days` outside 7–90 or an unknown `stage`.
- Services/jobs: `app/services/time_accounting.py` (new) — `accounting(db, workspace_id, project_id, days, stage)`; hours from consecutive `LabelEvent.created` values of one user with `SESSION_GAP_S = 900`, counting a gap of at most 15 minutes and a last event of 2 minutes; `derived_share` from `Image.annotations` of the touched images; `objects_per_hour` returns `None` when hours are zero. No worker job.
- Permissions + workspace isolation: `c.need("annotator")`; reviewers see every member, a labeler sees only themselves — the same `only_user` rule `labeling_ops.dashboard` already applies; rows are filtered by `c.project.id` and `c.ws.id`.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] The Time and speed section shows hours, images, objects, objects/hour and derived share per member for the chosen window and stage.
- [ ] A 15-minute gap rule is applied, so an overnight pause is not counted as work.
- [ ] Choosing a stage filters both the totals and the daily chart, and a zero-hour member shows `—` rather than `0`.
- [ ] Empty, loading and error states above all render: the no-activity line, skeleton rows, the load error and the 422 sentences.
- [ ] Workspace A cannot read workspace B's time report (404, not 403).
- [ ] Flag off ⇒ no Workforce tab and no request.

## Notes for the implementer
Hours are an estimate, not a timesheet: state the 15-minute rule on screen in one line so nobody reads the number as payroll. Attribute by the stage stored on the event at save time — recomputing it from the image's current stage would rewrite history every time an image moves.
