## User story
As a reviewer, I want the images waiting for screening in one list with a preview and two buttons so that
approving today's drop takes a minute, not a filter hunt.

## UX flow (LabelDesk words)
1. **Dataset · Images** — when images are `pending`, a banner above the grid reads "3 images are awaiting
   screening" with **Review them**. [empty: the banner is absent when none are pending]
2. **Dataset · Screening** (`?screening=pending`) — a 3-column preview grid; each tile shows the file
   name, batch, size and the capture date; clicking a tile opens the full image in a side sheet.
   [loading: 6 tile skeletons] [error: "Could not load the screening queue — retry"]
3. **Dataset · Screening** — each tile has **Release** and **Discard**; selecting tiles shows a bar
   "2 selected · Release · Discard". Discard opens a confirm naming the count ("Discard 2 images? The
   files are deleted.").
4. **Dataset · Screening** — releasing the last image replaces the grid with "Nothing is waiting for
   screening" and a link back to all images. [empty: same copy on first visit]

## Backend changes
- Models/schema: none (T-069 owns the column).
- Routers: `apps/backend/app/routers/images.py` — `POST P/images/screening` body
  `{ids: list[str], verdict: "release" | "reject"}` (cap 500 ids), one transactional pass, returns
  `{updated, skipped: [{id, reason}]}`; reuses `services.screening.verdict`; `409` when every id is
  already decided, `200` with `skipped` when only some are.
- Services/jobs: none (a 500-id release is fast; no job).
- Permissions + workspace isolation: `c.perm("project.review")`; ids are filtered by
  `Image.project_id == c.project.id`, so a foreign id is `skipped`, never written.
- Secrets/safefetch: none.
- OpenAPI: yes — new route.

## Acceptance criteria
- [ ] The banner appears only when `pending` images exist and links into the queue.
- [ ] Release and Discard work per tile and in bulk; Discard requires a count-bearing confirm.
- [ ] Draining the queue shows the empty copy, not a blank grid.
- [ ] An id from another project is skipped with a reason and never mutated.
- [ ] Empty, loading and error states above render.
- [ ] Flag off ⇒ no banner, no queue, `?screening=pending` is ignored by the old page.
- [ ] Workspace A cannot see or change workspace B's data (404 for a foreign project id).

## Notes for the implementer
Do not turn this into a new tab under the Dataset stage — it is the Images tab with a filter, so the
saved-view chip and the banner both point at the same URL. Bulk release is synchronous; 500 ids is the
cap for that reason.
