## User story
As a reviewer cleaning up the night shift, I want the slice bar to open its own gallery with ground truth against predictions, so that I pick the images to relabel instead of guessing which ones failed.

## UX flow (LabelDesk words)
1. **Evaluation → Slices** (`/:ws/:project/model-insights?tab=evaluation`) — each bar carries `See the images`; the gallery opens below the chart. [loading: thumbnails fade in as a grid of skeletons, the chart stays put] [error: "The slice could not be loaded" with a retry, and the chart keeps its numbers]
2. **Gallery** — `Worst first` order, each card showing the image with the ground-truth / prediction toggle the confusion view already uses, and its AP for the slice. [empty: "No failures in this slice." instead of an empty grid]
3. **Select** — checkboxes with `Select all`; the count reads `{n} selected`.
4. **Send to labelling** — creates the batch and confirms with a toast naming it; the button is disabled at zero selected.
5. **Saved slices** — a `Saved slices` row above the chart lists the definitions saved on this model; clicking one re-opens both the chart and the gallery. [error: saving a duplicate name shows the API's 409 sentence next to the field]

## Acceptance criteria
- [ ] Clicking a slice bar opens a gallery of exactly that slice's images, worst first, with ground truth against predictions.
- [ ] A selection becomes one named batch in one click, and the toast names it.
- [ ] A slice definition can be saved from this screen and re-opened later.
- [ ] Empty, loading and error states above all render: a clean slice says so, a slow gallery shows skeletons, a failure keeps the chart usable.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the Slices section is exactly the chart it is today, with no click affordance.
