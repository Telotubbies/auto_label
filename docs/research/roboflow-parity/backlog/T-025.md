## User story
As a workspace admin with two product lines, I want a folder inside a folder, so that "Safety / Cameras" can sit under "Safety" instead of everything staying one level deep.

## UX flow (LabelDesk words)
1. **Workspace home** — folder cards show their child count (`3 projects · 2 folders`); opening a folder shows its subfolders first, then its projects. A breadcrumb `Projects / Safety / Cameras` with each level clickable.
2. **New folder** — created inside the folder you are currently in (button label `New folder` and the helper line `Inside Safety.`).
3. **Move a folder** — drag onto another folder (T-024) or ⋮ → `Move to…`. Dropping a folder into its own descendant is refused: `A folder cannot go inside itself.` [error: this exact message; the tree does not change]
4. **Deep limit** — a third level is refused with `Two levels is enough to organise a workspace.` and the drop outline turns red.
5. **Delete a folder with children** — children lift one level, projects lift one level (existing rule), confirm sheet names the counts: `Delete Safety? 2 folders and 3 projects move up one level.`

## Backend changes
- Models/schema: `folders.parent_id` nullable FK `folders.id` (`ondelete="SET NULL"`), self-referential; `ADD COLUMN` `{"parent_id": "VARCHAR(32)"}` — there is no `FOLDERS` block yet, so add `FOLDERS = {"parent_id": "VARCHAR(32)"}` to `app/schema/dataset.py` and one `STEPS` row `("folders", dataset.FOLDERS)`.
- Routers: `GET /api/ws/{ws}/folders` returns `parentId` and `counts: {projects, folders}`; `POST` accepts `parent_id`; `PATCH` accepts `parent_id` (move) and validates: same workspace, depth ≤2, no cycle (walk up from the new parent); `DELETE` re-parents child folders before removing the row.
- Services/jobs: none — the walk is a small loop in `routers/workspaces.py`.
- Permissions + workspace isolation: create/move needs `reviewer`, delete needs `admin` (existing); a parent id from another workspace 404s, and a cycle attempt 422 with the message above.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Frontend changes
- Route: `/:ws` and `/:ws/folders/:fid` (new read-only path so a folder is linkable and the breadcrumb survives reload).
- Nav entry: none.

## Acceptance criteria
- [ ] A folder can contain folders and projects; the breadcrumb links every level and survives a reload.
- [ ] A cycle and a third level are refused with their own sentences and change nothing.
- [ ] Empty, loading and error states above all render (empty folder, load failure keeps the flat list).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged (flat folders).
- [ ] Deleting a folder never deletes a project or a child folder.

## Notes for the implementer
Depth is measured from the top: a folder with `parent_id IS NULL` is level 1, its children level 2, and level 3 is refused. Do not add drag-and-drop here — T-024 owns it and calls this card's PATCH.
