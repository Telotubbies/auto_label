## User story
As someone starting a project whose brief names three classes, I want a prompt-free pass over a sample that ranks the other objects actually present, so that a forklift or a cable nobody mentioned is a decision I make now rather than a silent hole in the model.

## UX flow (LabelDesk words)
1. **Dataset → Discover objects** (`/:ws/:project/browse`, drawn by T-655) — a sample size of 50, 200 or 500 images and a stated cost. This card runs the sweep.
2. **Running** — `[loading: "Reading 200 images — about 200 model calls"]` with a counter; `[error: "no open-vocabulary model is available on this worker"]` when the VLM is missing, before any credit is spent.
3. **The result** — a ranked phrase list with a count, a representative crop per phrase and an overlap warning when a phrase already resembles a class ("forklift" vs "Forklift truck").
4. **Promotion** — "Add as classes" creates the classes with the phrase as the class name and a prompt pack synonym; "Ignore for this project" is remembered and reappears only as a muted count on the next run.
5. **Repeat runs** — the response marks what is new since the last sweep for the same sample seed.

## Backend changes
- Models/schema: none — the ignore list lives in `Project.settings["discovery_ignored"] = [phrase]`, crops under `DATA_DIR/discovery/<project>/`.
- Routers: new `app/routers/discovery.py` — `POST /api/ws/{ws}/projects/{project}/discover` (`sample` ∈ {50, 200, 500}) → 202 job; `GET .../discover/{jid}` → status plus `{"phrases": [{"phrase", "count", "images", "crop", "overlaps", "ignored", "new"}], "sampled", "calls"}`; `POST .../discover/accept` (`phrases` ≤ 20) creating classes through the existing `ensure_class`; `POST .../discover/ignore` (`phrases`) appending to the ignore list. 400 when more than 20 phrases are promoted, 409 when the egress gate refuses, 404 when the flag is off.
- Services/jobs: `services/discovery.py` (new) — `sample_images(db, project, n)` (deterministic stride, same order every run), `sweep(vlm, rows)` calling `vlm.describe_objects(im)` per image and aggregating phrases (lower-cased, trimmed, singularised only by trimming a trailing "s"), `overlaps(phrase, classes)` using a normalised comparison, `crop_for(im, box)` writing one JPEG per phrase; job kind `discover` in `LOCAL_JOB_KINDS`; `adapters/vlm_ad.py` gains `describe_objects(im)` asking for all prominent objects with a label and a box, no class list.
- Permissions + workspace isolation: `reviewer` to run, `project.classes` to accept, `project.read` to read a finished sweep; crops are signed with `sign_path` like every other artefact, and a job id from another project is 404.
- Secrets/safefetch: `services/secretbox.py` holds a hosted endpoint token if one is stored; no image leaves the deployment unless `workspaces.ai_egress` is true (`ai_egress.require`).
- OpenAPI: yes — regenerate (`python tools/export_openapi.py`, `npm run gen:api-types`).

## Acceptance criteria
- [ ] A sample sweep returns ranked phrases with counts, a crop each and an overlap warning against existing classes.
- [ ] Accepted phrases become classes with their prompt pack; ignored phrases are remembered and marked on later sweeps.
- [ ] A repeat run marks what is new, and a missing open-vocabulary model fails before any credit or image is sent.
- [ ] Empty, loading and error states above all render: an empty sample, a job running with a counter, a refused gate.
- [ ] Workspace A cannot read workspace B's sweep or crops (404 on a foreign job id, signed crop URLs only).
- [ ] Flag off ⇒ no endpoint and no stored result is read.

## Notes for the implementer
The sweep names objects, it does not label them: no annotation is written and no image is promoted. Phrase normalisation is trim + lower-case + a single trailing "s" removed — anything cleverer invents classes. One crop per phrase with the highest per-box confidence, capped at 50 phrases so the page stays one screen.
