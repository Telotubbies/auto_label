## User story
As an enterprise admin, I want the identity provider to decide who is in this workspace and which role they hold, so
that onboarding and offboarding happen in the directory, not by hand.

## UX flow (LabelDesk words)
1. No screen in this card. It stores, per workspace, the group names that grant access (`required_groups`), whether
   matching users join automatically (`auto_join`), and the group → custom-role map.
2. `[empty]` no groups and auto-join off → today's behaviour: every join needs an invite.
3. `[error]` a group name that is empty or longer than 255 characters is refused at write time, so a sign-in can never
   fail because of a stored typo.

## Backend changes
- Models/schema: `Workspace.required_groups: JSON | None`, `Workspace.auto_join: bool = False`;
  new table `RoleGroupMap(id, workspace_id FK CASCADE, idp_group VARCHAR(255), custom_role_id VARCHAR(32), created)`
  with `UniqueConstraint(workspace_id, idp_group)` in `app/models/access.py` (created by T-384).
  `ADD COLUMN` additions to `WORKSPACES` in `app/schema/identity.py`.
- Routers: none in this card.
- Services/jobs: `app/services/dir_sync.py` (new) — `GROUPS_CLAIM = "groups"`, `groups_of(claims) -> set[str]`
  (accepts a list or a space-separated string, both common), `gate(ws, groups) -> tuple[bool, str]`
  (`False, "not_in_required_group"` when required groups exist and none match; admins exempt; the environment's
  default workspace never gated — one constant `DEFAULT_WS_SLUG` from `config`), `role_map(db, ws) -> dict[str, str]`,
  `set_required_groups(db, ws, groups, auto_join, actor)`, `validate_group(name)`.
- Permissions + workspace isolation: the gate reads only the workspace named by the sign-in; admin exemption is by
  effective `ws_role`, never by email.
- Secrets/safefetch: none.
- OpenAPI: no (no route yet).

## Acceptance criteria
- [ ] A workspace can require directory groups, and an unmatched member is refused at sign-in.
- [ ] Admins and the environment's default workspace are exempt.
- [ ] Group names are validated on write and unique per workspace in the role map.
- [ ] Empty, loading and error states above all render (no groups, invalid name).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ nothing gates and nothing syncs.

## Notes for the implementer
The four combinations (neither / auto-join / required / both) are decided in T-431; this card only stores them. Do not
gate on a claim shape that the IdP might not send — an absent `groups` claim means "no groups", not "deny everything",
unless required groups are configured.
