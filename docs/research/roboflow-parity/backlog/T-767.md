## User story
As the DPO who has to sign, I want the four required items drafted from the incident with a checklist I must tick, so that the notice that leaves is complete and the record of sending it is one file.

## UX flow (LabelDesk words)
1. **Incident page → `Draft the notice`** (`/:ws/ops/incidents/<id>`) — four editable blocks: `What happened` (nature and volume, pre-filled with the scope counts), `Who to contact`, `Likely consequences`, `What we did`. Each block carries a tick box that only enables once the text has content, and the `Send` button stays disabled until all four are ticked. [loading: the blocks render with a skeleton and no `Send`] [error: "The draft could not be saved — your text is still on screen." with `Try again`]
2. **Blocks a workspace's owner must read** — a read-only list of every affected workspace with the owner's address and the delivery state ("queued", "sent", "no address on file").
3. **`Send`** — a confirm dialog naming the number of recipients; sending records `notice_sent_at` and one `incident.notice.sent` audit row per workspace, and the header now reads "Notice sent — 14 recipients".
4. **`Download the evidence pack`** — a Markdown file (and `?format=json`) holding the incident facts, the timeline, the scope query, the final notice and the recipient list. The button label says `Markdown`, not `PDF`, because no PDF renderer ships. [error: "The pack could not be built — nothing was sent."]
5. **A notice already sent** — the blocks are read-only, with "Amend and resend" available to an owner only, which appends a new timeline entry rather than editing the first send.

## Backend changes
- Models/schema: no new table — `Incident.notice_text` and `Incident.notice_sent_at` already exist from T-766; deliveries are `audit` rows with `meta={"workspace": …}`.
- Routers: `app/routers/incidents.py` — `PUT /api/ws/{ws}/incidents/{iid}/notice` (draft; 422 when a block is empty), `POST …/notice/send` (409 when a block is unticked, 200 with `recipients`), `GET …/evidence?format=md|json` (a `Response` download).
- Services/jobs: `app/services/incident_notice.py` (new) — `BLOCKS = ("what_happened", "contact", "consequences", "what_we_did")`, `draft(incident, blocks) -> dict`, `checklist(blocks) -> dict`, `recipients(db, incident) -> list[dict]` (owners of the scanned workspaces, plus "no address on file"), `send(db, c, incident) -> int` calling `app/mailer.send` once per recipient with `kind="incident"`, `pack(incident, timeline, scope) -> str`.
- Permissions + workspace isolation: `workspace.audit` to draft; only the owner may amend a sent notice; the affected-workspace list is resolved server-side from the scope result — a client cannot add a recipient.
- Secrets/safefetch: none — `mailer.send` is the shipped mail transport, and no address is rendered to a caller who lacks `workspace.audit`.
- OpenAPI: yes.

## Tests to write first

- `test_an_empty_block_is_422` — `PUT …/notice` with `consequences: ""` → 422 naming the block; a complete draft returns 200 with all four.
- `test_send_refuses_until_every_block_is_ticked` — `POST …/notice/send` with one unticked → 409 and `notice_sent_at` stays null.
- `test_send_mails_every_affected_owner_once` — two affected workspaces → `POST` returns `recipients: 2`, the dev outbox holds two messages, and two `incident.notice.sent` audit rows exist.
- `test_a_workspace_without_an_owner_address_is_listed_not_mailed` — one owner with an empty email → the recipient row reads `no address on file` and no third mail is queued.

- `test_the_pack_contains_the_four_blocks_and_the_timeline` — `GET …/evidence?format=md` → 200 `text/markdown` containing each block's heading, the scope sentence and every timeline actor.
- `test_flag_off_hides_the_notice_routes` — with the flag off, all three routes 404 and no mail is queued.

## Acceptance criteria
- [ ] The four required blocks are drafted from the incident, and `Send` is impossible until each is ticked.
- [ ] Sending mails every affected owner once, records the recipients and appends one audit row per workspace.
- [ ] The evidence pack downloads as Markdown or JSON and contains the facts, the timeline, the scope sentence and the notice.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no draft panel, no send, all routes 404 and no mail leaves the process.
