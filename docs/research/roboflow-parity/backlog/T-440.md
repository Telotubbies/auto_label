## User story
As an ML engineer, I want to send a version to a partner training platform and pull the weights back, so that a
specialised model lands in the same registry as our own runs.

## UX flow (LabelDesk words)
1. **Train → `Train elsewhere`** (a disclosure under the presets) — choose a partner (`Custom endpoint` is the only
   entry until one is configured), a `Callback URL` (read-only, generated), then `Export and hand off`.
2. **Job** — the job tray shows `Preparing bundle 40%` then `Waiting for the partner` with an ETA-free state; the run
   page lists `Sent 4 Mar · bundle 2.1 GB · callback expires 7 Mar`.
3. **Weights return** — `POST /api/handoff/{token}` with a multipart `weights` file → a `TrainedModel` row in
   `status="ready"` once the file is verified, and the run page moves to `Received`.
4. **`[empty]`** no handoff configured: the disclosure reads `No external trainer is configured for this workspace.`
   and the button is disabled.
5. **`[error]`** an expired callback token → `410 This handoff link expired. Start the export again.`; a file that is
   not a valid weights archive → `415 The file is not a supported weights archive.`; a bundle that cannot be built →
   `409 The bundle was not sent. Nothing left this workspace.`

## Backend changes
- Models/schema: new `TrainingHandoff(id, workspace_id FK, project_id FK, version_id FK, job_id FK, partner VARCHAR(32),
  bundle_bytes INTEGER, token_hash VARCHAR(64) unique, expires FLOAT, status VARCHAR(16) default "sent",
  model_id VARCHAR(32) null, created_by, created)` in `app/models/training.py`.
- Routers: `app/routers/handoff.py` (new) — `POST /api/ws/{ws}/p/handoff` (admin/manager, creates the job),
  `POST /api/handoff/{token}` (unauthenticated by bearer, token IS the credential, multipart weights).
- Services/jobs: `app/services/handoff.py` (new) — `start(db, ctx, version, partner) -> dict` (builds the version's export
  archive with the existing exporter, copies it to `DATA_DIR/handoffs/<id>/`, posts to the partner's configured URL via
  `webhook_sink.send`, records the token hash and a 72-hour expiry), `receive(db, token, filename, data) -> dict`
  (validates the archive magic, writes under `DATA_DIR/models/<id>/weights.pt`, creates the `TrainedModel` with
  `status="ready"`, `runtime_refs={"handoff": id}`, audits `train.handoff_received`), `expire(db, now)`.
- Permissions + workspace isolation: handoff start needs `project.train`; the callback resolves the workspace from the
  token row, and the created model belongs to that workspace only.
- Secrets/safefetch: the callback token is stored as a sha256 hash and is single-use after success; the partner URL is
  admin-configured and `safefetch`-checked before the first send.
- OpenAPI: yes.

## Frontend changes
- API client: `handoffApi.start(ws, project, body)` in `src/lib/api/handoff.ts` (new); the disclosure renders inside
  `features/project/Train.tsx` (shared mount).
- Feature flag: `task_training_handoff`; off ⇒ no disclosure and the routes 404.

## Acceptance criteria
- [ ] A version can be handed to a configured partner and the run shows preparation, sent and received states.
- [ ] The callback accepts one archive, creates a ready model in the same workspace, and cannot be reused.
- [ ] Expired or invalid callbacks are refused with a specific status and message.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids; 410 for a foreign token).
- [ ] Flag off ⇒ no disclosure and no routes.

## Notes for the implementer
The archive build is the risky part: on failure nothing may leave and the job must say so. Reuse the existing exporter
and `webhook_sink.send`'s transport; do not write a second upload path.
