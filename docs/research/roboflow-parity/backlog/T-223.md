## User story
As an ML engineer, I want the version to tell me that a class is missing from valid and test before I spend a run, so that a meaningless per-class mAP is caught at the source.

## UX flow (LabelDesk words)
1. **Version detail → Trainability** — a chip next to *Train on this version*: *Ready*, *Ready with warnings (2)* or *Not trainable*, and a list under it. [empty: n/a] [loading: the chip reads "checking…"] [error: "Could not check this version — training still works."]
2. **Blockers** — each with the fix: "No train images — add images to the train split, then generate a new version." The primary button is disabled with the first blocker as its tooltip.
3. **Warnings** — "helmet appears in 0 valid and 0 test images — its per-class score will be empty." / "valid has 2 images — evaluation will be noisy." / "38% of the version is empty frames." Each warning carries a link into the dataset grid filtered to that class or split. [empty: "No warnings — this version is ready to train."]
4. **Per-class table** — a compact `class · train · valid · test` table under the list, so the numbers the warnings came from are visible.
5. **Stale** — the chip recomputes on every version payload refresh; no cache to invalidate.

## Backend changes
- Models/schema: none — everything is derived from `manifest.json` + `Version.stats`.
- Routers: `apps/backend/app/routers/versions.py` — `GET "/{vid}/readiness"` → `{"status": "ready"|"warnings"|"blocked", "blockers": [{"code","message","fix"}], "warnings": [{"code","message","link"}], "splits": {…}, "per_class": [{"class","train","valid","test"}], "null_share": float}`; 404 for a foreign or still-generating version (`code: "not_ready"`).
- Services/jobs: `apps/backend/app/services/versions_ready.py` (new) — reads the cached manifest through `insights.version_manifest`, counts per-class per-split, and applies the rules: blocker `no_train_images`, `manifest_missing`; warning `class_absent_from_eval`, `small_eval_split` (< 5 images), `null_heavy` (> 30% empty), `single_class`.
- Permissions + workspace isolation: `c.perm("project.read")` — the counts are already visible in the grid; a foreign project slug 404s and a foreign version id 404s through `_get`.
- Secrets/safefetch: none.
- OpenAPI: yes — regenerate both files.

## Tests to write first
pytest — `apps/backend/tests/test_version_readiness.py`:
- `test_absent_class_in_eval_is_a_warning` — a class with train boxes and none in valid/test → `status: "warnings"`, code `class_absent_from_eval`, and `per_class` shows zeros.
- `test_empty_train_split_is_a_blocker` — all images in test → `status: "blocked"`, code `no_train_images`.
- `test_small_eval_split_warns` — valid with 3 images → `small_eval_split`.
- `test_null_heavy_warns` — a version that is 40% empty frames → `null_heavy`.
- `test_clean_version_is_ready` — no blockers, no warnings, `status: "ready"`.
- `test_generating_version_is_404_with_a_code` — `status` queued → 404 `not_ready`.
- `test_readiness_needs_project_read_only` — a viewer gets 200, a stranger gets 404 on the slug.
node — `apps/frontend/tests/version-readiness.test.mjs`:
- `test_chip_label_follows_status` — `chipLabel('ready')` → "Ready", `chipLabel('warnings', 2)` → "Ready with warnings (2)", `chipLabel('blocked')` → "Not trainable".
- `test_first_blocker_disables_the_primary` — `trainBlocker({status:'blocked', blockers:[a,b]})` returns `a.message`.
- `test_class_row_renders_zeros` — `classRow({class:'helmet',train:9,valid:0,test:0})` shows `0`, not `—`.
- `test_warning_link_targets_the_grid` — `warningLink({code:'class_absent_from_eval'}, ws, slug)` → the browse URL with `status=all&class=…`.

## Acceptance criteria
- [ ] The chip and the list agree with the manifest: blockers disable training with a reason, warnings name the class or split and link to the matching grid view.
- [ ] A still-generating version answers 404 `not_ready`, and the panel renders that as a state.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no readiness request, no chip, training behaves exactly as today.

## Notes for the implementer
Rules are data (`RULES = [(code, predicate, severity, message, fix)]`) so area 5 can reuse the endpoint for the S8 health chip without copying thresholds. Fix strings name the action, not the code: "add images to train and generate a new version", never "blocker no_train_images".
