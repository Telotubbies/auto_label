## User story
As a reviewer, I want the image's real change history with a revert, so that "who changed this" is answerable without a support ticket and a bad autosave is recoverable after a reload.

## UX flow (LabelDesk words)
1. **Editor → History panel** — the list is now server data (T-145 renders it): one row per save with the author, a relative time, the kind and the annotation count. [empty: a never-saved image says "No saved changes yet"] [loading: skeleton rows] [error: "History could not be loaded" with retry]
2. **Revert** — the three-dot menu beside a row offers **Restore this version**; a confirm names what will change ("Restore the version from 14:32 by Somchai? This image currently has 4 labels."). On confirm the image is restored to that snapshot and a *new* revision records the revert, so the history is append-only. [error: a stale image (T-121's guard) → the confirm is refused and the bar offers Reload]
3. **Who and when** — each revision records the user, the kind (`save`, `revert`, `autolabel`, `merge`) and a note ("Auto label · merge").
4. **Retention** — the last 50 revisions per image are kept; older ones are pruned in the same transaction, so the table cannot grow without bound on a noisy image.
5. **What a revision is not** — it is not a version: versions freeze a dataset, revisions are per image and never touch splits or classes.
6. **Flag off** — the History panel falls back to today's session log and both routes are 404; no revision is written.

## Backend changes
- Models/schema: new table `annotation_revisions` (`models/revisions.py`, new) — `id`, `workspace_id`, `project_id`, `image_id`, `user_id`, `kind` (`save|revert|autolabel|merge`), `n`, `annotations` (JSON), `note`, `created`; index on `(image_id, created desc)`; registered in `models/__init__.py` (`DOMAIN_MODULES`).
- Routers: `GET /api/images/{image_id}/revisions?limit=50` → `[{id, userId, user, kind, n, note, created}]`; `POST /api/images/{image_id}/revisions/{revision_id}/revert` → validates the revision belongs to this image, calls `set_annotations` with its payload, records a `revert` revision and returns the image payload. `400` when the revision's classes no longer exist in the project (revert would orphan labels) with the list of missing names.
- Services/jobs: `services/revisions.py` (new) — `record(db, img, user_id, annotations, kind, note)`, `list_for`, `get`, `prune(image_id, keep=50)`; `labeling_ops.save_annotations` calls `record(..., "save")`; `handlers/training.run_autolabel` calls `record(..., "autolabel")`; `labeling_ops.merge_job` calls `record(..., "merge")`.
- Permissions + workspace isolation: both routes go through `image_ctx` (`project.annotate` for the POST, assigned rule for a labeler); the revision is re-checked against `image_id`, so a revision id from another image is 404, and a foreign workspace is 404.
- Secrets/safefetch: none.
- OpenAPI: yes — two routes.

## Acceptance criteria
- [ ] Every annotation save records one revision with author, kind and count, and a history read returns them newest first.
- [ ] Reverting restores the exact snapshot and appends a `revert` revision; the previous state is never deleted.
- [ ] A revert that would orphan a deleted class is refused with the class names and changes nothing.
- [ ] History is capped at 50 revisions per image and pruned in the same transaction.
- [ ] Empty, loading and error states above all render (the panel's states are T-145's).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ both routes 404 and no revision is written; saves behave exactly as today.
- [ ] Keyboard-only path: not applicable in this card.

## Notes for the implementer
Store the full annotation array per revision, not a diff: a 5,000-annotation image at 50 revisions is bounded by the same payload cap T-133 enforces, and diffs would need their own replay tests. Revert goes through `set_annotations`, so `ImageClass` and `n_annotations` stay consistent.
