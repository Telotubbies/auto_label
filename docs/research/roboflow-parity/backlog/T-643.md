## User story
As an ops lead, I want to set the two floors beside the class list and see how the batch will split before I spend a call, so that the review queue is a number I chose rather than a surprise after the job.

## UX flow (LabelDesk words)
1. **Auto label → Review policy** (`/:ws/:project/annotate`) — a `Card` under the class list with two number fields, "Accept at or above" and "Review down to", and the sentence "Boxes below the review floor are dropped and counted." [empty: before a preview, "Run a preview to see how this batch splits"] [loading: "Counting the bands on 4 samples…" while the preview runs, with the previous counts dimmed]
2. **An inverted policy** — `[error: the review floor must be below the accept floor]` under the second field; Preview and Run stay disabled.
3. **The default view** — a preview responds with a table: one row per class with accept / review / discard, a totals row, and a link "Open the review queue" that goes to `/:ws/:project/browse?status=review&tag=bucket=review`.
4. **The board** (`/:ws/:project/annotate`) — a banded run shows two cards above the columns: "Ready to use · 38" (`bg-success/15 text-success`) and "Needs review · 12" (`bg-warning/15 text-warning`), each opening its filtered grid. [empty: no banded run yet ⇒ neither card renders] [error: the last banded run failed ⇒ the existing failure banner names it]
5. **Job banner** — "38 accepted · 12 to review · 4 discarded" on the running card, from the job result.
6. **Flag off** — the panel is absent, the single slider and "send everything to Review" remain.

## Acceptance criteria
- [ ] Two floors are set in the dialog, the preview table splits every class into accept / review / discard, and Run carries the same numbers.
- [ ] After the run the board shows two queues with the same counts as the job report, each opening a correctly filtered grid.
- [ ] An inverted policy disables Preview and Run and names the field to fix.
- [ ] Empty, loading and error states above all render, including the pre-preview line and the zero-hit sample.
- [ ] Workspace A cannot read workspace B's counts: every number comes from this project's preview response.
- [ ] Flag off ⇒ no panel, no queue cards, and the single slider with "send everything to review" behaves exactly as today.

## Notes for the implementer
Show the review queue link only when the review count is above zero; a zero queue is a real result, not an error. Keep one sentence explaining that discard-band boxes are counted, never written — that is the difference between a policy and silent deletion. Percentages are stored as 0–1 in the payload and shown as whole percents in the fields.
