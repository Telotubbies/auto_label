## User story
As an operations lead, I want to tick two campaigns, see the union before I commit, and merge without
leaving Home, so that consolidation is a dialog instead of a data migration.

## UX flow (LabelDesk words)
1. **Home · project row menu** — **Merge projects** appears only when the workspace has ≥ 2 projects and
   the role can create projects. [empty: fewer than two → absent, not disabled]
2. **Merge dialog** — a checklist of projects (name, type, images); the new-name field is prefilled
   "A + B merged". Ticking sources updates the preview line: "840 images · 12 duplicates will appear once ·
   4 classes". [loading: the line shows "Calculating…" and the primary waits]
3. **Merge dialog** — **Merge** closes the dialog, shows "Merging 2 projects — follow it in the job tray",
   and lands on Home with the new project card in a "merging" state. [error: a 409 duplicate name → the
   name field shows "A project with this name already exists"]
4. **Home** — when the job finishes, the card shows its image count and a toast "Merged 2 projects · 828
   images". [empty: both sources empty → the primary is disabled with "Both projects have no images"]

## Acceptance criteria
- [ ] The action appears only with permission and at least two projects.
- [ ] The preview line reflects the ticked sources and blocks submit while it is loading.
- [ ] A duplicate name is refused in the field, not as a generic toast.
- [ ] After merging, Home shows the new project and the job finishes with an exact count.
- [ ] Empty, loading and error states above render.
- [ ] Flag off ⇒ no merge action anywhere.
- [ ] Workspace A cannot see or change workspace B's data: the checklist is built from `/projects` of the
      current workspace only.
