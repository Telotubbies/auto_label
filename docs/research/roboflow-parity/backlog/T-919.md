## User story
As a team lead with thirty finished runs, I want the Models page to show named models with their versions and a search box, so that I can find "the ppe model" without reading run names in reverse-date order.

## UX flow (LabelDesk words)
1. **Project → Models** (`/:ws/p/:project/models`) — the left rail becomes model groups: `ppe-detection` with `2 versions`, the best held-out score across them, the newest version's status pill and a *production* chip when an alias points into the group. [empty: no model at all keeps today's "No models yet — train a version to register the first one."] [loading: four group skeletons, each with two version lines] [error: "Models could not be loaded" + Retry, the right pane keeps the last selection]
2. **Search** — one box above the rail filters on the model name as you type, and the URL carries `?q=ppe` so a link reopens the same view. [empty: "No model matches “ppe”." + *Clear search*] [loading: the list dims, the previous results stay until the response lands]
3. **Expand a group** — clicking a model expands its versions newest first: `v3 · dataset v4 · mAP@50 0.71 · production`, `v2 · dataset v3 · mAP@50 0.68 · —`. Selecting a version keeps today's detail pane and writes `?model=<id>` exactly as now. [empty: a group whose every version was deleted is absent, never an empty accordion]
4. **Keyboard and deep links** — `?model=` on a version that the filter hides still selects it, and the rail scrolls that group open rather than showing the empty state.
5. **Reader without `project.models`** — the rail keeps its names and scores but no weights or evaluation link, as `visible_model` already masks them.
