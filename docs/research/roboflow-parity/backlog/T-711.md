## User story
As an inspector at the end of a line, I want the open lot, the unit in front of me and three large decisions on one card, so that the record is made while the part is in my hand instead of after the shift.

## UX flow (LabelDesk words)
1. **`ล็อตที่กำลังตรวจ`** — a bar above the stream's event list on `/:ws/:project/streams/:sid` shows the lot number, the work order and the three counters. [empty: `ยังไม่มีล็อตที่เปิดอยู่ — เปิดล็อตใหม่` with the open-lot button] [loading: `กำลังโหลดล็อต` as three skeleton chips] [error: `โหลดล็อตไม่สำเร็จ — ลองอีกครั้ง` with retry]
2. **Open a lot** — a small sheet takes `เลขล็อต` and `ใบสั่งผลิต`; a scan into the lot field submits on Enter, so a barcode scanner needs no click. [error: `หมายเลขล็อตนี้มีอยู่แล้วในโปรเจกต์นี้`]
3. **Decide the visible unit** — three buttons under the event's image: `ผ่าน` (success tone), `ไม่ผ่าน` (destructive tone), `ส่งซ่อม` (warning tone). `ไม่ผ่าน` opens the class picker, `ส่งซ่อม` opens the reason list and a due date. [loading: `กำลังบันทึกคำตัดสิน`] [error: `ล็อตนี้ปิดแล้ว — ยังบันทึกไม่ได้` and the card returns to the unit without a write]
4. **Rework comes back** — a unit already in rework shows `ส่งซ่อม · {reason} · กำหนด {date}` and only offers `ผ่าน` or `ไม่ผ่าน`, so a second rework is impossible.
5. **Close the lot** — `ปิดล็อต` is disabled while `undecided > 0` with the reason printed under it; on success the bar reads `ปิดล็อตแล้ว · {closed date}`. [error: `ปิดล็อตไม่ได้ — ยังมี {n} ชิ้นที่ไม่มีคำตัดสิน`]

## Backend changes
- Models/schema: none — T-710 shipped both tables.
- Routers: none — the screen calls `GET/POST /lots`, `GET /lots/current?station=`, `POST /lots/{id}/units` and `POST /lots/{id}/close`.
- Services/jobs: none.
- Permissions + workspace isolation: the page is already `<PermGate perm="project.streams">`; the decide buttons are disabled unless `can('project.review')` and the API enforces the same rule, so a crafted request from a viewer is 403. A lot id from another project is 404 through T-710's lookup.
- Secrets/safefetch: none.
- OpenAPI: no — no route changes.

## Acceptance criteria
- [ ] The bar shows the current lot with its number, work order and counters, and a lot is opened from it by typing or scanning.
- [ ] Three decisions are reachable in one click; a reject needs a class and a rework needs a reason and a due date, enforced by the API too.
- [ ] A closed lot disables the decisions and states why; the API refuses the same write with 409.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no lot bar and the stream page is byte-for-byte today's.
