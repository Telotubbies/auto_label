## User story
As the platform, I want a claimed `engine_apply` job to run the reviewed argv in a per-engine
environment, report progress and a log tail and stop on cancel, so that an install is observable,
bounded and never executes inside the API process.

## UX flow (LabelDesk words)
The visible surface is T-1009; this card supplies its job.
1. **Queued** — the job waits until a worker whose `--kinds` include `engine_apply` and whose name
   matches `params.host` claims it. The API process never claims it.
2. **Running** — phase `installing <engine>`, percent per engine, log lines appended.
3. **Cancelled** — the worker stops the current process group, removes the half-built environment and
   reports `cancelled`.
4. **Failed** — exit code and the last log line are kept; earlier engines that succeeded stay listed in
   `result.engines`.
5. **Done** — `result.engines` lists each engine, version, runtime and path; the next inventory reports
   them as installed.

## Backend changes
- Models/schema: none (job columns already exist).
- Routers (`apps/backend/app/routers/remote.py`):
  - `REMOTE_JOB_KINDS` gains `"engine_apply"` and `"model_pull"` (`config.py`), so claim and the reaper
    treat them as remote work.
  - `claim()` skips a candidate whose `params.host` is set and differs from `body.name`;
    `host_inventory.record(...)` (T-1001) stays.
  - `ProgressIn` gains `log: list[str] | None` and `phase: str | None`; `progress()` merges them into
    `j.result["log"]` (append, cap 200 entries, each ≤ 500 chars, `hf_…` redacted) and
    `j.result["phase"]`, keeping `heartbeat`.
  - `_payload()` gains one dispatch: for `engine_apply`/`model_pull` return
    `inference_jobs.payload(db, j)` (the model branch is T-1011's).
- Services/jobs: `inference_jobs.payload` returns `{host, action, engines:[{id, version, runtime,
  argv}]}` for `engine_apply`; the API rebuilds argv from the catalogue, never from the request body.
- Worker:
  - `apps/worker/labeldesk_worker/engines.py` (new) — `run_engine_apply(srv, job, args)`:
    1. Recompute `plan_id = sha256(canonical(steps, host, inventory_stamp))[:16]` from its **own**
       inventory and refuse a mismatch (`PlanChanged`), reporting `result.phase="stale_plan"`.
    2. `guard(argv, engines_dir)`: executable must be in `{uv, python, python3, docker, rm}`; every
       path-like argument must resolve under `engines_dir`; reject `..`, absolute paths outside it,
       shell metacharacters and `-` options that write outside (`--target`, `--prefix`, `-t`).
    3. `subprocess.Popen(argv, shell=False, cwd=engines_dir, env=minimal_env())`, stream stdout+stderr
       line by line to `progress(log=[line], phase=...)`, 30-minute timeout per engine.
    4. On `{"cancel": true}`: `terminate()` the process group, wait 10 s, `kill()`, remove the engine
       directory, report `cancelled`.
    5. Non-zero exit → `fail` with the code and the last line; success → `complete` with
       `result.engines`.
    Uninstall is the same handler with `action: "uninstall"` and the venv/docker argv.
  - `apps/worker/labeldesk_worker/cli.py` — `handlers["engine_apply"] = run_engine_apply`, an
    `--engines-dir` argument (default `LD_ENGINES_DIR` or `~/.labeldesk/engines`), and a refusal to run
    any engine handler unless `LD_ALLOW_ENGINE_INSTALL=1` (fail the job with
    `installs_disabled`).
- Permissions + workspace isolation: jobs are workspace-scoped; the payload only contains catalogue ids
  and argv, no tenant data.
- Secrets/safefetch: no fetch; `HF_TOKEN` is not passed to the install subprocess (minimal env drops it).
- OpenAPI: yes (the progress schema changes).

## Acceptance criteria
- [ ] `engine_apply` is claimed only by a worker that advertises the kind and matches `params.host`.
- [ ] The API process cannot claim it, proved with the embedded worker on.
- [ ] Arguments are an allowlisted argv; any path outside the engines directory is refused before exec.
- [ ] Progress carries a capped, redacted log tail and a phase; cancel leaves no half-built environment.
- [ ] Without `LD_ALLOW_ENGINE_INSTALL=1` the job fails with `installs_disabled` and runs nothing.
- [ ] A stale plan is refused, not executed.
- [ ] Existing `train`/`autolabel` claim and progress behaviour is unchanged.

## Notes for the implementer
Run each engine in its own process group and kill the **group**, or a pip subprocess survives a cancel.
A minimal environment (`PATH`, `HOME`, `LANG`, `TMPDIR`) keeps `HF_TOKEN` and other secrets out of an
install. Never `eval`, never `shell=True`, never join argv into a command string, including for logging
— log each argv element quoted.
