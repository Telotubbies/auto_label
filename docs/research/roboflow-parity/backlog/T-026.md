## User story
As a reviewer, I want to search every image in the workspace by text, class and tag, so that I can answer "where is this image used" without opening projects one by one.

## UX flow (LabelDesk words)
1. **Asset library** (`/:ws/assets`) — one search field and one `Filters` popover (project, type, class, tag, annotated, size, aspect, annotation count, date). Results load 60 at a time with `Load more`.
2. **Query** — free text matches the file name today; the richer query language (chips, negation, class counts) is area 2's `1-F4.3` work and plugs into this endpoint's single `q` parameter.
3. **No project access** — a project the caller cannot read never contributes rows *or facet counts*. [empty: `Nothing in this workspace matches.` when there are no images at all; `No images match these 3 filters. Clear filters.` when filters exclude everything] [loading: 12 tile skeletons] [error: `Could not search assets — Retry` keeps the typed query].

## Backend changes
- Models/schema: none — reads `images`, `image_classes`, `classes`, `projects`.
- Routers: `routers/assets.py` (new), prefix `/api/ws/{ws}/assets`: `GET ""` with `q, project, type, class_id, tag, annotated, split, min_mp, max_mp, min_ar, max_ar, min_ann, max_ann, since, until, sort, cursor, limit` → `{total, items: [{id, project, projectName, name, thumb, width, height, classes: [names], tags, created}], facets: {projects: [{slug, name, count}], classes: [{id, name, count}]}}`; `cursor` is `base64(created|id)` so paging is stable.
- Services/jobs: `services/asset_search.py` (new) — `visible_project_ids(db, ctx) -> list[str]` resolves the caller's `project.read` per project (same helper shape as `routers/workspaces.py:314`'s role loop), `search(db, ctx, params) -> dict` and `facets(db, ctx, params)`. One SQL statement per items page, one per facet group.
- Permissions + workspace isolation: `ws_ctx`, and every project id is filtered by `project.read` through `apply_project_role`; a `project` parameter outside that set returns an empty result, not 403; a foreign workspace slug is 404.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] One request returns items across every project the caller may read, each labelled with its project.
- [ ] Facet counts equal the filtered totals and never mention a project the caller cannot read.
- [ ] Empty, loading and error states above all render (workspace-empty vs filter-empty are distinguishable in the payload).
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ surface absent and the old behaviour unchanged (per-project `/images` untouched).
- [ ] A page of 60 images costs at most three SQL statements.

## Notes for the implementer
Do not copy the filter parser from area 2; take one `q` string plus the typed fields and let `1-F4.3` add the expression parser behind the same parameter. `total` is a count over the same predicate, never `len(items)`.
