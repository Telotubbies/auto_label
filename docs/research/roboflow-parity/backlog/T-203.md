## User story
As a reviewer, I want to keep a set share of deliberately empty frames instead of an all-or-nothing switch, so that background frames teach "nothing here" without drowning the signal.

## UX flow (LabelDesk words)
1. **Wizard → step 3 → Empty frames** — a percent slider *Keep 0–100% of empty frames* with three presets (0% / 10% / 100%). [empty: 100%] [loading: n/a] [error: "That percentage is not a number."]
2. **Warning block under the slider** — "Only frames you approved **with no annotations** count as empty. An image nobody has labelled is a different problem: it never enters a version." with a link to the board's *unlabelled* filter. [empty: n/a]
3. **Count line** — "12 empty frames in the pool → keeping 3" updates from the preview. [empty: "No empty frames in this pool."]
4. **Legacy** — a recipe with `filter_null: true` opens as 0% and shows the legacy note "this version dropped every empty frame".

## Backend changes
- Models/schema: none — null is *derived*: an image with `status == "done"`, no annotations and (when present) `review == "approved"`. Missing images never reach the pool because the pool already filters on `status == "done"`.
- Routers: none (recipe value); preview reports `pool.nulls_kept` / `pool.nulls_dropped`.
- Services/jobs: `app/services/versioning.py` — deterministic share keep: sort the null rows by `id`, keep `round(len * pct / 100)` of them after a seeded shuffle (`random.Random(seed)`), so the same recipe and seed always keep the same frames. `filter_null: true` normalises to `null_keep_pct: 0`.
- Permissions + workspace isolation: unchanged.
- Secrets/safefetch: none.
- OpenAPI: no.
- Flag: `task_190` off ⇒ only the boolean `filter_null` is honoured (current behaviour: drop every empty frame).

## Notes for the implementer
Do not add an `Image.null` column — null is derivable and a second source of truth would drift. State the derivation in one comment above the helper; the editor's "approve with zero annotations" path is what creates a null.
