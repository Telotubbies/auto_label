## User story
As an operator with boxes in the field, I want one list of devices with their last heartbeat and what is running on them, so that "is gate 3 alive" is a row instead of a phone call.

## UX flow (LabelDesk words)
1. **Deployments → Edge devices** (`/:ws/deployments?tab=edge`) — a table: device, services (running / total), streams, version, last heartbeat, health. Devices seen in the last 7 days first, then the rest, each sorted by heartbeat. A device unseen for 5 minutes reads `Offline`; that threshold is printed in the column header. [empty: no device → "No devices have checked in. Add one to get an install token." with the disabled reason when no fleet is configured] [loading: five skeleton rows] [error: "Devices could not load." with "Try again"]
2. **Add a device** — one dialog: name, optional project, optional "copy the config of" another device. It returns an install token shown **once**, with `Copy` and the line "This token is shown once. It lets one device enrol and nothing else." A `Duplicate config` action reuses another device's settings without copying its token.
3. **Version groups** — one read-only line: "Inference 3.2.1 · 4 devices", "Inference 3.1.0 · 1 device". Groups are derived from heartbeats and are not renameable.
4. **Health** — a per-device strip: disk %, camera FPS, inference FPS, and connectivity as the last heartbeat age. When a device has not reported a metric the strip says "not reported", never zero.
5. **Honest default** — with no fleet configured the tab renders one row of explanation: "Edge fleet management is not configured in this deployment." and no Add button.

## Backend changes
- Models/schema: new module `apps/backend/app/models/edge.py` — `EdgeDevice` (`id`, `workspace_id`, `project_id` nullable, `name`, `install_token_hash`, `token_used_at`, `services` JSON, `streams` JSON, `version`, `metrics` JSON (`disk_pct`, `camera_fps`, `infer_fps`), `last_heartbeat`, `config` JSON, `config_history` JSON list, `commands` JSON list, `maintenance_window` JSON, `created`, `updated`), registered in `models/__init__.py`.
- Routers: `apps/backend/app/routers/edge.py` (new) — `POST /api/edge/enroll` with `{token, name, version, services}` (token single-use, 15-minute validity, returns `{device_id, workspace}`); `POST /api/edge/devices/{id}/heartbeat` with `{metrics, services, streams, version}` (device token in `Authorization: Bearer`); `GET /api/ws/{ws}/edge-devices`; `POST /api/ws/{ws}/edge-devices` (create, returns the plain token once); `DELETE /api/ws/{ws}/edge-devices/{id}`.
- Services/jobs: `apps/backend/app/services/edge_fleet.py` (new) — `OFFLINE_AFTER_S = 300`, `mint_token() -> (plain, hash)` using `secrets.token_urlsafe` + HMAC with `config`'s secret, `enrol(db, token, body) -> EdgeDevice` refusing a used or expired token, `heartbeat(db, device, body)` updating metrics and version, `rows(db, workspace) -> list[dict]` sorting live-then-dead, `version_groups(rows)`, `health(device, now)`.
- Permissions + workspace isolation: the two `/api/edge/*` routes authenticate the device, never a user; the admin routes need `workspace.project.create` (owner/admin); a device id from another workspace is 404.
- Secrets/safefetch: the install token is stored hashed and shown once; a heartbeat carries no credential beyond its bearer token; no URL from a device is fetched.
- OpenAPI: yes — five routes, two of them unauthenticated-by-session.

## Tests to write first
pytest — `apps/backend/tests/test_edge_fleet.py`:
- `test_a_token_enrols_once` — the first enrol returns a device; the second with the same token is 409.
- `test_an_expired_token_is_refused` — a token minted 16 minutes ago is 410.
- `test_the_plain_token_is_returned_once_and_stored_hashed` — the create response contains the token, the row contains only its hash, and the list response never contains it.
- `test_a_heartbeat_updates_metrics_and_version` — disk, camera fps, infer fps and version land on the row.
- `test_a_device_silent_for_five_minutes_is_offline` — `health` flips at 301 s and the row sorts after the live ones.
- `test_metrics_the_device_did_not_report_stay_unreported` — a heartbeat without `infer_fps` leaves it `null`, and the row says so rather than zero.
- `test_a_foreign_device_is_404` for the admin routes.
- `test_flag_off_hides_every_route_including_enrol`.
node — `apps/frontend/tests/edge-devices.test.mjs`:
- `test_offline_is_decided_by_the_five_minute_threshold` — `health(now - 301, now)` is Offline and 299 is Online.
- `test_version_groups_are_counted_not_named` — two versions produce two groups with counts and no rename control.
- `test_an_unreported_metric_reads_not_reported` — a `null` disk renders the words, not `0 %`.

## Acceptance criteria
- [ ] A device enrols with a single-use 15-minute token, checks in, and appears with its version and metrics.
- [ ] Five minutes of silence reads Offline; an unreported metric reads "not reported".
- [ ] The install token is shown once, stored hashed, and never appears in a list response.
- [ ] Empty, loading and error states above all render, including "not configured in this deployment".
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no tab, no enrol route, and the catalogue's edge row returns to "Not available in this deployment.".

## Notes for the implementer
No hardware is specified and no vendor is named: this card defines the check-in contract a device must satisfy, and `LD_EDGE_FLEET=1` is what turns the surface on. Anything that pushes code or config to a device is T-359, which reads the same rows.
