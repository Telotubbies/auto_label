## User story
As an ML engineer, I want the version page to list the models trained on it and the exports it already has, so that the version is the place I come back to instead of hunting in two other screens.

## UX flow (LabelDesk words)
1. **Version detail → Runs on this version** — rows: run name, architecture, status, mAP50 when evaluated, and a link to the model page. [empty: "No runs yet — *Train on this version* starts the first one."] [loading: three skeleton rows] [error: "Could not load runs — retry"]
2. **Version detail → Exports** — one row per format already built: format label, size, "ready" with a download link for `project.export` roles, or progress with the percentage while it builds. [empty: "No exports yet — use *Export…*."] [error: the job's error line, not a toast]
3. **Repeat request is free** — clicking a format that already exists says "Built already — reusing the 3 min run" before showing the link (the API already returns the existing artefact).
4. **Delete dialog reads the count** — `modelCount` from this list feeds the consequence sentence in T-219 (one prop).
