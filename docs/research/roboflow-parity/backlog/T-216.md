## User story
As an ML engineer, I want my augmentations as ordered cards with a "start with none" note beside them, so that I can read what will run, reorder it, and resist the urge to tick everything.

## UX flow (LabelDesk words)
1. **Wizard → step 4 — Augmentation** — the ordered card list, each showing name, its parameters as one line ("±15° · inside each box"), a tier/scope chip and a remove action; *Move up / Move down* reorders (this order is the run order). [empty: "No augmentation — this is the recommended baseline. Add one only after a run without augmentation gave you a number to compare against."] [loading: n/a] [error: n/a]
2. **Baseline guidance panel** — a collapsible *How to choose* with three lines: start from zero; if the baseline is bad the problem is class balance, representation or dataset size, not augmentation; the symptom table (lighting → brightness/exposure, focus → blur/motion blur, sensor → noise/gain, mounting angle → rotation/shear/flip/90°, colour-irrelevant material → grayscale/hue/saturation, occlusion → cutout, many small objects → mosaic). [empty: n/a]
3. **Magnitude note** — "Strength and count are different dials: more images is the multiplier on the next step, stronger images is a bigger number here."
4. **Scope line** — one sentence under the list: "Augmentations apply to the **training split only**; valid and test keep the preprocessed originals."
5. **Preview** — one sample tile at the bottom rendered from the preview endpoint with the configured op chain, with a *Shuffle* action to re-roll the random draw. [loading: tile shimmer] [error: "Preview failed — generation still works."]

## Notes for the implementer
The shuffle request must send only `op_ids` (the table's defaults), never the configured params — the preview shows the *shape* of the augmentation, the numbers are already on the card. Keep `SYMPTOMS` as data so the node test can assert coverage.
