## User story
As the engineer who notices a leak at 02:00, I want to open one incident, see the hours I have left and a number for what is in scope, so that the notification starts with facts instead of an empty page.

## UX flow (LabelDesk words)
1. **Ops → Incidents** (`/:ws/ops/incidents`) — a table of incidents: severity chip, title, opened at, and the clock ("41:12 left" or "overdue by 6 h"). [empty: "No incidents — nothing has been opened for this workspace."] [loading: three skeleton rows] [error: "Couldn't load incidents." + `Try again`]
2. **`Open an incident`** — a dialog: title, severity (low, high, critical), discovered at (default now, never in the future), systems affected (checkboxes of the shipped component names), suspected cause. Saving starts the clock and names the on-call owner. [error: 422 → "Discovered at cannot be in the future."]
3. **The incident page** (`/:ws/ops/incidents/<id>`) — a solid `Card` header with the countdown, owner, severity and the four lifecycle states (investigating, identified, monitoring, resolved); the timeline lists every action newest first.
4. **`Count what is in scope`** — pick workspaces, projects and a window → "4,120 frames and 96 event clips in the window, counted from 2 projects" plus the exact query text under it, and the line "People cannot be counted from our data; the controller supplies the affected-subject number." [loading: "Counting…" with the button disabled] [error: "The scope query timed out — narrow the window."]
5. **`Add an update`** — one line of text and a state; the timeline appends it with the author and time.

## Backend changes
- Models/schema: `app/models/incidents.py` (new) — `Incident(id, workspace_id, title, severity, discovered_at, deadline_at, state, owner_id, systems JSON, cause, created, closed_at, notice_text, notice_sent_at)`, `IncidentUpdate(id, incident_id, state, text, user_id, created)`; register the module in `app/models/__init__.py`.
- Routers: `app/routers/incidents.py` (new) — `GET /api/ws/{ws}/incidents`, `POST /api/ws/{ws}/incidents` (201; 422 on a future `discovered_at` or an unknown severity), `GET /api/ws/{ws}/incidents/{iid}`, `PATCH /api/ws/{ws}/incidents/{iid}` (state and cause), `POST /api/ws/{ws}/incidents/{iid}/updates`, `POST /api/ws/{ws}/incidents/{iid}/scope` (the count and the query it ran).
- Services/jobs: `app/services/incidents.py` (new) — `SEVERITIES`, `STATES`, `open_incident(db, c, body) -> Incident` (sets `deadline_at = discovered_at + 72*3600`), `append(db, incident, state, text, user_id)`, `scope(db, workspace_id, projects, since, until) -> dict` counting `Image` rows and `StreamEvent` rows through indexed columns, `window_text(...)` for the query sentence, `remaining(incident, now) -> float`.
- Permissions + workspace isolation: `workspace.audit` (owner/admin) reads and writes; every statement filters `Incident.workspace_id == c.ws.id`, and an incident id from another workspace answers 404. The scope count may only name projects of this workspace.
- Secrets/safefetch: none.
- OpenAPI: yes.

## Acceptance criteria
- [ ] Opening an incident stores discovered time and a deadline exactly 72 hours later, and the table shows the countdown.
- [ ] The scope panel returns frame and clip counts with the query it ran, and states that people cannot be counted.
- [ ] Every incident action appends one timeline entry with author and time.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no nav entry, no route, all endpoints 404, and the DPA text is unchanged.

## Notes for the implementer
Owner-gated: who may open and close an incident, whether the 72-hour clock starts at discovery or at confirmation, and who signs the controller notice (INDEX §4.3). This card builds the clock and the count; it never writes the notification text — T-767 owns that, and the deadline stays a stored timestamp so a restart cannot reset it.
