## User story
As a workspace lead, I want to see the cycle's spend cumulative or per day, in credits or money, so that "will we run
out this cycle" and "what happened on Tuesday" are the same screen.

## UX flow (LabelDesk words)
1. **Usage & billing → Overview** — the chart card header: `Spend this cycle` with a `Cumulative` / `Per day` toggle,
   a `Cycle` / `Custom` date picker and a `Credits` / `Amount` switch. Cumulative is the default.
2. **Chart** — bars (per day) or one area (cumulative); the Y axis is credits, or currency when `Amount` is chosen
   and a per-credit price exists. [loading: skeleton the height of the chart] [error: `Could not load this range.` +
   retry, filters still usable]
3. **No price configured** — the `Amount` switch is disabled with the tooltip
   `No per-credit price is set for this workspace.`; nothing shows a made-up number.
4. **`[empty]`** the range records nothing: the axes render with `No usage in this range.` and `Clear range`.
5. **Table view** — a `Table view` disclosure under the chart lists the same days (date, credits, amount), so the
   numbers are readable and screen-reader friendly.

## Backend changes
- Models/schema: none (T-408's `CreditEvent` is the source).
- Routers: `GET /api/ws/{ws}/usage/series?since&until&granularity=day&mode=cumulative|daily&unit=credits|amount`
  → `{unit, price_per_credit: float | null, points: [{date, credits, amount | null}], totals: {credits, amount | null}}`.
  `400` for a range longer than 366 days or `until < since`.
- Services/jobs: `services/metering.py` — `series(db, ws, since, until, mode) -> list[dict]` (zero-filled days, one
  grouped query) and `price_per_credit(ws) -> float | None` reading `ws.quotas.get("price_per_credit")`; `None` means
  no amount is shown.
- Permissions + workspace isolation: `workspace.read`; the query is rooted at the workspace id.
- Secrets/safefetch: none.
- OpenAPI: yes.
