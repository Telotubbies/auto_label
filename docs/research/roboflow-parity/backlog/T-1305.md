## Problem
`safefetch` has good unit tests (`tests/test_r1_safefetch_timeout.py`,
`tests/test_r1_connector_ssrf.py`, `tests/test_stream_ssrf.py`), but the route-level attack surface is
covered only incidentally: search `q`, class names and tags, export and upload filenames,
`GET /api/files/{rel}`, stream sources, webhook URLs, connector URLs and MCP `upload_image_url`. Nobody
can answer "did we test traversal after the last refactor?" in one place.

## Design
One file, four groups, driven by payload tables. A **socket guard** fixture blocks every outbound
connection during the run (raise on `socket.connect`) except to the test client, so an SSRF that gets
past validation fails loudly instead of reaching the internet.

1. **SQLi** — payloads `' OR 1=1--`, `"`, `%`, `_`, `'; DROP TABLE images;--`, `\x00`, 5 000 chars, a
   UTF-8 combining sequence: into `q`, class name, tag, project slug, batch id, sort field. Assert: 200
   or 422, never 500, never a row from the other workspace, `images` table still there, and the payload
   is echoed only in the rendered name (never in a raw SQL fragment).
2. **Stored/reflected XSS** — `<img src=x onerror=alert(1)>`, `"><svg/onload=…>`,
   `javascript:alert(1)` in image name, comment, class name, tag, project name, workspace name. Assert
   the API returns the characters it stored (no double encode) **and** a repo-wide grep test proves no
   `dangerouslySetInnerHTML` receives an API field without the existing sanitiser.
3. **Traversal** — `../../etc/passwd`, `..\\..\\win.ini`, `%2e%2e%2f`, `....//`, absolute paths,
   NUL, 4 096-char names, Windows device names (`CON`, `NUL`, `AUX`) in: `GET /api/files/{rel}` (with a
   forged signature and with a valid one for a legal path), upload filename, export download name,
   version name, MCP `project` slug. Assert 400/404/403 and that no path outside `DATA_DIR` is opened
   (fixture wraps `open`/`Path.open`).
4. **SSRF** — every route that accepts a URL: upload-by-URL, stream source (`rtsp`, `http`), webhook
   URL, connector endpoint, MCP `upload_image_url`. Payloads: `http://169.254.169.254/latest/meta-data/`,
   `http://127.0.0.1:8000/api/health`, `http://[::1]/`, `http://0.0.0.0/`, `http://2130706433/`,
   `http://metadata.google.internal/`, `file:///etc/passwd`, `gopher://`, a public URL that 302s to
   `http://10.0.0.5/`, and a hostname resolving to both a public and a private address. Assert the
   request is refused with a user-facing message, the socket guard saw no connection, and
   `LD_STREAM_ALLOW_CIDR`/`LD_OT_ALLOW_CIDR` unset means private targets are refused.

## Files
Exclusive:
- `apps/backend/tests/test_sec_injection.py` (new, ~300 lines)
Shared: none expected. If a payload reveals a genuine defect, the one-line fix goes in the owning
module and is named in the report (`services/safefetch.py`, `routers/images.py`, `services/connectors.py`).

## Tests to write first
The four groups above, each as a `parametrize` over its payload table, with ids naming the payload.
Plus:
- `test_the_socket_guard_blocks_a_real_connection` — a control proving the guard works, so the SSRF
  group is not vacuous.
- `test_nul_byte_is_rejected_not_truncated` — a name with `\x00` does not create `passwd`.
- `test_windows_device_name_does_not_hang` — `CON` as a filename returns a user error within 2 s.

## Acceptance criteria
- [ ] Every payload group is in the gate and green; total file time under 25 s.
- [ ] No payload produces a 500, a stack trace or an SQL fragment in the response.
- [ ] The socket guard proves no outbound connection was attempted in the SSRF group.
- [ ] A traversal attempt never opens a path outside `DATA_DIR` (asserted by the `open` wrapper).
- [ ] The XSS group asserts both the API echo and the frontend grep guard.
- [ ] Any production change is one line per defect, named in the report, with the payload that found it.

## Notes for the implementer
Payloads are data, not prose: keep them in module-level tuples so a reviewer can read the table. Do not
weaken an existing SSRF test to make a payload pass — if the product lets a payload through, that is the
finding, and the PM decides. Skip nothing silently: a Windows-only path test uses `skipif(os.name !=
"nt")` *and* is listed in the report as not run on Linux.
