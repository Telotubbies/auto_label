## User story
As a workspace admin, I want folders inside folders and a way to move several projects at once, so that
"Customer A / Cameras / Line 3" is one tree instead of a flat list of names.

## UX flow (LabelDesk words)
1. **Home · sidebar** — **+ New folder** creates a folder at the top level or inside the selected folder
   (one level of nesting shown by indent). [empty: "No folders yet — create one to group projects."]
2. **Home** — the project row menu **Move project** lists folders; with several projects ticked the move
   applies to all. Dragging a project (or a folder) onto a folder also moves it. [error: dropping a folder
   into its own child → "A folder cannot move inside itself", the tree stays as it was]
3. **Home** — renaming a folder updates it in place; deleting a folder asks
   "Delete `Cameras`? Its projects and subfolders move up one level — nothing is deleted."
4. **Home** — a folder row shows its project count including subfolders ("12"), and an empty folder reads
   "No projects in this folder yet". [loading: the tree renders 4 skeleton rows]

## Backend changes
- Models/schema: `Folder.parent_id VARCHAR(32) NULL` in `models/project.py` plus `FOLDERS` block in
  `schema/dataset.py` (`{"parent_id": "VARCHAR(32)"}`) registered as a `STEPS` entry.
- Routers: `apps/backend/app/routers/workspaces.py`
  - `GET /folders` returns `{id, name, parentId, projectCount, totalProjectCount}` ordered by name.
  - `POST /folders` accepts `parentId`; `PATCH /folders/{fid}` accepts `name` and/or `parentId`;
    `400` for depth > 5 or a cycle; `404` for a folder outside the workspace.
  - `POST /folders/{fid}/projects` `{slugs: list[str]}` → `{moved}` in one transaction; `404` if any slug
    is outside the workspace; `400` when a slug is not readable by the caller.
  - `DELETE /folders/{fid}` — unchanged behaviour (contents move up one level); with nesting it sets
    children's `parent_id` to the deleted folder's parent and projects' `folder_id` likewise.
- Services/jobs: `apps/backend/app/services/folders.py` (new) — `depth(db, fid)`, `would_cycle(db, fid,
  parent)`, `delete_and_reparent(db, folder)`, `move_projects(db, ws, fid, slugs)`; all pure DB work so the
  routers stay thin.
- Permissions + workspace isolation: create/move needs `c.perm("workspace.project.create")`, rename/delete
  `c.need("admin")` (today's rule for delete); every lookup filters `workspace_id == c.ws.id`.
- Secrets/safefetch: none.
- OpenAPI: yes — two extended bodies, one new route.

## Acceptance criteria
- [ ] Folders nest to five levels; a sixth or a cycle is refused with a readable message.
- [ ] Moving one or many projects is atomic: an invalid slug moves nothing.
- [ ] Deleting a folder moves children and projects up one level and deletes no data.
- [ ] The tree returns rolled-up project counts.
- [ ] Empty/loading/error states above render.
- [ ] Flag off ⇒ flat folders exactly as today.
- [ ] Workspace A cannot see or change workspace B's data (404 for a foreign folder or slug).

## Notes for the implementer
Depth is counted from the root at write time, not stored. `Project.folder_id` and `Folder.parent_id` are
both nullable; a project at the root has `folder_id = NULL`, which the existing PATCH already handles.
