## User story
As an ML engineer, I want to replay twenty fixed images through a new build and see `18/20 match, 2 class flips` against the previous one, so that "the build changed behaviour" is a number before the line meets it.

## UX flow (LabelDesk words)
1. **Model → `บิลด์` tab** (the shipped model screen) — one row per build: profile, state, size, and the replay result. [empty: `ยังไม่มีบิลด์สำหรับอุปกรณ์`] [loading: the tab shows the shipped skeleton rows]
2. **`ทดสอบชุดทอง`** — queues the replay and the row reads `กำลังเล่นชุดทอง 12/20`; the job touches only the twenty stored images, never the camera. [error: `ไม่มีภาพครบ 20 ภาพในชุดทดสอบ — สร้างเวอร์ชันใหม่ก่อน`]
3. **The result** — `ตรงกัน 18/20 · พลิกคลาส 2` with the flipping classes named (`ถุงมือ → ไม่พบ`) and the build it was compared against. [empty: `ยังไม่ได้ทดสอบบิลด์นี้`]
4. **The first build of a model** — reads `ไม่มีบิลด์ก่อนหน้าให้เทียบ` and still stores the 20 predictions as the baseline for the next build.
5. **`ผูกกับอุปกรณ์`** stays available only for a build whose replay passed or which has no baseline; a mismatched device still answers 409.

## Backend changes
- Models/schema: none — the result is written into `EngineBuild.metrics["replay"]` (`{baseline, images, matched, flips, flips_by_class, against_build, at}`).
- Routers: `app/routers/engines.py` (T-682 created it) gains `POST /builds/{bid}/replay` → 202 with the queued `Job` (409 when the build is not `ready`); the existing `GET /models/{mid}/builds` returns `metrics.replay` per row.
- Services/jobs: `app/handlers/replay.py` (new) with `run_golden_replay(job)` registered in `handlers/__init__.py` `MODULES` (the registry composes itself) and `golden_replay` added to `config.LOCAL_JOB_KINDS`; `app/services/golden.py` (new) — `pick_golden(db, model, limit=20)` (the first 20 val-split images ordered by id, so the set is stable), `predict_set(adapter, build, images)`, `compare(current, previous)` returning `{matched, flips, flips_by_class}` where a mismatch is a different class set on the same image at the model's own confidence threshold.
- Permissions + workspace isolation: the replay route needs `c.need("admin")` and resolves the build through `workspace_id` + `project_id`; the job re-reads the build by id and fails cleanly (`ไม่มีภาพครบ 20 ภาพ`) rather than raising through the worker.
- Secrets/safefetch: none — images are local files.
- OpenAPI: yes — one new route.

## Acceptance criteria
- [ ] A ready build can be replayed over twenty stable stored images and the row shows matched, total and class flips.
- [ ] The first build stores a baseline and says there is nothing to compare; the next build compares against it.
- [ ] A version with fewer than twenty images fails with a sentence and leaves the previous metrics intact.
- [ ] Empty, loading and error states above all render.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no `บิลด์` tab and the model page is today's.

## Notes for the implementer
Twenty images, ordered by id, from the model's own val split — a random sample would make two runs incomparable and a training-split sample would flatter the build. Compare class *sets* per image at the model's own threshold, not per-box IoU: the question this answers is "did the decision change", and a flipped class is what the line feels. Copy: `engines.replay`=`ทดสอบชุดทอง`, `engines.replayRunning`=`กำลังเล่นชุดทอง {n}/{total}`, `engines.replayResult`=`ตรงกัน {matched}/{images} · พลิกคลาส {flips}`, `engines.replayIdle`=`ยังไม่ได้ทดสอบบิลด์นี้`, `engines.replayBaseline`=`ไม่มีบิลด์ก่อนหน้าให้เทียบ`, `engines.replayShort`=`ไม่มีภาพครบ 20 ภาพในชุดทดสอบ — สร้างเวอร์ชันใหม่ก่อน`.
