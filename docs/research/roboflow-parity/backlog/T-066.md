## User story
As an operations engineer, I want one big archive to become a background job I can leave, and a camera
gateway to hand me an image URL, so that neither path blocks my tab or my laptop.

## UX flow (LabelDesk words)
1. **Upload** — dropping a 6 GB zip returns immediately with "Archive import started — 18,400 files
   queued" and a job-tray row "Archive import · 0%". [loading: the tray shows a determinate bar]
   [error: a corrupt zip → "That file is not a valid .zip", nothing queued]
2. **Any screen** — the user navigates away; the job tray keeps the row, and the project rail count
   updates when it finishes. [empty: an archive with no supported image inside → "That archive holds no
   images LabelDesk can import", nothing queued] [error: quota hit mid-way → tray row reads "Stopped at
   the plan limit — 12,000 of 18,400 imported"]
3. **Upload** — "Add from URL" accepts `https://…/frame.jpg`, shows the fetched thumbnail in the
   pre-flight list, and imports it like a dropped file. [error: a private or unreachable URL →
   "That address is not reachable from LabelDesk", the row stays un-ticked]

## Backend changes
- Models/schema: none (job rows already exist; `Job.result` carries the counts).
- Routers:
  - `apps/backend/app/routers/uploads.py` (new), prefix `/api/ws/{ws}/projects/{project}`:
    - `POST /uploads/archive` (multipart `file`, `batch_name`, `split`, `tags`, `to_dataset`) —
      reads the body up to `MAX_UPLOAD_MB`, rejects a non-zip with 400; counts entries with
      `zipfile.ZipFile.infolist()`. ≤ 300 entries → runs `ingest(...)` inline and returns
      `200 {"mode": "sync", "result": {...}}`; larger → stores the archive under
      `DATA_DIR/uploads/{job_id}.zip`, adds `Job(kind="archive_ingest")`, returns
      `202 {"mode": "job", "job": job_out(j)}`.
    - `POST /uploads/from-url` (`url`, `batch_name`, `split`, `tags`, `to_dataset`) — `safefetch.fetch_bytes`
      (cap 20 MB, no redirects), then `ingest(...)`; returns `200` with the ingest result;
      `BlockedURL` → `400 {"detail": "That address is not reachable from LabelDesk"}` (no host echo).
  - Both routes call `routers.images.ingest` — the one refusal rule set (size, plan, unreadable,
    2 000/request) is reused, never re-implemented.
- Services/jobs: `apps/backend/app/handlers/intake.py` (new) — `run_archive_ingest(job)` opens the stored
  zip, feeds `ingest` in chunks of 25 entries (the connector-sync chunk size), `jobs.check(job)` per
  chunk, deletes the temp archive in `finally`, and returns `{uploaded, duplicates, annotated, failed}`.
  Registered as `HANDLERS = {"archive_ingest": run_archive_ingest}` and `"archive_ingest"` added to
  `LOCAL_JOB_KINDS` in `config.py`.
- Permissions + workspace isolation: `c.perm("project.upload")` on both routes; the job's `project_id`
  and `workspace_id` come from `project_ctx`; a foreign project is a 404. The handler re-reads the
  project inside its own session and refuses when it is deleted.
- Secrets/safefetch: `services/safefetch.py` only; no credentials, no redirect following.
- OpenAPI: yes (two new routes, new schemas).

## Acceptance criteria
- [ ] An archive over 300 entries becomes a job with a real id that the tray can follow; a small one
      completes inline.
- [ ] Cancelling the job stops between chunks and leaves no half-written batch that reports success.
- [ ] A URL import refuses private, link-local and non-http(s) addresses with one user-facing sentence.
- [ ] All refusals come from `ingest`; this card adds no second size/plan/readable rule.
- [ ] Empty/loading/error states above render (tray progress, corrupt-zip error, URL error).
- [ ] Flag off ⇒ both routes 404, the existing `/upload` multipart path is unchanged.
- [ ] Workspace A cannot see or change workspace B's data (404 for cross-workspace project ids); the
      fetcher cannot be pointed at an internal host by workspace B either.

## Notes for the implementer
The 300-entry split is decided server-side from `len(infolist())`, so the browser sends one request
either way (no client zip parser is added — none is installed and `DecompressionStream` would mean an
80-line reader for no user-visible gain). Store the archive under `DATA_DIR/uploads/`, never `DATA_DIR`
root, and delete it on success, failure and cancellation alike.
