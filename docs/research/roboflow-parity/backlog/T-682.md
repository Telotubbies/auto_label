## User story
As an ML engineer shipping to a Jetson fleet, I want every engine to record the TensorRT and CUDA version it was built against and the device it was pinned to, so that replacing box 14 is a lookup instead of a support ticket with no artifact trail.

## UX flow (LabelDesk words)
1. **`สร้างบิลด์`** — a manager picks a target profile (`Jetson Orin · TRT 10.3 · CUDA 12.6`) beside the existing export action; the build queues and the row reads `กำลังสร้างบิลด์` until it lands. [empty: `ยังไม่มีบิลด์สำหรับอุปกรณ์`] [error: `สร้างบิลด์ไม่สำเร็จ — ดูบันทึกของงาน`]
2. **The profile is recorded, not typed twice** — the build row carries device, TRT and CUDA, and the artifact path it wrote; a build made before this card reads `ไม่ทราบโปรไฟล์` rather than inventing one.
3. **`ผูกกับอุปกรณ์`** — choosing a registered device pins the build; a device whose profile differs answers 409 `บิลด์นี้ไม่ตรงกับโปรไฟล์ของอุปกรณ์` at pairing time, not at inference time. [loading: the pin button reads `กำลังผูก` under a second]
4. **A replaced box** — a technician opens `อุปกรณ์`, sees the device's profile and the build it served, and pins the same build to the replacement; the history of who pinned what stays readable.

## Backend changes
- Models/schema: `app/models/engine.py` (new) — `EngineBuild(id, workspace_id, project_id, model_id, profile JSON (device, trt, cuda, os, arch), artifact_path, bytes, state (queued|building|ready|failed), metrics JSON, error, created, updated)` with `Index(project_id, model_id)`; `DeviceTarget(id, workspace_id, project_id, name, profile JSON, build_id nullable, last_seen nullable, created, updated)` `UniqueConstraint(project_id, name)`. Register in `models/__init__.py`; `create_all` creates both, no `ADD COLUMN`.
- Routers: `app/routers/engines.py` (new), prefix `/api/ws/{ws}/projects/{project}`, `dependencies=[Depends(require_flag("task_engine_registry"))]`; `POST /models/{mid}/builds` `{device, trt, cuda}` → 202 with the `EngineBuild`; `GET /models/{mid}/builds`; `POST /builds/{bid}/pin` `{device_id}` → 200 or 409 on a profile mismatch; `POST /devices` `{name, device, trt, cuda}` → 201, 409 duplicate; `GET /devices`; `PATCH /devices/{id}`. 400 for an unknown device family or a `trt`/`cuda` that is not `major.minor`, 409 already queued.
- Services/jobs: `app/handlers/versioning.py::run_export_engine` reads `job.params["profile"]`, writes `DATA_DIR/engines/<mid>.<device>.engine`, creates and updates the `EngineBuild` row, and keeps the legacy `<mid>.engine` path for a build with no profile. `app/services/engines.py` (new) — `PROFILES` (the four device families with `trt`/`cuda`/`arch` bands), `compatible(build, device) -> bool` (device family and TRT major/minor must match), `pin(db, build, device)`.
- Permissions + workspace isolation: every route needs `c.need("admin")`; builds and devices are filtered by `workspace_id` **and** `project_id`, and a build or device id from another workspace is 404 before any write. Pin, build and register each write an `audit()` row.
- Secrets/safefetch: none — a profile is three strings and a pairing is a row; no credential is stored and nothing is dialled.
- OpenAPI: yes — six routes and their schemas.

## Acceptance criteria
- [ ] A build records its device, TensorRT and CUDA profile and the artifact path it wrote, and a legacy build reads `ไม่ทราบโปรไฟล์`.
- [ ] Pinning a build to a device with a different profile is refused with 409 and writes no link; a matching pin links both rows.
- [ ] A device is registered, listed and patched, and the station page can name the build that device serves.
- [ ] Empty, loading and error states above all render — no build reads `ยังไม่มีบิลด์สำหรับอุปกรณ์` and a failed build keeps its error sentence.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ the six routes 404, no profile is recorded, and the legacy unprofiled engine path is today's.

## Notes for the implementer
Compatibility is **device family plus TRT major.minor**, nothing smarter: an engine built for 10.1 will not load under 10.3 and a different GPU family needs its own plan, so refuse at pairing with one sentence rather than at inference with a traceback. Never overwrite the legacy `<mid>.engine` path from a profiled build — an existing stream still points at it. Copy: `engines.builds`=`บิลด์สำหรับอุปกรณ์`, `engines.pin`=`ผูกกับอุปกรณ์`, `engines.mismatch`=`บิลด์นี้ไม่ตรงกับโปรไฟล์ของอุปกรณ์`, `engines.empty`=`ยังไม่มีบิลด์สำหรับอุปกรณ์`, `engines.building`=`กำลังสร้างบิลด์`, `engines.buildFailed`=`สร้างบิลด์ไม่สำเร็จ — ดูบันทึกของงาน`, `engines.unknownProfile`=`ไม่ทราบโปรไฟล์`, `engines.pinning`=`กำลังผูก`, `engines.devices`=`อุปกรณ์`.
