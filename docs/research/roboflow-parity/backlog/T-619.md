## User story
As a labeler starting a shift, I want one ordered list of the tasks I can act on, so that I start work in a click instead of finding my batch card on a board.

## UX flow (LabelDesk words)
1. **Project → Queue** (`/:ws/:project/queue`) — stage chips across the top with counts (`Unassigned 40`, `Annotating 12`, `Review 8`, `Dataset 300`); the table below lists priority, image, dataset, assignee, status and age. [empty: "Nothing assigned in this stage." with a link to the board] [loading: five skeleton rows] [error: "This queue did not load." + `Retry`]
2. **Filters** — assignee and status `Select`s, both reflected in the URL so a link keeps the view.
3. **Select rows → `Assign`, `Release`, `Priority`, `Move to`** — the sticky action bar appears once anything is selected; a labeler sees only `Release` and `Priority` on their own rows, reviewers see all four. [error: "Already claimed by another person." for a row someone else holds]
4. **`Start`** — opens `/:ws/:project/images/<id>?status=<status>`, the same single-image editor the board opens.
5. **At the cap** — the claim action is disabled with "At cap — release work before claiming more.", and the header shows "3 open · cap 5".

## Backend changes
- Models/schema: none — the screen renders the queue payload T-618 defined, including `ProjectMember.task_cap`.
- Routers: none — `GET`/`POST /queue` and `PUT /queue/caps` ship in T-618.

- Permissions + workspace isolation: none added; the calls are project-scoped and a foreign image id is the 404 T-618 returns.
- Secrets/safefetch: none.
- OpenAPI: no.

## Acceptance criteria
- [ ] `/queue` lists the stage counts and rows in priority order, and filters survive a reload because they are in the URL.
- [ ] Selecting rows shows the bulk bar; a labeler never sees `Assign` or `Move to`, and the cap disables the claim with the cap sentence.
- [ ] `Start` opens the same editor the board opens, on the chosen status.
- [ ] Empty, loading and error states above all render: the empty stage line, skeleton rows, the load error with `Retry`, and the already-claimed sentence.
- [ ] Workspace A cannot see workspace B's queue: the screen calls this project's route only and a foreign id renders the 404 sentence.
- [ ] Flag off ⇒ no nav entry, no route and the board is unchanged.

## Notes for the implementer
One table, not four lanes: the board stays as it is for batch moves and this screen owns individual work. `Priority` is −5..5 and 0 is the default — render 0 as a muted `—` so an unprioritised row does not look negative.
