## User story
As a shift engineer, I want an event that cannot be stored right now to wait on the box in order, so that a full quota at 02:00 costs me a delay instead of the evidence for the one reject that mattered.

## UX flow (LabelDesk words)
1. **A rule fires while the quota is full** — the event row is still written and the frames go to the spool instead of being dropped; the event keeps `snapshot_error: "buffered"` so the timeline says the picture is waiting, not lost. [empty: with an empty spool the status read is `0 เหตุการณ์ · 0 MB`, not an error]
2. **A rule fires while the database is unreachable** — the same path writes the event to disk and the operator's frame stays visible; nothing raises into the capture loop. [error: a disk that cannot be written is the one failure that stays visible: `บันทึกชั่วคราวไม่สำเร็จ — พื้นที่ดิสก์เต็ม`]
3. **The ceiling is reached** — the policy drops the oldest images first and keeps every event row, so "what happened" survives even when "what did it look like" does not. [loading: the policy is read with the project, so the page renders before the first drop]
4. **The frame T-674 renders** — `รอส่ง 1,284 เหตุการณ์ · 412 MB · เก่าสุด 3 ชม.`; this card only produces those numbers through `GET …/spool/status` (surface in T-674).

## Backend changes
- Models/schema: `app/models/spool.py` (new) — `SpoolItem(id PK (the event id), workspace_id, project_id, stream_id, kind, payload JSON, blob_path, bytes, device_ts, created, state ('pending'|'sent'|'dropped'), attempts, last_error)` with `Index(project_id, state, created)`. Register in `models/__init__.py`; `create_all` in `bootstrap.py` creates it, so there is no `ADD COLUMN` block and no backfill. The ceiling policy lives on `Project.settings["spool"]` (`{"ceiling_mb": 512, "drop_order": ["image", "verdict"]}`), not in a table.
- Routers: none in this card (T-674 adds `/spool/status`, `/spool/policy`, `/spool/drain`); the writer is called from the stream worker.
- Services/jobs: `app/services/spool.py` (new) — `root() -> Path` (`DATA_DIR/spool/<project id>/`), `enqueue(db, *, event_id, workspace_id, project_id, stream_id, kind, payload, blob: bytes | None, device_ts) -> SpoolItem` (idempotent on the event id: a second call returns the existing row), `usage(db, project) -> {"items", "bytes", "oldest_age_s", "dropped_images"}`, `policy(project) -> {"ceiling_mb", "drop_order"}` with validation (`ceiling_mb` 64–20480, `drop_order` a non-empty subset of `image|verdict`, `image` before `verdict`), `enforce_ceiling(db, project) -> {"dropped": n, "freed": bytes}`, `blob_path(item) -> Path` and `read_blob(item) -> bytes`. The worker calls `enqueue` from `streams/manager.py::_record` in the two places that currently lose the frame: the `elif size:` quota branch, and the `except` around the event insert.
- Permissions + workspace isolation: nothing reads this service over HTTP yet; every helper takes `project_id` **and** `workspace_id` and filters both, so T-674's routes cannot leak a foreign row. The blob path is built from ids only, never from a user string, and `blob_path()` resolves under `DATA_DIR` and refuses a path that escapes it (the `retention._inside` pattern).
- Secrets/safefetch: none — no URL is fetched and no credential is written; the payload is the event dict the rule engine already produced.
- OpenAPI: no — no route changes here.

## Acceptance criteria
- [ ] A quota block or a failed event insert writes the event and its frames to the spool instead of dropping the image, and the event row says `buffered`.
- [ ] Re-recording the same event id never produces a second spool row or a second blob.
- [ ] The disk ceiling drops images before event rows and reports how many were dropped.
- [ ] Empty, loading and error states above all render — an empty spool reads `0 เหตุการณ์ · 0 MB` and a full disk is the only error the writer surfaces.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids) — every helper filters `workspace_id` as well as `project_id`.
- [ ] Flag off ⇒ `_record` behaves exactly as today: `snapshot_error: "storage quota reached"`, no spool file, no spool row.

## Notes for the implementer
The spool id **is** the `StreamEvent` id, which is what makes the drain in T-674 idempotent: the drained row is inserted with that id and a duplicate is skipped, never re-numbered. Order the ceiling drop by `created` ascending and never touch a row whose `state` is `sent`; a policy that drops both kinds is refused rather than silently emptying the box. `snapshot_error` uses the single word `buffered` so the existing timeline renders one sentence and no new column is needed.
