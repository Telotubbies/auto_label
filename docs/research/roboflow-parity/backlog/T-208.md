## User story
As an ML engineer, I want augmentations to be an ordered list of configured steps with documented bounds, so that what I see in the wizard is exactly what runs on each image.

## UX flow (LabelDesk words)
1. **Wizard → step 4** — the recipe carries `augmentation.ops: [{id, scope, params}]`; the rendered order is the order they run in.
2. **A legacy version** — a flat `{"flip_h":true,"blur":5}` recipe opens as two ordered ops, and regenerating from it produces the same pixels as today. [empty: "No augmentation — the recommended baseline."] [loading: n/a] [error: "Blur must be 0–25 px." under the field]
3. **Tier chip on every op** — *Basic* or *Premium*; a premium op on a plan without it shows "Available on Pro and Enterprise." and the op is not added.

## Notes for the implementer
The table (id · params · tier · scope · affects) is the whole feature; write it once, in this order:

| id | params (min–max, default) | tier | scope |
|---|---|---|---|
| `flip` | horizontal, vertical (bool, true) | basic | both |
| `rotate90` | direction: cw, ccw, upside-down (bool, cw) | basic | both |
| `crop` | drop % 0–50 (10) | basic | both |
| `rotate` | degrees 0–180 (15) | basic | both |
| `shear` | horizontal 0–30, vertical 0–30 (0) | basic | both |
| `grayscale` | percent 0–100 (10) | basic | image |
| `hue` | degrees 0–180 (15) | basic | image |
| `saturation` | percent 0–100 (20) | basic | image |
| `brightness` | up % 0–100 (15), down % 0–100 (15) | basic | both |
| `exposure` | percent 0–100 (10) | basic | both |
| `blur` | px 0–25 (2) | basic | both |
| `noise` | percent 0–25 (2) | basic | both |
| `gain` | percent 0–100 (10) | basic | both |
| `motion_blur` | length px 0–100 (10), angle 0–180 (0) | basic | both |
| `cutout` | count 1–10 (3), size % 1–50 (10) | premium | image |
| `mosaic` | images 3–9 (4) | premium | image |

`crop` is the only op that loses labels (boxes fully outside are dropped, partial ones clipped, no minimum-area control yet — say so in the card copy).
