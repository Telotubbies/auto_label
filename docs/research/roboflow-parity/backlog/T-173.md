## User story
As a reviewer judging an auto-label batch, I want the sample preview to show how sure each label is and the
board to show how the batch is progressing per class, so that I can decide "run it" and "approve it" from
evidence rather than from a blank percentage.

## UX flow (LabelDesk words)
1. **Auto-label dialog · sample preview** — each drawn box carries a small chip with its class name and
   confidence ("Harness 0.91"); hovering a chip highlights the box and vice versa. A footer line summarises
   "5 samples · 23 labels · 2 below your threshold". [empty: samples return no labels → "Nothing found above
   40 % — lower the threshold or check the prompt", with the threshold slider focused] [loading: the four
   sample tiles show skeletons at final size, not spinners] [error: "Sample run failed — <server sentence>",
   with Retry and no credit charged]
2. **Start batch** — unchanged; the job appears in the tray and on the board.
3. **Annotate board · job card** — one card per batch (not per assignee): batch name, "Running · 312 / 1,200",
   a per-class count line ("harness 180 · vest 96 · helmet 36"), and `Pause`/`Cancel` where the job supports
   it. [loading: first seconds show "Queued" with no fake percentage] [error: "Stopped at 312 · 4 images
   failed — open the report"; the card stays on the board until dismissed] [empty: no jobs today → the card
   area is absent, not an empty box]
4. **Completion** — the card becomes "Review 312 new labels" with the same count as the review lane; clicking
   opens the first new image. A toast names the batch.
5. **Board refresh** — counts poll with the existing job tray cadence; no new websocket.

## Backend changes
- Models/schema: none — `Job.result` already holds progress; add `per_class` and `failed_ids` keys, no column.
- Routers: `POST /api/projects/{id}/autolabel` response and `GET /api/projects/{id}/jobs` items gain
  `per_class: dict[str, int]` and `failed: int`; the preview endpoint returns `labels[].confidence` (already
  computed) and `below_threshold: int`.
- Services/jobs: `handlers/training.py` autolabel stage writes `per_class` as it goes (single counter dict,
  flushed with the existing `result` write); no new job kind.
- Permissions + workspace isolation: unchanged; job listing already scoped by project.
- Secrets/safefetch: none.
- OpenAPI: yes — response fields; regenerate.

## Acceptance criteria
- [ ] Every preview label shows its class and confidence; the summary counts labels below threshold.
- [ ] The board shows one card per batch with running counts that match the job tray.
- [ ] A failed or stopped job keeps its counts and offers the report.
- [ ] Empty, loading and error states above all render; no fake percentage before the first count.
- [ ] Workspace A cannot see or change workspace B's data (404).
- [ ] No flag: the surfaces extend existing unflagged screens, and existing autolabel tests stay green.

## Notes for the implementer
Confidence formatting is one decimal (0.91), the same as the proposal chip in the editor. Per-class order is
count descending, then class name, so two runs of the same data read the same.
