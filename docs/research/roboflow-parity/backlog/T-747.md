## User story
As a security lead, I want to set a minimum retention for the audit log and read a verified range on the audit page, so that the contract's "we keep these records for a year" is a setting with evidence, not a sentence in a PDF.

## UX flow (LabelDesk words)
1. **Workspace sidebar → `Audit log`** (`/:ws/audit`) — the page gains two `Tabs`: `Entries` (today's table) and `Integrity`. [loading: the shipped skeleton rows for Entries; the Integrity tab shows three skeleton lines] [error: "Could not load the integrity report." + **Try again**]
2. **`Integrity` → pick a range → `Verify`** — the default range is the last 90 days; the result reads `"12,430 events, chain intact, 2 gaps"` with the two gaps listed (`"2 Mar 2026 04:00–04:12 — no rows written"`). [loading: `Verifying 12,430 events…` with the shipped `Spinner`] [empty: "No audit rows in this range."]
3. **A break** — the verdict is destructive-toned: `"Chain break at event 88201 — stop deleting logs and open a ticket."` / `"พบจุดที่สายโซ่ขาดที่เหตุการณ์ 88201 — หยุดลบบันทึกและแจ้งทีม"`, and the gaps list stays visible.
4. **`Download digest`** — a `.txt` beside the CSV export, named `audit-chain-<ws>-<date>.txt`.
5. **`Retention floor`** — one `Select` (1 year / 18 months / 2 years / 5 years) and one line: `"Records younger than the floor are kept even if someone asks for deletion. This cannot be undone."` / `"บันทึกที่อายุน้อยกว่ากำหนดนี้จะถูกเก็บไว้ แม้มีผู้ขอให้ลบ และไม่สามารถย้อนกลับได้"` Setting it asks for the step-up sheet; lowering it later is refused with `"A retention floor cannot be lowered. Contact support."`
6. **Floor not set** — `"No floor is set. Records are kept until someone deletes them."` and the Verify result prints `"floor: not set"` so nobody reads "intact" as "retained".

## Backend changes
- Models/schema: `Workspace.audit_retention_days INTEGER DEFAULT 0` (0 = not set; one `ADD COLUMN` key in the `WORKSPACES` block of `app/schema/identity.py`). No new table.
- Routers: `GET /api/ws/{ws}/audit/retention` → `{floor_days, floor_set: bool, oldest_row: float | null, oldest_with_hash: float | null}`; `PATCH /api/ws/{ws}/audit/retention {floor_days}` (owner/admin, step-up, `workspace.audit`) → 400 `"a retention floor cannot be lowered"` when the new value is below the stored one, 400 when below 365 or above 3650, audit row `audit.floor` with `from`/`to`.
- Services/jobs: `app/services/audit_chain.py` gains `floor(ws) -> dict` and `assert_floor(ws, floor_days, requested)` (the single comparison both routes use); the verify result gains `floor_days` so the report can print it.
- Permissions + workspace isolation: both routes are `workspace.audit`; the floor is read from `c.ws` (resolved by slug), so a foreign workspace id is 404 and no tenant's floor is visible in another.
- Secrets/safefetch: none.
- OpenAPI: yes — two routes and one workspace field.

## Tests to write first
pytest — `apps/backend/tests/test_audit_retention_floor.py`:
- `test_a_floor_is_stored_and_reported` — `PATCH` with 365 → `GET` returns `floor_days: 365`, `floor_set: true`, and an `audit.floor` row exists.
- `test_a_floor_cannot_be_lowered` — a second `PATCH` with 180 is 400 whose detail contains `cannot be lowered`, and the stored value is still 365.
- `test_a_floor_outside_the_range_is_400` — 30 and 4000 are both 400 naming the accepted range; a non-admin is 403.
- `test_zero_means_not_set_and_is_reported_as_such` — a fresh workspace returns `floor_days: 0`, `floor_set: false`, and the integrity report carries `floor_days: 0`.
- `test_no_code_path_deletes_audit_rows` — grep the backend source for `delete(Audit)` / `DELETE FROM audit` outside `tests/` and assert no hit, so the floor has nothing to defend against today.
- `test_foreign_workspace_is_404` — a workspace the caller is not a member of never returns its floor.
node — `apps/frontend/tests/integrity-tab.test.mjs`:
- `test_verdict_line_reads_the_count_and_the_gaps` — 12430 with 2 gaps reads the count with a thousands separator and `2 gaps`; one gap is singular.
- `test_a_break_names_the_event_and_the_action` — `{intact: false, break_at: 'a1b2'}` reads the break sentence with the id, and its tone is `failed`.
- `test_an_empty_range_says_so_instead_of_intact` — `{events: 0}` reads "No audit rows in this range.", never "chain intact".
- `test_floor_sentence_covers_not_set_and_years` — `floorSentence(0)` reads the not-set sentence; `floorSentence(365)` says one year, not 365 days.
- `test_digest_filename_is_stable_per_day` — the filename contains the workspace slug and the date and ends in `.txt`.

## Acceptance criteria
- [ ] The Integrity tab verifies a chosen range, prints intact/break/gap with counts, and lists each gap with its reason.
- [ ] A retention floor can be set, is refused when lowered, and is printed in both the retention section and the verify result.
- [ ] The digest downloads as a text file beside the CSV export.
- [ ] Empty, loading and error states above all render: an empty range, the verifying spinner with the event count, and the load error with **Try again**.
- [ ] Workspace A cannot see or change workspace B's data (404, not 403, for cross-workspace ids).
- [ ] Flag off ⇒ no Integrity tab, no retention section, and the audit page is today's single table.

## Notes for the implementer
Owner-gated: how long the audit floor is — one year, the contract term, or longer — and whether it may ever be lowered, is a promise the owner signs, not a default an engineer picks; ship 365 days as the only offered minimum and "not set" until someone chooses (INDEX §4.3). The floor is a stored promise, not a deletion mechanism: nothing in the codebase purges audit rows today, and the test that says so is what keeps this honest. Never render "chain intact" alone — the floor line and the gap list are what stop a reader assuming more than the data proves.
