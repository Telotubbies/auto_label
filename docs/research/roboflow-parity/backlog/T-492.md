## User story
As a labeler who opened a shared link on my phone, I want a clear "this needs a desktop" notice with the link to copy, so that I stop trying to draw a box at 375 px and do not lose the image I was sent.

## UX flow (LabelDesk words)
1. **375 px, `/p/:project/annotate/:imageId`** — the image renders read-only with its boxes, the filename and the review state; above it a notice: "Boxes need a bigger screen. Open this image on a desktop to label it." with `Copy desktop link` and `Back to the board`. [empty: an image with no annotations reads "No boxes on this image" and the action is still the desktop link]
2. **Copy desktop link** — copies the absolute URL (with the same query) and confirms with a toast "Link copied"; the button never overflows its card at 375. [error: a clipboard refusal selects the URL text instead, so the user can copy manually]
3. **Data-saver or a slow image** — a skeleton at the image's aspect ratio, not a spinner. [error: an image that fails to load shows "This image did not load" with `Retry` and keeps the notice]
4. **Rotate to landscape** — the notice stays; drawing tools never appear below 768 px, because a mis-tap on a phone would create a real label.
5. **768 px and above** — the full editor renders; the notice and the copy button are absent.

## Acceptance criteria
- [ ] At 375 px the editor is read-only: no draw, no class picker, no hotkeys, no approve.
- [ ] The notice offers `Copy desktop link` and `Back to the board`; the copy path keeps the query string.
- [ ] Nothing overflows the card at 375 and no horizontal scroll appears.
- [ ] At ≥ 768 px the full editor renders and the notice is absent.
- [ ] Empty, loading and error states above all render: "No boxes on this image", an image skeleton at the right aspect ratio, and "This image did not load" with `Retry`.
- [ ] Workspace A cannot see workspace B's data: the preview requests one image by id; a foreign id still 404s and the editor shows its not-found state.
- [ ] Flag off ⇒ the current editor renders at every width, unchanged.

## Notes for the implementer
Read-only is a real state, not a disabled toolbar: mount the canvas without listeners so a stray tap cannot create a shape, and keep the approve/reject buttons unmounted rather than disabled — a phone review would need the full audit trail that area 3's review cards build.
