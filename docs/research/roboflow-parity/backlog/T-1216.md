## User story
As the design and quality leads, I want one audit of the board and the editor — where the product is
actually used for hours — covering keyboard speed, canvas legibility, the review loop and 375 px, so that
the core screen is measured, not admired.

## UX flow (LabelDesk words)
1. **Annotate board** (`/:ws/p/:project/annotate`) — three lanes, batch rows, the role-aware primary.
2. **Editor** (`/:ws/p/:project/annotate/:imageId`) — the class panel, the tool column, the canvas, the
   thumbnail strip, the review pill, next image.
3. **Review** — approve/reject at keyboard speed, the empty confirmation, the bulk confirm sentence.
4. **Assist** — the proposal-versus-committed state and the picker's disabled reasons.
5. **375** — the board rows and the explicit "desktop recommended" editor notice.

## Acceptance criteria
- [ ] The review loop is keyboard-complete and every shortcut shown on the control it triggers.
- [ ] Class colour is never the only signal; every chip carries its name and the counts agree with the
      object list.
- [ ] Canvas overlays (selection, handles, proposal) stay legible on light and dark images, with the
      measured ratios in the report.
- [ ] axe: 0 critical/serious; canvas is reachable and announced; the focus ring is never hidden by the
      top bar or the job tray.
- [ ] The 10 heuristics are scored per screen; no score < 3; the two worst are named with evidence.
- [ ] 375: no horizontal scroll, the board's rows are tappable, the editor says it is desktop-first.
- [ ] Findings are S1–S4 with evidence; each S1/S2 carries a proposed fix card title.
- [ ] P1 and P3 walk the area; SUS-8 and any dead end are recorded.
- [ ] The three states that fail most often are checked explicitly: empty lane, empty image, failed save.

## Notes for the implementer
Do not score the editor from a screenshot alone: the canvas work is measured by the keyboard pass and the
contrast sampler. A 10 px label on the canvas is a finding here even if the token audit passes.
