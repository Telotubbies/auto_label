## User story
As the security reviewer, I want one suite that attacks the hub the way an attacker would — payloads in
every field, tampered plans, spoofed inventory, guessed ids — so that "admin-only" is a tested claim
rather than a comment.

## UX flow (LabelDesk words)
No new screen. The user-visible outcomes the suite pins:
1. A crafted engine id, version, runtime, host, model id, variant or project slug is refused with
   400/404/422 and creates no job.
2. A tampered plan id is refused by the worker before any process starts.
3. A log line containing a token or an absolute path is stored redacted.
4. A guessed host, job or project id from another workspace answers 404, never 403 (no existence leak).
5. An oversized body is refused before parsing (the existing body limit).

## Tests to write first

  `&& curl evil`, `../x`, `vllm==1.0\nrm`, an overlong string: `POST /engines/plan` and `/install`
  answer 400/422, no `Job`, no `Audit` with that string.
- `test_model_fields_refuse_traversal_and_urls` — `../../x`, `https://evil/x`, `owner/name/extra`, an
  empty variant → 400/422.
- `test_host_and_job_ids_are_not_interpolated` — `host=../../etc`, a 4 kB id → 404/422, no 500.
- `test_oversized_body_is_refused` — a 2 MB plan body → 413 or 422 before the service runs.
- `test_confirm_must_be_a_boolean_true` — `confirm: "true"`, `1`, `null` → refused (pydantic strictness).
pytest — `apps/backend/tests/test_inference_isolation.py`:
- `test_cross_workspace_host_job_and_project_are_404` — 10 ids across workspaces A/B, for read, cancel,

- `test_flag_off_is_404_on_every_route` — parametrised over the route table.
- `test_token_never_appears_in_any_response` — seed `HF_TOKEN` in inventory; walk every GET/POST and
  grep the serialised body for `hf_`.
- `test_audit_carries_no_argv_and_no_path` — after one install enqueue, serialise every `Audit` row and
  assert no `argv`, `/home/`, `hf_`.
pytest — `apps/worker/tests/test_engine_guard.py`:
- `test_tampered_plan_id_is_refused_before_exec` — a modified argv with the same step count → guard

- `test_every_executable_outside_the_allowlist_is_refused` — `bash`, `sh`, `powershell`, `curl` → raise.
- `test_option_that_writes_outside_is_refused` — `--target`, `--prefix`, `-t`, `--root` → raise.
- `test_symlink_escape_is_refused` — a symlink under `engines_dir` pointing at `/tmp` → `resolve()`
  outside → raise.
- `test_log_redacts_a_token_and_a_home_path` — a line with `hf_secret…` and `/home/alice/.ssh` → stored
  without either.

## Acceptance criteria
- [ ] Every field named above is attacked and refused with a 4xx and no side effect.
- [ ] Plan tampering is refused by the worker before exec.
- [ ] Cross-workspace ids are 404 across read and write, for all five resource types.
- [ ] Flag off is 404 on every inference route.
- [ ] The token never appears in a response, a job row, a log or an audit row.
- [ ] The suite runs without network and without a real engine.

## Notes for the implementer
Attack the **service** as well as the route: a direct call with a hand-built body must fail the same way.
Keep payloads in one `PAYLOADS` table so a new field is one line, and assert "no job was created" after
each case — a 400 that still enqueued is the bug this suite exists for.
